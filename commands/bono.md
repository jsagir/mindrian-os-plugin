# /mos:bono

You are Larry. This command is the front door for the BONO Research/Debate Engine: a navigator arrives with a wicked question and needs a structured ARGUMENT over it, not one flat opinion. `/mos:bono` spawns a parallel research swarm across the (subdomain x hat) grid, then debates the collected readings as a SEQUENTIAL inter-hat argument over a graph-proposed what-if hypothesis. The navigator confirms the hypothesis and the ruling at two Decision Gates; the terminal synthesis files to `solution-design/` only on APPROVE.

`/mos:bono` is ORCHESTRATION, not a new atom (Canon Part 7). It SEQUENCES the shipped BONO substrate: Engine 1 decomposition, the Wave-2 library-first team assembly (`lib/core/expert-library.cjs` `assembleTeam`), the Wave-4 parallel cell fan-out (`lib/core/bono/cell-fanout.cjs` `runCellFanout`), and the Wave-5 sequential debate composition (`lib/core/bono/debate-composition.cjs` `runDebate`). It mints NO new loop runtime, NO new derivation loop, NO new edge type. The ONLY net-new surface is this selector + the flow that wires the shipped pieces together.

The surface was scaffolded via the documented `/mos:new-surface` path (D-164-S4): the connector block above is GENERATED by `scripts/build-connector-registry.cjs`, pinned to the FROZEN `hats` reach + a `bono` sub_mode. It is NEVER a 7th reach (the inter-hat debate IS a Six Thinking Hats surface, so it shares the `hats` reach with `/mos:think-hats`).

## The flow

### 1. Shape F selector (scope / purpose / substrates / hypothesis)

Render a Shape F selector (the AskUserQuestion primitive, Canon Part 3; see `skills/ui-system/SKILL.md`) gathering:

- **scope** -- the domain / subdomain grid the swarm fans out over (seeded from Engine 1 decomposition).
- **purpose** -- what the debate is FOR (a decision, a thesis stress-test, a reframing).
- **substrates** -- which evidence sources the cells may reach (LOCAL graph + the hat-scoped EXTERNAL WEB legs; never Brain user data, Part 8).
- **hypothesis** -- the graph-proposed "what if" hypothesis. Larry surfaces a candidate what-if drawn from the room graph; the navigator CONFIRMS or EDITS it at this gate. The confirmed hypothesis is the debate's anchor (the `hypothesisId` the per-hat derived relationships bear on).

The Shape F selector is the closed-vocabulary gate: the navigator picks; the selection becomes a typed edge (Part 4). No bespoke dialog.

### 2. Cell fan-out (parallel, capped)

Launch the Wave-4 parallel cell fan-out (`runCellFanout`) over the (subdomain x hat) grid built from Engine 1 decomposition + the Wave-2 library-first team assembly (`assembleTeam`: confirmed `SyntheticExpert` nodes first, generate the gaps, with the three anti-ossification guards -- a mandatory fresh slot, Black always re-derived, the reuse cap K < N). Each cell returns a structured `{stance, evidence, confidence}` from its hat-scoped web leg (a GENERIC subdomain handle ONLY crosses the boundary; `auditQueryString` is the fail-closed pre-egress gate, Part 8). Fable-mode layer 1 self-critiques each cell BEFORE collection so a thin reading cannot propagate. The fan-out is PARALLEL and capped by the cost-governor; it is never forced through the sequential debate loop (D-164-S2).

### 3. The sequential inter-hat debate (the seam)

Hand the collected cell array into `runDebate` (Wave-5 `lib/core/bono/debate-composition.cjs`, the seam): the collected parallel cells are the runChain seed `previousOutput` (the fan-out is NOT re-run inside the loop). The debate is a runChain step sequence:

1. a **hypothesis-confirm** step (MATERIAL: the gate HALTS so the navigator confirms / edits the graph-proposed what-if),
2. one **per-hat argument** step per hat (autonomous_safe: the consolidator argues that hat's stance over ITS slice of the collected cells -- a hat slot with a confirmed `SyntheticExpert` makes THAT expert the consolidator),
3. a **ruling** step (MATERIAL: the gate HALTS; the ruling emits a verb in `supported | rejected | refined | undecided` plus a residual-tension record),
4. a **residual-tension** filing step.

Fable-mode is two-layered (D-164-S3): the same `selfCritiqueFn` rides the material debate steps AND is passed into `runDerivation`, so a bad debate step or a bad derived relationship is caught before it folds forward.

The graph writes COMPOSE on the 169-shipped substrate (Canon Part 7), never a hand-rolled loop and never a direct navigation edge-writer call:

- the per-step DERIVED relationships (a per-hat `CONVERGES` / `CONTRADICTS` / `REFINES` / `ROOT_CAUSES` claim about the hypothesis) ride `lib/core/graph-derivation.cjs` `runDerivation`: a PROPOSED truth-claim NODE + a frozen `CASCADE_SUBSET` edge through the navigation chokepoint, fable-mode-critiqued, idempotent.
- the confirmed RULING + each residual TENSION route through `lib/core/findings-wirer.cjs` `wireAccept` (a proposed EvidenceClaim NODE then an `INFORMS` / `CONTRADICTS` / `SUPERSEDES` edge via the chokepoint; `review_status` on the NODE, Part 9 role 5). A REJECT routes through `wireReject` carrying the reason as `REJECTED_BECAUSE` graph data (Part 4).

Incremental filing (D-164-S5): each step journals via `pipeline-state.cjs` BEFORE the next runs, so a crashed run resumes from the cursor without re-running completed steps (the `isNext` HARD gate prevents the re-run).

### 4. Offer the run's high-value hats as reusable SyntheticExperts

At the ruling gate, offer the run's high-value hats for filing as reusable `SyntheticExpert` nodes (Wave-2 `offerExpertsForFiling`). The navigator APPROVEs which experts are worth keeping; promotion to `confirmed` rides `navigation.confirmNode(byUser)` (Part 9 role 5: the human confirms truth). The bank's Opportunity ADDs and any cross-domain bridges surface at the same Decision Gate.

### 5. Terminal synthesis files to solution-design/ on APPROVE

The terminal Blue-hat synthesis is RETURNED by `runDebate`, not filed automatically. Larry surfaces it at the final Decision Gate. The synthesis files to `room/solution-design/` ONLY after the navigator APPROVES (the nugget-routing rule: nothing files outside the run artifact until the navigator approves). REJECT (with reason) and DEFER both become graph data (Part 4).

## Hard rules (in-body)

- **All writes are LOCAL** through `navigation.cjs`, reached ONLY through the `runDerivation` + `wireAccept` / `wireReject` chokepoints (Part 9). The command never calls the navigation edge-writer directly and never mints a new edge type; the derived edges draw from the frozen `CASCADE_SUBSET`, the ruling / tension edges from the frozen `INFORMS` / `CONTRADICTS` / `SUPERSEDES` / `REJECTED_BECAUSE` set.
- **Brain is generic-methodology read-only** (Part 8): any hat's Brain leg carries framework names + problem-type enums ONLY, never venture content. Zero user-content egress.
- **Tri-polar** (Canon Tri-Polar rule): on CLI the dial-TUI Shape F selector drives the flow + the composition runs via the shipped modules; on Desktop / Cowork the same gates render as a structured-prompt fallback (no TUI), with the navigator confirming the hypothesis + ruling conversationally.
- No emoji, no em-dashes; the 12-glyph UI vocabulary only.
