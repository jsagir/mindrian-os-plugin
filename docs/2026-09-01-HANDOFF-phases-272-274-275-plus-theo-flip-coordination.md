## Real findings this session, most consequential first

### 1. Theo's `brain_query` will silently return empty results after the flip, not an error (found while researching, relayed to Theo's session)

Verified directly against `lib/core/brain-client.cjs:791-794`. The existing `normalizeBrainQueryResult`-equivalent logic:

```js
if (Array.isArray(result)) return { records: result };        // incumbent's bare-array shape
if (result && Array.isArray(result.records)) return result;   // already-normalized
return { records: [] };                                       // unexpected shape -> empty, never crash
```

Theo's `brain_query` (per its own `09-MOS-LEARNING.md`, read in full this session) returns `{rows, diagnostics}` -- neither a bare array nor a `.records` key. It falls through to the third line. Every caller (`rs-explain-command.cjs`, `rs-thesis-command.cjs`, etc.) will read `{records: []}` as "zero results," with no error, no crash, no visible signal. Same failure signature as Phase 273's C1 finding, on the read side this time. **Flagged to Theo's session directly. Whoever picks up the plugin-side Brain-envelope adaptation should special-case Theo's shape in this function before flip day, independent of when Phase 08.4 (Theo's remote hosting, see below) actually lands.**

### 3. REVERSE_SALIENT edges are a live, documented exception to "everything goes through navigation.cjs"

Found while building `rs-engine.cjs` (Phase 272): `navigation/edges.cjs`'s `ALLOWED_EDGE_TYPES` does NOT include `REVERSE_SALIENT` -- its own header names a deferred "D-168" legacy-vocabulary unification with `lazygraph-ops.cjs` as not-yet-done work. `rs-engine.cjs` writes `REVERSE_SALIENT` edges via `lazygraph-ops.cjs::upsertEdge` instead, matching `futures/orchestrator.cjs`'s existing, ungated pattern for the same edge type -- added to `scripts/check-substrate.cjs`'s `ALLOWED_DIRECT_IMPORT` with a full justification comment, not a silent bypass. **Worth knowing for anyone touching the "one chokepoint" claim in this repo's own docs, and relayed to Theo's session since Theo's `CLAUDE.md` Rule 4 currently asserts full unification that this repo's own code doesn't yet have either.**

### 4. The rank-agreement validation gate (D-11) was measuring the wrong axis of variance

Phase 272's numerical proof initially measured 0.06 top-50 overlap against a 0.95 gate -- looked like a broken port. Root-caused, not forced past: even Python's own `TruncatedSVD(algorithm="arpack")` compared against itself ACROSS independent processes (not within one, which is what the original noise-floor measurement actually tested) only reaches 0.42-0.50 overlap on this fixture room's densely-tied score distribution. The underlying numbers agreed almost exactly either way (avg delta ~0.0016-0.0018). Navigator ruling (D-11): replaced the top-K set-overlap metric with a Spearman rank-correlation + delta-bound metric on the LSA leg specifically. Result: rho = 0.9965, zero confident sign flips. **A second, non-gating finding surfaced while implementing D-11's fix, now quantified for the first time: gating on the raw `abs_diff` field (which folds in `semantic_score`) gives rho = 0.15, because D-01 deliberately keeps two different encoders (Python's `all-MiniLM-L6-v2` vs CJS's `MongoDB/mdbr-leaf-ir`) by design.** CJS-mode and Python-mode will show visibly different reverse-salient rankings for the same room in production -- not a bug, a real consequence of an already-locked architecture decision, written up prominently in `274-.../DEFERRED-SCOPE.md`'s sibling doc for Phase 272 (`272-.../DEFERRED-SCOPE.md`, item naming this explicitly) for whoever eventually considers deleting the Python fallback -- that decision implicitly also decides "CJS's rankings are the new ground truth," which nobody has decided yet.
