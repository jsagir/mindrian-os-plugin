# v1.12.4 Feynman tester draft — drafted 2026-05-02

This is the **what's-in-it-for-me variant** of the v1.12.4 announcement. Zero jargon. No version numbers in the headlines. No "JTBD" / "operator" / "phase" terminology. Just: what does Mindrian now do for you, and what does that feel like.

User can choose at send time between this and the bundled-update.md variant (which uses light technical framing for testers who like the under-the-hood story).

## Subject line

**MindrianOS just got smarter about what you're actually doing**

## Body (plain text — for the Gmail draft body, render with De Stijl HTML at send time)

> Hi all,
>
> Quick note. Mindrian has a new trick: it now picks up on what you're trying to do, and adapts.
>
> ## What this means in your day-to-day
>
> ### When you're hunting for a bottleneck
>
> You start typing about a stuck spot in your venture. Mindrian reads the words you're using and quietly tunes the next-move menu around bottleneck-hunting. The options Larry suggests now look different than if you were preparing a pitch. Same Larry, different toolkit per moment.
>
> ### When you're preparing a pitch
>
> Same thing the other way. The verbs Larry offers shift toward investor-thesis territory. The framing Larry uses shifts toward "what has to be true for this to return 10x." You stop having to manually tell him what frame you're in — he reads it from how you're talking.
>
> ### When you're just chatting
>
> Larry stays out of the way. No filing. No surfacing. No checklists. Plain conversation. He only switches gears when the conversation actually shifts.
>
> ### When you come back tomorrow
>
> Open a fresh terminal. Larry says "you were finding bottlenecks in customer-acquisition yesterday — keep going?". The thread you were on doesn't reset to zero. He picks it up.
>
> ### And the picker actually looks like Mindrian now
>
> When Larry asks you to choose between options, the menu now uses Mindrian's own visual vocabulary — colored rails, structured rows, keyboard shortcuts — instead of the generic Claude Code prompt. Same workflow, polished surface.
>
> ## The thing that's different
>
> Before this update, Larry treated every turn as fresh. You had to keep reminding him what you were doing. After this update, he carries forward what you're working on across turns and across sessions, and the menus he surfaces are tuned to that.
>
> Three sentences if you want the elevator pitch:
>
> 1. Mindrian now reads what you're trying to do, from how you talk
> 2. The menus it shows you are tuned to that, per /mos: command
> 3. It remembers across sessions
>
> ## To pull the update
>
> /plugin marketplace update
> claude plugin update mos@mindrian-marketplace
>
> If your install does not see the update, run the first command a second time and try again.
>
> ## Try it (5 minutes)
>
> Just use Mindrian normally. You should feel three things:
>
> 1. Larry asks fewer setup questions at session start
> 2. Different /mos: commands surface different next-move menus depending on what you've been talking about
> 3. The picker has colored rails and a structured layout instead of plain prompts
>
> If you want to nudge Mindrian explicitly: type `/mos:jtbd set find-bottleneck` (or whatever job fits what you're doing) and watch /mos:explore-domains, /mos:rs-fetch, /mos:think-hats each surface different options.
>
> ## Two limits worth knowing
>
> 1. The menus tune per command — but if you've been talking about something that doesn't fit cleanly into a job, Mindrian falls back to a general menu. That's the right behavior; it's not a bug.
>
> 2. The cross-session memory only kicks in if you opt your room into it (default: opt-in). Sealed rooms (the ones you've explicitly marked private) stay sealed.
>
> ## Feedback
>
> GitHub Issues for defects: https://github.com/jsagir/mindrian-os-plugin/issues
> Direct: jsagir@gmail.com
>
> One transcript per bug = 10x faster fix.
>
> Thanks for testing.
>
> — Jonathan

## What "Feynman simplification" means here, applied

Feynman's rule: if you can't explain it to a smart friend in plain words, you don't understand it well enough. Translation table for this email:

| Technical name | Feynman framing |
|----------------|-----------------|
| Operator state machine | "what mode you're in" / not even named — felt as Larry adapting |
| JTBD inference | "what you're trying to do" / "the job you're working on" |
| Selector dispatcher | "the menu Larry shows you" |
| Shape F.1..F.5 sub-shapes | "the picker has colored rails and a structured layout" |
| Per-command JTBD declaration | "different /mos: commands surface different menus" |
| Cross-session memory | "remembers across sessions" |
| Cross-room intelligence | "the same problem in two ventures? you'll see the connection" |
| Mode A / Mode B / Tier 0 | not named — "if Brain is up, more polish; if not, still works" |
| Phase 99 / 100 / 101 / 102 / 103 / 105 | not named — release version stays in CHANGELOG, not the email |
| Canon Part 8 LOCAL-only | "your data stays on your machine" |

Each row is a translation, not an omission. The technical fact is preserved; the language stops requiring the reader to know our terminology.
