# Phase 95.6 -- Windows Cold-Install Acceptance Gate

This gate is authoritative over the automated suites. A green CI run with a
failed cold-machine gate means Phase 95.6 is NOT done and v1.13.0-beta.9 does
NOT ship. Scheduled tester: Gary Laben (or a Wave-3 equivalent). It also
produces the source material for the case #4 autopsy at
`docs/autopsies/2026-05-09-gary-laben-install-failure.md` (Plan 95.6-06).

This is the empirical Dimension-8 gate. The automated fixtures simulate Windows
on a Linux CI box; they cannot prove the real thing. D-01 + D-03 + D-09
ultimately require a real Windows tester to run the canonical install path with
zero AI hand-holding (no Claude Code improvising the missing symlinks or
settings.json fragments) and reach an all-green `/mos:doctor`.

Source: `95.6-RESEARCH.md` "## Validation Architecture / The cold-machine manual
gate" + `95.6-VALIDATION.md` "## Manual-Only Verifications".

---

## When to run

- Before the v1.13.0-beta.9 ship (the phase gate, alongside a green full suite).
- After any change to `install.sh`, `scripts/doctor.cjs`, or the install site
  copy that touches the canonical Windows path.

## Tester

Gary Laben (Wave-2 critical tester, Windows 11, Surface Pro 7) or a Wave-3
equivalent on a fresh Windows machine. The tester must NOT let Claude Code
auto-repair a partial install; the point is to verify install.sh finishes on
its own.

## Preconditions

- Fresh Windows 11 machine, Git for Windows installed, no prior MindrianOS
  state anywhere on the machine (`%USERPROFILE%\.claude` absent or empty).
- Surface-class touch device preferred (matches Gary's Surface Pro 7); bring an
  external keyboard for the permission prompts.
- Claude Code installed via its own native installer.

---

## Checklist

1. Fresh Windows 11 machine, Git for Windows installed, no prior MindrianOS
   state (Surface-class touch device preferred -- matches Gary's Surface Pro 7;
   bring an external keyboard for the permission prompts).
2. Run the canonical install path exactly as the install site documents it (CMD
   shell -- what worked for Gary live; note any PowerShell deviation).
3. Observe: `git clone` completes with no MAX_PATH error and no manual
   `core.longpaths` intervention required (D-01 + D-02).
4. Observe: `install.sh` exits 0; if any skill dir is incomplete it prints a
   `WARN` and continues; agents, hooks, larry-extended default,
   `MINDRIAN_OS_ROOT` all registered (D-03).
5. Open a fresh `claude` session: the statusline `(hexagon) MindrianOS-Plugin
   <room> <context%>` renders at the bottom within ~1s (D-09).
6. Run `/mos:doctor --all` (or `/mos:doctor --statusline-visibility`):
   all-green, OR it names exactly what is missing and `--fix` resolves it.
7. Reach `/mos:onboard` -> Larry greets, in under 5 minutes total, with no
   maintainer help.
8. (D-05a, if recovery publish has landed) `npm view @mindrian/os@next version`
   returns the shipped beta version; if not yet landed, confirm the install
   site does not advertise the npx path.

Note: step 5 says "(hexagon)" in words on purpose -- the live statusline shows a
hexagon glyph; this checklist does not embed it (no emoji / no unicode hexagon
in the markdown body, per skills/ui-system).

---

## Pass criteria

All eight checklist items pass with NO manual intervention beyond following the
documented install path. Specifically:

- No manual `git config core.longpaths` was needed (step 3).
- No manual cp-loop completion was needed (step 4).
- No manual `settings.json` edit was needed (steps 4-5).
- `/mos:doctor` first-session output is all-green, or `--fix` resolves every gap
  it names (step 6).
- `/mos:onboard` reaches a Larry greeting in under 5 minutes (step 7).

A green CI run with ANY of the above failing means Phase 95.6 is not done.
