## Algorithm Foundations (From Papers)

### SemNovel: Semantic Novelty Scoring (Peng et al., JBI 2025, DOI: 10.1016/j.jbi.2025.104952)

**Core idea:** Measure how semantically distant a publication is from ALL prior publications in the same domain. Distance from consensus = novelty.

**Algorithm (reconstructed from abstract + methodology summaries):**

1. **Embedding model:** BAAI/llm-embedder -- a unified embedding model built on Llama2-7B-Chat foundation with BGE-base as embedding backbone. Produces dense vector representations of publication abstracts/titles.

2. **Semantic universe construction:** Embed the entire corpus (PubMed in their case) into a high-dimensional embedding space. This is the "consensus baseline" -- the space of everything already known.

3. **SemNovel score calculation:** For each target article, compute its distance from prior publications in embedding space. The score quantifies how far an article sits from the existing knowledge landscape. Higher distance = more novel.
   - **Distance metric:** Cosine distance in the LLM-embedder space (inferred from methodology description and standard practice with BGE models)
   - **Temporal constraint:** Distance is measured only against publications PRIOR to the target (not future ones). This is critical -- novelty is relative to what existed at publication time.

4. **Visualization:** t-SNE projects the high-dimensional embedding space into 2D for visual exploration of the "semantic universe."

5. **Validation results:**
   - Positive correlation with citation counts (rho = 0.1782, p < 0.001, Spearman rank)
   - Independent of journal impact factor, publication year, and author count
   - Nobel Prize-winning papers have statistically significantly higher SemNovel scores (p < 0.001, KS test)
   - Outperforms previous semantic novelty indicators

6. **Application demonstrated:** PD-1/PD-L1 immunotherapy field -- tracked evolution of novelty over time, showed interdisciplinary collaboration enhances novelty.

**What's NOT confirmed (needs full-text verification -- LOW confidence):**
- Whether the score uses k-nearest-neighbor average distance, centroid distance, or local density estimation
- Exact k value if kNN-based
- Whether they use cosine distance or Euclidean in embedding space
- Normalization method for scores across different time periods

### TopicForest: Hierarchical Gap Detection (Chang et al., JBI 2025, DOI: 10.1016/j.jbi.2025.104958)

**Core idea:** Build a forest of topic trees from flat embeddings, where each tree starts broad and drills down to specialties. Sparse or missing branches = knowledge gaps.

**Algorithm (verified from multiple sources including AMIA poster):**

1. **Embedding:** Contrastively trained LLM embeddings of biomedical abstracts into high-dimensional semantic space.

2. **Dimensionality reduction:** Manifold learning (t-SNE or UMAP) for visual interpretation and clustering input.

3. **Hierarchical clustering:** Binary partitioning with multi-level dendrogram cutting.
   - NOT agglomerative (bottom-up) -- uses divisive (top-down) binary partitioning
   - Dendrogram cutting at multiple levels produces multi-resolution topic granularity
   - At each level, the partition splits into two sub-clusters

4. **Label generation:** Recursive LLM-based topic summarization
   - Starts from the smallest (leaf) clusters
   - LLM generates a concise topic label for each leaf cluster
   - Parent labels are generated by summarizing child labels recursively upward
   - More efficient than re-reading all documents at each level
   - Outperforms c-TF-IDF and HyperMiner labeling in diversity and hierarchical affinity

5. **Output:** A forest of topic trees (not a single tree), where each root represents a broad research area and leaves represent narrow specialties.

6. **Evaluation:**
   - Corpus: 24,366 biomedical abstracts from Scientific Reports
   - Gold standard: Human-curated topic hierarchy
   - Metrics: Adjusted Mutual Information (AMI) for clustering quality, Dasgupta's cost for hierarchy quality
   - Results: AMI comparable to or better than BERTopic + K-means/HDBSCAN
   - Outperforms HyperMiner (VAE-based hierarchical model)

7. **Gap detection:** Sparse branches in the topic forest indicate under-researched areas. A branch with few or no publications beneath it, sandwiched between dense branches, signals a whitespace.

### Information Extraction Novelty (Peng et al., AMIA 2025)

**Core idea:** Novelty is not just about embedding distance -- it is about the emergence of NEW entities and NEW relationships in conclusions.

**Algorithm:**

1. **Extraction pipeline:**
   - Parse conclusion sections of research articles
   - Apply transformer-based Named Entity Recognition (NER) to extract biomedical entities
   - Apply relation extraction (RE) to identify relationships between entities

2. **Four novelty categories:**
   - **No Novelty:** Neither new entities nor new relationships found
   - **Entity-only Novelty:** New entity mentioned but only in known relationship patterns
   - **Relation-only Novelty:** Known entities connected by a novel relationship type
   - **Entity-Relation Novelty:** Both new entities AND new relationships (highest novelty)

3. **Impact validation:**
   - Entity-Relation Novelty articles receive highest citation impact
   - Relation novelty is more closely aligned with high-impact journals
   - Finding: relationship novelty matters more than entity novelty for research impact

### MedViz: Visual Analytics Platform (He et al., arXiv 2601.20709)

**Core idea:** Integrate SemNovel + TopicForest into an interactive visual analytics system with AI agent-driven exploration.

**Architecture:**

1. **Semantic map:** 2D projection of millions of articles, color-coded by topic/novelty
2. **Agent functions:** Multiple AI agents for querying, summarizing, and hypothesis generation
3. **Iterative exploration:** Researchers refine questions, zoom into regions, identify trends
4. **Hidden connection discovery:** Agent identifies connections between distant semantic regions

**Key insight for MindrianOS:** MedViz proves the pipeline works end-to-end: embed -> score novelty -> cluster hierarchically -> visualize -> agent-driven exploration. This is the exact architecture we are building.

### Anti-Features (Commonly Requested, Often Problematic)

Features that seem valuable but would create problems or violate architectural principles.

| Feature | Why Requested | Why Problematic | Alternative |
|---------|---------------|-----------------|-------------|
| Real-time embedding computation on every artifact save | "Keep whitespace map always current" | MiniLM inference on every save would slow down the filing pipeline and bloat session compute costs. SemNovel ran on a massive cluster. | Batch computation on /mos:whitespace command or session-start hook (same as HSI cache pattern). |
| LLM-embedder (BAAI/llm-embedder) as embedding model | "Use the exact same model as SemNovel for fidelity" | LLM-embedder is 7B+ parameters. Way too heavy for a local plugin. MiniLM is 80MB. The innovation insight transfers regardless of model size. | all-MiniLM-L6-v2 already loaded by HSI pipeline. Same distance-from-consensus principle applies. If users want higher quality, Tier 2 uses Pinecone (Brain embeddings use multilingual-e5-large). |
| Full PubMed-scale semantic universe | "Build the complete baseline like SemNovel did" | 35M+ PubMed abstracts. Impossible locally. Brain has 21K nodes -- sufficient for venture innovation domain consensus. | Brain's 21K methodology/framework nodes as domain-specific consensus. Brain embeddings via Pinecone as Tier 2 baseline. |
| Automated whitespace filling | "Let AI write the missing artifacts automatically" | Violates "user owns Layer 4" principle. Auto-generated content would pollute the room with unvalidated claims. | Generate HYPOTHESES (what should fill the gap), not CONTENT. User decides what to investigate. Larry guides, user acts. |
| Complex interactive 2D visualization (like MedViz) | "Show me the full semantic universe map" | MedViz is a full-stack web application. We are a CLI plugin. Interactive 2D scatter plots require browser rendering, mouse interaction, zoom/pan. | ASCII/text-based section heatmap for CLI. For presentation views, extend existing De Stijl dashboard HTML export with a simple Cytoscape.js whitespace overlay on the existing knowledge graph. |
| Novelty scoring against external corpora | "Score my artifacts against all papers in my field" | Requires downloading/indexing external corpus. Heavy infrastructure. Breaks "no server" constraint. | Score against Brain (internal consensus) and room self-reference. The insight is: distance from YOUR knowledge baseline = YOUR whitespace. External corpus comparison is a v2+ feature if demand exists. |
| Continuous agent-driven exploration (MedViz-style) | "Let an agent continuously explore my whitespace" | Would burn context budget. Agent loops are expensive and hard to control. /mos:act already handles autonomous execution with chain limits. | Batch whitespace scan + hypothesis generation. User triggers deeper exploration with /mos:act when they find an interesting gap. |

### Dependency Notes

- **Novelty Scoring requires Consensus Baseline:** Cannot measure "distance from known" without defining "known." Brain provides domain consensus; room provides self-referential baseline.
- **TopicForest requires Novelty Scoring:** The hierarchical clustering operates on the same embedding space. Build embeddings first, then cluster.
- **Pipeline Integration requires all three existing pipelines:** HSI, RS, and Analogy must exist and produce JSON output (they do -- all shipped in v1.6.0).
- **Entity-Relation Novelty is independent:** Can be built as a standalone enrichment. Uses Claude's native NER capability, no external models needed.
- **KuzuDB edges enhance but do not gate:** Whitespace detection works without graph storage. Graph storage enables cross-session persistence and MWP moat deepening.

## MVP Definition

### Launch With (v1.9.0 Phase 1-2)

Minimum viable whitespace detection -- enough to answer "what is missing in my room?"

- [ ] **Embedding-distance novelty scoring** -- Reuse MiniLM from HSI. Score each artifact by average cosine distance from Brain consensus baseline (Tier 1) or room centroid (Tier 0). SemNovel-inspired but adapted for venture domain.
- [ ] **Consensus baseline construction** -- Embed Brain framework/methodology descriptions as "what a complete venture analysis should cover." Graceful degradation to room-only baseline.
- [ ] **Whitespace zone identification** -- For each room section, compute embedding coverage density. Sections with sparse coverage relative to Brain expectations = whitespace zones. Output as .whitespace-results.json.
- [ ] **/mos:whitespace command** -- Trigger scan, display results in De Stijl CLI format. Show sections ranked by gap severity with one-line hypotheses.
- [ ] **Section coverage heatmap** -- Text-based dense/sparse visualization using existing glyph vocabulary.

### Add After Validation (v1.9.0 Phase 3-4)

Features to add once core whitespace detection works and produces useful results.

- [ ] **TopicForest hierarchical clustering** -- Binary partitioning + dendrogram cutting on room artifacts. Find gaps at multiple granularity levels. LLM labels via Claude.
- [ ] **HSI/RS pipeline integration** -- Compute embedding midpoints between HSI pairs. Map downstream of RS bottlenecks. Produce integrated whitespace map.
- [ ] **KuzuDB WHITESPACE_ZONE edges** -- Store gaps as graph entities. Enable cross-session tracking and MWP cascade detection.
- [ ] **Hypothesis generation with Brain** -- For each gap, query Brain for relevant frameworks/methodologies that would fill it. Generate specific, actionable hypotheses.

### Future Consideration (v1.9.x+)

Features to defer until whitespace detection proves valuable to users.

- [ ] **Entity-Relation novelty classification** -- Classify artifact novelty into 4 tiers (None, Entity-only, Relation-only, Entity-Relation). Requires NER extraction pipeline.
- [ ] **Temporal novelty tracking** -- Snapshot whitespace maps over time. Show gap closure progress. "You explored 3 new zones since last week."
- [ ] **Analogy engine integration** -- Map unmapped transfer zones in SAPPhIRE decompositions.
- [ ] **Dashboard whitespace overlay** -- Cytoscape.js visualization layer showing whitespace zones on the existing knowledge graph.

## Algorithm Adaptation: Biomedical to Innovation Domain

### What Transfers Directly

| SemNovel/TopicForest Concept | Innovation Domain Equivalent | Adaptation Needed |
|------------------------------|------------------------------|-------------------|
| PubMed articles | Room artifacts (methodology session outputs) | None -- same embedding pipeline |
| Publication abstract | Artifact body text | None -- already extracting body in compute-hsi.py |
| "Semantic universe" (all PubMed) | Brain consensus baseline (21K methodology nodes) | Scale down: 35M to 21K. But denser, domain-specific. Better signal. |
| Prior publications (temporal) | Existing artifacts at scan time | Simpler -- room artifacts have git timestamps |
| Novel paper | Artifact exploring unexplored territory | Same scoring logic applies |
| Citation count (validation) | Pipeline scoring (HSI, RS, breakthrough potential) | Different proxy but same concept: "does this novelty lead to impact?" |
| Topic hierarchy (Scientific Reports) | Room section hierarchy | Direct mapping. Sections = broad topics. Artifacts = narrow specialties. |
| Sparse branch = under-researched | Sparse section = whitespace zone | Direct mapping. |
| Entity-Relation novelty | New concept + new connection in artifact | Claude NER replaces transformer NER. Same classification logic. |

### What Needs Reinvention

| Biomedical Concept | Why It Does Not Transfer | Innovation Alternative |
|--------------------|------------------------|-----------------------|
| PubMed as ground truth | No equivalent complete corpus for innovation/venture | Brain methodology graph as domain expert consensus |
| 35M document scale | Room has 10-200 artifacts. Statistical power is different. | Compensate with richer per-artifact analysis (spectral profiles, MINTO reasoning) |
| Subject heading taxonomy (MeSH) | No equivalent controlled vocabulary for ventures | Room section hierarchy + Brain framework taxonomy |
| Journal Impact Factor | No equivalent quality signal | OM-HMM spectral gap score as quality proxy (already computed) |
| Pre-trained biomedical NER | Domain-specific entity recognition | Claude's general NER + Brain entity types (Framework, ProblemType, etc.) |

- SemNovel validation statistics (rho = 0.1782, KS test p < 0.001)

**LOW confidence (inferred, needs full-text verification):**

- Exact k value if kNN

**Implementation recommendation:** Use average cosine distance to k-nearest Brain consensus embeddings as the SemNovel-adapted score. This is the most likely approach given the paper's description and is the standard method in embedding-based novelty detection literature. If full-text access confirms a different approach, the adaptation is straightforward -- the infrastructure (embeddings, distance computation, scoring) remains the same regardless of the exact distance aggregation method.
