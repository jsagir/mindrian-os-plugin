## Current State

The cord is overwhelmingly a DOWN-lane (Brain methodology -> LOCAL) pipe today, with the UP-lane (LOCAL -> Brain, per-turn typed packet) built but dark.

DOWN lane (live, has production callers). brain-client.cjs exposes query/search/smartSearch/ask/askOp/schema/enrichCausalEdges/hatAwareRecommend/suggestValidationSteps/getFrameworkChain -- all of which SEND only generic methodology handles (framework names, problem-type enums, sanitized via sanitizeCypherInput to [a-zA-Z0-9 ._-]) and RECEIVE framework rows back. brain-derivation.cjs::deriveSection is the live orchestrator that consumes this lane: it reads the local Feynman/MINTO/STATE triple, passes it through the buildBrainQueryContext chokepoint (which strips everything to sha256 hashes + enum scalars + section slug), fires brain-client.search()/query() per BRAIN.md section, and writes the answers DOWN into the room's per-section BRAIN.md via an atomic tmp+fsync+rename. deriveSection has real production callers: scripts/brain-derive-command.cjs (the /mos:brain-derive command), scripts/brain-derivation-drain.cjs (the UserPromptSubmit queue drainer that spawns detached derivation children), brain-derivation-queue.cjs, navigation-engine.cjs, framework-chain-composer.cjs, cross-room-aggregator.cjs. 34 production .cjs files require brain-client. So the live cord direction is DOWN.

UP lane (built, DARK). packet.cjs::buildBrainPacket assembles a typed LOCAL->BRAIN "Brain Context Packet" and brain-client.cjs::sendPacket (Phase 110-03) is the SOLE wire path that would POST it as a brain_packet tool call. Neither has ANY production caller -- every buildBrainPacket / sendPacket reference outside the modules themselves is in tests/ or in the D-08 lexical guard in scripts/check-schema-aliases.cjs. The code itself says so: packet.cjs:105 ('dormant only because sendPacket has zero production consumers today') and brain-client.cjs:1163-1164 ('As of v1.13.0-beta.3 there is NO legacy free-form Brain *job* call site'). Even sendPacket's own degrade path returns reason:'brain_packet_tool_absent' because the live Brain has no brain_packet tool yet (brain-client.cjs:1277-1282). So the per-turn UP lane is wired end-to-end in-process but never fired and the remote endpoint doesn't implement it.

What crosses the cord: hashed/enum projection ONLY. Both chokepoints enforce identical shape. buildBrainQueryContext (brain-derivation.cjs:110-156) emits: section_slug (slug-safe folder name), problem_type (UDP/IDP/WDP enum), complexity (Simple/Complex/Wicked enum), phase_indicator enum, reasoning_health_score/evidence_density floats in [0,1], arguments_count int, mece_status enum, governing_thought_hash (sha256:), reverse_salient_present bool, brain_graph_version int. buildBrainPacket routes every prose field (summary/claim/title/text, contradiction + unsupported explanations, focus summary) through projectText() (packet.cjs:130-139): under the default local_summary_only AND allow_filenames it returns a sha256 hash, NOT prose; only under allow_excerpts (a Part-3 Decision-Gate APPROVE opt-in with NO shipped consumer -- roomHasExcerptApproval always returns false today) does a <=120-char excerpt cross.
