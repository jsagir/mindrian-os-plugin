# Feature Landscape: v1.8.0 Cowork Adaptation

**Domain:** MCP-native methodology routing, persistent intelligence, and interactive UI for Claude Desktop/Cowork
**Researched:** 2026-04-05
**Mode:** Ecosystem + Feasibility

## Table Stakes

Features users expect when a plugin claims Desktop/Cowork support. Missing = product feels broken on those surfaces.

### 1. Full MCP Tool Parity (15 Orphaned Commands)

| Feature | Why Expected | Complexity | Surface | Notes |
|---------|--------------|------------|---------|-------|
| All 64 commands accessible via MCP tools | Users on Desktop/Cowork have NO slash commands - MCP tools are their ONLY interface | Medium | Desktop + Cowork | 15 orphans: act, causal, dashboard, find-analogies, models, onboard, present, publish, query, reanalyze, rooms, scout, snapshot, speakers, wiki, splash, admin. The router currently covers 49/64. |
| Hierarchical router expansion (7-8 routers) | Desktop context window budget is ~5000 tokens for tool definitions. Flat registration would consume 30-60K tokens. | Low | Desktop + Cowork | Current 6 routers need expansion. Add `autonomous` (act, scout, reanalyze) and `admin` (admin, onboard, rooms, setup, splash) routers. Keep total under 8 routers for LLM reasoning quality. |
| Parameter richness beyond `command` + `section` | Current router overloads `section` parameter for JSON payloads - confusing for LLM tool selection | Medium | Desktop + Cowork | Act needs `mode` (chain/swarm/dry-run), scout needs `task` (health/deadlines/competitors/hsi/snapshot), present needs `format`. Zod schemas should be explicit per-router. |
| Graceful degradation when Brain unavailable | Desktop/Cowork users may not have MINDRIAN_BRAIN_KEY configured | Low | All | Already built for CLI (Tier 0 fallback). Verify same path works through MCP tool layer. |

**Dependency:** Existing `lib/core/*.cjs` modules + `lib/mcp/tool-router.cjs`. No new libraries needed - this is routing and Zod schema work.

### 2. Surface Auto-Detection

| Feature | Why Expected | Complexity | Surface | Notes |
|---------|--------------|------------|---------|-------|
| `/mos:setup` detects CLI vs Desktop vs Cowork | Users should not manually configure which surface they're on | Low | All | Detection heuristics: CLI = `process.env.CLAUDE_PLUGIN_ROOT` exists + hooks fire. Desktop = MCP stdio transport + no hooks. Cowork = MCP transport + `00_Context/` directory or Cowork-specific env vars. |
| Single install serves all surfaces | Plugin marketplace is one install. Users shouldn't need to reconfigure per-surface. | Low | All | Already true for CLI. Desktop needs `claude_desktop_config.json` entry auto-generated by setup. Cowork inherits from plugin install. |
| Hook-to-MCP equivalence mapping | CLI hooks (SessionStart, PostToolUse, FileChanged) have no equivalent on Desktop/Cowork - features that depend on hooks must have MCP-native alternatives | Medium | Desktop + Cowork | PostToolUse is CLI-only. Cowork equivalent = Desktop Scheduled Tasks polling for changes. SessionStart equivalent = first tool call detection in MCP server. FileChanged = scheduled task checking room mtime. |

**Dependency:** Existing `commands/setup.md`. Environment variable sniffing in MCP server entry point.

### 3. Pipeline Chaining via MCP

| Feature | Why Expected | Complexity | Surface | Notes |
|---------|--------------|------------|---------|-------|
| Multi-tool chains work end-to-end | The Week 7 pattern (scenario -> root-cause -> causal -> prediction) is the core product value. If chaining breaks on Desktop, the product is hollow. | Medium | Desktop + Cowork | MCP tool chaining is LLM-orchestrated, not server-orchestrated. The LLM reads output from tool A and decides to call tool B. This already works naturally IF tool outputs include `suggested_next` fields. |
| Consistent tool output shapes | Each tool must return structured output so the LLM can extract what it needs for the next tool | Medium | All | Current router returns `textResponse()` with mixed formats. Standardize: every methodology/analysis tool returns sections: `## Summary`, `## Artifacts Filed`, `## Room Changes`, `## Suggested Next`. |
| Chain state persisted to room | Pipeline results file to room sections, so chain step 3 can reference what step 1 produced by reading the room | Low | All | Already built - room filesystem IS the chain state. Each tool files artifacts. Next tool reads room state via `data_room status`. |

**Key insight on chaining:** Unlike MCP Tool Chainer (which uses server-side CHAIN_RESULT placeholders), MindrianOS chaining is room-mediated. Tool A files to room. Tool B reads room state. The room IS the chain state. This is more robust than placeholder-based chaining because intermediate results are persisted and inspectable. The LLM orchestrates the sequence; our job is consistent output shapes and `suggested_next` hints.

**Dependency:** `lib/core/state-ops.cjs`, `lib/core/room-ops.cjs`. The room-as-state pattern is already the architecture.

### 4. Brain-Driven Routing (MCP-Native)

| Feature | Why Expected | Complexity | Surface | Notes |
|---------|--------------|------------|---------|-------|
| Brain consulted for framework selection | The moat IS Brain-driven methodology routing. Without it, Desktop/Cowork users get dumb random framework selection. | Medium | All | `/mos:act` already does this on CLI via `brain-client.cjs`. The MCP `autonomous` router must call the same client. |
| Framework chain ordering from Brain | Brain knows which frameworks chain well together (CO_OCCURS, ADDRESSES_PROBLEM_TYPE relationships). This must be accessible via MCP. | Medium | All | Brain Cypher: `MATCH (f1:Framework)-[:CO_OCCURS]->(f2:Framework) WHERE f1.name = $current RETURN f2 ORDER BY f2.relevance DESC`. |
| Local fallback routing table | When Brain is unavailable, use `references/methodology/problem-types.md` routing table | Low | All | Already built in `commands/act.md`. Extract routing logic to `lib/core/routing-ops.cjs` for shared CLI + MCP use. |

**Dependency:** `lib/core/brain-client.cjs` (already built, uses HTTP to mindrian-brain.onrender.com). Brain MCP already deployed.

## Differentiators

Features that set MindrianOS apart from any other Claude plugin. Not expected, but create the "wow" moment.

### 5. De Bono Persistent Hats (Cross-Session Perspective Agents)

| Feature | Value Proposition | Complexity | Surface | Notes |
|---------|-------------------|------------|---------|-------|
| 6 always-on perspective agents | Every artifact gets 6 perspectives without user prompting. Black Hat catches risks, Yellow Hat finds opportunities, Blue Hat orchestrates. No other plugin does persistent multi-perspective analysis. | High | Cowork (primary), Desktop (degraded), CLI (hook-driven) | Implementation varies by surface - see below. |
| Cross-session memory per hat | Each hat remembers what it said. Black Hat tracks flagged risks and whether they were addressed. Yellow Hat tracks pursued opportunities. | High | Cowork (primary) | Memory stored in `room/.hats/{color}/memory.json`. Each entry: `{ timestamp, artifact, perspective, user_response }`. |
| Hat-triggered cascade detection | When Black Hat flags a risk in financial-model/ and the same pattern appears in market-analysis/, the cascade is surfaced | High | Cowork | Cross-section scanning after each hat perspective. Uses existing `proactive-intelligence.cjs` edge detection. |

**Implementation by surface:**

**Cowork/Desktop - Desktop Scheduled Tasks (persistent, survive restarts):**
- Each hat = a SKILL.md at `~/.claude/scheduled-tasks/mindrian-hat-{color}/SKILL.md`
- YAML frontmatter: `name: mindrian-hat-black`, `description: Black Hat risk analysis`
- Body = prompt that calls `data_room status` tool, reads new artifacts, generates perspective
- Schedule: staggered nightly (Black 11pm, Yellow 11:05pm, Green 11:10pm, Red 11:15pm, White 11:20pm, Blue 11:25pm)
- Tasks have full access to local files + MCP servers + plugins
- Morning briefing task at 9am aggregates hat outputs into daily summary
- Persistent across app restarts; catch-up run if laptop was asleep
- Each run = fresh session in Desktop sidebar under "Scheduled" section

**Desktop (on-demand fallback):**
- Hats run when user calls `data_room analyze-perspectives` tool
- Reduced value (not persistent across sessions) but fully functional

**CLI (hook-driven):**
- PostToolUse hook triggers perspective analysis after artifact-filing tools
- Full power, immediate feedback, but only during active session

**Dependency:** `lib/core/persona-ops.cjs` (already built with `invokePersona`, `analyzeAllPerspectives`). Needs: memory persistence layer in `persona-ops.cjs`, 7 Desktop Scheduled Task SKILL.md files.

### 6. MCP Apps Data Room Views

| Feature | Value Proposition | Complexity | Surface | Notes |
|---------|-------------------|------------|---------|-------|
| Interactive dashboard in conversation | Users see De Stijl Mondrian grid dashboard INSIDE Claude, not in a separate browser tab | Very High | Desktop + Cowork | Tool declares `_meta.ui.resourceUri: "ui://mindrian-os/dashboard"`. Host renders HTML in sandboxed iframe. Context preserved in conversation. |
| Interactive wiki with hyperlink navigation | Room sections as wiki pages, [[wikilinks]] are live links | Very High | Desktop + Cowork | Wiki explorer example in ext-apps repo as reference. Adapt existing De Stijl wiki template. |
| Knowledge graph with interactive nodes | Cytoscape.js graph in iframe, click nodes for artifacts, edges show relationships | Very High | Desktop + Cowork | Existing `room/exports/presentation/graph.html` serves as base. Needs postMessage bridge. |
| Bidirectional data flow | User clicks buttons in iframe that call MCP tools via postMessage | Very High | Desktop + Cowork | MCP Apps spec supports `tools/call` over postMessage JSON-RPC 2.0. Iframe acts as MCP client. |

**MCP Apps Technical Implementation (from spec 2026-01-26):**

Tool declaration with UI metadata:
```javascript
// In tool-router.cjs, tool definitions include _meta
server.tool(
  'data_room',
  'Manage your MindrianOS Data Room...',
  { command: z.enum([...]), section: z.string().optional() },
  async ({ command, section }, extra) => {
    // extra._meta.ui.resourceUri used by host for preloading
    return { content: [{ type: 'text', text: result }] };
  }
);
```

Resource registration for UI:
```javascript
// Register ui:// resources that tools reference
server.resource(
  'mindrian-dashboard',           // resource name
  'ui://mindrian-os/dashboard',   // URI
  { mimeType: 'text/html;profile=mcp-app',
    _meta: { ui: {
      csp: { resourceDomains: ['cdn.jsdelivr.net', 'unpkg.com'] },
      prefersBorder: true
    }}
  },
  async () => ({
    contents: [{
      uri: 'ui://mindrian-os/dashboard',
      mimeType: 'text/html;profile=mcp-app',
      text: generateDashboardHtml(roomDir)
    }]
  })
);
```

Iframe communication (in the HTML resource):
```javascript
// Inside the dashboard HTML, communicate with host via postMessage
window.addEventListener('message', (event) => {
  const msg = JSON.parse(event.data);
  if (msg.method === 'ui/notifications/tool-result') {
    updateDashboard(msg.params.content);
  }
});
// Call a tool from the iframe
window.parent.postMessage(JSON.stringify({
  jsonrpc: '2.0', id: 1,
  method: 'tools/call',
  params: { name: 'data_room', arguments: { command: 'analyze' } }
}), '*');
```

**Supported hosts (verified January 2026):** Claude Desktop, Claude.ai, VS Code Copilot, Goose, Postman, MCPJam.

**New dependency:** `@modelcontextprotocol/ext-apps` SDK. Existing assets: HTML templates in `room/exports/presentation/`, Cytoscape.js graph code, De Stijl CSS.

### 7. Cowork Scheduled Intelligence

| Feature | Value Proposition | Complexity | Surface | Notes |
|---------|-------------------|------------|---------|-------|
| Daily room briefing | Larry reports overnight changes, approaching deadlines, new contradictions | Medium | Cowork | Desktop Scheduled Task: daily at 9am. Reads room state, diffs against yesterday's snapshot. Writes to `room/.briefings/YYYY-MM-DD.md`. |
| Prediction deadline tracking | Predictions have expiry dates. Larry warns before they expire. | Medium | Cowork | Reads `room/REGISTRY.json` for prediction entries. Task checks daily, surfaces predictions expiring within 7 days. |
| Competitor watch | Scout's competitor monitoring runs on schedule | Medium | Cowork | Desktop Scheduled Task: weekly. Calls scout tool with competitors task. Needs WebSearch/Tavily MCP access. |
| Room health monitoring | Detect drift, stale sections, abandoned threads | Low | Cowork | Desktop Scheduled Task: daily. Calls scout tool with health task. Pure filesystem analysis. |

**Desktop Scheduled Tasks - verified capabilities:**
- Persistent across app restarts
- Full access to local files, MCP servers, plugins
- Catch-up: one run for most recently missed time (within 7 days)
- Minimum interval: 1 minute
- Each run = fresh session in Desktop sidebar
- Can edit files, run commands, create commits, open PRs
- Permission mode configurable per task (allow rules from settings.json apply)
- Task config: `~/.claude/scheduled-tasks/<task-name>/SKILL.md` with YAML frontmatter

**Key constraint:** Desktop app must be open and computer awake. For always-on intelligence, Cloud Scheduled Tasks work but clone fresh (no local room access unless git-synced). This limits the "Larry never sleeps" value prop to "Larry never sleeps while your computer is on."

**Workaround for always-on:** If room is git-synced, Cloud Scheduled Tasks can clone and analyze. Results written as git commits, pulled by Desktop on next wake. This is a v1.9 consideration.

**Dependency:** No new libraries. SKILL.md prompt files that invoke existing MCP tools. Requires MCP tool parity first (features 1-4).

## Anti-Features

Features to explicitly NOT build.

| Anti-Feature | Why Avoid | What to Do Instead |
|--------------|-----------|-------------------|
| Custom MCP transport for real-time push | MCP resource subscriptions are NOT implemented by Claude Desktop/Cowork clients. Building push would be dead on arrival. | Desktop Scheduled Tasks for periodic intelligence. Accept periodic over real-time. |
| KAIROS-style persistent daemon | Unshipped Anthropic internal (source leak, not official). Building our own daemon fights the platform and may conflict with future KAIROS release. | Desktop Scheduled Tasks + Cloud Scheduled Tasks are the sanctioned patterns. |
| Flat tool registration (64 tools) | Consumes 30-60K context tokens vs ~5000 budget. LLM reasoning degrades with too many tool options. | Hierarchical router: 7-8 routers with z.enum sub-commands. |
| WebSocket-based live dashboard | Sandboxed iframes in MCP Apps communicate via postMessage only. WebSocket to external server violates CSP. | MCP Apps bidirectional postMessage protocol. |
| React/Next.js for MCP App views | Build step, massive deps, bundle size. De Stijl views are self-contained HTML/CSS/JS. | Vanilla JS + CDN libs (Cytoscape, D3). Inline in resource responses. |
| Cross-user intelligence | Requires Anthropic team sharing (not yet available). Privacy controls nonexistent. | Defer to v2.0. Room-level patterns only. |
| State outside room/ directory | Breaks ICM principle (folder IS orchestration). Creates sync issues. | All persistence in `room/.hats/`, `room/.briefings/`, `room/.snapshots/`. |
| MCP Apps on CLI | Terminal cannot render iframes. No value add. | CLI keeps text output. MCP Apps = Desktop/Cowork only. |
| Custom scheduler | Platform provides CronCreate, Desktop Scheduled Tasks, Cloud Scheduled Tasks. Zero value in reimplementing. | SKILL.md files invoking MCP tools. |
| node-cron in MCP server | stdio servers are spawned per-session. Cron in ephemeral process is wasteful. | Desktop Scheduled Tasks handle persistence externally. MCP server stays stateless. |
| chokidar file watching | Resource subscriptions not supported by Claude clients. File watching without notification delivery is useless overhead. | Scheduled tasks poll room state periodically. |

## Desktop vs Cowork Capability Matrix

| Capability | CLI | Desktop | Cowork |
|------------|-----|---------|--------|
| Slash commands (/mos:*) | Full | None - MCP tools only | None - MCP tools only |
| Hook firing (SessionStart, PostToolUse) | Full | None | None |
| MCP tool access | Via plugin commands | Full (stdio) | Full (stdio or Streamable HTTP) |
| MCP Apps (interactive UI) | None | Full | Full |
| Scheduled tasks (session-scoped /loop) | Yes (dies on exit) | Yes (dies on exit) | Yes (dies on exit) |
| Scheduled tasks (persistent) | None | Desktop Scheduled Tasks | Desktop Scheduled Tasks |
| Cloud scheduled tasks | Via /schedule | Via Desktop UI | Via Desktop UI |
| File system access | Full | Full (local) | Sandboxed VM (mounted folders) |
| Brain MCP access | Via .mcp.json | Via claude_desktop_config.json | Via connector config |
| Parallel sessions | Subagent tool | Worktree isolation | Worktree isolation |
| MCP resource subscriptions | Not implemented | Not implemented | Not implemented |
| Bash script execution | Full | Full | Sandboxed (mounted volumes) |

**Key insight:** Desktop and Cowork are functionally identical for MindrianOS. Both speak MCP, both support scheduled tasks, both render MCP Apps. The only material difference is Cowork's sandboxed VM limits file access to mounted folders. All features designed for Desktop work on Cowork if paths resolve within the mount.

## MVP Recommendation

### Phase 1: MCP Foundation (must-ship, enables everything)
1. **Surface auto-detection** - Low complexity, unlocks conditional behavior
2. **15 orphaned command registration** in 2 new routers - Medium complexity, table stakes
3. **Standardized tool output shapes** with `suggested_next` - Medium, enables chaining
4. **Brain-driven routing as MCP tool** - Medium, the moat

### Phase 2: Scheduled Intelligence (high value, medium effort)
5. **Daily briefing** Desktop Scheduled Task - Medium, immediate wow factor
6. **Prediction deadline tracking** task - Medium, unique differentiator
7. **Scout automation** (health + competitors) tasks - Medium, passive value

### Phase 3: Persistent Perspectives (high value, high effort)
8. **De Bono hat scheduled tasks** (6 hats + briefing) - High, core differentiator
9. **Cross-session hat memory** persistence - High, deepens MWP moat
10. **Hat-triggered cascade detection** - High, integrates with proactive intelligence

### Phase 4: Interactive Views (highest effort, highest wow)
11. **MCP Apps dashboard** (De Stijl Mondrian grid) - Very high, visual wow
12. **MCP Apps wiki** (section navigation) - Very high, exploration wow
13. **MCP Apps knowledge graph** (Cytoscape interactive) - Very high, relationship wow

**Defer to Phase 4b:** Bidirectional tool calls from iframe. Read-only views first, interactive later.
