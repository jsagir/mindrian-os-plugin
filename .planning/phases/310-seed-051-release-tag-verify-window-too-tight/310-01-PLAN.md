<objective>
Close SEED-051's core ask: `scripts/release.sh` Step 5.5 must stop crying wolf on a good push.

Today a tag that has not finished replicating on GitHub after the retry window ends the whole
release ceremony on `exit 1`, even though every real release action succeeded. That is exactly
what happened on the v1.15.0 stable release (2026-07-02).

Purpose: a release that demonstrably pushed must close its own boxes (Steps 9.8 / 10 / 11), and
a release that did NOT push must still stop dead. Those two cases have to be told apart by an
independent check, not by trusting `set -e`.

Output:
- `scripts/release-lib/verify-tag-push.sh`, a pure decision function with injectable git probes.
- Step 5.5 in `release.sh` rewired to it: three outcomes (verified / warn / abort) instead of two.
- Two test suites that prove all three outcomes with zero network, zero real push, zero publish.
- A byte-level scope tripwire proving no other gate in the release ceremony changed.

## `scripts/release-lib/verify-tag-push.sh`

A library. It defines functions and nothing else. No `set -e`. No top-level side effects, no
global assignments, safe to source more than once, safe to source under `set -u` (every parameter
expansion guarded with `${VAR:-}`), safe with no colors defined (use `${GREEN:-}`, `${YELLOW:-}`,
`${NC:-}`, never bare `$GREEN`).

```
mos_verify_tag_at_origin <tag_ref> <retries> <backoff_seconds> <expected_main_sha>
```

Injected hooks, resolved by name from the environment:

| Env var | Default | Called as | Contract |
|---------|---------|-----------|----------|
| `MOS_TAG_PROBE_HOOK` | (none, caller must set) | `"$hook" <tag_ref>` | returns 0 if the tag is visible at origin, nonzero otherwise |
| `MOS_MAIN_SHA_HOOK` | (none, caller must set) | `"$hook"` | prints origin's `refs/heads/main` sha on stdout, empty if unreadable |
| `MOS_SLEEP_HOOK` | `sleep` | `"$hook" <seconds>` | pauses |

Return codes (documented as literals in the file header, no globals):

| Code | Meaning | Who prints what |
|------|---------|-----------------|
| `0` | tag visible at origin | library prints the green `  ✓ tag <tag> verified at origin (attempt N/M)` line, wording unchanged from today |
| `10` | tag NOT visible after all retries, BUT origin main sha matched `expected_main_sha` | library prints the yellow warn block; caller continues |
| `1` | tag NOT visible AND main did not verify, or a hook was unusable, or args were missing | library prints a one-line reason; CALLER prints the red recovery block and exits 1 |

Behavior, in order:
1. If fewer than 4 arguments: print `  x mos_verify_tag_at_origin: missing arguments` and return 1.
2. Resolve the three hooks. If `MOS_TAG_PROBE_HOOK` or `MOS_MAIN_SHA_HOOK` is empty or
   `command -v "$hook"` fails: print `  x mos_verify_tag_at_origin: probe hook '<name>' is not
   callable` and return 1. Fail closed. The library never invents a probe of its own and knows
   nothing about git.
3. Retry loop, `attempt` from 1 to `retries`:
   - If `"$tag_probe" "$tag_ref"` returns 0: print the green verified line and return 0.
   - Else if `attempt` is less than `retries`: print
     `  ... tag not yet visible at origin; retry $((attempt+1))/$retries in ${backoff}s`
     (wording unchanged from today) and call `"$sleep_fn" "$backoff"`.
4. After exhaustion, and ONLY then, call the main probe once:
   `remote_main="$("$main_sha_fn" 2>/dev/null || true)"`. Never call it on the success path, so
   the happy path makes no extra network call and its behavior is unchanged.
5. If `remote_main` is non-empty AND `expected_main_sha` is non-empty AND they are equal: print
   the yellow warn block and return 10. The warn block must name the matched short sha and the
   confirm command, for example:
   ```
     ! tag <tag> not visible at origin after N attempts, but origin/main already matches local HEAD (<short sha>)
       The push demonstrably succeeded; GitHub tag replication is lagging. Continuing (non-fatal).
       Confirm later: git ls-remote --tags origin | grep <tag>
   ```
6. Otherwise print one diagnostic line naming why the escalation stands (either
   `origin/main sha '<remote>' does not match local HEAD '<expected>'` or
   `could not read origin/main sha from origin`) and return 1.

The library must never depend on errexit and must guard every command substitution with `|| true`.

The `else` branch becomes:

```
  TAG_PUSH_RETRIES="${RELEASE_TAG_PUSH_RETRIES:-3}"
  TAG_PUSH_BACKOFF_S="${RELEASE_TAG_PUSH_BACKOFF_S:-5}"
  cd "$PLUGIN_DIR"

  release_tag_probe_at_origin() {
    git ls-remote --tags origin 2>/dev/null | grep -q "refs/tags/$1\$"
  }
  release_main_sha_at_origin() {
    git ls-remote origin refs/heads/main 2>/dev/null | awk '{print $1}'
  }
  : "${MOS_TAG_PROBE_HOOK:=release_tag_probe_at_origin}"
  : "${MOS_MAIN_SHA_HOOK:=release_main_sha_at_origin}"

  LOCAL_HEAD_SHA="$(git rev-parse HEAD 2>/dev/null || true)"

  TAG_VERIFY_RC=0
  mos_verify_tag_at_origin "v$NEW_VERSION" "$TAG_PUSH_RETRIES" "$TAG_PUSH_BACKOFF_S" "$LOCAL_HEAD_SHA" || TAG_VERIFY_RC=$?

  if [ "$TAG_VERIFY_RC" = "10" ]; then
    : # non-fatal by design (SEED-051): origin/main already carries this push, so the
      # ceremony must continue to Steps 9.8 / 10 / 11 instead of ending on a false red.
  elif [ "$TAG_VERIFY_RC" != "0" ]; then
    echo -e "${RED}  x tag v$NEW_VERSION NOT visible at origin after $TAG_PUSH_RETRIES attempts${NC}"
    echo "    Investigate: git ls-remote --tags origin | grep v$NEW_VERSION"
    echo "    Recovery: git push origin v$NEW_VERSION (push the tag explicitly)"
    exit 1
  fi
```

The `|| TAG_VERIFY_RC=$?` form is mandatory: it suspends errexit for the call so a return of 10
or 1 becomes a value to branch on instead of a silent script death. Do not use a bare call.
Do not `export` the hook variables; the library runs in the same shell.

Hunk C, the dry-run preview line (currently 237). Keep the `  Step 5.5  : ` prefix and the
`RELEASE_TAG_PUSH_RETRIES` and `SKIP_TAG_VERIFY` mentions, and append the new behavior, for
