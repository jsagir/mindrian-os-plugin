- `lib/core/graph-candidate-producer.cjs` (Plan 04, GDH-05 PRODUCER, D-169-06 -- THE missing fuel):
  `produceCandidates({roomDir, artifactPair, llm}) -> [{source, target, edge_type, reason}]` -- THE
  candidate-edge PRODUCER, the LLM DERIVATION step that runChain `onStep` dispatches. It reads the
  artifact-pair text (incl. the extracted .docx/.html from extractDocText, D-169-03) and PROPOSES candidate
  tuples whose `edge_type` is drawn ONLY from the frozen cascade subset of ALLOWED_EDGE_TYPES
  (CONTRADICTS, CONVERGES, INFORMS, INVALIDATES, ENABLES, REFINES, ROOT_CAUSES). The producer MUST be able
  to emit BOTH CONTRADICTS AND CONVERGES (not CONTRADICTS-only). This is the FUEL the four shipped derivers
  never generate (they only WRITE pre-structured findings; none GENERATE candidates from raw text -- the
  plan-check HIGH-1 finding). `llm` is an injectable function (a deterministic stub in tests) so the loop

  NEVER calls the Brain (brain-derive stays the one Brain-touching deriver, boundary-scanned in Plan 06).

  `runDerivation({roomDir, runChain, selfCritiqueFn, deriveFn}) -> {proposedNodes:[], edges:[], trace}` --
  the runChain composer. `deriveFn` IS the LLM producer above (defaults to
  `graph-candidate-producer.produceCandidates`, injectable for tests). Each runChain step invokes deriveFn
  on an artifact pair and marks the step `material:true` so fable-mode (167 selfCritiqueFn) critiques EACH
  candidate. Only critique-passed candidates flow through the candidate->finding adapter
  `candidateToFinding(candidate)` and are written as a PROPOSED truth-claim NODE (review_status='proposed'

  `rollupSubRooms(parentRoomDir) -> {edges}` -- a RECURSIVE, TRANSITIVE read-side ATTACH (D-169-11 arbitrary
  depth): it walks the NESTED_WITHIN child links of parentRoomDir, and for each child recurses into the
  child's own sub-rooms, so a sub-sub-room's edges roll up to the TOP-level parent. NEVER merges rows into
  the parent (read-side ATTACH only); idempotent re-apply at each nesting level.
