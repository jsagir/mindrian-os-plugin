<objective>
Complete the typed-edge layer and the ranking-input exposure on the projection. Add the documented CLOSED set of edge types (OPERATES + CHAINS / FEEDS_INTO / PREREQUISITE + CROSS_DOMAIN_ANALOGUE; BOG-05) as a frozen ALLOWED_EDGE_TYPES Set mirroring the frozen-bank idiom already in the repo, and expose the reach-ranking signals on every mindrian-operation node that declares a connector (reach_id, sub_mode, hierarchy_rank, posture, sensor_triggers PLUS the OPERATES/CHAINS edges; BOG-07). BOG-07 is elevated to load-bearing: the projection must carry the framework->command->reach chain AND the firing sensor provenance, not just the score signals, so the deferred nav engine can both rank and EXPLAIN.

Purpose: command->framework lives only in the registries as an untyped map, and the chaining (CHAINS/FEEDS_INTO/PREREQUISITE) is hand-wired across the 150.10 session. This plan promotes those into typed graph edges in the projection. Ranking signals (hierarchy_rank, posture, sensor_triggers) live only in connector frontmatter; this plan exposes them as a consumable on the projection node so the nav engine's "what fits" ranking can read them from the projection alone (nav-engine consumption itself is deferred; this plan exposes the inputs + defines the contract). Per Part 8 every edge and every exposed field is generic machinery metadata (framework names, reach_ids, enum/scalar signals), never user content.

Output: scripts/build-orchestration-projection.cjs extended with ALLOWED_EDGE_TYPES + the 5 typed edge emitters + ranking-input fields; data/brain-orchestration-projection.json regenerated with edges[] + enriched nodes; docs/ORCHESTRATION-PROJECTION-CONTRACT.md documenting the closed edge set + node field schema; extended generator tests including the fixture reach-ranking query.
</objective>
