<objective>
Build the orchestration-projection generator as a SIBLING of scripts/build-connector-registry.cjs (Part 7 high reuse: the registries already exist as sources). It reads data/connector-registry.json + data/command-registry.json + a skills/ + agents/ walk + a hand-authored data/cross-domain-analogues.json, and emits data/brain-orchestration-projection.json: a nodes[] + edges[] graph where EVERY node carries a methodology_tier of exactly pws or mindrian-operation (BOG-02), at per-file granularity (BOG-04, one node per command/skill/agent/framework), with the node list DERIVED from the sources (BOG-03, zero hand-authored nodes). This plan delivers the nodes layer + the cross-domain-analogue seed + the OPERATES-edge scaffold; Plan 03 completes the full typed-edge layer + ranking-input exposure.

Purpose: No generator emits a Brain orchestration projection today, and methodology_tier is net-new in the repo (only mindrian_internal exists, on :Person nodes). The futures-gap pain (a command shipping un-wired because the registry was not regenerated) is fixed structurally only once a generated projection plus a --check exist. This plan creates the projection; Plan 04 adds the --check tripwire. Per Part 9 the projection is a Brain-derived LOCAL cache, so the generator makes zero live Brain read/write (it mirrors the connector generator's discipline: the ONLY Brain touch in the connector sibling is a build-time --refresh-names read, which this generator does NOT need because it reads the already-committed registries).

Output: scripts/build-orchestration-projection.cjs (the generator), data/cross-domain-analogues.json (the hand-authored seed), data/brain-orchestration-projection.json (the emitted artifact), and the generator's unit tests.
