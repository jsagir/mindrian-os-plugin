## 1. The thesis (one paragraph)

MindrianOS is already a mature, layered Claude Code plugin (83 commands, 8 agents, 9 skills, 23 hooks, 1 MCP server). The packaging question is therefore not "MCP or Skill" but "how do you ship this cleanly through Claude Code's native marketplace mechanism without depending on third-party hubs." The answer has three parts: (a) publish `@mindrian/os` to npm and let Claude Code's native marketplace mechanism install it via `{"source": "npm", "package": "@mindrian/os"}`; (b) ship a thin `bin/cli.js` solely as a value-add for the Brain key setup wizard + doctor parity (NOT as the install entry point); (c) keep the SessionStart hook idempotent npm-install pattern for runtime dependency management. The MCP server stays. The skills stay. The architecture is correct; only the distribution layer is missing.

## 3. Distribution paths (in order of preference)

### Path A: Native marketplace npm source (PRIMARY)

This is the simplest path. Once `@mindrian/os` is published, the user's marketplace.json points at it directly:

```json
{
  "name": "mindrian-marketplace",
  "plugins": [
    {
      "name": "mos",
      "source": {
        "source": "npm",
        "package": "@mindrian/os",
        "version": "^1.13.0"
      }
    }
  ]
}
```

Claude Code installs from npm natively. No bin CLI required for this path. Verified against `code.claude.com/docs/en/plugin-marketplaces` 2026-05-10. `version` field accepts npm semver ranges. `registry` field optional for private registries.

User-facing install:
```
/plugin marketplace add jsagir/mindrian-marketplace
/plugin install mos@mindrian-marketplace
```

This is the canonical Anthropic-supported flow. **It's also the path that's currently broken because @mindrian/os is unpublished.** Fix this and most install pain goes away.

### Path B: Direct npx invocation (SECONDARY)

For users who want a single-line install without registering a marketplace:

```
npx @mindrian/os install
```

This requires a `bin` field in package.json pointing at `bin/cli.js`. The CLI's `install` subcommand:
1. Detects Claude Code on PATH (prints native installer URL if absent).
2. Adds the marketplace via `claude plugin marketplace add jsagir/mindrian-marketplace`.
3. Installs the plugin via `claude plugin install mos@mindrian-marketplace`.
4. Runs the Brain key setup wizard (prompts for MINDRIAN_BRAIN_KEY, writes to user environment with proper Windows quoting per `feedback_gmail_qp_env_var_corruption`).
5. Surfaces verification: `/plugin marketplace update` + `/mos:onboard`.

Path B is a thin wrapper around Path A. The bin CLI's PRIMARY value is the Brain key wizard + the doctor parity (Path C below). Without those, Path A is sufficient.

### Path C: `npx @mindrian/os doctor` (DIAGNOSTIC)

The bin CLI exposes the same checks `/mos:doctor` runs, but from outside Claude Code so users can run them BEFORE starting a session. This catches the install-cache drift incidents (2026-04-13 #1, 2026-04-28 #2, 2026-05-06 #3, 2026-05-08 Gary case #4) before they become live failures.

```
npx @mindrian/os doctor              # read-only check
npx @mindrian/os doctor --fix        # mirror /mos:doctor --fix logic
npx @mindrian/os update               # wraps /mos:update for CLI users
```

Path C makes the bin CLI worth shipping even though Path A handles the install itself.

## 4. SessionStart hook for runtime dependencies

Anthropic-documented pattern (verified 2026-05-10 against code.claude.com/docs/en/hooks):

```json
{
  "hooks": {
    "SessionStart": [{
      "hooks": [{
        "type": "command",
        "command": "diff -q \"${CLAUDE_PLUGIN_ROOT}/package.json\" \"${CLAUDE_PLUGIN_DATA}/package.json\" >/dev/null 2>&1 || (cd \"${CLAUDE_PLUGIN_DATA}\" && cp \"${CLAUDE_PLUGIN_ROOT}/package.json\" . && npm install) || rm -f \"${CLAUDE_PLUGIN_DATA}/package.json\""
      }]
    }]
  }
}
```

The hook is idempotent: it diffs the plugin's package.json against the data-dir copy and reinstalls only when they diverge. Failure deletes the data-dir copy so the next session retries cleanly. This is the official pattern for managing plugin node_modules and is exactly what mcp-server-brain needs.

**Note on Setup vs SessionStart (Anthropic distinction):** Setup hooks run on `--init / --init-only / --maintenance` only, not on every session. SessionStart hooks fire every session. Plugins requiring per-session dependency reconciliation use SessionStart with idempotent guards (above). Plugins requiring true one-time setup (e.g., DB schema migration) use Setup. MindrianOS uses SessionStart for npm-install-on-drift; Setup is reserved for future use.

## 6. The empirical reality (what's actually broken right now)

Two facts grounded in `scripts/release.sh` + npm registry probes (verified 2026-05-10):

1. **`@mindrian/os` returns 404 on the npm registry.** Never published. Marketplace.json cannot reference it via Path A (the primary distribution path) until it's published.

2. **`scripts/release.sh` has no Step 9.5.** The script has Steps 1-11 with zero `npm publish` invocations. The memory entry `feedback_release_lockstep_npm.md` claims Step 9.5 was added 2026-05-06; the actual file does not contain it. This is a missing feature, not a broken feature.

Both facts converge on a single fix: **ADD an npm publish gate to scripts/release.sh that runs in lockstep with every plugin release.** Without this, Path A (the primary distribution path) is permanently broken.
