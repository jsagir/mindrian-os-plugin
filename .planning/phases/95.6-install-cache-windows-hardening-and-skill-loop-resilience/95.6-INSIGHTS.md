- **Files affected:** 95.6-CONTEXT.md (line 56), 95.6-FAMILY-AUDIT.md (line 72 cluster), 95.6-01-PLAN.md (line 33 self-contradicts with line 64 reference data showing "189 / 80 / 73")

- **Fix action:** Replace 174 with 189 in all three files. Update PLAN line 33 to match line 64.

### CRIT-02: Audit claims Phase 95.2 uses `cp -aT` shell-out

- **Files affected:** 95.6-FAMILY-AUDIT.md Pattern C section + Section 8 implications
- **Source of truth:** `scripts/doctor.cjs:256` uses `fs.cpSync(sourceDir, installNewDir, { recursive: true, dereference: false, preserveTimestamps: true })`. Pure Node, NOT shell `cp -aT`. The 2026-05-06 autopsy at line 36 explicitly says: "performRecoveryAtomic writes the new tree to install.new first via fs.cpSync (Finding A; Windows-functional and exec-free)."
- **Why it matters:** The audit's Pattern C ("scripts can't reach upstream causes") cites `cp -aT` shell-out which 95.2 specifically removed FOR Windows-functionality reasons. This weakens Pattern C's argument. The "Windows-cross-shell" claim is partially undercut by 95.2 already being Windows-functional via `fs.cpSync`.
- **Fix action:** In FAMILY-AUDIT.md, distinguish pre-95.2 (`cp -aT`) from current (`fs.cpSync`). Reframe Pattern C to focus on the install.sh boundary, not the recovery code.

### CRIT-03: D-06 cites "Gary's CC flagged BSL-1.1 in two separate sessions" -- not in source

- **Files affected:** 95.6-CONTEXT.md (D-06, line 103) AND 95.6-FAMILY-AUDIT.md (R-06)
- **Source of truth:** `docs/testers/gary-laben/FEEDBACK.md` 2026-05-09 entry. `grep -i "BSL\|open[- ]source" FEEDBACK.md` returns 0 hits. The canonical tester record does not corroborate the claim.

- **Fix action:** Either add the missing FEEDBACK.md entry from the actual transcript that captured this signal (if it really happened), OR re-ground D-06 on the NATO institutional-trust argument from RESEARCH.md F-06.

### CRIT-04: scripts/release.sh "Step 9.5" does not exist

- **Files affected:** 95.6-CONTEXT.md D-05 (line 85) AND 95.6-FAMILY-AUDIT.md R-06
- **Source of truth:** `scripts/release.sh` has Steps 1-11. There is no Step 9.5. `grep "npm publish\|@mindrian" scripts/release.sh` returns 0 matches.

### CRIT-05: Live Brain key UUIDs in uncommitted FEEDBACK.md

## 3. Important issues (should fix before plan-phase merges to main)

### IMP-01: R-07 (Gary autopsy) has no plan slot

The audit recommends `docs/autopsies/2026-05-09-gary-laben-install-failure.md` (R-07) as a near-term action. RESEARCH.md "Synthesis: What Plans Need to Carry Forward" lists 8 plans (Wave 1 of 5, Wave 2 of 3). None of them includes the autopsy work. Every prior case in the family has an autopsy; case #4 should not ship without one.

**Fix action:** Add a Plan 95.6-09 (Wave 2) that writes the autopsy. OR fold into Plan 95.6-06 (D-04 README manual-recovery) since both are documentation deliverables. The autopsy must be filed BEFORE 95.6 ships as v1.13.0-beta.9, per the family's autopsy convention.

### IMP-02: R-02 partially conflicts with 95.2 SessionStart preflight scope

The audit recommends R-02 (pre-install dependency audit). Phase 95.2 already shipped `scripts/preflight-doctor.cjs` as the 8th SessionStart entry. The audit does not draw the timing-surface distinction between "pre-install audit" (before install.sh runs) and "post-install preflight" (after install completes, on session start).

**Fix action:** Add to 95.6-FAMILY-AUDIT.md R-02: "Pre-install audit runs BEFORE install.sh executes its work; SessionStart preflight (95.2) runs AFTER install completes. Two different surfaces, both required." Prevents a planner from re-architecting what 95.2 already shipped.

### IMP-03: Pattern C in audit is overreached

The audit's Pattern C claims "scripts can't reach upstream causes." But its own R-03 (cross-shell wrapper) and R-05 (settings.json allowlist) directly contradict this -- both operate from script and reach upstream causes. Three of Pattern C's five bullets are reachable from scripts (skill-loop guard, permission allowlist, cross-shell wrapper).

**Fix action:** Reframe Pattern C as "the cure-via-install.sh paradigm has a ceiling; scripts can reach upstream causes only by operating OUTSIDE the install.sh boundary." This is what R-03 and R-06 actually argue.

### IMP-04: PLAN-01 frontmatter `files_modified` understates files touched

PLAN-01 lists only the directory and FEEDBACK.md (lines 7-9). Task 1 also edits CONTEXT.md frontmatter inside the renamed dir. Task 2 may edit any file with a dangling reference.

**Fix action:** Add `.planning/phases/92-trust-layer-refactor/*-CONTEXT.md` to `files_modified`. Add a note: "potentially additional files if dangling references found in Task 2."

### IMP-05: PLAN-01 introduces `full_slug` frontmatter field without canon registration

The new field `full_slug` (which preserves the original 174-char descriptive name for searchability) is not used in any other phase CONTEXT.md. Per Canon Part 7 (Reuse Before Build), introducing a new frontmatter field needs justification.

**Fix action:** Either accept as a one-off and document inline why this directory needs `full_slug` while others don't, OR rewrite PLAN-01 to keep the searchable name in a `## Note` section within the file body rather than frontmatter.

### IMP-06: CONTEXT.md line 191 cites Phase 94 as v1.11.1 (off-by-one)

Phase 93 is the v1.11.1 hotfix per `93-CONTEXT.md`. Phase 94 is v1.11.2. The audit at Section 1 has it correct ("Phase: 93 (v1.11.1 hotfix, 2026-04-29)"). CONTEXT.md cross-references at line 191 has Phase 94.

**Fix action:** Change CONTEXT.md line 191 from "Phase 94" to "Phase 93".

### IMP-07: SEED-007 line 88 contains literal U+2014 + U+2013 inside backticks

The seed advocates a no-emdash scanner and itself contains the characters it bans. Either (a) document codepoints by name ("U+2014 EM DASH") instead of glyph, or (b) document with hex codes (`—`).

**Fix action:** Replace SEED-007 line 88's literal em-dash and en-dash with codepoint references.

## 5. Process recommendations from reviewers

These are not file-level patches but observations that affect how future audit work is done:

### PROC-01: Audit should gate claims by reading source files

Three of four CRIT-01 through CRIT-04 issues would have been caught by simple file reads at audit-write time:
- `cat scripts/release.sh | grep -n "Step\|publish"` would have caught CRIT-04
- `wc -c` on the Phase 92 leaf name would have caught CRIT-01
- A quick read of `scripts/doctor.cjs:256` would have caught CRIT-02

**Recommendation:** future family audits should self-verify each major factual claim with `verified by: <file>:<line>` citations.

### PROC-02: Add a claim-vs-source table at write-time

For future family audits, add a section: "Claim | Source-of-truth file". Two columns. Forces verification at write-time rather than at review-time.

### PROC-03: SEED template extension fields should be canonized

As more seeds adopt extensions (SEED-002, SEED-006, SEED-007 all have `canon_parts`, `binds_to_phase`, `binds_to_milestone`), document the canonical extension set in `~/.claude/get-shit-done/workflows/plant-seed.md` so seed authors converge instead of inventing per seed.

The "Per-tester folder structure" canon should explicitly say "create `replies/.gitkeep` so the empty directory survives git" -- or drop `replies/` from the contract and create per-reply files at the folder root.

### PROC-05: Gary's "scope clarity" finding needs canonical surface

The scope-question gap (does MindrianOS run in every Claude Code project, or only Mindrian-associated ones) appears in three places (REGISTRY Notes, FEEDBACK action item, ROOM cross-reference) but no canonical surface owns the answer. **Recommendation:** add one paragraph to STYLE-GUIDE.md or install-site copy.
