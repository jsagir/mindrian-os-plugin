# Phase 95.6 Plan 05: Statusline-First Install + /mos:doctor Class H + First-Session Self-Check Summary

**install.sh now writes the canonical statusLine block FIRST via an idempotent register_statusline() and records a disk-inspectable .install-receipt.json; /mos:doctor gains class H (install-incomplete) with a --fix that re-stamps the statusLine block; the first-session SessionStart hook auto-runs /mos:doctor and surfaces all-green-or-here-is-what-is-missing -- closing the "silent install-incomplete" gap (D-09).**

## Accomplishments
- `install.sh`: `register_statusline()` (idempotent; writes `{ "type": "command", "command": "bash \"<install-dir>/scripts/statusline-mos\"" }` into `~/.claude/settings.json`) is now called FIRST -- after the node+git preflight and the clone, BEFORE Step 4's command-symlink loop -- so a failure in any later registration step can never again leave the bottom-of-terminal statusline unstamped (the the Wave-2 tester 2026-05-08 + Jonathan "other machine" symptom).
- `install.sh`: writes `~/.claude/plugins/mindrian-os/.install-receipt.json` incrementally -- `receipt_init` right after the clone, then `receipt_step <name> <exit>` after each canonical step (`preflight`, `clone`, `register_statusline`, `register_commands`, `register_skills`, `register_agents`, `configure_hooks`), then `receipt_done` (sets `completed_at`) after the summary. A halted install leaves a partial receipt with `completed_at: null` -- which is exactly what class H reads. Every `receipt_*` call has a `2>/dev/null || true` tail so a receipt write never aborts the install.
- `scripts/doctor.cjs`: new **class H (install-incomplete)** -- reads `~/.claude/plugins/mindrian-os/.install-receipt.json`; if it shows a halted install, names the missing tail steps (`install halted -- missing steps: register_statusline, ...`); if there is no usable receipt, falls back to "does `~/.claude/settings.json` have a `.statusLine` block at all?" (class G assumes one exists and checks it RESOLVES; class H checks it EXISTS). `recoverable` is `true` only when `--fix` can actually help (statusLine block missing, or `register_statusline` is the lone missing receipt step); the missing-tail-steps case is report-only because re-running `install.sh` is the user's call. `--fix` writes the canonical statusLine block idempotently (byte-stable on re-run). Activated by `--statusline-visibility` and `--all`; `skip` on Desktop (mirrors class G's `CLAUDE_DESKTOP` carve-out). Report key: `checks['install-incomplete']`. Renderer adds a 4-zone-compliant row (glyphs within the approved vocabulary -- class F UI-compliance scan still passes). `--help` text extended.
- `scripts/check-onboard-statusline.cjs`: on the fire path (fresh first session / version bump), additionally spawns `node scripts/doctor.cjs --all --json` (1500 ms timeout) and appends a one-line summary to the gate's `additionalContext`: `MindrianOS install check: all green.` or `MindrianOS install check: N item(s) need attention. Run /mos:doctor --fix to resolve, or /mos:doctor --all for details.` Defensive contract intact: any error (doctor missing, spawn timeout, JSON parse failure) returns `''` and the gate is unchanged; the hook still emits `{continue: true}` and exits 0. Pure CJS, node built-ins only, zero npm deps; Canon Part 8 -- no network surface added (doctor.cjs is purely LOCAL).
