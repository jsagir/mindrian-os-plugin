## Why this file exists

D-05b makes the canonical install source the npm package `@mindrian/os`. That marketplace.json lives in a **separate repo** (`~/mindrian-marketplace/`), so plan 95.6-07 -- which runs inside `MindrianOS-Plugin/` -- cannot and should not edit it directly. This note (a) records the exact target shape, (b) records the safe sequencing so a future release-time operator (likely beta.10) flips it correctly, and (c) confirms `@mindrian/os` publishability rides on 95.6-06's Step 9.5 npm gate plus the release-time publish in 95.6-10.

## Current live state (2026-05-11)

`~/mindrian-marketplace/.claude-plugin/marketplace.json` plugin source is the GitHub `url` source with a pinned `ref`:

```json
{
  "name": "mindrian-marketplace",
  "owner": { "name": "Jonathan Sagir" },
  "plugins": [
    {
      "name": "mos",
      "description": "...",
      "version": "1.13.0-beta.8",
      "source": {
        "source": "url",
        "url": "https://github.com/jsagir/mindrian-os-plugin.git",
        "ref": "v1.13.0-beta.8"
      }
    }
  ]

```

`@mindrian/os` currently returns **404 on the npm registry** -- never published. So Path A via npm is not yet wired.

## D-05b target shape (the goal)

```json
{
  "name": "mindrian-marketplace",
  "owner": { "name": "Jonathan Sagir" },
  "plugins": [
    {
      "name": "mos",
      "description": "...",
      "source": {
        "source": "npm",
        "package": "@mindrian/os",
        "version": "^1.13.0"
      }
    }
  ]
}
```

This makes **Path A (marketplace + npm source) the primary distribution path**. Claude Code resolves the npm package transparently; users do not need to know it is npm under the hood. The `version` field accepts npm semver ranges. (Reference: `95.6-PACKAGING-RESEARCH.md` Section 3 Path A; `code.claude.com/docs/en/plugin-marketplaces`.)

## Why not flipped now (safe sequencing -- READ THIS)

Flipping the live marketplace.json to the npm source before `@mindrian/os` is actually published would **break every install** -- Claude Code would try to resolve a 404 package. So the sequencing is:

1. **beta.9 (now):** keep the GitHub `url` source with a pinned `ref` (`v1.13.0-beta.9`). Document the target (this file). Ship `bin/cli.js` + the `bin` field so `npx @mindrian/os doctor` is *ready* to work the moment the package lands.
2. **First live `npm publish`:** happens via 95.6-06's Step 9.5 npm gate during a real `scripts/release.sh` run -- 95.6-10 re-runs the `npm pack --dry-run` payload review as a BLOCKING checkpoint before the first live publish.
3. **Confirm the publish landed:** `npm view @mindrian/os@next version` must return the published beta version (e.g. `1.13.0-beta.10`). Until this returns a non-error string, do NOT flip.
4. **Flip the live marketplace.json (likely beta.10):** change `source` to `{"source": "npm", "package": "@mindrian/os", "version": "^1.13.0"}`, commit + push in `~/mindrian-marketplace/`, then `claude plugin marketplace update mindrian-marketplace`. Optionally keep the GitHub `url` source documented as a fallback for users who explicitly opt out of npm.

**Rule:** the live flip is gated on `npm view @mindrian/os@next version` returning the published version. Never flip prematurely.
