    ```bash
    # Step 5: Register skills
    echo "  . Registering skills..."
    SKILLS_DIR="${CLAUDE_DIR}/skills"
    mkdir -p "$SKILLS_DIR"

    SKILL_REGISTERED=0
    SKILL_SKIPPED=0
    for skill_dir in "$INSTALL_DIR"/skills/*/; do
      [ -d "$skill_dir" ] || continue
      skill_name=$(basename "$skill_dir")
      # D-03 (Phase 95.6): pre-filter -- a skill dir without SKILL.md is
      # structurally incomplete. Skills are non-critical for first-load
      # (commands + agents are the load-bearing surface), so WARN and
      # continue rather than aborting under `set -euo pipefail`. This is
      # the bug that broke Gary Laben's install 2026-05-08/09.
      if [ ! -f "$skill_dir/SKILL.md" ]; then
        echo "    WARN: skipping skill $skill_name: no SKILL.md" >&2
        SKILL_SKIPPED=$((SKILL_SKIPPED + 1))
        continue
      fi
      mkdir -p "$SKILLS_DIR/$skill_name"
      if ln -sf "$skill_dir/SKILL.md" "$SKILLS_DIR/$skill_name/SKILL.md" 2>/dev/null \
         || cp "$skill_dir/SKILL.md" "$SKILLS_DIR/$skill_name/SKILL.md" 2>/dev/null; then
        SKILL_REGISTERED=$((SKILL_REGISTERED + 1))
      else
        echo "    WARN: skipping skill $skill_name: could not link or copy SKILL.md" >&2
        SKILL_SKIPPED=$((SKILL_SKIPPED + 1))
      fi
    done

    SKILL_COUNT="$SKILL_REGISTERED"
    if [ "$SKILL_SKIPPED" -gt 0 ]; then
      echo "    $SKILL_REGISTERED skills registered ($SKILL_SKIPPED skipped -- see WARN above)"
    else
      echo "    $SKILL_REGISTERED skills registered"
    fi
    ```
    Notes:
    - The `[ -d "$skill_dir" ] || continue` guards the case where `skills/*/` glob does not match (defensive).
    - The `if ln ... || cp ...; then ... else WARN; fi` structure means a copy failure no longer kills the script (the `|| cp ... 2>/dev/null` is inside an `if`, so its non-zero status is consumed by the `if`, not by `set -e`). This is the core fix: with `set -e`, a bare `ln ... || cp ...` that fails is fatal; wrapped in an `if`, it is not.
    - `SKILL_COUNT` is reassigned from the real registered count so the summary block (line 178, `$SKILL_COUNT skills`) stays accurate.
    - Do NOT reorder Step 5 relative to other steps -- 95.6-05 owns the call-order reshuffle (it moves statusline registration to first). If you find `register_statusline` already in the file (95.6-05 landed first), leave the new function alone; only edit Step 5.
    - Do NOT touch `set -euo pipefail` at line 10 -- the fix is to make the skill-loop tolerate failure locally, not to disable strict mode globally.
