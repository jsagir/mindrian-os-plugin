# Phase 95.6 Plan 04: install.sh Windows Long-Path Preflight + OS Detection Summary

**install.sh now detects Windows (testably, via `MOS_TEST_FORCE_OS`), runs `git config --global core.longpaths true` with an explanatory banner before the clone so the 260-char MAX_PATH limit cannot break a fresh Git-Bash clone, fails with a named "Git for Windows" error if git is missing on Windows, and cleans a stale partial-clone directory before retrying so the "fires twice on retry" failure mode (the Wave-2 tester, 2026-05-08) is closed.**

## What changed

### 1. OS-detection block (top of `install.sh`, after `REPO`/`INSTALL_DIR`/`CLAUDE_DIR`)

```bash
case "${MOS_TEST_FORCE_OS:-$(uname -s 2>/dev/null)}" in
  windows|Windows|WINDOWS|MINGW*|MSYS*|CYGWIN*) IS_WINDOWS=1 ;;
  *) IS_WINDOWS=0 ;;
esac
```

`uname -s` reports `MINGW64_NT-...` / `MSYS_NT-...` / `CYGWIN_NT-...` under Git Bash / MSYS2 / Cygwin on Windows; `Linux` / `Darwin` otherwise. The `MOS_TEST_FORCE_OS` override lets the Wave 0 fixture (and CI) simulate Windows on a Linux box without an actual Windows machine -- it is the env-var name the Wave 0 test was written against.

### 2. `enable_longpaths_on_windows()` preflight function

Defined right after the OS-detection block. Behavior:
- Non-Windows (`IS_WINDOWS != 1`): `return 0` immediately -- a no-op pass-through, no global git config touched.
- Windows + no `git` on PATH: prints a named error to stderr ("You appear to be on Windows but 'git' is not on PATH." / "Install Git for Windows (it includes Git Bash): https://git-scm.com/download/win" / "Then re-run this installer from the Git Bash prompt.") and `exit 1`.
- Windows + git present: prints a banner explaining the global-config change ("-> running: git config --global core.longpaths true" + a parenthetical noting it is the standard fix for the Windows 260-char path limit and is safe to leave on), then runs `git config --global core.longpaths true`.

**Where it is called:** as the FIRST line of Step 1, *before* the generic `command -v git` check. This is deliberate -- on Windows-with-no-git it exits there with the Windows-specific message; on Windows-with-git it sets longpaths and returns; on non-Windows it returns immediately and the existing generic git/node checks run exactly as before. `grep -c "enable_longpaths_on_windows" install.sh` returns 2 (one definition, one call).

### 3. Stale-partial-clone cleanup (Step 2, clone branch)

The `else` branch (the clone path -- reached when `$INSTALL_DIR/.git` does not exist) now first checks `if [ -d "$INSTALL_DIR" ]`. If the directory exists without a `.git` (a partial clone left behind by a prior failed attempt -- e.g. a MAX_PATH error mid-clone), it prints `. Found a partial/incomplete install at $INSTALL_DIR -- removing it before re-cloning` and `rm -rf "$INSTALL_DIR"` before cloning. The `rm -rf` is *inside* the `[ -d "$INSTALL_DIR" ]`-without-`.git` branch, not unconditional -- a real install (`.git` present) routes to the `git pull` branch and is never removed.
