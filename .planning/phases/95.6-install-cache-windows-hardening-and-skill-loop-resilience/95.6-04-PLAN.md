<objective>
D-01: Add a Windows long-path preflight to `install.sh`. On Windows + Git Bash, run `git config --global core.longpaths true` before the clone, with a banner line explaining the global git-config change so the user knows what was modified. Surface a clear named error if the user is on Windows without git on PATH. Clean up a stale partial-clone directory so a retry-after-failure does not re-trigger the same error. OS-detection idioms (standard, no deps):
- `uname -s` returns `MINGW64_NT-...` / `MSYS_NT-...` / `CYGWIN_NT-...` on Git Bash / MSYS2 / Cygwin on Windows; `Linux` on Linux; `Darwin` on macOS.
- `$OSTYPE` is `msys` / `cygwin` on those Windows shells; `linux-gnu*` on Linux; `darwin*` on macOS.
- `$MSYSTEM` is set (e.g. `MINGW64`) inside Git Bash.
A robust check: `case "$(uname -s 2>/dev/null)" in MINGW*|MSYS*|CYGWIN*) IS_WINDOWS=1 ;; *) IS_WINDOWS=0 ;; esac` -- plus respect `MOS_TEST_FORCE_OS` (`windows` -> IS_WINDOWS=1; `linux`/`mac`/anything-else -> IS_WINDOWS=0) for testability.

         echo "     (this changes your global git config so the clone can create"
         echo "      deeply-nested directories; it is the standard fix for the"
         echo "      Windows 260-character path limit and is safe to leave on)"

         echo "  . Long-path support enabled"
