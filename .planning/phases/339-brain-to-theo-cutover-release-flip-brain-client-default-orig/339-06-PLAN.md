<objective>
The PREP cut's honesty half (D-08, FLIP-04). One new module, one chokepoint edit.

A stale install after the incumbent is suspended lands in one of two refusal kinds, and today
neither tells the user what to actually do:
- `unreachable` says "We can retry in a moment", which is a promise the copy cannot keep against a
  suspended origin.
- `no_key` is where a FRESH stale install actually lands, because a suspended origin makes
  `_tryAutoRegister` fail at `brain-client.cjs:337-346` and the copy then says "registration failed
  (HTTP 503, offline or unreachable)".

Both gain the two-command update path, sourced from ONE new constant module so it cannot drift
across the refusal copy, doctor and docs.

Purpose and its honest limit, which must be stated in the plan, in the code and in the CHANGELOG:
this copy ships in BYTES. An install that has not updated prints the OLD string, because a `main`
commit is not live until released AND picked up. This change is the durable fix for the NEXT
origin move and for honesty; the only levers that reach today's stale population are the soak
window and the tester note. Do not let any artifact imply otherwise.

Output: `lib/core/update-path.cjs` created, `lib/core/refusal-messaging.cjs` amended, two tests
turned green.
</objective>
