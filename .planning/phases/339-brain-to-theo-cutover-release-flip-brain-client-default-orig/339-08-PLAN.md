<objective>
The PREP cut's Tri-Polar half (D-09, FLIP-06). Claude Code CLI needs zero connector change: traffic
goes through the bundled `mindrian-brain` stdio shim and one line moves it. Claude Desktop and
Cowork reach the remote DIRECTLY, and they are moved only by a user editing their own config after
reading these docs.

The connector KEY stays `mindrian-brain`. Only the URL changes, and the `Authorization` header is
dropped. Session T verified 2026-09-03 that a real key, a garbage key and no header return
byte-identical payloads from Theo, and that `/register` answers 200 with an opaque token Theo never
checks, so pre-269 clients are not left dark.

The URL asymmetry is the trap in this plan and it must not be gotten backwards: a direct connector
hits the MCP endpoint itself, so the docs say `https://theo-mcp.onrender.com/mcp` WITH the path.
`lib/core/brain-client.cjs` line 24 takes the BARE origin because the client appends `/mcp` itself.
The two values sit within a few lines of each other in this phase's artifacts, and getting them
backwards produces `/mcp/mcp`, a 404 the client renders as "Brain unreachable" rather than a
config error.

`BRAIN_TOOL_MATCHER` and its byte-identical twins in `hooks/hooks.json` are NOT touched. The
egress guard is keyed on the connector NAME, not the host, which is exactly why D-09 and D-10 are
about the key and not the URL.

Output: five source files edited, two generator chains re-run, one shim's descriptions made
backend-agnostic.
</objective>
