<objective>
Repair the Brain re-derivation trigger so `BRAIN.md` actually regenerates on its three defined
triggers, and wire the explicit-ask surface into the connector spine (D-06 through D-11;
root cause per D-07, fix shape per D-08, flakiness per 245-RESEARCH.md F-6).

Purpose: the full trigger -> queue -> drain -> detached-spawn cascade already ships in
v1.16.0-beta.1 and is hook-wired at `hooks/hooks.json` UserPromptSubmit. It derives nothing.
`scripts/brain-derivation-drain.cjs` captures `start = Date.now()` at line 149, BEFORE
`Q.drain()` lazily requires `folder-memory.cjs` (which pulls `node:sqlite`) and
`brain-client.cjs`. On a cold hook process that load costs 96-191ms against a
`PARENT_BUDGET_MS` of 100, so the `break` at line 158 fires before the first spawn, while
`brain-derivation-queue.cjs:395-398` has ALREADY removed every dispatched entry from the queue.
Every turn since beta.1 has silently vacuumed the queue and spawned nothing. The overrun is
FLAKY, not deterministic (three cold runs measured 162ms, 96ms, 145ms), which is why 15+ warm
in-process tests never caught it. That is F-6's refinement of D-07: the mechanism is certain, the
magnitude is machine-dependent, so a fix validated only by a warm in-process test is not a fix.

This is a BUG FIX, not new build (D-06). No new hook, no new enqueue path (D-10 explicitly
rejects a PostToolUse hook as a Canon Part 7 violation).

Output: a drain that spawns before it commits, a queue whose dry run is non-destructive, a
connector-wired `/mos:brain-derive`, and four tests that pin all three trigger arms plus the
negative case.
</objective>

   - `sections` is an array of section slug strings, the ones the caller actually spawned.
   - Reads the queue via `readQueue`, removes exactly the entries whose `section` is a member of
     `sections`, and rewrites via `writeQueueAtomic` with `version: SCHEMA_VERSION` and the
     surviving entries, using the same atomic tmp+fsync+rename path already in the module.
   - Returns `{ removed: <count>, remaining: <count> }`.
   - Defensive and non-throwing: a non-string `roomDir`, a non-array `sections`, or an empty
     `sections` array is a no-op returning `{ removed: 0, remaining: <current length> }` with no
     write at all. Never throws (the caller is a hook and must stay fail-silent).
   - Idempotent: committing the same section twice removes it once and reports `removed: 0` the
     second time.
