<objective>
Fix G3 (D-04): `wrapDirective()` drops Phase 254's `egress_disclosure` field, making COMP-02 a no-op
on `brain_ask`, the highest-traffic Brain tool.

MEASURED THIS SESSION, and it is worse than 257-RESEARCH.md recorded. `wrapDirective()` is not a
whitelist filter that could be extended; it is a FIXED SEVEN-KEY BUILDER. It constructs a new object
with exactly `packet_version`, `packet_type`, `mode`, `mode_rationale`, `directive`, `user_override`,
`next_gate`, and never copies any other top-level field from `brainResponse`. That answers
257-RESEARCH.md's Open Question 3: the dropping is incidental, not a deliberate moat whitelist.

The new finding: the SAME builder also drops the `refusal` object that the shim's existing Phase
250-01 honest-refusal branch passes in at `bin/mindrian-brain-mcp-client.cjs:119-123`. Measured:

  wrapDirective({directive:{...}, next_gate:{...}, refusal: refusalResponse('unreachable', ...)}, ...)
  -> top-level keys: packet_version,packet_type,mode,mode_rationale,directive,user_override,next_gate
  -> refusal survives? false

So Phase 250-01's own fix is partly vacuous today: only `directive.guided.stage` ("tier_0_unreachable")
and `next_gate.options` survive; the typed refusal itself never reaches the model. Plan 06's G1 fix
clones that same idiom, so without this plan the G1 fix would be vacuous in exactly the same way.

Purpose: make the envelope carry the two honesty fields it currently discards, additively, without
changing a single byte of the envelope for any payload that carries neither.
Output: an additive pass-through plus a test that pins both the survival AND the byte-identical
absence.
</objective>
