<objective>
Baseline honesty (D-10), and the decision D-10 requires be stated either way.

STATED DECISION: the two frozen-literal failures ARE FIXED INSIDE THIS PHASE, not spun out. Reasons.
The fix is two constants in two files, replaced by a read of the file the constant was copied from,
which is small and well understood. The failure is Pitfall 4, the exact anti-pattern this phase
exists to prevent, sitting inside the very suite meant to guard against it, and this phase is about
to add a new test whose entire discipline is derive-never-freeze. Shipping that new discipline while
leaving its counterexample red inside the neighbouring suite would be incoherent. And leaving it red
means every downstream report has to carry an asterisk, which is the sort of asterisk that quietly
becomes permanent.

`bash tests/run-all-239.sh` measured 7 passed, 2 failed on 2026-09-02, pre-existing and NOT caused by
this phase. Both failures share one root cause: `tests/test-239-brain-tool-liveness.cjs:102` and
`tests/test-239-verify-release-section-18.cjs:162` both declare
`const liveMatcherLiteral = 'mcp__(?:plugin_[a-z0-9_-]+_)?mindrian-brain__.*';` while
`hooks/hooks.json` has carried `mcp__(?:plugin_[a-z0-9_-]+_)?(?:mindrian-brain|pws-brain-mcp)__.*`
since 2026-08-19. The literal is used to locate the matcher inside the file so a mutation leg can
stale it; when `indexOf` fails to find it, the setup assertion fails.

This plan runs FIRST in Wave 1 and captures the pre-change baseline for the whole phase, because
257-RESEARCH.md assumption A5 records that the doctor Class O acceptance result was never established
on this tree. A gate whose pre-change state is unknown cannot be reported honestly afterwards.

Purpose: nothing downstream in this phase can claim "suite green" without a recorded baseline to
claim it against.
Output: a baseline record, and two tests that derive the matcher instead of freezing it.
</objective>
