<objective>
Build the permanent answer to "is this still guarded?" (D-06).

This test is the phase's most durable artifact, because the phase itself exists as the cost of not
having it. The 2026-08-20 handoff concluded the four Brain tools were unguarded from
`git grep part8-egress-guard -- bin/` returning zero. That grep was accurate and the conclusion was
false: the shim delegates, and a filename grep cannot follow `brainClient.ask()` into `callTool()`.
Two and a half weeks and one phase were spent on a premise a wire probe would have refuted in a
minute.

So the method is not negotiable. Ground truth, not a grep, following
`lib/mcp/no-instructions.test.cjs`: spawn `node bin/mindrian-brain-mcp-client.cjs` for real, drive
genuine JSON-RPC over stdio, and inspect the actual response bytes, with
`tests/helpers/brain-capture-server.cjs` standing in as the network so "zero bytes left the machine"
is an observation rather than an inference.

And the tool list is DERIVED, never frozen. Pitfall 4 is not hypothetical here: two arms of the 239
suite were red for two weeks because they froze a hook-matcher string, and Plan 05 fixed exactly
that. A frozen tool array in this file would decay the same way, and would silently stop covering a
tool the moment one is added or renamed.

Purpose: make the guarantee structural, so the next session does not have to re-derive it and cannot
accidentally conclude the opposite.
Output: the invariant test, plus the phase's SKIP-safe aggregator.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| shim process -> network | The capture server is the oracle for "did anything leave the machine". Everything else is inference. |
| live tool catalog -> test coverage | A test whose tool list is frozen stops covering what the server actually exposes, while continuing to report green. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-257-30 | Information Disclosure | user content egress to a third-party graph | mitigate | Arm 2 drives a canary through every advertised tool and asserts zero recorded requests plus no canary in the capture record. The belt mutation leg proves the arm fires. |
| T-257-31 | Tampering | enforcement bypass via an unmatched or newly added tool namespace | mitigate | Arm 1 reconciles the expectation map against the live `tools/list` in both directions, so a new or renamed tool fails the test rather than escaping coverage. This is the phase's central thesis expressed as a gate. |
| T-257-32 | Repudiation | a future change silently reverting the honest refusal or the disclosure | mitigate | Arm 3 and Arm 4 assert on parsed wire responses; the two mutation legs in the acceptance criteria prove both arms can fail. |
| T-257-33 | Denial of Service | a guard that blocks unconditionally, the failure mode the open RCA describes for the hook | mitigate | Arm 4 (ambiguous proceeds) and Arm 5 (allow succeeds) both require the guard to discriminate. A block-everything regression fails this suite. |
| T-257-34 | Repudiation | evidence-by-grep creeping back into the proof | mitigate | Prohibited in the action, and the acceptance criteria require a real spawn plus a real handshake as the method proof. |
| T-257-35 | Denial of Service | orphaned child processes or a held port from a failing arm | mitigate | `finally` cleanup required, and a post-run hygiene check is an acceptance criterion. |
| T-257-SC | Tampering | npm/pip/cargo installs | accept | Zero external packages installed this phase (257-RESEARCH.md metadata). The test uses `node:test`, `node:assert` and existing helpers only. |
