<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user session cwd -> Bash tool invocation of `scripts/<name>` | A bare invocation resolves against WHATEVER file sits at that relative path in the user's own working directory, not the plugin's |
| markdown-authored regex predicate -> crafted markdown input | The scanner itself parses untrusted-shaped (author-controlled, not attacker-controlled, but still parsed) markdown text line by line |
| `SCRIPT_ALLOWLIST` exception mechanism -> silent suppression | An unreasoned or dangling-followup exception could silence the gate without a trace |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-274-01 | Elevation of Privilege / Tampering | Every one of the 34+ bare `scripts/<name>` invocation sites this instrument measures | mitigate | This is the phase's own core security finding, not just a usability bug: today, `node scripts/X.cjs` in a user's own Data Room executes whatever `scripts/X.cjs` happens to exist at that relative path in THEIR cwd, not the plugin's. A user's own room, or a malicious file dropped into it, can silently shadow the plugin's script. Anchoring to `${CLAUDE_PLUGIN_ROOT}` closes this local code-execution shadowing vector; the instrument built in this plan is what makes the closure provable and durable. |
| T-274-02 | Denial of Service | The widened `SCRIPT_INVOKE_RE` / `SCRIPT_ANCHOR_SHORT_RE` / `SCRIPT_ANCHOR_LONG_RE` regexes | mitigate | Every quantifier stays bounded and non-nested (T-271-01's existing constraint, reused verbatim), so no crafted markdown line can force catastrophic backtracking. Task 2's action explicitly forbids introducing an unbounded quantifier. |
| T-274-03 | Repudiation | `SCRIPT_ALLOWLIST` exceptions | mitigate | Reuses the EXISTING `validateAllowlist()` (throws at module load on a missing/empty `reason` or a dangling `followup` id) rather than a bespoke, unvalidated skip list -- no new suppression mechanism is introduced. |

No package-manager installs occur in this plan, so no `T-274-SC` supply-chain row applies.
</threat_model>
