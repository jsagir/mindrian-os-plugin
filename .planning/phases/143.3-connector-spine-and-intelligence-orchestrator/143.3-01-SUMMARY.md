# Phase 143.3 Plan 01: Connector Contract Foundation Summary

One-liner: The self-extending Connector Contract foundation -- a documented `connector:` frontmatter schema (CONN-01), a registry generator that descends the nested connector map and walks commands + skills (CONN-02), and the OPEN-1 dispatch-handle to EXACT-framework-name map -- generalizing Phase 122 from the command edge to the whole reach spine.

## What shipped

This plan ships the spine's source-of-truth contract and the build tool, mirroring Phase 122 (workflow-layer) generalized to the entire reach-wiring (Canon Part 7: ~90% reuse, one genuine net-new concern).

### Task 1 -- docs/CONNECTOR-CONTRACT.md (CONN-01) [commit fab400ba]
The `connector:` frontmatter schema reference, mirroring docs/COMMAND-FRONTMATTER.md. Documents all 11 sub-keys (connects_to_spine, sensor_triggers, reach_id, sub_mode, framework, posture, hierarchy_rank, filing, plan_gated, web_scope, surface) with types and meanings; the frozen 5 reach_ids + frozen 3 postures (drift-tested banks); the additive-degrade rule; the Part 8 boundary (framework + web_scope are GENERIC handles only, the only Brain touch is the build-time read-only --refresh-names allowlist read); the 6 routing-table families as worked YAML examples; and the `# --- Phase 143.3 connector frontmatter ---` delimiter convention.

### Task 2 -- scripts/build-connector-registry.cjs + data/connector-registry.json (CONN-02) [commit cbd83b0a]
The generator, copied from the Phase 122 skeleton. Net-new: `parseConnectorFrontmatter` extends the flat hand-rolled parser to DESCEND one indent level into the `connector:` nested map, accumulating indented sub-keys into out.connector with the same value coercions (null, boolean, integer, JSON array, unquoted-bracket CSV, indented dash-list, quote-strip, inline-comment strip). Walks BOTH commands/*.md AND skills/*/SKILL.md (sorted, deterministic). Filters to connects_to_spine === true. Builds a sensor_index (sensor_id -> connectors[]) and a framework_index (framework -> surfaces[]). Applies the WFL-01 build-time guard (framework not in the allowlist -> _unresolved). serializeRegistry strips _unresolved and emits JSON.stringify(clean, null, 2) + newline for stable byte-compare. main() keeps the three branches (--refresh-names / --check / default); brain-client is required ONLY inside refreshNames (Part 8). Emits the registry at 0 connectors (expected pre-retrofit). Exports buildRegistry, serializeRegistry, parseConnectorFrontmatter.

### Task 3 -- data/dispatch-framework-map.json + drift test + registry test entrypoint [commit 24780c11]
The OPEN-1 WFL-01 translation layer: 14 raw sensor dispatch handles / sub_modes mapped to their EXACT framework names (mos:research -> "Hypothesis-Driven Problem Solving", find-bottlenecks/reverse-salient -> "Reverse Salient Analysis", find-connections/cross-domain-connect -> "Usher's Model of Cumulative Synthesis", find-analogies/cross-domain-analogy -> "Four Lenses of Innovation", hsi/whitespace/score-innovation -> "HSI Semantic Surprise Analysis Assistant", think-hats/six-hats/team_perspective -> "Six Thinking Hats"). tests/test-dispatch-framework-map-drift.cjs asserts every mapped value resolves in framework-names.json (reading the explicit framework_names + curated_extras keys, NOT Object.values().flat()), no value is a slug, and mos:research maps exactly. lib/memory/connector-registry.test.cjs asserts --check passes + registry shape + frozen-bank (REACH_IDS/POSTURE_IDS) conformance; tests/test-connector-registry.cjs is the 1-line shared entrypoint.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Block-comment terminator collision in the header doc**
- **Found during:** Task 2 (first generator run)
- **Issue:** The usage comment line `scan commands/*.md + skills/*/SKILL.md -> write` contained the literal `*/` sequence, which prematurely closed the JSDoc block comment and produced a SyntaxError at load.
- **Fix:** Reworded the comment to "scan the commands and skills frontmatter" (no glob literal). The other `commands/*.md AND skills/*/SKILL.md` occurrence is on a `//` line comment and is harmless.
- **Files modified:** scripts/build-connector-registry.cjs
- **Commit:** cbd83b0a (folded into the Task 2 commit)

**2. [Rule 2 - Missing critical functionality] sensor_triggers unquoted-bracket coercion**
- **Found during:** Task 2 (nested parser unit test)
- **Issue:** The Phase 122 flat parser leaves a non-JSON bracket value (e.g. `[SENS-02]`, the natural sensor_triggers shape with unquoted tokens) as a raw string. A connector with `sensor_triggers: [SENS-02]` would have parsed to a string, not an array, breaking the sensor_index build in Plan 02.
- **Fix:** Extended coerce() so a bracketed value that fails JSON.parse falls back to splitting the inner CSV into a trimmed, quote-stripped array (empty `[]` -> []). The indented dash-list form is also supported. Verified all three forms parse to arrays.
- **Files modified:** scripts/build-connector-registry.cjs
- **Commit:** cbd83b0a (folded into the Task 2 commit)
