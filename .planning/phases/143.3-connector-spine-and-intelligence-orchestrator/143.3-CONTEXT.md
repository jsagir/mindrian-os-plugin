# Phase 143.3: Connector Spine + Intelligence Orchestrator - Context

## The one-paragraph why

The Phase-143 sensor spine (`lib/core/insight-sensors.cjs::dispatchSensors`) is built + tested but has ZERO production consumers - every `SENS-0x` fires into the void. This phase ships the FIRST CONSUMER (the `intelligence-orchestrator` skill) AND generalizes it into a self-extending CONNECTOR CONTRACT so any skill/command - existing or future - plugs into the wiring by declaring its connector in frontmatter (Phase 122's `framework -> command` registry pattern, applied to the ENTIRE spine: sensor -> reach sub-mode -> framework -> command -> filing -> posture -> hierarchy-rank). The orchestrator reads a generated `connector-registry.json`, never a hardcoded table.

## Spec (READ THESE - they are the phase research)

- `CONNECTOR-CONTRACT-spine.md` - the universal wiring contract: the `connector:` frontmatter schema, the generator + CI tripwire, the registry, the retrofit, the structural question (own phase = THIS phase). THE PRIMARY SPEC.
- `ROUTING-TABLE-intelligence-orchestrator.md` - the reconciled 6-family routing table (becomes a DERIVED VIEW of the registry, not the source of truth) + the 5-step core loop + OPEN-1..5 (the refinement openers to resolve in planning).
- `RESEARCH-HATS-WIRING.md` - the hat-scoping table, the SENS-04 dispatch, the /mos:research 7-stage pipeline, the Appendix-E 5 handoff triggers, the deep-research escalation, the orchestrator frontmatter.

## Locked decisions (navigator, 2026-06-07)

1. **Live, tier-gated.** The orchestrator calls `dispatchSensors` LIVE each beat (reaches are real, not guessed), gated behind `tier_mode` - degrade to doctrine-sim at tier_0 so it is safe pre-144. It is the PROMPT-side consumer; Phase 144 is the ENGINE-side consumer of the same spine; the two coexist.
2. **Filing = `fileEvidenceWithReadback`** (first consumer of the FILEVAL honesty path) with `wireAccept` as the fallback on readback error; `surfaceFileEvidenceResult` reminds the navigator what landed.
3. **New skill** (`skills/intelligence-orchestrator/SKILL.md`), NOT folded into room-proactive; the two arbitrate via the Intelligence Hierarchy + one-reach-per-beat.
4. **Connector Contract = generated registry** (the navigator's "any skill/command, same connectors, one spine" directive). The orchestrator reads the registry; the routing table is a derived view.

## Requirements

### The Connector Contract (the self-extending spine)
- **CONN-01:** the `connector:` frontmatter schema (per CONNECTOR-CONTRACT-spine.md): connects_to_spine, sensor_triggers, reach_id (frozen 5), sub_mode (render label), framework (exact name, resolver key), posture (frozen 3), hierarchy_rank, filing, plan_gated, web_scope, surface. Additive; absent fields degrade.
- **CONN-02:** the generator (`scripts/build-connector-registry.cjs`, mirror build-command-registry.cjs) + the generated `data/connector-registry.json`. Walks all skill/command frontmatter, emits the registry.
- **CONN-03:** the CI tripwire (`--check`, pre-commit + a run-all suite): every reach_id is one of the 5; every framework resolves via `commandsForFramework()` (the WFL-01 name-drift guard); every posture is one of the 3; no duplicate (sensor, reach, sub_mode) collision. Drift impossible to commit. A WARN when a new methodology command ships without a connector block.
- **CONN-04:** retrofit the algorithmic cohort - the 6 PUSH families + RS / HSI / whitespace / analogies / connections / hats / research declare their connector frontmatter (they already carry framework names from Phase 122). The ~70 other commands + skills retrofit incrementally as touched.

### The Intelligence Orchestrator (the first consumer / the spine reader)
- **ORCH-01:** `skills/intelligence-orchestrator/SKILL.md` - the generic reach dispatcher that READS `connector-registry.json` (never a hardcoded table) and routes. Frontmatter per RESEARCH-HATS-WIRING.md.
- **ORCH-02:** the 5-step core loop: read spine (LIVE, tier-gated) -> map to sub-mode via the registry -> gate to ONE (Intelligence Hierarchy: Tensions > Bottlenecks > HSI > Convergences > Blind Spots; deep_research the sanctioned multi-reach exception) -> offer as a Shape-F Decision Gate (never auto-fire; Part 3) -> on APPROVE resolve via `commandsForFramework(<exact framework>)` (WFL-01) + fire.
- **ORCH-03:** filing via `fileEvidenceWithReadback` (fallback `wireAccept`) + `surfaceFileEvidenceResult` (the FILEVAL honesty remind) + the memory_event + cascade edge (Part 4 / Part 9).
- **ORCH-04:** the live-call tier gate + coexistence with Phase 144 (engine-side) and room-proactive (cascade findings) - one-reach-per-beat across all surfaces, arbitrated by the hierarchy.
