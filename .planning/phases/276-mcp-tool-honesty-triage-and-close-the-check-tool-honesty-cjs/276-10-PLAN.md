<objective>
Stop the substrate from reporting "there is no database" about a database it has just proven
exists.

`lib/core/navigation/spine-events.cjs`'s `_emit` (lines 133-145) calls `_hasRoomDb(roomDir)` first,
which proves the file exists via `fs.statSync(...).isFile()` (lines 114-123). If that passes, it
opens. If the open throws, the catch at line 141 returns
`{ ok: false, reason: 'no_room_db' }` and discards the error entirely, binding it as `_e` and never
reading it. By the time control reaches that line, "no room db" is a statement the code has just
disproven. The only two errors `openRoomDb` can throw there are `RoomDbBusyError` and
`RoomDbBrokenError`, or an unclassifiable stranger it re-throws as itself. None of them means
"no database."

`_emitWithOperatorEdge` (lines 214-223) is a byte-for-byte repeat of the same four lines. **Two
sites, one bug, which is itself the propagation pattern in miniature.**

`room-db.cjs`'s own doc comment names this exact outcome as the thing the typed errors exist to
stop: "Treating a busy room as a cold start is exactly the data-loss path GRAPHDB-02 exists to
close" (lines 148-157), and for the broken case, "a broken room has history that must not be
silently overwritten by a fresh start" (lines 168-175). The typed errors were built.
`spine-events.cjs` throws them away.

**D-276-5 fixes the shape: this is the RETURN-SHAPE variant, not a re-throw.** `spine-events`
cannot re-throw, because its whole contract is a `{ok, reason}` return and its own header at line
24 promises exactly that to every caller. So classify in the catch and return a DISTINCT reason:
`room_db_busy`, `room_db_broken`, and `room_db_open_failed` for the unclassifiable stranger.

**Check `err.name` BEFORE `instanceof`.** `room-db.cjs:157-160` sets `this.name` explicitly and says
why: "so err.name still discriminates across a module-instance boundary, where instanceof can fail
on a duplicated require." `spine-events` reaches `room-db.cjs` through `roomDbMod`, which is exactly
the duplicated-require shape, and this repo has already been bitten by it.

The damage this fixes is upstream of any reason branch. Zero callers branch on
`reason === 'no_room_db'` today, measured. `_emit` returns `{ok: false}` and every caller treats the
event as not logged. On a busy room that is a SILENTLY DROPPED SPINE EVENT: the `memory_event` row
CLAUDE.md calls the local mind's record of what happened simply never exists, and nothing anywhere
reports that it should have. The reason string is what a human or a debug session reads afterward,
and today it says the wrong thing.

M8 is IN as its smallest piece (D-276-5): correct the `room-db.cjs:150-153` comment, because
`timeout: 5000` already IS the retry.

Purpose: make the substrate's status honest at the two sites that lie about it.
Output: typed reasons, a checked F-selector path, and a truthful retry contract.
</objective>
