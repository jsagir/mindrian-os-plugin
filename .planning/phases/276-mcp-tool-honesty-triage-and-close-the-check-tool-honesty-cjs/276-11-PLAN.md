gate_id does not survive a server restart, and nothing says so.**

and the row lands MEDIUM rather than HIGH RISK. **D-276-3 is explicit: do NOT add `minted` to

the word across the surface, and it would treat a vocabulary change as a substitute for saying the
true thing. The rule is fix the claim, not the detector, when the code is right. An in-memory
gate-ledger mint is not persistence, and the phase says so once, in the description.

**`graph_write`'s CAS fail-open (flip-day item c), the strongest of the three.**
`lib/mcp/tools/graph.cjs:226-227`'s `read_version` parameter describe says "a lost update is
rejected as a conflict instead of silently clobbering." Traced end to end:

the write proceeds as if the check passed. It fails open a second time at `:82-85` on a guard read
error. **The behavior is deliberate and defensible; the defect is that the description does not
disclose it.** Theo's own `05-MOS-LEARNING.md` says the same: "fails open on a missing node,
deliberately... Do not read a pass here as proof the node existed."
