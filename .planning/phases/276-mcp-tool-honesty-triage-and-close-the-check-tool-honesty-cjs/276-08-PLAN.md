<objective>
Propagate the proven honesty-fix pattern to the three `lib/mcp/tool-router.cjs` surfaces that still
carry a CLI description over an MCP reference echo.

The framing is load-bearing: **this phase is the propagation pass for the MCP-description layer.**
Phase 273's reviewer named the real thesis, quoted verbatim in the ROADMAP: "several of the good
fixes here were applied at exactly one site and never carried to their siblings." That is precisely
what happened here. The `rooms-open-false-success` RCA fixed this pattern for three orchestration
commands and never carried it to `scout`, to `export`, or to `room_content`'s identical fall-through
group. The fix shape differs from Phase 273's (description strings and response markers rather than
changes-aware SQL) but the failure mode and the remedy discipline are identical.

The four moves, all shipped and proven in quick 260903-kwl on `meeting` (commits `3a35f4f6`,
`2f1f4cf3`, `86c2e1e1`):

1. Rewrite the description to assert no capability the handler lacks, and NAME the surface that
   does have it (`tool-router.cjs:1381` is the worked example).
2. Lead the response with a machine-checkable in-band marker: `noWriteBanner()` yielding
   `**filed: false**` (`:384-394`), or the `NOT EXECUTED.` banner (`:1635-1638`) for a
   declared-but-unimplemented mutation. **Two markers exist. Canon Part 7 forbids a third.**
3. Replace silent omission of a missing reference with an explicit not-found line.
4. Point `Suggested Next` at the real write path instead of asserting completion. The honest
   template already sits two branches from the dishonest one: "Instructions returned - run them,
   then check status to confirm what actually changed" (`:1646`).

Pitfall 2 is the trap. `tests/test-234-tool-description-floor.cjs` enforces a 120-character floor
over the wire across all 36 tools plus a 2048-byte cap, and `tests/test-270-tool-schema-budget.cjs`
holds total description plus schema bytes to a 10 percent drift tolerance. An honesty fix naturally
SHORTENS an overclaiming description. The honest rewrite must ADD a disclosure sentence rather than
delete the claim sentence; `meeting`'s fixed description got LONGER, not shorter. A diff that
removes more description bytes than it adds is the warning sign.

Purpose: close the four HIGH RISK findings and the real half of the seven `export` MEDIUMs.
Output: three honest descriptions, one revised membership rule, and no new marker.
</objective>
