<objective>
Land the one-line GREEN fix for detector bug D-1, correct the checker's own false verification
claim, enumerate its boundaries honestly, and freeze the resulting findings into a checked-in
disposition ledger.

This is the highest-value single item in the phase. `splitBranches` runs its case-label regex over
the MASKED text, in which every string literal including its delimiters is replaced by spaces. So
for `case 'graph-index': {` the masked text reads `case               : {`, `\bcase\s+` greedily
matches 18 characters instead of 5, `idx` lands directly on the colon, the quote check at
`scripts/check-tool-honesty.cjs:541` rejects the label, and every `case` label in the repo is
discarded. `branchMap` is always empty for a switch-dispatched tool.

The consequence measured: 33 branches (`room_state` 5, `room_content` 15, `room_graph` 13) are
classified against their tool's ENTIRE handler body, because `scanAll` builds each branch's
effective text as own plus shared and own is empty. A single write anywhere in a 15-command tool
makes all 15 commands report "a write primitive is reachable." That is a false negative at 33
times the scale of the already-documented `extract_shallow` miss, and it is the structural reason
the first sweep found only one HIGH RISK.

The measured effect of the fix: 10 findings become 24 (5 HIGH RISK, 18 MEDIUM, 1 UNKNOWN, 106 OK
over the same 36 tools and 130 branches), surfacing 4 hand-verified HIGH RISK defects in
`room_content`. Re-measure at execution time rather than trusting these figures; the tree is
shared.

There is a symmetry worth naming in the record: the tool built to catch "claims it did X, did not
do X" contains an instance of that exact defect. Its header comment at lines 559-565 claims the
fall-through grouping was "verified against real fall-through in this codebase (room_content's
new-project/setup/update/help group)." That verification cannot have happened, because the switch
path never produced a label. Correcting that comment is part of this plan, not an aside.

**The sequencing rule is binding.** The RED test already landed alone in plan 276-01, observed
failing. This plan's fix lands in a SEPARATE commit, matching the `209b604f` (RED) / `75278850`
(GREEN) precedent under which this script was built. Any plan whose first task edits a description
string is closing the wrong list; this plan edits no description string.

Purpose: make the real finding list visible before anyone triages it.
Output: a working splitter, an honest header, and the frozen ledger.
</objective>
