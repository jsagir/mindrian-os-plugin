<objective>
Propagate the busy timeout to every opener that can genuinely contend, and name every exclusion
with its reason.

This is Phase 273's Critical C4, and Phase 276 is the fast-follow that phase's own `273-CONTEXT.md`
D-02 registered: "Full propagation of the same fix pattern to its sibling openers (C4's
busy-timeout gap) ... is explicitly OUT of this phase's scope, registered as a fast-follow phase,
not silently dropped." Say that in the SUMMARY. It converts "two Criticals were left unfixed" into
"a named, scheduled commitment is being honored", which is a materially different and more accurate
framing.

The measured state: `grep -rln "new DatabaseSync(" lib/ scripts/` returns 35 files, of which 32 are
production sites after excluding `*.test.cjs` and one vendored type stub. Exactly ONE site carries
`timeout: 5000`: `lib/core/room-db.cjs:259-260`, added by Phase 218-02 D-05. The most-used opener
in the repo, `lib/core/lazygraph-ops.cjs:434`'s `openGraph` with roughly 38 call sites, is a bare
constructor.

**D-276-4 is binding on the fix shape: OPTION-ONLY.** The researcher recommended routing Group A
through `openRoomDb` (assumption A9) and the navigator OVERRULED it. `openRoomDb` is synchronous
and returns a bare handle while `openGraph` is async and returns `{db, conn}` across 38 call sites,
and `openRoomDb` runs a 7-step migration chain on EVERY open, which `tool-router.cjs:594-603`
documents as the exact reason a status-line read must never use it. That is the same roughly
40-file regression shape Phase 273 D-01a already rejected for the `ok` flip. Routing
`lazygraph-ops` through `openRoomDb`, which would also close M12 and C2's residue, is a NAMED
follow-up of this phase, registered in the close-out, not built here.

**Guard against a cosmetic fix.** Adding `{timeout: 5000}` to all 32 constructors and declaring C4
closed would satisfy a grep and change almost nothing, because most of those sites cannot contend.
The honest measure of C4 is "can a contended write on room.db now wait instead of failing in 0ms",
which is exactly what `tests/test-276-busy-timeout-propagation.cjs` asserts with an elapsed-time
floor. Group C (read-only opens) and Group D (`:memory:` and version probes) are EXCLUDED with
`lib/core/room-db.cjs:251`'s own sentence as the stated reason: "a longer wait, never a new failure
mode; WAL readers never block writers." Padding the count is the exact cosmetic-compliance failure
this phase exists to avoid.

Purpose: make a contended room.db write wait rather than fail, at every site where contention is
possible.
Output: the option at every contending opener, and a written exclusion record.
</objective>
