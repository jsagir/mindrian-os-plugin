<objective>
Fix the detector-side half of the triage. Every finding whose root cause is a heuristic bug gets a
detector fix, never an allowlist entry. That is D-276-2, and it is a prohibition rather than a
preference: a proven false positive is a detector fix.

Four detector defects, in descending value order:

- **F-10 Bug B, the barrel re-export (highest value, systemic).** `lib/core/navigation.cjs:562`
  reads `getRoomContext: roomContext.getRoomContext,`, an assignment from another module rather
  than a local function definition. `locateFunctionBody` searches for a definition site in
  `navigation.cjs`, finds none, and the branch reports UNKNOWN. This matters far beyond
  `context_assemble`: `navigation.cjs` is the mandated Canon Part 9 chokepoint and it is a facade
  of re-export assignments, so ANY tool whose only write is a `navigation.<reexport>()` call is at
  risk of reporting UNKNOWN rather than WRITES. Most tools escape today only because they also call
  something else the scanner can resolve. That is luck, not coverage.

- **F-10 Bug A, a STRONG verb matched as a noun.** `lib/mcp/tools/context.cjs:36` ends "Never
  returns raw file contents." `file` is in `STRONG_VERBS`. `isLocallyNegated` requires the negator
  to sit immediately adjacent to the verb, and "Never returns raw " intervenes, so the guard
  misses. A NEGATIVE capability statement is read as a positive persistence claim, which is the
  worst possible inversion.

- **F-2 through F-8, a command name read as a prose verb.** `publish` and `snapshot` are both in
  `WEAK_VERBS`. In `tool-router.cjs:1456` they are COMMAND NAMES inside an enumeration, not verbs.
  This is the identical disease class as the already-fixed `isPartOfHyphenatedToken` guard, which
  caught `rooms-archive` but not a bare unhyphenated command name sitting in its own tool's
  parenthetical command list.

- **F-15 through F-24, the mixed-mode WEAK tier.** `classifyBranch` already discounts a
  tool-scoped STRONG claim to LOW when a sibling branch writes. A WEAK tool-scoped claim on the
  same mixed-mode tool gets no discount and lands MEDIUM. Whether the discount should extend to
  the WEAK tier is a real design question, and this plan answers it once rather than leaving ten
  rows sitting in a bucket nobody decided about.

The underlying honesty issue behind F-2 is real and SEPARATE: the `export` handler is a pure
reference echo whose `Suggested Next` rationales assert "Snapshot generated", "Dashboard
generated" and "Export complete." That half is owned by plan 276-08 and is not touched here.

Purpose: make the finding list reflect real defects rather than heuristic noise, without hiding
anything.
Output: a corrected detector and an amended ledger.
</objective>
