<objective>
Author the Wave 0 RED tests for Layer 2, the local-graph substrate half of this phase.

Layer 2 is the same disease as Layer 1, one layer down. Layer 1 is "a tool says it wrote and did
not." Layer 2 is "the substrate says there is no database when there is one." Phase 273 closed on
2026-08-31 with C4 and C5 deliberately deferred, recorded in its own `273-CONTEXT.md` D-02 as
"registered as a fast-follow phase, not silently dropped." This phase is that fast-follow.

Two tests, both built on a genuinely held foreign write lock:

- **TOOLHON-09 (C4).** The Node 22.16 busy-timeout fix lives at exactly one of 32 production
  `DatabaseSync` openers. The honest measure of C4 is not "how many constructors carry the
  option" but "can a contended write on room.db now wait instead of failing in 0ms." So the test
  asserts an ELAPSED-TIME FLOOR, not merely that no throw occurred. On a Node between v22.13 and
  v22.15 the `timeout` option is silently ignored while the module still loads, so a
  return-value-only assertion would pass vacuously on such a runtime.

- **TOOLHON-10 / TOOLHON-11 (C5).** `spine-events.cjs`'s `_emit` catch block returns
  `{ok:false, reason:'no_room_db'}` for an error that can only be busy or broken, after
  `_hasRoomDb` has already proven the file exists via `fs.statSync(...).isFile()`. The test proves
  the misreport today and pins the corrected typed reasons, plus a run-time census of every
  `no_room_db` producer so the propagation gap cannot silently regrow.

**Do NOT author `tests/helpers/held-write-lock.cjs`.** A working held-write-lock helper already
ships as `tests/helpers/room-db-lock-holder-236.cjs` (Phase 236-03, 121 lines). Building a second
one would reproduce, inside this phase's own test suite, exactly the propagation gap the phase
exists to close.

Purpose: make both Layer 2 fixes provable by observation instead of assertion.
Output: two RED test files.

**WAVE 0 IS RED BY DESIGN.** Both tests exiting 1 at the end of this plan is the CORRECT state.
