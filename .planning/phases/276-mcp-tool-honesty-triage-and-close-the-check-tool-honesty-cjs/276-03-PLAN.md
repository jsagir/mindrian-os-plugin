Author the Wave 0 RED tests that pin the two Layer 1 description defects with the largest blast
radius, so the fixes in plan 276-08 are provable rather than asserted.

`orchestration.scout` is the third confirmed instance of one repeating disease, after
`rooms-open-false-success` (2026-07-27) and `meeting-file-meeting-false-success` (2026-09-03): an
MCP mega-tool description written from the CLI command's behavior, wired over an MCP reference
echo. The description at `lib/mcp/tool-router.cjs:1491` says "The room and scout operations are
ordinary reads and writes, so use them freely" while `scout` falls through to the generic
reference echo at `:1623-1655`, whose `Suggested Next` footer then reads "Scout intelligence
gathered." Nothing is gathered and nothing is written. The CLI `/mos:scout` genuinely writes
(a `.snapshots/` state snapshot, a competitor report, an HSI pipeline run), which is exactly why
the description survived review.

`room_content` is the fourth, fifth, sixth and seventh instances, and they are invisible to the
checker today because of detector bug D-1. The description at `:738` calls itself "the WRITE
surface (new-project, setup, file-opportunity, create-funding, invoke-persona)" while the
`new-project` / `setup` / `update` / `help` fall-through group at `:756-773` is a reference echo,
and `personaOps.invokePersona` at `lib/core/persona-ops.cjs:550-571` is read-only. The honest
counterpoint the tests must encode: four commands (`file-opportunity`, `create-funding`,
`update-funding-stage`, `generate-personas`) DO write, so the description is half true. The fix is
to make the enumeration match the four that actually write.

Purpose: pin both defects before any string is edited, so no fix can be declared done by reading
a diff.
Output: two RED test files.

**WAVE 0 IS RED BY DESIGN.** Both tests exiting 1 at the end of this plan is the CORRECT state.
