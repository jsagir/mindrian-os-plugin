# Phase 369.1 Plan 06: Dependency self-install library Summary

**Frozen, script-free `npm ci --ignore-scripts` self-install with a never-killed detached installer and a dependency-free responder that serves one honest status tool on both protocol eras.**

## Accomplishments

- `buildInstallArgs(descriptor, installArgs, { frozen })` gives `ci --ignore-scripts --no-audit --no-fund` whenever `npm-shrinkwrap.json` exists (the loader's own flags); explicit install args and the no-lockfile form are unchanged (eureka argv test green). `runGuardedInstall` picks `frozen` itself, kills a timed-out foreground npm with SIGKILL (finding 1), and returns `reason`. The SessionStart reconcile fallback and its last-ditch spawn use the frozen form when the shrinkwrap exists; its `{continue:true}` guarantee and cold start are untouched.
- Test seams are inert in production: `MINDRIAN_TEST_NPM_CLI` (an existing path runs as npm-cli.js, a missing one spawns and fails with ENOENT like a machine without npm) and `MINDRIAN_TEST_CONNECT_BUDGET_MS` are read only when `MINDRIAN_TEST_MODE === '1'` (unit arm asserts both ignored otherwise).
- `lib/core/mcp-install-responder.cjs` (266 lines, node built-ins only, requires cleanly from a directory with no node_modules): `initialize` (echoes a known protocol version), `ping`, `tools/list` (exactly `mos_install_status` or `brain_install_status`), `tools/call` (re-reads the status file every call; unknown tool name is an error result), notifications ignored, unknown methods and `server/discover` get -32601, parse errors with a recoverable id get -32700, stdin end and a closed stdout exit 0. Lines for installing, done, failed with reason, and npm-not-found each name the fix; no long dashes.
- `lib/core/dep-install-detached.cjs` and `startDetachedInstall(dir)`: the child claims the status file atomically (link), runs `runGuardedInstall` with the 120 s hook budget, re-checks the production dependency set, writes `done`, `failed` (reason) or `npm-not-found`, exits 0. `ensureDepsPresent({ connectPath: true })` now starts or joins that installer instead of installing in-process and waits only for the remaining process-wide budget; it never kills the installer. A tree whose dependency directories all exist is not trusted while an install is in flight (finding 2).

## Server/discover evidence (Task 2 acceptance)

`server/discover` is answered with JSON-RPC -32601. The test's `versionNegotiation: { mode: 'auto' }` SDK client then falls back to `initialize` and negotiates `2025-11-25 (era legacy)` in 31 to 71 ms for both server names (responder-module arm output). Reading the SDK confirms why: on stdio an `rpc-error` that is not the unsupported-version code classifies as `legacy` and `fallbackAvailable` is true for the auto client. No mirrored discover result was captured because none was needed.

## Measured install timings (this host, real npm 22.x via the recording seam, scratch copy from npm pack, temp npm cache, never the repo root)

- Cold cache: `ensureDepsPresent` on the connect path with a 4 s budget returned in 3,779 ms with `{healed:true, ok:false, reason:'installing', detached:true}`; the detached installer reached `done` 15.9 s after it started (16.3 s end to end); 134 top-level entries in node_modules; recorded argv exactly `["ci","--ignore-scripts","--no-audit","--no-fund"]`; the next start returned `{healed:false, ok:true}`.
- Warm cache (same cache, node_modules and status removed): 3,767 ms to the status answer, `done` after 12.4 s.
- Both are at or below the 17 to 26 s that 369.1-03 measured for the loader-style end to end run (that figure included its own wait), and above the 15 s default connect budget on a cold cache, so the in-band status answer is the normal first experience, as finding 4 said.

## Deviations from Plan

**1. [Rule 1 - Contract] `healed:true` on an unfinished connect-path install**
- **Found during:** Task 3 verify. **Plan text:** return `{ healed: false, ok: false, reason: 'installing', detached }`. **Pinned by test-266 (case 6):** a missing tree whose install did not finish must report `healed === true`, `ok === false`. The plan's own must-have says the 266 tests stay green, so the 266 contract wins; `reason` and `detached` are still returned. The budget-exhausted early return keeps `healed:false, budgetExhausted:true` as before.

**2. [Rule 1 - Contract] Log wording**
- The connect-path breadcrumb reads "self-healing npm install (detached installer) in <dir>" because test-266 process-budget counts that phrase to prove exactly one heal attempt per process. Commit `2c339ae31`.

**3. [Rule 2 - Correctness] Dead-installer and in-flight handling beyond the plan text**
- `installInFlight` (status installing with a live pid and no finishedAt, or a live lock holder) gates the presence probe on the connect path (finding 2); the responder reports a dead installer as stopped rather than "installing"; the child claims the status file atomically so two servers racing at start never run two installers' status bookkeeping against each other (npm stays serialized by the existing install lock).

**4. [Wording] `failed to install` instead of `could not install`** because the pinned unit test requires `/failed/i` in the failed line.
