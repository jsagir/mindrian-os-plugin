# Phase 369.1 input: Desktop plugin install (navigator, 2026-10-04)

## What was measured
- Claude Desktop, Customize > Plugins > Add marketplace, URL `jsagir/mindrian-marketplace`, Sync automatically on: "Marketplace sync failed. Check the repository URL and try again." (two attempts, screenshots in the navigator's session).
- Repo `jsagir/mindrian-marketplace` is PUBLIC, default branch `master`; `.claude-plugin/marketplace.json` is reachable at `https://raw.githubusercontent.com/jsagir/mindrian-marketplace/master/.claude-plugin/marketplace.json` (HTTP 200). The address is not the fault.
- The manifest has one plugin, `mos`, `version: 2.0.0-beta.55`, `source: {"source":"npm","package":"@mindrian_os/cli","version":"2.0.0-beta.55"}` (D-01/D-06 of the release ceremony: npm source, version pinned per cut by RULE 5).
- The same marketplace works from the CLI (`claude plugin marketplace add jsagir/mindrian-marketplace`, `claude plugin install mos@mindrian-marketplace`).

## Why (docs, via the claude-code-guide agent, 2026-10-04)
- Desktop's "Add marketplace" syncs only plugin sources it can fetch itself: github, git, git-subdir, relative path, archive (zip or tar.gz over HTTPS with a sha256 pin). It does not resolve `npm` sources. Private marketplace repos also fail in the Desktop dialog (it does not use the user's git credentials).
- Sources: https://code.claude.com/docs/en/plugins/marketplace-reference#plugin-sources ; https://code.claude.com/docs/en/plugins/host-marketplace#grant-access-to-a-private-marketplace ; https://code.claude.com/docs/en/plugins/install#add-a-marketplace ; https://github.com/anthropics/claude-code/issues/61271 ; https://github.com/anthropics/claude-code/issues/17201

## The second, bigger question (research first)
- The plugin ships its dependencies as `npm-shrinkwrap.json` inside the npm tarball and the loader installs them per machine with `npm ci --ignore-scripts` (Phase 341, RULE 8, `tests/test-341-shrinkwrap-no-dev.cjs`). On the CLI that loader runs from a hook. Desktop is the hookless surface. Open question: on Desktop, who runs the install, and does `bin/mindrian-mcp-server.cjs` (needs @modelcontextprotocol/server, zod, express, ...) start at all after a Desktop marketplace install? Measure before designing; a Desktop-safe loading path may be needed (for example the MCP server entry self-checking `node_modules` and running the install once, or a prebuilt archive that already carries production dependencies within the payload ceiling).
- Interim path that works today (documented for users until this phase ships): `claude_desktop_config.json` with `mindrian-os` -> `node <plugin cache>/bin/mindrian-mcp-server.cjs` and `mindrian-brain` -> `node <plugin cache>/bin/mindrian-brain-mcp-client.cjs` (WSL: `wsl.exe -e node ...`).

## Candidate shape for deliverable 1 (verify, do not assume)
- `archive` source beside the npm source: `https://registry.npmjs.org/@mindrian_os/cli/-/cli-<version>.tgz` with a sha256 computed from the published tarball at cut time, written by `scripts/release.sh` in the RULE 5 lockstep (docs/RELEASE-CEREMONY-RULING-SYSTEM.md).
