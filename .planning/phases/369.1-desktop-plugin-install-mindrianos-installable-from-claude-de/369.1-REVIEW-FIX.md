## Fixed Issues

### CR-01: Install status file is hijackable

**Status:** fixed
**Files modified:** `lib/core/dep-install-status.cjs` (new), `lib/core/mcp-install-responder.cjs`, `lib/core/dep-install-detached.cjs`, `lib/core/mcp-dep-heal.cjs`, `tests/test-369.1-review-fixes.cjs` (new), `tests/test-369.1-dep-self-install.cjs`, `tests/test-369.1-cli-install.cjs`, `tests/run-all-369.1.sh`
**Commit:** f4f5e0700
**Applied fix:** The record moved from a predictable file under the shared `os.tmpdir()` to `<home>/.mindrian/run/dep-install-<hash>.json`. The directory is created 0700 and lstat-checked on every use (a real directory, owned by this user, mode forced to 0700); writes are a fresh `O_EXCL | O_NOFOLLOW` 0600 temp file renamed into place (a planted symlink is replaced, never written through); reads lstat-check the file (regular, owner, not group or world writable, size cap) and open it `O_NOFOLLOW`. What comes back is an allow-listed shape: a known state, a `reason` that must match a fixed pattern (`exit-N`, `timeout`, `npm-not-found`, `installer-error`, `spawn-failed`, `interrupted`, `incomplete: <package names>`; anything else becomes `unknown`), integers and ISO dates. No plugin path is stored and no file path is printed in `instructions`, the tool description or the tool result. A record with no valid start time is never "running", so a planted `{"state":"installing","pid":1}` cannot pin the self-install. The old tests that pinned the tmpdir path and `pluginRoot` in the record were updated (one shared HOME per run). RED against the pre-fix tree: 8 of 8 arm checks.

### CR-02: A half-installed node_modules is trusted whenever the installer died

**Status:** fixed: requires human verification
**Files modified:** `lib/core/mcp-dep-heal.cjs`, `lib/core/dep-install-detached.cjs`, `scripts/sessionstart-npm-reconcile.cjs`, `tests/test-369.1-review-fixes.cjs`
**Commit:** 14a560408
**Applied fix:** `treeTrusted(dir, probe)` now gates `ensureDepsPresent`, the connect-path wait and the SessionStart hook: the dependency directories must exist AND no record may say "installing" without a `finishedAt` (dead installer, stale installer, or running installer all mean the tree is unfinished). An interrupted install therefore re-runs; `runGuardedInstall` removes the partial `node_modules` under the install lock first (the detached installer passes `cleanTree` when it claimed over an interrupted record), and a successful in-process install settles a leftover interrupted or failed record to `done`. The hook leaves a live installer to finish (no blocking wait in a SessionStart hook). Deliberate deviation from the review's sketch: it also required node_modules/.package-lock.json; I did not adopt that, because the existing 266 and dep-heal tests (and any non-npm tree) have none, and the navigator's shape for this finding was the status-based rule. RED against the pre-fix tree (the connect path and the hook ran no npm).

Both entry points catch that, and a budget-spent MODULE_NOT_FOUND for a bare package (starting the installer first), and serve the in-band responder through a new shared `serveInstallResponderFor` helper instead of crashing (decision 8). `runGuardedInstall` stays for the hook path. The dead `if (true) ... else` in the brain entry went away in the same rewrite (IN-03 incidentally). RED against the pre-fix tree: both entries exited 1 with MODULE_NOT_FOUND and npm was killed before finishing.
