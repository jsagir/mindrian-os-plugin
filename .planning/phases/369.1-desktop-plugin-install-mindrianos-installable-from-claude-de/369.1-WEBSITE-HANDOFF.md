## The one thing to know first

Do not put the Desktop install on the public site until the next plugin release is cut and picked up. Everything below works today in a throwaway test marketplace and on the plugin's main branch, but the real marketplace (`jsagir/mindrian-marketplace`) only gets the Desktop copy when the next release is cut (the next beta is held for a Brain-side commit, so there is no date yet). A commit on main is not live until it is released. The five-step terminal-first install on `/` and `/docs/install` stays exactly as it is.

## 1. The Desktop paragraph (ready to adapt, plain and short)

Suggested copy, for `/docs/install` under a "Claude Desktop" heading, after the terminal steps:

> **Using Claude Desktop?** Open Customize, then Plugins, then Add marketplace. Enter `jsagir/mindrian-marketplace` and install MindrianOS. Larry and your rooms work in Cowork and in the Code tab. Chat shows MindrianOS skills and commands, but Chat does not run a plugin's tools, so the room tools are not there.
>
> The first task on a new machine may tell you MindrianOS is installing its packages. That takes a few seconds to about half a minute, once. Ask again and everything is there.

Why it is worded this way (so the page does not over-promise):

- "Installable on Desktop" means Larry plus the room tools in **Cowork** and in the **Code tab**. Claude Desktop's **Chat** ignores a plugin's local tools by design, so Chat gets skills and commands only. A separate Chat extension is a follow-up, not shipped.
- The first-run message is the normal first experience, not an error: a fresh machine has to download the plugin's packages once (measured 17 to 26 seconds here), and MindrianOS answers honestly while that finishes instead of failing.
- Do not mention internal names (the Desktop copy is called `mos-desktop` inside the marketplace; a reader only needs "MindrianOS").

What was actually observed (the page should not claim more): the navigator installed the Desktop copy from a test marketplace and saw it install cleanly, list rooms on the first Cowork task, show both servers connected in the Code tab, and show skills without room tools in Chat. Those are human observations; Desktop's own logs hold no line for them. The real marketplace has not yet been checked on Desktop (that waits for the release).

## 2. Interim path until the next release reaches users (documented, not built)

For a user who wants Larry's tools in Desktop before the release, the older route still works: add two servers to Desktop's `claude_desktop_config.json` by hand.

Where the plugin lives: the folder where Claude installed it (for the terminal install that is `~/.claude/plugins/cache/mindrian-marketplace/mos/<version>/`).

- Released versions up to and including the current beta (2.0.0-beta.55): the two server files are under `bin/`:
  - `node <plugin folder>/bin/mindrian-mcp-server.cjs`
  - `node <plugin folder>/bin/mindrian-brain-mcp-client.cjs`
- From the next release on: the same two files live under `scripts/`:
  - `node <plugin folder>/scripts/mindrian-mcp-server.cjs`
  - `node <plugin folder>/scripts/mindrian-brain-mcp-client.cjs`
  - The old `bin/` paths keep working for one release (small forwarding files), so an existing config does not break at the upgrade. They are removed one release after that, so new instructions should use `scripts/`.
- Desktop on Windows with the plugin inside WSL: wrap the same command, for example `wsl.exe` with the arguments `-e node /home/<you>/.claude/plugins/cache/mindrian-marketplace/mos/<version>/scripts/mindrian-mcp-server.cjs`.
- Never paste a secret into that file. The two server entries need no key and no extra arguments, so the page should show them with none.

Because the interim path asks for a version-numbered folder, it is a power-user note. It does not belong in the five-step install; at most a collapsed "Advanced" block on `/docs/install`.
