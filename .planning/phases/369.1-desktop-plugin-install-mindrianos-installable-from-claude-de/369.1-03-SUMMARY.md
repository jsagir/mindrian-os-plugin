## Findings plans 06 and 10 must honour (measured while proving the tests satisfiable)

1. **A timed-out foreground npm must be killed with SIGKILL (or run async).** `spawnSync(..., { timeout })` sends SIGTERM; a real `npm ci` cleans up slowly, the call blocks well past the budget, and the server then misses the host's ~30 s window. The first throwaway reference failed `initialize did not answer within 25000 ms` until `killSignal: 'SIGKILL'` was set.
2. **Do not trust node_modules after an interrupted install.** `productionDepNames` only checks that each top-level dependency directory exists; a killed `npm ci` (or the detached installer mid-run) leaves those directories present, the next start believes the install is complete and crashes on the first require. The `interrupted install ... connected twice` scenario pins this; the reference passes it by consulting the status file (installing with a live pid) before the presence probe.
3. **The CLI loader usually installs dependencies for a relative-path plugin that ships npm-shrinkwrap.json** (claude 2.1.289: node_modules present after `claude plugin install mos-desktop@...` in 5 of 6 isolated runs, absent in the first probe; absent when the shrinkwrap is removed). It also COPIES the plugin into `<config>/plugins/cache/<marketplace>/<name>/<version>` rather than loading in place. This differs from the docs sentence quoted in the plan. The test therefore deletes a loader-made node_modules before starting servers so the mos-desktop leg always exercises the self-install; `loader-installed-deps: yes|no` is still printed.
4. `claude plugin details mos-desktop@mindrian-marketplace` names the plugin by its plugin.json name: `mos 2.0.0-beta.56 ; Skills 241, Agents 17, Hooks 12, MCP servers 2, LSP servers 0` (printed by the test for the spike record).
5. Cold `npm ci --ignore-scripts` on the current set measured 17 to 26 s end to end in these runs (including the 4 s budget wait), above the 13.3 s research figure; the 15 s connect budget is therefore routinely exceeded on a cold cache and the status-tool path is the normal first experience, not an edge case.
