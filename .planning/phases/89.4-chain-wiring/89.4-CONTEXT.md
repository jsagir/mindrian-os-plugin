### One New Module + Cross-Cutting Wiring
- `lib/core/rs-chain-feeder.cjs` -- engine-choreography codification module
  - Reads Brain FEEDS_INTO topology via brain-client.queryTopology (or equivalent existing API; if missing, uses brain-client.search with allow-listed query parameters)

1. **Upstream Awareness** -- when caller invokes the chain feeder, it consults Brain for required upstream framework state (systems-thinking / hsi_semantic_surprise_analysis / Cynefin freshness check). 2. **Downstream Emission** -- every ReverseSalient output (from 89.2 + 89.3) gains chain metadata block: `{recommended_verb (Canon Part 3 10-verb vocabulary), feeds_into (PWS VP / JTBD / Causal Loop / Navigation Engine), spawn_skill (per §6.4 rule table)}`
3. **Skill-Spawn Rule Table** (per kickoff §6.4 -- 5 rules):
   - high breakthrough (≥7) + structural_transfer → `/mos:find-analogies`
   - high breakthrough (≥7) + market signal (industry-fetcher result count > 0) → `/mos:lean-canvas`
   - cross-methodology discovery (multiple substrate frameworks intersect) → `/mos:pipeline`
   - expert network dense (mapExperts result count > 5 with resolved institutions) → `/mos:persona`
   - low breakthrough (<5) + Cynefin complex (substrate metadata.cynefin === 'complex') → `/mos:think-hats`

### Canon Part 3 Closed-Vocabulary Enforcement

### Skill-Spawn Rule Table (per kickoff §6.4 -- locked deterministic rules)

```js
const SKILL_SPAWN_RULES = [
  { match: (rs, score, opts) => score >= 7 && rs === 'structural_transfer',
    spawn: '/mos:find-analogies', confidence: 0.85,
    reasoning: 'high breakthrough + structural transfer -> SAPPhIRE/TRIZ deepening' },
  { match: (rs, score, opts) => score >= 7 && (opts.industry_signals_count || 0) > 0,
    spawn: '/mos:lean-canvas', confidence: 0.80,
    reasoning: 'high breakthrough + market signal -> business model exploration' },
  { match: (rs, score, opts) => (opts.cross_methodology_substrates || []).length > 1,
    spawn: '/mos:pipeline', confidence: 0.75,
    reasoning: 'cross-methodology discovery -> chained pipeline (RS -> JTBD -> Persona)' },
  { match: (rs, score, opts) => (opts.resolved_experts_count || 0) > 5 && (opts.resolved_institutions_count || 0) > 1,
    spawn: '/mos:persona', confidence: 0.70,
    reasoning: 'expert network dense -> team composition' },
  { match: (rs, score, opts) => score < 5 && opts.cynefin === 'complex',
    spawn: '/mos:think-hats', confidence: 0.65,
    reasoning: 'low breakthrough + Cynefin complex -> perspective diversity' },
];
```

First-match-wins. NULL spawn_skill if no rule matches (= no skill recommended).

### Brain FEEDS_INTO Topology Consumption

Per kickoff §6.3, the engine consults Brain's FEEDS_INTO topology to determine the next legitimate engine hop. Implementation:
- Brain has FEEDS_INTO edges between framework nodes (e.g., RSDiscovery -FEEDS_INTO-> HSI -FEEDS_INTO-> NavigationEngine)
- rs-chain-feeder.cjs lookupUpstream queries Brain for: "Which frameworks feed INTO `reverse_salient_engine` at problem_type=X stage=Y?"
- Brain returns: list of upstream framework IDs + their freshness requirements
- chain feeder cross-references against active room state (per existing folder-memory.cjs reads) to determine if upstream output exists + is fresh
- If upstream missing/stale: returns `{state: 'pause', missing_upstream: [...], suggested_action: 'Run Methodology'}`
- If upstream OK: returns `{state: 'ready'}`

Defensive: if Brain unreachable (per existing isAvailable check), chain feeder returns `{state: 'ready'}` (assume upstream is OK; degrades gracefully).
