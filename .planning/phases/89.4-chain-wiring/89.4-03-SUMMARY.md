# Phase 89.4 Plan 03: rs-chain-feeder skill-spawn rule table Summary

Wires the locked deterministic 5-rule SKILL_SPAWN_RULES table into `lib/core/rs-chain-feeder.cjs` per kickoff section 6.4; first-match-wins; emitChainMetadata propagates the recommendation through the chain metadata block; Canon Part 8 tightened to unconditional auditQueryObject on opts.

## What Shipped

### lib/core/rs-chain-feeder.cjs (in-place enhancement; module.exports byte-identical except additive SKILL_SPAWN_RULES export)

1. **SKILL_SPAWN_RULES** -- Object.freeze'd 5-entry array at module scope; each rule entry is also independently frozen so the table cannot mutate at runtime. Rules in declared order:

   | # | Predicate                                                                  | Spawn                | Conf | Reasoning |
   |---|---|---|---|---|
   | 1 | `score >= 7 && rs === 'structural_transfer'`                               | `/mos:find-analogies`| 0.85 | high breakthrough + structural transfer -> SAPPhIRE/TRIZ deepening |
   | 2 | `score >= 7 && (opts.industry_signals_count or 0) > 0`                     | `/mos:lean-canvas`   | 0.80 | high breakthrough + market signal -> business model exploration |
   | 3 | `(opts.cross_methodology_substrates or []).length > 1`                     | `/mos:pipeline`      | 0.75 | cross-methodology discovery -> chained pipeline (RS -> JTBD -> Persona) |
   | 4 | `(opts.resolved_experts_count or 0) > 5 && (opts.resolved_institutions_count or 0) > 1` | `/mos:persona` | 0.70 | expert network dense -> team composition |
   | 5 | `score < 5 && opts.cynefin === 'complex'`                                  | `/mos:think-hats`    | 0.65 | low breakthrough + Cynefin complex -> perspective diversity |

   Verbatim against kickoff section 6.4 + 89.4-CONTEXT.md §Skill-Spawn Rule Table.

2. **recommendSkillSpawn body swapped** -- Plan 89.4-02 stub replaced by first-match-wins iteration. Returns `{spawn_skill, confidence, reasoning}` with the matched rule's payload, OR `{spawn_skill: null, confidence: 0, reasoning: 'no rule matched'}` when no predicate fires. match() predicates are wrapped in try/catch; a throwing predicate is treated as a non-match so the loop continues. Canon Part 8 auditQueryObject runs unconditionally on opts BEFORE rule evaluation (tightened from the 89.4-02 Object.keys guard).

3. **emitChainMetadata wired internally** -- now calls recommendSkillSpawn(rs_type, safeScore, active_context); the returned chain metadata block carries spawn_skill + confidence + reasoning fields ADDITIVELY on top of the 89.4-02 surface (recommended_verb + feeds_into preserved). active_context is reused as opts for rule evaluation. Backward-compatible: spawn_skill remains string-or-null in BOTH 89.4-02 stub and 89.4-03 wired versions; confidence + reasoning are new additive fields.

4. **module.exports** -- unchanged surface plus additive `SKILL_SPAWN_RULES` export for caller introspection (89.5 Decision Gate UI may iterate to render available skills); lookupUpstream + emitChainMetadata + recommendSkillSpawn + ExternalEgressViolation + CanonVerbViolation + CANONICAL_VERBS all preserved byte-for-byte.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] 89.4-02 Test 4 + Test 9 STUB-specific assertions blocked Plan 89.4-03 GREEN**

- **Found during:** Task 2 GREEN regression run
- **Issue:** test-rs-chain-feeder-core.cjs Test 4 asserted `block.spawn_skill === null` with the message `'spawn_skill must be null in 89.4-02'`, and Test 9 asserted `result.spawn_skill === null` with `'spawn_skill must be null in 89.4-02 stub'`. After Plan 89.4-03 swapped the stub for the rule-table body, these STUB-specific values were no longer accurate -- Rule 1 fires for `structural_transfer + score 8` and returns `/mos:find-analogies`. The plan's must_haves explicitly required "89.4-02 backward-compatibility preserved -- spawn_skill is string-or-null in BOTH 89.4-02 stub AND 89.4-03 wired", which describes a SHAPE invariant. The Test 4 / Test 9 assertions had baked the literal stub VALUE into the regression check rather than the shape.
- **Fix:** Broadened both assertions from `spawn_skill === null` to `(spawn_skill === null) || (typeof spawn_skill === 'string' && spawn_skill.startsWith('/mos:'))`. T9 also broadened `confidence === 0` to `typeof confidence === 'number' && confidence >= 0 && confidence <= 1`, and dropped the stub-text reasoning grep in favor of `reasoning is non-empty string`. The shape contract (string-or-null spawn; numeric confidence in [0, 1]; non-empty reasoning) is now the durable invariant. The other 8 tests in the 89.4-02 suite pass byte-for-byte unchanged.
- **Files modified:** `lib/memory/test-rs-chain-feeder-core.cjs`
- **Commit:** `274a280` (bundled with Plan 89.4-03 GREEN)
- **Why this is Rule 1 (Bug) and not Rule 4 (Architectural):** The fix is test-only; the production module surface is unchanged. The bug was that the Plan 89.4-02 author baked transitional STUB values into "regression" tests, which is a known anti-pattern. The shape contract was always the right thing to assert; broadening the tests aligns them with the contract the plan documented.
