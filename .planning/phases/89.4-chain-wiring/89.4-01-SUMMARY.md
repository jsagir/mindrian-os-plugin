# Phase 89.4 Plan 01: rs-canon-violations Summary

**One-liner:** Foundation module shipping CanonVerbViolation sentinel error + Object.freeze 10-string CANONICAL_VERBS array + strict validateVerb closed-vocabulary checker per Canon Part 3, mirroring the 89.2-01 ExternalEgressViolation sibling pattern byte-for-byte by anatomy while staying semantically distinct.

## What Shipped

`lib/core/rs-canon-violations.cjs` (82 lines) -- the Canon Part 3 enforcement chokepoint:

1. **CanonVerbViolation sentinel error class** -- extends Error; `.name = 'CanonVerbViolation'`; `.meta = {attempted_verb, surface}`. Anatomy mirrors ExternalEgressViolation (89.2-01) byte-for-byte so Canon-aware caller wrappers catch both classes uniformly via `err.name`.

2. **CANONICAL_VERBS frozen 10-string array** in canon-mandated order:
   1. `Run Methodology`
   2. `Reformulate`
   3. `Spawn Sub-Agent`
   4. `Navigate Graph`
   5. `Devil's Advocate` (double-quoted JS string for native apostrophe)
   6. `Scenario Plan`
   7. `Synthesize`
   8. `Bank Opportunity`
   9. `Defer`
   10. `Free-Text` (hyphen, not space)
   `Object.freeze` applied so mutation throws in strict mode.

3. **validateVerb(verb_string, surface?)** -- strict closed-vocabulary checker:
   - Non-string input -> `TypeError('validateVerb: input must be a string; got <typeof>')`
   - Out-of-set string (including `''`) -> `CanonVerbViolation` with `meta.attempted_verb` + `meta.surface` (defaults to `'unknown'`)
   - In-set string -> returns input verbatim

`lib/memory/test-rs-canon-violations.cjs` (218 lines) -- 8 fixture scenarios + suite-end report.
