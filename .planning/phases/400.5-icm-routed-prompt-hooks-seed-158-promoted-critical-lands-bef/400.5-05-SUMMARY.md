## Harness defect found and fixed (recorded, not a change of a pass rule)

The first smoke run gave FAIL with cancel_total 2. The transcript (S1) and stream (S2) sources showed 0. The 2 came from the debug-file reader (S3): it matched the word "timeout" in debug lines that echo the hook's own JSON output (the context text of the seeded missed-turn note holds "hook_timeout"). The reader now treats lines that echo the hook output ("Parsed initial response", "Checking first line for async", "additionalContext") as output, not status. A self-test leg proves that such an echo is not a cancel and that a real "UserPromptSubmit ... timed out" line still is. Commit bcf9502d4. No threshold, deadline, budget or pass rule changed. The smoke was rerun once and passed; the arms ran after the fix.
