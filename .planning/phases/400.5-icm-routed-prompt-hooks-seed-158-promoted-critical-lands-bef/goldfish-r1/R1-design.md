# Goldfish R1, design lens (architecture): NOT READY FOR PLAN, 1 Blocker, 7 Major, 9 Nit

D-01 Blocker (7): count model hides a real miss permanently and drifts. missed = seen - served computed before seen+1; tool usually wins the race (warm 14-35 ms, spike file line 9; command hook pays node cold start), so the single first-prompt miss (G8 case) never shows. "Blocked admin prompt increments neither file" is false: under OR-1 A the tool still runs and does served+1. Invariant-hook timeout and the 24 h stale rule leave served > seen for good, hiding later misses. Fix: per-turn key sha256(session_id + "\0" + prompt); tool appends served keys (ring or multiset); invariant script stores its previous key; on prompt N check only key N-1 (no race); invariant script alone owns missed and noted; state the repeated-identical-prompt edge; T4 runs with the tool faster than the command hook. (Same as Z-01, IR-01.)
D-02 Major (5.1, 7): startedAt = receipt time cannot detect a late start; node:sqlite busy waits and first-call module load are synchronous (lib/core/room-db.cjs:309-310, F-13); stdio not read while blocked. 5.1 last bullet unimplementable; a call 1 s late answers at 3.5 s after the 3 s cancel and counts served. Fix: event-loop heartbeat (50 ms unref timer lastTick, or perf_hooks.monitorEventLoopDelay); origin = min(receipt, lastTick + interval); served only when answerTime - origin <= 2,500 ms; T5 leg: 1.5 s synchronous tool call, hook call during block, assert not served + note next prompt. (Same as IR-04.)
