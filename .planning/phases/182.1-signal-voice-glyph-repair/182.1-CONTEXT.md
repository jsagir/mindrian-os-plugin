# Phase 182.1 - SIGNAL voice-glyph repair

## Why this phase exists

Phase 182 (signal-voice-color-render) shipped the Voice Signature as a BRACKETED COLOR-NAME
WORD (`[BLUE]`) that detectVoiceMark greps for, enforced only as a declared convention. Dogfooding
the v1.15.0-beta.7 tester walkthrough (2026-06-28, navigator Jonathan Sagir) found TWO defects:

1. The mark was DARK at runtime: the instruction lived only in skills/larry-personality (not the
   always-loaded agent body), and test-larry-voice-mark-182.cjs asserted only that the doctrine
   STRING exists, never that a turn emitted a mark. Green test, dark feature. RCA:
   `.planning/debug/voice-signature-dark-runtime.md`.
2. Worse: even when emitted, `[BLUE]` is a WORD NAMING a color, not color. Part 12 requires "make
   VISIBLE BY COLOR." Empirical test on the navigator's host (2026-06-28): ANSI escape codes
   (truecolor AND 256-color AND basic-16) render as LITERAL TEXT - the statusline is colorless too.
   So neither a bracketed word nor ANSI satisfies Part 12 on this surface.

## The fix (navigator-confirmed)

EMOJI carry their own font-rendered color and survive where ANSI dies (verified: the emoji squares
came back colored even through the tool pipe that stripped every ANSI code). The five De Stijl
Mondrian primaries delivered as emoji squares ARE the Voice Signature:

  building = blue square ; challenging = red square ; contradiction = yellow square ;
  gate = black square ; invisibility = white square

The palette is UNCHANGED (the same 5 primaries, no sixth color); only the DELIVERY mechanism moves
from word/ANSI to colored glyph. ANSI background is progressive-enhancement-only where a host paints
it; truecolor when supported.
