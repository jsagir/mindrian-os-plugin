  <action>
    Extend scripts/interpret-whitespace.cjs (created in Plan 01) with three-gate validation functions. Per PITFALLS research Pitfall 2, these gates filter noise before any hypothesis is generated.

    **Add exported functions:**

    1. `anchorGate(gap, gapIndex, umap2d)` -- per Pitfall 2 Gate 1:
       - Uses umap_2d data from whitespace-results.json
       - Check that the gap's nearest_room_artifacts come from at least 2 distinct clusters
       - Approximation: check that nearest artifacts are not all within a small UMAP distance of each other (spread > threshold)
       - If all nearest artifacts cluster tightly together and gap is on the periphery, reject
       - Return { passed: boolean, reason: string }

    2. `brainConsensusGate(gap, brainFrameworkNames)` -- per Pitfall 2 Gate 2:
       - The gap.brain_framework must exist in the Brain's known framework set
       - If the gap references a framework the Brain doesn't recognize, it's noise
       - This gate is simple: does the framework actually exist in Brain ADDRESSES_PROBLEM_TYPE results?
       - Return { passed: boolean, reason: string }

    3. `semanticCoherenceGate(gap)` -- per Pitfall 2 Gate 3:
       - Placeholder for now -- always returns { passed: true, reason: "deferred to hypothesis generation" }
       - Full implementation requires embedding round-trip (generate description, embed, check distance) which happens during hypothesis generation
       - The hypothesis builder in Task 2 will perform this check at generation time

    4. `validateZone(gap, gapIndex, umap2d, brainFrameworkNames)` -- orchestrator:
       - Run all three gates in sequence
       - Return { valid: boolean, gates_passed: string[], gates_failed: string[] }
       - A zone must pass Anchor Gate AND Brain Consensus Gate to be valid
       - Semantic Coherence Gate is advisory (does not block)

    **Wire into interpretWhitespace():**
    - After classification and chain selection, run validateZone on each gap
    - Add `validated: boolean` and `validation: { gates_passed, gates_failed }` to each enriched gap
    - interpretation-results.json includes validation status per gap

    **Update tests:** Add test cases for gate logic using mock UMAP coordinates.
