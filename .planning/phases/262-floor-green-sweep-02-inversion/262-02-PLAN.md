<objective>
Make the floor gate incapable of lying about a payload it cannot read. Today
`probeFramework` distinguishes only "the probe failed" from "the probe succeeded". A
successful HTTP call carrying an envelope the gate does not recognize degrades silently to
`null`, `null` is neither `1` nor `>= 3`, and every row reads MISS. Against Theo (the
designated Brain successor) that composes into `Frameworks passing: 0/28`, exit 1, a
banner reading `FLOOR DOES NOT HOLD`, and zero error signal, indistinguishable from a
genuinely red floor.

Purpose: D-04 (CONTEXT.md), adopting 262-RESEARCH.md's "The Theo Flip" recommendation in
full. This is the small additive track: add a third state, "the probe succeeded but I do
not recognize the payload", and route it through the VOID machinery that already exists
(banner, exit 3, per-row detail, mandatory human re-run). It is correct today regardless
of when the flip lands.

Explicitly NOT in scope (D-04, deferred): adapting the gate's readers to Theo's actual
`{canonical, matched_via, coverage}` and `{framework, score, ...}` shapes.
`theo-mcp.onrender.com` returns HTTP 502 and cannot be exercised, so that adaptation is
flip-day work and belongs with Theo's other seven named adaptation-list files.

Dependency note: this plan depends on 262-01 only for the phase test harness
(`tests/run-all-262.sh`). It has no dependency on FLOOR-01's live run or exit code.

Output: one new hermetic test suite, one additive change to `probeFramework`, zero change
to `evaluateFloor`, zero change to the module's export surface.
</objective>
