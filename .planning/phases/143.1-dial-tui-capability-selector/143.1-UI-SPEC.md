## 1. Design Contract Overview (the non-negotiable terms)

These eight terms are LOCKED. A checker treats any violation as a hard fail, not a style note.

1. **No bespoke scrollable widget.** The interactive chooser renders AS Shape F.1 (Brain-suggestion
   variant) through the host AskUserQuestion primitive. The plugin cannot repaint the cursor, add a
   scroll region, or paginate in-prompt. `MAX_K = 3` is a hard host clamp (`lib/workflow/f-selector-ranker.cjs:77`,
   "clamps caller k to fit the locked mockup row budget"). NEVER raised.
2. **The "dial" is the right-aligned CONFIDENCE COLUMN**, not a scrollbar or a needle widget. The
   navigator reads the dial by scanning the right column: a percentage plus a filled/empty triangle
   glyph hierarchy.
3. **Two separate K's.** `MAX_K = 3` (the AskUserQuestion chooser, untouched) vs a NEW
   `DIAL_REACH_K = 5` (the read-only preview/gauge). "Rank 5, preview 5, choose 3." This split is the
   load-bearing architectural decision.
4. **Recommended marker is a one-glyph triangle swap**, never the literal text "(Recommended)". The
   verified glyphs are `MARKER_RECOMMENDED = '▶'` (filled) and `MARKER_ROW = '▷'` (empty), from
   `lib/hmi/shape-f1-renderer.cjs:58-59`. Filled on reach #1 IFF `mode_a AND score >= 0.7`; reach #2
   ALSO filled only when `score >= 0.7 AND margin < 0.15`. Zero filled markers in Mode B / Tier 0.
5. **Feynman-JTBD labels swap the mechanism-verb rows at render time.** The canonical verb still
   persists to the graph edge; the label is a render-time alias only. 5 frozen template families with
   a runtime `{topic}` slot from `navigation.getActiveFocus` / `getNeighborhood`. The label bank
   carries zero em-dashes and zero banned mechanism nouns.
6. **Tri-polar.** A surface-agnostic structured reach-list core (no ANSI baked in). CLI is the master
   template. Desktop and Cowork consume the same core. Completion is gated on all three mapped.
7. **The 8 anti-patterns (brief Section 8) are explicit DO-NOT fences** (Section 11 below).
8. **Reuse map (brief Section 7) is the build floor.** Net-new is small; everything else is reuse.

## 3. Spacing Scale (terminal grid re-interpretation)

The 8-point pixel scale does not apply to a fixed-width terminal grid. The contract is column budget,
not pixels.

| Token | Value | Usage |
|-------|-------|-------|
| row budget | 3 option rows (hard) | The AskUserQuestion chooser. MAX_K = 3. Plus 2 host-injected trailing rows. |
| preview budget | 5 reaches | The read-only gauge / preview list. DIAL_REACH_K = 5. |
| label column | left-aligned, host-managed width | The WHAT-THEY-GET label text |
| confidence column | right-aligned, fixed 3-4 chars (`87%`) | The "dial" needle position |
| marker gutter | 1 glyph + 1 space before each row | `▶ ` or `▷ ` |
| footer stat-strip | 1 line | "top-3 of N" overflow indicator |

Exceptions: none. The host owns all other spacing; the plugin must not fight it.

## 4. Typography (glyph + weight hierarchy)

Terminal has no font-size axis. "Weight" is expressed through the filled/empty glyph hierarchy and the
right-aligned percentage, which together ARE the visual hierarchy.

| Role | Representation | Hierarchy meaning |
|------|----------------|-------------------|
| Recommended row | `▶` filled triangle + highest % | reach #1 (and #2 on near-tie) in Mode A, score >= 0.7 |
| Standard row | `▷` empty triangle + its % | every other offered reach |
| Confidence value | right-aligned `NN%` monospace | the dial needle position; degrades to markdown bold on Desktop |
| Overflow note | footer stat-strip "top-3 of N" | signals there are more reaches than the 3 shown |
| Cold-room row | `▷` empty triangle + `--` or low % | Mode B / Tier 0; ZERO filled markers by design (Section 6.4) |

## 5. Color (terminal palette re-interpretation)

ANSI color is NOT baked into the surface-agnostic core (brief Section 6: follow the nav-dial
resolve/format split). Color, where the CLI formatter applies it, follows the existing De Stijl
statusline palette. The contract here is the SEMANTIC reservation, not hex values.

| Role | Representation | Usage (reserved for) |
|------|----------------|----------------------|
| Dominant (60%) | default terminal foreground | label text, row bodies |
| Secondary (30%) | dimmed / muted | the confidence column digits, footer stat-strip |
| Accent (10%) | the filled `▶` glyph emphasis | RESERVED for the Recommended marker ONLY |
| Destructive | reserved | not used by this surface (no destructive action in the dial) |

Accent reserved for: the filled-triangle Recommended marker. Never applied to every row, never to the
host cursor. In Mode B / Tier 0 there is NO accent on screen (zero filled markers) -- and that absence
is the intentional design, not a missing state (Section 6.4).

## 6. The Reach-List Data Contract (the surface-agnostic core)

The orchestrator (DIALTUI-01) returns ONE structured object that every surface consumes. No ANSI, no
host-specific formatting. This is the shared source of truth (brief Section 6).

```
ReachList {
  reaches: [ Reach x up to DIAL_REACH_K(5) ]   // ranked desc by score
  tier_mode: 'mode_a' | 'mode_b' | 'tier_0'
  offered_count: int                            // how many cross into the AskUserQuestion chooser (<= MAX_K=3)
  total_count: int                              // N, for the "top-3 of N" footer
}

Reach {
  reach_id: 'context_block'|'contradiction'|'cross_room'|'brain_consult'|'deep_research'
  canonical_verb: string        // persists to the graph edge; NEVER rendered as the row label
  label: string                 // the WHAT-THEY-GET Feynman-JTBD render-time alias (Section 9)
  score: float                  // normalized D4 blend
  source: 'local'|'registry'|'brain'|'blend'
  brain_component: float        // brain_confidence * 0.40  (provenance, explainability)
  local_component: float        // recency_decay + problem_type_bind terms (provenance)
  recommended: bool             // the FROZEN-gate result (Section 7)
}
```

### Scoring (DIALTUI-01, reuse the shipped D4 blend -- do NOT invent a second formula)

- Candidates from `f-selector-ranker.rankForSelector` called with `DIAL_REACH_K = 5`.
- Per-reach score = `brain_confidence*0.40 + (1-recency_decay)*0.30*investment_level + problem_type_bind*0.30*investment_level`, normalized.
- REMOTE Brain contributes `brain_confidence` (weight 0.40, always on), pre-derived at session time from
  BRAIN.md (`pattern_matches` / `framework_chain_predictions`). ZERO live Brain calls at render time
  (pure, sync, LOCAL-only). Remote influence is pre-baked through the brain-derivation chokepoint
  (generic handles only, Part 8 clean).
- LOCAL graph contributes `recency_decay` and `problem_type_bind` (both gated by `investment_level`),
  plus neighborhood density via `graphAdjust` for the margin/tie test.
- Registry-only reaches default `brain_confidence = 0.5`, so they can never solo-cross 0.7. A cold room
  with no BRAIN.md renders 5 reaches with ZERO markers -- correct by design (Section 6.4).

## 6.1 Component Anatomy

The surface has two stacked components driven by the SAME ReachList:

```
+---------------------------------------------------------------+
|  [A] STATUSLINE GAUGE (D2, CLI only)                          |
|      Investigate | Blend | >Insight<     <- needle, read-only |
+---------------------------------------------------------------+
|  [B] F.1 CHOOSER (the interactive selector, all surfaces)     |
|      Brain-suggestion variant, hard 3 rows                    |
|      label column ............................. NN%  <- dial  |
|      label column ............................. NN%           |
|      label column ............................. NN%           |
|      [footer stat-strip: top-3 of 5]                          |
|      (host-injected: "Type something" / "Chat about this")   |
+---------------------------------------------------------------+
```

- [A] is the read-only preview/gauge (DIAL_REACH_K=5 informs the needle band; the needle itself reuses
  `nav-dial.resolveDialPosition` / `formatDialSegment`). Not interactive.
- [B] is the interactive chooser. Hard 3 rows (MAX_K=3). The "dial" is the right-aligned confidence
  column inside [B]. Overflow beyond 3 is surfaced in the footer stat-strip and routes to the
  host-injected free-text row -- never to in-prompt pagination.

The confidence-column dial: each row ends with a right-aligned `NN%` and is prefixed by `▶` or `▷`.
Scanning the right column top-to-bottom IS reading the dial. This is canon-legal graded ranking without
a widget the host will not give us.

## 7. State Matrix

Five render variants. The marker logic (DIALTUI-02) is the frozen gate, reused verbatim, applied
per-reach.

### The frozen Recommended gate (never re-tuned without an INTERFACE_VERSION bump)

```
reach#1.recommended = (tier_mode == 'mode_a') AND (reach#1.score >= 0.70)
reach#2.recommended = (tier_mode == 'mode_a') AND (reach#2.score >= 0.70)
                                              AND ((reach#1.score - reach#2.score) < 0.15)
all other reaches    = false
```

`0.70` is the FROZEN floor. `0.15` is `MARGIN_THRESHOLD`. NEVER lower 0.70 to force a second marker.

| # | State | tier_mode | Filled `▶` markers | Render rule |
|---|-------|-----------|--------------------|-------------|
| S1 | Mode A, clear leader | mode_a | exactly 1 (reach #1) | reach #1 gets `▶` + highest %; rows 2-3 get `▷`. The common case. |
| S2 | Mode A, near-tie | mode_a | exactly 2 (reach #1 + #2) | reach #1 AND #2 get `▶` (they co-lead, margin < 0.15); row 3 gets `▷`. |
| S3 | Mode B (Local Only) | mode_b | 0 | every row gets `▷`. No %-as-confidence claim of "recommended"; the 0.7 gate is a Brain-only concept. Looks INTENTIONAL (Section 6.4). |
| S4 | Tier 0 cold-room | tier_0 | 0 | hardcoded minimal reach set, all `▷`, confidence shown as `--` or low registry-default %. The zero-marker state is DESIGNED, not broken (DIALTUI-11). |
| S5 | Partial-slot label degradation | any | per the gate above | a reach whose `{topic}` slot cannot resolve drops its label to the generic JTBD one_line (Section 9 ladder); marker logic is unchanged -- only the label text degrades. |

### 6.4 The "looks intentional" mandate (DIALTUI-11, explicit)

The Mode B / Tier 0 zero-marker dial MUST read as a deliberate "all options equal weight, navigator
decides" state (Canon Part 3, Section 6.2), NOT as a broken or still-loading dial. Concretely:

- All five (or the Tier-0 minimal set) reaches render with the `▷` empty marker, evenly.
- A one-line framing accompanies the chooser so the absence is explained, e.g.
  "No recommendation -- offline. You pick." (Mode B) or
  "New room -- nothing to rank yet. Start anywhere." (Tier 0).
- The confidence column shows `--` (Tier 0, no signal) or the honest low registry-default % (Mode B),
  never a fake high number and never a blank that reads as a render failure.
- A checker scores this as a first-class dimension (Section 12, V7): a cold-room screenshot must be
  visually distinguishable-as-intentional from a populated Mode A screenshot.

## 8. Interaction States

A single `closeReach()` transaction (DIALTUI-09) has four explicit outcomes, all routed EXCLUSIVELY
through `navigation.cjs` (never `room.db` directly).

| Interaction | Trigger | Edge / event written | Notes |
|-------------|---------|----------------------|-------|
| Resting-detent commit (intent-sync) | navigator commits the recommended detent WITHOUT rotating | `SELECTED_REACH` edge (DIALTUI-08) + positive `f_selector_sync_confirmed` event (DIALTUI-07) | Committing without rotating IS the "yes, in sync" signal. One keystroke, zero extra prose. |
| Rotate-to-pivot commit | navigator commits OFF the recommended reach | `PIVOTED` edge (DIALTUI-06) FROM chosen TO declined-recommended, ENUM-only props `{declined_recommended:'cmd:...', margin, decision_id}` + `f_selector_pivot` event, PLUS the `SELECTED_REACH` edge | "Why not the recommendation" becomes graph data (Canon Part 4). Feeds an investment_level-scaled pivot-penalty back into the ranker. No free text captured. |
| Defer / reject | navigator defers or rejects via the existing path | `DEFERRED` (+30d) or `REJECTED` edge via `recordSelectorDecision` | Reuses the shipped `selector-decisions.cjs` cascade idiom (DEFERRED / REJECTED already in `ALLOWED_EDGE_TYPES`). |
| Free-text / none-fit overflow | navigator uses the host-injected free-text row ("top-3 of N" did not contain the fit) | `recordSelectorMiss({top_k_offered, user_intent})` | NEVER add a 4th explicit Free-Text row (collides with host-injected rows -- anti-pattern). |

### The explicit "are you in sync?" surface

Reserved ONLY for the `DECISION_GATE` operator (the one operator `resolveOffer` always fires for).
Everywhere else, keep the shipped abstention triple (margin floor 0.15, strong-signal 0.30,
consecutive-ignore suppression): the dial simply does not appear when Larry is not confident. Do not
add a second "in sync?" prompt for ordinary reaches -- the resting detent IS the signal.

### Every committed reach also writes Layer-3 state

Closes the Canon Part 3 Layer-3 gap (DIALTUI-08): a `SELECTED_REACH` edge FROM active focus TO
`cmd:<command>` with props `{jtbd, framework, recommended, decision_id}`, PLUS a STATE.md Decisions row
or a TodoWrite next-action (reuse the wikilink injector). `SELECTED_REACH` is system bookkeeping
(exempt from human-confirm per the Part 9 audit-node carve-out); if the reach also promotes a
truth-claim node, THAT promotion still routes through `confirmNode` with a human `byUser`. Keep the two
writes distinct.

## 9. Label-Bank Contract (Feynman-JTBD, DIALTUI-04 + DIALTUI-05)

The dial table is authored in MECHANISM language -- exactly what the navigator must NOT read. A
deterministic hybrid label composer (`lib/hmi/dial-label-composer.cjs`, modeled on
`lib/core/rs-query-to-text.cjs`) swaps the mechanism-verb rows for WHAT-THEY-GET labels at render time.
The canonical verb still persists to the graph edge.

### The 5 frozen template families (WHAT-THEY-GET voice)

| reach_id | Template | Slot source |
|----------|----------|-------------|
| `context_block` | "Pull up what we decided about {topic}." | `navigation.getActiveFocus` |
| `contradiction` | "Show where {topic_a} and {topic_b} pull against each other." | `getNeighborhood` (two nodes) |
| `cross_room` | "Bring in what {room_name} already worked out about {topic}." | acknowledged room switch + focus |
| `brain_consult` | "Suggest the next move for {framework_or_situation}." | `{framework}` is a GENERIC handle (Part 8) |
| `deep_research` | "Go find out what the world knows about {topic}, framed through {framework}." | `{framework}` GENERIC handle (Part 8) |

### Composer rules

- Hybrid, not pure-static, not per-turn-LLM. One frozen template per reach + a runtime `{topic}` slot
  filled from the active focus node via `navigation.getActiveFocus` / `getNeighborhood`. Never the raw
  message, never `room.db` directly. FNV-1a deterministic pick (matters on CLI; matters less on Desktop).
- Style gate at authoring time: every template passes the feynman-prompts Stage-2 contract (everyday
  words, say-it-out-loud test, zero jargon, hyphens only).
- Degradation ladder (DIALTUI-04, must cover partial slots, not just cold start):
  1. full focus -> fill `{topic}`
  2. recent message only -> noun from the message
  3. unresolvable slot (e.g. contradiction with one node unfetched) -> drop to the generic JTBD one_line
  - NEVER render a raw `{topic}` slot.

### Drift test (DIALTUI-05)

Assert the template bank contains:
- ZERO em-dashes
- ZERO banned mechanism nouns: `Context Block`, `contradiction surface`, `cross-room`, `Brain consult`,
  `deep research plan` (the bank must contain none of its own source mechanism terms)
- coverage of EXACTLY the 5 canonical reach ids -- no more, no fewer
- Also fix the 7 pre-existing em-dashes in `jtbd-taxonomy.json` (lines 71, 197, 227, 285, 346, 379, 387).

## 11.1 Part-8 Egress-Audit Seam (Brain + deep-research labels)

The `brain_consult` and `deep_research` labels carry a `{framework}` slot. Per brief Section 4 and Canon
Part 8:

- These two labels MUST pass the dual-egress audit seam (the `rs-query-to-text.cjs` Part-8 audit pattern)
  BEFORE their `{framework}` slot can become an outbound query.
- The other three labels (`context_block`, `contradiction`, `cross_room`) are render-only and never
  egress.
- The seam enforces that only a GENERIC handle (framework name, phase id, problem type) crosses; raw
  user artifacts, numbers, names, and meeting text never reach the Brain or the web. The default on
  ambiguity is: do not egress.
- This mirrors the shipped Phase 90 / Phase 110 tripwire idiom (chokepoint + audit + adversarial
  fixtures). The drift test (DIALTUI-05) plus this seam together guard the boundary before any consumer
  lands.
