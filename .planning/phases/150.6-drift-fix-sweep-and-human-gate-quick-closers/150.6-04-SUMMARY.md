Recorded here as a deviation extension of Phase 150.6 (not a planned 150.6-04 task). Scoped fix for the DETECTION half of RCA `.planning/debug/plugin-silent-disable-after-cc-self-upgrade.md`.

**Gap.** When `claude plugin update mos@mindrian-marketplace` collides with a Claude Code self-upgrade, the plugin can land DISABLED -- its `enabledPlugins["mos@mindrian-marketplace"]` flips to `false` in `~/.claude/settings.json`. Every prior detector lived in plugin SessionStart hooks, which do NOT run while the plugin is disabled. Zero code checked the enabled flag (verified by grep).

**Built (commit `078c1b3c` -- `fix(150.6): DRIFT-12 add class N plugin-enabled-state silent-disable detector`).**

1. `lib/core/check-plugin-enabled.cjs` -- pure, sync, read-only probe. `checkPluginEnabled(opts) -> {installed, enabled, key, settings_path}`. Reads `enabledPlugins` + `installed_plugins.json`; test seams for both paths via `opts`. `enabled=null` when the key is absent (older CC) = "unknown, not an error". Never throws. Defensive on both key shapes (`mos@...` / `mindrian-os@...`). NEVER writes settings.json.
2. `scripts/doctor.cjs` -- class N wired in the existing class-roster idiom. Runs on a BARE `doctor` run AND under `--all` (the accumulative-engine trigger), NOT behind a class flag -- because a disabled plugin's own hooks cannot run, so the check must fire with no flag. `installed && enabled===false` -> CRITICAL (`warn`, red) with detail "this state is the silent-disable failure (install-cache family case 7)" + fix `claude plugin enable <key>` (or /plugin in the TUI). `enabled===true`/`null` -> OK. Bare run exits 1 on CRITICAL; `--all` keeps the graceful-degradation exit-0 invariant.
3. **Load-bearing surface confirmed** -- `node bin/cli.js doctor` (the `npx @mindrian_os/cli doctor` entry) resolves the active plugin from the on-disk install cache and reaches class N + propagates the non-zero exit WHILE the plugin is disabled. The cache + npm package exist on disk regardless of the enabled flag.
