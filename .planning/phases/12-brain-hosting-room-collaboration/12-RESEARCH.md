# Phase 12: Brain Hosting + Room Collaboration - Research

**Researched:** 2026-03-25
**Domain:** Remote MCP server deployment (Streamable HTTP), API key auth, git-based room sync
**Confidence:** HIGH

## Summary

Phase 12 delivers two independent capabilities: (1) a remote Brain MCP server that wraps Neo4j and Pinecone behind a single API-key-gated endpoint on Render, and (2) git-based room collaboration scripts for team sharing. Both are well-understood technical domains with clear implementation paths.

The Brain MCP server is a NEW standalone Node.js server in `mcp-server-brain/` that uses `@modelcontextprotocol/sdk`'s `StreamableHTTPServerTransport` with Express for HTTP hosting. It exposes 5-7 tools that directly call Neo4j (via `@neo4j/neogql` / direct Cypher HTTP API) and Pinecone (via `@pinecone-database/pinecone` SDK). API key validation is simple Express middleware checking `Authorization: Bearer <key>` against an env var. Render deploys this as a Node.js web service with automatic git-push deploys.

The room collaboration feature uses standard git with three helper scripts (`room-git-init`, `room-git-push`, `room-git-pull`). STATE.md merge conflicts are resolved by the "recompute" strategy -- since STATE.md is always derivable from room contents via `compute-state`, on conflict we throw away both versions and regenerate. This avoids any need for custom merge drivers.

**Primary recommendation:** Build the Brain MCP server as a minimal Express + MCP SDK server with stateless StreamableHTTPServerTransport. Use Pinecone JS SDK and Neo4j Cypher HTTP API directly rather than spawning the existing MCP servers as sub-processes.

### Pattern 1: Stateless StreamableHTTP MCP Server

**What:** The Brain MCP server creates a new McpServer + transport per request. No session state. No session ID.
**When to use:** Always for this server. Brain queries are stateless lookups -- no conversation context needed.
**Why:** Stateless means no memory pressure, no session cleanup, no stale session bugs. Render free tier can spin down and restart without losing state.

```javascript
// mcp-server-brain/server.cjs
const express = require('express');
const { McpServer } = require('@modelcontextprotocol/sdk/server/mcp.js');
const { StreamableHTTPServerTransport } = require('@modelcontextprotocol/sdk/server/streamableHttp.js');
const { validateApiKey } = require('./lib/auth.cjs');
const { registerNeo4jTools } = require('./lib/neo4j-tools.cjs');
const { registerPineconeTools } = require('./lib/pinecone-tools.cjs');

const app = express();
app.use(express.json());

// API key auth middleware (before MCP route)
app.use('/mcp', validateApiKey);

// MCP endpoint -- stateless: new server + transport per request
app.post('/mcp', async (req, res) => {
  const server = new McpServer({
    name: 'mindrian-brain',
    version: '1.0.0',
  });

  registerNeo4jTools(server);
  registerPineconeTools(server);

  const transport = new StreamableHTTPServerTransport({
    sessionIdGenerator: undefined, // stateless
  });

  await server.connect(transport);

  try {
    await transport.handleRequest(req, res, req.body);
  } catch (err) {
    if (!res.headersSent) {
      res.status(500).json({
        jsonrpc: '2.0',
        error: { code: -32603, message: 'Internal server error' },
        id: null,
      });
    }
  }
});

// Health check
app.get('/health', (req, res) => res.json({ status: 'ok' }));

const PORT = process.env.PORT || 3000;
app.listen(PORT, () => {
  console.log(`Brain MCP server listening on port ${PORT}`);
});
```

### Pattern 2: API Key Auth Middleware

**What:** Simple Express middleware that validates Bearer token against env var.
**When to use:** Every request to `/mcp`.

```javascript
// mcp-server-brain/lib/auth.cjs
function validateApiKey(req, res, next) {
  const authHeader = req.headers.authorization;

  if (!authHeader || !authHeader.startsWith('Bearer ')) {
    return res.status(401).json({
      error: 'Missing API key. Set Authorization: Bearer <your-key>',
      help: 'Contact support@mindrian.ai for a Brain API key.'
    });
  }

  const key = authHeader.slice(7);
  const validKeys = (process.env.BRAIN_API_KEYS || '').split(',').filter(Boolean);

  if (!validKeys.includes(key)) {
    return res.status(401).json({
      error: 'Invalid Brain API key. Contact support@mindrian.ai'
    });
  }

  next();
}
```

**Key decision:** Store multiple API keys in a single env var (`BRAIN_API_KEYS`) as comma-separated values. This allows adding/revoking keys by updating one Render env var. No database needed.

### Pattern 3: Neo4j Tool Wrapping

**What:** Directly call Neo4j via the official driver instead of spawning `@neo4j/mcp-neo4j` as a subprocess.
**Why:** Subprocess spawning on Render adds cold-start latency and complicates deployment. Direct driver calls are faster and simpler.

The original `@neo4j/mcp-neo4j` exposes three tools:
1. `get-neo4j-schema` -- returns node labels, properties, relationship types
2. `read-neo4j-cypher` -- executes read-only Cypher queries
3. `write-neo4j-cypher` -- executes write Cypher queries (with user approval)

```javascript
// mcp-server-brain/lib/neo4j-tools.cjs
const neo4j = require('neo4j-driver');
const { z } = require('zod');

let driver = null;

function getDriver() {
  if (!driver) {
    driver = neo4j.driver(
      process.env.NEO4J_URI,
      neo4j.auth.basic(process.env.NEO4J_USER || 'neo4j', process.env.NEO4J_PASSWORD)
    );
  }
  return driver;
}

function registerNeo4jTools(server) {
  server.tool('brain_schema', 'Get the Brain knowledge graph schema (node labels, relationships, properties)', {},
    async () => {
      const session = getDriver().session({ defaultAccessMode: neo4j.session.READ });
      try {
        const result = await session.run('CALL apoc.meta.schema() YIELD value RETURN value');
        const schema = result.records.map(r => r.get('value'));
        return { content: [{ type: 'text', text: JSON.stringify(schema, null, 2) }] };
      } finally {
        await session.close();
      }
    }
  );

  server.tool('brain_query', 'Run a read-only Cypher query on the Brain knowledge graph',
    { cypher: z.string().describe('Read-only Cypher query'), params: z.record(z.any()).optional() },
    async ({ cypher, params }) => {
      const session = getDriver().session({ defaultAccessMode: neo4j.session.READ });
      try {
        const result = await session.run(cypher, params || {});
        const records = result.records.map(r => r.toObject());
        return { content: [{ type: 'text', text: JSON.stringify(records, null, 2) }] };
      } finally {
        await session.close();
      }
    }
  );

  server.tool('brain_write', 'Write data to the Brain knowledge graph (requires confirmation)',
    { cypher: z.string().describe('Write Cypher query'), params: z.record(z.any()).optional() },
    async ({ cypher, params }) => {
      const session = getDriver().session({ defaultAccessMode: neo4j.session.WRITE });
      try {
        const result = await session.run(cypher, params || {});
        return { content: [{ type: 'text', text: `Written. Stats: ${JSON.stringify(result.summary.counters.updates())}` }] };
      } finally {
        await session.close();
      }
    }
  );
}
```

### Pattern 4: Pinecone Tool Wrapping

**What:** Direct Pinecone SDK calls for semantic search.

The original `@anthropic/pinecone-mcp` (now `@pinecone-database/mcp`) exposes: `search-records`, `list-indexes`, `describe-index`, `describe-index-stats`, `upsert-records`, `rerank-documents`.

For Brain, we only need: `search-records` (semantic search) and `describe-index-stats` (index info).

```javascript
// mcp-server-brain/lib/pinecone-tools.cjs
const { Pinecone } = require('@pinecone-database/pinecone');
const { z } = require('zod');

let client = null;

function getClient() {
  if (!client) {
    client = new Pinecone({ apiKey: process.env.PINECONE_API_KEY });
  }
  return client;
}

function registerPineconeTools(server) {
  const indexName = process.env.PINECONE_INDEX || 'neo4j-knowledge-base';

  server.tool('brain_search', 'Semantic search across Brain embeddings (1,427 PWS knowledge vectors)',
    {
      query: z.string().describe('Natural language search query'),
      topK: z.number().optional().describe('Number of results (default 5)'),
      filter: z.record(z.any()).optional().describe('Metadata filter')
    },
    async ({ query, topK, filter }) => {
      const index = getClient().index(indexName);
      const results = await index.searchRecords({
        query: { topK: topK || 5, inputs: { text: query }, filter },
      });
      return { content: [{ type: 'text', text: JSON.stringify(results, null, 2) }] };
    }
  );

  server.tool('brain_stats', 'Get Brain index statistics (record count, namespaces)',
    {},
    async () => {
      const index = getClient().index(indexName);
      const stats = await index.describeIndexStats();
      return { content: [{ type: 'text', text: JSON.stringify(stats, null, 2) }] };
    }
  );
}
```

### Pattern 5: STATE.md Recompute on Conflict

**What:** When git pull encounters a merge conflict in STATE.md, discard both versions and regenerate via `compute-state`.
**Why:** STATE.md is derived data -- it is always recomputable from the room's artifacts. No information is lost by regenerating it.

```bash
# scripts/room-git-pull (conflict resolution excerpt)
git pull origin main 2>&1 || {
  # Check if STATE.md is conflicted
  if git diff --name-only --diff-filter=U | grep -q "STATE.md"; then
    echo "STATE.md conflict detected. Regenerating from room contents..."
    # Accept theirs for all non-STATE.md conflicts (abort on those)
    git checkout --theirs room/STATE.md
    git add room/STATE.md
    # Regenerate STATE.md
    bash "$PLUGIN_ROOT/scripts/compute-state" room/ > room/STATE.md
    git add room/STATE.md
    git commit -m "chore: regenerate STATE.md after merge conflict"
  else
    echo "ERROR: Non-STATE.md merge conflict. Resolve manually."
    exit 1
  fi
}
```

### Anti-Patterns to Avoid

- **Spawning @neo4j/mcp-neo4j as subprocess on Render:** Creates double cold-start penalty and makes the Brain server depend on npx availability at runtime. Use the neo4j-driver directly.
- **Custom merge driver for STATE.md:** Overengineered. STATE.md is derived data. Recompute is simpler and more reliable than section-aware merge logic.
- **Storing API keys in a JSON file on Render:** Render env vars are the correct mechanism. JSON file would need to be committed or mounted, both adding complexity.
- **Session-based MCP transport for Brain:** Brain queries are stateless lookups. Session state adds memory overhead and complexity with zero benefit.
- **Sharing package.json with the plugin:** The Brain server deploys independently to Render. It needs its own `package.json` with its own dependencies. The plugin repo contains both, but they install separately.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Neo4j query execution | Custom HTTP client to Neo4j REST API | `neo4j-driver` package | Handles connection pooling, auth, transaction modes, result parsing. The REST API requires manual bolt protocol handling. |
| Pinecone vector search | Custom fetch calls to Pinecone REST API | `@pinecone-database/pinecone` SDK | Handles auth, retry, rate limiting, response typing. |
| MCP protocol handling | Custom JSON-RPC implementation | `@modelcontextprotocol/sdk` StreamableHTTPServerTransport | Protocol is complex (initialize, tools/list, tools/call, progress, cancellation). SDK handles all of it. |
| API key generation | Custom random string generator | `crypto.randomUUID()` (Node 19+) or `uuid` package | UUIDs are the standard format. Cryptographically random by default. |
| Git operations | Custom file-sync protocol | Standard `git` CLI in bash scripts | Git handles merge, conflict detection, history, branching. No sync protocol competes. |

## Common Pitfalls

### Pitfall 1: Render Free Tier Cold Start
**What goes wrong:** Render free tier spins down after 15 minutes of inactivity. First request after spin-down takes 30-60 seconds (Node.js process boot + npm install if using Docker).
**Why it happens:** Free tier limitation. Render keeps no warm instances.
**How to avoid:** (1) Document the cold-start delay for users. (2) Use native Node.js runtime on Render (not Docker) to reduce cold-start. (3) Consider Render paid tier ($7/month) for always-on if cold start is unacceptable. (4) Add a health check endpoint so Render's uptime monitor can keep it warm.
**Warning signs:** Users report "Brain connection timeout" on first request of the day.

### Pitfall 2: Neo4j Driver Connection Leak
**What goes wrong:** Creating a new neo4j.driver() per request leaks connections. Neo4j Aura has connection limits.
**Why it happens:** Forgetting to reuse the driver singleton.
**How to avoid:** Create driver once at module load (singleton pattern shown above). Always close sessions in `finally` blocks. Never close the driver itself unless shutting down.
**Warning signs:** Neo4j Aura dashboard shows connection count climbing.

### Pitfall 3: Pinecone Integrated Inference Requirement
**What goes wrong:** `search-records` with text query fails because the index was not created with integrated inference.
**Why it happens:** The existing `neo4j-knowledge-base` Pinecone index may use external embeddings (uploaded vectors) rather than Pinecone's integrated inference.
**How to avoid:** Check the index configuration first. If using external embeddings, use `query()` with vector input instead of `searchRecords()` with text input. The Brain server may need to embed queries externally (e.g., via OpenAI) before querying Pinecone.
**Warning signs:** Pinecone returns "Index does not support integrated inference" error.

### Pitfall 4: PORT Environment Variable on Render
**What goes wrong:** Server listens on hardcoded port 3000 but Render assigns a different port via `PORT` env var.
**Why it happens:** Render dynamically assigns ports. The server must read `process.env.PORT`.
**How to avoid:** Always use `const PORT = process.env.PORT || 3000`. Never hardcode.
**Warning signs:** Service shows "Deploy failed" on Render dashboard.

### Pitfall 5: Git Merge with Unstaged Room Changes
**What goes wrong:** `room-git-pull` fails or loses local changes because the user has unstaged modifications.
**Why it happens:** Git refuses to merge when working directory is dirty.
**How to avoid:** `room-git-pull` must first stash local changes, pull, then pop the stash. Or: auto-commit before pull.
**Warning signs:** Users report "your local changes would be overwritten by merge."

### Pitfall 6: APOC Not Available on Neo4j Aura Free
**What goes wrong:** `CALL apoc.meta.schema()` fails because APOC is not available on all Neo4j Aura tiers.
**Why it happens:** Neo4j Aura Free does not include APOC procedures.
**How to avoid:** Use `db.schema.visualization()` or `CALL db.labels()` + `CALL db.relationshipTypes()` + `CALL db.propertyKeys()` as fallback. Test against the actual Aura instance.
**Warning signs:** "Unknown procedure: apoc.meta.schema" error on first schema query.

```bash
#!/usr/bin/env bash
# scripts/room-git-init: Initialize room/ as a git repo for team sync
set -euo pipefail

ROOM_DIR="${1:-./room}"
REMOTE_URL="${2:-}"

if [ ! -d "$ROOM_DIR" ]; then
  echo "ERROR: Room directory not found at $ROOM_DIR"
  exit 1
fi

cd "$ROOM_DIR"

if [ -d ".git" ]; then
  echo "Room already initialized as git repo."
  git remote -v
  exit 0
fi

git init
echo ".DS_Store" > .gitignore
echo "*.pyc" >> .gitignore
git add .
git commit -m "init: Data Room for team collaboration"

if [ -n "$REMOTE_URL" ]; then
  git remote add origin "$REMOTE_URL"
  echo "Remote set to: $REMOTE_URL"
  echo "Run: scripts/room-git-push to push initial state"
fi
```

### Room Git Push Script

```bash
#!/usr/bin/env bash
# scripts/room-git-push: Stage, commit, push room changes
set -euo pipefail

ROOM_DIR="${1:-./room}"
MSG="${2:-sync: room state update $(date +%Y-%m-%dT%H:%M)}"

cd "$ROOM_DIR"

# Check if git repo
if [ ! -d ".git" ]; then
  echo "ERROR: Room is not a git repo. Run scripts/room-git-init first."
  exit 1
fi

# Stage all changes
git add -A

# Check if there are changes to commit
if git diff --cached --quiet; then
  echo "No changes to push."
  exit 0
fi

git commit -m "$MSG"

# Push if remote exists
if git remote get-url origin &>/dev/null; then
  git push origin "$(git branch --show-current)"
  echo "Pushed to remote."
else
  echo "Committed locally. No remote configured."
fi
```
