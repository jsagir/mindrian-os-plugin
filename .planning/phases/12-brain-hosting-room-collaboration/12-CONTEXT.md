# Phase 12: Brain Hosting + Room Collaboration - Context

**Gathered:** 2026-03-24
**Status:** Ready for planning
**Source:** Architectural decisions by Claude based on existing codebase analysis

<domain>
## Phase Boundary

Phase 12 delivers two capabilities:
1. **Brain Hosting**: A single remote MCP server that wraps both Neo4j and Pinecone Brain access behind one API key, deployed on Render. Remote users add one MCP config entry instead of managing raw Neo4j/Pinecone credentials.
2. **Room Collaboration**: Git-based room sharing so teams can collaborate on a shared Data Room.

</domain>

<decisions>
## Implementation Decisions

### Brain Hosting Architecture
- Brain MCP server is a NEW lightweight Node.js MCP server (NOT a fork of the plugin's MCP server)
- It wraps the existing `@neo4j/mcp-neo4j` and `@anthropic/pinecone-mcp` functionality into a single server
- Lives in `mcp-server-brain/` directory (separate from plugin, deployable independently)
- Uses Streamable HTTP transport (not stdio) since it runs remotely
- Deployed on **Render** (Jonathan already has an account and Render MCP tools available)
- URL pattern: `https://mindrian-brain.onrender.com` (no custom domain needed yet)

### API Key Authentication
- Simple API key validation — no OAuth, no user accounts for v3.0
- Keys are UUIDs generated by Jonathan, shared manually with paid-tier users
- Server validates `Authorization: Bearer <key>` header on every request
- Keys stored in a simple JSON file or environment variable on the Render service
- Invalid key → 401 with clear error message: "Invalid Brain API key. Contact support@mindrian-os.com"

### Brain MCP Tools (what the remote server exposes)
- Wraps the same Neo4j Cypher queries the Brain agents use (schema query, read cypher, write cypher)
- Wraps Pinecone semantic search (search-records, search-docs)
- Larry enrichment context: when a Brain query returns results, format them as Larry-style teaching context
- Total: ~5-8 MCP tools (same as current neo4j-brain + pinecone-brain combined)

### Desktop/Cowork User Config
- Users add to their `claude_desktop_config.json`:
```json
{
  "mcpServers": {
    "mindrian-brain": {
      "url": "https://mindrian-brain.onrender.com/mcp",
      "headers": {
        "Authorization": "Bearer <your-api-key>"
      }
    }
  }
}
```
- One entry replaces the current two (neo4j-brain + pinecone-brain)
- Works on Desktop and Cowork identically

### Room Collaboration (Git Sync)
- Room collaboration uses standard git — no custom sync protocol
- New scripts: `scripts/room-git-init`, `scripts/room-git-push`, `scripts/room-git-pull`
- `room-git-init`: initializes room/ as a git repo (or connects to existing remote)
- `room-git-push`: stages room changes, commits with auto-message, pushes
- `room-git-pull`: pulls remote, handles STATE.md merges
- STATE.md merge strategy: section-based merge (Accumulated Context is append-only, Current Position takes latest)
- New commands: `/mindrian-os:room-sync` (push/pull/status)

### Claude's Discretion
- Render deployment configuration (Dockerfile vs native Node, env vars setup)
- Exact Neo4j/Pinecone query wrapping implementation
- Git merge conflict resolution algorithm details
- Error handling patterns for network failures

</decisions>
