# Phase 88.2 Plan 04: Operator-aware Dispatcher Integration Summary

Operator-aware extension of `lib/hmi/selector-dispatcher.cjs` that routes the
five Phase 88.2 Wave-1 sub-shape renderers (F.1..F.5) directly, refuses any
Shape F.* presentation when the conversation operator is `JUST_TALK`,
attaches an AskUserQuestion structural-marker trailer to every successful
Shape F.* return, and emits LOCAL-only telemetry on presentation events when
callers opt in. The Phase 101-04 9-test contract is preserved byte-stable;
the new 19-assertion harness sits alongside it.

## What shipped

### F.1..F.5 sub-shape direct dispatch

The dispatcher's `pickShape()` previously routed only the umbrella `'F'`
through JTBD-aware logic that picked F.6 (taxonomy-driven) or fell back to
F.1 (canonical 10-verb). Plan 88.2-04 adds five new entries
`{'F.1','F.2','F.3','F.4','F.5'}` that route directly to their Wave-1
renderers (`shape-f1-renderer.cjs` ... `shape-f5-renderer.cjs`) without
consulting JTBD state. The umbrella `'F'` keeps its original behavior.

### JUST_TALK refuse

`Canon Part 3` says the conversation operator gates which surfaces are
allowed. `lib/render/render-v2.cjs:244` already implements this for the
render layer (when `operator === 'JUST_TALK'`, the entire output is
suppressed with `contract: { suppressed: true, reason: 'just-talk' }`). The
dispatcher now mirrors that gate at the selector layer: when JUST_TALK is
active and ANY Shape F.* is requested (umbrella or sub-shape), pickShape
returns:

```
{
  shape: 'error',
  rendered: {
    error: 'render_v2_compaction_violation',
    detail: 'Shape F selector refused: operator JUST_TALK suppresses all selector output (render-v2 step 6 / Canon Part 3).',
    operator: 'JUST_TALK',
    requested: <the requested shape>
  }
}
```

The error code `render_v2_compaction_violation` matches the success
criterion in the executor prompt and is the canonical name for this gate
across the dispatcher + render-v2 boundary.

### AskUserQuestion structural-marker trailer

Every successful Shape F.* return now carries the trailer string
`[AskUserQuestion contract: shape=F.X verbs=N]` on two surfaces:

1. `rendered.askuserquestion_marker` -- scalar string for introspection.
2. `rendered.zones.footer` -- the trailer is appended to the existing
   footer (preceded by a blank line if non-empty). When the renderer's
   footer is null/undefined/empty, the trailer becomes the footer.

Both surfaces project from the same source: `contract.shape` and
`contract.verbs.length`. Open-vocab sub-shapes (F.1/F.2/F.5) report their
final cap-and-Free-Text-appended verb count (5 or 6 typical, 10 for the
canonical default); closed-vocab sub-shapes (F.3/F.4) report their fixed 5.

### Telemetry emission (opt-in)

Telemetry is gated by `payload.emitTelemetry === true`. The reason for the
opt-in design surfaced during integration testing: `lib/render/render-v2.cjs`
calls `pickShape()` from its Zone 4 enrichment path (line 147), but that
call is *enrichment*, not *presentation*. The fs_scope guard in
`test-render-v2-provenance.cjs` caught the first naive emit-on-every-render
implementation immediately by detecting the FS read on
`~/.mindrian/telemetry/selector.jsonl` during a render() call, which Canon
Part 8 forbids.

The opt-in flag is the correct architectural resolution:

- `render-v2.cjs` (enrichment) -- omits the flag -> zero FS side-effect.
- Future presentation surface (the actual AskUserQuestion call site) -- sets
  `emitTelemetry: true` -> ledger row is written.

Both behaviors are tested. The success criterion "telemetry on every
selector presentation" is preserved: a *presentation* is a call with
`emitTelemetry: true`; a *render-v2 enrichment* is not a presentation and
correctly does not emit.

### Closed-vocab carve-out

While integrating the sub-shape dispatcher, the existing `ensureFreeTextLast`
defense-in-depth helper was found to break F.3 and F.4 contracts (Wave-1
test assertions 3 and 4 in this plan caught it). F.3 (Shallow/Medium/Deep/
Extreme/Back) and F.4 (Key insights / +contradictions / +actions / Create
artifact draft / Back) explicitly set `contract.freeTextOffered === false`
because depth and extraction are closed axes per `skills/ui-system/SKILL.md
Section 2`. The fix: `ensureFreeTextLast` now respects the
`freeTextOffered === false` flag and leaves closed-vocab contracts alone.
This preserves the Wave-1 renderer 7-assertion test contracts byte-stable.

### recordSelectorResponse re-export

`lib/hmi/selector-telemetry.cjs#recordResponse` is re-exported at the
dispatcher level as `recordSelectorResponse(roomDir, record)`. This gives
the eventual AskUserQuestion answer surface a single import point
(`lib/hmi/selector-dispatcher.cjs`) for both presentation dispatch AND
response telemetry. Wrapped in try/catch -- never fails Larry's turn.

**1. [Rule 1 - Bug] Closed-vocab F.3/F.4 carve-out in ensureFreeTextLast**

**2. [Rule 2 - Critical] Telemetry emission must be opt-in (Canon Part 8 fs_scope guard)**
- **Found during:** Task 1 regression sweep (test-render-v2-provenance.cjs#fs_scope failed with `readFileSync(/home/jsagi/.mindrian/telemetry/selector.jsonl)`)
- **Issue:** The naive "emit on every successful F.* presentation" implementation triggered FS reads during `lib/render/render-v2.cjs`'s Zone 4 enrichment dispatch call. The success criterion "telemetry on every selector presentation" is preserved: a *presentation* is by definition a call that flips the flag.
- **Files modified:** lib/hmi/selector-dispatcher.cjs, tests/test-selector-dispatcher-88-2-04.cjs
