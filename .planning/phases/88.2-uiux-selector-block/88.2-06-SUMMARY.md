## Why we use node:sqlite, not better-sqlite3

The plan body's Task 2 implementation outline referenced `require('better-sqlite3')` in the buildReviewedEdge + emitRoundCompleted skeletons. During execution we found:

1. `lib/core/lazygraph-ops.cjs` line 19 uses `const { DatabaseSync } = require('node:sqlite')`.
2. `lib/import/PRECONDITIONS.md` documents `better-sqlite3` as broken in this Node/WSL environment.
3. `tests/test-navigation-memory-events.cjs` (Phase 109 reference test) uses `DatabaseSync` exclusively.
4. 88.2-03 and 88.2-05 SUMMARY.md files explicitly logged this same Rule-3 deviation, and the post-Wave-1 fix-commit 5bcddc2 already standardized the suite on `node:sqlite`.

Per Rule 3 (Auto-fix blocking issues), we substituted `require('node:sqlite').DatabaseSync` with the same lazy-load + try/catch envelope. Behavioral contract (graceful-fail with structured `{ok, reason}` envelope, never throws) is identical. The dbPath also moved to `<roomDir>/.mindrian/room.db` (not `<roomDir>/.mindrian/<basename>.db` as the plan body skeleton showed) to match the 88.2-05 buildRejectedBecauseEdge pattern + the test-selector-telemetry-dual-surface bootstrap pattern.

## Why caller-supplied brainAvailable wins over env-var

`MINDRIAN_BRAIN_KEY` is set in the project shell (a real Brain key for the Mindrian Aura instance). A strict reading of RESEARCH.md DISCRETION-AMEND-02 (`brainAvailable === true OR process.env.MINDRIAN_BRAIN_KEY -> tier-1`) would have caused every cold-start test invocation to promote to Tier 1. The `selectDecoys with cold-start returns 4 decoys at default roundSize=20` test specifically expects `tier === 'tier-0'`. Test isolation requires the boolean to be authoritative when explicitly supplied. The env-var only fires when the caller leaves `brainAvailable` undefined, preserving the production semantic that "Brain key in env -> Brain reachable" while letting tests + intentional cold-start callers force the cold path.
