## Why personaContext stays in the renderer (not the agent body)

D-AMEND-04 final paragraph: "Persona narration on top of the rendered output is OWNED BY THE AGENT BODY (Larry), not the renderer. Renderers ship structural shape; Larry's agent body wraps with persona-aware framing when speaking the question."

The renderer extension in this plan is NOT persona narration. It is a single-line header suffix that flows from `contract.personaContext` back through the dispatcher to the telemetry surface so Phase 121 can correlate response patterns by persona-blend. The user-facing narration (Larry voicing "as a founder, what's stuck?") is still owned by the agent body and built on top of the renderer's output. Clean separation preserved.

## Why we use node:sqlite, not better-sqlite3

The plan body's `<interfaces>` block referenced `better-sqlite3` as the sqlite binding. During execution we found:

1. `lib/core/lazygraph-ops.cjs` line 19 uses `const { DatabaseSync } = require('node:sqlite')`.
2. `lib/import/PRECONDITIONS.md` documents `better-sqlite3` as broken in this Node/WSL environment.
3. `tests/test-navigation-memory-events.cjs` (Phase 109 reference test) uses `DatabaseSync` exclusively.

Per the plan body's own NOTE ("if the project uses a different sqlite binding pattern, match the project's pattern"), we matched the project pattern. The behavioral contract (graceful-fail with structured `{ok, reason}` envelope, never throws) is identical.
