## 1. System Classification

**System Type:** Hybrid (Autonomous Agent reasoning pass + Extraction/Eval critic - a labeled, lower-confidence fallback path for an already-shipped embedding-based system)

**Description:**
A fallback scoring path for the already-shipped `/mos:eureka` cross-domain opportunity engine
(Phases 211-216). When the local embedding encoder is unavailable or a room's typed-edge graph
is too thin, Eureka currently hard-stops at `pairs_scored:0`. Reasoning-mode instead reads raw
room markdown directly, runs the SAME Grounding Guard structure-mapping rubric (`eureka-critic.cjs`
Stage B, encoder-free by construction) at full rigor, anchors on Jaccard lexical overlap as the
one numeric leg that survives, and emits a result byte-shape-identical to embedded mode's
`{provenance, ranked, tail, statements}`, explicitly labeled `mode:'reasoning'` end to end. Used
by the same navigator who runs `/mos:eureka` normally, on a cold machine or a not-yet-graph-populated
room. "Good" = the label never lies: a lower-confidence result is honestly weaker (never fabricates
an encoder-derived number, never auto-confirms via `banked:true`), but the analogy-evaluation bar
itself never drops.

**Critical Failure Modes:**
1. A reasoning-mode result reports a non-null `differential_score` or `semantic_similarity` - those fields only exist when the real encoder ran; a fabricated number is a false-reassurance failure, not a rounding error (D1/G-1, this session's own domain research flagged this as the single sharpest measurable line).
2. A reasoning-mode statement gets written with `banked:true` - breaks Canon Part 9's human-only truth-promotion invariant the same way an auto-confirmed claim would in any other phase (G-3).
3. The reasoning-mode rubric silently runs a shorter or single-pass version of the Grounding Guard's 6-item adversarial rubric - a critic that looks the same but scrutinizes less is the exact "labeled lower-confidence" framing turning dishonest (D3/G-2).
4. Reasoning-mode's output shape diverges from `eureka-portfolio-report.cjs`'s existing `{provenance, ranked, tail, statements}` contract - breaks every existing consumer of Eureka's output, not just this phase's own surface (D4/G-5, a hard ROADMAP requirement).
5. The `mode:'reasoning'` label is present in one output artifact (JSON) but silently absent from another (markdown report, HTML export) for the same run - lets a downstream reader mistake a weaker result for a full-confidence one (D6/G-4).

## 1b. Domain Context

> Researched by `gsd-domain-researcher`. Grounds the evaluation strategy in domain expert knowledge.

**Industry Vertical:** Degraded-evidence analytic judgment for venture research (an INTERNAL research-methodology tool, not a consumer-facing regulated vertical). The narrow domain question this phase raises is NOT "is the analogy good" (that is Phase 212's Grounding Guard) but "when is a lower-confidence AI output honest enough to surface." The nearest professional disciplines are intelligence-analysis calibration tradecraft (ICD 203 confidence-vs-likelihood standards) and clinical differential-diagnosis reasoning under limited data (working diagnosis vs confirmed diagnosis), both applied on top of Gentner structure-mapping analogy evaluation.

**User Population:** The navigator (Larry's human) -- a single venture researcher running Eureka cross-domain discovery inside a Data Room, on a cold machine (embedding model not yet fetched) or a young room (thin graph). They are both the operator who triggers reasoning-mode and the sole consumer of its ranked pairs, and the only party who may promote a `proposed` opportunity to `confirmed` (Canon Part 9). A shared `/mos:eureka html` export can also reach a second reader who did not run the scan and sees only the rendered result.

**Stakes Level:** High. Not life-safety or regulated-industry Critical, but the whole failure surface of this phase is a CALIBRATION failure: a lower-confidence result that reads as authoritative can make a navigator over-trust a weaker signal and steer real attention or capital toward a cross-domain "opportunity" that only a fully-instrumented embedded scan would have caught as thin. The degrade is honest by design or it is a liability; there is no low-stakes middle.

**Output Consequence:** Reasoning-mode emits the SAME canonical Opportunity Statement shape embedded-mode does (`ranked` pairs + statements), labeled `mode: reasoning`, `banked: false`. Acted on, a mis-calibrated reasoning-mode pair steers where the navigator points diligence next; if the caveat is weak and the pair later gets human-confirmed, a thinly-grounded analogy becomes durable graph truth that downstream analyses inherit. The design's own controls (mode label mandatory, `banked` can never be true on this path, upgrade-on-re-run) ARE the risk mitigation, not gaps to fill.

### What Domain Experts Evaluate Against

**Dimension: Confidence-basis honesty (confidence separated from plausibility)**
- Good: the result expresses how much it trusts its BASIS separately from how plausible the pair is, and names WHY the basis is weak -- 2 of the critic's 3 numeric legs (`differential_score`, `semantic_similarity`) are structurally `null` because the encoder is absent, and no calibration bucket applies -- so only the Jaccard `lsa_similarity` is a real number. No blended single "quality score" that fuses trust-in-evidence with plausibility.
- Bad: a single confidence number that silently mixes "this pair is plausible" with "I trust the evidence," OR any reported `differential_score` / `semantic_similarity` the encoder never computed. A reasoning-mode result that reports a differential number is lying about its evidentiary base.
- Stakes: Critical
- Source: ICD 203 Analytic Standards -- likelihood (standardized probability language) and analyst confidence (high/moderate/low in the basis) must be expressed separately and are explicitly prohibited from being combined in one sentence; Sherman Kent, Words of Estimative Probability (separating estimative odds from confidence in them).

**Dimension: Critic-bar parity where the bar is encoder-free (structure-mapping rigor held, never relaxed)**
- Good: reasoning-mode runs the SAME encoder-free Stage B critic at full strength -- the six binary structure-mapping items (schema statable without either domain's nouns; one-to-one mapping with no orphans; a checkable consequence; adds over nearest prior; genuinely not a restatement; free of unsourced quantities), BOTH passes (neutral + adversarial), verdict computed by CODE (`verdictFromRubric`, biased to reject). The lower confidence label comes ONLY from the missing similarity and calibration legs, never from a slacker analogy bar.
- Bad: reasoning-mode drops the adversarial pass, softens or paraphrases the rubric, lets the LLM pick the verdict, asks Claude to estimate a semantic-similarity score, or treats "lower confidence" as license to admit weaker analogies. A degraded-confidence tag used to smuggle a lower quality bar past the navigator.
- Stakes: Critical
- Source: Gentner structure-mapping theory (systematicity, one-to-one correspondence, no orphan elements) as operationalized in `lib/core/eureka-critic.cjs` `RUBRIC_ITEMS` + two-pass adversarial `runRubric` + verdict-by-code; SEED-050's documented failure modes the items trace to.

**Dimension: Working-diagnosis posture (never closes as confirmed; upgradeable)**
- Good: the reasoning-mode result behaves like a clinician's working diagnosis, not a final verdict -- a deliberately SHORT differential, `banked: false`, `proposed` only, upgradeable in place to embedded-mode; the uncertainty caveat is stated once, prominently, up front (the anti-overconfidence antidote); a later embedded re-run surfaces the reasoning-to-embedded DELTA rather than silently replacing the old result.
- Bad: the reasoning-mode result is banked or human-confirmed off a weak basis, rendered as a full authoritative ranked list, or silently overwritten on embedded re-run so the navigator never sees the confidence basis changed -- premature closure dressed as a finished answer.
- Stakes: High
- Source: clinical diagnostic-calibration literature -- overconfidence induces premature closure, and explicit acknowledgement of diagnostic uncertainty is the documented antidote (Berner & Graber, *Overconfidence as a Cause of Diagnostic Error*; UCSF Codex clinical-reasoning primer); Canon Part 9 (human-only truth-promotion) makes `banked:false` non-negotiable on this path.

**Dimension: Mode disclosure travels to every consumer (the label cannot be lost)**
- Good: the `mode: reasoning` label and its caveat ride WITH the result at every surface -- the Shape E render's caveat zone, the JSON `provenance.run_mode`, and the `/mos:eureka html` export -- so neither the navigator nor a downstream reader of a shared report can mistake a reasoning-mode pair for an embedded one. Reasoning and embedded results are never merged into one ranked list.
- Bad: the mode is defaulted, hidden, buried in a footer, dropped on html export, or the two modes' pairs share a single ranked list. A shared report that reads as embedded-mode when it was not is the exact over-trust vector this phase exists to prevent.
- Stakes: High
- Source: ICD 203 (the basis for uncertainty must be indicated and explained in the product itself, not held separately); SEED-058 required capabilities 1, 4, and 6 (mandatory visible mode field, prominent caveat in the render, mode label on exports).

### Known Failure Modes in This Domain

1. **False-reassurance label (the core risk of this phase).** A "lower-confidence" tag that reads as a mild footnote while the output looks exactly as authoritative as an embedded-mode result. The label becomes a liability shield rather than honest calibration, and the navigator over-trusts a weaker signal because the degrade was cosmetically marked but substantively indistinguishable. This is the single failure the whole phase exists to avoid.
2. **Fabricated evidentiary number.** The reasoning pass emits (or is asked to estimate) a `differential_score` / `semantic_similarity` the encoder never produced -- fluency dressed as measurement. This reopens the exact sycophancy channel (arXiv:2310.13548) the two-pass adversarial rubric was built to close, and it is why only the free Jaccard `lsa_similarity` may carry a number in reasoning-mode.
3. **Silent premature closure.** The reasoning-mode result is presented as a finished verdict, or is silently replaced on a later embedded re-run with no delta shown, so the navigator never sees that the confidence basis changed from thin to instrumented. A working diagnosis frozen and treated as confirmed.
4. **Symptom-not-cause degrade message.** The original proving case ("David", 2026-07-14): `/mos:eureka` returned `pairs_scored: 0` and rendered "not enough entries," which is true of the SYMPTOM but false of the CAUSE (`encoder_unavailable` intersecting an empty graph). A degrade path that still misdescribes WHY it degraded sends the navigator to fix the wrong thing (add content) when the real blocker is infrastructural (model never fetched). Honest calibration includes an honest reason.

### Regulatory / Compliance Context

No external regulatory regime applies (single-navigator internal venture-research tool, no third-party data subjects, no regulated advice output). The binding constraints are INTERNAL constitutional standards that function as this domain's compliance regime, and they are the design's own risk controls rather than gaps:
- **Canon Part 9 (human-only truth-promotion).** Reasoning-mode output lands as `proposed` and `banked` can NEVER be true on this path; only a human `confirmNode(byUser)` promotes it. A reasoning-mode result that banks or self-confirms off a degraded basis is the most severe breach this phase can commit.
- **Canon Part 8 (graph boundary).** Reasoning-mode reads LOCAL room markdown only, adds zero new network surface, and never egresses persona/claim content; the embedding-model fetch stays the same explicit opt-in it is today. The in-session Claude is the judge, never the Brain.
- **Self-imposed analytic standard (ICD-203-style).** The confidence-vs-plausibility separation above is not externally audited; the team holds itself to it the way an intelligence shop holds itself to ICD 203. It is checked structurally (the result carries `null` on the two absent legs and a mandatory `mode` field) rather than by an outside regulator.

## 2. Framework Decision

**Selected Framework:** No external framework - extend the in-repo Claude-as-local-judge seam (`scripts/eureka-critic-run.cjs` `--emit-prompts`/`--score`), anchored on `lib/core/eureka/lexical-overlap.cjs` (Jaccard) as the one numeric input that survives when the embedding encoder is unavailable

**Version:** N/A - zero new npm dependencies (repo convention held all session); reuses whatever Claude Code itself already provides as the reasoning substrate

**Rationale:**
Phase 226 is a fallback/degrade path for the already-shipped Eureka engine (Phases 211-216), not
a new AI system build. The genuinely hard design question - what a "lower-confidence" result means
when 2 of the Grounding Guard critic's 3 numeric inputs (differential_score, semantic_similarity)
are structurally unavailable in exactly this scenario, since both derive from the same encoder this
fallback exists to route around - is an evaluation-strategy question, not a framework-selection one.
`scripts/eureka-critic-run.cjs` already ships a Claude-as-local-judge seam for exactly this shape of
problem; extending it with `lexical-overlap.cjs`'s Jaccard score as the one surviving numeric anchor
avoids inventing a second scoring mechanism. Any external framework would violate the zero-new-deps
constraint this repo has held through Phases 222/223/225 and would duplicate reasoning capability
Claude Code already provides natively.

**Alternatives Considered:**

| Framework | Ruled Out Because |
|-----------|------------------|
| Claude Agent SDK (Anthropic) | Conceptually the closest external match (Claude-native, MCP-aware) but a net-new dependency duplicating capability this plugin already runs inside; same elimination logic as Phase 223's framework decision |
| sentence-transformers / a lighter local embedding model as a fallback-fallback | Defeats the purpose - the entry condition for reasoning-mode IS "the embedding encoder is unavailable"; falling back to a different embedding model doesn't address the scenario this phase targets |
| A rules-based/heuristic-only scorer (no LLM reasoning at all) | Would be lower quality than what Claude's own reasoning can provide over raw room markdown, and this repo already has a shipped Claude-as-judge seam to extend instead of building a parallel heuristic path |

**Vendor Lock-In Accepted:** No - reuses the same in-house, zero-framework-lock-in approach Phase 223 selected; the reasoning capability is Claude Code itself, not a vendor SDK dependency

// Mirrors the --emit-prompts / --score split of eureka-critic-run.cjs: a CLI process

// 1) Read raw markdown DIRECTLY from the filesystem (NOT room.db) -- works even when

// 2) The Claude session proposes plausible cross-domain pairs from the raw entries
//    (this is the reasoning pass; no embedding model is invoked). Each pair carries
//    mechanismText (an entry's mechanism prose) + a one-line mappingStatement.

// 3) The ONE surviving numeric anchor: Jaccard vocabulary overlap. LOW overlap on a
//    pair the reasoning pass still judged connected is the eureka signature (shared
//    meaning the vocabulary hides), the same signal signed_diff encodes in embedded mode.
function anchorFor(pairTextA, pairTextB) {
  return { lsa_similarity: lexicalOverlap(pairTextA, pairTextB), lexical_method: LEXICAL_METHOD };

// 4) Run the SAME Stage B two-pass rubric (encoder-free) with the Claude session as judge.
async function scorePairReasoning(candidate, judgeFn) {
  const rub = await critic.runRubric(candidate, { judgeFn }); // { rubric_pattern, verdict, reasoning_tag }
  return rub; // verdictFromRubric already ran inside; CODE picked the class, not the LLM
}

// 5) Emit the canonical statement shape, labeled mode:reasoning, banked:false, and
//    render a REAL (short) ranked list with the confidence caveat stated once up front.

### Common Pitfalls
1. **Re-inventing embedding similarity badly.** The reasoning pass must NOT try to estimate a cosine score in its head. Its job is the 6 binary rubric items (relational-schema statability, one-to-one mapping, falsifiability, novelty-over-prior, non-restatement, no unsourced quantities), plus letting `lexicalOverlap` supply the ONLY number. Asking Claude for a made-up "semantic score" reopens exactly the sycophancy channel the two-pass adversarial rubric was built to close.
2. **Letting `differential_score` / `semantic_similarity` masquerade as present.** When the encoder is down, `scoreMeasured` returns both as `null` (`warning: 'encoder_unavailable'`); the critic's D1 payload has 3 numeric inputs and 2 are structurally unavailable here. Only `lsa_similarity` (the Jaccard leg) is real. A reasoning-mode result that reports a differential number is lying.
3. **Trying to reuse `stageA` as-is.** Stage A Gate 2 (domain-swap invariance) calls `spine.embedTexts`; with no encoder it degrades to `{ pass:false, tag:'calibration_unknown', degraded:true }` and never clears a candidate. Reasoning-mode uses Stage A ONLY for its encoder-free Gate 1 (fabricated-quantity `/\b\d+(?:\.\d+)?[KMB]\b/` + `$`-figure) and skips the swap gate, then goes straight to the Stage B rubric.
4. **Silently merging modes.** SEED-058 req 1: every result carries a `mode` field (`embedded` | `reasoning`), surfaced in the render and the `/mos:eureka html` export, never defaulted or hidden. A reasoning-mode statement must never be banked or trusted the same as an embedded-mode one.
5. **Entering reasoning-mode speculatively.** Req 2: the branch is entered only AFTER the real embedded attempt proves `idx.embedded !== true` (or the scored-pairs floor is unmet after a genuine attempt), never before trying the real path. The embedded scoring logic itself is untouched (req 7: purely additive branch).
6. **Unbounded LLM cost on a large room.** Raw-markdown reasoning over N entries is O(N^2) candidate pairs against a paid reasoning pass, not cheap vector math. Without a cap this is unbounded; see the cost budget in 4b.5 (candidate-pair ceiling + the Phase 167 fable-mode posture-scoping precedent SEED-058 names explicitly).

## 4. Implementation Guidance

**Model Configuration:**
The reasoning substrate is the ambient Claude Code session itself (Canon Part 8: the judge needs
raw content, so it never sits behind the MCP boundary or a network API). There is no model id,
temperature, or `max_tokens` to set at an SDK call site, because there is no SDK call: the pattern
is the same `--emit-prompts` / `--score` split `eureka-critic-run.cjs` already ships. The `.cjs`
process emits neutral + adversarial prompt files; the local Claude session answers them faithfully;
`--score` replays those answers through the real `runRubric`. The only "configuration" is the two
env-tunable Stage A floors (`EUREKA_SWAP_INVARIANCE_FLOOR`, `EUREKA_ENTITY_MIN`) -- and in
reasoning-mode the swap floor is moot because the swap gate needs an encoder that is absent. The
determinism the pipeline relies on comes from the CODE side: `verdictFromRubric` is a total function
biased to reject, and `parseRubricResponse` defaults every unparseable item to `false`.

**Core Pattern:**
The reasoning-mode scoring flow, grounded in the shipped functions:
```javascript
// (0) ENTRY GUARD -- only after the real embedded attempt failed (never speculative).
//     eureka-portfolio-report.cjs already computes idx.embedded; branch on its negation.
if (idx.embedded !== true /* or scored-pairs floor unmet after a genuine attempt */) {

  // (1) RAW MARKDOWN, not room.db. Walk roomDir for *.md, strip frontmatter + HTML
  //     comments (the loadCandidate idiom), yield [{ id, section, text }].
  const entries = readRoomMarkdown(roomDir);

  // (2) REASONING PASS (the local Claude session) proposes cross-domain candidate pairs
  //     from the raw entries and, per pair, a mechanismText + a one-line mappingStatement.
  //     Emitted as prompt files exactly like eureka-critic-run.cjs --emit-prompts.

  // (3) NUMERIC ANCHOR -- the only number that survives with no encoder.
  const anchor = lexicalOverlap(pair.textA, pair.textB); // jaccard-v1, [0,1]
  //     LOW anchor on a pair the reasoning pass still judged connected == the eureka
  //     signature (shared meaning the vocabulary hides). This is the reasoning-mode
  //     stand-in for signed_diff, and it is labeled lsa_similarity, never differential_score.

  // (4) STAGE B RUBRIC (encoder-free) with the session as judge -- the real critic here.
  const judgeFn = judgeFromAnswers(sessionAnswers[pair.id]); // neutral + adversarial
  const rub = await critic.runRubric(
    { mechanismText: pair.mechanismText, mappingStatement: pair.mappingStatement },
    { judgeFn }
  ); // -> { rubric_pattern, verdict, reasoning_tag }; CODE picked the verdict, not the LLM

  // (5) CANONICAL SHAPE, labeled. buildOpportunityStatement gives { text, banked, critic,
  //     weak_dimensions, fields }. banked STAYS false (pending path); mode = 'reasoning'.
  const st = oppmod.buildOpportunityStatement(candidate);
}
```
The one design commitment: reasoning-mode reuses Stage B (the two-pass rubric, which is pure text
reasoning) and the Jaccard anchor, and skips Stage A's swap-invariance gate and the entire
embedded `scoreMeasured` semantic leg, because those are exactly the pieces that go `null` when the
encoder is unavailable.

**Tool Use:**
- **`/mos:eureka` command surface** (tri-polar: CLI hooks, Desktop conversational, Cowork shared) -- the one entry point; the reasoning-mode branch lives behind it, no separate "fallback command" (SEED-058: one command, one mental model).
- **`doctor.cjs` encoder health check** (Phase 217) -- the availability probe the entry condition reads to decide embedded vs. reasoning; it already exits 0 under scoped scans (Canon Decision #8, graceful degradation).
- **Filesystem read** (raw markdown) -- reasoning-mode's substrate, deliberately NOT room.db, so it works before SEED-034's write-path harness has populated the graph.
- **No Brain MCP, no network judge, no embedding model.** Canon Part 8 holds: reasoning-mode reads LOCAL content only and adds zero new network surface. `runRubric`'s judge is the in-session Claude, never Plurai.

**State Management:**
Mirror the embedded-mode convention in `eureka-portfolio-report.cjs`, do not invent a new one:
- **Report artifacts:** write the SAME `{ provenance, ranked, tail, statements }` markdown + JSON pair, with `provenance.run_mode = 'reasoning'` and a top-of-report confidence caveat. The JSON `statements[]` keep the exact field names (`rank, a, b, tail_flag, text, banked, critic, weak_dimensions, potential_tier`).
- **Graph write-back:** if a reasoning-mode statement is filed at all, it lands as a `proposed`/`candidate` opportunity node THROUGH `navigation.writeOpportunityNode` + `navigation.linkOpportunityEvidence` in one `BEGIN/COMMIT/ROLLBACK` batch -- never a raw INSERT (the `run-all-219.sh` grep gate), and `banked` can never be true on the reasoning path. Stamp `formula_version` to distinguish it (e.g. `eureka-reasoning-v1` vs. embedded's `eureka-critic-v1`) so a re-run can tell the two apart.
- **Re-run upgrade (SEED-058 req 5):** because banked opportunity nodes UPSERT on `sessionId + name` (`BANK_SESSION_ID`), a later embedded-mode run over the same room updates the same node in place; the report should surface the reasoning -> embedded delta rather than silently replacing it.

**Context Window Strategy:**
Embedded mode chunks nothing into the LLM -- it embeds text into vectors. Reasoning-mode is the
opposite: it reads raw markdown into the reasoning context, so context budget becomes the real
constraint. Strategy:
- **Two-pass, not one-shot.** First pass reads compact per-entry summaries (title + section +
  mechanism sentence, not full bodies) to PROPOSE candidate pairs; only the shortlisted pairs pull
  their full mechanism prose into the rubric pass. This keeps the O(N^2) blow-up out of the context.
- **Per-pair rubric prompts carry mechanism + mapping ONLY** (the `buildNeutralPrompt` contract) --
  never the whole room, never provenance or framing. Each rubric call is small and bounded.
- **Hard candidate ceiling** (see 4b.5): cap proposed pairs so a 200-entry room cannot silently
  fan out to ~20k rubric passes. The Jaccard anchor is free (pure CJS) and can pre-filter: compute
  `lexicalOverlap` over all pairs first, then send only the interesting band (low-lexical, reasoning-
  plausible) to the paid rubric pass.

## 4b. AI Systems Best Practices

> Written by `gsd-ai-researcher`. Cross-cutting patterns every developer building AI systems needs - independent of framework choice.

### Structured Outputs with Pydantic

This is a CJS/Node repo, so the equivalent of Pydantic is **zod** (`^3.25.76`, already a dependency
for the MCP tool schemas -- no new dep). But note the honest state of the pipeline: the embedded
path does NOT validate its scoring output with zod today. It uses **frozen JS object shapes plus
field-contract tests** (`tests/test-215-field-contract.cjs`, `tests/test-216-field-contract.cjs`)
and `parseRubricResponse`, a tolerant parser that defaults every unparseable rubric item to `false`
(bias-to-reject). Reasoning-mode has TWO structured surfaces, and the ROADMAP hard requirement is
that the second one matches the embedded shape, not a new shape:

**(a) The rubric answer the Claude reasoning pass returns** -- the small, per-pair structured object
`runRubric` consumes via `judgeFn`. Validate it at the boundary so a garbled judge answer never
silently blesses a pair:

```javascript
const { z } = require('zod');

// The 6 binary rubric items (a-f) the reasoning pass answers, each with one-sentence evidence.
// Mirrors RUBRIC_ITEMS in eureka-critic.cjs exactly -- CODE (verdictFromRubric) picks the class.
const RubricItem = z.object({
  answer: z.enum(['yes', 'no']),
  evidence: z.string().min(1).max(400),
});
const RubricAnswer = z.object({
  a: RubricItem, b: RubricItem, c: RubricItem,
  d: RubricItem, e: RubricItem, f: RubricItem,
});
const ReasoningPass = z.object({
  neutral: RubricAnswer,
  adversarial: RubricAnswer,
});
```

**(b) The reasoning-mode result object** -- must match the embedded `statements[]` field names
byte-for-byte (ROADMAP: "output shape has to match what 211-216 already produce, not invent a
second shape"):

```javascript
const ReasoningStatement = z.object({
  rank: z.number().int().positive(),
  a: z.string(), b: z.string(),
  tail_flag: z.boolean(),
  text: z.string().min(1),
  banked: z.literal(false),               // reasoning-mode can NEVER bank (pending path invariant)
  critic: z.string(),                     // 'reasoning' | verdict enum, never 'pass'
  weak_dimensions: z.array(z.string()),
  potential_tier: z.string(),             // abstract tier ENUM, never a real market figure
  mode: z.literal('reasoning'),           // SEED-058 req 1: mandatory, visible, never defaulted
  lsa_similarity: z.number().min(0).max(1),   // the surviving Jaccard anchor
  differential_score: z.null(),               // structurally unavailable with no encoder
  semantic_similarity: z.null(),              // structurally unavailable with no encoder
});
```

**Retry logic:** the reasoning pass is not an autoregressive API you loop on; it is the local
session answering emitted prompts. So "retry" means: on a `ReasoningPass` parse/validate failure,
re-emit that one pair's prompt for a faithful re-answer, **max 1 retry**. On a second failure, do
NOT drop to a guess -- default the pair's rubric items to `false` (the shipped bias-to-reject) so it
routes to a cautious verdict, and log the pair id + the raw judge string to the report's honesty
block. Surface (do not swallow) any zod error on the final `ReasoningStatement` shape: a shape
mismatch means the branch drifted from the embedded contract, which is the exact thing the ROADMAP
requirement forbids.

### Async-First Design

`runRubric`, `stageA`, `scoreMeasured`, and both `main`s are already `async`. The reasoning-mode
branch slots into `eureka-portfolio-report.cjs`'s existing `async main`, so it inherits the
`try/finally` that closes the room db handle. Rules:
- **One common mistake to avoid: `await` inside a hot pair loop with no concurrency cap.** The
  embedded path already does `await scoreMeasured(...)` per pair in a `for` loop
  (`eslint-disable no-await-in-loop`); that is tolerable for cheap vector math but NOT for a paid
  reasoning pass. Batch the rubric prompts (emit all, answer all, `--score` all) rather than an
  awaited call per pair inside the loop. Reuse the `MINDRIAN_CRITIC_RESOLVE_TIMEOUT_MS` /
  `MINDRIAN_CRITIC_RESOLVE_BATCH_MS` bounded-pass pattern (per-item timeout + batch deadline, batch
  `0` = operator kill switch) that `oppmod.resolveCriticVerdicts` already ships.
- **Stream vs. await:** await for the structured rubric answer (you need the whole object to
  validate against zod before `verdictFromRubric` runs -- a half-streamed rubric is unusable).
  Stream only for the human-facing render narrative if `/mos:eureka` shows progress, never for the
  scoring payload.
- **Never `asyncio.run()`-equivalent nesting:** do not spawn a second Node event loop or a
  child `eureka-critic-run.cjs` process from inside the report's loop; call the exported functions
  (`critic.runRubric`, `oppmod.buildOpportunityStatement`) directly.

### Prompt Engineering Discipline

- **System vs. user separation is already encoded in the prompt builders.** `buildNeutralPrompt`
  and `buildAdversarialPrompt` carry **mechanism + mapping ONLY** -- never the differential score,
  the excitement band, or any provenance/framing. Exposing the candidate's persuasive framing to
  the judge reopens the sycophancy channel (arXiv:2310.13548) the two-pass design closes. Reasoning-
  mode MUST reuse these builders verbatim, not write freer prompts.
- **What the reasoning pass must actually be asked** (the load-bearing prompt-design question): with
  only Jaccard surviving as a number, do NOT ask Claude to estimate a semantic-similarity score --
  it would re-invent embedding cosine badly and sycophantically. Ask it exactly the 6 binary rubric
  items over the raw text: (a) can the shared relational schema be stated WITHOUT either domain's
  nouns; (b) do elements map one-to-one with no orphans; (c) is there a checkable consequence;
  (d) does it add over the nearest prior/graph edge; (e) is it genuinely not a restatement;
  (f) is it free of unsourced quantities. Run it twice -- neutral, then adversarial ("argue this is
  generic filler, complete a counter-mapping") -- and let `verdictFromRubric` compute the class.
  The reasoning pass is a STRUCTURE-MAPPING judge, not a similarity estimator.
- **Few-shot:** inline the 6 items with their `evidence_instruction` strings (already in
  `RUBRIC_ITEMS`); no dynamic retrieval of examples is needed or wanted -- the rubric IS the
  calibration, and pulling room-specific few-shots would leak content across pairs.
- **`max_tokens`:** each rubric answer is 6 yes/no items with one sentence of evidence each -- bound
  it explicitly (a few hundred tokens), never unbounded. An overlong judge answer is a smell that
  the pass is arguing instead of grading.

### Context Window Management

Reasoning-mode is the Autonomous-agent context problem, not the RAG chunking one, because it reads
raw markdown into the reasoning window instead of embedding it. Manage it in three moves:
1. **Summarise for proposal, expand for judging.** The pair-proposal pass sees compact per-entry
   digests (title + section + one mechanism sentence); only shortlisted pairs pull full mechanism
   prose into the rubric pass. This keeps the O(N^2) candidate space out of the window.
2. **Jaccard pre-filter before the paid pass.** `lexicalOverlap` is free pure-CJS math; compute it
   over all candidate pairs first and send only the eureka-interesting band (low lexical overlap +
   reasoning-plausible) to the rubric. This is both a context and a cost control.
3. **Per-pair prompts are self-contained and small** (mechanism + mapping only), so no single rubric
   call approaches the window limit regardless of room size. The room never enters the window whole.

### Cost and Latency Budget

- **The problem:** embedded mode scores a pair with cheap vector math (a cosine); reasoning-mode
  scores it with a paid two-pass LLM reasoning call. A 30-entry room (the SEED-058 proving case,
  "David") has up to ~435 raw pairs; a 200-entry room has ~20k. Two rubric passes each = the fan-out
  is the whole risk, exactly the concern SEED-058 flags and points at Phase 167 fable-mode's
  posture-scoping precedent.
- **Hard cap (required, not optional):** ceiling the number of pairs sent to the rubric pass
  (e.g. `MINDRIAN_EUREKA_REASONING_MAX_PAIRS`, default small -- start ~25 to match embedded's
  `--top 25`), selected by the free Jaccard pre-filter, so cost is bounded by the cap, never by room
  size. Reasoning-mode returns a REAL but deliberately SHORT ranked list (SEED-058 req 3).
- **Cheap-model / free-math routing for sub-tasks:** the Jaccard anchor, tokenization, and
  `verdictFromRubric` are zero-cost deterministic CJS -- keep every classification and pre-filter
  step there. Spend the paid reasoning pass ONLY on the 6-item rubric for the shortlisted pairs.
- **Caching:** the rubric verdict for a given (mechanismText, mappingStatement) pair is
  deterministic given the same judge answers; cache on a hash of the two texts + `LEXICAL_METHOD`
  (`jaccard-v1`) so a re-run of an unchanged room does no new reasoning work. This is exact-match
  caching; it also gives the re-run upgrade path (req 5) a cheap "did this pair change" check.
- **Latency posture:** reasoning-mode is a degrade path, not the hot path -- a short bounded list in
  a few seconds beats the embedded path's fuller result only when the encoder is genuinely absent.
  The bounded-pass deadline (`..._BATCH_MS`, `0` = kill switch) caps worst-case wall time.

## 5. Evaluation Strategy

> The central eval question for this phase is NOT "is the analogy good" (Phase 212's
> Grounding Guard already owns that) but "is a lower-confidence result HONEST enough to surface."
> Every dimension below is a calibration check, and the single most important one -- the
> fabricated-number prohibition -- is a deterministic code assertion, never a judge call. The
> "LLM judge" in this phase is played in CI by deterministic stub `judgeFn`s (the Phase 212
> encodeFn/judgeFn seam precedent), NOT a live model; real-judge accuracy is a HUMAN calibration
> checkpoint, mirroring the 212 plan-05 `>=0.85` bar, and is never asserted automatically.

### Dimensions

| # | Dimension | Rubric (PASS / FAIL) | Measurement | Priority |
|---|-----------|----------------------|-------------|----------|
| D1 | **Fabricated-number prohibition** (the hard, code-detectable guardrail Section 1b flagged) | PASS: every `mode:'reasoning'` statement and its JSON carry `differential_score === null` AND `semantic_similarity === null`; only `lsa_similarity` (Jaccard, `jaccard-v1`) holds a real `[0,1]` number. FAIL: any non-null `differential_score`/`semantic_similarity` on a reasoning result, or Claude asked to estimate either. A reasoning result that reports a differential number is lying about its evidentiary base. | **Code** -- deterministic `node:assert.strictEqual(x, null)` on both legs across every fixture; NEVER an LLM-judge score | Critical |
| D2 | **Confidence-basis honesty** (confidence separated from plausibility, ICD 203) | PASS: the result expresses trust-in-BASIS separately from pair plausibility and names WHY the basis is weak (2 of the critic's 3 numeric legs structurally null, no calibration bucket applies); no single blended "quality score" fuses the two. whether the upgrade delta reads honestly; the **calibration reviewer (ICD 203 lens)** reference-labels

(Gentner lens)** labels that the six-item bar held at true parity. Automated legs assert the STRUCTURE
(null legs, call-count, field names, `banked===false`); the humans calibrate the caveat WORDING and
own the real-judge accuracy bar (a human checkpoint, never an automated assertion).

`provenance` block. That block is the trace record: `run_mode`, the degrade cause
(`encoder_unavailable` / `below_floor`), `pairs_scored`, `pairs_sent` vs the cap, and
`formula_version` (`eureka-reasoning-v1`, distinct from embedded's `eureka-critic-v1`) so a re-run
can tell the two paths apart.

**Key Metrics to Track** (read from the `provenance` block, one record per run):
1. **run_mode distribution** (reasoning vs embedded) -- how often the fallback fires, i.e. the real
   frequency of the cold-machine and thin-graph gaps this phase exists to cover.
2. **Fabricated-number invariant** -- the null-rate of `differential_score` / `semantic_similarity`
   on reasoning results. Must be 100% null; any non-null is a P0 (D1).
3. **banked-on-reasoning count** -- must be exactly 0. Any value `> 0` is a Canon Part 9 breach (D5).
4. **pairs_sent vs cap** -- cost-cap headroom; how close runs come to
   `MINDRIAN_EUREKA_REASONING_MAX_PAIRS` (D8).
5. **reasoning->embedded upgrade delta** -- how much the confidence basis shifted once the encoder
   arrived (the primary calibration-quality signal: a consistently large delta means reasoning-mode
   was systematically over- or under-ranking).

**Alert Thresholds** (hard-fail the run AND the phase gate -- these are the online guardrails):
- ANY non-null `differential_score` / `semantic_similarity` on a `mode:'reasoning'` result -> hard
  fail. This is the one invariant that can never regress; it is the whole reason the phase exists.
- ANY `banked === true` on the reasoning path -> hard fail (Part 9, human-only truth-promotion).
- `mode` label absent from the render OR the JSON `provenance.run_mode` OR the html export -> hard
  fail (a report that reads as embedded when it was not is the exact over-trust vector).
- `pairs_sent > cap` -> hard fail (the unbounded-cost / O(N^2) fan-out guard).

**Smart Sampling Strategy** (the offline flywheel -- sampled batch, feeds the rubric, not a live block):
- **Sample every reasoning->embedded UPGRADE run.** This is the single highest-signal event: it is
  the only moment the working diagnosis can be compared against the instrumented one. The navigator +
  calibration reviewer label whether the reasoning-mode ranking was directionally honest and whether
  the delta read clearly (not silently swapped).
- **Sample reasoning-mode runs whose top pair was later human-confirmed off the embedded re-run** --
  did the short working-diagnosis list point diligence the right way, or did the navigator confirm a
  thin analogy that the fuller scan would have demoted?
- **Signal-metric divergence watch (the early-warning line):** if the navigator repeatedly acts on
  reasoning-mode pairs that the embedded re-run demotes, the reasoning rubric or the Jaccard band
  pre-filter is mis-calibrated. The fix routes back into the six rubric-item WORDING or the pre-filter
  band, never a silent code patch -- consistent with Section 1b holding the analogy bar at parity
  and lowering confidence ONLY through the missing similarity/calibration legs.
