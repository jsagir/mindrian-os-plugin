# Phase 369.2 Plan 16: answer lines carry execution truth Summary

A run's answer now says which questions were searched, which were not and why, what an empty result does and does not prove, and whether the searches for evidence against the claim ran, in plain words and with no id. The real-room report a person reads at every cut says the same.

## Plain-English version

Before: the deep answer read "The deep run stopped on cap after N searches and K validated rows; the governing thought reads X with Y unresolved branches", and the quick answer counted rows only. Neither said which question was never searched, or that "no records" is only what one query returned. After: the answer is assembled from the ledger the run kept. It names up to three questions that were not searched, each with its reason ("the run's search budget ran out before it"), then counts the rest. If a query came back empty it says which query and which provider, and that this is not proof the literature is silent. It says "Only 5 of 8 searches for evidence against it ran (the run's search budget ran out)" or "Not verified: ... did not run" and never "verified", "confirmed" or "complete" unless the ledger says complete.

## Deviations from Plan

**1. [Rule 1 - Bug] STOP_WORDS.budget would say "cost budget" for a search-cap stop**
- **Found during:** reading the 369.2-15 finding and deep.cjs (stop_reason 'budget' is set by both the USD stop and the search cap; test E8 pins it).
- **Issue:** the plan text maps budget to "the cost budget ran out", which is false for the common cap-8 stop (WD1 stops on the search cap with stop_reason 'budget').
- **Fix:** STOP_WORDS.budget is "the search or cost budget ran out"; `stopWords(stop, ops)` narrows it to "the search budget ran out" or "the cost budget ran out" when the operations carry a search_cap, ce_reserve_exhausted or budget_usd reason. REASON_WORDS.budget_usd keeps the plan's exact "the cost budget ran out" because an operation carries that reason only when the dollar stop closed it. No deep.cjs stop code changed.
- **Files:** lib/core/research-planner/job-lines.cjs. **Commit:** 61ebb9c0f

**2. [Rule 1 - Bug] The file writer turned the `—–` escapes in job-lines.cjs into literal dash characters**
- **Found during:** the dash grep before the first GREEN commit (the grep printed the line after the commit ran).
- **Issue:** `noDash` in the new module carried a literal em dash and en dash, against the hyphens-only rule.
- **Fix:** restored the escapes; the grep over all seven files now finds no dash. The behavior is identical.
- **Files:** lib/core/research-planner/job-lines.cjs. **Commit:** cf3e3fcd7

**3. [Rule 2 - correctness] Wording additions the plan did not name**
- A `skipFalsifiers` option on incompleteLines so deep does not list the same evidence-against operation as both an unsearched question and a counterevidence sentence; a `stopWords` helper; the CE reason words drop a trailing " before it" so "(the run's search budget ran out)" reads as a reason; `plurality_required` and `navigator_stop` stop words.
- The It could not line reads "<jobs> Beyond that, it could not <existing sentence>" rather than prepending the jobs to the bare verb phrase, which would not parse.
- WD9 (refused slot, verdict unresolved, card section) and WD7 (unit contract) were added beyond the plan's WD1-WD6.
