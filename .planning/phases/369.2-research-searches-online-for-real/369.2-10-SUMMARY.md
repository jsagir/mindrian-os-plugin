# Phase 369.2 Plan 10: One run grant per run through the CLI, ambient, MCP and acceptance suites Summary

The seven suites that plan 09 turned red now approve each web run once (the run grant) and keep every safety assertion. A room-started pass under a standing grant is pinned to what it now does: it queues a card that lists every exact string and sends nothing. The user-facing texts in the MCP tool, the standing card and the room's decision nodes no longer say "grant".

## Plain-English version

Before: the tests let a standing permission stand in for the approval of a run, because that is how the code used to work. After plan 09 it does not, so those tests failed for one reason only. Now each test does what a navigator does: the room shows a card with the exact searches, the navigator says yes to that run, and then the searches go out, exactly those. The overnight (ambient) path is described truthfully: it never searches by itself, it leaves a card. The words on the cards and next-step lines now say what the approval is for ("approve this run", "the search approval") instead of "grant".

## Deviations from Plan

**1. [Name clash] New legs take free numbers.** The plan names MCP "M12" and CLI "C13"; test-363-mcp-tool already has M12 (connectors export) and test-363-cli already has C13 to C17. The new legs are M13 (mcp) and C18 (cli). Ambient M12 and M13 are as planned. Each carries the suffix "(369.2 R02)".

**2. [Rule 1 - facts] The pass does not queue an evidence card.** The plan says M5, M9c and M13 end with "the evidence card is queued". A run grant is keyed to a run_id and every pass builds a fresh plan with a fresh run_id, so ambient step 5 (the only place that queues an evidence card) cannot be reached by a real pass. The tests assert the truthful form: the pass queues only the plan card (no evidence card queued), and the evidence card comes back from run-quick itself, unfiled. No ambient.cjs code change (comments only, as planned).

**2b. M6 seeds its ledger.** Because the pass no longer records a run, M6 seeds ledger entries with grants.recordRun to keep already_run_for_delta and throttled pinned, and M6b adds the "throttle not consulted for a run grant" assertion the plan asked for.

**3. [Scope, per the coordinator brief] Files outside the plan's files_modified.** research.cjs, wire-snapshot-zod4.json, test-365-never-do-gate.cjs (re-pin), grants.cjs, planner.cjs, test-363-grants.cjs, test-289-contract-recommended.cjs, tests/fixtures/seed104/whitespace-golden.json and tests/fixtures/366-theo-lane/golden.json. The brief said to apply the naming ruling to these texts and to re-pin RESEARCH_BASE in its own commit; the wire entry was refreshed in the same commit as the description (the 261002-cud precedent, 0b39f8528). golden.json is only read by test-366-theo-lateral-lane.

**4. [Rule 2 - truthfulness] Standing card rewritten to say what a standing approval does now.** Since plan 09 a standing grant sends nothing, so "lets the room send short search strings" would have been false on the card the ruling asked me to rename. The new body says it records the terms and search shapes the room accepts, sends nothing by itself, and that each run still asks once. Flagged for the navigator to read because it is new wording. The policy-version line moved from the body to the payload (it carries the id drp363-grant/1, which the ruling keeps out of card text); test-363-grants G11 asserts it in the payload and adds a no-word-grant assertion.

**5. [Test helper] A10 stubs coverFor as well as runQuick** to keep the re-ask call site pinned, since coverFor no longer covers under a standing grant (comment in the leg).
