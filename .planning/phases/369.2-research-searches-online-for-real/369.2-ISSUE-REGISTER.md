## Executive finding

The dominant failure pattern is silent degradation with a plausible success surface. The system often preserves its safety controls, but the operation underneath the control is missing, misrouted, starved, or unable to recover. This produces outputs that look governed and complete while key work never happened.

Four issue families account for most of the observed damage:

1. False or incomplete success: room scaffolding reports success without room.db; plans display leaves whose queries will never run; synthesis proceeds without a complete counterevidence pass.
2. Accepted input that is silently discarded or transformed badly: term2 is accepted but unreachable, Scientific Roadmapping leaf slots are ignored, and limiter prose is converted into an exact-phrase query.
3. A correct guard with a broken recovery path: write scope correctly blocks the wrong room, quote verification correctly rejects a mismatch, and graph integrity correctly rejects missing nodes, but the user cannot recover cleanly.
4. Capability labels that do not match the implementation: the patent lens is PubMed; broad search may include an unauthenticated industry lane; the analogy engine's structural score depends on graph entities rather than the supplied structural encoding.

## Recommended implementation order

1. Make success truthful: require database creation and readback for room success; make plans fail when a leaf has no reachable query; make synthesis incomplete when mandatory counterevidence did not run.
2. Fix source and slot routing: replace the false patent mapping, validate credentials before advertising broad coverage, assign Scientific Roadmapping slots, reject prose fallbacks, and validate term2 reachability.
3. Restore recovery: normalize quotes, keep rejected rows correctable, expose registry stderr, distinguish already-closed lanes, and name missing graph endpoints.
4. Align surfaces and documentation: unify Brain policy behavior, Jev flags and key preflight, room-creation semantics, browser-launch feedback, and the analogy engine's declared structural inputs.
5. Add end-to-end regression tests around outcomes: test that each displayed question generates a fetch, every mandatory pass spends reserved budget, every successfully created room accepts an MCP write, and every filed artifact can create its promised edges.
