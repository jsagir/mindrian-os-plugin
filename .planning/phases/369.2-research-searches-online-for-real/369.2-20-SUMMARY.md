After the entity fix a literal '<' quote now verifies, so it no longer drops. The test drops attempt 1 with a wrong number ('R < 0.4' for the text 'R &lt; 0.3') and corrects it with the right one. A fifth run checks that no window opens when every row was kept.

**2. [Rule 1 - behavior needed by the plan] already_recorded at step validate.** The plan wants a third call to answer already_recorded. When one lane is the last expected lane, the step is validate after the first record, and the old guard answered wrong_step. The guard now checks "expected and recorded" first. **3. Extra export and legs.** bareId is now exported from evidence-rows.cjs (the correction check resolves record ids the same way validateRows does). Extra legs: numeric entities (Q13b), the extra hash legs (Q13c, Q13h), the window-closed-after-validate leg and the no-window leg (Q13d), dropped_ids and exports (Q13f).

**4. Initial state fields.** initDeepState now writes `correction: {}` and `validated_round: null`. State files from before this plan lack them; the code treats a missing correction object as no window.

- The CE lane has no correction window (plan scope: non-CE lanes).
