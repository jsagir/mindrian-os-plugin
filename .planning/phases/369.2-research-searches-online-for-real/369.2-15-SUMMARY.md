# Phase 369.2 Plan 15: the counterevidence reserve and the completion gate Summary

A deep run can no longer spend its falsification budget on ordinary expansion, and it says which falsifiers ran. At cap 8 the falsification pass now executes inside a reserved share of the cap; where it cannot, the run reports it in a status computed from the ledger and is not complete.

## Plain-English version

Before: at a cap of 8 the two research rounds ate every search, the falsification pass planned nothing and ran nothing, and the run still said "counterevidence ran: true" and finished fine. After: the run sets aside a few searches at the start (3 of 16, 2 of 8). Rounds can only spend the rest. The pass spends the reserve. The result now carries a status (complete, partial, not_run, not_needed) with how many falsifier searches were planned, ran and failed, counted from the ledger across all rounds, so a falsifier that already ran in round one still counts. A run is only complete when every mandatory operation ran and the falsification status is complete.

## What changed in deep.cjs

- `computeCeReserve(plan)` and `roundCap(state)`; `initDeepState` writes `state.ce_reserve`, with the `opts.ceReserve` test seam (a non-negative integer). A state loaded without it reads 0.
- `activeGrant(..., {forCounterevidence})`: rounds and follow-ups see cap minus reserve through the grant's effective cap (`validateExecutedQuery` enforces it as cap_exceeded); `executeQueries` takes a `ceMode` flag, `runCounterevidence` and `prepareCounterevidence` pass the full cap; `proposeFollowups` and `extendCard` use `roundCap` (the counterevidence card shows the full cap).
- `nextAfterStop`: a round cut at the round cap (`state.round_cap_stop`) with reserve left still goes to the pass; a time or USD stop skips it as before.
- `executeQueries` reads the stop from the current query (`passStop`) instead of the latched `state.stop_reason`. Without this the pass stopped after one query once a round had left stop_reason at 'budget'.
- `runCounterevidence`: `state.ce.run = executed > 0` (the `|| queries.length === 0` false positive is gone; `grep "queries.length === 0"` no longer matches the assignment).
- `synthesize`: `run.counterevidence` gains status, planned, executed, failed, reasons from `operations.counterevidenceStatus(ledger)`, old fields kept; `completion` already carried the status (plan 14); `governing_status` and `unresolved_branches` wording untouched (open question 1).

## Deviations from Plan

**1. [Rule 1 - Bug] A round cut at the round cap skipped the counterevidence pass**
- **Found during:** Task 2 (B1 still executed 0 after the reserve landed)
- **Issue:** a round truncated at the (now smaller) round cap set stop_reason 'budget', and `nextAfterStop` sends 'budget' straight to synthesize, so the reserved searches were never spent. After that, the per-query latch `state.stop_reason === 'budget'` in `executeQueries` stopped the pass after one search.
- **Fix:** `state.round_cap_stop` flag; `nextAfterStop` still runs the pass when that flag is set and reserve remains; `executeQueries` reads the stop from the current query. stop_reason stays 'budget' (E8 pins it).
- **Files:** lib/core/research-planner/deep.cjs. **Commit:** ae76dfaac

**2. [Rule 1 - Bug] `ran` and the unresolved flag misread a pass that added zero searches (found by run-all-363, whitespace acceptance W5 and W5b)**
- **Found during:** Task 3 aggregator run (45/2 after ae76dfaac; Task 3's list did not name the whitespace acceptance suite)
- **Issue:** with `ce.run = executed > 0` alone, a whitespace deep run whose falsifiers all ran in round one reported `ran: false`, the exact C17 misread in the other direction.
- **Fix:** `ran` is true when the pass or any falsifier operation executed; the 'counterevidence not run' unresolved flag stays unless every falsifier operation executed (so E7's budget-stop flag stays, and B6 still reads not_run, ran false).
- **Files:** lib/core/research-planner/deep.cjs. **Commit:** 431fdd164

**3. [Rule 2 - correctness] The reserve is capped at cap - 1.** The plan formula gives 1 at cap 1, which would leave round one no searches. B7 covers cap 1 -> 0.

**4. B4 is derived, not a second deep run.** No fixture produces a deep run whose pass plans zero queries and zero gaps without state surgery. B4 asserts the all-rounds count on the real cap-16 ledger (run.counterevidence.executed 7, more than the pass alone, 3) and on that ledger with the pass ops removed (complete, executed 4). The whitespace acceptance suite (W5, W5b) covers the zero-extra-search deep run end to end.

No test pin moved in tests/test-363-run-deep.cjs, so Task 3 produced no commit.
