# Phase 369.2 Plan 14: the ledger wired into quick and deep Summary

Every quick and deep run now says, operation by operation, what it promised and what happened. Rows exist before the first fetch, each fetch moves its row to a terminal state, and run.json carries a "complete" that is computed from the ledger.

## Plain-English version

Before: a lane the fan-out cap cut, a counterevidence branch the search cap cut, a slot the composer refused, and a leaf with no composed search all left no trace, so "nothing found" and "never searched" looked the same. After: each of those has a row with a reason (lane_cap, search_cap, no_query_composed, bad_slot:<slot>). A search that failed at the provider is "not executed, attempted", never "empty". An empty result is only recorded with a counted zero. The run is "complete" only when the ledger says so.

## What the wiring does

- planner.cjs: `markLocalOnly(leaf, refusal, detail)` persists `leaf.refusal = {reason, slot}` (a slot name, never a value; for bad_slot the first slot whose value fails `composableTerm`).
- plan.cjs: `validateRunResult` accepts optional `operations` (array) and `completion` (object with boolean `complete`); older run.json files stay valid.
- quick.cjs: after the grant check and before the first fetch it creates the ledger and mints one op per fetch query (kind falsifier when the template is, else direct), one theo op per theo leaf, one refused_before_fetch op per leaf.refusal, one not_executed no_query_composed op per researchable web leaf with no query. Each fetch transitions its op at the audit and `runQueries.push` site with `audit_ref {q_hash, ts}`; theo checks map onto theo ops after the lane; a sweep and `completion(ledger, {counterevidence_needed: false})` run before the run object is validated; an audit-write failure closes the ledger as run_aborted before refusing. A quick run starts a fresh ledger each time (a re-ask returns before any ledger exists), so it never reads an old file and has no ledger_corrupt path.
- deep.cjs: `initDeepState` seeds round-one ops, lane_cap ops for the lanes `allLaneSpecs` returns beyond the cap (`laneSpecs` is now `allLaneSpecs(plan).slice(0, cap)`, same behavior), no_query_composed ops, refused ops. `proposeFollowups` mints round-two and follow-up ops (and search_cap ops for default searches the cap trimmed). `prepareCounterevidence` mints a falsifier op per CE query (plan_dimension `CE:<note>:<leaf>`), a search_cap op per over_cap gap, and a closed op per composition gap. `executeQueries` transitions at the `state.executed.push` site and closes every query it did not reach with time, budget_usd or search_cap; `fetchRound` closes the queries a truncated round never reached. `synthesize` sweeps with the stop reason mapped to the vocabulary (default search_cap) and sets `run.operations` and `run.completion` with `counterevidence_needed = plan.budget.counterevidence === true`. `state.executed`, `planned_round_one` and `timings.not_run` are kept.
- `loadState` (called by every deep step) refuses `ledger_corrupt` when `readLedger` throws; an absent file is a run begun before the ledger and reads as not complete at synthesize.
- lib/mcp/tools/research.cjs unchanged (`git diff HEAD~1 --stat` empty); RESEARCH_BASE untouched.

## Deviations from Plan

None that change behavior the plan names. Choices where the plan was silent or loose:

1. **L3 builds the refusal with a bad slot, not a theo prose slot.** `markLocalOnly` is only reached for web leaves (corpus openalex) in `attachQueries`, so a theo leaf with a prose slot never produces `leaf.refusal`. The leg uses a web leaf whose term fails composition (bad_slot). The theo mapping is covered separately by L9.
2. **Refusal reasons are mapped into the ledger vocabulary.** `bad_slot` becomes `bad_slot:<slot name>` (`bad_slot:unspecified` when no slot is identified), `term_not_composed` stays as is, any other composer reason (for example egress_violation) becomes `bad_slot:<reason>`.
3. **Counterevidence op dimension** is `CE:<note>:<leaf>` (note = goal_falsifier, branch_falsifier or limiter_derivation), so two branches never share an id; composition gaps use `CE:<branch>`.
4. **Ordinals are counted at mint time** (number of earlier ops with the same dimension, kind, template and round) and a query is found again by (query_id, round); ids are never recomputed on resume.
5. **A quick run does not read an existing ledger** (it starts a fresh one), so the ledger_corrupt handling lives in deep's loadState only.
6. **Round-two and follow-up ops are minted in `proposeFollowups`**, not inside `defaultRoundTwo` or `startRound`, because those two have no room directory; the rows still exist before dispatch.

## Findings for later plans

- **Scientific-roadmapping deep runs are never "complete" today.** The SR fixture has 9 researchable web leaves (L1 to L5, L12 to L15) that no limiter lane owns, so the run never searches them. Following the plan ("no_query_composed ops for researchable leaves with no query") they are mandatory not_executed ops, so `run.completion.complete` is false on every SR run, honestly. If the navigator-facing report should treat unsearched non-limiter leaves as non-blocking, that is a change to `mandatory` for those ops (one line in `seedDeepLedger`), a decision for plan 15 or later, not made here.
- **Pitfall 6 (for the phase CHANGELOG in plan 34):** persisting `leaf.refusal` changes `planHash` for any plan that carries a refusal; a deep run in flight across the upgrade whose plan has a refusal refuses `plan_hash_mismatch`. Plans with no refusal hash as before (no pinned hash in the 12 suites moved).
- **Pre-upgrade deep runs in flight** have no operations.json: executeQueries creates one lazily from that point (rows for what runs next), and synthesize reports not complete when no file existed.
- `lib/mcp/tools/research.cjs` result passes the new `run.operations` and `run.completion` through untouched; a later plan decides how the card and exports read them.
