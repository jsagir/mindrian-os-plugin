## Decisions Made

- `classify()` free-form arm returns `theoVerdict(...)`; every other arm (packets, known shapes, navigator release, final ambiguous) is byte-unchanged.
- `roomDir: undefined` resolves the active room, `null` means "no room"; this keeps the in-process raw-field guards (hatAwareRecommend, suggestValidationSteps, intel-pipeline and others that call `classify` without a roomDir) protected by the lexicon.
- Content rules as planned, with these tuned edges: a TitleCase run bridged by function words is one name ("Jobs To Be Done framework", "Porter Five Forces"); a run touching a methodology token or head noun, or sitting next to a head noun, is a methodology name; a Cypher literal compared to a `(x:Framework)` `.name` is exempt; labels after `:` and property keys after `.` are exempt; a string over 4000 characters is treated as private_context (a pasted document is room content by provenance).

## Deviations from Plan

**1. [Rule 3 - Blocking] Lexicon opens room.db through the navigation read-only door, not DatabaseSync**
- **Found during:** Task 2 commit (pre-commit `scripts/check-substrate.cjs --diff`, rule m3-direct-sqlite-require)
- **Issue:** the plan said `new DatabaseSync(file, {readOnly:true})`; the substrate gate refuses a `node:sqlite` require outside the navigation allow-list.
- **Fix:** `require('./navigation/spine-events.cjs').openRoomDbReadOnlyForCaller(roomDir)` (file: URI `?mode=ro`, SQLite rejects writes; the lexicon checks the file exists first, so a null handle fails closed). Consequence: two acceptance greps read differently. `grep -n DatabaseSync part8-room-lexicon.cjs` finds only comments (no `readOnly: true` literal) and `grep -c openRoomDb` is not 0 because the read-only door's name `openRoomDbReadOnlyForCaller` contains the prefix; the creating opener `openRoomDb(` is never referenced.
- **Files modified:** lib/core/part8-room-lexicon.cjs
- **Commit:** d2e40e885

**2. [Rule 1 - Bug] Name rule blocked the plugin's own generic questions and a CSV parity row**
- **Found during:** Task 2 and Task 3 (part8-egress-guard.test.cjs PB8-09 row 1 "Porter Five Forces"; test-205-grill-engine, whose Arm A question carries Red-Team-Steelman, Premortem, Reference-Class-Forecasting)
- **Fix:** TitleCase-run rule, hyphenated-compound exemption, `METHODOLOGY_TECHNIQUE_WORDS = {premortem}`.
- **Files modified:** lib/core/part8-egress-guard.cjs
- **Verification:** part8-egress-guard.test.cjs exit 0 (PB8-09 every CSV row), test-205-grill-engine exit 0
- **Commit:** d2e40e885

**3. [Rule 1 - Bug] callTool belt sentinel shape for non-free-form tools**
- **Found during:** Task 3 broad sweep (test-c8j-brain-wire deepStrictEqual on `discover_structure`)
- **Fix:** only free-form tools (brain_ask, brain_query, brain_search) get the new sentinel; every other tool's belt block keeps `{error, tool, egress_class}` byte-for-byte.
- **Commit:** d2e40e885

**4. [Rule 2 - Hardening] 4000-character ceiling and the unresolved-roomDir default**
- Added beyond the plan: a free-form string over 4000 chars blocks as private_context, and an undefined `roomDir` resolves the active room inside `theoVerdict` (see Decisions). Both close a way for room content or an unguarded raw-field caller to bypass the new allow path.

**5. Net guard scoped to the capture server.** `hygiene-355 installNetGuard` throws on every fetch, which would also stop the capture-server legs; the test installs an equivalent guard that only fails on a non-capture URL (V7 asserts zero stray sockets).

**6. Hook message.** Only `room_content` and `room_check_unavailable` blocks use the new "Canon Part 8: outbound Theo payload carries room content (<class>, <token_class>). Blocked." text; the `content_set` block keeps its existing wording so no unrelated pin moves.
