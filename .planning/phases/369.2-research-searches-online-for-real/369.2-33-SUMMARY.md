### D4: a counterevidence query quotes the entanglement sentence (integration gap)

Failure text: `the entanglement sentence is in 0 sent strings and 1 composed operations: CE:limiter_derivation:L7 ci.derivation not_executed search_cap "Entanglement requires pre-positioned physical barriers" AND ("fundamental limit" OR "theoretical limit" OR bound)`. The first closure run counted sent plus composed strings together and also found 1 ("is in 1 strings"); I did not split sent from composed in that run, so whether it left the machine then is UNVERIFIED. The leg now reports the two counts apart.

Root cause (read in `lib/core/research-planner/deep.cjs` `prepareCounterevidence`, and `families.cjs` `composableTerm` / `proseShaped`): LM1 has no derivation row, so it classifies as `assumed`. Its statement is composed through `composableTerm`, which treats a value as prose only when it holds sentence punctuation (`[.!?]` followed by text, markdown marks, list lead). The seed118 statement has 7 words and no punctuation, so it passes as a term and is sent as one quoted phrase. Plan 17's unit test uses a 132-character statement that ends with a question mark. The leaf lanes (L7, L8) are refused `bad_slot:limiter` correctly. Whether the string is sent or only composed depends on the search budget. No production edit was made here. Suggested owner action: a quick task or a plan 17 follow-up in `families.composableTerm` or in the CE composer (a limiter statement of 5 or more words is a sentence, so a gap `bad_slot:limiter`).

### D10: the seed118 room has no thing that bridges to the encoding (integration gap)
