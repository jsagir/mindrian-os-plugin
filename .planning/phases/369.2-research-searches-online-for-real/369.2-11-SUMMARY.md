# Phase 369.2 Plan 11: Basket is a card, never prose; commands teach one run approval Summary

The F.8 filing basket, where INPUT defect 4 ("i accept" taken as approval) happened, is now pinned card-only on both enforcement points, and the two command docs stop teaching the standing-grant flow and name the approval by its job.

## Plain-English version

Before: the "a yes is a card, never prose" rule was tested on the search approval only. Nothing proved that a typed "i accept" cannot file a basket. Also, two command docs still told the host that a standing permission lets the room search on its own. After: three new tests prove the basket cannot be approved by typing (the hook refuses it on the CLI, the server refuses a relayed answer after a dismissed dialog, and an accepted basket files exactly once). The docs say each run is approved once on its card, which lists every search, and the word "grant" no longer appears in what a navigator reads.
