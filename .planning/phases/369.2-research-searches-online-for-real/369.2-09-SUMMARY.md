# Phase 369.2 Plan 09: One run approval per run, every exact string on the card Summary

Every web run is now approved once, on a card that lists every exact string that will leave the machine, and a standing term grant can no longer authorize a send it never showed. The card is named by its job ("See every search before it leaves, then approve this run once.") and never says "grant".

## Plain-English version

Before: the planner asked for a standing permission with a list of terms, then asked again for each new term, and the card showed the actual search strings only when a slot held a phrase. A standing permission could therefore send a string no card had shown. After: each run gets one approval. The card says "These N searches will leave this machine for <your question>. Nothing is sent until you approve." and lists every string, one per line. Approving covers exactly those strings (a changed string is refused with zero fetch). Old standing permission files still read fine; they just do not send anything on the web lines any more.

## Navigator ruling 2026-10-05 (grant name), as applied here

Card (grants.cjs `runCard`): `title` = "See every search before it leaves, then approve this run once."; question "Send these N searches to OpenAlex for this run?"; options "Send these N searches (Recommended)" and "Not now"; body line 1 "These N searches will leave this machine for <job>. Nothing is sent until you approve."; then "The searches, exactly as they will be sent:" and one `- <q>` per string; caps, room scope, "Revoke: tell Larry to revoke the search approval at any time; the next search stops"; "Approving never files anything." The job is the navigator's own stated question (`grants.jobOf(plan)`, one line, 140 chars), fallback "this research run". Ids, policy version, families and template ids ride in the payload.

Answer lines: `grants.approvedLine(n, job)` -> "Approved: N searches left for <job>." (singular "1 search"), `grants.refusedLine()` -> "Nothing left this machine." The approved line is added to a finished `runQuick` result as `approval_line` (N = the searches that actually ran, so the claim is true when it is read) and surfaces on the CLI `run-quick` and MCP `run_quick` done outputs. The refusal line is the note the run gate returns when the navigator answers not now.
