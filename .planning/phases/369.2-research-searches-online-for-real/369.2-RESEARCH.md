## Summary

The diagnosis is done; this document is the implementation map. Three findings change how the planner must cut the work:

1. **The web-line fence is three layers deep, not one.** Removing `auditQueryString` from `families.cjs` alone (the v16 quick's open item) does not free the web lines: `lib/core/research-corpus.cjs:792` (`fetchCorpusEnvelope`) and `lib/core/rs-fetcher-academic.cjs:118` (`buildAcademicQuery`) run the same fence again before dispatch. Measured today: `fetchCorpusEnvelope({source:'openalex', query:'"wireless sensing in Tel Aviv"'})` throws `ExternalEgressViolation` with zero network calls, while the same call with "Lisbon" reaches fetch. In `deep.cjs`/`quick.cjs` that throw becomes `outcome: failed, failure_class: unknown_error` - a silent degradation of exactly the kind this phase exists to kill. Every existing planner test stubs `fetchEnvelopeFn` and so bypasses these two layers; only a test that drives the real corpus with the OpenAlex replay preload (`tests/helpers/openalex-replay-363.cjs`, the way `scripts/real-room-run.cjs` does) can see it. Removing the `research` line from `data/egress-policy.json` without touching `audit-ledger.cjs:83` aborts every run (`lineForProvider('openalex')` becomes null, `appendAudit` returns `egress_line_off`, the runner returns `audit_write_failed`).
2. **J4 is already a pinned known red.** `lib/core/part8-egress-guard.test.cjs` PB8-03 ("What frameworks address an ill-defined problem at the discovery stage?" must ALLOW) is carried as a KNOWN red in `tests/run-all-363.sh:177` and as a red leg of `run-all-361`. The content-not-shape fix heals it. A prototype of the content rules (room lexicon, private-context markers, unknown identifiers, unknown names not next to a methodology head noun) run against the 10 Phase 0 probe prompts, the 10 `test-354` PRIVATE canaries, `CANARY7F3A2B` and the PB8-03 leaky sentence gave 0 mismatches (scratch run, not shipped). Twelve test files pin `freeform_unproven`/`freeform_unmatched` (47 references); they are the main churn of wave 1.
3. **The operation ledger belongs beside the run, not in room.db.** `lib/core/navigation/CONTEXT.md:63` forbids DDL beyond the two write chokepoints, scaffolded rooms can lack room.db (SW-01, 369.3), and the planner is fs-only today. `deep.cjs` already keeps `state.executed`, `state.planned_round_one` and `timings.not_run`; the ledger is the missing pre-dispatch half of that, written as `operations.json` in `.mindrian/research-runs/<run_id>/` and snapshotted into `run.json`.

**Primary recommendation:** Wave 1 removes the fence at all three web layers (composer, grant check, corpus/fetchers) and moves `appendAudit` off the policy gate in the same commit, replaces the Theo free-form arm with one `theoVerdict()` used by all four enforcement points (callTool belt, `_typedFreeformGate`, `query()`, the PreToolUse hook), and proves both through `real-room-run.cjs --seed` on a second fixture room whose question names a fenced city, a person and a product. Waves 2-4 then build the ledger and route every fix through it.

### Anti-patterns

- **Removing a fence in one layer.** The corpus and academic fetcher re-run it; a stubbed `fetchEnvelopeFn` test passes while production fails as `unknown_error`.
- **Inferring completion from `ok: true`.** `fetchRound`, `runCounterevidence`, `synthesize` all return `ok:true` on incomplete work today; only `completion` may say complete.
- **Treating a failed call as empty.** `executed_empty` needs a numeric count from a completed call.
- **Opening room.db through `openRoomDb` from the hook.** It creates the directory and database (REV-05); use `DatabaseSync(..., {readOnly:true})` on an existing file.
- **Ids in cards.** Leaf ids, lane letters, run ids, shape and verdict codes belong to the JSON payload, the filed record and the ledger.

## Common Pitfalls and landmines

1. **Fence in three layers** (above). Warning sign: a city query composes but the audit line shows `outcome: failed, failure_class: unknown_error`.
2. **Policy line removal aborts every run.** `audit-ledger.cjs:83` refuses a record for a provider with no line. Change `appendAudit` in the same commit as `data/egress-policy.json`.
3. **`--offline` silently stops working.** Today offline works by turning the `research` line off (`egress-policy.cjs:114`); with the line gone, quick and deep must check `opts.offline` directly. `scripts/real-room-run.cjs --offline` and the gate's "refuses an offline receipt" depend on it.
4. **`audit` field coupling.** `deep.cjs` and `quick.cjs` write `part8_verdict: q.audit === 'pass' ? 'pass' : 'tripped'`, and `audit-ledger.cjs:28 VERDICTS = ['pass','tripped']`. A new `'not_applicable'` value records web strings as `tripped` unless both writers and `VERDICTS` change. Simplest: web composer keeps `audit:'pass'` meaning "no Part 8 check applies", documented; cleaner: add `not_applicable` everywhere.
5. **`contentHash` must not change.** `normalizeText` keys `contentHash` (`evidence-rows.cjs:122`); entity decoding goes into a separate quote key.
6. **Plan hash shifts.** Persisting `leaf.refusal` or `query_kinds` changes `planHash` (`plan.cjs` HASH_EXCLUDED has only `plan_hash, created_at, revision`); a deep run in flight across the upgrade refuses `plan_hash_mismatch`. Acceptable, say so in the CHANGELOG.
7. **Byte pins.** `tests/test-365-never-do-gate.cjs:520` `RESEARCH_BASE` pins `research_run`'s description, title and input schema; any change to `lib/mcp/tools/research.cjs` DESCRIPTION (`:800`) or its zod schema needs a re-pin (handler code is free). `GATE_BASE` (`:543`) pins `gate.cjs` bytes; this phase should not touch `gate.cjs`. Do not add a new `research_run` op for the ledger; carry it in run results.
8. **Release step-block fixtures.** `tests/fixtures/341-release-step-block-hashes.txt` (35 blocks) and the 310 fixture (red on HEAD, 35 headers vs 33 pinned) break on any `release.sh` edit; this phase should not need one. If the receipt schema changes, the gate lives in `scripts/release-lib/real-room-gate.sh`, not `release.sh`.
9. **Skill mirrors and registries.** Editing `commands/research.md`, `eureka.md`, `find-*.md`, `scout.md` requires `node scripts/build-skill-mirrors.cjs` and `--check`; frontmatter edits additionally move `data/connector-registry.json` and the orchestration projection. `data/harness-manifest.json` is already stale against `agents/larry-extended.md` (muy summary, run-all-341 FAIL 2); editing larry surfaces will not fix it by itself.
10. **Goldens.** `tests/fixtures/seed104/whitespace-golden.json` (S0), `tests/fixtures/366-eureka-golden/`, perspective interface goldens re-capture when cards always show strings and perspectives use the web slot rule; capture with the test's `--capture` flag and a dated comment.
11. **Known reds that will flip or stay.** Before wave 1: run-all-363 `PASSED=45 FAILED=4 SKIPPED=1 KNOWN=4` (535 s); run-all-366 `PASSED=70 FAILED=0 KNOWN=1` (119 s); `test-muy-real-room-rule` 14/1 (G10b: CHANGELOG `[Unreleased]` lost the real-room entry at the beta.59 cut). PB8-03 turns green in wave 1 (drop its `run_known`), which also changes `run-all-361`'s totals.
12. **Hook budget.** The Part 8 hook's timeout is 2000 ms; the lexicon read is ms-scale, but `resolveActiveRoom` plus a 256 KB artifact walk is not; read titles and claims from room.db, not the artifact bodies, in the hook.
13. **Standing grants.** Ambient quick runs use standing grants (`grants.cjs` `lifetime: 'standing'`, throttle `:507`). Retiring `new_term` on web lines without moving those runs to run grants would let an ambient run send strings no card showed. Route web runs through run grants.
14. **`laneSpecs` cap.** `deep.cjs:237 specs.slice(0, cap)` (fan-out cap from `orchestrator.resolveFanoutCap`) drops whole lanes silently; the ledger must mint `not_executed:lane_cap` rows for them.
