<objective>
Let a person answer a gate raised in another session without loosening the ledger: the shell raises a mirror of it on its own session (gate_render mirror_of), the answer on the mirror records the source as answered in the same transaction, and the source replays that answer to its owner.

Purpose: the answerability half of gap 1 (SHELL369-12), following the design paragraph in 369-33-PLAN.md's objective (the ruled direction "the shell raises the gate on the browser session", 369-ADAPTER-RULING.md). The browser never answers the source id: the source stays owned by its session (D-19, Phase 289), the browser answers its own mirror through the nonce-bound human-only path (D-15), and the durable anchor carries the decision across processes.
Output: mirror_of on gate_render, the mirror and answered-elsewhere logic in gate_answer, and tests/test-369-gate-mirror.cjs.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller -> gate_render mirror_of | any session bound to the room can ask for a mirror |
| mirror answer -> source anchor | one session's answer settles a gate owned by another process |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-369-36-01 | Spoofing (a card the person never saw) | gate_render mirror_of | mitigate | the card is built from the room's record; a caller's different option ids are refused mirror_mismatch (arm 1) |
| T-369-36-02 | Elevation of privilege | answering another session's gate | mitigate | the browser answers only its own mirror under the session-scoped ledger; a stranger is refused session_mismatch and the owner still answers (arm 5); the source id is never consumed by another session |
| T-369-36-03 | Tampering (double decision) | two answers | mitigate | the anchor read runs inside the write transaction before the first write; the first committed answer wins, the other replays answered_elsewhere and writes nothing (arms 3, 4, 5) |
| T-369-36-04 | Tampering (approve with Hold) | mirror coherence | mitigate | approving ids carried from the record; the 289 coherence check refuses (arm 7) |
| T-369-36-05 | Repudiation | which surface decided | mitigate | the source anchor carries answered_via the mirror id; the decision node is the mirror's |
| T-369-36-06 | Denial of service | resume run twice | mitigate | the resumeFn runs once at the post-release point, a repeat replays (arm 6) |
</threat_model>
