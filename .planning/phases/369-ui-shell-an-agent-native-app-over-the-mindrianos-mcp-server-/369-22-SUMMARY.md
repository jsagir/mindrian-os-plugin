## Task 2: the launcher

`lib/ui-shell/launch.cjs` (CJS, built-ins plus `lib/mcp/daemon-lifecycle.cjs`, switch-case router).

- `start`: `ensureDaemon({ env: { MINDRIAN_MCP_FIRST: 'cowork' } })` (the plan 07 scrub removes CLAUDE_CODE_SESSION_ID there); reads `<dist>/manifest.json` (refuses "The workspace is not built in this install." when absent); mints a 32-byte base64url code and hands the server only its sha256, through the environment at spawn or `POST /control/bootstrap` with the 0600 control token on reuse; spawns `node <serverEntry>` detached with CLAUDE_CODE_SESSION_ID deleted, telemetry off, `MOS_DAEMON_URL`, `MOS_SHELL_PORT`, `PORT`, `HOSTNAME=127.0.0.1`; waits up to 20 s (`MOS_SHELL_START_TIMEOUT_MS`); writes `~/.mindrian/ui-shell/shell.json`; prints exactly the link and "This link works once, for this computer only, for the next 60 seconds."; `--open` goes through `platform.openBrowser` (its loopback guard).
- `stop` kills only the pid in shell.json after confirming its command line contains the recorded server entry (/proc, else ps); a stale or foreign record is cleared and the process left alone. `status` prints running (port, version, pid) or "not running".
- Refusals exit 1 with a What / Why / Fix message: missing build, port in use by another program, server stopped while starting, control file not private.
- Fixture `tests/fixtures/369/fake-shell-server.cjs` stands in for the shell server (control endpoint, single-use 303 exchange, env-keys dump). Commit 08359dab5.

## Deviations from Plan

**1. [Rule 3 - Blocking, environment] Verification ran with NODE_PATH pointing at the leftover ajv and accepts directories.** The shared `node_modules` is damaged (see Deferred Issues): `ajv` and `accepts` are missing, so `build-connector-registry.cjs --check` failed at a clean HEAD (proven by reverting my three changes), with 19 lines of "GAP mcp_tool_file" for every tool file. A scratchpad directory of two symlinks to `node_modules/.ajv-bECekonM` and `node_modules/.accepts-HiMB8sGW`, passed as NODE_PATH, made the gate pass (exit 0) without touching the shared tree. The tests themselves carry no NODE_PATH dependency; they need a healthy `node_modules`.

**2. [Rule 1 - small robustness] "Listening line" implemented as a port probe.** The plan says wait for the server's listening line; the real Next standalone server prints its own banner, so the launcher probes 127.0.0.1:<port> and also fails fast when the child exits. The fake server still prints a listening line.

**3. [Rule 2 - missing critical] PORT and HOSTNAME set in the server env.** The Next standalone `server.js` reads `PORT` and `HOSTNAME`, not `MOS_SHELL_PORT` (the package's own `start` script maps them); without `HOSTNAME=127.0.0.1` it would bind every interface. Plan 28's server entry may read the MOS_ names; both are set.

**4. Reuse conditions tightened.** Reuse also requires the recorded daemon port to match, so a daemon restarted on another port replaces the shell server instead of leaving it pointed at a dead URL.
