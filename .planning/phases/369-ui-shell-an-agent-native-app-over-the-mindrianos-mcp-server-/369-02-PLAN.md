<objective>
Wave 0, part 2 of 4: build the enforcement for the D-17 erasable-only rule in a walled-off package, prove the root manifest stays free of TypeScript and UI packages, and wire the gate into the release ceremony.

Purpose: Node strips types but never reads tsconfig and never type-checks, so nothing at runtime stops an enum or a namespace from landing in lib/core until a user's machine throws. And any TypeScript or UI package added to the root package.json (even as a devDependency) reaches every user through the loader's `npm ci --ignore-scripts` with no `--omit`. This plan closes both doors before any TypeScript is written.
Output: tools/ts-check (package, lockfile, tsconfig, runner, fixtures, README), two tests, one release.sh gate block.

Scope note (2026-10-02 checker warning, planner's call recorded): 17 files are kept in one plan because ten of them are fixtures of a few lines each (one forbidden construct or one allowed shape per file, no logic), so the real load is the runner, its tsconfig, two tests and one release.sh block; the fixtures must stay that small, and any fixture that needs logic beyond its one construct is a sign to stop and split.
</objective>
