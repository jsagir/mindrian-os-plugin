Per D-08, D-14 and D-15, `server/actions.ts` `createShellActions({ pool, proposalSource })` registers with defineShellAction and the generated adapter wrappers (never raw tool-name strings in action bodies): `listRooms` (both; room_list), `openRoom` (human; room_bind; when the browser session has an open gate in another room it refuses `{ ok: false, reason: 'gate_open', gate_id }` unless the input carries `confirmLeave: true`, which the UI's room-switch dialog sets), `roomDoc` (both; composes room_state status and question_read into the `room` document: question, purpose, counts), `readArtifact` (both; room_artifact), `feedChanges` (human; room_changes passthrough for the browser replica), `askClaude` (human; runs `proposalSource.propose({ roomSlug, selectedNodeId, question })` then calls `proposeDecision` through the in-process AGENT path), `proposeDecision` (agent; validates the proposal with ProposalSchema and calls gate_render on the BROWSER session's MCP key, recording the gate id against that browser session and room), `readGate` (human; returns the gate card this browser session minted, from the server-side record of gate_render results keyed by browser session and gate id, with the room it was minted in), `listOpenGates` (human; the gate ids and headers this browser session holds open, for the Decisions view and the waiting count), `approveDecision` (human; gate_answer with gate_id, chosen and verdict on the same MCP key; returns the server's answer unchanged so the UI can render recorded, replayed or refused states). Plan 21 adds the single-use render nonce to readGate and approveDecision. `invoke(name, input, ctx)` takes the principal ONLY from ctx (`'human'` from the browser route, `'agent'` from the in-process adapter path), deletes any `principal` key from input before validation, refuses `{ ok: false, reason: 'human_only' }` when `callableBy(ctx.principal)` excludes the action and `{ ok: false, reason: 'unknown_action' }` for names not registered; fileArtifact, reviseClaim, attachEvidence and publishDeliverable are deliberately absent (comment cites D-08 and D-13). <threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser (127.0.0.1) -> action, feed and status routes | untrusted requests carrying a session cookie |
| in-process agent path -> action registry | the Claude adapter flow must never reach human-only actions |
| shell server -> MCP daemon | one MCP session per browser session |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-369-32-01 | Tampering | CSRF on approveDecision or openRoom | mitigate | the action route runs origin guard, session and requireCsrf before invoke; arm 6 proves 403 over HTTP |
| T-369-32-02 | Elevation of Privilege | the agent path invoking approveDecision | mitigate | principal from the code path only, input principal deleted, callableBy enforced (arm 3) |
| T-369-32-03 | Elevation of Privilege | the 1:1 adapter exposed over HTTP | mitigate | no route imports the adapter; one browser action route (arms 4 and 10) |
| T-369-32-04 | Tampering | a gate minted on the adapter's session (unanswerable by the person) or a room switch retargeting an open gate | mitigate | proposeDecision mints on the browser session's MCP key; openRoom refuses gate_open without confirmLeave (arm 5) |
| T-369-32-05 | Information Disclosure | feed pages or hints for a room the session is not bound to | mitigate | feed routes read only the session's bound room through its own MCP session; no cookie, no page (arm 7) |
| T-369-32-06 | Tampering | XSS from room content | mitigate | room content rendered as text in React (no raw HTML); CSP from plan 19 blocks inline scripts |
| T-369-32-07 | Repudiation | "Connected" shown without a live round trip | mitigate | connection state flips to connected only after an acknowledged MCP call (arm 9) |
</threat_model>
