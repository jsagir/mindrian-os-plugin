<objective>
Measure both production-built candidates on the nine D-05 measures with one harness, write the comparison, put it to the navigator as a Decision Gate (D-07), and record the decision with everything the chassis-neutral shell plans need to proceed.

Purpose: the chassis choice shapes every later plan; D-07 makes it the navigator's call on measured evidence, with a stated tie-break (the workroom default holds on a split, the donor's winning parts are transplanted). The UI-SPEC also hands the bake-off one implementability question: whether the BlockNote display renders under the contract's CSP without inline styles.
Output: the harness, results.json, a comparison table, a harness test, the navigator's decision, and the decision record.

Scope note (2026-10-02 checker warning, planner's call recorded): the four tasks stay in one plan. The executor's load is Task 1 (harness and scoring tests) and Task 2 (two builds and one measurement run); Task 3 is a Decision Gate with no executor load and Task 4 is a short record written from the reply. Splitting Task 1 into its own wave-3 plan would not shorten the critical path (this plan already waits on plan 17 in wave 3) and would separate the harness from the first run that exercises it. If context passes half after Task 2, the executor commits and returns at the Task 3 checkpoint, which it does anyway.
</objective>
