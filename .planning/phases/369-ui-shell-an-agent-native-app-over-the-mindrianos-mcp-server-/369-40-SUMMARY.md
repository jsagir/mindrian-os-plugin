# Phase 369 Plan 40: Terminal-only link, secret-free browser start, exact identity, allow-listed env, adapter default Summary

Run the way Claude Code runs it (`!node ... start`, stdout a pipe), the launcher now puts no sign-in credential into the conversation or any argument list: it arms the start slot through the 0600 control channel and opens the browser at `http://127.0.0.1:<port>/auth/start`; a real terminal still gets the one-time link.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Own opener instead of platform.openBrowser**
- **Found during:** Task 2
- **Issue:** `platform.openBrowser` returns nothing (the plan needs "opened or not") and spawns `xdg-open` without an `error` listener, so a missing opener raises an unhandled async 'error' event and crashes the launcher after the slot is armed.
- **Fix:** `defaultOpenBrowser` in launch.cjs: same disable switches (MINDRIAN_OPEN_BROWSER_DISABLE, MINDRIAN_TEST_MODE, CI) and localhost guard, listens for `error`/`exit`, resolves true/false. lib/core/platform.cjs untouched.
- **Commit:** a4b3081b9

**2. [Rule 2 - Missing critical] Stale control token cannot be armed with**
- **Issue:** after a stale-record clear the previous server's token file could still be on disk, so a fresh spawn could be armed with a dead token (race with the new server's write).
- **Fix:** a leftover plain token file is unlinked before a spawn (symlinks and directories are left for the server's own refusal); the launcher then waits for the new file.
- **Commit:** a4b3081b9

**3. [Test design] Env dump moved next to the token file**
- The old fixture used `FAKE_SHELL_ENV_DUMP`; the allow-list would strip it, so the fixture now writes its dumps beside the control token file, whose path the launcher does pass. Arm 1c was rewritten accordingly.
