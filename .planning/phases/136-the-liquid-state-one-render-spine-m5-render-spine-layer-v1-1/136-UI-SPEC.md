# Phase 136 - UI Design Contract

> Visual and interaction contract for the M5 render-spine layer. This is NOT a CSS/Tailwind web phase. The "design system" is a De Stijl TERMINAL token core (ANSI-legible semantic color PAIRS + box-drawing glyph vocabulary) mapped onto three surfaces: the opt-in `mos tui` ink navigator (the novel surface), Larry's inline 4-zone text render, and the live-SSE web twin. The six standard design dimensions are mapped onto this reality: "typography" = monospace glyph/box-drawing vocabulary; "spacing" = the 4-zone anatomy + pane layout grid; "color" = contrast-checked semantic ANSI pairs. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> No em-dashes anywhere (project hard rule, hyphens only). Source of truth for the look-and-feel: the canonical `136-tui-achievable.html` mockup committed in this phase dir. Behavior reference: `136-tui-simulation.html` (in-place highlight + slot whisper, Space multi-select, free-text escape).

## Spacing Scale (mapped: 4-zone anatomy + pane layout)

Terminal layout has no px. "Spacing" is the column/zone discipline. All numeric exceptions are character-cell multiples of 4 where a numeric value applies (web twin paddings).

### Zone discipline (inline + tui, from SKILL.md Section 1, applies to all surfaces)

| Token | Value | Usage |
|-------|-------|-------|
| Zone 1 Header | 1 line | room > section > node breadcrumb; decision-gate marker when a gate is open |
| Zone 2 Body | flex | tree / detail / shape payload; no chrome |
| Zone 3 Intelligence strip | <=3 lines | LazyGraph whisper slot; HIGH/MEDIUM signals only; omit when silent |
| Zone 4 Action footer | 2-3 lines | NEVER omitted; grounded next-move commands |
| Indent unit | 2 spaces per tree depth | fractal tree nesting (mockup: `pad += '  '` per level) |
| Glyph gutter | 1.4em / 2 cells | fixed-width glyph column before every tree label (`.gl` width:1.4em) |
| Width ceiling | 80 cols default | never expand beyond; <60 cols -> compact header, collapse trees, 1 signal max |

### `mos tui` pane layout

| Token | Value | Usage |
|-------|-------|-------|
| Workspace split | session=room / window=section / pane=surface (D-11) | launcher-generated from the room graph |
| TUI internal split | tree pane : detail pane = 1fr : 1fr | the `mos tui` navigator body (mockup `.tui` grid) |
| Pane header | 1 line, uppercase, `letter-spacing` cue | identifies pane owner (`mos tui navigator (ink)`) |

### Web twin (numeric, character-cell multiples of 4)

| Token | Value | Usage |
|-------|-------|-------|
| Pane padding | 8px / 12px | pane body inset (mockup `.pbody` 10px 12px rounds to scale; use 8/12) |
| Gate widget width | 360px | floating decision-gate pane |
| Gate row padding | 4px / 8px | option rows |

Exceptions: gate widget fixed at 360px (content-driven, not a layout grid cell). The 1.4em glyph gutter is an em multiple, not a 4-multiple, because it tracks the monospace cell, not a px grid.

## Typography (mapped: monospace glyph + box-drawing vocabulary)

Terminal "typography" is the glyph vocabulary + the box-drawing set + the two weight-equivalents available in a terminal (normal + bold). Exactly 2 weights; the "sizes" are the four semantic text roles (no px in a terminal; the web twin pins px for parity).

### Weight (exactly 2)

| Weight | Terminal | Web twin | Usage |
|--------|----------|----------|-------|
| Normal | default SGR | 400 | body content, tree labels |
| Bold | `\033[1m` | 700 | pane headers, selected verb labels, primary action, breadcrumb focus node |

### Text roles (4 - the terminal analog of font sizes)

| Role | Web twin px | Weight | Line height | Usage |
|------|-------------|--------|-------------|-------|
| Header / breadcrumb | 12px | bold | 1.5 | Zone 1; pane headers; gate title |
| Body | 12px | normal | 1.5 | tree labels, detail body, conversation text (mockup `.pbody` 12.2px line-height 1.5) |
| Meta / hint | 9.5-10px | normal | 1.6 | counts, timestamps, key-hints, "would write to room.db" label |
| Section label | 10-11px uppercase | bold | 1.5 | pane owner tags, "other rooms" separator, gate context chip |

Body line-height 1.5 (terminal + web). Header line-height 1.5 (single-line zones). No display tier (terminal has no large type).

### Box-drawing vocabulary (the layout "type" set)

| Element | Char(s) | Usage |
|---------|---------|-------|
| Border (tui pane) | ink `borderStyle: 'round'` (`╭ ╮ ╰ ╯ ─ │`) | pane and gate-widget frames |
| Tree branch | `├` (branch) / `└` (last-branch) | sibling connectors (existing glyph vocab) |
| Breadcrumb separator | `>` (arrow glyph) | Zone 1 `room > section > node` |

## Glyph Vocabulary (12 existing + 4 new TUI glyphs)

The 12-glyph SKILL.md vocabulary is the base. Phase 136 adds exactly 4 new glyphs per D-14. Every glyph has ONE meaning. NO EMOJI.

### Existing 12 (reused, from SKILL.md Section 3)

`filled-square` progress fill / decision-gate marker; `down-triangle ▼` expanded node; `right-triangle-filled ▶` collapsed+content / primary action / >=0.7 pick; `right-triangle-empty ▷` collapsed+empty / alternative; `branch ├`; `last-branch └`; `checkmark ✓` complete; `bullet •` draft/partial; `warning ⚠` contradiction/tension; `lightning` convergence; `empty-square` gap; `arrow >` inline suggestion / breadcrumb separator.

### New 4 (Phase 136, D-14)

| Glyph | Codepoint | Meaning | Surface |
|-------|-----------|---------|---------|
| `◇` | U+25C7 white diamond | Cross-room / cross-wall edge node ("other rooms" separator + cross-wall edge marker) | tui + web |
| `○` | U+25CB white circle | Empty section (0 entries) - tree node with no content | tui + web (matches mockup `.empty`) |
| `☑` | U+2611 ballot box with check | Multi-select option TOGGLED ON (gate widget) | tui + web |
| `☐` | U+2610 ballot box | Multi-select option TOGGLED OFF (gate widget) | tui + web |

Glyph legibility caveat (Assumption A5): confirm `◇ ○ ☑ ☐` render at single-cell width on the Windows tester's terminal during execution; if `☑/☐` render double-width or tofu, fall back to `[x]` / `[ ]` ASCII pair (still glyph-backed, still passes the contract).

## Color (mapped: contrast-checked semantic ANSI pairs, glyph-backed)

The token core is a surface-agnostic graph of semantic color PAIRS: each meaning is bound to a De Stijl base hue AND its terminal-legible variant, contrast-checked to WCAG 3:1 (UI) / 4.5:1 (text). Color is ALWAYS glyph-backed - never color alone (D-14). The CLI semantic 5-color contract (SKILL.md Section 4) governs the inline surface; the terminal-legible variants below govern the `mos tui` + web-twin dark surface.

### Surfaces (60/30/10 mapped to terminal background tiers)

| Role | Hex | Contrast vs bg | Usage |
|------|-----|----------------|-------|
| Dominant (60%) | `#0D0D0D` bg (mondrian_black) | - | terminal/tui/web background |
| Secondary (30%) | `#161514` surface | 1.06 vs bg (elevation only, non-text) | pane bodies, selected-row base, gate widget body |
| Accent (10%) | semantic variants below | see pairs | reserved for the specific elements listed per pair |

### Semantic color PAIRS (each = base hue + terminal-legible variant + backing glyph)

| Semantic | Base hue (palette.json) | Terminal variant | Contrast vs `#0D0D0D` | Backing glyph | Reserved for |
|----------|-------------------------|------------------|----------------------|---------------|--------------|
| body / foreground | `#F5F0E8` cream | `#E8E2D6` t-fg | 15.07 (text PASS) | none (default text) | all body/tree-label text |
| core / focus / affirmative | `#2D6B4A` success_green | `#5BBF8A` t-green | 8.57 (text PASS) | `✓` checkmark / `▶` focus | confirmed nodes, the focused/selected tree row, "written to room.db" confirmation, multi-select `☑` |
| thin-client / command / link | `#1E3A6E` mondrian_blue | `#6E8AC6` t-blue | 5.66 (text PASS) | `>` arrow / detail header `#` | commands, paths, links, detail-pane heading, graph-edge target |
| warning / tension | `#C8A43C` mondrian_yellow | `#D8B24A` t-yellow | 9.61 (text PASS) | `⚠` warning | CONTRADICTS edges, tension rows, selected-row outline |
| error | `#A63D2F` mondrian_red | `#C9604F` t-red | 4.88 (text PASS) | `x` (error line 1) | errors ONLY (never warnings) |
| Larry / decision | `#6B4E8B` amethyst | `#9A7BBE` t-amethyst | 5.51 (text PASS) | `filled-square` gate marker | Larry voice, gate title, free-text slot accent |
| host CLI / floating | `#B5602A` sienna | `#CE7A45` t-sienna | 6.01 (text PASS) | `◇` (host pane) | the Claude Code host-pane tag, floating gate-pane border, launcher/zellij chrome (host-owned) |
| meta / hint (UI, 3:1) | `#A09A90` gray_meta | `#7A756C` t-dim | 4.25 vs bg (UI 3:1 PASS; non-essential text) | none | counts `(12)`, timestamps, key-hints, "would write" label, separators |

Accent reserved for: the exact elements named in the "Reserved for" column above. NEVER "all interactive elements". NEVER combine two semantic colors on one token (SKILL.md Section 4 hard rule). Color is decoration-free: every colored token also carries its backing glyph or its zone position.

Caveats recorded (not blocking):
- `meta/hint #7A756C` is 4.25 vs bg (clears the 4.5 text bar only narrowly and is 3.98 vs the `#161514` surface). It is declared a UI/meta token at the 3:1 bar for NON-ESSENTIAL text (counts, hints, timestamps). Do NOT use it for any essential content. RESOLVED (UI-checker FLAG, 2026-05-31): because 3.98 vs `#161514` falls below even the 3:1 UI bar, meta/hint is RESTRICTED to the `#0D0D0D` base background ONLY - it must NOT render on any elevation surface (`#161514` selected-row base, gate widget body, pane body). The contrast linter (Req 7) must assert 3:1 for this pair measured against EVERY background it can land on (which, by this restriction, is only `#0D0D0D`) and 4.5:1 for the seven text pairs above; a meta/hint token placed on `#161514` is a linter failure.
- The web twin uses the SAME variants (the mockup CSS `--t-*` vars equal these hexes), so the contrast check is one check for both dark surfaces.

### Destructive / second semantic color

`error #C9604F` (red) is the only destructive-signal color and is reserved for errors ONLY. BUD (promote section to sub-room) and gate-commit are NOT destructive (they are additive graph writes); they use `core/affirmative green`. There are no irreversible destructive actions in this phase (zoom is reversible, focus events are journaled, edges are additive). See Copywriting Contract for the one confirm-style interaction (gate commit preview).

### Key map (the stated keys are LOCKED; the rest are recommended defaults per Claude's discretion)

| Key | Action | Scope | Source |
|-----|--------|-------|--------|

| `Right` / `Enter` | expand node (tree) / commit set (gate) | tree, gate | LOCKED |

### Tree node states

| State | Glyph | Color | Visual treatment |
|-------|-------|-------|------------------|
| Collapsed + content | `▶` right-triangle-filled | body fg | default row |
| Collapsed + empty | `○` (new) | meta dim | label + `(0)` in dim |
| Expanded | `▼` down-triangle | body fg | children rendered indented 2 cells/level |
| Selected / focused | (node's own glyph) | green | `#161514` surface base + yellow 1px outline (mockup `.row.sel`) |

| Cross-room | `◇` (new) | sienna | under "other rooms" separator |

### Gate widget states (the write node, D-13)

| State | Visual | Write behavior |
|-------|--------|----------------|
| Option OFF | `☐` + verb label | no pending edge |
| Option ON | `☑` (green) + verb label | pending `DECISION` edge (1 per toggled option) shown in preview |
| Free-text focused | amethyst-outlined box, `f - free text` label | pending `FREE_TEXT` edge when non-empty |
| Live preview | "would write to room.db" panel listing pending edges (`> DECISION reformulate`, `> FREE_TEXT "..."`) | updates on every toggle/keystroke; nothing written yet |
| Commit (`Enter`) | confirmation line in conversation: `✓ N decisions written to room.db via the core` | each pick -> typed `DECISION` edge; free-text -> `FREE_TEXT` edge; ALL through `navigation.cjs writeEdge`; one `memory_event` fans out to inline + web + tui |
| Cancel (`Esc`) | gate closes | zero writes (silent-dismiss is allowed ONLY before commit; no edge created) |
| Selected-count cue | footer `gate N selected` | live count = toggled + (free-text non-empty ? 1 : 0) |

Inline-surface variant: when options <=4 and non-persistent, the gate is the native AskUserQuestion in the Claude Code pane (no widget). When >4 or persistent, the richer widget renders in `mos tui` (split + zoom) and the web twin.

### Zoom / re-root + breadcrumb contract

- Zoom (`a`) re-roots the tree at the selected node and writes a `focus_changed` memory_event via `focus.cjs setFocus(db, sessionId, nodeId, 'user')` (D-04). Audit-node carve-out: no human-confirm (Canon Part 9).
- Two-way sync (D-05): Larry's next inline turn reads `getActiveFocus` -> conversation and tui stay in lockstep ("the node you are on").
- Breadcrumb (Claude's discretion - prescribed default): a single Zone 1 line `room > section > node` using the `>` arrow glyph as separator. The focus node renders BOLD. On re-root, show the full path from room root to the zoomed node. Stays inside the 4-zone anatomy (never a second header).

## Loading / Empty / Error / Silent States

| State | Surface | Treatment |
|-------|---------|-----------|
| Loading (SSE connecting) | tui / web | meta-dim line `connecting to core...`; no spinner emoji; replace on first event |
| Empty section | all | `○` glyph + `(0)` count in meta dim; detail pane shows `section (0)` + `press -> to expand` (mockup) |
| Empty room (cold) | inline | SKILL.md Cold Start: `-- MindrianOS -- no room --`; primary action `/mos:new-project` |
| LazyGraph silent | all | Zone 3 OMITTED ENTIRELY when nothing relevant to the active JTBD changed (D-08, Req 9); never an empty box |
| ink absent | tui launch | graceful degrade: `[mos tui] ink not installed. The seamless inline + web surfaces work without it.` exit code 2; seamless base unaffected (Req 2/4) |
| No multiplexer | launcher | route to web twin (the no-multiplexer fallback, D-11) |
| Error | all | SKILL.md Section 7 three-line pattern: line 1 `x` (red) + what failed; line 2 `Why:` + reason; line 3 `Fix:` + one command (blue). Never a stack trace, never >3 lines, never JSON. First failure only. |
