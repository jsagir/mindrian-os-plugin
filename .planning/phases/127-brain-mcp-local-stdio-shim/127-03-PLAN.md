```markdown
# Brain Setup (v1.13.0-beta.20+)

## One-step onboarding (new installs)

1. Drop your Brain API key in `~/.mindrian.env`:
   ```
   echo "MINDRIAN_BRAIN_KEY=<your-key>" > ~/.mindrian.env
   chmod 600 ~/.mindrian.env
   ```

Don't have a key? Request one at https://mindrianos.vercel.app/brain-access. Without a key, every Brain command returns a structured "Brain unavailable" response and Larry surfaces a one-line upgrade hint -- the plugin still works at Tier-0.

## Existing testers (migration from v1.13.0-beta.19 or earlier)

If you previously wired the Brain manually via `claude mcp add ... mindrian-brain ...`, the plugin auto-migrates you on first launch of v1.13.0-beta.20. The legacy user-scope HTTP-transport entry is removed via the supported `claude mcp remove --scope user mindrian-brain` CLI; the plugin-bundled stdio entry takes over.

The auto-migration is safe:
- Pre-migration snapshot at `~/.mindrian/pre-migration-snapshots/<ISO>.json`.
- Idempotency log at `~/.mindrian/migrations.jsonl` (sha256 fingerprints, no raw identifiers).
- Refuses to migrate if your legacy key differs from `~/.mindrian.env` (rotate keys first).
- Dry-run: `node scripts/migrate-brain-mcp-from-http-to-stdio.cjs --dry-run` shows what would happen.

## Diagnostics

`/mos:doctor --brain-smoke` runs a 5-layer end-to-end probe (plugin root -> key resolver -> HTTPS schema -> MCP stdio handshake -> e2e brain_schema). Surfaces the exact failing layer if anything is wrong.

## What changed in beta.20

Before: install plugin + drop key + `claude mcp add` + restart + hope.
After:  install plugin + drop key. Restart. That's it.
```
