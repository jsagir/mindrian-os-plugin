## Decision map

See `275-01-PLAN.md`'s Decision map for the full D-01 through D-13 table. This plan implements
**D-13** (migration is additive and idempotent; L4 inline-content drift is report-only, never
rewritten) and closes the phase's verification surface.

### D-13 rationale (a Claude's Discretion item, resolved here, on the record)

`275-CONTEXT.md` leaves the migration path for rooms that already use `opportunity-bank` as an
ad-hoc non-frozen slug as a Claude's Discretion item, flagged by `## RULING 2026-09-04` as real
execution work. Resolved as **additive and report-only**:

- **Additive.** The migration creates what is missing and touches nothing that exists. It never
  moves, renames, merges or deletes a directory or a file. A room that has been using
  `opportunity-bank/` as an ad-hoc directory already has exactly the right directory name; the
  promotion into `SECTION_NAMES` means the scaffold now recognises it, not that it needs relocating.
  What such a room is missing is the identity file, the contract, and the reference documents, and
  those are precisely what gets added.
- **Report-only for L4 drift.** SEED-076 found 5 of 12 sections in the audited `launchpad-02` room
  inlining real content into `ROOM.md` instead of dated entry folders. That content is
  human-authored. Canon Part 9's "files preserve meaning" invariant and this repo's own
  existence-check-before-write discipline both forbid a script rewriting it. The migration REPORTS
  each drifted section with a file and a line count so a human can move it; it does not move it.
  Auto-splitting human prose into entry folders is a content decision no script should make.

**CLI contract**, matching the analog exactly:
`node scripts/migrate-room-sections-v275.cjs <roomDir> [--dry-run] [--report-drift]` and

**What it migrates, all additive.** For the given room:

1. **Missing section directories and identity files.** For each slug in `SECTION_NAMES` with no
   `<room>/<slug>/ROOM.md`, create the directory and render `ROOM.md.section.tmpl` with the same
   `sectionSubs` the scaffold builds, including the new `STATEMENT` key. Call
   `scaffoldRoomSkeleton` for this rather than duplicating the render logic; it is already
   idempotent and already existence-checks every write. Verify by reading the function before
   relying on it, and if calling it whole would also rewrite `STATE.md`, use `isStateAuthored`'s
   own guard, which already protects a human-authored `STATE.md`.
2. **Missing `statement:` on an EXISTING section `ROOM.md`.** This is the one in-place frontmatter
   edit, and it is a strict addition: insert a `statement: <the value from SECTION_METADATA>` line
   into the existing frontmatter block, immediately after the `section:` line, ONLY when no
   `statement:` key is present. Never overwrite an existing one, even if it differs from the table:
   a room owner may have edited it, and that edit is the human content this rule protects. Do not
   add the body blockquote to an existing file; a `ROOM.md` a human has been editing is not a
   template render target.
3. **Missing per-section `CONTEXT.md`.** Call the exported `writeSectionContracts` with a section
   list filtered through `SECTION_NAMES`, never with a raw directory listing (threat T-275-10).
4. **Missing `references/` directory and its documents.** Call the exported `writeReferenceDocs`,
   plus the identity render for `references/ROOM.md` if `scaffoldRoomSkeleton` does not already
   cover it on this path.

**Idempotency by detection**, matching the analog's `hasAllV88Fields` strategy: before writing
anything, detect per target whether it is already migrated. A second run on the same room must
produce byte-identical output and report zero writes. This is a hard acceptance criterion, not a
best effort.

**What it must NOT do**, stated in the header docblock so a future reader cannot miss it (D-13):
never move, rename, merge or delete any directory or file; never overwrite any existing file;
never touch a room's `venture_stage` value; never write into `references/` anything derived from
the room. A room already using `opportunity-bank/` as an ad-hoc directory keeps its content exactly
where it is and gains only the missing identity, contract and reference files.

**`--report-drift`, the ICM L4 pass, report-only.** For each section directory, read its `ROOM.md`
and decide whether it has drifted into carrying real content. Use a defensible signal and state it
in the docblock rather than guessing: the file's body (everything after the frontmatter block) is
longer than the rendered template's body would be for that section, AND the section directory
contains no artifact recognised by `isIndexableArtifactFile` (directly or one level down, matching
`discoverSections`'s own nested-artifact pass). Both conditions together mean content went into the
identity file instead of into an entry folder. Report each hit with the section slug, the `ROOM.md`
path and its body line count. Print a one-line explanation of what a human should do (move the
content into `<slug>/<artifact-slug>/<artifact-slug>.md`, leave `ROOM.md` as identity only) and
cite the section's own `CONTEXT.md` Outputs clause as the rule.

Emit the drift report as a distinct, clearly-labelled block in the output. Do NOT let a drift
finding change the exit code: drift is a human-actionable report, not a migration failure. State
that in the docblock.

**Reporting.** Follow the analog's `main()` shape: a summary of what was created, what was skipped
as already-migrated, and what errored, then exit 0 unless a real runtime error occurred. Under
`--dry-run` list every intended write and write nothing at all: prove it by asserting the room's
file set and every file's mtime are unchanged after a dry run.
