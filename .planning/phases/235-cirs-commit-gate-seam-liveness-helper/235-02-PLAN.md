<objective>
Fix CIRS-02: MCP tools currently sit entirely outside CIRS's wired-XOR-excluded invariant.
`coverageReport()` in `scripts/build-connector-registry.cjs` (the R9 gap hard-fail's source of
truth, consumed by both `--check` and the pre-commit hook) walks only `listSourceFiles()`
(commands/skills/agents) -- it never walks MCP tool files at all. The SEPARATE
`listMcpToolConnectorDescriptors()` function (used only by `buildRegistry()` and mirrored by
`check-shape-declaration.cjs`'s advisory sweep) silently `catch { continue }`s on any
`require()` failure and silently returns an empty array for a file missing its `connectors`
export -- verified this session by a simulated load failure: connectors dropped from 21 to
19 while coverage errors stayed at 0 and gap stayed at 0. A new tool file that forgets to
export `connectors`, or that throws at require time, is born invisible to the born-wired
gate, and the gate's own printed recovery command (`node scripts/build-connector-registry.cjs`)
would just regenerate the registry missing the same entries -- turning the gate green while
the tool stays dark.

This session's systems-thinking analysis (already reflected in ROADMAP.md's CIRS-02 wording)
refined the fix beyond "extend the coverage walk to include MCP tools" alone: the deeper,
higher-leverage move is a genuinely repo-wide "seam-liveness assertion" helper any test file
can call to assert "this hook matcher actually matches a live tool name," "this enqueue has a
registered consumer," "this mint is consumable by its ratifier" -- because roughly ten other
findings from this session's audit are the exact same "seam" shape (a claim on one side, an
unverified reachability on the other) living in pieces CIRS's own build-time enumeration was
never designed to reach. This plan builds that helper as a small, generic, well-tested
library FIRST, then makes CIRS-02's own fix be "coverageReport() also walks MCP tools AND
uses the shared helper for that walk," not a CIRS-only patch.

Purpose: Close the specific MCP-tool blind spot AND leave behind a reusable primitive
Phases 237/238/239 can consume for their own hook-matcher/enqueue-consumer/mint-ratifier
liveness proofs (per ROADMAP's stated soft dependencies), without those phases needing to
reinvent the same "is this seam alive at both ends" logic.

Output: `lib/core/seam-liveness.cjs` (new, generic + 4 named wrappers) with its own test file
proving all 3 named dead-seam shapes; `scripts/build-connector-registry.cjs` extended so
`coverageReport()` walks MCP tool files through the new helper; the regenerated coverage
ledger; a mutation-proof integration test.

Consultation requirement (binds this plan per REQUIREMENTS.md's Cross-Cutting Research
Consultation section and CLAUDE.md's "Consult ALL Relevant Grounding Sources" rule, both of
which name Phase 235 explicitly for MCP tool registration and hook-matcher questions): Task 2
requires, before writing the hook-matcher wrapper's fixture shape or touching
build-connector-registry.cjs's registry-generation logic, (a) a brief consult of the
`claude-api` skill (and `claude-code-guide` agent for any direct product-behavior question)
to confirm the REAL shape of a Claude Code hook matcher / MCP tool name (e.g. the
`mcp__<server>__<tool>` naming convention visible in this repo's own `hooks/hooks.json`), so
the seam-liveness helper's hook-matcher wrapper models a shape later phases can actually
reuse; and (b) a brief consult of `mcp__langtalks-graph-expert__*` (MANDATORY per CLAUDE.md
for any MCP-protocol-adjacent work) for whether the corpus has prior art on "liveness/health
checking of registered tool surfaces" -- "not in the corpus yet" is an acceptable, expected
answer. Record a one-line citation of each consult's outcome in Task 2's code comments.
