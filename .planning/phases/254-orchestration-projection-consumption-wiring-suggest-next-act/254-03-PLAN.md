<objective>
Close WIRE-04: make the three framework vocabularies structurally incapable of diverging SILENTLY.

There are three today and they already disagree. `framework-chain-composer.cjs::KNOWN_FRAMEWORKS`
holds 18 generic strategy-framework names; `data/command-registry.json` and
`data/brain-orchestration-projection.json` each hold the same 28 PWS framework names. The overlap
is exactly 1 (`Lean Canvas`), with three more near-miss aliases that do not string-match
(`Mullins` / `Mullins Model`, `Beautiful Question` / `Beautiful Question Framework`,
`Jobs-to-be-Done` / `Jobs to Be Done (JTBD)`). That mismatch is the ROOT CAUSE of the one-step-chain
defect Plans 01 and 02 fix, and nothing in the tree catches it.

The gate's design is a DECLARED-DRIFT LEDGER, not a purge. 254-RESEARCH.md Open Question 3 is
explicit: "do not delete blind. Add the drift gate (WIRE-04) first so the divergence becomes
visible, then decide with data" - because `detectCompletedFramework` and
`parseFrameworkChainSection` also read `KNOWN_FRAMEWORKS` and have other callers, and the
composer's own header calls the list a "NAME-RECOGNITION BOOTSTRAP ONLY". So every existing
non-registry name gets an explicit entry with a reason (the `validateAllowlist()` shape
`scripts/check-plugin-path-anchoring.cjs` already ships), and any UNDECLARED divergence fails the
build from that moment on.

Checked against Phase 263's SEED-A per D-05: different concern, no conflict. SEED-A is a Brain-repo
gate over the LIVE `:Framework` population; this is a local BUILD-TIME gate over three committed
local vocabularies. Phase 263 has zero plans and is not started; this proceeds independently and
neither gate can shadow the other.

Purpose: WIRE-04 exists so the defect Plans 01/02 fix cannot come back by a different door.
Output: one gate script, one fixture suite, three one-block wiring edits.
</objective>
