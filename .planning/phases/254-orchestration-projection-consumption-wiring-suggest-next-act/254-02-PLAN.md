**Why the gap is not closed in this phase, and what is done about it instead.**
`brain-router.recommend()` returns a chain of COMMAND SLUGS validated against its own
`KNOWN_METHODOLOGIES` list (`lib/mcp/brain-router.cjs:99-108`, 30 slugs), not a chain of framework
NAMES. `resolveChainSource` returns framework names. Wiring the MCP surface is therefore not an
input swap; it needs its own vocabulary reconciliation between a fourth vocabulary and
`data/command-registry.json`, plus its own regression suite over a released MCP handler. No
requirement in this phase names the MCP surface: WIRE-01 and WIRE-02 name `/mos:suggest-next`,
WIRE-03 names `/mos:act --chain`. Expanding into a fourth vocabulary here would balloon WIRE-04.

The gap is INSTRUMENTED rather than left invisible: Plan 03's drift gate carries an advisory arm
that measures `brain-router.cjs::KNOWN_METHODOLOGIES` against `data/command-registry.json`, so the
divergence is reported on every run and the follow-up is concrete rather than a memory. Plan 06
records the follow-up as a named item in the phase SUMMARY.
