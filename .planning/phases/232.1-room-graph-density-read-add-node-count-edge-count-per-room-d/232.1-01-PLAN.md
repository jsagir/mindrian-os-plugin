<objective>
Add the system-wide room-graph census: a genuinely read-only sibling door into
`room.db` (D-04, corrected) plus a new `cadence: always` doctor registry module
(D-01/D-02/D-03/D-05/D-06/D-08) that counts `nodes` and `edges` rows for every
registered room. This is the primary deliverable of Phase 232.1 and closes
SEED-074's own "Suggested first move": the room-graph density measurement
SEED-074 gates on becomes self-reported by `/mos:doctor` instead of requiring a
human to check by hand.

Purpose: SEED-074's own author found, on 2026-07-25, that `openRoomDbForCaller`
(the existing sanctioned Canon Part 9 door) silently mutates any `room.db` it
"reads" -- it runs 13 `CREATE TABLE IF NOT EXISTS` statements plus 5 migrations
on every open (232.1-RESEARCH.md Pitfall 1, reproduced empirically with a
before/after schema diff). A census through that door would silently migrate
30 of the 38 live rooms on first run. This plan's central act is adding a
second, genuinely non-mutating MODE of entry through the SAME
`lib/core/navigation/` chokepoint -- never a second chokepoint, never a direct
`room.db` open from outside it.

Output: `openRoomDbReadOnlyForCaller` (new function, re-exported from
`navigation.cjs`), `lib/core/doctor/room-graph-density-module.cjs` (new doctor
module), one new `data/doctor-modules.json` entry, one new
`commands/doctor.md` inventory line, and a hermetic regression suite
(`tests/test-232.1-room-graph-density.cjs` + `tests/run-all-232.1.sh`) proving
the whole thing never mutates a `room.db`.
</objective>
