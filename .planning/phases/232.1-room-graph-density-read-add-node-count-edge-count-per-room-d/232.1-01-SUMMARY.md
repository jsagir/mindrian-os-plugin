## Decisions Made

- **The read-only door carries no sibling closer.** `room-db.cjs::closeRoomDb` accepts a bare `DatabaseSync` and just calls `.close()` in a try/catch, so `closeRoomDbForCaller` is already correct for the new handle. A duplicate closer would be dead surface that drifts. The reason is stated in the function header so a future reader does not add one.
- **`ctx.home` is still not consulted.** `readRegistry()` takes zero arguments and honors only `MINDRIAN_ROOMS_HOME`, so the contract-parity test's scratch `ctx.home` is ignored and the sweep reads the real registry. That is exactly what `cascade-rooms-module.cjs` already does. RESEARCH's Pitfall 2 flagged it because, combined with the mutating door, `npm test` would have migrated the developer's real rooms; with the read-only door that risk is gone. Closing the residual gap would introduce an unproven `roomsHome`-vs-`home` join ambiguity across every module sharing `readRegistry`, so it is documented in the module header as a follow-up rather than attempted here.
- **Room filesystem paths are deliberately absent from the JSON payload** (T-232.1-04). Verified: no `rooms[]` entry contains a `/`.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] The seeded `nodes` INSERT did not satisfy the post-migration schema**

- **Found during:** Task 2 (test scenario 4)
- **Issue:** The plan specified `INSERT INTO nodes (id, type, properties) VALUES (?, ?, ?)`. The real, fully migrated `nodes` table (after `phase-109-nodes-provenance` and `phase-160-nodes-bitemporal`) carries NOT NULL `source_path`, `created_by`, `created_at`, `last_seen_at`, and a CHECK constraint restricting `created_by` to `('user','larry','import','brain','system')`. The three-column INSERT failed with `NOT NULL constraint failed: nodes.source_path`, then with the CHECK constraint.
- **Fix:** Widened the seed INSERT to the seven required columns with `created_by = 'system'`, and added a comment naming the migrations that make the bare triple non-insertable.
- **Files modified:** `tests/test-232.1-room-graph-density.cjs`
- **Verification:** Scenarios 4 and 6 now report the exact seeded counts (2/1 and 3/2).
- **Committed in:** `ebe1ec52` (Task 2 commit)

**2. [Rule 3 - Blocking] The verbatim `runDoctorJson` helper left the module DEFERRED, so no row ever appeared**

- **Found during:** Task 2 (test scenarios 4-8)
- **Issue:** This is RESEARCH's Pitfall 5 firing for real, and it is the interesting one. The plan required `introduced_version` to equal `.claude-plugin/plugin.json`'s version (`1.15.3-beta.47`, the in-progress version per CHANGELOG's `[Unreleased]` header). But the accumulative engine resolves the RUNNING version from the plugin cache actually INSTALLED on the box, which on any dev machine lags the repo by design (here `1.15.3-beta.46`, the last released tag). `introduced_version > running` means the engine pushes the module onto `deferred[]` and never calls `check()`. No row, no error, no signal: a silent no-op that looks exactly like success. The plan's two acceptance criteria (introduced_version equals plugin.json, and the test asserts the row exists) were in genuine tension.
- **Fix:** Kept `introduced_version` truthful at `1.15.3-beta.47` and made the TEST hermetic instead. `makeScratchPluginHome(scratch)` builds a scratch `HOME` carrying a minimal plugin install plus marketplace cache stamped with the repo's OWN version, and `runDoctorJson` sets both `HOME` and `MINDRIAN_ROOMS_HOME` into the scratch tree. That resolves the running version to the version this code actually ships in, which is the configuration real users are on once it ships. A bare `HOME` override alone was tried first and rejected: it made doctor exit 3, because class A then correctly reported a missing install dir and missing marketplace cache. The scratch plugin home fixes both at once and is strictly more hermetic than the class-B helper it was copied from (the engine watermark write now lands in scratch, never in the developer's real `~/.mindrian`).
- **Files modified:** `tests/test-232.1-room-graph-density.cjs`
- **Verification:** `report.checks['room-graph-density']` present, doctor exits 0, and `report.checks['accumulative-engine'].deferred` no longer contains the module. Separately confirmed against the REAL registry via an in-process `check()` call: status ok, 45 rooms, 21324/8663, zero mutation.
- **Committed in:** `ebe1ec52` (Task 2 commit)
