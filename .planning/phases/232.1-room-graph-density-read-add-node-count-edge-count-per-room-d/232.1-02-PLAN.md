<objective>
Fold the D-07 single-room density line into the `room_state` MCP tool's
`status` and `get-state` branches, so a conversational Larry session sees the
currently bound room's own node/edge counts without needing `/mos:doctor`.
This is the secondary (Desktop/Cowork) surface of Phase 232.1's "both surfaces
ship" decision (D-01) -- Plan 232.1-01 already delivered the primary
(CLI/doctor) surface.

Purpose: D-07 requires the SAME read-only door Plan 232.1-01 built (D-04
corrected) -- a status line must never be able to trigger a schema migration
as a side effect of simply being read, for the identical reason the doctor
census could not use the mutating `openRoomDbForCaller`. It must also read
from `activeRoomDir` (the live, per-call-resolved active room), never the
frozen boot-time `roomDir` closure -- that exact distinction is the documented
root cause of the `intern-w1-room-state-false-empty` bug class
(232.1-PATTERNS.md), and this plan's new line would silently reproduce that
bug for itself if it read the wrong variable.

Output: `roomDensityLine(activeRoomDir)` (new function in `tool-router.cjs`,
wired into both `room_state` read branches) plus
`tests/test-232.1-room-state-density.cjs`, a hermetic regression suite proving
correct counts, correct room resolution under a mid-session active-room
switch, and zero mutation.
</objective>
