FORBIDDEN_PATTERNS is re-exported byte-for-byte from lib/core/cross-room-aggregator.cjs (lines 87-94, exported at line 753). The aggregator is the Canon authoritative source (mirrored from Phase 90-05 brain-md-invariants + Phase 90-00 schema heuristics).

The six patterns (email / currency magnitude / quoted-person / meeting fragment / SSN-like / phone-like) are imported by reference, not redefined, so a future canon amendment at cross-room-aggregator.cjs propagates to rs-brain-substrate-prompts.cjs with zero code change. Defensive guard at require-time throws if the re-export ever fails or the length drops below 6 (Canon Part 8 drift risk signal).

## Invariants Addressed

From 89.1a-VALIDATION.md invariant set:

- **I1 (Canon Part 8 boundary).** preSendAudit performs JSON.stringify(payload) + for-each FORBIDDEN_PATTERNS regex check. On match: append reject entry to audit log, throw BrainBoundaryViolation. This runs BEFORE any brainClient.search / query call (verified by pullFromBrain source: `preSendAudit(...)` precedes `await brainClient.search(...)`). Inline test fixture confirmed: `preSendAudit(tmpDir, {query: '$5.2M valuation secret'}, 'test')` throws BrainBoundaryViolation, audit log records `outcome:reject, reason:forbidden_regex, pattern:\$[0-9][\d,.]*[KMB]?\b`.

- **I4 (Graceful degradation).** loadSubstrate is wrapped in top-level try/catch. Every external boundary (brainClient.isAvailable failure, pullFromBrain rejection, require-time error, Pitfall 1 Pinecone quota fallback) returns a structured {success:true, substrate:[], mode:'B3', warning, reason?} object. NEVER throws. Inline test confirmed: `loadSubstrate({roomDir: tmpDir})` returned `{success:true, mode:'B3'}` when Brain was reachable but pull failed to return substrate-quality matches.

- **I5 (Structured result).** Every return path of loadSubstrate carries `mode` from the frozen RESULT_MODES enum: A3 on successful pull, B3 on every graceful-degradation path. Plan 02 will add A1 (fresh cache) + A2 (stale re-pull) + B1 (offline + fresh cache) + B2 (offline + stale cache) return paths. RESULT_MODE_SET exported via _test surface so Plan 03 fixtures can assert membership without redeclaration.

- **I7 (Chokepoint exclusivity).** buildBrainSubstrateQuery is the ONLY function in rs-brain-substrate.cjs that reads user-controlled ctx input and produces a brainClient.search descriptor. validateCtx is its first statement (grep verifies). pullFromBrain (internal) and loadSubstrate (public entry) both route through buildBrainSubstrateQuery; no alternate code path exists. The prompts module never imports brain-client (grep verifies 0 matches), so it cannot bypass the chokepoint from the vocabulary layer either.

## Canon Part 8 Compliance (Graph Boundary)

Three independent tripwires now defend every outbound Brain methodology query:

1. **Allow-list (validateCtx).** Frozen ALLOWED_CTX_KEYS (6 slug-safe handles). TypeError on any unknown key. TypeError on any string value that fails SLUG_REGEX. TypeError on any problem_types value outside PROBLEM_TYPE_ENUM. TypeError on any namespace outside NAMESPACE_ENUM. TypeError on any limit outside [1, 10000].

2. **Chokepoint (buildBrainSubstrateQuery).** validateCtx as first statement. Extracts ONLY slug-safe scalars (namespace, topK) into searchParams. audit_meta carries handles (Object.keys only), prompt_version, built_at — no content.

3. **Pre-send scan (preSendAudit).** JSON.stringify(payload) scanned against FORBIDDEN_PATTERNS (6 regexes: email, currency, quoted-person, meeting fragment, SSN, phone). Match -> append audit reject + throw BrainBoundaryViolation. Runs BEFORE every brainClient.search / query call.

No forbidden triple-field references in code (grep verified: 0 matches for `governing_thought | identity_text | decision_log | meeting_transcript | artifact_body` in rs-brain-substrate.cjs).

## Plan 02 Handoff (Cache Persistence)

Plan 02 lands the cache I/O layer. Specific handoff points:

- **readCache(roomDir)** — reads .mindrian/brain-substrate-cache.json, returns {ok, cache, age_days} or {ok:false, reason}. Consumes schema locked in CONTEXT.md section "Cache Design (locked)": schema_version 1.0, pulled_at ISO-8601, ttl_days 30, source_index pws-brain, embedding_count, content_hash sha256, substrate array with generic methodology metadata only.
- **atomicWriteSubstrateCache(roomDir, substrate)** — writes to .mindrian/brain-substrate-cache.json.tmp then fs.renameSync to final path (Phase 88-04-B atomic pattern: openSync wx + fsync + validate + rename). Must refuse to cache Pinecone quota fallback (Pitfall 1 already caught in pullFromBrain but defense-in-depth at write time is sensible).
- **isFresh(cache)** — computes now - cache.pulled_at < cache.ttl_days * 86400000. MINDRIAN_BRAIN_SUBSTRATE_TTL_DAYS env var overrides the 30d default.
- **loadSubstrate extension** — current Plan 01 code has explicit `// Plan 02 TODO` markers at the four insertion points for Mode A1 (cache read), Mode A2 (stale re-pull), Mode B1 (offline + fresh cache), Mode B2 (offline + stale cache). The B3 graceful degradation path stays byte-identical.
- **brain-client injectability** — CONTEXT.md "Specific Ideas" raises factory-pattern injection for mock-friendliness. Plan 01 takes brainClient as a module-level require; Plan 03 adversarial fixtures will need either a test-only override or a factory. Recommend Plan 02 add a `_setBrainClient(client)` test hook on the `_test` export if Plan 03 needs it; otherwise keep the direct require and mock via require cache surgery.

## Plan 03 Handoff (Adversarial Fixture Suite)

Plan 03 exercises preSendAudit + buildBrainSubstrateQuery + BrainBoundaryViolation across >= 6 adversarial scenarios (per CONTEXT.md "Test Strategy"):

1. Leaked user artifact body in query parameter -> expect BrainBoundaryViolation, audit reject entry.
2. Leaked venture name / trademark in query parameter -> expect BrainBoundaryViolation.
3. Leaked meeting transcript fragment -> expect BrainBoundaryViolation (matches "meeting with" FORBIDDEN pattern).
4. Leaked proprietary number ($5.2M valuation) -> expect BrainBoundaryViolation (matches currency pattern; already verified inline in Task 2 verify script).
5. Malformed payload injection (nested object to sneak user data past Object.keys check) -> validateCtx rejects on forbidden top-level key; JSON.stringify in preSendAudit surfaces nested strings.
6. Oversized payload (attempt to exceed allow-list via volume) -> LIMIT_MAX 10000 in validateCtx rejects.
