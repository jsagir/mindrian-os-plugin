<objective>
Author the `USES_FRAMEWORK` edge batch that closes the roadmap's absorbed "25 missing edges" item,
derived from a tracked source rather than from an unreachable artifact.

**The source problem, stated first because it changes what this plan can honestly deliver.**
The roadmap's Phase 256 entry names "the 25 missing `USES_FRAMEWORK` edges ... this session's
Command-Framework Map audit found" and cites a `claude.ai/code/artifact/...` URL. That artifact is
not reachable from this repository or from any tracked file. The itemised list of 25 does not exist
on disk anywhere. Reconstructing it from the roadmap's one-line summary would be inventing a
worklist and calling it a recovered one.

**What replaces it, and why the replacement is better rather than merely available.** Every
methodology command in MindrianOS-Plugin declares its frameworks in its own frontmatter, as a
`frameworks:` array. `scripts/build-brain-census.cjs`'s exported `scanMethodologyCommands()` already
reads exactly that, and `data/flagship-floor-set.json`'s own comment records the scan producing 50
methodology commands across 28 distinct frameworks. That frontmatter is tracked, greppable, and
authoritative: when `commands/find-bottlenecks.md` declares `frameworks: ["Reverse Salient
Analysis"]`, that IS the named read source for a `USES_FRAMEWORK` edge from that command to that
framework. So this plan derives the missing-edge list from the declaration rather than from a
memory of an audit, and it ships the derivation as a re-runnable script so Phases 262 and 263 can
regenerate it instead of inheriting a frozen table.

**The measured gap this closes, and its honest limit.** `261-RESEARCH.md` measured graph-wide only
86 `USES_FRAMEWORK` edges against 112 `:MindrianCommand` nodes, with 59 commands (53 percent)
reaching zero frameworks and nine having no outgoing edges at all. That 53 percent is the visible
product symptom. `261-RESEARCH.md` is also explicit that authoring edges is the ONLY operation in
this phase that moves it: the archived-block relabel rescues zero of the 59. This batch is
therefore the one whose effect Phase 262 should actually see, which is precisely why it must be
logged separately from the relabel with a probe between them.

**What is NOT in scope, named so it is not silently absorbed.**
`payloads/framework-command-map-2026-08-18/` already exists, compile-only, unexecuted, and is a much
larger body of work: roughly 272 edges and 70 new nodes across `TEACHES`, `FEEDS_INTO`,
`ADDRESSES_PROBLEM_TYPE`, `RELATES_TO` and a schema extension for agent, skill, tool, sensor and
workflow node types. It uses `TEACHES`, not `USES_FRAMEWORK`, so it does not move the metric
`261-RESEARCH.md` measured, and its schema extension is a Canon-Custodian-review-class change.
It is not a CER requirement and it is not in this phase. Task 1 must record that exclusion with its
reason so a future reader does not mistake the omission for an oversight.

Output: one derivation script and `payloads/command-framework-edges-2026-08-21/`, committed
locally, never executed.
</objective>
