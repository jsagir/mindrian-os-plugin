# Phase 129.5 Plan 02: confirmNode Chokepoint + Human-Attribution Guard Summary

**The dead lever made live: confirmNode is the single APPROVE-to-promote door, promoteNodeStatus now REJECTS larry/brain/system/assistant on confirm/validate of truth-claim nodes, and resolveByUser maps USER.md identity to a non-agent byUser that defaults to 'navigator'.**

## Accomplishments

- `confirmNode(db, id, byUser, reason?)` chokepoint added in the new `lib/core/navigation/confirm-node.cjs`: it resolves the node's current `review_status` and delegates to `promoteNodeStatus` with the correct `fromStatus`, so no caller needs to know the from-state. It is the only production caller of `promoteNodeStatus` (a source-grep test enforces this).
- Human-attribution guard added to `promoteNodeStatus`: `AGENT_IDENTITIES = {larry, brain, system, assistant}` are REJECTED (case-insensitive, `reason: 'agent_attribution_forbidden'`) on confirm/validate transitions of `TRUTH_CLAIM_TYPES = {claim, CausalClaim, assumption, decision, opportunity}`. The guard fires before any mutation and leaves `review_status` unmutated. System-bookkeeping nodes (memory_event / audit / focus) are exempt per the Canon Part 9 v1.5 carve-out; reject/stale/supersede transitions are never gated.
- `resolveByUser(roomDir)` reads the active room's `USER.md` (via `readUserMd`), picks `user_id` then `canonical_role` then `'navigator'`, and coerces any agent identity to `'navigator'` (defense-in-depth so a poisoned USER.md cannot smuggle an agent into a confirm). Never throws.
- `navigation.cjs` re-exports `confirmNode` + `resolveByUser` with a per-export justification block; SUBSTRATE-CONTRACT M11 allow-list + a Phase 129.5-02 amendment name both exports and the consumers.

## Decisions Made

- The `nodes.created_by` column carries a SQLite CHECK constraint limiting it to `{user, larry, import, brain, system}`. The audit `memory_event` row written by `logEvent` inherits its `created_by` from the payload, so a human navigator identity (`jonathan` / `navigator` / `founder`) cannot be stored in that column directly. Resolution: map any non-agent, non-system human byUser to the canonical `'user'` marker for the audit row's column, while preserving the LITERAL human identity in (a) the unconstrained payload `confirmed_by` field and (b) the unconstrained `nodes.confirmed_by` column on the truth-claim node. This keeps the existing system / agent paths byte-compatible.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Audit-node created_by CHECK constraint conflicted with human byUser**
- **Found during:** Task 2 (GREEN implementation)
- **Issue:** The plan's design routes the human navigator byUser through `promoteNodeStatus` to `logEvent`, which writes the audit `memory_event` row's `created_by` column. That column has a CHECK constraint `IN ('user','larry','import','brain','system')`, so a human identity like `jonathan` / `navigator` failed the insert with `event_log_failed:CHECK constraint failed`, making every human confirm return `{ok:false}`. This blocked the core success path of the plan.
- **Fix:** In `promoteNodeStatus`, mapped the audit row's `created_by` to the canonical `'user'` marker for non-agent / non-system human byUser values (keeping `system` and agent paths literal), and added a `confirmed_by` field to the event payload carrying the literal human identity. The truth-claim node's own `confirmed_by` column already stores the literal identity (unconstrained TEXT).
- **Files modified:** lib/core/navigation/transitions.cjs
- **Verification:** The human-confirm test now passes; `nodes.confirmed_by == 'jonathan'` and the status_promoted payload `confirmed_by == 'jonathan'`. Test suite 19/19 green.
- **Committed in:** 64bfb1ba (Task 2 commit)

**Plan-test alignment note:** The RED suite originally asserted the status_promoted event payload `created_by == human`. Once the constraint surfaced, the assertion was retargeted to the payload `confirmed_by` field (the unconstrained carrier of the literal human identity), which is the correct contract. The agent-guard, confirmNode, resolveByUser, and source-grep behaviors were unchanged.
