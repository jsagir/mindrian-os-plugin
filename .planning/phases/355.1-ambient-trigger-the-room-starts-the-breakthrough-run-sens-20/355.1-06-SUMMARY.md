## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] the same_hash RED test leg asserted an outcome the real classifier cannot produce**
- **Found during:** Task 2, GREEN (first run of `tests/test-3551-evaluator.cjs` against the real module)
- **Issue:** The RED test called `evaluateRoomDelta` a second time on the SAME unmodified room right after `recordAmbientRun`, expecting decision `'same_hash'`. Since class a/e are absolute since-bound thresholds (plan 355.1-03's shipped `classifyRoomDelta` contract) and `recordAmbientRun` advances the ledger's watermark to absorb the already-counted claims, the real re-evaluation correctly detects zero new facts and reports `'no_change'` -- `'same_hash'` can only occur when a classifier still detects a delta whose hash matches the one already recorded, which the real since-bound classifier structurally cannot reproduce twice against an unmodified room.
- **Fix:** Split the leg into two: the real-flow assertion now expects `'no_change'` (documented inline), and a new dedicated leg proves the ladder's own `same_hash` mapping using a stubbed `classifyFn` that keeps returning the already-recorded hash, independent of the real classifier's since-bound behavior.
- **Files modified:** `tests/test-3551-evaluator.cjs` (this plan's own new test file)
- **Verification:** `node tests/test-3551-evaluator.cjs` passes all 19 checks
- **Committed in:** `6995409a3` (a dedicated fix-up commit, kept separate from the Task 1 RED commit and the Task 2 GREEN commit)

**2. [Rule 1 - Bug] the one-spawner scan's spawn-call regex missed the module's own spawnImpl( test seam**
- **Found during:** Task 2, GREEN (first run of `tests/test-3551-one-spawner.cjs` against the real module)
- **Issue:** `lib/core/ambient-trigger.cjs` calls the module-level spawn seam as `spawnImpl(process.execPath, argv, {...})` (so `_internal.setSpawnImpl` can swap it for tests), but the RED test's `SPAWN_CALL_RE` required an exact `spawn(`/`fork(`/`exec(`/`execFile(` token immediately followed by `(`, which `spawnImpl(` does not match.
- **Fix:** Widened the regex to an explicit `(Impl|Sync)?` optional suffix (not a loose `\w*`, which would also false-match an unrelated `execute(`/`executor(` call), catching `spawnImpl(` alongside the four direct forms.
- **Files modified:** `tests/test-3551-one-spawner.cjs` (this plan's own new test file)
- **Verification:** `node tests/test-3551-one-spawner.cjs` passes all 3 checks; the negative-control leg (a planted `spawn(` call) still correctly matches the unmodified pattern
