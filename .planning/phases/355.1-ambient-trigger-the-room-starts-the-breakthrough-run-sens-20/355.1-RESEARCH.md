**Researched:** 2026-09-23

## Summary

The phase is buildable almost entirely from shipped parts, but the PRD carries four factual errors and one internal contradiction that the planner must correct before writing plans. (1) **SENS-20 is already taken**: Phase 345 registered `sensorStrategyReach` as `SENS-20` across the full seven-place sensor lockstep (`lib/core/insight-sensors.cjs:771,819`, `lib/core/sensors/sensor-priority.cjs:213`). The next free id is **SENS-21**; Phase 345 set the precedent for correcting a stale id at registration time and recording the correction. (2) **The MCP loop never calls `decide()`**: `suggest_next` and `reach_candidates` call `dispatchSensors` directly with `ctx = { roomDir, lowFillSections }` only (`lib/mcp/tools/sensors.cjs:67-75`). So a sensor that needs a `decide()` ctx producer never fires on Desktop or Cowork, and 355-22's fire-once mark (which 355-22 places inside `decide()`) never runs there either. (3) **The cadence runner cannot host the stamped run**: it is constitutionally zero-egress (`scripts/scout-cadence-runner.cjs:34-47`), and 355-16 made `--stamp` opt-in precisely so the cadence and cascade callers stay Theo-free (355-16 T-355-76). (4) **Hook `timeout` is in seconds, not milliseconds** (official Claude Code docs): every `"timeout": 3000` in `hooks/hooks.json` is 50 minutes, and all matching hooks run in parallel. The Stop chain is therefore not bounded by the harness; the evaluator must bound itself.

The internal contradiction: the PRD says the detector "starts the run" and also that it "never routes and never executes" (Phase 144 fence), and it says SENS-20 "produces a candidate reach" while the only card is SENS-13's. These reconcile cleanly if the planner splits the work into (a) a pure detector module that is also the registered SENS-21 sensor, (b) a machinery evaluator (not a sensor) that reads the delta through a new navigation statement-home module and spawns the one existing child, and (c) SENS-13 as the only card in the normal path, with SENS-21 firing only as the honest degrade when the run could not start on the current surface. That keeps one card per delta (Hooked: one action) and keeps SENS-21 alive (not a dark, registered-but-never-firing sensor, the Phase 343/345 "place 7" scar).

Measured facts that shape the design: the Phase 117 fire child runs p50 8.4 s, p90 11.6 s, max 166 s from fire to finding (n=135 completed fires across 31 live rooms); its 24 h per-room daily cap caused 1,999 of 2,811 recorded suppressions; claims arrive in bursts (per active room-hour p50 5, p75 66, p90 192 over the last 90 days); contradiction signals are nearly absent in the live fleet (1 CONTRADICTS edge, 0 contradiction decision nodes, 0 cascade CONTRADICT findings across 31 rooms); and only 472 of 3,333 live artifacts (14%) carry the `framework:` or `methodology:` frontmatter the 355 stamp needs to resolve an endpoint, so most real-room ambient findings will stamp `unverified` and never reach the card. That is the correct behavior under AMB-05, but the Hooked audit must disclose that the variable reward is sparse.

**Primary recommendation:** Register the detector as **SENS-21** on the `context_block` reach (posture `hold`), extend the Phase 117 fire child (`scripts/auto-explore-fire.cjs`) with an ambient mode that composes the stamped producers and files through 355-20's writer, add one statement-home read module under `lib/core/navigation/` for the five delta classes, evaluate the delta from (i) the existing PostToolUse fingerprint hook, (ii) one new `async: true` Stop hook entry, and (iii) `stop_gate_check`'s `closeOutRoom` on the MCP loop, and keep the run ledger plus lock under `<roomDir>/.mindrian/` by extending `scripts/scout-cadence-guard.cjs` with an ambient-origin JSON ledger beside its unchanged text throttle.

### Pattern 2: Pure detector, separate evaluator

**What:** The SENS-21 module exports three things: `computeDeltaHash(facts)` and `classifyRoomDelta(facts, priorLedgerEntry, floors)` (pure, no I/O, no async), and `sensorRoomDelta(turn, tuple, ctx)` (pure read of one fresh side-channel file). The evaluator imports the pure functions; the sensor never writes, never spawns.
**When:** Always. The sensor-roadmap-type scar: a sensor marked `async` returns a Promise that `dispatchSensors` silently drops (`sensor-strategy-reach.cjs` header).
**Example (shape, following `sensor-eureka.cjs`):**
```javascript
// Source: lib/core/sensors/sensor-eureka.cjs (shape), adapted
const { makeReach, REACH_IDS } = require('./sensor-types.cjs');
const SENSOR_ID = 'SENS-21';
const REACH_ID = 'context_block';
if (REACH_IDS.indexOf(REACH_ID) === -1) throw new Error('sensor-room-delta: REACH_ID off the frozen bank');
const DEGRADE_STATES = Object.freeze(['spawn_failed', 'deps_missing']);
function sensorRoomDelta(turn, tuple, ctx) {
  try {
    const roomDir = (ctx && typeof ctx.roomDir === 'string') ? ctx.roomDir : '';
    if (!roomDir) return null;
    const p = path.join(roomDir, '.mindrian', 'last-room-delta.json');
    if (!isFreshFile(p)) return null;            // replicated 30-min window, WR-01 future-mtime guard
    const s = readJsonSafe(p);
    if (!s || s.schema_version !== 1) return null;
    if (DEGRADE_STATES.indexOf(s.run_state) === -1) return null;   // normal path: SENS-13 carries the card
    return makeReach({ reach_id: REACH_ID, posture: 'hold', dispatch: 'ambient-run-unavailable',
      companions: [], signal: 'room_delta',
      evidence: { run_state: s.run_state, classes: (s.classes || []).join('|') } });
  } catch (_e) { return null; }
}
```

### Pattern 3: Detached spawn from a hook or from the MCP server

**What:** `spawn(process.execPath, [firePath, roomDir, '', ambientId, sessionId, '--ambient'], { detached: true, stdio: 'ignore', windowsHide: true, env: process.env }).unref()`.
**Why:** Node docs: `detached: true` makes the child "the leader of a new process group and session" on POSIX; "the process will not stay running in the background after the parent exits unless it is provided with a stdio configuration that is not connected to the parent"; `unref()` lets the parent exit without waiting. On Windows a detached child gets "its own console window" unless hidden. [CITED: nodejs.org/docs/latest-v22.x/api/child_process.html]
**MCP stdio rule:** never run a producer in-process on stdio transport, because stdout is the JSON-RPC channel (`lib/mcp/tool-router.cjs:1559-1573`, the `eureka-run` precedent spawns detached with `stdio: 'ignore'` for exactly this reason). [VERIFIED: read]

### Anti-Patterns to Avoid

- **A sensor that spawns or writes.** Violates the Phase 144 fence and breaks `test-sensors-routing-fence.cjs`.
- **A `decide()` ctx producer for SENS-21.** It would never run on the MCP path (C2) and is the un-gated seventh place.
- **Running producers in the MCP server process.** Corrupts stdio JSON-RPC and blocks the tool call.
- **Reusing `computeStrategyCounts().claims_since`.** It counts the ghost `node_created` memory event.
- **Hashing volatile facts** (evaluation time, a growing count while a child is in flight). The same room state must hash the same way twice, or the no-re-run guarantee is fake.
- **Sharing the 117 daily cap** (`auto_explore_fired` within 24 h) with ambient runs. It already suppresses 71% of fire attempts and would starve the ambient path.
- **Calling `_inferRungFromQuestion`** anywhere in the framing path.

### 5. Bounding the Stop evaluation

- Harness: timeouts are seconds, default 600; matching hooks run in parallel; `async: true` never blocks and its timeout is not enforced; async hooks "may not finish before the session ends" [CITED: code.claude.com/docs/en/hooks]. No hook in `hooks/hooks.json` uses `async` today.
- Recommended: a new Stop entry `{ "type": "command", "command": "node \"${CLAUDE_PLUGIN_ROOT}/scripts/<evaluator>.cjs\" --stop", "timeout": 5, "async": true }`. Inside: read stdin (`session_id`, `cwd`, `stop_hook_active`), resolve the room through `resolveSessionRoom({ sessionId, requireOwnership: true })`, run the evaluator with an internal wall-clock budget (for example 1500 ms, checked between steps), spawn, emit `{ continue: true }`, exit 0. The detached child survives the hook's exit (Pattern 3).
- Precedent: `scripts/gsd-graph-derive-sweep.cjs` is a Stop entry whose whole contract is "only write a tiny queue file, exit 0". [VERIFIED/CITED]

## Common Pitfalls

### Pitfall 1: Registering the sensor as SENS-20
**What goes wrong:** Two sensors stamp `SENS-20`; `SENS_PRIORITY` rejects or mis-ranks; `test-345-lockstep.cjs` fails.
**How to avoid:** Use SENS-21; re-grep `SENSOR_REGISTRY_IDS` immediately before the registration commit (357/358/361 are concurrent).
**Warning signs:** `build-connector-registry --check` red; two files claiming the same id.

### Pitfall 2: A sensor that only fires through `decide()`
**What goes wrong:** Green on CLI tests, dead on Desktop/Cowork (C2).
**How to avoid:** The Desktop leg calls the real `suggest_next` handler (or `dispatchCandidateReaches` via `_internal`) with a fixture room, never `sensorRoomDelta` directly.

### Pitfall 3: Desktop SENS-13 repeats
**What goes wrong:** 355-22's mark runs only in `decide()`, so each `suggest_next` pull within 30 minutes re-offers the same finding.
**How to avoid:** Close the MCP seam in this phase (Open Question 2) and pin it with a two-pull test through `suggest_next`.

### Pitfall 4: Stop timeout believed to be 3 s
**What goes wrong:** The script trusts the harness to kill it; a slow room.db open or a stuck child spawn holds the turn for up to 50 minutes.
**How to avoid:** `async: true`, an internal budget, spawn-and-exit, and a test that asserts the hook script exits under its budget with a planted slow read.

### Pitfall 5: Parallel Stop hooks racing on STATE.md
**What goes wrong:** On CLI, `on-stop` rewrites STATE.md in parallel; a truncated read looks like a stage change.
**How to avoid:** Unreadable or empty STATE.md means "no change"; the MCP seam reads after `_closeOutStateMd`.

### Pitfall 6: Duplicate children
**What goes wrong:** Fingerprint (class e), async Stop, and flag-on CLI close-out all spawn in one turn.
**How to avoid:** One lock in the child (`'wx'`), the delta-hash compare in the evaluator, and a test that fires all three seams at once and counts exactly one child run (count lock acquisitions or ledger writes).

### Pitfall 7: The 117 daily cap starving ambient runs
**What goes wrong:** `dailyCapHit` (1 `auto_explore_fired` per 24 h) suppresses the ambient path too.
**How to avoid:** Ambient runs are governed by the ambient ledger's throttle; do not emit `auto_explore_fired` for ambient runs, or filter by an `origin` payload field.

### Pitfall 8: Cadence guard file locations
**What goes wrong:** `lastRunFile` lives in the real `$HOME/.mindrian/scout-cadence/`, keyed by `sha256(abs path)[:12]`; tests that call `recordRun` write to the developer's home; a moved room resets.
**How to avoid:** Ambient ledger lives under `<roomDir>/.mindrian/`; tests set `HOME` to a mkdtemp dir if they touch cadence functions.

### Pitfall 9: Part 8 leaks through argv, logs or the side channel
**What goes wrong:** A claim title or artifact path in the child's argv (`ps` shows it), in stderr lines, in a memory_event payload, or in the delta file.
**How to avoid:** argv carries only roomDir, a mode flag, a hash-derived id and the session id; the delta file and ledger use closed enum schemas; add every new file to the 355-21 Part 8 target list and to `run-all-355.1.sh`'s own egress sweep (`fetch\(|https?://|require\(['"]node:https?|\b(curl|wget)\b` on executable lines, the run-all-355 idiom); only `verification-stamp.cjs` may reach the wire.

### Pitfall 10: Score literals in rendered lines
**What goes wrong:** The 117 finding JSON carries `top_differential_score`; a card or Larry line copies a decimal or a count ("3 new connections").
**How to avoid:** Card text comes only from `formatStampLines(stamp, 'card')` plus the framing phrase; run the D-30 regex and a count check over rendered lines; the planted-score negative control proves the check bites.

### Pitfall 11: Test-file glob collision
**What goes wrong:** The decimal-phase precedent names tests `test-150-5-*`/`test-267-1-*`; `test-355-1-*.cjs` would match `tests/run-all-355.sh`'s `tests/test-355-*.cjs` glob and run inside the closed 355 gate.
**How to avoid:** Prefix `tests/test-3551-*.cjs` (the compact precedent: `tests/run-all-1431.sh`), aggregated by `tests/run-all-355.1.sh`.

### Pitfall 12: Eureka and scout are not autonomous_safe
**What goes wrong:** A `runChain` over `/mos:eureka` halts at step one and the ambient run files nothing.
**How to avoid:** Decide explicitly (Open Question 3); always pass `/mos:`-prefixed names to `postureForCommand`.

### Pitfall 13: Shared-tree collisions
**What goes wrong:** `lib/core/navigation.cjs` (357, 358, 361), `lib/mcp/stop-gate-handler.cjs` (357), `lib/core/navigation-engine.cjs`, `lib/mcp/tools/sensors.cjs`, `lib/mcp/tools/gate.cjs` (358), `skills/larry-personality/SKILL.md` (357, 358) are edited by peers.
**How to avoid:** Re-read before each edit, commit `--only` owned paths, `git add -f` under `.planning/phases/**`, never revert an unowned diff, no `state.*` writes while a peer executes (memory: two-session tree collision, 5 observations).

### Pitfall 14: Room mirror refused at close
**What goes wrong:** `write-scope-check` refuses the rethinking-mindrianos filing when the active room differs (hit by 344, 345, 347 close-outs).
**How to avoid:** Bind the session to rethinking-mindrianos before the mirror step, or record the drafted mirror verbatim in the close-out for a follow-up.

### Pitfall 15: Em-dashes
**How to avoid:** The run-all-355 em-dash leg over new files and added lines (`BASE` diff), copied into run-all-355.1.sh.

### Delta hash (shape)
```javascript
// Hash only watermark-bounded identities, never evaluation time or live counts.
function computeDeltaHash(facts) {
  const lines = [];
  if (facts.a) lines.push('a:' + facts.a.max_created_at);
  for (const k of (facts.b_new_keys || [])) lines.push('b:' + k);
  if (facts.c_new_stage_hash) lines.push('c:' + facts.c_new_stage_hash);
  for (const k of (facts.d_new_children || [])) lines.push('d:' + k);
  if (facts.e) lines.push('e:' + facts.e.max_created_at);
  lines.sort();
  return crypto.createHash('sha256').update(lines.join('\n')).digest('hex');
}
```
