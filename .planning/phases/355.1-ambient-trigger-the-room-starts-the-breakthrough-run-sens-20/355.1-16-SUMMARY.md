# Phase 355.1: Ambient trigger, the room starts the breakthrough run (2026-09-27)

## The navigator's ruling

Recorded verbatim in substance (`355.1-PRD.md`): users will not know when to trigger the
breakthrough engine. The point of MindrianOS is ever-growing opportunities and breakthroughs,
depending on context and the need of the user, never on the user explicitly asking. Rare are the
users who will know to ask for it; all will gain from using it. This closes Phase 213's KEY
finding (SEED-049 in `sensor-eureka.cjs`: "a command-triggered eureka engine is dead on arrival;
students do not type commands") on every surface, not only the file-write case Phase 117 already
covered.

## The design: detector, evaluator, card

One new detector, `SENS-21` (a pure sensor, produces a candidate reach only, never routes,
Phase 144 fence), one evaluator that is not a sensor (reads the room delta, computes a delta hash,
consults the ledger and lock, spawns the child), and one surfacing path (SENS-13's existing
fire-once card, now carrying a problem-type framing). Five delta classes, detected only through
`lib/core/navigation.cjs` reads: claims past a disclosed floor, a CONTRADICTS edge, a venture-stage
change, a sub-room created, a filed artifact (the Phase 117 class, kept). The Phase 117 fire child
grew an `--ambient` mode that composes the five Phase 355 producers behind one ledger and lock, so
every finding still carries the 355 stamp and direction phrase. Tri-polar: CLI keeps its
PostToolUse fingerprint and gains a new async Stop-hook entry; Desktop and Cowork evaluate the same
delta at the MCP server's own `stop_gate_check` close-out. `/mos:auto-explore` stays a documented
fallback, never the way in.

## Research corrections (C1-C13, one line each)

- **C1** SENS-20 was already taken by Phase 345's `sensorStrategyReach`; the free id is SENS-21.
- **C2** The MCP loop bypasses `decide()` entirely (`suggest_next`/`reach_candidates` call
  `dispatchSensors` with `{roomDir}` only), so fire-once on hookless surfaces cannot live inside
  `decide()`.
- **C3** SENS-13 was dark in production: the fire child called `runEurekaScan` with no pair and
  exited before the promise settled.
- **C4** The cadence runner is zero-egress by constitution; the ambient run had to extend the
  Phase 117 fire child instead, the one spawner already outside any turn or transaction.
- **C5** Hook `timeout` is in seconds, not milliseconds; an `async: true` hook's timeout is not
  enforced by the harness, so the new Stop entry must self-bound its own budget.
- **C6** Three of five delta classes had no navigation reader (node_created is a ghost event,
  CONTRADICTS edges carry no timestamp, nothing read stage or sub-room creation); one new
  statement-home reader module closes the gap.
- **C7** `/mos:eureka` and `/mos:scout` measure `halt` in the posture registry; the child calls
  their library functions directly rather than requesting a registry reclassification.
- **C8** The only existing free-text rung classifier is a keyword marker table, forbidden for
  AMB-07; the framing follows a non-keyword lookup chain instead.
- **C9** Phase 355's D-50 assumed Desktop/Cowork cannot compute a stamp; a child spawned inside the
  MCP server's own process calls `brain-client` directly and can, a disclosed refinement (Ruling 1).
- **C10** Only 14 percent of live artifacts (472 of 3,333) carry the frontmatter a stamp needs to
  resolve, so most real-room ambient findings will stamp unverified.
- **C11** Find-connections is prompt-driven; it can only stamp pairs another producer already
  surfaced, never generate its own, in an unattended run.
- **C12** Measured fire-child latency: p50 8.4s, p90 11.6s, max 166s (n=135); the lock's stale
  window and the ambient budget are derived from this, not a narrower fresh resample.
- **C13** Delta class (b), a CONTRADICTS edge, is near-dormant live (1 edge, 0 contradiction
  decision nodes across 31 rooms); implemented per the lock but tested only against a fixture.
