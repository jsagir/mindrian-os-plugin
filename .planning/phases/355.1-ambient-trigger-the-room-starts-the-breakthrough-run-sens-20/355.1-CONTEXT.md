## Phase Boundary

The room, never the user, starts the breakthrough run. A room-delta detector (SENS-20) in the existing sensor registry recognizes five delta classes (claims added past a disclosed floor, a contradiction surfaced, a venture-stage change, a sub-room created, a new artifact filed) through the one navigation chokepoint, and starts the cross-connection producer run underneath as `autonomous_safe` machinery on every surface (CLI hooks; the MCP server's own loop on Desktop and Cowork). The run composes the five Phase 355 producers so every finding carries the 355 stamp and direction phrase; a per-room run ledger with a delta hash prevents re-runs; only `strong` and `indirect` findings reach the card, once, through 355-22's SENS-13 fire-once path; the card's framing derives from the room's problem type, not keywords. Navigator ruling 2026-09-23: rare users know to ask for a breakthrough; all gain from one that arrives on its own. This phase widens the Phase 117 ambient door (fingerprint hook plus detached fire child, surfaced by SENS-01) and consumes Phase 213's KEY (eureka reach runner plus SENS-13); it mints no rival trigger, no new command, no new MCP tool, no seventh reach.

<decisions>
## Implementation Decisions

### Trigger vocabulary (AMB-01, locked)
- The trigger is a room delta, never a clock and never a command.
- Five delta classes, each detected only through `lib/core/navigation.cjs` reads (no second SQL door): (a) N or more claim nodes added since the last run, N a disclosed floor in `data/floor-ledger.json`, never a bare literal; (b) a CONTRADICTS edge surfaced since the last run; (c) a venture-stage change in STATE.md; (d) a sub-room created; (e) a new artifact filed (the existing Phase 117 class, kept).
- A per-room delta hash (sha256 over the sorted delta facts) is computed once per evaluation and is what the ledger compares against.

### The detector (AMB-02, locked)
- Exactly one new detector, `SENS-20` room-delta, under `lib/core/sensors/`, registered in `lib/core/insight-sensors.cjs` SENSOR_REGISTRY in canonical order (SENS-01..SENS-19 are taken).
- It rides an EXISTING reach id from the frozen six (CIRS R3); it produces a candidate reach only, never routes, never executes (Phase 144 fence).
- Posture is joined from `lib/core/recipe-maps.cjs` (`postureForCommand`), never typed by hand.

### The run underneath (AMB-03, locked)
- On a delta, the producer run starts as a detached background child in the `scripts/auto-explore-fire.cjs` pattern, or through `scripts/scout-cadence-runner.cjs`'s composition; one of the two existing spawners is extended, never a third.
- The run composes the five Phase 355 producers (eureka bridge, find-connections, find-bottlenecks, HSI, whitespace) so every finding carries the 355 stamp and direction phrase.
- The run is `autonomous_safe` in substance: reads plus `proposed`-status writes through 355-20's writer; it runs unattended under the Post-Gate doctrine (`lib/core/chain-executor.cjs` `runChain`); the first material step (filing confirmed, opportunity qualified) stays behind the gate.

### Run ledger (AMB-04, locked)
- A per-room run ledger extends `scripts/scout-cadence-guard.cjs`'s throttle file shape (no fork): `last_run`, `last_delta_hash`, `origin: 'ambient'`, per-producer outcome.
- The same delta hash never re-runs; a throttle floor (disclosed in the floor ledger) bounds runs per room per hour; a lock file under `<roomDir>/.mindrian/` prevents a duplicate child; the D-06 regulator cap is honored.

### Surfacing and the Hooked lens (AMB-05, locked)
- The finding surfaces exactly once through 355-22's SENS-13 fire-once path as the next move on the card.
- Only `strong` and `indirect` stamps reach the card; `unverified` stays in the ledger and the log. The reward is the stamp tier, never a score.
- A filed `355.1-HOOKED-AUDIT.md` maps internal trigger (the delta), action (one card), variable reward (stamp tier), investment (the navigator's gate answer, which writes the graph edge the next run reads). Larry's line carries no praise, no grade, no count (Canon Part 12).

### Tri-polar (AMB-06, locked)
- CLI: the PostToolUse fingerprint hook plus a Stop-hook delta evaluation (the fingerprint alone misses classes b, c, d).
- Desktop and Cowork: the MCP server evaluates the delta in its own loop (`stop_gate_check` close-out or turn-start `context_assemble`) and starts the same child.
- `/mos:auto-explore` remains a fallback and is documented as such, never as the way in. Each surface has its own test leg; a skipped surface is a stated call.

### Strategy, not keywords (AMB-07, locked)
- The card's framing derives from the room's silently classified problem type (undefined / ill-defined / well-defined / wicked) through the existing local classifier, never a keyword match; an ill-defined room gets a find-the-problem framing, a well-defined room a pursue-or-drop framing.
- No new command, no new MCP tool. The framing text lives in one place beside the direction phrases and passes 355-23's no-decimal, tri-polar and em-dash gates.

### Boundaries (AMB-08, locked)
- Canon Part 8: the child reads the room locally; Theo receives only framework handles and enums through 355-06's adapter; the 355-21 egress sweep covers every new file.
- Canon Part 9: machinery confirms nothing; everything files `proposed`.
- Canon Part 11: every new surface is born wired or excluded with a declared HITL shape; `build-connector-registry --check`, `build-orchestration-projection --check`, `check-render-coverage`, `check-shape-declaration` green.
- No em-dashes anywhere.
- zod only at the two edges where bytes arrive from outside (MCP tool inputs, the Jev or Theo response parse, exactly as 355-06's `Stamp` schema does); never for the run ledger, the delta reads, the lock file or any egress guard, which stay plain frozen objects the Part 8 sweep can read (navigator ruling 2026-09-23 on the zod question).

### Proof and close (AMB-09, locked)
