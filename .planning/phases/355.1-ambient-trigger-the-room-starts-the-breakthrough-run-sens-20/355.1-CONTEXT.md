## Phase Boundary

The room, never the user, starts the breakthrough run. One new detector, SENS-21 (the PRD said SENS-20; Phase 345 already holds SENS-20 as `sensorStrategyReach`), plus one evaluator that is not a sensor, plus an ambient mode of the existing Phase 117 fire child. The evaluator recognizes five delta classes (claims added past a disclosed floor, a CONTRADICTS edge surfaced, a venture-stage change, a sub-room created, a new artifact filed) through readers re-exported from the one navigation chokepoint, and starts the five Phase 355 producers underneath as `autonomous_safe` machinery on every surface: on CLI from a new async Stop-hook entry (plus the existing PostToolUse fingerprint for class e), on Desktop and Cowork from the MCP server's Stop-time close-out. Every finding carries the 355 stamp and direction phrase; a per-room run ledger with a delta hash and a lock prevents re-runs; only `strong` and `indirect` findings reach the card, once, through SENS-13; SENS-21 fires only as the honest fallback offer when the run could not start on the current surface; the card's framing follows the room's problem type through a non-keyword lookup chain. Navigator ruling 2026-09-23: rare users know to ask for a breakthrough; all gain from one that arrives on its own. This phase widens the Phase 117 door and closes Phase 213's KEY (SENS-13 is dark in production today: the child calls the eureka scan without a pair and exits before it finishes); it mints no rival spawner, no command, no MCP tool, no seventh reach.

## Implementation Decisions

### Research corrections applied (locked; the PRD text yields to these)
- SENS-21, not SENS-20. Phase 345 registered `sensorStrategyReach` as SENS-20 in all seven lockstep places (`insight-sensors.cjs:771,819`, `sensor-priority.cjs:213`). Record the id correction the way 345 recorded its own; re-check the id is still free at registration time (peers can claim one).
- The MCP loop never calls `decide()`: `suggest_next` and `reach_candidates` call `dispatchSensors` with `{roomDir}` only. So SENS-21 reads a file in the room, never a `decide()` ctx producer, and 355-22's fire-once mark (which lives in `decide()`) does not hold on Desktop; this phase closes that gap (see Ruling 2).
- The cadence runner cannot host the stamped run: it is constitutionally zero-egress and 355-16 makes `--stamp` opt-in so cadence and cascade callers never call Theo. The spawner is the Phase 117 fire child, extended with an ambient mode.
- Hook `timeout` values are seconds, not milliseconds (Claude Code docs); the `3000` values in `hooks/hooks.json` mean 50 minutes and all matching hooks run in parallel. The new Stop entry uses `async: true` and the script enforces its own time budget.
- SENS-13 is dark today (`auto-explore-fire.cjs:334-340` calls `runEurekaScan` without a pair and exits); surfacing depends on 355-19 and 355-20 landing, a stated dependency.

### The split: detector, evaluator, card (AMB-02, AMB-03, AMB-05, locked)
- SENS-21 is a pure detector and the registered sensor: under `lib/core/sensors/`, registered in `lib/core/insight-sensors.cjs` SENSOR_REGISTRY in canonical order and in every lockstep place 345 touched, riding the EXISTING `context_block` reach at posture `hold` (sensor-priority Group B). `deep_research` is rejected because it is suppressed in turns 1-2, which would hide the offer right after a change that happened between sessions. It produces a candidate reach only; it never routes, never executes (Phase 144 fence). It fires only when the ledger says a delta was seen and the run could not start on the current surface (the honest fallback offer).
- The evaluator is not a sensor: one module that reads the room delta, computes the delta hash, consults the ledger and lock, and spawns the child. It is called from the CLI Stop hook and from `stop_gate_check` -> `closeOutRoom`, right after `_closeOutStateMd` (`context_assemble` is declared a pure read that never writes; wrong place).
- SENS-13 shows the card in the normal path: exactly one card per delta hash. Posture for anything the chain runs is joined from `lib/core/recipe-maps.cjs` (`postureForCommand`), never typed by hand.

### Trigger vocabulary and readers (AMB-01, locked)
- Five delta classes: (a) N or more claim nodes added since the last run; (b) a CONTRADICTS edge surfaced since the last run; (c) a venture-stage change in STATE.md; (d) a sub-room created; (e) a new artifact filed (the Phase 117 class, kept).
- Three of the five have no reader today: `node_created` events are a ghost (2 rows against 9,004 claims fleet-wide), CONTRADICTS edges carry no timestamp, nothing in navigation reads stage or sub-room creation. The fix is ONE new reader module in the style of `lib/core/navigation/graph-integrity-counts.cjs`, re-exported from `navigation.cjs`; never reuse `computeStrategyCounts().claims_since` (it reads the ghost event). Reads through the chokepoint only; no second SQL door.
- The per-room delta hash is sha256 over the sorted delta facts, computed once per evaluation; it is what the ledger compares against.

### The run underneath (AMB-03, locked)
- Extend `scripts/auto-explore-fire.cjs` with an ambient mode that replaces the dead eureka call at `:334-340`, so classes (a) to (e) all run through one child behind one lock. Measured child runtime today: p50 8.4 s, p90 11.6 s, max 166 s (n = 135); the ambient mode budgets against that.
- The child composes the five Phase 355 producers so every finding carries the 355 stamp and direction phrase; it calls their library functions directly (Ruling 3); writes are `proposed`-status through 355-20's writer; nothing it does needs a human to ratify; the first material step (filing confirmed, opportunity qualified) stays behind the gate.

### Run ledger (AMB-04, locked)
- Extend `scripts/scout-cadence-guard.cjs`'s throttle file shape (no fork): `last_run`, `last_delta_hash`, `origin: 'ambient'`, per-producer outcome; a lock file under `<roomDir>/.mindrian/`; the same delta hash never re-runs; D-06 regulator cap honored.
- Floors, both disclosed in `data/floor-ledger.json` and approved at the checkpoint: claim floor N = 5 (the measured median claims per active room-hour across 31 live rooms); throttle 1 run per room per hour.

### Surfacing and the Hooked lens (AMB-05, locked)
- Only `strong` and `indirect` stamps reach the card; `unverified` stays in the ledger and the log; the reward is the stamp tier, never a score, never a count.
- Honesty the Hooked audit must state: only 14 percent of live artifacts carry the `framework:` or `methodology:` frontmatter a stamp needs today, so most real-room findings will stamp `unverified` and never reach the card until rooms carry that frontmatter.
- `355.1-HOOKED-AUDIT.md` maps internal trigger (the delta), action (one card), variable reward (stamp tier), investment (the gate answer that writes the edge the next run reads). Canon Part 12: no praise, no grade, no count in Larry's line.

### Tri-polar (AMB-06, locked)

- `/mos:auto-explore` stays a documented fallback, never the way in. One test leg per surface; a skipped surface is a stated call.

### Strategy, not keywords (AMB-07, locked)
- The only existing free-text classifier (`_inferRungFromQuestion`) is a keyword table and is forbidden here. The framing follows a non-keyword lookup chain: the ratified `jtbd goal.rung`, then `ROOM.md` `pws_stage`, then explicit STATE.md fields, then the structural MINTO classifier, then neutral. Most live rooms land on undefined or unknown today; the neutral framing must read well.
- An ill-defined room gets a find-the-problem framing; a well-defined room a pursue-or-drop framing. No new command, no new MCP tool. The framing text lives in one place beside the direction phrases and passes 355-23's no-decimal, tri-polar and em-dash gates.
