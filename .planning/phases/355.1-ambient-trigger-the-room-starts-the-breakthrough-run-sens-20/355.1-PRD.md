**Ruling (navigator, 2026-09-23, recorded verbatim in substance):** users will not know when to trigger the breakthrough engine. The point of MindrianOS is ever-growing opportunities and breakthroughs, depending on context and the need of the user, never on the user explicitly asking. Rare are the users who will know to ask for it; all will gain from using it.

## 1. Goal

A cross-domain finding (eureka bridge, find-connections, find-bottlenecks, HSI, whitespace) reaches the navigator because the ROOM changed in a way that makes one likely, on every surface, with no command typed and no schedule waited for; the finding is stamped by Phase 355 and surfaces once as the next move on Larry's card; the navigator's ratify or reject is the investment that makes the next run sharper.

## 3. Requirements (each locked; IDs AMB-01..AMB-09 are phase-local and registered at close like HIPS-xx)

**AMB-01 - Delta vocabulary.** The trigger is a room delta, never a clock and never a command. The recognized delta classes, each detected only through `navigation.cjs` reads (no second SQL door): (a) N or more claim nodes added since the last run (N is a disclosed floor in `data/floor-ledger.json`, never a bare literal); (b) a CONTRADICTS edge surfaced since the last run; (c) a venture-stage change in STATE.md; (d) a sub-room created; (e) the existing Phase 117 class, a new artifact filed (kept, not replaced). A per-room delta hash (sha256 over the sorted delta facts) is computed once per evaluation and is what the ledger compares against.

**AMB-02 - One detector, existing reach.** One new detector `SENS-20` (room-delta) in `lib/core/insight-sensors.cjs` under `lib/core/sensors/`, registered in canonical order, riding an EXISTING reach id (planner picks `deep_research` per the SENS-13 precedent or `context_block` per SENS-01/SENS-14, and says why). It PRODUCES a candidate reach only; it never routes and never executes (Phase 144 fence). Posture per the registry contract; `autonomous_safe` is joined from `recipe-maps.cjs`, never typed by hand.

**AMB-03 - The run underneath.** On a delta, the producer run starts underneath as machinery: the detached background child pattern of `auto-explore-fire.cjs` (or the cadence runner's composition, planner decides after research, one of the two, never a third spawner), now composing the five Phase 355 producers so every finding carries the 355 stamp and direction phrase. The run is `autonomous_safe` in substance (reads plus `proposed`-status writes through 355-20's writer; nothing it does needs a human to ratify) and runs unattended under the Post-Gate doctrine; the first material step (filing confirmed, opportunity qualified) stays behind the gate.

**AMB-04 - Run ledger, no re-runs.** A per-room run ledger (extend `scout-cadence-guard.cjs`'s throttle file shape, do not fork it): `last_run`, `last_delta_hash`, `origin: 'ambient'`, per-producer outcome. The same delta hash never re-runs; a throttle floor (disclosed in the floor ledger) bounds runs per room per hour; a running child is never duplicated (lock file under `<roomDir>/.mindrian/`). D-06 regulator cap honored.

**AMB-05 - Surfacing, Hooked.** The finding surfaces exactly once through 355-22's SENS-13 fire-once path as the next move on the card; only `strong` and `indirect` stamps reach the card, `unverified` stays in the ledger and the log (variable reward by stamp tier, never a score). The Hooked model is the mandatory lens for this first step: a filed `355.1-HOOKED-AUDIT.md` maps internal trigger (the delta), action (one card), variable reward (stamp tier), investment (the navigator's gate answer, which writes the graph edge the next run reads). No praise, no grade, no count of findings in Larry's line (Canon Part 12).

**AMB-06 - Tri-polar, no typed fallback as the primary path.** CLI: the PostToolUse fingerprint hook plus a Stop-hook delta evaluation (the fingerprint alone misses classes b, c, d). Desktop and Cowork: the MCP server evaluates the delta in its own loop (`stop_gate_check` close-out and/or turn-start `context_assemble`, planner picks one after research) and starts the same child; `/mos:auto-explore` remains a fallback and is documented as such, never as the way in. Each surface is tested with its own leg; a skipped surface is a stated call, not an omission.

**AMB-07 - Strategy, not keywords (the deferred 355 front end).** The card's framing derives from the room's problem type (classified silently: undefined / ill-defined / well-defined / wicked, through the existing local classifier, never from a keyword match) and the opportunity-review entry point: an ill-defined room gets a find-the-problem framing, a well-defined room gets a pursue-or-drop framing. No new command, no new MCP tool (355's boundary holds). The framing text lives in one place beside the direction phrases and passes the 355-23 no-decimal, tri-polar and em-dash gates.

**AMB-08 - Boundaries that hold.** Canon Part 8: the child reads the room locally; Theo receives only framework handles and enums through 355-06's adapter; the Part 8 egress sweep (355-21) covers every new file. Part 9: no truth claim is confirmed by machinery; everything files `proposed`. Part 11: every new surface is born wired or excluded with a declared HITL shape; `build-connector-registry --check`, `build-orchestration-projection --check`, `check-render-coverage`, `check-shape-declaration` all green. No em-dashes anywhere.

**AMB-09 - Proof and close.** `tests/run-all-355.1.sh` (hygiene-355 helper reused): delta detection legs per class, ledger no-re-run leg, throttle leg, lock leg, stamp-tier gating leg, SENS-20 fire-once leg, tri-polar legs (one per surface), Part 8 egress leg, negative controls (a planted second spawner, a planted score literal). `node scripts/doctor.cjs --acceptance` unregressed against `355-BASELINE.md`.
