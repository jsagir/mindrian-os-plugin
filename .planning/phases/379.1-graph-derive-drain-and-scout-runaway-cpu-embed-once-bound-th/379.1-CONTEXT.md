## Addendum 2026-10-21: the debug session verdict (outranks the incident report)

Source: .planning/debug/drain-and-scout-runaway-cpu-wsl-windows.md, status root_cause_found. The debugger ran the code; marks are its own (PROVEN, UNVERIFIED, ASSUMED).

1. The trigger is data, not code. On 2026-10-18 the Eureka JHTV workflow filed 2119 generated markdown files into solution-design/full-catalog-run-2026-10-18. The room went from 44 artifacts to 2163. The drain and scout code is byte-identical between beta.59, beta.69 and this branch for every suspect file. The Eureka adapter branch changed none of it. PROVEN.
2. The scout (rs-engine runModeInternal) is not stuck in the encoder. It is in buildLsaMatrix: lib/core/numeric/svd.cjs diagonalises a 2000 x 2000 Gram matrix with a hand-written cyclic Jacobi solver. One sweep is 1,999,000 rotations; measured 19 min per sweep under contention, about 11 min uncontended. 10 to 14 sweeps expected at n=2000, so 2 to 4 hours per run (ASSUMED). discoverArtifacts has no cap; scout-cadence-runner.cjs runStep calls execFileSync with no timeout. The incident report's D6 named the right symptom and the wrong cause. This changes CPU379-06 (see ROADMAP).
3. The drain is one process with 22 threads: 11 onnxruntime threads. embedding-spine.cjs:405 calls pipeline() with no session_options. Measured 8.69 to 10.43 cores and 1.66 to 1.84 s per pair. One room-scope queue entry from 2026-07-06 yields N(N-1)/2 = 2,338,203 pairs: 45 to 50 days of work. The vector seam at classifier line 178 is dead because makeArtifact sets no vector. Confirms D1, D2, D3.
4. The lock reclaim defect is reproduced in a temp room: with the lock mtime backdated 11 minutes while the first worker lived, a second drain reclaimed it and both ran. PID is written but never read; release does not check the owner. Confirms D5.
5. The scout has no single-flight guard: scripts/session-start:1793-1796 starts scout-cadence-runner.cjs on every session start, clear and compact. The only throttle is a 24 h stamp written at the END of a run, so a killed run never arms it. SCOUT_CADENCE_SKIP=1 exists as a switch; the drain has no switch.
6. Hooks: every prompt cold-starts 8 node processes; 0.49 to 0.85 s idle, 20.1 s under encoder load (one sample). Budgets are wall-clock kills; nothing reserves CPU.
7. Line numbers in the incident report that differ from this branch are listed in the debug file; the planner uses the debug file's numbers.

Smallest fix set the debugger proposed (proposal only, nothing applied): A scout bound (cap before LSA, timeout on runStep), B scout single-flight, C drain pair cap with disclosure plus embed-once through the existing .rs-engine-cache.json, D intra_op_num_threads 2 in pipeline() plus os.setPriority in the worker, E lock heartbeat and PID check, F operator mitigation now (SCOUT_CADENCE_SKIP=1, remove the stale 2026-07-06 queue entry).

Open design question for the planner: the long-term SVD fix (top-k subspace or Lanczos in place of full Jacobi) is out of this phase unless the research shows it is small; the cap is the phase's floor.

## Consult: neo4j-vector-index-skill and neo4j-graphrag-skill (main session, 2026-10-21, navigator asked)

Applicability: the room graph is SQLite (room.db), not Neo4j. Room vectors derive from room content and never reach the Brain's Neo4j (Canon Part 8). The graphrag skill (retrievers over Neo4j) does not apply to the drain. The vector-index skill's RULES transfer; its Cypher does not.

Locked for the vector cache (CPU379-01):
- D-379.1-06 The cache key carries the model identity: (content_hash, model_id, dim). Assert dim on every write (the live encoder is 384-dim per RESEARCH.md). A model change invalidates all rows; never mix vectors from two models in one scoring pass.
- D-379.1-07 Batch writes: one SQLite transaction per batch of vectors; never one write per row.
- D-379.1-08 Similarity is cosine over normalized vectors. The drain's encoder probe gains one sanity check: two known-similar texts must score clearly above two unrelated texts, and an all-identical or all-zero result marks the encoder unavailable (the skill's "score always 1.0" failure).
- D-379.1-09 No quantization. At about 2,163 vectors x 384 float32 the cache is a few MB; scalar or binary quantization is out of scope.

Proposal for the planner (CPU379-02, probe before adopting):
- P-379.1-01 Candidate pruning by nearest neighbours: for each artifact take its top-k neighbours by cosine over the cache (k about 10, value from the probe), and run the full scorer (lexical leg plus Part 8 audit, measured 3.5 ms per pair with vectors) only on those pairs. On the jhtv room that is on the order of N x k = 21,630 scored pairs instead of N(N-1)/2 = 2,338,203. The cosine pass is N^2 dot products of dim 384 in plain JS with Float32Array; its runtime is UNVERIFIED and must be measured in a probe on this machine. If adopted, the cursor from D-379.1-01 still bounds each drain; the ceiling-and-skip still applies to rooms where even N x k exceeds the budget. Do not add a native ANN extension (sqlite-vec or similar): no build step on the user's machine (CLAUDE.md conventions), and node:sqlite extension loading is out of scope.
- Rank fusion note for a later phase, not this one: the skill combines lexical and semantic signals by rank (RRF), not by raw score. The scorer's lexical and semantic legs today combine raw scores. File as a seed if the planner sees it matters.

## Decisions after the breakthrough research (main session, 2026-10-21; source: 379.1-BREAKTHROUGH-RESEARCH.md)

- D-379.1-12 CPU379-02 is CHANGED: the top-k cosine pruner over the Float32Array vector cache is the PRIMARY bound (P-379.1-01 adopted; probe: full N x (N-1) pass at N=2163, D=384 took 10,832 ms on this machine). - D-379.1-14 CPU379-06 keeps the artifact cap as the floor AND adds a separate, gated plan: replace the cyclic Jacobi in lib/core/numeric/svd.cjs with a seeded randomized truncated SVD (Halko, Martinsson, Tropp 2011; probe: 2163 x 2000, k=80, p=10, q=2 in 3,381 ms in about 120 lines). - D-379.1-15 LSA stays. The scout's output is absDiffTopk(lsaMatrix, semMatrix) (rs-engine.cjs:524-585); both legs from the same vectors would zero the output. Do not replace the lexical leg with the embeddings.

The pair memo key, if a pair memo is built, is (hash_a, hash_b, model_id, scorer_version).
- D-379.1-17 Matryoshka truncation of mdbr-leaf-ir (model card: robust to MRL truncation) is NOT used this phase; file a seed for rooms above about 10k artifacts (128-dim first pass probe: 4,011 ms vs 10,832 ms).
