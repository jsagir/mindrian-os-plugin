**Phase Goal:** Stop the graph derive drain and the session-start scout from taking the whole CPU on a large room: embed each file once (cache by content hash), bound the work per drain with a cursor, cap the worker (time, priority, ONNX threads in embedding-spine.cjs), count a killed worker as an attempt, make the lock prove its PID is dead, apply the same caps to the scout cadence runner. ## Verdict

The algorithmic fix is real and tested. The CPU and clock bounds hold. The phase goal also says "ship in beta.73", and the phase set a peak RSS limit of 1,024 MB in its own release leg (CPU379-08). The one live full run breached it: 1,837 MB. A breach of a limit the phase itself set is a gap. The release gate refuses the receipt, so beta.73 is blocked. This verifier did not lower or raise any limit, did not re-run the live leg, and wrote no receipt.

Note on direction: the incident report measured 509 MB RSS for the unfixed worker. The fixed worker peaks higher in memory (though far lower in CPU and clock). The fix traded CPU for memory without a measured bound on memory.
