# Phase 379.1 Plan 02: Foundation modules (vector cache, artifact scope, job lock, encoder thread cap) Summary

**Three new lib/core modules and the ONNX thread cap on the one pipeline() call: a (content_hash, model, dim)-keyed JSON vector cache in the rs-engine format, a scope predicate whose wildcard-only and overbroad declarations exclude nothing and are reported with counts, a job lock that never reclaims a live owner by age and reclaims a recycled PID after the 6 h ceiling, and intraOpNumThreads 2 / interOpNumThreads 1 / allow_spinning '0' proven hermetically through a stub package and live (12 threads after load, limit 13).**

## What the plan's output asks for (first)

- **allow_spinning shipped: YES.** `tests/fixtures/379.1/probe-allow-spinning.json` records `extra_honoured: true` (ORT 1.30.0). `embedding-spine.cjs` has `ALLOW_SPINNING_EXTRA_SHIPPED = true`; `buildSessionOptions()` returns `{ intraOpNumThreads: resolveThreads(), interOpNumThreads: 1, extra: { session: { intra_op: { allow_spinning: '0' } } } }`. The value is a string (the binding throws on a non-string). The probe measured no idle-CPU halving from it (673 vs 815 ms), so the SUMMARY makes no idle-CPU claim for the flag; the cap is the control.
- **D-379.1-07 deviation is in the code with its comment.** `vector-cache.cjs` header records: JSON file in the rs-engine byte-shape `{ version, updated_at, model, embeddings }`, tmp plus rename, Part 7 reuse, accepted 2026-10-21; `SAVE_EVERY_BATCHES = 8` with the cadence comment (after every 8th batch, at the deadline, at an encoder failure, at the end; about 9 rewrites instead of 68 at batch 32 over 2,163 artifacts). The module never reads or writes the `eureka_vec*` or `eureka_fts*` tables; the CONTEXT.md row says so.
- **OVERBROAD_DIR_SHARE_DEFAULT 0.5 is in the code with its comment.** `artifact-scope.cjs` carries the constant, the env name `MINDRIAN_SCOPE_OVERBROAD_DIR_SHARE` (decimal in (0, 1], else the default), the checker's note that the pre-walk counts may differ from a walker on rooms with dot-directories or depth above 8, and the guard B comment that the share is advisory when `stats.truncated` is true.
- **Two vector stores now exist in a room** (from the CONTEXT finding): the Python Eureka engine's vec0 tables in room.db and the node JSON cache this module owns. They are keyed by different models unless proven equal. A seed to unify them after beta.73 is the right follow-up; nothing here blocks on it.

## Decisions Made

- allow_spinning shipped behind `ALLOW_SPINNING_EXTRA_SHIPPED = true` (probe-driven, implementation-time; flip to false ships no extra block and `resolveAllowSpinning()` returns null).
- `load()` enforces the dim only when `expect.dim` is a positive integer (otherwise non-empty and finite); the drain and scout should always pass the live dim.
- `isExcludedDir` returns false for the room root and for any directory outside the room before the marker check.
- `acquire()` applies the boot guard before the liveness rule and gives the calling process's own pid no special adoption.
- `acquire()` returns `recovered: { pid, reason }` on a reclaim and `loadScope` returns `dir_share` (the resolved threshold): small additive fields for the Plan 04 and 05 disclosures and the doctor.
- The checker INFO notes were applied: G6a and G6b tests exist; the OVERBROAD_DIR_SHARE_DEFAULT comment carries the pre-walk caveat; the guard B comment states the share is advisory when truncated; the T-379.1-03 sleep sentence is in the job-lock header. `scope.stats.truncated` is the field Plans 04 and 05 expose as `scope_prewalk_truncated`.
