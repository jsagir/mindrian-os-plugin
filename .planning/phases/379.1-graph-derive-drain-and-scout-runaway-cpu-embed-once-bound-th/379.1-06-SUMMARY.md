## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing critical] The leg must not download the embedding model**
- **Found during:** Task 1 design (the drain child loads the real encoder; `getEncoder` downloads on a cache miss)
- **Issue:** a hermetic test or a release run on a machine without the model would fetch it, a network call the leg must not make.
- **Fix:** a disk check (`modelCachedLocally`, through the spine's `resolveModel` and `resolveCacheDir`) before the drain child. No model: outcome `encoder_unavailable`, status `inconclusive`, child not started. The gate refuses `inconclusive`, so this cannot pass a release by accident.
- **Commit:** 3bda66559

**2. [Rule 3 - Blocking] Existing tests assumed a gate with no large room leg**
- **Found during:** Task 2 (`test-muy-real-room-rule` G3, G4, G7, G13, G14; `test-3692-wording` WD6; `test-3692-closure`)
- **Issue:** receipts built by hand had no `large_room_leg`; receipts written by a hermetic real run (empty HOME) carry an `inconclusive` leg by design, so the gate now refuses them.
- **Fix:** the shared receipt builder carries a passing leg; the hermetic-run arms read a receipt copy with a passing leg and say why in a comment; the gate's large-leg verdicts are pinned by the new arm G15. The OFFLINE check was moved before the large-leg check so G7 and G14 keep their OFFLINE refusal.
- **Commit:** a77ac4e13

**3. [Rule 1 - Bug] pair-cursor scenario 8 depended on the clock**
- **Found during:** the phase runner (failed 1 of 4 direct runs)
- **Issue:** the 1 ms budget is not spent when 12 texts embed in under 1 ms, so the first drain finished the entry. Root cause: the test relied on the embed step being slower than the budget.
- **Fix:** the first drain's embedFn holds the clock for 5 ms. 5 of 5 runs green afterwards.
- **Files modified:** tests/test-379.1-pair-cursor.cjs
- **Commit:** d8ebc1b66
