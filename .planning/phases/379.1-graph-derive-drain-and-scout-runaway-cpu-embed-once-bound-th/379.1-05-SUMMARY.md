**2. [Rule 1 - Spec mismatch] hsi-engine returns `success: false`, not `ok: false`**
- **Found during:** Task 1 (read of the runTier1 envelope family)
- **Issue:** the plan says "ok false"; the module's own not-ok envelope is `{ success: false, error, detail }`, and the plan also says to copy the family exactly.
- **Fix:** the cap returns the `success` shape; the test asserts `success === false`.
- **Commit:** c08ae53dd

**3. [Rule 2 - Missing critical] A lock error must not block the cadence; the abandoned drop must not race a live drain**
- **Found during:** Task 2 and Task 3 design
- **Issue:** `jobLock.acquire` can return `reason: 'error'` (a read-only room). Treating it as in flight would stop the scout for good. The doctor's queue write could clobber a live drain's patch.
- **Fix:** only `held` and `recovering` mean in flight (the throttle stamp still bounds a lock-less run). `healAbandoned` defers while a live drain with a fresh heartbeat holds the lock, and says so in a recovery line.
- **Commit:** b365c6521, b708474c4

**4. [Rule 2 - Missing critical] fix must not re-enqueue what it just abandoned**
- **Found during:** Task 3
- **Issue:** an 8-day entry also counts as stuck, so the existing branch would re-enqueue the room right after the drop and recreate the stuck entry.
- **Fix:** the existing branch now needs `queueStuckCount - queueAbandonedCount > 0` (or needsHeal); asserted by scenario 4b.
- **Commit:** b708474c4
