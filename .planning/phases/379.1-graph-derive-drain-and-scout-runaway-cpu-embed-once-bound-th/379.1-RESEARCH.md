## Summary

The debug session is the ruling source. Two workers take the CPU for two different reasons. The drain (scripts/gsd-graph-derive-drain.cjs --worker) scores every pair of a 2163-artifact room, embeds both texts per pair, runs on the ONNX default thread pool, has no time limit, and its lock reclaims after 10 minutes without a PID check. The scout (scripts/scout-cadence-runner.cjs step 7, rs-engine runModeInternal) is not in the encoder at all. It is in the cyclic Jacobi solver of lib/core/numeric/svd.cjs on a 2000 x 2000 Gram matrix, with no artifact cap, no step timeout and a throttle stamp written only at the end of a run. Both exploded on 2026-10-18 when a Eureka workflow wrote 2119 generated files into the room (PROVEN by the debug file and by this session's file counts).

This session verified every seam by reading the code on this branch and ran four probes. The incident report's line numbers match this branch for every file it cites (PROVEN; the table in "Line number check" lists them). The thread cap works with the installed stack: `session_options: { intraOpNumThreads: 2, interOpNumThreads: 1 }` in the `pipeline()` call takes the process from 22 threads and 10.1 cores to 12 threads and 2.0 cores (PROVEN by probe). A pair scored with cached vectors still costs 3.5 ms of pure JS (lexical leg plus the Part 8 audit), so 2.3 million pairs is 137 minutes even with embed-once (PROVEN by probe). The pair bound and the cursor are therefore required, not optional. The repo already has a content-hash vector cache (rs-engine.cjs `.rs-engine-cache.json`, sha256 first 16 hex chars, model-stamped) and a PID-liveness lock idiom (lib/core/write-lock.cjs). Both are the Part 7 reuse targets.

**Primary recommendation:** Land the fix in this order, each a small commit with its own test: (1) thread cap in embedding-spine.cjs getEncoder (one call, every encoder user gets it); (2) embed-once through a shared vector-cache module extracted from rs-engine.cjs, attached to artifacts so the existing classifier seam at line 178 lights up; (3) pair slice with cursor and a hard pair cap with the existing derivation_skipped disclosure; (4) attempt record before the work, worker priority and time budget; (5) lock with heartbeat, PID check and owner-checked release, shared by drain and scout; (6) scout artifact cap, runStep timeout, throttle stamp at start; (7) the artifact-scope declaration consumed by both walkers; (8) doctor extension; (9) the generated large fixture leg in real-room-run.cjs.

### Pattern 1: one env-validated tunable per cap
**What:** every new cap reads its env at call time with the positive-int validation shape of `resolveBatchSize` (embedding-spine.cjs:189-196, PROVEN) or `envInt` (reasoning-mode.cjs, PROVEN).
**When to use:** every new constant in this phase.
**Example:**
```javascript
// Source: lib/core/semantic-index/embedding-spine.cjs:189-196 (PROVEN, this repo)
function resolveThreads() {
  const raw = process.env.MINDRIAN_EMBED_THREADS;
  if (typeof raw === 'string' && raw.trim() !== '') {
    const n = Number(raw.trim());
    if (Number.isInteger(n) && n > 0) return n;
  }
  return DEFAULT_THREADS; // 2, see D3
}
```

### Pattern 2: attach vectors to the artifact objects, do not touch the classifier's scoring path
**What:** pairs reference the same artifact objects (PROVEN buildAllPairs 326-334 pushes `{a: arts[i], b: arts[j]}`). Set `art.vector` once per artifact and the existing seam at classifier 178-180 passes `opts.vectors` to the scorer, which then never calls embedTexts (PROVEN scorer 536-540).
**When to use:** D2.

### Pattern 3: write state before work, clear on success only
**What:** the queue entry is the only durable record. Rewrite it atomically (sweep.writeQueue, tmp + rename, PROVEN gsd-graph-derive-sweep.cjs:114-121) before the first pair and after each slice.
**When to use:** D1 and D4.

### Anti-Patterns to Avoid
- **Materializing all pairs:** `buildAllPairs` builds N(N-1)/2 objects (2,338,203 for N=2163) before scoring one (PROVEN 323-337). The slice builder must iterate (i, j) from the cursor and stop at the limit.
- **Age-only lock reclaim:** reproduced by the debugger (E5). Liveness is the truth; age is documentation (write-lock.cjs header, PROVEN).
- **Recording the attempt after the work:** a killed worker leaves no trace (D4). Record first.
- **Throttle stamp at the end of the run:** the scout re-fires on every session start while a run is alive (PROVEN: two live scout runs at research time).
- **Lowering the MCP server's priority:** only the detached worker and the scout runner call os.setPriority. embedTexts from an in-session tool stays at normal priority.

### Priority (PROVEN by probe and docs)
- Call: `os.setPriority(0, process.platform === 'win32' ? os.constants.priority.PRIORITY_BELOW_NORMAL : os.constants.priority.PRIORITY_LOW)` at the top of the worker branch of `main()` (after `parseArgs`, inside try/catch) and at the top of `scout-cadence-runner.cjs main()`.
- Node docs: priority is an integer from -20 to 19; mapped to six constants; "On Windows, setting priority to PRIORITY_HIGHEST requires elevated user privileges. Otherwise the set priority will be silently reduced to PRIORITY_HIGH." Constants: PRIORITY_LOW = IDLE_PRIORITY_CLASS on Windows, nice 19 elsewhere; PRIORITY_BELOW_NORMAL = BELOW_NORMAL_PRIORITY_CLASS, nice 10 [CITED: https://nodejs.org/api/os.html#ossetprioritypid-priority].

- WSL caveat (ASSUMED, consistent with the debugger's E7 UNVERIFIED note): nice inside the WSL VM orders processes inside the VM only. ### Liveness semantics (PROVEN by probe and docs)
- `process.kill(pid, 0)`: "As a special case, a signal of 0 can be used to test for the existence of a process." "Sending signal 0 can be used as a platform independent way to test for the existence of a process." [CITED: https://nodejs.org/api/process.html#processkillpid-signal and the Signal events section]. Probe: pid 1 -> EPERM, own pid -> no throw, pid 999999 -> ESRCH. Treat EPERM as alive (write-lock.cjs rule).

### Design (prescriptive): `lib/core/job-lock.cjs`
- `acquire(lockPath, { staleMs })` -> `{ ok, handle } | { ok: false, reason: 'held' | 'recovering' }`. Lock content JSON: `{ pid, started_at, heartbeat_at, boot_ms, job }`. A bare integer in an old lock file is read as `{ pid: n }` (legacy).
- Reclaim rule: reclaim only when (a) `pid` is dead (ESRCH), or (b) `boot_ms` differs from the current boot by more than 120 s (`Date.now() - os.uptime() * 1000`; PROVEN `os.uptime()` works here; ASSUMED stable to a few seconds across calls; PID reuse after a WSL or Windows restart is the case this guards), or (c) the file is unparseable. A live pid with a stale heartbeat is reported as `held_stale` and left alone (write-lock.cjs rule: never displace a live owner by age); the doctor surfaces it (CPU379-07).
- Reclaim atomicity: `fs.renameSync(lockPath, lockPath + '.dead-' + Date.now())` then retry 'wx'; only one contender's rename succeeds (ASSUMED: rename of a missing source throws ENOENT for the loser). The `.recover` mutex of write-lock.cjs is the alternative if the planner prefers an exact copy.
- `heartbeat(handle, intervalMs = 30000)`: `setInterval` that rewrites the JSON with a fresh `heartbeat_at` through tmp + rename; `.unref()` so it never keeps the process alive. 30 s is 1/20 of the 10-minute stale window (ASSUMED proportion).
- `release(handle)`: read the file; remove only when `pid === process.pid` and `started_at` matches the handle. A non-owner release is a no-op.
- Used by: the drain (`.mindrian/graph-derive-drain.lock`, same path as today) and the scout runner (`.mindrian/scout-cadence.lock`, new).
- Test: repeat the debugger's reproduction (backdated mtime with a live holder -> second acquire returns held, not reclaimed; dead pid -> reclaimed; foreign release is a no-op).

## Common Pitfalls

### Pitfall 1: embed-once without a pair bound still takes hours
**What goes wrong:** 2.3 million pairs x 3.5 ms of lexical plus Part 8 audit = 137 minutes (PROVEN probe).
**How to avoid:** D1 slice and caps. **Warning sign:** a drain that runs past its budget with zero encoder threads busy.

### Pitfall 2: one cache file for two engines thrashes
**What goes wrong:** rs-engine hashes the body; the classifier hashes the full file. Same id, different hash, each run re-embeds and overwrites (PROVEN text derivations).
**How to avoid:** separate file, shared module.

### Pitfall 3: the in-session backfill has the same N squared
**What goes wrong:** `graph-backfill.cjs` calls `classifier.buildAllPairs` (PROVEN 595, 621). `/mos:graph --derive` on the big room would run for hours in the foreground.
**How to avoid:** route it through `attachVectors` and the same per-entry pair cap, or at least the cap with a visible refusal. Scope: CPU379-02 says "in the background"; name the foreground gap in the plan.

### Pitfall 4: priority cannot be raised again
**What goes wrong:** PROVEN EACCES on WSL when raising. Code that lowers then restores will throw.
**How to avoid:** set once in the worker; never in the MCP server or a hook.

### Pitfall 5: Windows IDLE class can starve the worker
**What goes wrong:** no progress inside the budget, attempts count up, entry dropped as exhausted (ASSUMED).
**How to avoid:** BELOW_NORMAL on win32; attempts reset on progress.

### Pitfall 6: PID reuse after a reboot
**What goes wrong:** a lock from before a WSL restart names a pid that now belongs to a live unrelated process; kill(pid, 0) says alive; the drain never runs again.
**How to avoid:** the `boot_ms` field; the doctor's dead-lock reason.

### Pitfall 7: the scout's Python legs are outside the CJS scope predicate
**What goes wrong:** `compute-hsi.py` walks through `rs_corpus_exclude.py`; with sklearn installed it would still see 2163 artifacts (UNVERIFIED availability).
**How to avoid:** the runStep timeout bounds them this phase; the JSON declaration can be read by the Python module later (open question).

### Pitfall 8: a `derivation_completed` per slice hides the real completion
**What goes wrong:** the health module reads the last completion event (PROVEN readLastDeriveCompletion) to decide `deriveAttemptCompleted`.
**How to avoid:** write completion only on the last slice; put progress in the entry.

### Pitfall 9: the hook entry must stay free of encoder work
**What goes wrong:** anything heavier than the self-detach at drain 603-617 or the enqueue at sweep hook (3 s) breaks the 2 to 3 s prompt-path budgets.
**How to avoid:** all new work is in `--worker` or in the scout runner.

### Pitfall 10: provenance 'stub' on precomputed vectors
See D2. Harmless for edges; fix or document.
