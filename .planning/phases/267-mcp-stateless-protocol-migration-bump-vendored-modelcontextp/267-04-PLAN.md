Create `tests/helpers/mcp-stdio-tee.cjs`: an executable CJS script. argv after the script is the real server command (e.g. `node /abs/bin/mindrian-mcp-server.cjs`). It spawns that command with the parent's env unchanged, pipes host stdin -> child stdin and child stdout -> host stdout byte-for-byte (no buffering changes beyond line framing needed to parse), pipes child stderr to its own stderr, and forwards exit code and SIGTERM/SIGINT to the child. While piping it parses newline-delimited JSON-RPC in BOTH directions and appends one JSONL record to the file named by env `MOS_TEE_LOG` (skip logging when unset) ONLY for: host->server messages whose method is `initialize` or `server/discover` or `notifications/initialized` (record `{ts, dir:'c2s', method, protocolVersion: params.protocolVersion, clientInfo: params.clientInfo, capabilityKeys: Object.keys(params.capabilities||{}), capabilities: params.capabilities}` plus, for a modern `_meta` envelope, only its protocolVersion key), and server->host responses to those ids (record `{ts, dir:'s2c', id, protocolVersion: result.protocolVersion, serverInfo: result.serverInfo, hasInstructions: typeof result.instructions === 'string', error: error && error.code}`). Any other method is recorded as `{ts, dir, method}` only, never params or result. After the first 20 records stop logging entirely.
