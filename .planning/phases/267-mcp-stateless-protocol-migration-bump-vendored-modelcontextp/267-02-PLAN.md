The three runtime-loop prompts built for Desktop's prompt menu are dead on every surface.
- RCA 5: `lib/mcp/session-catchup.cjs:335-338` installs SIGTERM/SIGINT listeners that never exit, which disables Node's default exit-on-signal; in HTTP mode the listening socket keeps the process alive (research observed a test server survive SIGTERM and need SIGKILL).
- RCA 6: `bin/mindrian-mcp-server.cjs:404` `app.listen(port, host, () => {...})` ignores the error argument that Express 5 passes to the listen callback (verified at plan time: express 5.2.1 calls the callback with EADDRINUSE), so on a bind failure the server logs "MCP server ... started (... HTTP on 127.0.0.1:3847 ...)" and, flag-ON, writes a pidfile for a port it does not own.
- RCA 7: with MINDRIAN_MCP_FIRST on and a hook-supplied MINDRIAN_SESSION_ID (the normal hook case), `bin/mindrian-mcp-shim.cjs:63-68` pre-seeds `clientOpts.sessionId`, so the client sends `mcp-session-id: <hook id>` on its very first request; the daemon's flag-ON route (`bin/mindrian-mcp-server.cjs:338-352`) answers any header id it did not mint itself with 400 "Bad Request: No valid session ID provided", and its `sessionIdGenerator` always mints `randomUUID()`. Live at plan time: every POST from the shim got 400 and the shim never connected; without MINDRIAN_SESSION_ID the same shim connected (unbound). The shim's own comment ("the daemon's session-registry accepts a caller-supplied id") describes a D-02 one-namespace binding the transport layer never implemented. Fixing it means choosing how a caller-supplied identity becomes the binding key, which is the room-binding identity model CTX rules out of this phase (icm-architect consult: a follow-up seed), so this RCA is filed, pinned by 267-15, and routed to the navigator.
