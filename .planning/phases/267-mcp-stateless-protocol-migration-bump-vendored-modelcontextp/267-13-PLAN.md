<objective>
Make the local server's process lifecycle honest, test-first: it exits on SIGTERM/SIGINT after teardown (RCA 5), and it reports a failed HTTP bind as a failure instead of printing "started" (RCA 6).

Purpose: both defects were found while planning this phase's HTTP work and sit in the file this wave owns. RCA 5: registerShutdownHandler's listeners replace Node's default exit-on-signal and never exit, so an HTTP-mode server survives SIGTERM and holds port 3847 (research Pitfall 9 saw false test results from exactly this). RCA 6: Express 5 passes bind errors to the listen callback, which ignores them, so a failed bind prints the success line and, flag-ON, writes a pidfile for a port the process does not own: the recurring false-success class. RESEARCH's MCPV2-14 ("HTTP-mode process exits on SIGTERM") is the requirement.
Output: RED test, fixed entry point, two resolved RCAs.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| OS signals -> server process | host or user stops the server |
| pidfile -> other clients (shim, adapter-client) | clients trust the pidfile's port to reach the daemon |

| T-267-29 | Spoofing | pidfile written for a port the process does not own (listen failure) | mitigate | on listen error no pidfile is written and the process exits 1; flag-ON clients therefore never connect to a foreign listener that happens to hold the port |
| T-267-30 | Repudiation | false "started" log | mitigate | success line printed only on a successful bind; test asserts its absence on EADDRINUSE |
| T-267-31 | Tampering | session snapshot lost on fast exit | mitigate | terminal listener registered after registerShutdownHandler, so the snapshot and teardown run first (Node runs listeners in registration order); test asserts the snapshot line on SIGTERM |
