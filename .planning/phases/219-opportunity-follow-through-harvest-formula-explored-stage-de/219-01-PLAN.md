<interfaces>
Contract this plan defines (consumed by Plans 03/04/05):

- `writeOpportunityNode(db, { name, sessionId, lifecycle, lens, jtbd, score, extraProps })` returns `{ ok: true, node_id }` or `{ ok: false, reason }` (never throws). Node kind is `opportunity`. `review_status` is NEVER passed (column DEFAULT 'proposed' lands). `lifecycle` defaults to `'candidate'` and is a member of `candidate|qualified|explored|promoted|parked|retired`; it rides the additive JSON props bag, NEVER a DDL column (218 D-10 precedent). Idempotent UPSERT keyed on `OPPORTUNITY_NODE_ID(sessionId, name)` (the typed-entity 31-multiplier hash idiom) - re-writing the same (sessionId, name) merges props, it does not duplicate. Lifecycle advance = same call with a new lifecycle value.
- `linkOpportunityEvidence(db, { opportunity_id, target_id, edge_type, properties })` returns `{ ok, ... }`; `edge_type` restricted to `DERIVED_FROM | SUPPORTS | INFORMS` (D-04 justification: EVIDENCES is NOT in ALLOWED_EDGE_TYPES - it appears only in a READ query at insights.cjs:192; DERIVED_FROM is the Brain answer's named provenance edge and already the Breakthrough->Artifact edge; reuse-first passes, zero net-new edge types this phase). Rejection edges (REJECTED_BECAUSE) are written by Plan 04 via navigation.writeEdge directly, not through this helper.
- Banking predicate env seam: `MINDRIAN_OPPORTUNITY_BANK_PREDICATE` = `critic` (default: bank statements with `st.banked === true`) | `critic+tail` (also bank tail-flagged weak-signal candidates) | `all` (every statement with a resolved verdict). Planner decision, logged here per the phase context: start at `critic`, documented override for live tuning on ador/corepower.
</interfaces>
