### Pattern 1: Parallel CJS SessionStart Hook (95.2 Finding C)
**What:** A standalone Node.js script registered as one entry in the SessionStart array in hooks.json. It receives no stdin (we do not need to read prompt/event payload for this hook), computes its envelope, and emits a single JSON line on stdout.
**When to use:** Whenever a SessionStart concern is independent of the existing scripts/session-start Bash banner -- specifically when the new logic should isolate from the 200+-line load-bearing file.
**Example skeleton (verified pattern):**
```javascript
// Source: scripts/preflight-doctor.cjs (95.2 Finding C precedent, lines 1-117)
#!/usr/bin/env node
'use strict';

const path = require('node:path');
const fs = require('node:fs');
const os = require('node:os');

const ENVELOPE_ALLOWED = new Set([
  'decision', 'reason', 'continue', 'stopReason',
  'suppressOutput', 'systemMessage', 'hookSpecificOutput',
]);

function emitEnvelope(obj) {
  const filtered = {};
  for (const k of Object.keys(obj || {})) {
    if (ENVELOPE_ALLOWED.has(k)) filtered[k] = obj[k];
  }
  if (filtered.continue === undefined) filtered.continue = true;
  try { process.stdout.write(JSON.stringify(filtered)); } catch (_) {}
  process.exit(0);
}
function emitEmpty() { emitEnvelope({ continue: true }); }
process.on('uncaughtException', () => emitEmpty());

function main() {
  // ... read side-channel file, validate, format, emit envelope ...
  emitEnvelope({
    continue: true,
    hookSpecificOutput: {
      hookEventName: 'SessionStart',
      additionalContext: tripleContextBlock,
    },
  });
}

main();
```

## Common Pitfalls

### Pitfall 1: PostCompact / SessionStart Schema Confusion
**What goes wrong:** Plan emits envelope using PostCompact-style schema (no `hookSpecificOutput`) on a SessionStart hook, OR vice versa.
**Why it happens:** Phase 95-04 RESEARCH established that PostCompact rejects `hookSpecificOutput`. SessionStart REQUIRES it for `additionalContext`. The two events have different envelope rules.
**How to avoid:** This phase is SessionStart only. The 9th-entry hook fires at SessionStart (matcher `startup|clear|compact`), not PostCompact. Use `hookSpecificOutput.additionalContext` per D-03.
**Warning signs:** `scripts/check-hook-schema-compatibility.cjs` flags violations.

### Pitfall 2: Byte-Identity Drift Through Re-formatting
**What goes wrong:** Consumer accidentally re-renders the triple by parsing the side-channel body and reformatting (e.g. via a different formatter call).
**Why it happens:** Tempting to "clean up" the prose in `<roomDir>/.mindrian/last-post-compact.md` before re-injection.
**How to avoid:** The TRIPLE_CONTEXT block is byte-identical because both writer and reader call the SAME formatter with the SAME inputs. The consumer should call `formatTripleContext()` from scratch using `readTriple` over the active room sections (live walk), rather than parsing the side-channel body and replaying. The side-channel file's body is an audit / fallback ONLY; the re-injection re-derives from live state. This preserves Test 9 byte-identity AND covers the case where the room state advanced between WRITE and READ.
**Warning signs:** Test 9 fails. Two block emissions from same fixture inputs are non-equal.

### Pitfall 3: Cross-Room File Survives a Room Switch
**What goes wrong:** User auto-compacts in room A, switches to room B via `/mos:rooms switch`, the side-channel file persists at `<roomA>/.mindrian/last-post-compact.md`, and on the next SessionStart in room B the consumer wakes up trying to inject room A's context into room B.
**Why it happens:** Side-channel files are per-room directories but the SessionStart hook fires globally. Without explicit room-stamp validation, the consumer is blind.
**How to avoid:** D-04 stamp + validate. The frontmatter `source_room_path` MUST exactly match the active room path resolved from `.rooms/registry.json`. On mismatch: HARD SKIP + forensic-rename to `.last-post-compact-cross-room-skip-<ISO>.md` + emit `{continue: true}` (silent).
**Warning signs:** Test 6 in the rewritten suite (cross-room scenario) fails. Logs show "cross-room mismatch" stderr emission.

### Pitfall 4: Race Between PreCompact Snapshot and PostCompact Side-Channel
**What goes wrong:** PreCompact writes `pre-compact-snapshot.json` (88-08), PostCompact writes `last-post-compact.md` (95-04). Both files coexist. Consumer might read the WRONG one.
**Why it happens:** Two different files, two different write times, ambiguous freshness.
**How to avoid:** The 95.5 consumer reads ONLY `last-post-compact.md`. The PostCompact hook (scripts/post-compact:201-281) handles the snapshot-vs-live-walk logic internally. Consumer is downstream; it does not re-read the snapshot.
**Warning signs:** Test 1 in the rewritten suite confirms consumer behavior is independent of snapshot presence.

### Pitfall 5: Stale Side-Channel from Crashed Prior Session
**What goes wrong:** Prior session crashed mid-compact, side-channel file written but never consumed. Now 3 days later, a new session starts and stale context gets injected.
**Why it happens:** No cleanup on crash; only on consume.
**How to avoid:** D-02 staleness check at read time (mtime > 600s = skip + delete). Belt-and-suspenders D-04b: registry `last_switched_at` (or `last_opened`) more recent than file mtime = skip.
**Warning signs:** Test 5 in the rewritten suite (staleness skip + delete) fails. User reports "Larry restored memory from yesterday's session."

### Pitfall 6: hooks.json Re-Serialization Whitespace Drift
**What goes wrong:** A naive `JSON.stringify(data)` strips formatting; a sed/awk patch corrupts the JSON.
**Why it happens:** Edit-tool string surgery on the structurally-precise hooks.json file.
**How to avoid:** ALWAYS use `JSON.stringify(data, null, 2) + '\n'` (matches the 2-space indent + trailing newline of the existing file). Read-modify-write through Node only. This was a 95.2 B4 fix precedent.
**Warning signs:** `git diff hooks/hooks.json` shows whitespace churn beyond the inserted entry.

### Side-Channel Read + Staleness Check (D-02 step 1)

```javascript
// Reference: scripts/post-compact:84-88 (mtime>600s pattern)
//            scripts/preflight-doctor.cjs:62-69 (spawnSync with timeout)
const path = require('node:path');
const fs = require('node:fs');

function readSideChannel(roomDir) {
  const sidePath = path.join(roomDir, '.mindrian', 'last-post-compact.md');
  let stat;
  try { stat = fs.statSync(sidePath); } catch (_) { return null; }
  if (!stat || !stat.isFile()) return null;

  const ageSec = Math.floor((Date.now() - stat.mtimeMs) / 1000);
  if (ageSec > 600) {
    // D-02 staleness: skip + delete (no forensic preserve for stale -- this is
    // not a successful consume; it is a janitorial purge).
    try { fs.unlinkSync(sidePath); } catch (_) {}
    return null;
  }

  let content;
  try { content = fs.readFileSync(sidePath, 'utf8'); } catch (_) { return null; }
  return { path: sidePath, mtimeMs: stat.mtimeMs, content };
}
```

### YAML Frontmatter Parse (D-04 stamp validation)

```javascript
// Reference: lib/core/folder-memory.cjs:322-367 (parseCurrentRoomField pattern)
function parseStamp(content) {
  if (typeof content !== 'string' || content.indexOf('---') !== 0) return null;
  const rest = content.slice(content.indexOf('\n') + 1);
  const closeMatch = rest.match(/^---\s*$/m);
  if (!closeMatch) return null;
  const fmText = rest.slice(0, closeMatch.index);
  const stamp = {};
  for (const raw of fmText.split(/\r?\n/)) {
    if (!raw || /^\s*#/.test(raw)) continue;
    const m = raw.match(/^(source_room_path|source_room_slug|written_at|schema_version)\s*:\s*(.+?)\s*$/);
    if (!m) continue;
    let v = m[2].trim();
    if ((v[0] === '"' && v.endsWith('"')) || (v[0] === "'" && v.endsWith("'"))) {
      v = v.slice(1, -1);
    }
    stamp[m[1]] = v;
  }
  if (!stamp.source_room_path || !stamp.source_room_slug || !stamp.written_at) return null;
  return stamp;
}
```

### Active-Room Cross-Check (D-04 + D-04b)

```javascript
// Reference: lib/core/folder-memory.cjs:280-296 (registry lookup pattern)
const os = require('node:os');

function getActiveRoom() {
  // Canonical registry under ~/MindrianRooms/.rooms/registry.json (per
  // /home/jsagi/MindrianRooms/.rooms/registry.json verified 2026-05-06).
  const registryPath = path.join(os.homedir(), 'MindrianRooms', '.rooms', 'registry.json');
  let reg;
  try { reg = JSON.parse(fs.readFileSync(registryPath, 'utf8')); } catch (_) { return null; }
  if (!reg || !reg.active || !reg.rooms || !reg.rooms[reg.active]) return null;
  const entry = reg.rooms[reg.active];
  // path may be relative ("mindrian/mindrianOS") or absolute. Resolve against root.
  let roomPath = entry.path;
  if (!path.isAbsolute(roomPath)) {
    const root = (reg.root || '~/MindrianRooms').replace(/^~/, os.homedir());
    roomPath = path.resolve(root, roomPath);
  }
  return {
    slug: reg.active,
    path: roomPath,
    last_opened: entry.last_opened || null, // ISO string or null
  };
}

function validateRoomMatch(stamp, activeRoom) {
  if (!stamp || !activeRoom) return false;
  if (stamp.source_room_slug !== activeRoom.slug) return false;
  if (path.resolve(stamp.source_room_path) !== path.resolve(activeRoom.path)) return false;
  return true;
```

1. **Should D-04 stamp use `written_at` or rely on filesystem mtime?**
   - What we know: D-04 specifies all three frontmatter fields including `written_at`. mtime is reliable on local FS.

   - Recommendation: Use BOTH. `written_at` for the freshness comparison vs `last_opened`; mtime for the 600s staleness check. They serve different purposes.

2. **Forensic ISO suffix collision under sub-second compact events.**

### Q9: Cleanup lifecycle implementation

**Atomic rename pattern (D-02 step 2):**
```javascript
const fs = require('node:fs');
const path = require('node:path');

function forensicRenameOnConsume(sidePath, frontmatterStamp) {
  const dir = path.dirname(sidePath);
  // Use written_at from stamp when present, fall back to fresh now() to
  // ensure a unique filename even if multiple consumes within same minute.
  const baseTs = frontmatterStamp && frontmatterStamp.written_at
    ? frontmatterStamp.written_at
    : new Date().toISOString();
  // Safe-for-filesystem characters only (replace : and . to -).
  const ts = baseTs.replace(/[:.]/g, '-');
  const target = path.join(dir, '.last-post-compact-consumed-' + ts + '.md');
  try { fs.renameSync(sidePath, target); } catch (_) { /* soft-fail */ }
  return target;
}
```

**ISO format choice:** Use `frontmatter.written_at` when available (more accurate to the compact event time); fall back to `new Date().toISOString()` to guarantee uniqueness. Replace `:` and `.` to make the filename portable across filesystems. Result: `.last-post-compact-consumed-2026-05-06T22-15-30-123Z.md`.

**Same pattern for cross-room skip (D-04 mismatch):**
```javascript
function forensicRenameOnCrossRoom(sidePath) {
  const dir = path.dirname(sidePath);
  const ts = new Date().toISOString().replace(/[:.]/g, '-');
  const target = path.join(dir, '.last-post-compact-cross-room-skip-' + ts + '.md');
  try { fs.renameSync(sidePath, target); } catch (_) { /* soft-fail */ }
  return target;
}
```

**Same pattern for stale-skip (D-02 step 1):** **NO forensic preservation.** Stale files are NOT successful consumes; they are janitorial garbage. Use plain `fs.unlinkSync(sidePath)` and emit `{continue: true}` empty.

**Why three different cleanup rails?**
1. **Stale (mtime > 600s) -> unlink (no forensic)** -- the file's content is already invalid; preserving it adds clutter without audit value.
2. **Cross-room mismatch -> forensic rename to `cross-room-skip-`** -- preserves Canon Part 8 audit trail (someone needs to see this happened).
3. **Successful consume -> forensic rename to `consumed-`** -- preserves successful trail for debugging "did the consumer fire?" questions.

A future Phase 95.6 doctor sweep can prune all three forensic-renamed file types older than 7 days under one helper.

**HIGH confidence** -- pattern verified against existing scripts/post-compact:69-71 atomic rename + general fs.renameSync semantics.
