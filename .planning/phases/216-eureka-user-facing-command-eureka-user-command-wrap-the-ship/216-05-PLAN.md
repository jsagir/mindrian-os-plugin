Root cause (confirmed against live ador-ip-test data): `buildRoomNativeSubstrate` in lib/core/eureka/room-native-substrate.cjs lines 139-145 falls back to the node's schema-level `type` column for the `section` field. In ador-ip-test the 11 pre-Phase-162-vintage Section anchor nodes carry props `{name, label}` with NO `section` key, so all of them hit the row.type fallback; and because every edge is BELONGS_TO artifact-to-section, the Section anchors dominate node degree and therefore every top-ranked pair. `deriveSharedProblems()` in scripts/eureka-portfolio-report.cjs (line 217) then interpolates `a.section`/`b.section` straight into user-facing prose, and `opportunity-statement.cjs` `deriveFields()` (line 195) does the same in `novel_application`.

The genuine domain signal DOES exist on room.db rows: Artifact nodes carry `props.section` (a real slug like "business-model"), and every non-system row's `source_path` first path segment IS the section folder slug ("business-model/2026-05-26-investor-meeting-prep-eran" derives "business-model"; a vintage Section anchor's source_path is the bare slug itself). Where no signal exists, the honest 'unknown' fallback (the same default the scorer already uses at eureka-portfolio-report.cjs techFor line 202 and loadGraph line 290) is CORRECT; a mistyped "Section x Section" is not.
