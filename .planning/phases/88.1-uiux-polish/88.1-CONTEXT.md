# Phase 88.1: UI/UX Polish + MINTO Surface Plumbing

## Release target: v1.10.14

## Goal

Close the gap between what MindrianOS ships (71 commands, 9 skills, 8 agents, 10+ hooks) and the Claude Code 2.1.x polish bar for a moat-depth plugin. Three converging workstreams plus one new surface (README) the reviewer surfaced:

1. **MINTO Surface Plumbing.** Three front-facing surfaces re-invent their own summaries. Replace with reads of Phase 88's wired `governing_thought`.
2. **Description-Driven UX.** 71 command descriptions, 8 agent descriptions, README permissions block. Under-promise, not over-promise. One atomic hygiene sweep.
3. **Hook Output Primitives.** Retrofit silent hooks to use `systemMessage`, `suppressOutput`, `additionalContext`. Add two new hooks: schema validation on Data Room writes, async auto-commit.
4. **README as the 7th surface.** Three short paragraphs that set user expectations before the first session: what a Room is, permissions stance, commands-vs-Larry.

## The 7 Claude Code UX surfaces

Six Claude Code-native surfaces + one that sits upstream of every install:

| # | Surface | Leverage | This phase? |
|---|---|---|---|
| L1 | **Descriptions** (command/skill/agent `description:` fields) | HIGHEST -- compounding, zero runtime cost | YES (Workstream B) |
| L2 | Slash menu (`/` picker) | HIGH -- discovered through descriptions, feels good | YES (indirect via L1 + argument-hint) |
| L3 | **Hook output primitives** (`systemMessage`, `suppressOutput`, `additionalContext`, `updatedInput`, `permissionDecision`) | HIGH -- underused across ecosystem | YES (Workstream C) |
| L4 | Status line | MEDIUM -- surfaces live project state | YES (Workstream A) |
| L5 | ANSI escape codes in terminal | LOW -- already well-handled | NO |
| L6 | **Permissions block** (`settings.json` allow list + `--dangerously-skip-permissions` stance) | HIGH -- leverage point, NOT hygiene (reviewer correction) | YES (Workstream B) |
| L7 | **README** (paragraphs a new user reads before the first session) | HIGH -- compounding expectation-setter (reviewer addition) | YES (Workstream D) |

**L1 is promoted to the top** per reviewer: tightened descriptions work forever, across every session, for every user, with zero runtime cost. Cheapest compounding win.

**L6 is promoted from hygiene to leverage point** per reviewer: every permission prompt is friction; MindrianOS is a methodology tool where users will not tolerate stopping mid-think to approve `Bash(git status:*)` for the fourth time.

**L7 is the surface no one names** per reviewer: the README paragraph that sets expectations is load-bearing. GSD's single-paragraph permissions stance in their README is arguably bigger than their status line.

## What's IN scope

### Workstream A -- MINTO Surface Plumbing (gated by Phase 88)

- **88.1-04 Statusline MINTO segment.** Extend `scripts/context-monitor` to read active section's `MINTO.md:governing_thought`. 5s TTL cache to stay within 300ms render budget. Graceful fallback when MINTO absent.
- **88.1-05 `/mos:status` MINTO summaries.** Replace raw artifact counts with 1-line `governing_thought` per filled section. Users see what they know, not just how many artifacts exist.
- **88.1-06 SessionStart MINTO banner.** On session start, read `governing_thought` for top-3 most-recently-modified sections of the active room. Render 4-line banner: brand + version + room name + compressed focus summary.

### Workstream B -- Description-Driven UX + Permissions (parallel-safe, independent of Phase 88)

- **88.1-01 Slash command frontmatter hygiene sweep.** Audit 71 commands in `commands/`:
  - `description:` -- under 60 chars, verb-first, user vocabulary, **UNDER-promise** (reviewer addition). "Classify problem type against the PWS matrix" beats "Diagnose any problem instantly."
  - `argument-hint:` -- present when command takes args. Example `[phase-num]`, `<issue-id>`, `[--flag]`.
  - `allowed-tools:` -- granular matchers (`Bash(git diff:*)`) not broad (`Bash`).
  - `model:` -- routed appropriately (trivial to haiku, heavy to opus).
  - `disable-model-invocation:` true on destructive commands (`/mos:publish`, `/mos:export`, `/mos:rooms archive`).
  Ship as one atomic audit + N targeted edits.
  **Anti-pattern to kill:** over-promising. Every command currently whose description makes claims the command cannot fully keep is a trust debt. Revise.

- **88.1-02 README permissions.allow block + settings template.** Write the canonical block covering the 80% path. Ship BOTH the nuclear option (`--dangerously-skip-permissions` with full warning) AND the granular option (pre-approved tool matchers). Document which to use when. GSD-style.

- **88.1-10 Subagent PROACTIVELY audit.** Review 8 agents: which should be auto-delegated? Add "PROACTIVELY" to descriptions of agents that react to observed state (reviewers, verifiers, classifiers), not explicit user requests. Audit `color:` consistency and `isolation: worktree` usage.

### Workstream C -- Hook Output Primitives

- **88.1-03 `systemMessage` retrofit on existing hooks.** Audit all 10+ hooks in `hooks/hooks.json`:
  - Silent on success? Add `systemMessage` so users see the hook acted (`✓ Lint passed`, `⚡ MINTO regenerated`, `⚠ ROOM.md missing`).
  - Noisy tool output? Pair `suppressOutput: true` with `systemMessage` for clean one-line feedback.
  - Could inject useful context? Add `additionalContext` on `PostToolUse` for lint results, test output, type errors.

- **88.1-07 Frontmatter schema validation hook (NEW, arscontexta pattern).** `PostToolUse` on `Write|Edit` matching `.room-root` subtrees. Validates YAML frontmatter against per-section schema (required: `title`, `source`, `status`; optional: `governing_thought`, `confidence`). On violation: `systemMessage` advisory, does NOT block. Writes offense log to `${CLAUDE_PLUGIN_DATA}/schema-violations.jsonl`.

- **88.1-08 Async artifact auto-commit hook (NEW, arscontexta pattern).** `PostToolUse` on `Write|Edit` matching `.room-root` subtrees. Non-blocking `git commit -m "file: <artifact>"` into local `data-room-autocommit` branch. User never touches git for routine filing. Idempotent, throttled at 1 commit / 5s per path. `systemMessage: "auto-committed to data-room-autocommit"`.

- **88.1-16 Query efficiency telemetry hook (NEW -- defends the 57x claim).** `PostToolUse` on `Read|Grep|Glob` when called within `/mos:*` command context. Emits one event per query to `~/.mindrian/telemetry/query-efficiency.jsonl` with shape `{event:'query.served', command, tokens_used, tokens_naive_estimate, ratio, ts}`. Naive estimate computed from the room's total artifact token count at query time (cached per session). Ratio lets us verify the README's 57x claim holds on real sessions. `/mos:scout` extended to aggregate. Phase B deliverable: median ratio gate in release criteria (see success criterion #15). Rationale: the 57x is the moat's sharpest quantified claim; without telemetry it is marketing copy, with telemetry it is defensible architecture.

### Workstream D -- README as 7th surface (NEW, reviewer addition)

- **88.1-12 README expectation paragraphs.** Three paragraphs placed near the top of `README.md`, read by every new user before the first session:
  1. **What a Room is.** One paragraph. Living Data Room vs folder. `/mos:new-project` and `/mos:rooms` named. Cross-relationship scan surfaced as the product's nature.
  2. **Permissions stance.** One paragraph. Recommend `--dangerously-skip-permissions` with rationale (methodology tool; read-heavy on workspace; write-heavy only on `~/MindrianRooms/`). Include the granular `settings.json` block for users who prefer prompts.
  3. **Commands vs Larry.** One paragraph. When to type `/mos:find-analogies` (muscle memory, you know the move). When to talk to Larry in English (you do not yet know the framework). Both paths point at the same underlying logic. *Skills AND commands, not skills OVER commands* (reviewer correction).

### Release gate

- **88.1-11 v1.10.14 release gate.** 5-gate protocol (CHANGELOG + plugin.json + package.json + git tag + marketplace ref). BSL sweep. Chat-presence gate stays. Feynman suite green.

## Risks

### R1 -- MINTO read latency in statusline
**Mitigation:** 88.1-04 ships with mandatory 5s TTL cache. Single jq-call pattern. Graceful fallback to current emoji-only segment if cache miss is expensive.

### R2 -- Schema validation hook false positives
**Mitigation:** 88.1-07 ships ADVISORY not BLOCKING (exit 0 with systemMessage). Offense log for later review via `/mos:admin`.

### R3 -- Auto-commit conflicts
**Mitigation:** Separate branch `data-room-autocommit`. Throttle 1 commit / 5s per path.

### R4 -- Description discipline is subjective ("who picks the verb?")
**Mitigation:** 88.1-01 ships with reviewer checkpoint -- executor produces candidate descriptions; orchestrator approves/rejects in batch. Under-promise rule is the tiebreaker: when in doubt, pick the less ambitious description.

### R5 -- PROACTIVELY misuse
**Mitigation:** 88.1-10 only adds PROACTIVELY to agents whose job is observation+reaction.

### R6 -- Chat-presence gate regression
**Mitigation:** 88.1-11 re-asserts chat-panel grep as acceptance criterion.

### R7 (NEW, reviewer) -- "Skills beat commands" absolutism seeps in via description sweep
**Mitigation:** 88.1-01 reviewer pass explicitly checks for command descriptions that position commands as "legacy" or "fallback." Every command description must stand on its own merit. Commands are keyboard shortcuts for power users, full stop.

## Success criteria (what must be TRUE at v1.10.14 tag)

1. Every command in `commands/*.md` has `description` <= 60 chars, verb-first, and does NOT over-promise
2. Every command that accepts arguments has `argument-hint:` set
3. All 10+ hooks emit `systemMessage` output where appropriate (zero silent-on-success hooks that could announce)
4. README contains a `permissions.allow` block AND three expectation paragraphs (Room / Permissions / Commands-vs-Larry)
5. `scripts/context-monitor` shows a new statusline segment for active-section `governing_thought`
6. `/mos:status` output uses `governing_thought` per filled section (not raw counts)
7. SessionStart emits a 4-line banner with active-room MINTO summary
8. New `PostToolUse` frontmatter validation hook active on `.room-root` subtrees; advisory, logs violations
9. New `PostToolUse` auto-commit hook active on `.room-root` subtrees; throttled 1/5s; isolated branch
10. Subagent audit: at least 3 agents that should auto-delegate carry "PROACTIVELY"; color scheme consistent
11. `node lib/memory/run-feynman-tests.cjs` exits 0 with count >= 28
12. Cascade-e2e baseline exact match preserved
13. 5-gate release: CHANGELOG [1.10.14], plugin.json 1.10.14, package.json 1.10.14, git tag v1.10.14, marketplace.json ref v1.10.14
14. **NO interactive primitives shipped in this release.** AskUserQuestion rollout is Phase 88.2.
15. **57x claim defensibility gate.** Query efficiency telemetry (88.1-16) collects >= 50 real query events during a validation window. Median `tokens_used / tokens_naive_estimate` ratio is >= 40x. Below 40x => the release ships with README copy updated to "up to 57x" OR the alignment-audit leakers (88.1.5) that pull down the median are fixed before v1.10.14 tag. Rationale: the 57x is the product's sharpest quantified claim; shipping it unmeasured is trust debt. Either measure it and hold it, or retune the copy. No third option.
