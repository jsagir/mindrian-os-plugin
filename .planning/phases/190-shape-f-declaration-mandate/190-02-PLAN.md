<RULES>
- CJS only, node:fs + node:path only; zero new npm dependencies (Canon Part 8: zero Brain, zero network).
- Idempotent: running the generator twice in a row produces a byte-identical second run (no diff on re-run).
- Non-destructive: every other frontmatter key, every body line, and file byte order outside the frontmatter
  block is preserved exactly. The generator ONLY inserts or updates hitl_shape / hitl_why / hitl_stages keys.
  A skill's existing `connector:` nested block (its own `surface:`, `excluded:`, `reason:`, etc.) is untouched;
  the new hitl_shape/hitl_stages keys are ROOT-level siblings of `connector:`, never merged into it.
- Data-driven, not surface-class-driven: the generator iterates data/hitl-shape-backfill.json's keys and
  patches whichever file each key names. It does NOT contain a hardcoded "if under skills/, do X" branch that
  differs from "if under commands/, do Y" beyond the ONE structural difference Task 1 documents (skills
  commonly have no `body_shape:` line, so the insertion falls through to the "append at end of frontmatter"
  path already defined for that case -- no new code path, just the existing fallback firing more often).
- No em-dashes anywhere in generated content.
- This plan does NOT write the enforcement gate (scripts/check-shape-declaration.cjs); that is Plan 03,
  running in parallel this same wave against synthetic fixtures, not against this plan's real-file output.
</RULES>

## Trust Boundaries

| generator -> shipped surface files | a bulk, mechanical rewrite of 125 files is higher blast radius than a single-file edit; a bug in the frontmatter patcher could corrupt every command/skill at once |
