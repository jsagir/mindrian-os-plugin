<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| shipped surface frontmatter -> the gate | a surface author could hand-write a plausible-looking but wrong hitl_shape; the gate is the only check on that claim |
| PLAN.md frontmatter -> the gate | a future plan could add a command or skill without declaring its shape, silently regressing R16 the way 143.x/144.1 regressed the born-wired gate |
| a skill's connector.excluded claim -> the gate | a skill could falsely claim connector.excluded:true to dodge the HITL mandate while actually reaching a fork; this is the SAME trust boundary Canon Part 11 R1 already accepts for CIRS wiring, not a new one this plan introduces |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-190-03-01 | Spoofing | a command falsely declares a "safe" shape (e.g. F.1) to hide an actual independent-fan-out F.8 basket | mitigate | the f-selector-ranker-contradiction predicate catches the one concretely provable case (ranker consumers must include F.7); broader semantic drift is a named residual, flagged for a future doctor --drift pass |
| T-190-03-02 | Repudiation | a plan adds a command or skill surface without declaring hitl_shape at all | mitigate | --check-plan fails closed when cirs_relationship.surfaces_added is non-empty and hitl_declarations is missing/incomplete |
| T-190-03-03 | Spoofing | a skill sets connector.excluded:true to dodge the mandate despite having a real fork | accept | identical residual risk already accepted under Canon Part 11 R1 for CIRS wiring; not a new attack surface this plan creates, and the reason field is human-authored and reviewable in code review |
| T-190-03-SC | Tampering | npm/pip/cargo installs | accept | zero package installs; node:fs + node:path + node:child_process only |
