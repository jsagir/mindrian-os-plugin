    - generatePersonas rejects rooms with fewer than 2 populated sections
    - listPersonas(roomDir) returns array of {hat, hat_label, domain, filename} parsed from frontmatter
    - invokePersona(roomDir, hatColor, artifactPath?) returns {persona, artifact, hat} content
    - analyzeAllPerspectives(roomDir, artifactPath) returns all 6 perspectives keyed by hat color
    - Every generated file includes disclaimer in frontmatter and body footer
  </behavior>
  <action>
    Create `lib/core/persona-ops.cjs` following the opportunity-ops.cjs pattern exactly:

    1. Header: 'use strict', require fs/path, require discoverSections from section-registry, require safeReadFile from index.cjs
    2. Import parseFrontmatter from opportunity-ops.cjs (reuse, don't duplicate)
    3. Define HAT_DEFINITIONS constant (6 hats with color, label, perspective, focus_areas, tension_hat) -- sourced from hat-perspectives.md reference but hardcoded for zero-IO performance
    4. Define DISCLAIMER constant: "This is a perspective lens generated from your room data. It is NOT professional advice. Validate all insights with qualified professionals."

    5. `extractDomainSignals(roomDir)`:
       - Read STATE.md for venture name and stage
       - Use discoverSections() to find all sections
       - For each section dir, count .md files (excluding STATE.md) to determine populated sections
       - Extract primaryDomain from problem-definition first artifact (slugify venture name or extract key terms)
       - Return { primaryDomain, ventureStage, populatedSections: [...names], sectionCount, ventureName }

    6. `generatePersonas(roomDir)`:
       - Call extractDomainSignals; reject if sectionCount < 2 (return { error: '...' })
       - mkdir personas/ (recursive: true)
       - For each hat in HAT_DEFINITIONS:
         - Build YAML frontmatter with hat, hat_label, domain, perspective, generated_from (populated section names), generated_date (ISO date), room_hash (crypto.createHash('md5').update(stateContent).digest('hex').slice(0,7)), disclaimer
         - Build body: "# {Color} Hat -- {Label} Perspective\n\n## Who I Am\n\n{2-3 sentences}\n\n## What I See In Your Room\n\n{subsection per populated section with section name + brief signal}\n\n## My Questions For You\n\n{3 numbered questions tailored to hat perspective}\n\n## Where I Disagree With Other Hats\n\n{tension points}\n\n---\n*{disclaimer} Generated from room state on {date}.*"
         - Write to `personas/{color}-{domain}.md`
       - Return { generated: [...filenames], domain, sections_used }

    7. `listPersonas(roomDir)`:
       - Read personas/ dir, filter .md files (exclude STATE.md)
       - For each file, parseFrontmatter and extract hat, hat_label, domain, disclaimer
       - Return array of { hat, hat_label, domain, filename, disclaimer }

    8. `invokePersona(roomDir, hatColor, artifactPath)`:
       - Find file starting with `{hatColor}-` in personas/
       - If not found, return { error: 'No {hatColor} hat persona...' }
       - Read persona content
       - If artifactPath provided, read artifact content
       - Return { persona: content, artifact: artifactContent || null, hat: hatColor }

    9. `analyzeAllPerspectives(roomDir, artifactPath)`:
       - For each hat color, call invokePersona
       - Return { perspectives: { white: {...}, red: {...}, ... }, artifact: artifactPath }

    10. module.exports = { generatePersonas, listPersonas, invokePersona, analyzeAllPerspectives, extractDomainSignals }

    Key constraints:
    - Zero npm dependencies (pure Node.js built-ins + existing core modules)
    - Reuse parseFrontmatter from opportunity-ops.cjs (require it, don't copy)
    - Hat-color naming only (never human names) per PERS-04
    - Persona body text should reference actual section names from the room, not generic placeholders
    - Use crypto.createHash for room_hash (Node.js built-in)
  </action>
