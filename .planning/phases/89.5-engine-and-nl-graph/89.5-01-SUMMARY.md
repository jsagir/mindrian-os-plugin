## Decisions Made

(See `key-decisions` frontmatter for the full annotated list.) Most consequential:

1. **Bucket vocabulary is 6, not 5** -- 1 `unknown-bucket` safe-default sentinel + 5 substantive TAM/SAM proxies. The plan text said "5-bucket"; the implementation needed an explicit unknown-bucket entry to satisfy the missing-breakthrough_score edge case (T6) deterministically. Future bucket vocabulary expansion requires a 89.5-01-N revision (canon-amend discipline preserved).
2. **Both-must-satisfy bucket selection** -- top-down highest-bucket wins, but both signals AND score must clear each bucket's threshold pair. Prevents single-dimension inflation.
3. **Token-fill expanded to 3 placeholders** -- `[BRIDGE]/[SOURCE]/[TARGET]`, not just `[bridge_concept]`. Rationale: a value-prop string that names only one side of the cross-domain bridge is incomplete; surfacing both source and target makes the assessment legible at the Decision Gate.

## Deviations from Plan

**1. [Rule 2 - Missing Critical] Bucket vocabulary expanded from 5 to 6 (added explicit `unknown-bucket` safe-default)**

- **Found during:** Task 2 (GREEN implementation)
- **Issue:** Plan §6 specified a "frozen 5-bucket table" but Task 1 RED's T6 (missing breakthrough_score -> low-bucket safe default) requires a deterministic non-throwing path for the missing-score case. A bucket vocabulary of 5 substantive buckets + an unkeyed default would either (a) drift to one of the 5 (semantically wrong) or (b) require a sentinel `null` in the bucket table (defeats the frozen-table contract).
- **Fix:** Added `unknown-bucket` as the 6th frozen entry; bucketize() returns `unknown-bucket` when `score === null` (the explicit-missing path discriminated via `Object.prototype.hasOwnProperty.call`).
- **Files modified:** lib/core/rs-commercial-assessor.cjs
- **Verification:** T6 GREEN; deterministic invariance T3 GREEN.
- **Committed in:** f918652 (Task 2 GREEN)

**2. [Rule 1 - Bug-fix-of-spec] Token vocabulary expanded from `[bridge_concept]` to `[BRIDGE]/[SOURCE]/[TARGET]`**

- **Found during:** Task 1 RED design
- **Issue:** Plan §8 specified `buildValueProposition` filling `[bridge_concept]` from `rs_discovery.bridge_concept`. T8 (classification table coverage: 3 distinct template stems) requires that the rendered output for the three classifications differ in their first 12 characters. With only the bridge_concept token filled, all three classifications would still render identical leading words ("Apply [bridge]", "Implement [bridge]", "Bridge [A]") -- but `_fallback`'s leading word "Cross-domain" would differ from `structural_transfer`'s "Apply" by 4 characters, not 12. The 12-char-distinct invariant requires source + target tokens too (so the rendered string surfaces both sides of the cross-domain pair).
- **Fix:** Expanded token vocabulary to `[BRIDGE]/[SOURCE]/[TARGET]` (filled from `rs_discovery.bridge_concept` / `query_concept` / `doc_concept` respectively, with safe-default fallbacks). Kept the leading-word-distinct stem design rule (Apply / Implement / Bridge / Cross-domain).
- **Files modified:** lib/core/rs-commercial-assessor.cjs, lib/memory/test-rs-commercial-assessor.cjs
- **Verification:** T8 GREEN with 12-char stem distinctness; A1 sweep T12 GREEN (no FORBIDDEN_PATTERNS leak via the expanded token-fill).
- **Committed in:** 60f4018 (Task 1 RED), f918652 (Task 2 GREEN).
