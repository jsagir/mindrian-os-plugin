## Audit-Site Enumeration (Canon Part 8 defense-in-depth)

The translate() entry point + buildBrainQueryFromNL chokepoint together define **4 independent tripwires** defending the Brain boundary against arbitrary user NL:

| Seam | Location | Audit primitive | Catches |
| --- | --- | --- | --- |
| **A** | translate() first line | auditQueryObject({nl_query, opts}, 'rs-nl-to-query-input') | Forbidden patterns nested in opts (e.g., a leaked meeting_transcript / financial figure / decision_log field). Throws BEFORE buildBrainQueryFromNL runs. |

| **2** | buildBrainQueryFromNL last line | auditQueryObject(brainQuery, 'rs-nl-to-query-brain-output') | Forbidden patterns that snuck through the entity extractor (e.g., extractor regression bound a multi-word phrase containing forbidden bytes). Throws BEFORE return. |
| **C** | translate() before return | auditQueryObject(bundle, 'rs-nl-to-query-output') | Forbidden patterns in the returned bundle that snuck past SEAM A + the chokepoint (last line of defense before the orchestrator sees the bundle). |

## Decisions Made

(See `key-decisions` frontmatter for the full annotated list.) Most consequential:

1. **SQL placeholder switched to ? (SQLite) from $1 (PostgreSQL)** -- the FORBIDDEN_PATTERNS currency-magnitude regex `\$[0-9][\d,.]*[KMB]?\b` matches `$1` as if it were a `$1` currency token. Switching to `?` placeholders sidesteps the collision entirely without affecting parameterized-binding semantics. Cypher is unaffected (named placeholders use $word form which the pattern can't match).
2. **Brain-query OMISSION as the safe default** -- when intent unrecognized OR intent.brain_template is null OR extractor returned empty scalar, brain_query is set to null (Brain query OMITTED). The translator is permissive in form (accept arbitrary NL) but conservative in egress (no Brain RPC unless intent matches and scalar audits pass).
3. **Frozen ALLOW_LIST_INTENTS with 5-field shape** -- {intent_id, keyword_patterns, brain_template, sql_template, cypher_template, params_extractor}. Each entry independently Object.freeze'd. Expanding the intent vocabulary requires a Plan-N revision (canon-amend discipline preserved).

## Deviations from Plan

**1. [Rule 1 - Bug-fix-of-spec] SQL placeholder syntax switched from $1/$N to ?/SQLite-style**

- **Found during:** Task 2 (GREEN -- T2/T5/T9/T14 failing on SEAM C output audit)
- **Issue:** Plan §6 specified `'$1'-style placeholders` for SQL templates. The FORBIDDEN_PATTERNS currency-magnitude regex `\$[0-9][\d,.]*[KMB]?\b` from `rs-egress-prompts.cjs` (re-exported byte-for-byte from `cross-room-aggregator.cjs`) matches `$1` as if it were a `$1` currency token. Every translate() output containing the SQL template `"... WHERE room_slug = $1 ..."` was failing SEAM C audit with `matched_pattern: "\\$[0-9][\\d,.]*[KMB]?\\b"`. The plan's spec inadvertently created a Canon Part 8 false-positive trap.
- **Fix:** Switched all SQL templates in ALLOW_LIST_INTENTS from `$1` to `?` (SQLite-style placeholders). Both syntaxes are valid; `?` sidesteps the collision entirely. Test T2 explicitly accepts either `$1` OR `?` so the test contract is preserved. Cypher placeholders (named `$word` form) are unaffected because the FORBIDDEN_PATTERN requires a digit immediately after `$`, and `$word` has a letter.
- **Files modified:** lib/core/rs-nl-to-query.cjs
- **Verification:** T2 + T5 + T9 + T14 GREEN after the switch; T15 chokepoint exclusivity GREEN; T16 A1 sweep GREEN.
