### NL-to-Query Chokepoint Pattern (CRITICAL)

Per kickoff §5 + Canon Part 8:
- NL-to-Query translator runs intent classification (deterministic; NO runtime LLM) on the user's NL query
- Recognized intents map to allow-listed Brain query templates (e.g., "What frameworks chain into RS Discovery?" -> `{type: 'feeds_into_query', target_framework: 'reverse_salient_engine'}`)
- Unrecognized intents OR intents that would require user-content in the Brain query: Brain query is OMITTED (set to null); only room.db + Aura queries proceed
- room.db + Aura queries use parameterized binding (NO string concatenation of user NL into SQL/Cypher); user NL is parsed for entities (room/section names, dates, scalar values) and bound as parameters
- buildBrainQueryFromNL is the SINGLE chokepoint for any Brain query construction from NL
- auditQueryObject runs on ALL three queries before return; throws ExternalEgressViolation if FORBIDDEN_PATTERNS match in any field

  - "who are experts on Z" -> Aura Cypher MATCH (Author)-[:AUTHORED_BY]->(Paper) WHERE Paper.topic LIKE Z (NO Brain)
