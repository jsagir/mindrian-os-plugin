# Phase 150.9 - Validation Strategy

> Per-phase validation contract for feedback sampling during execution.
> Derived from 150.9-RESEARCH.md "## Validation Architecture". Drift classes are
> verified by driving production-shaped input through doctor (the FIX-11 lesson:
> acceptance must drive the real entry path, never a hand-shaped fixture).

---

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | node CJS test files (`tests/test-*.cjs`) + bash phase gate (`tests/run-all-150.9.sh`), matching the shipped doctor-class test idiom |
| **Config file** | none - plain node + bash, no test runner config |
| **Quick run command** | `node tests/test-doctor-class-p.cjs && node tests/test-doctor-class-q.cjs` |
| **Full suite command** | `bash tests/run-all-150.9.sh` |
| **Estimated runtime** | ~5-15 seconds (shells out to gsd-health once for Class Q) |

---

## Sampling Rate

- **After every task commit:** Run the quick command for the class touched
- **After every plan wave:** Run `bash tests/run-all-150.9.sh`
- **Before `/gsd-verify-work`:** Full suite must be green
- **Max feedback latency:** 15 seconds
