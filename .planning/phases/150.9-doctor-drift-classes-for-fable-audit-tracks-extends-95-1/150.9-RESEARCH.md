## Summary

This phase is ~90% wiring, exactly as the CONTEXT and Canon Part 7 assert. The host engine (`scripts/doctor.cjs`, 4617 lines) already ships a mature lettered-class roster A-N with a settled class contract, a `classFlagsActive` graceful-degradation invariant, a 0/1/2/3/4 exit-code chain, and a `--json`/human dual renderer. Letters O, P, Q, R are unused and unreserved anywhere in the codebase or `commands/doctor.md` (verified by grep). P and Q are safe.

The two checkers Class P must wrap are BOTH `require()`-able, not CLI-only: `check-skill-vs-code-drift.cjs` exports `{ check, shapesFromSkill, shapesFromCode }` and `check()` returns a structured `{valid, missing_in_skill, missing_in_code, missing_crossrefs, missing_rules_files}` object with NO `process.exit` side-effect. `check-first-touch-drift.cjs` is the harder case: it is CLI-only (no `module.exports`, calls `process.exit` directly in `main()`), so Class P must either shell out to it OR refactor it to export a `check()` (the Part-7-cleaner option; see Don't Hand-Roll). Both checkers have zero network surface (grep `fetch|http|curl|brain|tavily` returns 0).

Class Q's source is `gsd-tools validate health --raw` (the CLI that `/gsd-health` wraps). Its JSON shape was captured by a live run on this repo: a top-level `{status, errors[], warnings[], info[], repairable_count}` where every issue is `{code, message, fix, repairable}`. W007 ("Phase NN exists on disk but not in ROADMAP.md") lives in `warnings[]`; I001 ("…-PLAN.md has no SUMMARY.md") lives in `info[]`. The accepted D-02 coupling is to these two record shapes plus the top-level `status` enum.

**Primary recommendation:** Add `--drift` as a NEW class-flag that activates Class P (report-only, wraps both checkers via `require()`) + Class Q (shell-out to `gsd-tools validate health --raw`, parse W007/I001) + the DRIFT.md writer. Register `--drift` into the `classFlagsActive` OR-chain so the run honors the graceful-degradation exit-0 invariant (preserving the marketplace-cache-drift-deadlock carve-out automatically, since that carve-out lives in Class A's `checkInstallVersion()` which `--drift` never touches). Heal-where-safe per D-03: DRIFT.md auto-writes and missing SUMMARYs auto-stub under `--fix`; Class P never edits prose.

### Pattern 1: The lettered-class contract (the host pattern P/Q must conform to)
**What:** Each class is a function returning a plain object `{class:'<letter>', status, ...class-specific fields}`. `status` is from an informal enum observed across A-N: `'ok' | 'warn' | 'error' | 'skip'` (plus class-specific verbs like `'DEPRECATED_USAGE'`). The result lands in `report.checks['<kebab-name>']`. The class fn NEVER calls `process.exit` -- exit is owned solely by `_finalizeAndExit`.
**When to use:** Every new class.
**Example (Class L, the closest analog -- pure LOCAL scan, exit-0 invariant):**
```javascript
// Source: scripts/doctor.cjs:3289 (checkDeprecatedUsage return)
return {
  class: 'L',
  status: status,            // 'OK' | 'DEPRECATED_USAGE'
  action: action,
  deprecated_uses: deprecated_uses,
  scanned_files: scanned,
  transcripts_dir: transcriptsDir,
};
```

### Pattern 2: Class dispatch + soft-fail wrapper
**What:** In `main()`, gate each class behind its flag, wrap in try/catch, record an `error`-status finding on throw (never crash doctor).
**Example (Class K dispatch -- the template for P/Q):**
```javascript
// Source: scripts/doctor.cjs:4288
if (flags.staleFirstTouch) {
  try {
    const { scanForStaleCopy } = require(path.join(__dirname, '..', 'lib', 'core', 'stale-copy-scanner.cjs'));
    const result = scanForStaleCopy();
    report.checks['stale-first-touch-copy'] = { class: 'K', status: result.valid ? 'ok' : 'warn', /* ... */ };
  } catch (err) {
    report.checks['stale-first-touch-copy'] = { class: 'K', status: 'error', detail: err.message, violations: [] };
  }
}
```

### Pattern 3: Subprocess shell-out (the Class Q model)
**What:** Use `cp.spawnSync('node', [absolutePathToTool, ...args], {encoding:'utf8'})`, then `JSON.parse(stdout)`. Class M already does this for a sibling tool.
**Example:**
```javascript
// Source: scripts/doctor.cjs:2987 (class M brain-smoke subprocess)
const r = cp.spawnSync('node', [doctorPath, '--brain-smoke', '--json'], { /* opts */ });
```
For Class Q the target is `gsd-tools.cjs validate health --raw`. The tool-locator idiom (handle multiple install topologies) is in `~/.claude/gsd-core/workflows/health.md:52` (the `_GSD_TOOLS` resolver) -- Class Q should mirror that resolution order rather than hardcode `~/.claude/gsd-core/bin/gsd-tools.cjs`.

### Anti-Patterns to Avoid
- **Reimplementing the ROADMAP/SUMMARY scan in doctor.cjs.** D-02 is explicit: shell out to gsd-health. Reimplementing duplicates GSD's own logic and re-introduces the parser bug (`118-30` mis-parse, W006) that gsd-health already owns.
- **Letting Class P auto-edit prose.** D-03: prose-vs-code is REPORT-ONLY. Class P status is `warn`, never a `--fix` that rewrites a doc.
- **Calling `process.exit` inside a class fn.** Breaks the `classFlagsActive` exit-0 invariant and the deadlock carve-out. Exit is `_finalizeAndExit`-only.
- **Hardcoding the gsd-tools path.** Multiple install topologies exist; use the resolver order.

## Common Pitfalls

### Pitfall 1: check-first-touch-drift.cjs is CLI-only and self-exits
**What goes wrong:** A naive `require('check-first-touch-drift.cjs')` RUNS `main()` (it calls `main()` unconditionally at module top-level, line 220) and `process.exit`s -- killing doctor.
**Why it happens:** Unlike check-skill-vs-code-drift.cjs, it has no `if (require.main === module)` guard and no `module.exports`.
**How to avoid:** Either (a) minimal refactor: wrap `main()` in `if (require.main === module)` and add `module.exports = { check }` exposing the pattern-scan as a pure fn (Part-7-clean, recommended), or (b) shell out via `spawnSync` and parse stdout `DRIFT:` lines + exit code (1 = drift, 0 = clean). Option (a) is preferred for testability and to match check-skill-vs-code-drift.cjs's already-clean shape.

### Pitfall 2: gsd-health JSON shape drift (the accepted D-02 coupling)
**What goes wrong:** A future gsd-core release renames W007/I001, moves I001 from `info[]` to `warnings[]`, or changes the `{code, message, fix, repairable}` record shape; Class Q silently parses nothing and reports a false "clean."
**Why it happens:** Class Q depends on an external tool's output contract it does not own.
**How to avoid:** (1) Pin the contract in a fixture (`tests/test-doctor-class-q.cjs` injects a canned health JSON and asserts the parse). (2) Class Q should assert the top-level shape (`typeof json.warnings === 'object' && Array.isArray(json.info)`) and emit a `status:'error'` finding ("gsd-health output shape unrecognized -- W007/I001 parse skipped") rather than a false "clean" when the shape is unexpected. (3) Treat an empty `warnings[]`/`info[]` from a `status:'broken'` or `status:'error'` health run as "could not determine," not "no drift."

### Pitfall 3: gsd-health is CWD-sensitive and home-directory-guarded
**What goes wrong:** Run from the wrong CWD, gsd-health returns `E001 .planning/ directory not found` (or `E010` if CWD === home), and Class Q sees zero warnings -> false clean.
**Why it happens:** `cmdValidateHealth` resolves `.planning/` relative to CWD and hard-refuses CWD === homedir (verified: a sandbox-CWD run returned E001; a repo-root run returned the full 183-warning report).
**How to avoid:** Class Q must spawn gsd-health with `cwd` set to the repo root (resolve via the workspace, not `process.cwd()`), and treat a `status` of `broken`/`error` as "indeterminate," surfacing it rather than swallowing it.

### Pitfall 4: Accidentally arming the default roster (violates D-04)
**What goes wrong:** Registering `--drift` logic under the `flags.all || flags.fix || !classFlagsActive` trigger (the way the accumulative-engine and Class N run on a BARE doctor) would make P/Q fire every session.
**Why it happens:** Copy-pasting the Class N / accumulative-engine dispatch guard instead of the Class K/L flag guard.
**How to avoid:** D-04 is opt-in only. Gate P/Q/DRIFT.md strictly behind `if (flags.drift)`, NEVER behind `!classFlagsActive`. Add `flags.drift` to the `classFlagsActive` OR-chain so the run itself stays exit-0.

## DRIFT.md Schema (proposed -- Claude's discretion per CONTEXT)

Designed for machine-diffability so the NEXT audit DIFFs instead of rediscovers (FIX-13 intent). YAML frontmatter holds queryable scalars; the body holds one stable-id row per finding so a `git diff` of two audits is legible.

### Root index: `.planning/DRIFT.md`
```markdown
---
kind: drift-baseline-index
audit_date: 2026-06-11
auditor: doctor --drift (Class P + Q)
milestone: v1.13.1
status: degraded            # mirrors gsd-health top-level status
counts:
  prose_vs_code: { high: 3, med: 10, low: 3 }   # Class P
  gsd_record:    { w007: 23, i001: 30 }         # Class Q

| finding_id | track | severity | status | source_class | detail | per_folder |
|------------|-------|----------|--------|--------------|--------|------------|
| W007-150.7 | gsd_record | warn | open | Q | Phase 150.7 on disk, absent from ROADMAP.md | .planning/phases/150.7/DRIFT.md |
| I001-103-00 | gsd_record | info | open | Q | 103-00-PLAN.md has no SUMMARY.md | .planning/phases/103/DRIFT.md |
| P-skill-F.6 | prose_vs_code | high | open | P | SKILL.md missing shape F.6 shipped in code | (report-only) |
```

### Per-folder detail: `.planning/phases/<NN>/DRIFT.md`
```markdown
---
kind: drift-baseline
phase: 103
audit_date: 2026-06-11
status: open
finding_ids: [I001-103-00, I001-103-01]
---

# Phase 103 drift

| finding_id | severity | status | detail | first_seen | last_seen |
|------------|----------|--------|--------|------------|-----------|
| I001-103-00 | info | open | 103-00-PLAN.md has no SUMMARY.md | 2026-06-11 | 2026-06-13 |
```

**Diff-stability rules (the FIX-13 contract):**
- `finding_id` is a STABLE deterministic key (`<code>-<phase>-<plan>` for Q; `P-<surface>-<token>` for P), so a finding that persists across audits keeps its id and `git diff` shows only `status`/`last_seen` deltas.
- `status` lifecycle: `open -> closed` (closed rows stay in the file with a `closed_date` so history is preserved, mirroring CLAUDE.md decision 14 "regression with history preservation").
- `first_seen` is set once and never rewritten; `last_seen` bumps each audit. Re-running `--drift` on an unchanged repo produces a byte-identical body except `last_seen` (which a `--no-touch` mode can suppress for true idempotence in tests).
- Per-folder files carry ONLY that phase's findings; the root index carries the rolled-up scalars + a pointer column. Two granularities, one source pass (D-01).
