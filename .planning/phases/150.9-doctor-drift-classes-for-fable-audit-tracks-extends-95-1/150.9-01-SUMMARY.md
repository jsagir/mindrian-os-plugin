## Decisions Made

- **first_seen ledger as HTML comments.** The diff-stability contract needs set-once first_seen to survive re-audits, but I did not want a frontmatter list that churns the body diff. Persisted first_seen as one `<!-- gsd:drift first_seen <id>=<date> -->` comment per finding inside each per-folder file, read back on the next write. This keeps the human-visible body table clean and the diff legible.
- **Traversal = refuse the write, keep the finding.** A finding whose phase is a traversal token is skipped for the per-folder write (never escapes .planning/) but its row still renders in the root index with a `(report-only)` pointer. The data is not lost; only the unsafe filesystem write is refused.
- **Phase-999 synthetic fixtures.** Per the plan, the test finding set is obviously-synthetic (phase 999, finding_id W007-999-test) so a stray scratch file can never be mistaken for a real audit baseline.
