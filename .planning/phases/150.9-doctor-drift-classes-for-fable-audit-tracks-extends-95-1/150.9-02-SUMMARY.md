## Decisions Made

- **Subprocess, not refactor, for the first-touch checker.** RESEARCH Open Question 1 left the choice between (a) refactoring `check-first-touch-drift.cjs` to export `check()` or (b) shelling out. Chose (b): Class P `spawnSync`s it and reads its exit code (1=drift) + `DRIFT:` lines. This avoids touching a shipped CLI-only checker (zero behavior delta to its CLI path) and structurally guarantees the Pitfall-1 self-exit can never kill doctor. `check-skill-vs-code-drift.cjs` (already require-clean) stays a `require`.
- **Hermetic Class Q injection via env override.** `resolveGsdTools()` checks `MINDRIAN_DOCTOR_GSD_TOOLS` FIRST, then mirrors the `workflows/health.md:52` `_GSD_TOOLS` resolver order (RUNTIME_DIR/repo-root gsd-core, then `$HOME/.claude/gsd-core/bin`). Tests point the override at a tiny `fake-gsd-tools.cjs` that prints canned health JSON, so the D-02 shape coupling is pinned in a fixture (Pitfall 2 guard) with no dependency on the live gsd-core install.
- **Report-only prose in the heal arm.** The heal arm records Class P findings into the root DRIFT.md index with `per_folder:false`, which the Plan-01 writer renders as a `(report-only)` pointer. Prose drift is thus documented in the baseline (so the next audit diffs it) but never auto-edited -- the exact D-03 mechanical/judgment-call split.
