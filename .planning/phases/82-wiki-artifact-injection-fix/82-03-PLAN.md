# Plan 82-03: collectSectionMinto helper + summary upgrade

## Goal

Add a new helper `collectSectionMinto(sectionPath)` to `scripts/generate-presentation.cjs` that reads `<sectionPath>/MINTO.md` if present, parses the frontmatter, and returns the `governing_thought` field or `null` if the file is absent, unreadable, or has no governing_thought. Wire the helper into `collectSections` so that each section's `summary` field upgrades to the governing_thought when it is non-null. When `collectSectionMinto` returns null, the existing title-extraction fallback from the current `collectSections` logic (the one that reads the first artifact's h1) is preserved unchanged. This is a graceful upgrade that leverages the v1.10.2 Feynman-MINTO per-section MINTO.md infrastructure for free and stays fully backwards-compatible with pre-81 rooms that have no per-section MINTO files. The goal is testable: a fixture section with a MINTO.md containing `governing_thought: "the test thought"` produces `sec.summary === "the test thought"`; the same section without a MINTO.md produces the current title-extraction summary unchanged.

## Task Breakdown

1. **Confirm `parseFrontmatter` exists and handles the governing_thought case.** Grep `scripts/generate-presentation.cjs` for `parseFrontmatter`. The existing helper at line 62 parses flat `key: value` pairs with optional quotes. Test it mentally against a MINTO.md fixture: `governing_thought: "the test thought"` parses to `fm.governing_thought === "the test thought"`. No new helper needed. Acceptance: existing `parseFrontmatter` is reused without modification.

2. **Add `collectSectionMinto(sectionPath)` helper.** Logic:
   ```
   function collectSectionMinto(sectionPath) {
     const mintoPath = path.join(sectionPath, 'MINTO.md');
     const content = safeRead(mintoPath);
     if (!content) return null;
     const fm = parseFrontmatter(content);
     const gt = (fm.governing_thought || '').trim();
     return gt.length > 0 ? gt : null;
   }
   ```
   Place it immediately after `collectMinto` at line 193. Do not log on the absent path; absence is the expected case for pre-81 rooms. Acceptance: function exists and returns null for a section without MINTO.md, returns the governing_thought string for a section with one.

3. **Wire the helper into `collectSections`.** At the point in the section loop where `summary` is computed, change the logic to:
   ```
   let summary = '';
   const sectionMinto = collectSectionMinto(sectionDir);
   if (sectionMinto) {
     summary = sectionMinto;
   } else if (mdFilePaths.length > 0) {
     const firstContent = safeRead(mdFilePaths[0]);
     if (firstContent) summary = extractTitle(firstContent, path.basename(mdFilePaths[0]));
   }
   ```
   Acceptance: a fixture section with MINTO.md governing_thought produces `sec.summary === governing_thought`; the same section without MINTO.md produces the extracted title from the first artifact.

4. **Preserve the interaction with plan 82-02's SKIP_FILES alignment.** Because MINTO.md is in SYSTEM_FILES (and therefore SKIP_FILES), `findMdFiles` will NOT return MINTO.md as a content artifact. This means `collectSectionMinto` is the ONLY path that reads MINTO.md in the presentation generator, which is exactly the design intent. No double-injection. Acceptance: grep the generator for `'MINTO.md'` and confirm the only read sites are `collectMinto` (room-level) and `collectSectionMinto` (section-level).

5. **Handle the case where the first artifact has no h1.** The existing `extractTitle` helper falls back to `path.basename(filePath, '.md')`. The summary field in that case becomes the filename, which matches current pre-82 behavior. This is the documented "no breaking change" path. Acceptance: a section whose first artifact has no h1 and no frontmatter title produces `sec.summary === <basename>` when MINTO.md is also absent.

## Risks

- **Frontmatter parser does not handle multi-line governing_thought values.** Mitigation: the Feynman-MINTO generator in v1.10.2 writes governing_thought as a single-line quoted string. Confirmed by reading `scripts/vault-section-minto-generator.cjs` before implementation. If a future generator writes multi-line YAML, we revisit.
- **A section with a MINTO.md whose frontmatter uses a YAML list or nested object for governing_thought.** Mitigation: the parser returns an empty string on unrecognized shapes; `collectSectionMinto` treats empty as null, and the fallback fires. No crash.
- **ROOM.md inside a section directory also has a `governing_thought` frontmatter field for some rooms.** Mitigation: ROOM.md is not MINTO.md and is never read by `collectSectionMinto`. This is intentional; ROOM.md is the identity file per Decision 15, not a reasoning artifact.
- **A section with MINTO.md but empty governing_thought string.** Mitigation: the `.trim()` + `.length > 0` guard returns null, falling through to title extraction.

## Deviation Notes

None. CONTEXT locks the helper name, the parse-and-return contract, and the fallback rule. This plan implements all three verbatim.
