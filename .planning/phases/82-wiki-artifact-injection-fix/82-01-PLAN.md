# Plan 82-01: Wire artifacts + per-artifact cap + SKIP_FILES alignment

## Goal

Modify `scripts/generate-presentation.cjs` `collectSections` (lines 155-191) so every section in the returned data structure has a populated `sec.artifacts` array whose entries match the contract that `templates/presentation/wiki.html` already consumes at lines 236-243, 265-267, and 328-355. Each artifact entry carries `{filename, title, content, excerpt, date}` with content truncated at a 20 KB per-artifact ceiling and a human-readable truncation banner appended over the cap. At the same time, align the `SKIP_FILES` constant (line 58) with `lib/vault/room-scanner.cjs` `SYSTEM_FILES` (lines 22-39) so ROOM.md, STATE.md, MINTO.md, CLAUDE.md, COWORK-INSTRUCTIONS.md, TODOS.md, WHATS-NEXT.md, INDEX.md, MILESTONES.md, TEAM-STATE.md, MEETINGS-INTELLIGENCE.md, and action-items.md are never injected as wiki artifacts. The goal is testable: running the modified generator against `test-fixtures/feynman/sections/fixture-small/` produces a section list where every `sec.artifacts` array has the correct length and each entry has the correct JSON shape.

## Scope

Files modified:
- `scripts/generate-presentation.cjs` (estimated delta: +90 / -10 lines)
  - Import or mirror `SYSTEM_FILES` from `lib/vault/room-scanner.cjs` as the new source of truth for `SKIP_FILES` (line 58).
  - Add a helper `extractArtifactMeta(filePath, content)` that returns `{title, excerpt, date}` via the documented preference rules.
  - Add a helper `buildArtifactEntry(absPath, relPath)` that reads the file, parses frontmatter, extracts meta, applies the 20 KB content cap with truncation banner, and returns the full artifact object `{filename, title, content, excerpt, date}`.
  - Rewrite the body of `collectSections` so that for each section it walks `mdFilePaths`, calls `buildArtifactEntry` on each survivor, sorts the resulting array by date descending (files without a date sort to the bottom by filename ascending), and assigns the result to `sec.artifacts`.
  - Preserve the existing `entryCount`, `summary`, `color`, `label`, and `id` fields on each section object (summary logic is upgraded in plan 82-03, not here).

Files NOT modified in this plan:
- `lib/vault/room-scanner.cjs` (we only import from it; a later refactor can add a named export if one does not already exist, tracked as a TODO comment)
- `templates/presentation/wiki.html` (the template already expects this shape)
- `scripts/generate-presentation.cjs` `collectMinto` function at line 193 (room-level, stays exactly as-is)

## Task Breakdown

1. **Grep for an existing SYSTEM_FILES export.** Run `grep -n "module.exports" lib/vault/room-scanner.cjs` and `grep -n "SYSTEM_FILES" lib/vault/*.cjs` to determine whether `room-scanner.cjs` already exports `SYSTEM_FILES`. If it does, `require` and use it directly. If it does not, mirror the constant inline in `generate-presentation.cjs` with a block comment that reads exactly: `// MIRROR: source of truth is lib/vault/room-scanner.cjs SYSTEM_FILES. Keep in lockstep. TODO: refactor room-scanner to export SYSTEM_FILES and import here.`. Acceptance: one of the two paths is taken and documented in the file.

2. **Replace the SKIP_FILES constant at line 58** with either `const SKIP_FILES = SYSTEM_FILES;` (if imported) or a literal `new Set([...])` that contains exactly the SYSTEM_FILES entries (if mirrored). The set must contain: STATE.md, ROOM.md, CLAUDE.md, COWORK-INSTRUCTIONS.md, TODOS.md, WHATS-NEXT.md, INDEX.md, MILESTONES.md, TEAM-STATE.md, MEETINGS-INTELLIGENCE.md, action-items.md, MINTO.md. No additional entries beyond SYSTEM_FILES. Acceptance: `grep -n "SKIP_FILES\|SYSTEM_FILES" scripts/generate-presentation.cjs` shows the constant is tied to SYSTEM_FILES by import or mirror.

3. **Add `extractArtifactMeta(filePath, content)` helper** above `collectSections`. Logic:
   - Parse frontmatter via existing `parseFrontmatter(content)` (already in file).
   - Title: prefer `fm.title` if non-empty, fall back to first `^# (.+)$` line via the existing `extractTitle` pattern, fall back to `path.basename(filePath, '.md')`.
   - Excerpt: strip frontmatter block (`---\n...\n---`), strip the first h1 line, strip leading whitespace. Take the first 200 characters. If the 200-character cut happens mid-word, back up to the last whitespace. If the original body was longer than 200 chars, append `"..."`.
   - Date: prefer `fm.date` if it matches `YYYY-MM-DD`, fall back to `fs.statSync(filePath).mtime.toISOString().slice(0, 10)`. Return `null` if both paths fail (defensive; real files always have mtime).
   - Return `{title, excerpt, date}`. Acceptance: called against a fixture artifact with known frontmatter, returns the documented shape.

4. **Add `buildArtifactEntry(absPath)` helper** above `collectSections`. Logic:
   - `const raw = safeRead(absPath); if (!raw) return null;`
   - `const meta = extractArtifactMeta(absPath, raw);`
   - Apply the 20 KB cap: if `Buffer.byteLength(raw, 'utf8') <= 20480`, content is raw unchanged. Otherwise truncate to 20480 bytes at a paragraph boundary (back up from byte 20480 to the nearest `\n\n` or `\n`), then append the banner `\n\n---\n\n**Note:** This article was truncated at 20 KB for file size. Open the source file at <relative-path> to read the full content.` where `<relative-path>` is the path relative to the room directory.
   - Return `{filename: path.basename(absPath), title: meta.title, content, excerpt: meta.excerpt, date: meta.date}`.
   - Acceptance: called against a 25 KB synthetic artifact, returns a content string <= 20480 + banner_length, with the excerpt still derived from the ORIGINAL (un-truncated) body.

5. **Rewrite the body of `collectSections`** to walk each section, map `mdFilePaths` through `buildArtifactEntry`, drop nulls, sort the resulting array by date descending (dateless entries sort to the bottom by filename ascending), and set `sec.artifacts` on the pushed object. Preserve `id`, `label`, `color`, `entryCount`, and `summary` as they are today. `entryCount` should match `sec.artifacts.length` (recompute after the filter). Acceptance: running the modified generator against `test-fixtures/feynman/sections/fixture-small/` produces at least one section with a non-empty `sec.artifacts` array and every entry matches the documented shape.

6. **Threading buildArtifactEntry through the room root.** `buildArtifactEntry` needs the absolute path; `collectSections` already has `roomDir` in scope and `path.relative(roomDir, absPath)` gives the banner's relative path. Thread `roomDir` into the helper as a second argument and compute the relative path there. Acceptance: the banner in a truncated artifact renders a short relative path like `problem-definition/some-artifact/some-artifact.md`, not an absolute path.

## Risks

- **SYSTEM_FILES is exported from room-scanner.cjs at lines 345-349** (verified by plan-checker 2026-04-14). Use direct require: `const { SYSTEM_FILES } = require('../lib/vault/room-scanner.cjs');`. The mirror-with-TODO fallback path documented in task 1 is therefore dead code and should be removed during execution. No drift risk because the constant is consumed via require, not duplicated.
- **Existing `parseFrontmatter` helper at line 62 does not handle every YAML edge case.** Mitigation: we do not need YAML arrays or nested objects for this work; frontmatter `title`, `date`, and `author` are flat strings. The existing parser is sufficient.
- **Excerpt extraction on an artifact whose body is entirely inside frontmatter.** Mitigation: the 200-char excerpt code returns an empty string if the stripped body is empty. The wiki template already handles empty excerpts in its sidebar render.
- **`buildArtifactEntry` returning null for an unreadable file.** Mitigation: the filter step in task 5 drops nulls before assigning to `sec.artifacts`. `entryCount` is recomputed post-filter so counts stay honest.
