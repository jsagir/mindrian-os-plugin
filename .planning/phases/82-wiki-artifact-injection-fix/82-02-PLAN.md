# Plan 82-02: Per-room cap + warning + in-wiki banner

## Goal

Extend the `collectSections` function from plan 82-01 so it enforces a per-room total injected-markdown ceiling of 2 MB. When the cap fires, the generator drops only the `content` field of over-cap artifacts (sidebar metadata stays intact), logs a single-line warning to stderr in the documented format, and sets a top-level flag on the room data structure that the wiki template renders as a yellow callout banner at the top of the sidebar. The 2 MB cap counts only the raw byte length of the `content` strings across all artifacts, not the template, the marked.js bundle, or the styles. The goal is testable: a synthetic fixture with 250 artifacts averaging 10 KB each triggers the warning, sets the flag, and renders the banner. Real fixture rooms (small/medium/large) do NOT trigger the cap and produce no banner.

## Scope

Files modified:
- `scripts/generate-presentation.cjs` (estimated delta: +35 / -5 lines)
  - Add a `ROOM_INJECTION_CAP_BYTES` constant set to `2 * 1024 * 1024` (2097152).
  - Modify `collectSections` to track a running byte counter as artifacts are appended. After building each artifact entry, check whether adding its content would exceed the cap. If yes, drop the `content` field on that entry (set it to empty string) and increment a `droppedCount` counter. Leave `filename`, `title`, `excerpt`, and `date` intact so the sidebar still lists the article.
  - At the end of `collectSections`, if `droppedCount > 0`, write a single line to `process.stderr` in the exact format: `WARN: room exceeded 2 MB injected-markdown cap, <truncatedCount> artifacts truncated, <droppedCount> artifacts dropped\n`. The `truncatedCount` is inherited from plan 82-01's per-artifact 20 KB truncations and is tracked alongside `droppedCount` in the same pass.
  - Return `{sections, totalArtifacts, bloatBanner}` where `bloatBanner` is a string when the cap fired or `null` otherwise. The main() function at line 508 assigns this to `ROOM_DATA.bloatBanner` (top-level).
- `scripts/generate-presentation.cjs` `main()` at line 508: update the destructure from `collectSections` to `const { sections, totalArtifacts, bloatBanner } = collectSections(roomDir);` and add `bloatBanner` to the `ROOM_DATA` object literal at line 523.
- `templates/presentation/wiki.html` (estimated delta: +12 / -0 lines)
  - Add a single bloat-banner render block in the sidebar `buildSidebar()` function near line 254, before the existing `Home` div. The block reads `ROOM_DATA.bloatBanner` and, if truthy, emits an inline-styled yellow callout div. Inline style: `background:#C8A43C;color:#0D0D0D;padding:8px 10px;font-size:12px;border-left:3px solid #8B6F0E;margin-bottom:8px;`. The banner text comes from `ROOM_DATA.bloatBanner` itself, already escaped via `escHtml`.

Files NOT modified:
- `lib/vault/room-scanner.cjs`
- Any template other than `wiki.html`
- `collectMinto` at line 193
- Plan 82-01 code paths beyond threading the byte counter through the loop

## Task Breakdown

1. **Add the `ROOM_INJECTION_CAP_BYTES` constant** near the top of `scripts/generate-presentation.cjs` next to the `SECTION_COLORS` block. Value: `const ROOM_INJECTION_CAP_BYTES = 2 * 1024 * 1024;`. Acceptance: grep confirms the constant exists and is 2097152.

2. **Thread a byte counter through `collectSections`.** Declare `let injectedBytes = 0; let truncatedCount = 0; let droppedCount = 0;` at the top of the function. After `buildArtifactEntry` returns an entry, compute `const entryBytes = Buffer.byteLength(entry.content || '', 'utf8');`. If `injectedBytes + entryBytes > ROOM_INJECTION_CAP_BYTES`, drop the content (set `entry.content = ''`) and increment `droppedCount`. Otherwise add `entryBytes` to `injectedBytes`. Track per-artifact-truncation by having `buildArtifactEntry` also return a `wasTruncated` flag that the caller reads and adds to `truncatedCount`. Acceptance: a synthetic fixture known to exceed 2 MB raises `droppedCount > 0`.

3. **Emit the stderr warning exactly once per generator run.** After the sections loop finishes, check `if (droppedCount > 0 || truncatedCount > 0)` and call `process.stderr.write('WARN: room exceeded 2 MB injected-markdown cap, ' + truncatedCount + ' artifacts truncated, ' + droppedCount + ' artifacts dropped\n');`. Note: the warning fires when anything was truncated by the per-artifact cap too, even if the per-room cap did not fire; this gives users a single place to learn about any cap activity. Acceptance: grep the test harness capture for the exact string.

4. **Set the bloat banner field on the return value.** If `droppedCount > 0`, build `bloatBanner = 'Some articles were truncated or omitted to keep this snapshot under 5 MB. Open the source files for full content.'`. If only `truncatedCount > 0` (per-artifact truncations but room cap not hit), leave `bloatBanner = null`. Return `{sections, totalArtifacts, bloatBanner}`. The per-artifact truncation case already shows its own inline banner via plan 82-01, so the sidebar banner is reserved for the per-room drop case. Acceptance: synthetic over-cap fixture produces a non-null bloatBanner; fixture-small/medium/large produce null.

5. **Wire bloatBanner into ROOM_DATA.** At line 508 of `main()`, update the destructure. At line 523 of `main()`, add `bloatBanner,` to the `ROOM_DATA` object literal. Acceptance: `JSON.stringify(ROOM_DATA)` output for an over-cap fixture contains `"bloatBanner":"Some articles were truncated`.

6. **Render the banner in wiki.html.** In the `buildSidebar()` function near line 254, insert at the top of the sidebar html string (before the `sb-home` div): `if (ROOM_DATA.bloatBanner) { html += '<div style="background:#C8A43C;color:#0D0D0D;padding:8px 10px;font-size:12px;border-left:3px solid #8B6F0E;margin-bottom:8px;">' + escHtml(ROOM_DATA.bloatBanner) + '</div>'; }`. Acceptance: opening a wiki.html generated from an over-cap fixture shows the yellow banner; opening one from fixture-small shows no banner.

## Risks

- **`buildArtifactEntry` needs to expose a `wasTruncated` flag.** Mitigation: if plan 82-01 did not already return one, add the flag to the return shape in 82-01 during implementation OR compute it here by comparing `Buffer.byteLength(content)` to the pre-truncation file size. The second path is safer because it avoids a 82-01 rework. Document this in implementation notes.
- **Stderr warning fires on per-artifact-only truncations, not only on per-room drops.** This is intentional (users should see any cap activity) but may be surprising. The warning text is explicit: it reports both counts separately so the reader can tell which case fired.
- **Banner styling clashes with a future light-theme wiki render.** Mitigation: the hard-coded yellow is legible on both the dark and light De Stijl palettes. If a future release adds explicit theme-aware banner styles, it can replace the inline style without breaking this plan's contract.
- **250-artifact fixture generation is slow in the test harness.** Mitigation: the fixture is synthetic (plan 82-04 creates it programmatically inside the test via os.tmpdir), not a permanent fixture directory. Node 18+ creates 250 tiny files in well under a second.

## Deviation Notes

None. The CONTEXT specifies the 2 MB cap, the exact warning format, the banner text, and the rule that metadata survives while content drops. This plan implements all four verbatim.
