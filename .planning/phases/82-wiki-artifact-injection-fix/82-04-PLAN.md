# Plan 82-04: Fixture-based tests

## Goal

Create `scripts/generate-presentation.test.cjs` using Node's built-in `node:assert` module (no jest, vitest, mocha, tap, or any other test framework). The test file exercises the three production code changes from plans 82-01, 82-02, and 82-03 across nine test cases: artifact shape, SYSTEM_FILES exclusion, per-artifact 20 KB cap, per-room 2 MB cap, MINTO-driven summary upgrade, title-extraction fallback, order within section, title extraction preference order, and backwards-compatibility against fixture-medium. Tests run against the existing Phase 81 fixtures at `test-fixtures/feynman/sections/fixture-{small,medium,large}/` where possible, and create synthetic fixtures in `os.tmpdir()` for the three cap-behavior cases (one 25 KB artifact, 250 artifacts averaging 10 KB, and the SYSTEM_FILES exclusion synthetic). The test file runs via `node scripts/generate-presentation.test.cjs` and exits 0 on success, non-zero on any assertion failure. Register the test file alongside the existing `scripts/vault-section-minto-generator.test.cjs` so whatever runner discovers that test also discovers this one. The goal is testable: `node scripts/generate-presentation.test.cjs` prints `ok - N tests passed` and exits 0.

## Scope

Files created:
- `scripts/generate-presentation.test.cjs` (estimated size: ~280-320 lines)
  - Shebang + strict mode + `const assert = require('node:assert');` + `const fs = require('node:fs'); const path = require('node:path'); const os = require('node:os'); const { spawnSync } = require('node:child_process');`.
  - A `tests` array or object collecting named test cases. A small runner at the bottom that iterates, prints `ok - <name>` or `FAIL - <name>: <err>`, tallies, and exits with the pass count.
  - Nine test functions, one per case listed below.
  - A `makeSyntheticFixture(files)` helper that writes a fixture to `os.tmpdir()` under a unique subdir and returns the path. Includes `.mindrian` and `ROOM.md` scaffolding so the generator accepts it as a valid room.
  - A `runGenerator(roomDir)` helper that `require`s the generator module directly so we can call `collectSections` as a function rather than spawning the CLI. This requires the generator to export the functions under test; if it does not, we spawn the CLI with `spawnSync` and parse the ROOM_DATA JSON from the generated wiki.html output.

Files modified:
- `scripts/generate-presentation.cjs` (conditional, estimated +5 lines): at the bottom of the file, add a test-only export block guarded by `if (require.main !== module)`. Specifically: `module.exports = { collectSections, collectSectionMinto, buildArtifactEntry, extractArtifactMeta };`. This allows the test file to `require` and call these helpers directly without spawning. The existing `main()` call at the end of the file stays (only runs when the file is invoked as the entry point). Acceptance: `node scripts/generate-presentation.cjs` as CLI still works unchanged; `require('../scripts/generate-presentation.cjs')` returns an object with the four exports.

Files NOT modified:
- Existing Phase 81 test fixtures (we read them, never write them)
- `test-fixtures/feynman/sections/fixture-{small,medium,large}/` contents
- Any other test file

## Out of Scope

- Adding jest/vitest/mocha/tap or any test framework
- Adding a test runner script beyond a minimal iteration loop inside the test file itself
- Integration tests that cover the full wiki.html render path (the template render is tested by eyeballing in 82-05 manual verification; cap-level unit tests are sufficient for this plan)
- Performance benchmarks
- CHANGELOG, version bump, release (plan 82-05)

## Task Breakdown

1. **Add module exports to the generator.** At the very bottom of `scripts/generate-presentation.cjs`, immediately before the `main();` line, add:
   ```
   if (require.main === module) {
     main();
   } else {
     module.exports = { collectSections, collectSectionMinto, buildArtifactEntry, extractArtifactMeta, ROOM_INJECTION_CAP_BYTES };
   }
   ```
   Replace the bare `main();` at line 757 with this guarded block. Acceptance: `node scripts/generate-presentation.cjs test-fixtures/feynman/sections/fixture-small --output /tmp/x` still works AND `node -e "console.log(Object.keys(require('./scripts/generate-presentation.cjs')))"` prints the five exports.

2. **Create `scripts/generate-presentation.test.cjs` with the harness scaffold.** Shebang `#!/usr/bin/env node`, `'use strict';`, require the node built-ins and the generator module. Define a `tests = []` array, a `test(name, fn)` helper that pushes into the array, and a `run()` function at the bottom that iterates, catches assertion errors, prints one line per test (`ok -` or `FAIL -`), increments counters, and calls `process.exit(failed > 0 ? 1 : 0)`. Acceptance: an empty test file runs and prints `0 tests passed`.

3. **`makeSyntheticFixture(spec)` helper.** Signature: `makeSyntheticFixture({sections: {name: {files: [{name, content}]}}, bareFiles: []})`. Writes the structure under `os.tmpdir() + '/gsd-82-04-' + crypto.randomUUID()` and returns the path. Creates a `ROOM.md` and `STATE.md` at the top level so the generator treats it as a valid room. Returns the absolute path. Acceptance: called with an empty spec, creates a valid empty room directory; called with one section and one artifact, produces the documented filesystem shape.

4. **Test 1: artifact shape on fixture-small.** Call `collectSections('test-fixtures/feynman/sections/fixture-small')`. Assert the returned object has a `sections` array. For every section with `entryCount > 0`, assert `sec.artifacts` is an array of the expected length. For every artifact entry, assert `typeof entry.filename === 'string'`, `typeof entry.title === 'string' && entry.title.length > 0`, `typeof entry.content === 'string'`, `typeof entry.excerpt === 'string'`, and `typeof entry.date === 'string' && /^\d{4}-\d{2}-\d{2}$/.test(entry.date)`.

5. **Test 2: SYSTEM_FILES exclusion.** Create a synthetic fixture with one section containing: `ROOM.md`, `STATE.md`, `MINTO.md`, `CLAUDE.md`, `action-items.md`, and `real-artifact.md`. Run `collectSections`. Assert `sec.artifacts.length === 1` and `sec.artifacts[0].filename === 'real-artifact.md'`.

6. **Test 3: per-artifact 20 KB cap.** Create a synthetic fixture with one section containing one artifact whose body is a 25000-character string (call it 25 KB for test purposes). Run `collectSections`. Assert `Buffer.byteLength(sec.artifacts[0].content, 'utf8') <= 20480 + 300` (allowing for the banner length). Assert `sec.artifacts[0].content.includes('truncated at 20 KB')`. Assert that `sec.artifacts[0].excerpt` is still derived from the FIRST 200 chars of the original body (not the truncated version); to test this, seed the original body so its first 200 chars are predictable and the 20 KB truncation point lands well after char 200.

7. **Test 4: per-room 2 MB cap.** Create a synthetic fixture with one section containing 250 artifacts, each ~10 KB, named `art-000.md` through `art-249.md`. Total raw content: ~2.5 MB. Capture stderr by spawning the generator as a subprocess with `spawnSync(process.execPath, ['-e', "require('./scripts/generate-presentation.cjs').collectSections(process.argv[1])", syntheticRoomPath], {encoding: 'utf8'})` and reading `result.stderr`. Assert the stderr string contains `'WARN: room exceeded 2 MB injected-markdown cap'` AND `'artifacts dropped'` with a non-zero drop count. Assert the returned `bloatBanner` field is a non-null string containing `'truncated or omitted'`. Assert that at least 50 artifacts have `content === ''` while their `filename`, `title`, `excerpt`, and `date` fields are still non-empty.

8. **Test 5: summary upgrade with MINTO.** Create a synthetic fixture with one section. Inside that section, create a `MINTO.md` file whose frontmatter is exactly:
   ```
   ---
   governing_thought: "test governing thought"
   ---
   
   # Section MINTO body
   ```
   Also create a `real-artifact.md` in the same section with a different h1. Run `collectSections`. Assert `sec.summary === 'test governing thought'`.

9. **Test 6: summary fallback without MINTO.** Create a synthetic fixture with one section containing just `real-artifact.md` whose h1 is `# My Artifact Title`. No MINTO.md. Run `collectSections`. Assert `sec.summary === 'My Artifact Title'`.

10. **Test 7: order within section (date descending).** Create a synthetic fixture section with three artifacts: `a.md` (frontmatter date 2026-04-10), `b.md` (2026-04-12), `c.md` (2026-04-11). Run `collectSections`. Assert `sec.artifacts.map(a => a.filename)` equals `['b.md', 'c.md', 'a.md']`.

11. **Test 8: title extraction preference order.** Create a synthetic section with three artifacts: one with `title: "Frontmatter Title"` in frontmatter AND `# H1 Title` in body -> expect `"Frontmatter Title"`. One with no frontmatter title but `# H1 Only` -> expect `"H1 Only"`. One with neither -> expect the basename without extension. Run `collectSections` and assert each title matches.

12. **Test 9: backwards compat against fixture-medium.** Call `collectSections('test-fixtures/feynman/sections/fixture-medium')`. Assert every section has `entryCount === sec.artifacts.length`. Assert `bloatBanner === null`. Assert every section's `summary` is a non-empty string. This guards against the upgrade breaking rooms that have no per-section MINTO files today.

13. **Runner output.** At the bottom of the file, `run()` prints `1..N`, then for each test either `ok N - <name>` or `not ok N - <name>` followed by the error. Print a final tally: `# N tests, P passed, F failed`. Exit `process.exit(F > 0 ? 1 : 0)`. Acceptance: `node scripts/generate-presentation.test.cjs` prints the tally and exits with the correct code.

14. **Register with existing runner.** Grep `package.json` and any `scripts/*test*` for a central test runner. If `package.json` has a `"test"` script, append `&& node scripts/generate-presentation.test.cjs` to it. If not, add a new `"test:presentation"` script that runs just this file. Also check `scripts/vault-integration-test.cjs` and see whether it imports other `*.test.cjs` files; if it does, append this one. Acceptance: `npm test` (or the equivalent local runner) picks up the new file automatically.

## Risks

- **The generator's `main()` side-effects fire on `require`.** Mitigation: task 1 wraps `main()` in `if (require.main === module)` so requiring the module for tests does not run `main()`. This is a load-bearing change; without it the test file would spawn the full generator on every require and the tests could not isolate `collectSections`.
- **Existing Phase 81 fixtures drift and fail test 1 or test 9.** Mitigation: test 1 and test 9 use only shape assertions (array existence, field presence, type checks) rather than exact content matches, so fixture content changes do not break them. If the fixture directory structure changes (a section is added or removed), test 9's `entryCount === sec.artifacts.length` still holds because it compares within each section.
- **Synthetic fixture cleanup on test failure.** Mitigation: wrap each synthetic fixture creation in a try/finally that calls `fs.rmSync(fixturePath, {recursive: true, force: true})` on exit. Use unique UUIDs so parallel test runs never collide.
- **`spawnSync` for the stderr-capture test is slower than direct function call.** Mitigation: use direct function call for everything except test 4 (the per-room cap stderr capture). For test 4 we must spawn to isolate stderr; it adds ~1 second to the test run, acceptable.
- **Frontmatter parsing in the test synthetic fixtures must match exactly what the real `parseFrontmatter` accepts.** Mitigation: write the synthetic frontmatter in the exact format used by `scripts/vault-section-minto-generator.cjs` output, which is already validated by Phase 81 tests.
- **No central test runner is registered today.** Mitigation: task 14 registers the new test file either through `package.json` `scripts.test` or inline into `scripts/vault-integration-test.cjs`. If neither path works cleanly, commit the file standalone and document the run command in 82-05's CHANGELOG `Testing` note.

## Deviation Notes

- CONTEXT specifies 6 test cases ("artifacts shape, per-artifact cap behavior, per-room cap behavior, SYSTEM_FILES exclusion, summary upgrade with MINTO present, summary fallback with MINTO absent"). The user prompt expands this to 9 test cases adding order-within-section, title-extraction strategies, and backwards-compat-against-fixture-medium. All three additions are covered by CONTEXT's "Claude's Discretion" section (order by date, title strategy, preserve pre-81 behavior), so the expansion is authorized by the discretion block, not a deviation.
- Test 4 uses `spawnSync` to capture stderr. This is the only test that spawns a subprocess; the others use direct `require` + function call. This is a practical deviation from a hypothetical "all tests are direct calls" rule but is necessary because capturing stderr from within the same process requires stdout/stderr swapping, which is fragile.
