**THE DEFECT.** `bin/mindrian-brain-mcp-client.cjs` describes three of its six tools in terms of
backends this plugin retired: `brain_ask` (`:85`) still says "Auto-routes Pinecone/Neo4j
server-side", `brain_search` (`:142`) says "Pinecone with Neo4j fulltext fallback", and
`brain_stats` (`:158`) says "Pinecone index size". `CLAUDE.md`'s stack table states plainly
"Pinecone is RETIRED"; the live backend is a Memgraph teaching graph with 1024-dim
multilingual-e5-large vectors embedded LOCALLY. This was reported once on 2026-08-10 in
`docs/brain-audit-2026-08-10/2026-08-10-HANDOFF-brain-service-audit.md` ("four plugin tool
descriptions still name the retired Pinecone/Neo4j backend") and is still shipping. It matters
beyond tidiness: per the corpus finding this repo's own D-03 doctrine rests on, a tool description
IS the instruction channel, so a description naming a backend that no longer exists actively
misinforms the model about what the tool can do.

**THE GUARDRAIL GAP Phase 266 does not close.** MCPFIX-04 expands the prose-SHAPE checks (length
floor and ceiling, starts-with-capital, ends-with-period, no em-dash) to every tool. It does not
check for a raw markdown heading, an embedded newline, or a retired backend name. Those are a
different defect class: `room_state`'s wire description currently reads
`... # Voice DNA -- Larry's Voice & Tone\n\n*A demanding but warm professor who asks on`, which is
markdown leakage rather than a shape violation. This plan adds the complementary HYGIENE tripwire
and states in its own header which test owns what, so a future reader does not delete one thinking
it duplicates the other.

Purpose: one shipped misinformation defect, and the one description check nobody owns.
Output: six honest Brain descriptions and a wire-level hygiene tripwire across both servers.
