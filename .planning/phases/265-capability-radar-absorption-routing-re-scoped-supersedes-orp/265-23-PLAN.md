Three jobs that all have to happen after wave 4 and all write files wave 4 must not touch.

1. **RATIFY THE GRANTS.** Plans 265-14, 265-15, 265-19 and 265-21 each added a dispatch token to a
   command whose registry row is still `pending`, because five plans in one wave writing
   `data/subagent-dispatch-grants.json` would be a git-index race. Plan 265-12's tripwire reports
   that state as `unratified`, which passes by default and FAILS under `TEST_265_GRANTS_STRICT=1`.
   This plan performs the single ratification write, and plan 265-24's phase gate sets the strict
   flag so a forgotten grant cannot ship.

2. **BUILD THE ONE MCP DIAGNOSTIC THAT IS LOW-RISK AND WELL-DEFINED.** Claude Code 2.1.128 added
   "`/mcp` now shows the tool count for connected servers and flags servers that connected with 0
   tools". `scripts/doctor.cjs` has an L4 MCP stdio handshake and a version-match check at about
   lines 1298 to 1359, but grep for `listTools`, `tools/list` and `toolCount` across that file
   returns nothing: no count, no zero-tool assertion.
   `references/capability-radar/capabilities-index.md:205` already flagged this as a candidate and
   it was never built. It is mechanical, so it gets built.

3. **RECORD, DO NOT GUESS, EVERYTHING ELSE.** The MCP audit left several items that need a genuine
   architecture decision rather than an edit. The instruction from the navigator is explicit: do not
   guess, add them to the capability ledger as `dormant` or `adopting` candidates with the reasoning
   captured. The largest of these is `alwaysLoad`, and it deserves stating carefully because it is a
   TRADE and the repo currently documents only one side of it. `alwaysLoad: true` on both servers
   pins about 7,557 eager tokens into every session (`mindrian-os` about 7,062 plus
   `mindrian-brain` about 495). The case FOR keeping it is real: it closes the Brain cold-start
   window that `references/capability-radar/capabilities-index.md:187` calls "the single biggest
   leverage adoption", and it is what makes Canon Part 3 Mode A available at turn 1. The case
   AGAINST is also real: the langtalks corpus's two independent sources both name eager loading as
   THE MCP context problem, and Anthropic's own stated practice is deferred loading for exactly the
   more-tools-than-the-budget-justifies case. The lever nobody has used is that `alwaysLoad` is
   PER-SERVER, so the only way to get both is to split the surface. That is a real architectural
   change with real cost, and the honest next step is measurement, which plan 265-17's budget
   assertion now provides on every run. Do NOT silently drop `alwaysLoad`: the cold-start regression
   it would reintroduce is documented and was deliberately paid for in Phase 114.

Purpose: the phase's whole premise is that findings must be ABSORBED or ROUTED, never left to rot in
a research file nobody reads again.
Output: five ratified grants, one new doctor organ, and a ledger that carries every deferred
decision with its reasoning.
</objective>
