<objective>
`/mos:reason` is the highest-confidence fan-out candidate in the repo and the one with the
cleanest independence evidence, because the file says so itself.

Step 1 enumerates every canonical Data Room section containing at least one artifact (the file
names 11 candidates). Steps 2 through 8 then run PER SECTION: invoke the plan script, read the
artifacts, reason, assemble JSON, write a temp file, invoke the write script, clean up. The loop
declares its own iterations independently failable, twice, in its own words: Step 2 says "If
stderr contains an error, surface it to the user and move on to the next section", and Step 7
says the same. Inputs are disjoint (each section reads only its own artifacts) and outputs are
disjoint (each section writes only its own `MINTO.md`).

The per-section work is the heaviest in the set. Step 3 is explicit that excerpts are not enough:
"For each artifact, use the Read tool to load the full file (not just the excerpt). The excerpts
in the payload are first-line previews; Feynman stages 1, 2, 4, 5 need the full body to do honest
work." So ONE context absorbs the full body of every artifact in every populated section, then
runs four distinct reasoning passes per section. That is up to 44 reasoning passes over full
document bodies in one window, and it degrades predictably: a section processed late reasons with
a context already saturated by ten other sections. `--regenerate-all` guarantees the worst case
rather than risking it.

`/mos:grade --full` already treats the same canonical room sections as a parallel dispatch
partition for a lighter purpose. mos-reason does strictly more per-section work and still runs it
in one context.

Two things naive parallelization would get wrong, and this plan handles both:

- **The migration backup is a real ordering dependency.** `--regenerate-all` runs
  `scripts/vault-regenerate-all.cjs`, which creates `.migration-backup/YYYY-MM-DD-HHMMSS/` and
  runs `runTier0` for every section. Fanning out before that backup exists risks agents
  overwriting pre-migration files with no recovery path.
- **The sequential loop provides accidental cross-section coherence.** Today the agent has seen
  earlier sections' governing thoughts by the time it writes later ones. Independent agents lose
  that entirely, so consolidation must compare returned governing thoughts and FLAG direct
  contradictions.

Purpose: this is the largest quality and context win available in the phase, with an existing
sibling pattern to copy and the lowest dedup risk of the five fan-outs.
Output: a hybrid protocol whose sequential head is sequential for a stated reason.
</objective>
