<objective>
`/mos:research`'s multi-lens fan-out is sequential by accident, and the fix is one condition.

`lib/core/lens-engine.cjs` freezes four rotation modes
(`['serial', 'parallel', 'single', 'weighted-by-context']`). The dispatch at about line 347 reads:

```
if (mode === 'parallel') {
  findingNodes = await Promise.all(lenses.map((lens) => runOneLens(lens, runOpts)));
} else {
  // serial AND single AND weighted-by-context share the sequential path.
  for (const lens of lenses) { findingNodes.push(await runOneLens(lens, runOpts)); }
}
```

`/mos:research` Stage 4 calls `runSourceLens`, which calls `rotate({... rotationMode:
'weighted-by-context' ...})`. So the engine ALREADY ships a working `Promise.all` branch, and
research deliberately shares the sequential path with it. `/mos:persona --parallel` sets
`rotation_mode: parallel` and gets concurrency; `/mos:hat-briefing` declares `rotation_mode:
consume` and rotates nothing. `/mos:research` is the only lens-engine client on the
sequential-by-accident fourth mode.

There is NO LLM reasoning inside a lens. Per lens the work is: consult the 30-day
`.mindrian/research-cache`, on a miss make ONE live `fetchCorpus` call, write back to cache, return
items. Ranking afterwards is deterministic CJS. The cost is LATENCY, not tokens. `--broad`
(scholarly plus industry plus patent, all weight 1.0) is the clearest case: three equally-weighted
independent HTTP legs, fetched one after another.

This is why subagents are the WRONG tool here and why this plan is deliberately separate from the
five subagent fan-out plans in this phase. Handing each lens to a Claude subagent would spend an
entire agent context to perform one HTTP fetch and return a JSON array. The defect is a library
condition, not a dispatch shape.

Purpose: a one-condition change buys the concurrency that the markdown has been claiming
("Research subquestions fan out independently", `--broad` described as "comprehensive
parallel-angle intelligence") and the runtime has not been delivering.
Output: `weighted-by-context` on the concurrent branch, with the order guarantee proven rather
than assumed.
</objective>
