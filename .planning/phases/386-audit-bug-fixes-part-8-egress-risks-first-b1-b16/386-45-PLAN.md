<objective>
Fix finding B18: at SessionStart the room opens report "room.db cannot be opened (it is damaged or is not a database)" for a room on a Windows drive read from WSL, although the file header is a valid SQLite file ("SQLite format 3", 11.5 MB) and other tools open it. Reproduce on fixtures only: a synthetic room.db built by tests/helpers/synthetic-room-db.cjs, copied into a new empty scratch folder under /mnt/c when one can be made without touching any owner data (for example a new folder under the Windows temp folder of the user, removed at the end); if none can be made, the RCA is static and says so. Never read, copy or open the owner's real room.db.

Part 9: room.db is the local mind and the open path keeps its migration safety. This plan does not change the open path. The honest message is the fix; a mode change goes to the owner as a decision.
Output: RCA with the emitter and the repro result, a failing test, the typed-cause fix, and a recorded decision on any mode change.
</objective>

Option A (recommended when the repro shows WAL works, or when it was static): keep WAL; the honest message of Task 2 is the whole fix.
