<objective>
Build the one seam that lets Python consume CJS-owned vector machinery, and prove it works on BOTH
vector backends.

This is the answer to CONTEXT.md D-02, and it is the highest-risk item in the phase. 296-RESEARCH.md
F-2 live-executed both directions and found that room.db carries one of TWO vector tables chosen by
a runtime capability probe: `eureka_vec` (a `vec0` virtual table) when the `sqlite-vec` extension
loads, or `eureka_vec_fallback` (a plain BLOB table) when it does not. A plain Python `sqlite3`
connection reads the second and throws `OperationalError: no such module: vec0` on the first.

`sqlite-vec` is a hard `dependencies` entry in `package.json`, so it is installed on every real user
machine and absent from this checkout. That inverts the usual dev-versus-prod risk: a direct Python
`SELECT` passes here and is broken for every actual user. CONTEXT.md's REVISION block promoted the
CJS-side bridge from "permitted by the Discretion clause" to "required by F-2" for exactly this
reason.

The mirror-image handoff already ships: `lib/core/rs-pinecone-bridge.cjs` spawns `python3` from CJS
today. This plan builds the same shape pointing the other way.

Purpose: one backend-agnostic entry point, and a test that can never go green having exercised only
one backend.
Output: `scripts/rs-vector-bridge.cjs` and `tests/296-vector-read-both-backends.test.cjs`.
</objective>

    NOT construct a pipeline: `embedTexts` owns the model-load singleton, the batch sizing, the

    Op `knn`. Request `{room: string, query: number[], k?: number}`. Validate: `room` a non-empty
    string else `bad_room`; `query` a non-empty array of finite numbers else `bad_query`; `k`
    defaults to 10 and clamps to the range 1 to 1000. Open the handle with
    `openRoomDb(room, { allowExtension: true })` from `lib/core/room-db.cjs`. `allowExtension: true`

    Call `readMeta(db)`. Call `knnQuery(db, query, k)`. Write
    `{success:true, backend, meta, dim, hits}`. Close the handle in a `finally` block with
    `closeRoomDb(db)`, guarded so a close failure cannot turn into a throw.

    Op `meta`. Request `{room: string}`. Same open, same `ensureStore`, then
    `{success:true, backend, meta, dim}` and the same `finally` close. This op exists so a caller
    can ask "which backend and which model does this room use" without running a query.

    Never call `new DatabaseSync` directly: `openRoomDb` owns WAL, `synchronous`, `foreign_keys`,

    op, which touches no database at all. Pitfall 8 (holding a write transaction across an `await`

    Zero network. No `fetch`, no `node:http`, no `node:https`, no `brain-client`. Bound every

    envelope, matching the `scrubSecret` discipline recorded as `T-272-11`.

| Python parent to CJS child | A JSON envelope crosses a process boundary via stdin and stdout; the child's `room` field is a filesystem path supplied by the parent |
