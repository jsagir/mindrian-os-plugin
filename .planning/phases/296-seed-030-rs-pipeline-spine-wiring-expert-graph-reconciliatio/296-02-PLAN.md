<objective>
Close the real `rs-experts` gap. Not the one CONTEXT.md's original D-03 described.

296-RESEARCH.md F-6 established that D-03's premise was false, not merely stale: `rs-experts` has
had no remote Brain-Cypher coupling since 2026-05-22 (`2f0e4e79`), which predates SEED-030's own
2026-06-17 evidence date. There is nothing to "keep remote" and nothing to stop crashing, because
it does not crash. Every failure path in `lib/core/rs-expert-brain-projection.cjs` already returns
an empty array.

The real defect (F-7) is that one hand-rolled three-line block answers three different questions:
(a) no Tier-1 transport ships at all, (b) a transport ships but the instance is unreachable, and
(c) the transport works and the topic genuinely has zero experts. Cause (c) is a CORRECT answer
being dressed as a fault, which tells the user the tool is broken when it worked perfectly.

Theo's `CONN-05` names this exact collapse ("if 'not found' and 'the instance is unreachable' both
arrive error-flagged, Larry cannot tell them apart, and those two need completely different
responses"), and Theo's declared vocabulary has no `Author` / `Person` / `Institution` label at
all, which makes keeping `rs-experts` LOCAL-only structurally required by the eventual cutover
rather than a compromise. Both halves of the corrected D-03 are confirmed by Theo, not merely
permitted.

Purpose: three causes, three distinguishable outputs, using the refusal rail that already ships.
Output: a corrected `resolveExpertTier` seam, its six-case proof, and a command doc that no longer
claims a Brain Cypher MATCH that has not existed for over a year.
</objective>
