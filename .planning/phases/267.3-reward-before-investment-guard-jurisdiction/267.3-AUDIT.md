### 1.3 Four independent proofs of the guard's scope

The guard cannot see anything outside `commands/*.md`. Four separate places in the code say
so, and they are not copies of one another; each is a different layer of the stack.

**Proof 1 - the library's own header.** `lib/core/mva-rule-linter.cjs:6-9`:

> The reward-before-investment rule linter (per docs/reward-before-investment
> -rule.md). Scans commands/\*.md frontmatter, validates that every interactive
> command declares an `interactive_first_reward` field

**Proof 2 - the only directory entry point.** `lib/core/mva-rule-linter.cjs:224-243`,
`scanCommands(commandsDir)`, calls `fs.readdirSync(commandsDir)` at line 227, filters
`f.endsWith('.md')` at line 238, and hands the list to `scanFiles`. It is non-recursive and
it accepts exactly one directory. There is no second discovery path.
`lib/core/mva-rule-linter.cjs:170-204`, `scanFiles(filePaths)`, is the shared classifier
but it judges only the paths a caller already found; it discovers nothing itself.

**Proof 3 - the CLI's default target.** `scripts/check-reward-before-investment.cjs:127`:

```js
const target = process.argv[2] || path.join(__dirname, '..', 'commands');
```

The staged mode is narrower still: `scripts/check-reward-before-investment.cjs:82` filters
the staged set with `/^commands\/[^/]+\.md$/`, a single-level, commands-only regex.

**Proof 4 - the hook-level gate never even fires.** `scripts/hooks/pre-commit-room-minto-guard.sh:300`:

```sh
if git diff --cached --name-only --diff-filter=ACM | grep -qE '^commands/.+\.md$'; then
```

The whole `mva-rule-linter` arm (lines 299-313) sits inside that condition. A commit that
stages `scripts/session-start` and nothing under `commands/` does not run the reward linter
at all. This is the strongest of the four: even if the library could read a bash script, the
hook would not ask it to.

**Consequence.** The guard's jurisdiction is exactly `commands/*.md`, at commit time only,
and only for files a given commit happens to stage. Everything else in the product is
outside it.

### D-C. The lint scope

**Question:** does the linter keep its `--staged` scope only, or does it also gain a
whole-tree audit wired into a release gate?

Evidence for widening: Section 4.4. DEFERRED-271-D1 is a direct, dated demonstration that
a staged-only gate lets debt hide until an unrelated sweep happens to stage the files. 67
of 113 commands are undeclared right now and no commit is currently blocked by that fact.

Evidence for caution: the whole-tree audit ALREADY EXISTS as the CLI's default mode
(`scripts/check-reward-before-investment.cjs:127`) and it exits 1 today. Wiring it into
`scripts/verify-release` before the backfill lands would turn every release red
immediately. So the question is not only "whole-tree or not" but "wired when".

Phase 245-02 deliberately narrowed the commit gate to `--staged` for a good reason, recorded
at `docs/reward-before-investment-rule.md:117-129`: one pre-existing offender was blocking
every commit that touched any command, which made `COMMIT_NO_VERIFY=1` mandatory rather than
exceptional. Any widening must not undo that fix.
