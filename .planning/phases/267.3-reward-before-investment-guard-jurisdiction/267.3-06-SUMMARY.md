## Deviations from Plan

**None requiring a rule invocation.** Two things worth naming as process notes rather than
deviations:

**1. `export` was argued in full even though the plan only flagged `eureka` and `funding`.**
`export` turned out to be `publish`'s closest sibling in this batch (both HTML Data Room
artifacts, one filed locally, one deployed live), and the `live_deliverable` term's own written
definition explicitly names a "filed document" as a qualifying shape distinct from a live URL.
Giving it the same full-paragraph treatment as the plan's two flagged rows, rather than a bare
table-cell HIGH, made the genuine tension (filed vs. deployed, reversible vs. irreversible)
visible for the checkpoint rather than buried. This is Rule 2's spirit (missing analytical rigor
would be a correctness gap in an audit-trail document whose whole purpose is showing work) but
did not require deviating from any plan instruction - the plan invites "argued rather than
asserted" reasoning generally, it only names two rows as MUST-argue.

**2. A self-caught arithmetic error in the classification doc's own "concentration" note.** The
first draft of the diagnostic-opt-out concentration paragraph said "15 of 25"; recounting the
actual table found 18 HIGH rows plus 2 NEEDS-RULING proposing the same value, for a true count
of 20 once both rulings landed as proposed. Corrected before Task 2's checkpoint was surfaced
(Rule 1: a factual bug in a document under active review), so the navigator ruled against the
corrected number, not the wrong one.
