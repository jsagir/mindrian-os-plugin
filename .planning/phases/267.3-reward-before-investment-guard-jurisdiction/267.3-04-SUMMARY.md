# Phase 267.3 Plan 04: Classify and Declare the 17 Blocked Commands Summary

Seventeen commands that had blocked Phase 271 for a day now carry human-ruled
`interactive_first_reward` declarations traceable to a cited line of their own bodies, and the
closed vocabulary gained a ninth member because one of the seventeen, `publish`, could not be
described honestly by any of the eight that existed.

## The Shape of This Wave, in One Paragraph

Task 1 wrote the rubric and proposed 17 values. Task 2 was a blocking human checkpoint and the
navigator ruled on all 17. Task 3, this record, applied them. The ruling widened scope: it
minted a new vocabulary term, which wave 2's plan text never anticipated, so Task 3 had to land
a full canon amendment BEFORE it could write a single line of frontmatter. That amendment is
the more consequential half of this wave.

## Part 1: The Canon Amendment (`live_deliverable`)

### Why a ninth term was necessary

Row 13 of the classification argued `publish` honestly and reached a dead end. `publish` DOES
deliver a reward: `commands/publish.md:149` parses the deploy output and hands over a live
shareable URL for the navigator's whole Data Room. It passes all four of the rule doc's
qualifying tests without strain. And the eight-member vocabulary had no token for it:

| Existing term | Why it is false for `publish` |
|---|---|
| `reframe_question` | Bound to onboard's single-sentence opener |
| `instant_brief` | Bound to the 30-second MVA pipeline, which publish does not run |
| `schema_preview` | A promise about extraction; publish extracts nothing |
| `calibration_distribution_preview` | Bound to grade's calibration set |
| `paragraph_preview` | Bound to file-meeting's first paragraph |
| `methodology_reframe` | Requires Larry's analysis over the navigator's material; publish analyzes nothing |
| `--none (scripting only)` | Forbidden twice over: `hitl_shape: "F.0"` is a declared human fork (TB-2), and none of `--no-interactive` / `--script` / `-q` appears in the file (TB-1) |
| `--none (diagnostic surface)` | False in the OPPOSITE direction from all the others: publish performs an irreversible action and hands back an artifact, which is categorically not "reporting state rather than delivering a variable reward" |

The navigator's ruling names the deciding principle: filing a knowingly-false-but-least-false
declaration defeats the whole phase (GUARD-02 requires every addition be recorded as a canon
amendment with a written reason; GUARD-10 forbids a gate satisfied by a fabricated-green
answer). So the term was minted, with the same weight as wave 1's D-B ruling.

### Where the term landed, and the near-miss that widened it

The navigator's instruction named two places. There turned out to be **four**, and the fourth
was found by reading the test suite rather than by being told:

| Place | What lives there | Enforced by |
|---|---|---|
| `lib/core/mva-rule-linter.cjs` | the frozen `REWARD_TYPES` Set, plus the header-comment definition in the same style the existing eight use | it IS the source of truth |
| `docs/reward-before-investment-rule.md` allowed-values list | the one-line bullet | T13 (set-equality, both directions) |
| `docs/reward-before-investment-rule.md` `## Vocabulary amendments` | the full entry: token, surface class, ruling, date, evidence, the four qualifying tests applied, why each prior term fails, and what the term does NOT cover | **T15, added by this plan** |
| `data/first-reward-surfaces.json` `_doc.reward_vocabulary` | the mirror array | T14 (set-equality, both directions) |

**The registry was the near-miss.** Nothing in the brief mentioned it. T14 asserts set-equality
between the registry mirror and the Set in both directions, so amending the Set and the doc
alone would have redded `run-all-267.3.sh` on its own do-not-regress arm. The general repair
shipped with the specific one: the rule doc's amendment preamble previously read "only here and
in `lib/core/mva-rule-linter.cjs` together", which is a two-place instruction for a three-place
invariant, and it now names all three plus the tests that hold them. The next amender cannot
repeat the near-miss by following the document's own instructions.

### The test-coverage question, answered by reading the pattern

The brief asked whether wave 2's pattern implies a parallel test case. The measured pattern:
wave 2 added T12 (the original six survived, the Set is still frozen), T13 (rule-doc bullet
parity) and T14 (registry parity). T13 and T14 are parametric over the live Set, so they picked
up `live_deliverable` with no edit at all. T12 is the only non-parametric one, and it guards
only the ORIGINAL six. Nothing guarded the ADDED members, and nothing anywhere checked that a
term carries its written reason.

So T15 is T12's sibling, filling exactly that gap:

- All three amendment members present and unrespelled (`methodology_reframe`,
  `--none (diagnostic surface)`, `live_deliverable`).
- `REWARD_TYPES.size === 9`, so a silent drop or a tenth term added without a ruling reds here.
- Each of the three carries a `### <token>` entry in the rule doc's `## Vocabulary amendments`
  section. This is the doc's own law made enforceable: "A code change without an entry in this
  section is a command-level invention wearing a library's clothes."

No per-command binding was added (no test asserting `publish` declares `live_deliverable`),
because wave 2 set no such precedent for amendment terms. The only per-command parity test in
the suite, T11, is bound to the rule doc's four ORIGINAL prescriptions, which is a different
thing. Keeping T15 vocabulary-only also kept the amendment commit self-contained and green
without depending on frontmatter that had not been written yet.

`lib/core/mva-rule-linter.test.cjs`: **15/15 passed.**

### The router sub-case

Row 15 (`show`) was also ruled, and it was ruled deliberately narrowly. `show` is a pure router
by its own file's explicit design (`commands/show.md:40`: "you do NOT build any view here"): it
produces no artifact and reports no status, and every reward it appears to deliver is its
TARGET's reward. That is neither a diagnostic surface nor a reward, and the vocabulary has no
term for an INHERITED reward. Rather than mint a tenth term for one command, the ruling reuses
`--none (diagnostic surface)` and records the reading explicitly, with a written warning against
expansion by resemblance: a future router-shaped command still needs its own first-delivery
check, not a rubber stamp from this precedent. That warning is now in the rule doc and in the
linter's header comment.

`commands/scout.md` precedent and the plan's instruction that a `--`-leading token be quoted in

one of the 17 round-trips through the linter's own `parseFrontmatter`, verified rather than
assumed.
