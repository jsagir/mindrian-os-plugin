## Part 1 - The rubric

### 1.1 The question the rubric answers

Not "what is this command for". The question is narrower and answerable from the
file: **what is the first thing this command hands back to the navigator, and
which of the eight legal tokens names that thing honestly.**

### 1.2 The signals that go in

Every one of these is readable off the file without guessing.

| Signal | Where it lives | What it tells you |
|---|---|---|
| `hitl_shape` / `hitl_stages` | frontmatter | Whether the command reaches a genuine human fork. `F.0` is a decision-close, `F.1` a single-fork next move. Either one means the command is interactive BY ITS OWN DECLARATION. |
| `body_shape` | frontmatter | `methodology` is a Larry-narrated reasoning flow. `E (Action Report)` is a report. `A` / `B` / `C` are layout disciplines, orthogonal to the reward question. |
| `kind` | frontmatter | `methodology`, `meta`, `mechanical`. Describes the family, not the reward. See TB-4. |
| `serves_jtbd` and `teaching` | frontmatter | What the author says the command is for, in their own words. |
| script vs narrate | body | Does the body shell out (a bash fence, a `node scripts/` call) or does it narrate a conversation. |
| first user-visible delivery | body | The load-bearing signal. See S-1 for what counts. |

### 1.3 S-1: what counts as a first delivery

A delivery is something the command PRODUCED and handed over. Not everything
user-visible is a delivery.

These are NOT deliveries:

- A question, however short. `Ask: "Quick pass or deep dive?"` is an ask.
- A menu, a selector, or an `AskUserQuestion` card. The rule doc puts a pick from
  three or fewer options on the investment side of the ledger and calls it a
  non-violation, which is exactly the point: it costs the navigator nothing and it
  gives them nothing.
- A framework explanation printed from a reference file. A textbook summary fails
  qualifying test 4 (it is not uniquely attributable to MindrianOS).
- A prerequisite or tooling message ("you will need the Vercel CLI").
- An error envelope.

The cited line in Part 2 is the first line at which the command hands over
something it produced.

### 1.4 The gate every candidate value must pass

The four qualifying tests, verbatim in substance from
`docs/reward-before-investment-rule.md:52-56`. A candidate that fails any one of
the four is not a reward:

1. **Unpredictable** - the navigator could not have produced it themselves in
   under 30 seconds.
2. **Intelligible** - the navigator understands what they are seeing without
   explanation.
3. **Valuable** - they would pay attention to it on someone else's screen.
4. **Uniquely attributable to MindrianOS** - not something a general assistant
   could do in the same time budget.

### 1.5 The two named disqualifiers

Both are the rule doc's own words, not an inference:

- **D-1: a grade is not a reward.** `docs/reward-before-investment-rule.md:58`,
  "A grade is not a reward (predictable output of an asked question)." A numeric
  score the navigator asked for cannot be the declared first reward.
- **D-2: a status report is not a reward.**
  `docs/reward-before-investment-rule.md:59-60`, "A `/mos:status` output is not a
  reward (predictable report)." and "A status report is not a reward." This is the
  disqualifier that sends a command to `--none (diagnostic surface)`.

### 1.6 The tie-break rules

**TB-1. `--none (scripting only)` is FORBIDDEN without a real scripting flag.**
The scripting override at `docs/reward-before-investment-rule.md:95` is legitimate
only "IF the command is invoked with a `--no-interactive`, `--script`, or `-q`
flag". If the body carries no such invocation path, this token is forbidden no
matter how script-heavy the command looks. A body full of bash fences is not a
scripting flag. A `--json` output-format flag is not a scripting flag either: it
changes the shape of the output, not the interactivity of the invocation.

*Measured, not assumed.* All 17 bodies were scanned for `--no-interactive`,
`--script` and a standalone `-q`. Zero of 17 carry any of the three. TB-1
therefore forbids `--none (scripting only)` on every one of the 17, without a
single judgment call being needed.

**TB-2. `hitl_shape: F.0` or `F.1` cannot take a scripting opt-out.** An F.0
decision-close or an F.1 single-fork surface reaches a genuine human fork by its
own declaration (Canon Part 11). A command that declares it stops for a human
cannot also declare it is a silent script. This is the rule that would have caught
the 271-03 `publish` error on its own, and TB-1 catches it a second time
independently.

**TB-3. When two terms both fit, prefer the closer minting flow, and record the
loser.** The rule doc's "Application to existing flows" section binds four of the
six original terms to exactly one command each. Compare the candidate's first
delivery against those shapes and take the nearer one. A row where two terms
plausibly fit and no runner-up is recorded is an incomplete row.

**TB-4. The family qualifier in a term's class definition is descriptive, not a
gate.** `methodology_reframe` is defined as "a conversational methodology command
whose first delivered value is Larry's analysis or reframe over the user's OWN
material". The first clause names the family the term was minted against; the
SECOND clause is the discriminating test. A command outside that family whose
first delivery is unmistakably Larry's analysis over the navigator's own material
takes the term. Reading the first clause as a gate would leave `deck` and
`suggest-next` with no honest token while their substance matches exactly.
This rule is stated explicitly because it is the one Part 1 rule the navigator
might reject, and rejecting it moves exactly two rows.

**TB-5. Preview versus deliverable.** When the first delivery is a structure the
command will then go on to fill or execute, it is a preview and takes
`schema_preview`. When the same-looking structure IS the command's whole output
and nothing further runs, it is the analysis itself and takes
`methodology_reframe`. This is the distinction `267.3-DECISIONS.md` Section 3.2
already draws when it calls `schema_preview` "a promise about extraction, not an
analysis", and it is what the `find-bottlenecks` calibration example encodes:
mapping the system boundaries previews the Reverse Salient structure BEFORE the
navigator invests in the full bottleneck hunt.

**TB-6. No minting.** The vocabulary is closed at the eight members of
`REWARD_TYPES`. If no member is honest for a command, the row is NEEDS-RULING. It
is never a licence to invent a token; a ninth term is a second canon amendment and
belongs to a ruling, not to a classification.

### 1.7 The four calibration examples, read as worked judgments

Read before classifying anything. Each is tailored to its own command; none is a
template.

- `commands/onboard.md:12` = `reframe_question`. Fits because onboard's first
  screen is a single-sentence question and the reward is Larry reframing THAT
  SENTENCE, before any material exists. It is bound to the sentence, not to the
  room.
- `commands/find-bottlenecks.md:12` = `schema_preview`. Fits because mapping the
  system boundaries shows the SHAPE of the Reverse Salient hunt before the
  navigator commits to the hunt. The preview is of work still to come.
- `commands/new-project.md:12` = `instant_brief`. Fits because new-project runs
  the actual 30-second MVA pipeline. The term is bound to that pipeline, so it
  does not travel to commands that merely produce a fast summary.
- `commands/grade.md:11` = `calibration_distribution_preview`. Fits because the
  reward is the calibration set's anonymized distribution, shown INSTEAD of the
  grade, precisely because disqualifier D-1 says the grade itself cannot be it.

### 1.8 How to apply this to the remaining 50

In order: read the frontmatter signals; find the first delivery per S-1; run the
four qualifying tests; check the two disqualifiers; if the answer is "it reports
state", stop at `--none (diagnostic surface)`; if the answer is "Larry reasons
over the navigator's own material", stop at `methodology_reframe`; if the answer
is "a structure to be filled later", stop at `schema_preview`; check TB-1 before
ever writing `--none (scripting only)`; record the runner-up; and mark
NEEDS-RULING rather than force a fit.
