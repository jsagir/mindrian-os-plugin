## ADDENDUM 2 2026-11-26: QA-F11 part B and the F2 fallback (navigator decisions)

### QA-F11 part B: one UserPromptSubmit process
- Evidence: second paste shows all six UserPromptSubmit hooks time out together, including two that touch no database and measure 25-140 ms alone; host IO pressure full ~13%. See the update at the end of 400.4-QA-SOURCE-F11-hook-timeouts.md.
- Decision: replace the six UserPromptSubmit entries in hooks/hooks.json with ONE entry that runs a new dispatcher script (scripts/userprompt-dispatch.cjs), which reads stdin once and runs, in-process and in the current order, admin-command-gate, intent-classifier, first-install-router, brain-derivation-drain, jtbd-update userprompt, auto-explore-drain. Each check runs under its own deadline; the whole dispatcher answers inside 2,500 ms and skips any check whose turn starts after the deadline, noting `skipped_deadline` on stderr. Output contract unchanged: the combined stdout must equal what the host received from the six separate hooks (same additionalContext order, same block decisions; a block from admin-command-gate still blocks). Each original script keeps working when run alone (export a run(input) function and keep the CLI main).
- The dispatcher is plumbing, not a new invocable surface (Part 11): no command, skill or agent is added. Windows: invoke with `node` the same way other node hooks in hooks.json are invoked.
- Phase 402 keeps consolidation for every other hook event; record the hand-off in the SUMMARY.
- Test: a parity test runs the six scripts separately and the dispatcher on the same inputs and asserts identical stdout and exit decision; a budget test asserts the dispatcher exits within 3,000 ms with room.db locked for 10 s.
