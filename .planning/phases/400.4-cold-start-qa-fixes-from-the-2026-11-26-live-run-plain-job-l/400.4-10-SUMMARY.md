# Phase 400.4 Plan 10: Hook-safe room.db busy wait (QA-F11 part A) Summary

Three UserPromptSubmit hooks that write room.db now check the write lock first with one 750 ms wait. When room.db stays busy they write `room_db_busy` to stderr, exit 0 and write nothing. intent-classifier starts as one node process and caps its room.db waits the same way. Under a 10 s lock every hook exited in about 0.9 to 1.1 s, against a 3 s budget.
