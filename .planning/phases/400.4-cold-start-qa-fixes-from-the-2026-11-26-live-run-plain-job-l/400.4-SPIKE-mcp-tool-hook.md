# Spike 2026-11-26: UserPromptSubmit hook of type mcp_tool (Claude Code CLI 2.1.332)

Spike dir (scratch, may be cleared): /tmp/claude-1000/-home-jsagi/e6ee814a-8860-471e-a60e-bee786b6a4fb/scratchpad/mcp-hook-spike/
Method: headless `claude -p ... --plugin-dir <scratch plugin> --model haiku --setting-sources project`; one stdio MCP server, one tool, a unique token per run.

## Results (all PROVEN)
1. The hook fires on every prompt and calls the plugin's own MCP tool (`server: "plugin:<plugin>:<server>"`). Debug: `Hooks: mcp_tool calling plugin:spikeplug:spikesrv/prompt_check with 1 arg(s)`.
2. CONTRACT: the model sees the result ONLY when the tool's text is the JSON `{"hookSpecificOutput":{"hookEventName":"UserPromptSubmit","additionalContext":"..."}}`. Plain-text tool output is recorded as stdout but the attachment content is the fixed string "UserPromptSubmit completed", so the model gets nothing (reply NONE). A command hook with the same plain text does reach the model. This contradicts the hooks docs ("treated like command-hook stdout").
3. Latency: hook round trip 14-35 ms (tool body under 1 ms). Server cold connect about 20 ms isolated, about 3.2 s with the full installed setup.
4. Lifetime: one server process (same pid) served two prompts in one session; SIGINT at session end.
5. Failure modes: tool slower than the hook timeout -> `hook_cancelled`, prompt proceeds, model sees nothing; tool isError -> `hook_non_blocking_error`, prompt proceeds, model sees nothing. No honest-refusal signal reaches the model.
6. `"input": {"prompt": "${prompt}"}` passes the full user prompt.

## Not verified
First-prompt wait on a slow-starting server (suggested by a 98 ms gap, not forced); interactive TTY; `--resume`; Desktop and Cowork; `onFailure: "block"`; whether a tool result can carry a block decision; models other than haiku.

## Consequence for plans 12 and 13
- The routable checks (brain-derivation-drain, auto-explore-drain, jtbd-update, intent-classifier) can run inside the already-running MindrianOS MCP server through one mcp_tool hook, returning the JSON additionalContext shape, with no cold start per prompt and no cross-process room.db lock wait (the server is itself a room.db writer).

- Every mcp_tool result must use the JSON shape; a test must pin it (plain text is silently dropped).
