# Phase 400.4 Plan 12: run(input, opts) exports for the six UserPromptSubmit scripts (QA-F11 base) Summary

## What changed

- `lib/core/hook-io.cjs`: `HookExit`, `makeSink()` (`out`, `err`, `take(code)`), `finishCli(result)` (stdout, then stderr, then `process.exit(code)` after both flushed). `grep -c "require(" lib/core/hook-io.cjs` prints 0.
- The five small scripts: every `process.exit`, `process.stdout.write` and `process.stderr.write` on the run path is now a sink write plus `throw new HookExit(code)`. The stdin read, the module-load main and the `uncaughtException` backstop moved under `require.main === module`. The plan 10 write-lock gate stays inside run(): a busy room.db gives code 0, a `room_db_busy` note in stderr and no write.
- jtbd-update: the three top-level module loads that exit on failure moved into `ensureDeps(sink)` (same stderr note, code 0). The stdin read stays lazy in the CLI (it never reads fd 0 when the env var wins), and run() hands out its input once, as a second read of a pipe gave '' before.
- first-install-router: the emit helpers write to a module sink and throw HookExit(0). The one `catch` that wrapped an emit (`_deliverVerifyInsight`) now rethrows HookExit.
- brain-derivation-drain: the async main moved under `require.main === module`; the hook mode is `run()`. `--single` and `--dry-run` keep their CLI paths. The detached children keep `process.execPath`, the same script path and the same arguments.
- intent-classifier: `STDIN_RAW`, `STDIN_MESSAGE`, `STDIN_SESSION_ID`, `TURN_IS_HARNESS` and `STDIN_CWD` are `let` values set by `setTurnInput(raw)`; the session-binding memo is reset there too. The 11 `process.stdout.write` sites call one writer `OUT`. The MINTO drain block is `mintoDrainFirst()`, called at the start of `runTurn()` (drain first, then classify, then await the navigation engine block). `run()` swaps in a sink, serializes calls, and treats `opts.deadlineAt` as advisory. The engine closure keeps the writer of its own turn, so a late write after an abandoned run goes to a dead sink, not to the process stream.

## Masks used by the test

1. The fixture copy root path becomes `<ROOT>` (each run uses a fresh copy of a fixture under the OS temp dir; root names have equal length so a byte replace keeps sqlite files valid).
2. Node process warning lines (a line starting with `(node:PID)`, and the `--trace-warnings` hint) are dropped. The CLI shows them; a sink never does. This was found by the first `--capture` run (intent-classifier E3, E4, E5 differed only in the PID of a circular-dependency warning).
3. ISO timestamps become `<TS>`.
4. A number followed by `ms` becomes `<N>ms`.

After these, every case was stable across two capture runs.

## Risks and hand-off to Phase 400.5

- Process-wide state used by run(): `setHookBusyCap(750)` (the cap module state, plan 10) is set inside the room.db gates of the three writers and inside `runTurn()`. In a long-lived server a tripped cap stays tripped. Phase 400.5 must decide whether the server resets it per prompt or runs these scripts with the cap on purpose.
- `process.env` writes remain: the classifier deletes `MOS_MINTO_DRAIN_ROOM` after reading it and bridges `MINDRIAN_ROOMS_ROOT` to `MINDRIAN_ROOMS_HOME`. The old plan 13 text said the caller restores env after each check.
- `auto-explore-drain` takes its room from `MINDRIAN_ROOM_DIR` or `process.cwd()`. A server caller must set the cwd or the env value, or pass it in a later change. The input payload `cwd` is not used by this script (same as before).
- `first-install-router` runs `spawnSync('bash', [check-onboard])` (400 ms timeout) on a first-install turn. Inside a server this blocks the event loop for up to 400 ms.
- The golden covers 6 cases. Router phases after the first turn (reward and investment legs) are covered by the existing 267.2 tests, which pass unchanged, not by the golden.
- `hooks/hooks.json` is unchanged (`git diff 0000709bd HEAD -- hooks/hooks.json` is empty).
