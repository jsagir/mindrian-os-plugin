# Phase 400.4 Plan 03: Cortex leg cap and honest reply-size estimate Summary

context_assemble now keeps at most `cortex_k` cortex nodes (default 40, max 500), most recent first. It reports the cut in `_meta.omitted`, and `estimate_only` replies carry `_meta.reply_bytes_estimate`, measured from the same JSON serialisation as the real reply.

## Accomplishments

- Task 1 (TDD): RED commit 1fac55048 (C1 failed: 122 rows, expected 40). GREEN commit 11a643855. In legD the cap is a slice after `rankByRecency`. A per-call holder carries the cap and the total. `_meta.cortexK` and `_meta.cortexTotal` exist only when a cap was requested and sit before `omitted`, so `omitted` stays last. The estimate-mode body moved into the exported pure `toEstimateResult`; the 372 golden compares clean (10 calls).
- Task 2: commit 2a38da3fb. `cortex_k` (zod int 1 to 500) on `context_assemble`; the handler always assembles with `estimateOnly: false`, measures `Buffer.byteLength(JSON.stringify(payload, null, 2))`, then either sets `_meta.reply_bytes` (real reply) or runs `toEstimateResult`, nulls the brief text, rebuilds the payload and sets `_meta.reply_bytes_estimate`. One sentence added to the tool description; every existing sentence kept.
