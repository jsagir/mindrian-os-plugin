## What changed in the SQL

- Anchor row gets `edge_dirs = json_array()` and `direction_in = NULL`.
- Outbound arm: `JOIN edges e ON e.source = nh.id`, next node is `e.target`, appends 'out'.
- Inbound arm: `JOIN edges e ON e.target = nh.id`, next node is `e.source`, appends 'in'. The `e.target = nh.id` join uses idx_edges_target.
- Both arms keep `nh.depth < :max_depth` and the `json_array_length` bound; `nh.id != next_n.id` became `NOT EXISTS (SELECT 1 FROM json_each(nh.edge_path) WHERE json_each.value = next_n.id)`.
- The final SELECT adds `edge_dirs, direction_in`. The score expression is untouched. LIMIT :top_k stays. The focus id is still a named parameter.
- getNeighborhood maps `edgeDirs` (parsed) and `directionIn`; every existing key and position is kept.
