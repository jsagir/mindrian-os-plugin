<objective>
Give the session-start mode-selection Decision Gate a real, advisory-only, code-level firing
checkpoint (SPEC Requirement 1). Currently the gate (skills/conversation-mode/SKILL.md,
hitl_shape F.1) is enforced by prose alone; nothing anywhere records whether it fired or a
default was explicitly stated, so a silent skip is structurally invisible. This plan builds the
two net-new pieces that make a silent skip DETECTABLE: a session-scoped sidechannel store
(mirroring lib/core/card-fire-sidechannel.cjs's pattern, not its file or TTL, per D-01/D-02) and
a doctor.cjs check-only module that reads it (D-04/D-05). Wiring the actual call sites
(selector-dispatcher.cjs and conversation-mode.md's default-stated branch) is plan 227-04, which
depends on this plan's exports existing first.

Purpose: close gap 3 of intern-w1-mode-gate-skip.md's confirmed root cause (RESOLVED
2026-07-11, gaps 1-2 already fixed): give the mode-selection gate an actual code-level firing
checkpoint, so a silent skip has something structural to catch, not just prose.

Output: lib/core/mode-select-sidechannel.cjs, lib/core/doctor/mode-select-checkpoint-module.cjs,

## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| local filesystem, mode-select-lane-picks.json | a new local sidechannel file, single-user machine, no network, no multi-tenant access |
| doctor.cjs check module reading a corrupt or adversarial store file | the runner reads a JSON file that could in principle be hand-edited or corrupted between writes |
| environment variable input (CLAUDE_SESSION_ID, MODE_SELECT_SIDECHANNEL_PATH, MINDRIAN_HOME) | process.env values trusted as session and path hints, the same trust level this codebase already extends to CLAUDE_SESSION_ID and MINDRIAN_HOME everywhere else |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|------------------|
| T-227-01 | Tampering | mode-select-lane-picks.json | accept | single-user local machine, advisory-only signal that never gates a security decision or a hard-fail; a forged or deleted record only ever produces an extra advisory warn line in a doctor report, never a blocked action |
| T-227-02 | Denial of Service | mode-select-sidechannel.cjs writeStoreAtomic | mitigate | 64KB size cap with oldest-first truncation, mirroring card-fire-sidechannel.cjs's existing bound, plus a 24h TTL prune on every read, so the file cannot grow unbounded across many sessions |
| T-227-03 | Tampering leading to a crash | mode-select-checkpoint-module.cjs check reading a corrupt or malformed store file | mitigate | every fs and require operation wrapped in try/catch, degrades to a warn finding rather than throwing, the never-throw contract, task 3 behavior (d) tests this explicitly |
| T-227-04 | Information Disclosure | the record schema (lane, ts) | accept | the record carries only a generic enum-shaped scalar and an epoch timestamp, zero user text, zero room content, zero Brain egress per Canon Part 8, nothing to disclose |
| T-227-05 | Elevation of Privilege | doctor check escalating to a hard-fail | mitigate | fix_supported is false, so no auto-remediation path exists to abuse, and the check always returns ok or warn, never error or non-zero on its own, honoring the Phase 210 advisory-only precedent this phase must not violate |
