<objective>
Close finding F-2: the severity ladder makes the critical-repair enqueue gate unreachable for the two breaches navigators actually hit.

The gate at `runSessionStart` fires only on `result.severity === 'critical'`. Today, neither breach ever reaches it:

- **Missing MINTO.md.** `validateSection` emits a purpose-built synthetic existence violation hardcoded to severity `error`. The registered wrapper validator `lib/memory/validators/minto-invariants.cjs` deliberately short-circuits a missing file to `{severity: null, violations: []}`, so the underlying content validator's own file-not-found CRITICAL never runs on this path. The guardian's synthetic violation is the ONLY signal, and it is one rung too low.
- **Missing or empty `governing_thought`.** `lib/core/feynman-minto-invariants.cjs` records it at `SEVERITY.ERROR`. This path does run, because it fires on an EXISTING MINTO.md with a missing field, and it too stops one rung short.

Net effect, as the RCA's second finding put it: only a zero-byte MINTO or an orphan temp-marker file ever reaches critical, so the repair ladder is unreachable for everything else.

Purpose: satisfy success criterion 2. SC2 requires a repair or escalation to be RECORDED, not just relabelled, so both legs assert the enqueue actually happened and landed in the queue file.

Output: a severity ladder whose top rung is reachable by real breaches.

**Resolution R-05, and the two places NOT to fix this.** RESEARCH.md's anti-pattern list is explicit and this plan honors it. Do NOT delete the short-circuit in `lib/memory/validators/minto-invariants.cjs`; its comment states a real design reason (it is a content validator for an existing file) and two independent missing-file signals is intentional layering, not duplication to collapse. Do NOT raise the sibling `schema_version` check that sits immediately above `governing_thought` in the same function; RESEARCH.md's F-2 code map names only `governing_thought`, and widening scope here would change enqueue behavior for a breach nobody measured.

**Pitfall 5 is a first-class task, not a footnote.** Raising these two constants changes which scenarios reach the enqueue gate, and the enqueue gate lives in a different function from the constants. `lib/memory/feynman-minto-guardian.test.cjs` already asserts queue-file contents in several scenarios, including test 2, "all-valid rooms produce no enqueue," and test 4, "pre-commit: error severity exits 2." Both are candidates to flip. Task 3 exists to run the full suites BEFORE writing new assertions and reconcile every break deliberately.
</objective>
