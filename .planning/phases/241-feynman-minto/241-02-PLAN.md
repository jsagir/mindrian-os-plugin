<objective>
Close finding F-0 (the filed `minto-debounce-consumer-dead-end` RCA), and correct that RCA's central claim, which this plan's own file reads disproved.

**Resolution R-02, and a MANDATORY correction the executor must carry.** The RCA concluded the promised debounce consumer "was never wired," resting on one piece of evidence it called "decisive, not circumstantial": `grep -n "minto-debouncer|debounc" scripts/intent-classifier.cjs` returns zero hits. That grep is correct and the conclusion drawn from it is wrong. The UserPromptSubmit hook registered in `hooks/hooks.json` is `run-hook.cmd intent-classifier`, which runs `scripts/intent-classifier`, an EXTENSIONLESS BASH WRAPPER that is a different file from `scripts/intent-classifier.cjs`. That wrapper carries a live Phase 88-05 drain block (its lines 40 to 104) which drains with `olderThanMs: 30000` exactly as the debouncer's docstring promised, atomically appends the drained entries to `.mindrian/pending-tier1-regen.json`, and spawns `scripts/vault-section-minto-generator.cjs --write` detached for each drained section. It is covered by 7 tests in `lib/memory/debouncer-drain-at-prompt.test.cjs`, already registered in the runner at line 177. The consumer exists, acts, and is tested.

Therefore the phase does NOT wire a second consumer into `scripts/intent-classifier.cjs`. Doing so would duplicate a shipped mechanism (Canon Part 7, reuse before build) and would create two drains racing for the same queue in the same hook invocation. What survives from the RCA's Option B, unchanged and still real, is its paired minimal piece: **stop the unconditional `olderThanMs: 0` vacuum at BOTH stop-path sites.** Both sites drain with no consumer and no inspection of the returned array, so every entry younger than the consumer's 30-second threshold that happens to be alive at session stop is destroyed before the next prompt can act on it, and the `queue-health` validator's 500 and 1000 thresholds stay structurally unreachable. That half of the RCA's reasoning stands on its own evidence and is what this plan fixes.

Purpose: make the repair ladder genuinely reachable end to end, and replace a wrong finding with a measured one so the next reader is not misled a second time.

Output: two de-vacuumed stop paths, an honest summary line, a census test that would have caught the RCA's own methodology error, and a resolved RCA.

**Resolution R-02b, what replaces the drain.** Both sites switch to the debouncer's existing `peek(roomDir)` read-only accessor (already exported alongside `enqueue` and `drain`, so this is reuse, not new API) and report a real pending count. Neither site drains at all. The queue is then bounded by the live prompt-time consumer in normal operation and by the `queue-health` validator's alarm when that consumer is not reaching a room, which is exactly the signal the vacuum was suppressing. No new TTL tunable is introduced, because a TTL would reintroduce a silent discard under a different name.
</objective>
