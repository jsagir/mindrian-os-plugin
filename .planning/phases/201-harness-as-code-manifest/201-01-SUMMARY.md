# Phase 201 Plan 01: Declare the Runtime Surfaces in the Harness Manifest Summary

Extended the single `data/harness-manifest.json` (via the existing generator, not a fork) to declare the harness's four RUNTIME surfaces - the runChain spine, the decide() engine, the statusline cockpit, and the brain-orchestration reader - as digest-only `{ role, path, digest }` entries alongside the three DATA maps, with `--check` failing closed on any drift between a declared digest and its on-disk file.

## What shipped

- **`scripts/build-harness-manifest.cjs`** - added `RUNTIME_SURFACE_BINDINGS` (4 roles) + `buildSurfaceEntry()`; `buildManifest()`/`serializeManifest()` now emit a `runtime_surfaces` array; `runtime_surfaces` added to `NODE_FIELD_ALLOWLIST` as generic machinery; `validateManifest()` re-digests each surface file and pushes a role-named STALE finding on drift (UNRESOLVED on a missing file). The 3-branch main (default write / --check / --refresh) is intact; LOCAL only, node built-ins only.
- **`data/harness-manifest.json`** - regenerated: 3 data maps (byte-unchanged digests) + a new 4-entry `runtime_surfaces` block. Additive; D-166-03 preserved.
- **`lib/core/recipe-maps.cjs`** - `_loadManifest()` now surfaces `runtime_surfaces` (tolerant read, degrades to `[]`); the three read-joins (`postureForCommand` / `wiringForReach` / `rankedNextReach`) are byte-unchanged.
- **`tests/test-201-harness-manifest.cjs`** (new) - 5 assertions across the 3 tasks (declare, drift fail-closed, tolerant reader + regression guard).
- **`tests/run-all-201.sh`** - rewired the 201-01 legs from the removed sibling manifest to the single manifest + the new test.

## Deviations from Plan

**1. [Rule 1 - Bug / Canon compliance] Consolidated + removed a prior sibling-manifest fork.**
- **Found during:** Task 1 recon. A prior 201-01 attempt (commit `7dedd7bb`) had FORKED the runtime surfaces into a separate `data/harness-runtime-manifest.json` generated by a new `scripts/build-harness-runtime-manifest.cjs`, with its own test asserting `runtime_surfaces` must NOT appear in the main manifest.
- **Issue:** That directly contradicts the authoritative plan ("extend it, do not fork it"; runtime surfaces declared "IN ADDITION to the existing 3 data-map entries" in the SAME manifest) and Canon Part 11 (one governed path; the manifest is a descriptor, not a second registry). A second manifest declaring runtime surfaces IS a second registry.
- **Fix:** Put `runtime_surfaces` into the single `data/harness-manifest.json` via the existing generator (adding `runtime_surfaces` to `NODE_FIELD_ALLOWLIST` resolves the Part-8 boundary concern the fork was avoiding), then `git rm` the three fork artifacts and rewired `tests/run-all-201.sh`.
- **Files:** removed `scripts/build-harness-runtime-manifest.cjs`, `data/harness-runtime-manifest.json`, `tests/test-201-harness-runtime-manifest.cjs`.
- **Commit:** `5658c7b1`.

**2. [Commit granularity] Tasks 1 and 2 share one commit.**
- The plan lists a commit per task. Task 1 (the runtime_surfaces builder) and Task 2 (the `--check` drift branch) both modify the same generator function-set and the same test file, so they landed in one coherent commit (`5658c7b1`) rather than two artificially-split commits. Task 3 (the reader) is its own commit (`9cd97128`). All three tasks' substance is delivered and verified.
