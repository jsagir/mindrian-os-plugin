# Plan 84-04: Mullins 20-section scaffold JSON and loader

## Goal

Ship a declarative `skills/mullins-scaffold/scaffold.json` file listing the 20 canonical Mullins 7-domain venture assessment sections, and a small CJS loader at `lib/core/mullins-scaffold.cjs` exposing `listSections()`, `getSection(id)`, and `sectionExists(id)`. The scaffold is a template, not a mandatory skeleton: rooms that reference it get structure; rooms that do not are structurally unaffected. Closes SCOPE-NB-01 and SCOPE-NB-02. This is the writing-surface half of the Smart Notebook Co-Pilot Path C hybrid (the co-pilot inject channel lands in 84-05 and 84-06).

## Scope

1. Create `skills/mullins-scaffold/` directory with a `SKILL.md` stub identifying the scaffold and a `scaffold.json` data file.
2. The `scaffold.json` file is a single JSON document with top-level keys `version`, `generated_from`, and `sections`. Each `sections` entry has `id`, `domain`, `title`, `summary`, `prompt_hints` (array of short strings), and `related_sections` (array of other section ids). The 20 canonical sections are distributed across the 7 Mullins domains:
   - Market domain: `market-size`, `market-growth-rate`
   - Industry attractiveness domain: `industry-attractiveness`, `industry-life-cycle`
   - Target segment domain: `target-segment-benefit`, `target-segment-size-growth`
   - Industry dynamics (micro) domain: `five-forces`, `industry-dynamics`
   - Mission, aspirations, propensity domain: `mission-aspirations`, `risk-propensity`, `founder-fit`
   - Ability to execute domain: `critical-success-factors`, `execution-capability`, `margin-structure`
   - Connectedness (value-chain up, down, across) domain: `connections-upstream`, `connections-downstream`, `connections-across`, `ecosystem-position`, `deal-flow`, `brand-trust`

   Total count is exactly 20 sections. No section has a blank `title` or `summary`.
3. Create `lib/core/mullins-scaffold.cjs` (CJS, no new deps). The module:
   - Loads `scaffold.json` via `require(path.join(__dirname, '..', '..', 'skills', 'mullins-scaffold', 'scaffold.json'))` with a try/catch so missing file does not crash callers.
   - Exports `listSections()` returning an array of section objects (shallow clone so callers cannot mutate the module cache).
   - Exports `getSection(id)` returning the section object or `null` if not found.
   - Exports `sectionExists(id)` returning a boolean.
   - Each exported function returns the safe fallback (`[]`, `null`, `false`) on any internal error; failures go to stderr debug only.
4. JSDoc headers on the module and on each exported function, matching the style of existing `lib/core/*.cjs` modules (e.g. `lib/core/room-db.cjs` from 84-02).
5. Rigidity lock: the loader does NOT write anything to disk, does NOT materialize sections into a room, and does NOT touch STATE.md. Materialization is v1.10.9 scope.

## Out of Scope

- `/mos:organize --materialize-section` and `--show-scaffold` subcommands (deferred to v1.10.9)
- Writing scaffold rows into the `scaffold_log` table from 84-01 (that fires only when a section is actually materialized)
- Any change to STATE.md, ROOM.md, or room templates
- Translating or localizing scaffold content
- Any UI, wiki, or dashboard rendering of the scaffold

## Task Breakdown

1. Draft `scaffold.json` with 20 sections across 7 domains. Validate with `node -e "JSON.parse(require('fs').readFileSync('skills/mullins-scaffold/scaffold.json','utf8'))"`.
2. Write `skills/mullins-scaffold/SKILL.md` stub (title, one-paragraph description, pointer to `scaffold.json`).
3. Write `lib/core/mullins-scaffold.cjs` loader with the three exported helpers and JSDoc.
4. Manual smoke: `node -e "const m=require('./lib/core/mullins-scaffold');console.log(m.listSections().length, m.sectionExists('market-size'), m.getSection('industry-attractiveness'))"`. Expected output: `20 true {object}`.
5. Grep confirms zero em-dashes and zero emoji in new files.

## Risks

- Risk: section naming conflicts with future v1.10.9 materialization logic. Mitigation: section ids are kebab-case slugs, stable, documented in the JSON; materialization code in v1.10.9 will key off `id` fields only.
- Risk: JSON file grows without a schema, drifts. Mitigation: ship a single `version: 1` field so future migrations can detect and translate.
- Risk: loader is called before file exists (early hook path). Mitigation: try/catch with `[]`, `null`, `false` fallbacks.

## Deviation Notes

- Revision 1 plan for 84-04 referenced a Mullins scaffold without pinning a section count. This version pins exactly 20 sections per the spec's "Mullins 20-section scaffold" phrasing (spec Components item 1).
- Scaffold JSON and loader are shipped as separate artifacts so the data can evolve independently of the code.
