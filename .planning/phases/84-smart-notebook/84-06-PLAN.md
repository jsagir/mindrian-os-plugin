# Plan 84-06: UserPromptSubmit graph-findings injection via intent-classifier extension

## Goal

Extend `scripts/intent-classifier.cjs` (the Phase 83-07 deliverable) with an env-gated code path that reads the top 3 non-suppressed findings from the active room's `.proactive-intelligence.json` and emits them into the hook's stdout alongside the existing topic classification output. Default `MINDRIAN_COPILOT_INJECT_FINDINGS=1` (ON). Hardcoded top-3 cap is the suppression mechanism (Dependabot lesson: suppression from day one). Kill switch `MINDRIAN_COPILOT_INJECT_FINDINGS=0` restores byte-identical Phase 83 behavior. The existing 200ms budget still applies. On any internal error, the extension exits 0 silent, the user's prompt is never disrupted. Closes SCOPE-NB-08.

## Scope

1. Read `scripts/intent-classifier.cjs` (Phase 83-07 deliverable) end to end before editing. Understand the existing topic-classification flow, the existing stdout shape, and the existing 200ms budget discipline (timer, early-exit patterns).
2. Add a single new code block at the end of the existing classifier output, guarded by:
   ```js
   const injectFindings = process.env.MINDRIAN_COPILOT_INJECT_FINDINGS;
   const injectEnabled = injectFindings === undefined || injectFindings === '1' || injectFindings === 'true';
   ```
   Default ON: when the env var is unset OR set to `1` OR set to `true`, the extension fires. When the env var is `0` or `false` or any other value, the extension is BYTE-IDENTICAL skipped (no stdout write, no side effect). This is reviewer finding I3 in its updated form (gate is default-ON; kill switch restores Phase 83 exactness).
3. When enabled, the extension:
   - Resolves the active room via the same Phase 83 logic already in the classifier (reads `~/.claude/MindrianRooms/.rooms/registry.json` active field, or falls through silently if absent).
   - Opens `<activeRoomDir>/.proactive-intelligence.json` via `fs.readFileSync` + `JSON.parse`. On any error (missing file, parse failure, read permission) exits the block silently; no stdout, no stderr.
   - Picks the top 3 findings. "Top" means: filter to non-suppressed entries (the existing `suppressed` flag or repeat-count threshold used elsewhere), sort by `confidence` descending, take first 3.
   - Formats each finding as one short line: `[graph] {type}: {message}` (no em-dashes, no emoji). Writes them to stdout after the existing topic classification output, behind a heading line `GRAPH FINDINGS (top 3)`.
4. Hardcoded top-3 cap IS the suppression. No env var to raise it. No config file. Reviewer-flagged Dependabot case: push channels without built-in suppression become noise.
5. Budget discipline: if the existing topic classification already consumed >= 150ms of the 200ms budget, SKIP the graph-findings read entirely. Use the same timer primitive Phase 83-07 already uses; do not introduce a new timing library.
6. Failure discipline: ALL errors inside the new block are swallowed. The block writes nothing on failure. The classifier's existing topic classification output is untouched. Exit code 0.
7. Document the kill switch in a single comment above the new block:
   ```
   // Kill switch: set MINDRIAN_COPILOT_INJECT_FINDINGS=0 for byte-identical Phase 83 behavior.
   ```
   The CHANGELOG [1.10.8] entry (plan 84-10) will surface the env var publicly.

## Out of Scope

- Any change to the Phase 83-07 topic classification itself
- Raising or lowering the top-3 cap via config or env
- Writing anything to disk or to the graph
- Cross-room finding injection (findings are active-room-only; cross-room is v1.11.x)
- Decision provenance or edge citations in the injected message
- Confidence-based filtering (beyond the existing `suppressed` flag); v1.10.9 scope if noise proves to be an issue
- Dashboard intelligence strip live feed (v1.10.9+)

## Risks

- Risk: 200ms budget blown by JSON read under load. Mitigation: hard cap at 3 findings; read only as much of the JSON as needed; if topic classification already consumed >= 150ms, skip the graph-findings block entirely.
- Risk: corrupt JSON crashes the hook. Mitigation: full try/catch around read and parse; silent exit 0 on any error.
- Risk: kill switch default interpretation drift (e.g., a future dev reads `false` as a string and treats it as truthy). Mitigation: explicit `=== '0' || === 'false'` is the OFF path, everything else is ON; test case 9 in 84-08 validates byte-identical with kill switch.
- Risk: reviewer I3 flagged default-OFF for safety; spec inverted to default-ON after external research showed the 15-point LongMemEval gap. Mitigation: kill switch documented in CHANGELOG, escape hatch is always one env var away.
- Risk: injected findings include em-dashes or emoji from upstream cascade output. Mitigation: bash-script and graph-insight generators are controlled by MindrianOS code; neither path introduces em-dashes; the injection formatter uses explicit hyphens and plain text.
