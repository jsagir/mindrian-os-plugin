3. Content of the new sub-section (no em-dashes, no emoji, no en-dashes):

   ```markdown
   ### When memory is real (v1.10.8 and later)

   Starting in v1.10.8, some recall IS backed by real stored state. When a finding is surfaced to you via the UserPromptSubmit graph-findings injection (the `GRAPH FINDINGS (top 3)` block in additional context), that finding came from the per-room lazygraph via the `readGraphFindings()` bridge. In that case, the phrase "I have that in memory" or "the graph shows" is a TRUE statement and the honest response pattern is:

   - "The graph shows a contradiction between X and Y, surfaced {when}."
   - "That claim was previously contradicted by {stakeholder} per {edge type}."
   - "I have that connection in the room's graph; want the provenance?"

   STILL FORBIDDEN, even in v1.10.8 and later:

   1. Claiming cross-room recall. The graph is per-room. If the user asks about a different room, you do NOT have that in memory and the `### No fake recall` rule applies.
   2. Claiming recall from sealed rooms. Sealed-room content is structurally invisible via the Phase 83 scope-by-construction guard.
   3. Claiming older-than-history-limit recall. The `sinceTimestamp` watermark in `readGraphFindings()` caps how far back the bridge looks; anything older is not in working memory and the `### No fake recall` rule applies.
   4. Claiming recall from the SQLite voice_log without a matching injection. If the graph-findings block was not present in the prompt's additional context, you do NOT have that memory loaded and must search before claiming.

   The rule is: "I remember" is honest ONLY when the injected graph-findings block surfaced the claim. Everything else still follows `### No fake recall`.
   ```
