# Plan 84-07: Voice-log writer plus reader: memory-lifecycle stop population and on-stop surfacing

## Goal

Extend `scripts/memory-lifecycle.cjs` (the Phase 84-03 deliverable) so its `stop` subcommand populates the `voice_log` table with structured rows built from the session's fragment rows, not the current stub. Simultaneously extend `scripts/on-stop` so it reads the latest `voice_log` row for the closing session and surfaces a short session-summary line alongside the existing cascade output. Both the writer AND the reader ship in this plan. Shipping the writer without the reader would recreate the "nobody reads the store" anti-pattern Phase 84 was meant to fix (external research Q3 finding, spec Risk 5). Closes SCOPE-NB-09 and SCOPE-NB-10.

## Scope

### Part A: Writer (memory-lifecycle stop population)

1. Read `scripts/memory-lifecycle.cjs` (320 lines per 84-03 SUMMARY). Locate the existing `stop` subcommand that currently calls `writeVoiceLogStub()` from `memory-ops.cjs` (84-01 helper at L444-490).
2. Replace the stub write with a structured population built from the closing session's fragment rows:
   - Query `fragments` table for rows where `session_id = ?` ordered by `created_at ASC`. Cap at a sensible upper bound (e.g., 500 fragments; sessions with more get the last 500, stderr debug note).
   - Construct a single `voice_log` row containing:
     - `session_id` (FK)
     - `fragment_count` (int)
     - `first_fragment_at`, `last_fragment_at` (timestamps from fragment rows)
     - `summary` (a short text built from the first and last fragment contents, truncated to 500 chars; NOT an LLM call, just a naive concatenation with `...` between)
     - `topics` (JSON string of distinct `topic` fields from fragments, if the fragments table has a topic column; empty array otherwise)
     - `created_at` (`Date.now()`)
   - Use a new helper `writeVoiceLogRow(db, row)` added to `lib/core/memory-ops.cjs`. The stub helper `writeVoiceLogStub()` stays in place for backwards compat but is no longer called from `memory-lifecycle.cjs stop`.
3. Failure discipline: if fragment read fails or session id is missing, fall back to the existing stub behavior (single empty row with the session id). Never crash `stop`.
4. Add a new subcommand `read-voice-tail <session_id>` to `scripts/memory-lifecycle.cjs` that queries the latest `voice_log` row for the given session id and prints a single JSON line to stdout (machine-readable). Exits 0 with empty output if no row exists. This subcommand is the reader API surface for Part B.

### Part B: Reader (on-stop surfacing)

1. Read `scripts/on-stop` (bash). Locate the existing end-of-response summary block where STATE.md analytics are surfaced.
2. Add a new block BEFORE the existing analytics output:
   - Call `node scripts/memory-lifecycle.cjs read-voice-tail "$SESSION_ID"` (or however session id is resolved in on-stop today; inspect first).
   - Parse the single JSON line into a bash variable set.
   - If the JSON is empty, skip the block silently (fall through to existing analytics).
   - If the JSON is present, print a single human-readable line: `SESSION SUMMARY: {fragment_count} fragments, {first..last timespan}, summary: {truncated summary}`.
3. Failure discipline: if the read-voice-tail call fails, if node is missing, or if jq is not available for JSON parsing, skip the block silently. Use `|| true` on the command. Fall through to the existing analytics summary with zero user-visible change.
4. Keep the block lean: one node call, one summary line, no loops, no retries.

### Shared

- `memory-ops.cjs` gains one new helper `writeVoiceLogRow(db, row)` alongside the existing `writeVoiceLogStub()`. JSDoc, try/catch wrap, safe fallback.
- `memory-lifecycle.cjs` gains one new subcommand handler for `read-voice-tail`.
- No schema migration. The 84-01 `voice_log` schema already supports structured rows; only the write path changes.

## Out of Scope

- Any change to the 84-01 schema
- Voice-retrieval `scopedRead` primitive (deferred to v1.10.9)
- Cross-session voice-log aggregation or summary queries
- LLM-generated summaries (this plan uses naive string truncation)
- Voice-log entries written at times other than session stop (pre/post compact hooks stay as 84-03 left them)
- Dashboard or wiki surface of voice_log rows
- Any change to the `fragments` table itself

## Risks

- Risk: fragment rows have unexpected shape (topic column missing, or the fragments table has drifted). Mitigation: reader falls back to `[]` for missing columns; writer tolerates any subset of fragment fields.
- Risk: summary truncation to 500 chars cuts mid-UTF8. Mitigation: truncate on a codepoint boundary (`Array.from(str).slice(0, 500).join('')`) or pad to a safe round-down.
- Risk: `on-stop` jq parse fails on minified JSON with no whitespace. Mitigation: use node one-liner (`node -e "const j=JSON.parse(process.argv[1]);process.stdout.write(j.summary||'')"`) instead of jq, to avoid the jq dependency.
- Risk: writer without reader (anti-pattern). Mitigation: this plan ships both; neither half is considered done without the other. Spec Risk 5 is closed by this plan.
- Risk: session id resolution in `on-stop` is fragile. Mitigation: inspect current `on-stop` session id logic before writing; reuse the existing variable, do not introduce new resolution.

## Deviation Notes

- Revision 1 plan for 84-07 targeted a markdown voice-log writer and an intent-classifier augmentation. Spec reshape splits those concerns: intent-classifier is 84-06; voice-log writer+reader is this plan; the markdown writer is rolled into the structured voice_log row shape.
- `writeVoiceLogRow()` is additive alongside `writeVoiceLogStub()` so any early-hook code paths that still call the stub continue to work; only `memory-lifecycle.cjs stop` is rewritten to use the new helper.
