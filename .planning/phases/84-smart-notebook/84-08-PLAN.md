# Plan 84-08: Fixture-based tests for 84-04 through 84-07 plus 84-09 plus Phase 83 regression guard

## Goal

Provide node built-in `assert` based tests for every behavior introduced in plans 84-04, 84-05, 84-06, 84-07, and 84-09. Tests synthesize fixtures under `/tmp/84-test-fixtures/<uuid>/`, override `HOME`, `CLAUDE_CONFIG_DIR`, and `MINDRIAN_ROOMS_ROOT` into the fixture so nothing touches real user state, and register with `lib/memory/run-feynman-tests.cjs` using the same pattern as `test/83-*.test.cjs`. Tests also run the Phase 83 regression guard: the full existing runner must still go green with every new test file added. No jest, vitest, mocha, or ava. Closes SCOPE-NB-12 (the Phase 83 regression half) and jointly validates SCOPE-NB-03 through SCOPE-NB-10 and SCOPE-NB-14.

Note: plan 84-09 ships AFTER this plan, but its test fixtures are written here per the spec's Testing section so the behavior is validated before 84-10 releases v1.10.8 (spec Risk 8). The test file asserts on the behavior of the rewritten self-update script; if 84-09 has not landed yet, those specific test cases are marked pending via a `SKIP_SELF_UPDATE` env-gated skip and unskipped when 84-09 lands.

### Fixture-builder helpers

Implement shared helpers at the top of the test file:
- `mkFixtureDir()` returns a unique `/tmp/84-test-fixtures/<uuid>` path.
- `mkFixtureRoom(dir)` creates a minimal room with `.mindrian/room.db` initialized via `initMemorySchema()` and `initLazygraphSchema()`.
- `mkFixtureProactiveJson(roomDir, findings)` writes a `.proactive-intelligence.json` with the given findings array.
- `mkFixtureCache(dir, versions)` creates a fake `mos/<version>/` layout for self-update tests.
- Every test body wraps in `try { ... } finally { fs.rmSync(fixtureDir, {recursive:true, force:true}) }` to prevent cruft on failure.

## Risks

- Risk: running `scripts/on-stop` from a node test process introduces bash shell dependency. Mitigation: dev-env assumption (bash is available on Linux + macOS); skip the on-stop test on Windows if `process.platform === 'win32'`.
- Risk: the self-update fixture tests require a git operation. Mitigation: stub the git clone with a local-file copy source (e.g., point the clone URL at a local bare repo in the fixture, or mock the clone step via a `SELF_UPDATE_SOURCE_DIR` env override the rewritten script honors for testing).
- Risk: fixture cleanup leaves cruft under `/tmp` on test failure. Mitigation: every test body wraps in try/finally with `fs.rmSync(fixtureDir, {recursive:true, force:true})`.
- Risk: Phase 83 regression guard (case 15) double-runs the runner from inside a test, causing infinite recursion. Mitigation: run the runner in a child process with an env var `SKIP_META_REGRESSION=1` that the runner respects (add the check if not already present), or shell out to `node lib/memory/run-feynman-tests.cjs 83` to run only the Phase 83 subset.
- Risk: test timing flakiness when the cascade path involves the 200ms budget. Mitigation: use large timeouts (5s per test), synchronous fixture I/O, and deterministic `sinceTimestamp` (0) for bridge tests.
- Risk: reviewer finding I3 byte-identical assertion (case 9) fails on trailing newline differences. Mitigation: capture a fresh Phase 83 baseline from a canonical fixture before the byte-comparison, not a hand-written expected string.
