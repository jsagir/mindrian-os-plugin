The gate is not a scope reduction: the shape is always sent when the server accepts it, and the probe is tested offline with the capture server advertising both schemas.

Type rule on recommend_chain (plan check B2): Theo refuses a call whose problem_type differs from shape.problem_type (RECOMMEND_CHAIN_SHAPE_TYPE_CONFLICT_REFUSAL). When a validated shape is attached, the problem_type sent equals shape.problem_type and the envelope says problem_type_source signal; when the router rung and the room shape disagree, the shape's type is sent and the envelope evidence records rung_conflict: {router, shape}; two different types never ride on one call.

Builder placement (plan check F1, option a): the shim builds a shape only when CLAUDE_CODE_SESSION_ID is present and that session owns a bound room (plan 392-11 resolver, status bound, lexicon_scope session). Without a session id the shim sends a bare call (no shape) and runs the lexicon check against the machine-global active room, recording lexicon_scope machine_global in telemetry. On Claude Desktop and Cowork no plugin hook runs and no session id is exported, so the shim path there is today's machine-global behaviour in this phase; success criterion 5 is met on the CLI hook path; the mindrian-os server never builds the shape in this phase.
