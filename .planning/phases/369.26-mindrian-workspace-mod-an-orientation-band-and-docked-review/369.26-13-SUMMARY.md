# Phase 369.26 Plan 13: Sources tab Summary

**The Sources tab: the evidence behind waiting decisions listed by the artifacts' own heading titles and the folder each is stored in, readable in the pane (first 10,000 characters as Markdown, P107 when longer), with only what resolves through room_artifact ever drawn.**

## What was built

### Task 1: model, loader, reader, fixtures
- `loadSources(act)`: sample mode answers from the fixtures with no call. Live mode reads `gate_list` (via `fetchGates(act.io)`), takes the union of the open cards' evidence ids (deduplicated, only ids that could be a room-relative `.md` path, at most 10), probes each with `room_artifact` at `max_bytes` 4096, and keeps a row only when the artifact answered ok and has a first heading. `where` is the top-level folder segment as stored. The list is written to the `rows` key and returned.
- Result classes: clean refusals (`not_found`, `not_markdown`, `path_outside_room`) are dropped; transport failures (rejected, unreadable, `read_error`, `room_unbound`) are failures. Unavailable (M03) only when the list cannot be read or every probe failed; otherwise the rows that resolve (possibly none, which is P104).
- `openSource(act, row)`: reads with `max_bytes` 40000, keeps the first 10,000 characters (never splitting a surrogate pair), `isCut` true when longer or when the tool says it cut. A failed read, a refusal, a non-string body or a non-room path sets `{ state: 'unavailable', title }`. `closeReading(act)` writes `reading: null`.
- `firstHeading`: first ATX heading after any frontmatter, outside fences, max 120 characters; a carried twin of plan 12's `titleFromMarkdown` (not imported).
- Fixtures: every title and folder ends with (sample); the wide sample has three rows, one longer than 10,000 characters; `several` adds a fourth; `empty` and `noroom` are empty; `unreadable` is unavailable.

### Task 2: views
- `sourcesList(ctx, load)`: P100 panel; per row the title, P102 (when stored in a folder) and a P103 button keyed `source:<i>` with NO hotkey; P104 for empty, M03 for unavailable, heading only before the first load. Plain mode puts each row in a single-bordered Box and draws no color prop.
- `readingView(ctx, reading)`: P105, the title, the text as `Markdown` with no link handler, P107 when cut, the P106 Back button (key `sources:back`, hotkey `b`). An unreadable artifact says M03 and still offers Back.

### Task 3: body
- `sourcesBody`: view is the list or the reading; no room bound draws only P12; `keys` returns `b` H07 only while a reading is open; `explainId` X03; `onOpen` closes any reading then loads.

## Deviations from Plan

### Auto-fixed Issues (ENGINE-RULES wins over plan text)

**1. [Rule 3 - Blocking] loadSources reads `gate_list`, not `vm.gates`**
- **Found during:** Task 1.
- **Issue:** The plan says the list is the union of evidence ids across `vm.gates`, and also that only `room_artifact` is called. `onOpen(act)` has no `ctx`, so a loader cannot see `vm`; the kit offers no way to read the model.
- **Fix:** `loadSources(act)` calls the existing read-only `fetchGates(act.io)` (`gate_list`, no arguments, MINDRIAN_SERVER only) then `room_artifact`. The test asserts only those two tools, only the Mindrian server, and at most 10 probes. Nothing reaches the Brain.
- **Commits:** `29f29d9ce`.

**2. [Rule 2 - Missing critical] Ids that cannot be a room path are never sent**
- **Issue:** The plan sends every id to `room_artifact`. Opaque node ids would waste the 10-probe budget and ship an arbitrary string into a path argument.
- **Fix:** `isRoomMarkdownPath` filters before the cap: relative `.md` paths only, no `..`, no backslash, no drive or leading slash, no empty segment. The tool's own containment still stands behind it (T-369.26-13-01). `openSource` applies the same check to a row's path.

**3. [Interpretation] Views are `(ctx, data)` not `(el, ctx)`**
- Same as plan 11: `ctx` already carries `el`. Reused plan 11's `panel()` frame from `src/pane/room/panel.tsx` (reuse before build; not edited).

**4. [Interpretation] A file at the top of the room has no P102 line**
- `where` is `null` when the path has no folder; nothing is drawn instead of a guessed name.

**5. [Interpretation] Before the first live load only the heading is drawn**
- The deck has no "loading" wording; the heading alone is honest and brief. In sample mode the view reads the fixtures directly from `ctx.vm.sampleName`, so it never depends on a load having run.

**6. [Test environment] No `setTimeout` type**
- The mod's tsconfig has no DOM or Node types. Press-then-check arms use a `settle()` helper (a few microtask turns); the fake act never waits on a timer.
