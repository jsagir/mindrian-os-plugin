# Phase 369.26 Plan 14: Review tab, the docked decision card Summary

**The Review tab draws the waiting decision as the concept's compact card straight from the recorded contract (question, one suggestion only when recorded, up to three numbered choices, Decide later, one dim line naming the real key, expiry), presses the mod's one room write through plan 10's answer machine over a `body.review` slice, and cannot say "saved" before the runtime does.**

## What was built

- **review-io.ts (the adapter, route B).** `reviewIo(act, slice)` builds plan 10's `ReviewIo`: `mcpCall` is `act.io.mcpCall` (pinned to the Mindrian OS server by the kit), every write is `act.update('review', fn)`, `refresh` is `act.refresh`, `toast` is `act.toast`, `now` is `act.io.now`. `readReview(slice)` reads the slice back tolerantly (a damaged value reads as empty, never as saved). `runChoice` (press, then move the open card to the next waiting one and `act.focus` the tab strip), `runLater`, `runAsk`, `reopenCard`. Slice keys: `phase`, `lastResult`, `mirrors`, `dismissed`, `foreign`, `openCard`, `settled`.
- **The atomic claim under route B.** `claimSaving` runs plan 10's `claimSaving(rec, ...)` INSIDE the functional `act.update` (one `update($, bodyAtom, ...)` in the hook file, versioned, re-run on a version miss), and records what the function last saw in a closure variable; the last run is the committed one, and only the press whose own claim is the one stored goes on. The machine's in-process guard (no await before the check) stands beside it. Proved two ways: a pure arm (two presses at once on a recording act, one `gate_answer`) and a real-pane arm (two `ui.press` at once with a held answer, one `gate_answer`).
- **consequence.ts.** `isSavable` (single select, every drawn choice has a verdict; an approve on a card that runs work is not), `suggestedChoice` (recorded recommended choice if drawn, else first by rank), `consequenceFor` (D10, D11 or D12 plus the digit of that choice, null when nothing is savable).
- **expiry.ts.** `formatExpiry(ms)` is `HH:MM` from Date fields; `expiryWords` is P113, null when the card records no expiry.
- **choice-buttons.tsx.** One Button per recorded choice by rank (max three), key `choice:n`, digit hotkey only while the pane holds the keyboard, the recorded recommended one `variant="primary"`, the rest secondary. 72 columns or more: one row; under 72: stacked with D05 above (D05 also in plain mode). `CHOICE_FORM = 'boxed'` (single-border Box around a Button labeled `[n] label`) or `'plain'` (engine `n: label`, no Box); both forms drawn in a test.
- **proposal-card.tsx.** The card in the panel frame: question, suggestion line (U+25B6 or `>` in plain mode, D01, label, D03 with the recorded description else D04 dim), phase sentence (D23, D24 with label, D13, D26, D27, E01 to E07 on a `problem` block with cream words, D31 to D34), P114 and the P115 button for a foreign card, D30 for a read-only card, buttons, Decide later (D16, `d`), the dim consequence line, P113. `cardPlan` decides what is drawn; the key list reads the same plan.
- **decision-list.tsx and bodies/review.tsx.** `listState` (noroom, unreadable P112, empty P111, cards: waiting sorted soonest, open card, others), heading P110 or P116 with the real count, the others under P117 as buttons labeled by header (no hotkey), D14 in the card place when every card is set aside, the settled-answer sentence above the list. `reviewBody`: keys `1-n` H15, `d` H16, `i` H19 only when drawn; X04; `detailsExtra` lists each option description in full under D02; `onOpen` clears the settled mark and re-reads the live model (no call for a sample, like the Room tab).

### Auto-fixed Issues (ENGINE-RULES and the caller's binding facts win over plan text)

**1. [Rule 3 - Blocking] Route B, and the view functions take `(ctx, ...)` not `(el, ctx, ...)`**
- The plan's `ProposalCard(el, ctx, card, phase)` becomes `ProposalCard(ctx, card, heading, waiting)`: plan 11 settled that the context already carries `el`, and the card reads its phase from `ctx.body.review`. `ChoiceButtons(ctx, card, waiting, form?)`.

**2. [Rule 2 - Missing critical] The wide sample card could not be drawn with buttons**
- **Issue:** the sample card's option ids were `sample-gate-1-a/b/c`; only the first was in the card's `approving`, the others are in no verdict table, so by plan 10's rule the whole card was read-only (D30), and the plan's wide-sample behavior (three buttons) and the task 3 press check were impossible.
- **Fix:** `src/model/fixtures.ts` (plan 04's file, sample data only) now records the card as the concept shows it: ids `approve`, `defer`, `reject`, labels "Apply to the regional innovation grant (sample)", "Not yet, show me more (sample)", "No, leave this route out (sample)"; `approving: ['approve']`. Nothing else referenced those ids or labels. The `several` sample's second card (unclassified ids) and third card (a chain halt that resumes) stay read-only on purpose and exercise D30.
- **Commit:** `1bf2269b3`.

**3. [Rule 1 - Spec] Plain mode: the suggested choice is not `inverse`**
- A `Button` has no rest-state `inverse` (the declaration file offers it only inside `hover`), so UI-SPEC 12.2's "inverse" for the suggested choice cannot be drawn. In plain mode the suggested choice stays the primary Button, the suggestion line starts with a greater-than mark, and D05 is drawn. The test asserts exactly that. Noted in INTERIM.md.

**4. [Rule 3 - Blocking] Text carries no address in the engine**
- `key` on a `Text` is dropped, so a line a test must find sits in a keyed `Box` (`review:suggestion`, `review:consequence`, `review:expiry`, and so on). No behavior change.

**5. [Rule 3 - Blocking] The review-answer guard flagged `act.update(`**
- `tests/test-369.26-review-answer.cjs` (plan 10's file) forbade `update(` in `src/pane/review`. Under route B the adapter legitimately calls `act.update(...)`, a closure, not the engine's `update($, ref, fn)`. The regex now flags only a bare `atom(`, `update(` or `read(` (a member call is allowed); `from 'claude-code'` is still forbidden, so my files derive their drawn types from `ReturnType<typeof panel>` instead of importing the engine module. The other four arms of that guard are unchanged and pass.

**6. [Interpretation] Several smaller calls**
- `expiry.ts` was written in Task 1 (the card draws P113); the plan listed it under Task 2.
- A card the runtime answered (phase saved, copy not D13) leaves the waiting list at once: otherwise the sample, whose model never changes, and a failed re-read would keep a saved card on the list as waiting. Its sentence stays above the list until the tab is opened again (the `settled` slice key, plan 14's own).
- A refusal leaves the buttons drawn (so the person can try again; the runtime refuses again, never a false save). A finished stale check (D32 to D34) also keeps them; D31 hides them while the check runs. A foreign card draws P115 instead of choices. Saving hides Decide later too (a set-aside during an open call would only confuse).
- A wait that stays open (D13) does not move the open card; D24, D26 and D27 do.
- `onOpen` makes no live call for a sample (plan 11's existing test "a sample makes no call when a tab is pressed" requires it; the plan said `act.refresh()` unconditionally).
- The hint key for the digits is `1` for one choice, else `1-n`.
- After a save the engine focus key is `tab:review` in color mode and the first other tab in plain mode (the active tab is a label there), through the pure `tabFocusKey`.
