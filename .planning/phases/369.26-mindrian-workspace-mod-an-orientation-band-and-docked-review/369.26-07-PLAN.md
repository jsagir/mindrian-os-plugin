Engine facts read while planning (verify in the declaration file): `$.ui.open` is a request: with `focus` the surface focuses the pane only while the prompt has the keys over an empty composer, otherwise the pane opens without the keyboard; with a single open pane the engine draws no title (R-21 mostly answered, confirm in plan 17); `closeOnEscape` raises `ui.close` with origin `person` and "a hook may refuse that close and keep it open", which is the mechanism for "Esc closes the sub-panel first"; a Button's `hotkey` is armed only while its site holds the keyboard; `Pane` render props are title, isFocused, bodyColumns, placement (dock or inline) and scroll (no working flag: grep to confirm). A pane opened by the mod never sets `holdToasts` (a pane that stays open must not hold other plugins' toasts).

Decisions this plan fixes (Claude's discretion; UI-SPEC rulings preserved):
- `TabContext` narrows here to `{ $, el, vm: ViewModel, theme: Theme | null, mode: Mode, bodyColumns: number, isFocused: boolean, tab: TabId }`; `TabBody` gains an optional `detailsExtra(ctx)` (the Review tab puts option descriptions in details, UI-SPEC 13.2) and an optional `onOpen($)` that a body uses to load its own data; the shell calls it after a tab press and when the engine raises `ui.open` for PANE_ID with the active tab. This plan makes the one allowed edit of src/pane/types.ts (plan 01 owns it, plan 02 narrowed labelId).
- The shell draws the details button (P50 or P51) in every tab; its `s` hotkey is armed only in Room, Think and Sources (UI-SPEC 8.2 key table: `s` is not a Review key).
- The tab-specific keys in the hint line are dim TEXT (key letter plus its H label), because each tab body draws its own pressable buttons with those hotkeys and a letter must be unique among everything drawn at once (UI-SPEC 8.2). Shell-owned pressable buttons: Help (`h`), Explain (`e`, drawn in the hint line when the width allows and always inside the all-keys panel), details (`s` in three tabs).
- The workspace command (UI-SPEC 8.1, 12.1): `workspace` opens the pane at Review when the model says a decision waits, else Room; `workspace plain` flips plain mode; `workspace sample <name>` sets the sample atom to a name in SAMPLE_NAMES (an unknown name opens nothing and changes nothing); `workspace live` clears it. No deck entry exists for the command description or result lines (plan 02 OQ-13): the description is P00, the opened result is P00, the plain switch result is N01 (or P00 when turning it off), the sample switch result is N04.
- Working note: if the Pane props carry no working flag, P05 is driven by a `workingAtom` set true in `prompt.submit` and false in `turn.complete` hooks registered in src/registrars/pane.tsx.
