Facts measured while planning (re-read before use):
- `whitespace_scan` takes no arguments and answers `{ ok, room_dir, open_questions: [...], unsupported_claims: [...], gap_count }` (lib/mcp/tools/sensors.cjs lines 328-366). An unsupported claim is `{ claim: { id, type, sourcePath, reviewStatus, lastSeenAt }, missingEvidenceFor, standing, standing_words, explanation }` (lib/core/navigation/insights.cjs findUnsupportedClaims, lines 194-215): it carries NO plain title, only an opaque node id and a source path. Read `findOpenQuestions` in the same file for the open-question shape before using it.
- `room_artifact` takes `{ path (room-relative .md), max_bytes }` and returns the markdown for display (lib/mcp/tools/artifact-read.cjs); check whether a claim's `sourcePath` is room-relative before passing it, and drop it if it is not.
- The reasoning brief that should supply "what we think so far" and "the one gap that could change the decision" is planned in Phase 369.25 and not built; UI-SPEC 7.4 and 15 allow an INTERIM partial source: the governing text of the folder's reasoning file read as text. The reasoning file is `MINTO.md` in the folder; its front matter field `governing_thought` is the governing text (lib/core/feynman-minto-invariants.cjs lines 385-402). When 369.25's reader lands, only `readGoverningThought` in model.ts changes.

Decisions this plan fixes (Claude's discretion; UI-SPEC rulings preserved):
- Understanding: `governing_thought` read from `<folderDir>/MINTO.md` front matter with the same scalar parser plan 04's `parseRoomPurpose` uses (export a shared `frontMatterScalar` there only if plan 04 already exports it; otherwise copy the 10-line logic locally with a comment naming the source); ok gives the sentence as data and the jump button P73 (hotkey `v`, key `think:evidence`, runs `update($, tabAtom, () => 'sources')`); P72 ("Based on {n} pieces of evidence") is drawn only when a count is recorded, which no live source gives today, so live rooms never draw it; absent file or empty field gives not_recorded (M04) and no button; a read error gives unavailable (M03).
- Uncertainty (P74, yellow): data is the first open question's plain text from `whitespace_scan` when no brief exists; if the open-question node carries no plain text field it is not recorded (M04). P79 is never drawn in the interim (see must_haves).
- Gap list (P75 heading on `problem`, then up to 3 titles, then P76): titles come from `titleFromMarkdown(markdown)` (the first line starting with `# `, trimmed, at most 120 characters, markdown markers removed) over a `room_artifact` read with a small `max_bytes` (4096); at most 3 reads per load, results cached in the think state by path; unresolved points are counted in P76's n but never drawn; when the scan found points but none resolved, draw P75 and P76 with the real total as n; found none P77; scan failed M03.
- Load: `thinkBody.onOpen` calls `loadThink($)` which writes `thinkAtom` with `update`; the body renders from `thinkAtom` (sample mode reads `src/pane/think/fixtures.ts` through the same seam, no MCP call). The searching state (P78, fixture-only) is carried by the `several` sample so it is drawn somewhere in the render check.
- `keys(ctx)` returns `v` H17 when P73 is drawn (plan 16 adds g, w, a); `explainId` is X02.
