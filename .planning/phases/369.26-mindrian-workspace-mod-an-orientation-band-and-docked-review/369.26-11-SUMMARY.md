# Phase 369.26 Plan 11: Body kit and Room tab Summary

**The shared pane body kit (one generic `body` state key with `act.patch`, `act.update`, a server-pinned `act.io`, `refresh`, `readAsset`, `sampleName`, `focus`) and the Room tab built on it: where you are, what the folder is for, one next step with a button that only fills the prompt box, and what is waiting, each missing fact in its own words.**

## What was built

### Task 1: the body kit

- **State.** `types/state.d.ts` declares `body: Record<'room' | 'think' | 'sources' | 'review', { [key: string]: unknown }>` (an index signature, no nested `Record<string, unknown>`). `INITIAL.body` is one empty record per tab. The atom is declared once in `src/registrars/pane.tsx` (`key: 'body'` appears once). `claude plugin validate` lists `mindrian-workspace.body` as declared, read and written and lists no key named `Record`.
- **Pure half** (`src/pane/kit.ts`, no `$`, no atom, no hook): `mergeBody` (new record, other tabs are the same objects, an `undefined` value removes the key), `replaceBody`, `asBody` (repairs a stored value), `emptyBody`, `allowedServer` (true only for `MINDRIAN_SERVER`), `isAssetName` (a bare name only: refuses empty, a slash either way, dot names, `..`).
- **Closures** (`makeAct` in `src/registrars/pane.tsx`, one spelling of every `$.noun.event`): `act.io` (a `LiveIo` whose `mcpCall` rejects, with no call, for any server but the Mindrian OS one), `act.patch(tab, partial)`, `act.update(tab, fn)`, `act.refresh()` (never rejects, writes the `viewModel` key), `act.readAsset(name)` (`${$.plugin.root}/assets/<name>`), `act.sampleName()`, `act.focus(key)`. `setTab` now uses `act.focus`.
- **Context.** `TabContext` gained `body` and `detailsOpen`; `PaneInput` gained `body`; the render hook reads the body atom (through `asBody`) and the shell fills `ctx.detailsOpen` from its own per-tab flag.

### Tasks 2 to 4: the Room tab

- **Where line** (`where-line.tsx`): P10 inside a folder, P11 at the top of the data room, P12 with no room bound, B14 when a part of the place cannot be read. Blue block with cream words and a bold label in color mode; the same words in plain mode with no color prop.
- **Purpose** (`job-panel.tsx`, P20): the purpose as `Text` (one line) or `Markdown` (several lines); M01, M02, M03 or M04 in the same place when it is not there. Never a related fact.
- **Next step** (`suggested-move.tsx`, P30): the step as data, then P31 with the reason or P32. A step not recorded (M04), unreadable (M03) or still being looked up (M04) draws NO button. The primary button P33 (`next:prefill`, hotkey `n`) runs `prefillRecorded(act, command)` when the model carries a recorded command, else `prefillPrompt(act, 'Q01')`. Both only fill the box and toast P34 or P35. A waiting decision never becomes the step.
- **Waiting** (`waiting-panel.tsx`, P40): P41 / P42 / P44 with the real count; an unreadable count is its own words. The P43 jump (`waiting:review`, hotkey `v`) is drawn only when at least one decision waits and runs `act.setTab('review')`.
- **Result panels** (`result-panel.tsx`, P55 and P56): drawn only when the review slice holds a recorded result (D24 with the label) and no card is saving; P56 is P41, P42 or P44 from the CURRENT model count, or M03 when it cannot be read.
- **roomBody**: where line, purpose, next step, waiting, result panels, then the reserved place for plan 15's P52. With no room bound it draws ONLY the where line (P12). `keys` returns `n` H01 then `v` H02, each only when its button is drawn (plan 15 inserts `m` H03 between). `explainId` is X01. `onOpen` calls `act.refresh()` for a live model and does nothing for a sample.
- **prefillRecorded(io, text)** in `src/runtime/prefill.ts`: fills the text unchanged, only when it is non-blank and at most 2000 characters, else adds nothing and toasts P35. `prefillPrompt` keeps its behavior (a shared private helper now carries the fill and toast).

## Deviations from Plan

### Auto-fixed Issues (ENGINE-RULES wins over plan text; caller's binding facts applied)

**1. [Rule 3 - Blocking] The closures' real-engine arms moved out of `pane-kit.test.tsx`**
- **Found during:** Task 1.
- **Issue:** The plan says the closures' real-engine arms run through the Room body in Task 4. I first wrote them as a test command hook that calls the exported `makeAct($)`. The engine refused every `$.state`, `$.mcp`, `$.fs` call from that hook ("its hooks module does not call it (host rule; the scan lists no calls)"): a test hook can use only the nouns the module's static scan lists, and the scan cannot follow `$` into an imported function.
- **Fix:** Removed those arms. The Room body proves `sampleName`, `refresh`, the server pin on the live path, `setTab`/`focus` through the real pane (Task 4). `patch`, `update`, `readAsset`, the pin's REFUSAL and `focus` are proved by `tests/test-369.26-body-kit.cjs`: it copies the mod to a temp dir, swaps the Think body for a probe body that runs every closure from `onOpen`, mounts the real pane and checks the result. Its mutation arm removes the pin in the copy and the probe fails. `makeAct` and `makeIo` are still exported from the registrar (the exports are harmless to the scan; nothing may import them).
- **Commits:** `2b16fb3bd`, `9eb069e4c`.

## Notes for later plans

1. **The kit is final for plans 12 to 15.** Use `ctx.body.<tab>`, `ctx.detailsOpen`, `act.patch`, `act.update`, `act.io`, `act.refresh`, `act.readAsset`, `act.sampleName` (await it), `act.focus`. Plan 16 adds only `act.guidance`. `prefillPrompt(act, id, data)` and `prefillRecorded(act, text)` take `act` as their `io`.
2. **A live room has no body until its model exists.** With no sample and no model read yet the shell draws only the tab strip and the hint line (plan 07's rule). Opening the pane through `workspace` runs `onOpen`, which refreshes the model, so the Room body then draws. Bodies that load their own slice in `onOpen` should treat "no model yet" the same way.
3. **Slice writes belong to presses, selects and `onOpen`, never a view (rule 4).** `mergeBody` drops a key written as `undefined`; clear a key by writing `undefined`, not `null`, unless a null is meant.
4. **Hotkeys `o`, `r`, `k`, `h`, `e` are reserved**; the Room tab uses `n`, `v`, `s` and (plan 15) `m`.
5. **Test idiom for a body that needs a closure which uses `$`:** a test hook cannot lend `$`; mount the real pane and drive it, or use the scratch-copy probe in `tests/test-369.26-body-kit.cjs` (swap a body, write a probe test, run `claude plugin test` on the copy). A press on a Button a test hook drew finds nothing, but its `onPress` is on the element object (`n.onPress`, with the key in `n.props.key`), so a pure arm can capture and call it.
6. **Plan 14, route A versus B:** see deviation 3 above. Route B (`body.review`, `act.update` for the claim) needs no hand-off; route A needs the mirror into `body.review.lastResult` and `body.review.phase`.
7. **Plan 15:** the P52 button and the list go where the comment in `room.tsx` sits (after the result panels); its `keys` entry `m` H03 goes between `n` and `v`.
