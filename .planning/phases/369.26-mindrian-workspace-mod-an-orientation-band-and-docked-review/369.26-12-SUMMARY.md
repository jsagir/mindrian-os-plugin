# Phase 369.26 Plan 12: Think core Summary

**The Think tab's first half: what we think so far (the folder's governing thought), what we are unsure about, and the points with no evidence yet (titles resolved from `whitespace_scan` through `room_artifact`), each from a named source or as its own missing-data words, with the yellow and red blocks as siblings.**

## What was built

### Task 1: model, fixtures, gap resolver

- **ThinkModel** (`model.ts`): three `Seen` fields. `understanding` is `Seen<{ sentence, evidenceCount }>`, `uncertainty` is `Seen<string>`, `gaps` is `Seen<{ points, total, more }>`. `isThinkState(slice)` narrows `ctx.body.think` and is false for a missing or malformed model. Plain JSON, no atom, no `.d.ts`.
- **Governing thought** (`readGoverningThought`): `<folderDir>/MINTO.md` front matter field `governing_thought`. A missing file, an empty field, a block-scalar indicator or no front matter reads not_recorded (M04); a read error reads unavailable (M03). `evidenceCount` is always null live, so P72 is never drawn live.
- **Open question** (`openQuestionText`): the first open question's plain text when its node carries a `text`, `title`, `label` or `question` field, else not_recorded. The node `findOpenQuestions` returns today has only an opaque id, a source path and a time, so live rooms read M04 here.
- **Gap resolver** (`gaps.ts`): one `whitespace_scan` (`scanRoom`), then up to three `room_artifact` reads (`path`, `max_bytes` 4096) for the first three distinct room-relative `.md` source paths. `titleFromMarkdown` takes the first `# ` line outside front matter and code fences, strips markers, cuts at 120. Titles are cached by path (`p:<path>`), a no-heading result is cached as null, a failed read is never cached. Points: at most three, one per artifact. `total` is the real count of unsupported claims and `more` is `total - points.length`, so unresolved points are in P76's n. A path that is absolute, has `..`, a scheme or drive prefix, or is not `.md` is counted and never read. A rejected, refused or misshapen scan is unavailable.
- **Loader** (`loadThink(act)`): sample mode writes `fixtureFor(name)` and makes no call; live mode resolves dirs through `resolveDirs(act.io)`, with no room bound it writes all-unavailable and makes no scan; otherwise it reads the governing thought, scans once, and writes `{ model, titleCache }` through `act.patch('think', ...)`. Never throws (a failure writes all-unavailable).
- **Picks**: `nextPicks` (toggle, at most two, drops the oldest), `togglePick(act, picks, title)` writes `{ picks }` through `act.patch`, `picksOf` keeps only still-drawn titles.
- **Fixtures**: wide (sentence, count 4, uncertainty, two titles, total 5, more 3), narrow = wide, missing (not recorded, gaps total 0), several (gaps searching, the one place P78 is drawn), unreadable (all unavailable); every other name draws wide. Every string ends with (sample).

### Task 2: panels

- `understandingPanel`: P70, the sentence, P72 only when a count is recorded, button P73 (key `think:evidence`, hotkey `v`) to Sources; missing states draw M04 or M03 and no button.
- `uncertaintyBlock`: yellow block with black words (P74 and the text); missing states sit on the cream page. No claim line is drawn.
- `gapList`: red block with cream words only when `total > 0` (P75, up to three pick rows, P76 with `more`); none found draws P75 and P77 on the cream page, unreadable draws M03; searching draws nothing. Pick rows are `Button plain` with key `pick:<i>`, no hotkey.
- `stateNote`: P78 while searching; a red 2-cell mark plus the words of P75 when a gap exists; else nothing.
- Plain mode: bordered Boxes with the heading words, no color prop anywhere (tested on four surfaces).

### Task 3: thinkBody

Order: understanding, state note, then a container (`think:blocks`) holding the yellow block and the red list as siblings, side by side from 72 columns and stacked below. No room bound draws only P12. `keys` returns `v` H17 only when P73 is drawn; `explainId` X02. `onOpen` runs `act.refresh()` for a live room (never for a sample) then `loadThink(act)`.

## Deviations from Plan

### Auto-fixed Issues (ENGINE-RULES wins over plan text)

**1. [Rule 3 - Blocking] The loader's tool list includes `status_read`**
- The plan's acceptance says the only tools called are `whitespace_scan` and `room_artifact`, and also says to use `resolveDirs(act.io)`, which makes one `status_read` call. The test asserts the set is exactly `status_read`, `whitespace_scan`, `room_artifact`, all on `MINDRIAN_SERVER`, none on the Brain server.

**2. [Rule 3 - Blocking] A picked gap title is marked by a Text, not by an `inverse` Button**
- `ButtonProps` has no `inverse` prop (checked in the laid declaration file). Each pick row is a `Box` holding a bracket mark `Text` (`[x]` picked with `inverse`, `[ ]` otherwise) and the plain Button. The marks are glyphs, not copy-deck words; the deck has no pick strings, as the plan says.

**3. [Rule 3 - Blocking] The title cache is read through `act.update`**
- `loadThink(act)` has no `ctx`, so it cannot read its own slice. `readTitleCache` calls `act.update('think', fn)` with a function that captures the slice and returns it unchanged. It rewrites the same value (one redundant redraw). Proved by a test that a second load with the cache in the slice makes no `room_artifact` call.

**4. [Rule 2 - Missing critical] `onOpen` also runs `act.refresh()` for a live room**
- With no sample and no model, the shell draws only the strip (plan 07 rule), so a pane opened straight on Think would never draw the body. Room's `onOpen` already refreshes; Think now does the same. A sample makes no call. All calls stay on the Mindrian OS server.

**5. [Interpretation] Red only when there is something to flag**
- The plan says the gap list is a red block. "None found" (P77) and "cannot read" (M03) sit on the cream page in plain words: red means "no evidence yet for these points", and painting an empty or unreadable result red would claim a gap that is not shown. While a search is under way the list is not drawn and the state note says P78.

**6. [Interpretation] Several claims in one artifact draw one title**
- Titles are one per distinct artifact path, so the same heading is not drawn twice; the extra claims count toward "and n more".
