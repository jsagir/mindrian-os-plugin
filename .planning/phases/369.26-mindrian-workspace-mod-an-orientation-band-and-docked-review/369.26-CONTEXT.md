<domain>
## Phase Boundary

Build a Claude Code mod (a hooks-module plugin, TypeScript `.tsx`, no DOM, no Node) that draws, natively in the terminal:

1. An orientation band above the prompt (`ui.render` on `AbovePrompt`): three rows at 110+ columns, one row at 55 columns, with the five-rectangle logo, the room the person is in, what the folder is for, the next step, health, context used, and decisions waiting.
2. A docked Pane (`ui.render` on `Pane`, id `mindrian-workspace`) with four tabs: Room, Think, Sources, Review. Review draws the decision card with one-press save.

Visual target (locked): `/home/jsagi/Downloads/mindrian-terminal-concepts/` wide.png, narrow.png, missing-data.png, prompts.txt. The UI-SPEC (`369.26-UI-SPEC.md`, 27 concept rulings C-01 to C-27, copy deck, states, keys) is the contract. Everything a person sees is a copy deck ID in plain English (navigator hard rule 2026-10-06; ICM is "data room" on screen).

This phase delivers: the mod, its tests (`claude plugin test`), a fixture-driven render of the three concept states, and the spike 008 render check (12 items in UI-SPEC 17.2) recorded with real results. It does NOT replace `statusLine` in settings.json (a mod cannot; the old bar stays as the fallback), does NOT run any command itself (it only prefills the prompt box), and does NOT write to any room except through the existing gate path (`gate_answer`).

</domain>

<decisions>
## Implementation Decisions

### Contract
- The UI-SPEC is locked as written: copy deck IDs only, zero hex literals in source (colors read from `references/visual/palette.json` at run time), muted/grey hue not used, red only for broken, refusal, error and the no-evidence list, green only in the logo.
- Band yields completely when `hasSurvey` is true; reads `maxRows` and `bodyColumns` from props only; no animation.
- Pane opens only from a person's action (the `o` key, the workspace command), so it seats at any width; Esc closes it.
- Nothing optimistic: "saved" shows only after the runtime confirms; a render hook never writes.
- Tabs: Room / Think / Sources / Review (C rulings), no digit hotkeys. Band keys default to `o` open workspace and `h` get help.
- Decision card: options from the recorded gate card only, `[1]` to `[3]` plus mod-owned `[d]` decide later, one press saves through `gate_answer`; multi-answer cards stay in the conversation's own dialog.

### Build
- Mod is a walled-off package at `ui/mindrian-workspace-mod/` (own package.json, tsconfig, tests; never in the root package.json), loaded in dev with `claude --plugin-dir`. Shipping inside the plugin install is deferred (OQ-12).
- Sources the mod can honestly read first: `status_read` room binding, `$.session.usage()` context percent, `gate_list`, `~/.mindrian/room-health.json`, folder `ROOM.md` purpose. Sources that do not exist yet (next move, understanding, uncertainty: 369.25 reader) draw the recorded-missing states (M01 to M04), never a guess. Fixture mode feeds the three concept states for the render check and tests.
- Test every state with `mount` per surface (terminal, desktop) in `*.test.ts` run by `claude plugin test`; `claude plugin validate` must pass; `tsc -p` clean.
- GSD owns all edits; commits use `--only`; two sessions share the tree.

### Claude's Discretion
- File layout inside the package, atom naming, adapter/test fixture shape, wave order (adapter and theme first, band, pane shell, tabs, decision card, render check).
- Resolution of OQ-01 to OQ-12 defaults stay as the spec's rulings until the navigator answers; any answer is a one-line copy-deck or ruling change, not a redesign.

</decisions>
