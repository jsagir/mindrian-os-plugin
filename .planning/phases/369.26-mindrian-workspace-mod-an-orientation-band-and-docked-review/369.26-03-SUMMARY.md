## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] The engine's static scan refuses `$` crossing an import; the plan's `resolveMode($)` and `loadTheme($)` call shape cannot be used from another file**
- **Found during:** Task 3 (tests failed, then a scratch plugin reproduced it)
- **Issue (three measured facts, scratch plugin under the real `claude plugin validate` and `claude plugin test`):**
  1. `$` is followed only into a function declared in the SAME file. A hooks module that calls an imported `resolveMode($)` fails to load: "`$` is passed to "resolveMode", imported from "./theme/plain": `$` is followed only into a function declared in this same file, never across an import". An imported function used AS the hook (`on('ui.render', {...}, hook)`, with `$` as the hook's own parameter and `$.store.get` inside it or inside a function declared in that file) is fine.
  2. `update($, atom, fn)` and `read($, atom)` need the atom (or a literal `{ plugin, key }` reference) spelled in the same file: an atom imported from `state/atoms.ts` fails ("the state library's update takes a source the scan can read ... written there or in a const of this file").
  3. The test `$` of `claude plugin test` is the engine's own: it has no `store`, `env`, `fs`, `state` or `plugin` noun, so a test cannot call `resolveMode($)` with `mock.env`/`mock.store` and an `on('fs.read')` hook. Those mocks only answer a plugin's own `$` inside a mounted hook. Also: a render hook may not write state (the engine skips it: "drawing is pure").
- **Fix:** logic split so nothing in an imported module needs `$`: `parseTheme(raw)` and `decideMode({ switchOn, paletteText, noColor, term })` are pure and are what other plans call; `resolveMode($)`, `setPlain($, on)` and `loadTheme($)` keep their `$` reads and writes inside their own files (valid for a hook declared in that file). `setPlain` writes state with `$.state.set({ plugin, key } as const, on)` rather than `update(plainAtom, ...)`. Tests exercise the pure parts (23 tests, all five trigger cases, the trigger order, the no-color-key walk).
- **Engine wiring evidence:** a scratch plugin (not committed) put a hook in the same file as `resolveMode`, mounted `AbovePrompt` under `mock.env`, `mock.store` and an `on('fs.read')` hook, and drew: color mode with the six job colors; `NO_COLOR=1` gave `{ plain: true, note: N01 }`; a denied palette read gave `{ plain: true, note: N03, theme: null }`. Its `claude plugin validate` listed `env reads: NO_COLOR, TERM`, `$.fs.read`, `$.store.get`, `$.store.set`, `$.state.set` and `state writes: mindrian-workspace.plain`.
- **Files modified:** `src/theme/theme.ts`, `src/theme/plain.ts`, `tests/theme.test.ts`
- **Commits:** `cfb8d02fa`, `41593dcee`
