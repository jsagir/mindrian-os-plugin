# Phase 369.26 Plan 15: Registry-backed "More things to do here" Summary

**The Room tab now offers every non-methodology command in the registry, collapsed behind one m press, filterable by folder, each with its one-line plain reason and an "Add to my prompt" button that only fills the prompt box; counts and names are read at run time from guarded copies of the registry and job canon.**

## What was built

- **Assets (task 1).** `sync-assets.cjs` gained the two pairs; `assets/command-registry.json` and `assets/section-job-canon.json` are byte copies of `data/`. `tests/test-369.26-registry-sync.cjs` (8 arms) keeps them byte-equal (failure message names the fix command), checks the field contract, prints the facts below, and asserts no registry count is written into the mod and no `hitl_shape` or `prompt.submit` appears in `src/`.
- **Model (task 2).** `registry-model.ts` is pure over `act.readAsset`. `parseActions` never throws (bad JSON or wrong shape reads as unavailable, M03). `filterRows`, `canonFolder`, `effectiveFilter` (default: the current folder when the canon knows it, else All), `toggleActions` (open writes the flag first, reads the registry once, caches it; a failed read is retried on the next open), `pickFolder` (an unknown folder is ignored).
- **View.** `action-list.tsx`: heading P123, P120 label with a `Select` (terminal, desktop, vscode) or one button per option (mobile), first option P121, then the canon's folders as stored; one row per command with the reason as data and a P122 button with no hotkey; P124 only while the shell's details are open for Room. A press calls `prefillRecorded(act, command)` with the registry's `command` text unchanged (it already carries the slash and namespace). No problem-type filter is drawn (R-11).
- **Room body (task 3).** P52 button (P53 open), key `room:actions`, hotkey `m`, after the result panels; the list draws under it only while open. Keys now `n`, `v`, `m` (UI-SPEC 8.4). `onOpen` closes the list every time the tab opens (sample or live).

## Deviations from Plan

**1. [Rule 3 - Blocking] Deck lacked the three-digit ids**
- Plan 02's deck and its guard read two-digit ids only, so UI-SPEC 9.3 P100 to P124 had no entry and `text('P122')` could not be written. Added all 22 (P100, P102 to P107, P110 to P117, P120 to P124, which plans 13 and 14 also need) to `src/copy/deck.ts` and widened the id pattern in `tests/test-369.26-copy.cjs` to two or three digits (A2 parity holds, 195 ids). Neither file is in `files_modified`. Commit `69525eae7`.

**2. [Rule 3 - Blocking] `TabContext.surface` (additive)**
- The resolved element table lists a `Select` on mobile (runtime) but the engine draws none, so `'Select' in el` cannot choose between a Select and buttons. Added an optional `surface` to `TabContext` (`src/pane/types.ts`) and set it in `buildPane` (`src/pane/pane.tsx`, one line). Optional, so existing contexts and tests are untouched. Kit files `registrars/pane.tsx` and `pane/kit.ts` were not touched.

**3. [Rule 3 - Blocking] The palette sync guard's scratch arm**
- `tests/test-369.26-palette-sync.cjs` builds a scratch repo with the old two pairs; with four pairs its "starts equal" step failed. The scratch repo now carries the registry pair too.

**4. [Interpretation] Registry fields**
- `serves_jtbd` is a list, so `ActionRow` holds `jobs: string[]` (plan said `job`). A row with a null `jtbd_summary` (4 rows) is not listed: the list gives a reason for every row, and the registry guard reports the missing reasons as information, not failure. The folder's second job counts too (the canon names one for competitive-analysis and strategy).
- Guard arm for counts: the whole `src/` is held to the total (114); the derived counts (80, 34) are held to the three action-list files only, because 80 is also the context-limit percentage elsewhere in the mod.
- A failed registry read is retried on the next open (plan said "once"); a good read is never repeated.

**5. [Plan 11 test edits, forced by the new key]** `tests/room-tab.test.tsx`: keys now `n, v, m` and the element budget expects `room:actions` among the four buttons; the wrapper box is keyed `actions:row` so the unchanged "room: panels in order" arm still holds. `tests/pane.test.tsx`: the Explain-on-the-line arm runs at 140 columns, because the Room hint line with `m: More things to do` no longer fits Explain at 100 and the shell moves it to the all-keys panel (UI-SPEC 8.4; `e` still works).
