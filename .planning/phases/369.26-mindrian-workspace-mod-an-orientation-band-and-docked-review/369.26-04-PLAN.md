- `ViewModel`: `source: 'live' | 'sample'`; `sampleName: SampleName | null`; `place: { isBound: boolean; registryFallback: boolean; room: Seen<string>; folder: Seen<string | null> }`; `purpose: Seen<string>`; `health: Seen<'sound' | 'drift' | 'broken'>`; `context: Seen<number>` (percent used, 0 to 100); `waiting: Seen<number>`; `gates: Seen<GateCard[]>` soonest expiry first; `next: { step: Seen<string>; reason: Seen<string>; command: string | null; method: Seen<string>; isLookingUp: boolean }`; `details: { reads: Seen<string[]>; writes: Seen<string[]>; updatedAt: Seen<number>; version: Seen<string>; files: Seen<string[]> }`; `readAt: number`. JSON data only (state values), `null` not `undefined`.
- `GateCard`: `{ gateId, kind, header, selectMode: 'single' | 'multi', options: GateOption[], approving: string[] | null, subjectNodeId: string | null, evidenceNodeIds: string[], mintedAt: number | null, expiresAt: number | null, resumes: boolean }` (`resumes` is true for a chain-halt card whose approval RUNS the halted step server-side, lib/mcp/tools/gate.cjs gate_answer description; plan 10 refuses to save an approve on it); `GateOption`: `{ id, label, description: string | null, rank: number | null, preview: string | null, recommended: boolean }`. Opaque node ids are carried but never drawn.
- Gate contract source: `gate_list` answers `{ ok, room, gates: [...], count }` where each gate is `boundRaised` in lib/core/navigation/room-projection.cjs (fields gate_id, kind, header, select_mode, options[{id,label,description,rank,preview,recommended}], recommended (null in practice), notice, approve_label, subject_node_id, evidence_node_ids, approving, framework, minted_at, expires_at, resumes). `status_read` answers `{ ok, segments: { room_binding: { bound, source, slug, registry_fallback, note? }, ... } }` (lib/mcp/session-room.cjs describeRoomBinding). MCP tool results arrive as `{ content: [{ type: 'text', text: '<json>' }], isError }`.
- `SampleName`: wide, narrow, missing, empty, noroom, limit, drift, broken, several, nofile, unreadable.

Decisions this plan fixes (Claude's discretion; CONTEXT "adapter/test fixture shape"):
- Sample selection order in `readViewModel`: the session atom `sampleAtom` (set by the `workspace sample` command, plan 07), then the environment variable `MOS_WORKSPACE_SAMPLE` read with `$.env.get('MOS_WORKSPACE_SAMPLE')` (a dev switch: tests seed it with `mock.env`, the render check starts the session with it set, no typing needed), then the live atom. A sample never persists across sessions (no `$.store`), so a forgotten fixture cannot outlive the session; the pane always shows N04 while `source` is `sample`.
- Fixture strings that name a folder, a purpose, a step or a card carry the suffix "(sample)" (UI-SPEC 10.3: the band carries it only in fixtures). The concept images' words are the layout target, not the fixture's exact strings.
- The folder rule is the UI-SPEC R-05 interim: the folder is the last path segment of the working directory when it is inside the room's directory, else null (top of the data room); one function (`placeFrom`) so plan 369.25's reader can replace it (OQ-08 default: the folder's own name as stored).
