Decisions this plan fixes (Claude's discretion; UI-SPEC rulings preserved):
- Layout (UI-SPEC 7.6 and 10.6): heading (P110 one, P116 several with the real count), the question (the card's header as data), the suggestion line (U+25B6, D01, the recommended option's label, then D03 "because {description}" when the option has a description else D04 as a dim line), the choice buttons, the consequence line, the expiry line P113 under the card. Pane width 72 or more: buttons in one row; 40 to 71: stacked one per row with D05 above (D05 is also drawn in plain mode). In plain mode the suggestion marker is a greater-than mark and the suggested button is `inverse`.
- Choice buttons: one per option in `choiceOptions(card)` order, numbered `[1]` to `[3]` by position, hotkey the digit (armed only when `ctx.isFocused`), the option with `recommended` is `variant="primary"` (the blue block in color mode, C-25), the others secondary. `CHOICE_FORM` is `'boxed'` (a single-border `Box` around a `Button` whose label is the option label, hotkey digit) or `'plain'` (the engine's plain `n: label`, no Box); the default is `'boxed'` per UI-SPEC C-27, and the task-3 render capture decides whether to flip it and records the result in INTERIM.md (UI-SPEC 17.2 item 6, R-22).
- Savability: a card is drawn with pressable choices only when it is `single` select, every drawn option has `verdictFor(card, option)` not null; otherwise the card is drawn read-only (heading, question, suggestion if any) with D30 where the buttons would be, plus the Decide later button, because the answer then belongs to the conversation. D30's first sentence says "more than one answer"; for an unclassified or runs-work card it is only a stand-in for words the deck does not have (plan 10 OQ-14 and OQ-15); this plan does not invent a string.
- Consequence line: `consequenceId(card, suggestedOption)` where the suggested option is the recorded recommended one, else the first by rank; the key in the sentence is that option's digit; for a card with no savable option none is drawn.
- Phase display (from plan 10's phase atom): ready draws the card; saving replaces the choice buttons with D23; saved shows D24, D13, D26 or D27 in place of the buttons; refused shows the E sentence in a `problem` block with cream words and keeps the card; checking shows D31 then D32, D33 or D34; foreign (card in `foreignAtom`) shows P114 and a P115 button (hotkey `i`, armed only when focused) that runs `mirrorHere`. A decide-later card shows D14 in its place and appears under P117.
- Decide later: Button D16, hotkey `d` (armed only when focused), always drawn, runs `decideLater`, writes nothing.
- Several waiting decisions: the open card is `openCardAtom` or the first non-dismissed by soonest expiry; the others are one Button each (labeled with the card's header, no hotkey) under P117; pressing one sets `openCardAtom`. After a save, `openCardAtom` moves to the next waiting card, else null, and focus returns to the tab strip (UI-SPEC 8.3: `$.ui.focus({ requestId, key: 'tab:review' })`; read its signature).
- Expiry: P113 "Open until {time}" with the local clock time of `expiresAt` formatted `HH:MM` (24-hour, built from Date fields because Intl may be absent; test with fixed values and a note that the zone is the engine's).
- Details: `detailsExtra` lists each option's description (the full text) under the shell's details button, so descriptions that do not fit the compact card are one press away (UI-SPEC 13.2).
- `keys(ctx)` returns, only when drawn: `1` to `3` as one entry H15, `d` H16, `i` H19; explainId X04. With nothing waiting the hint is Help only.
- onOpen: `refreshViewModel($)` so the waiting list is fresh when the tab opens.
