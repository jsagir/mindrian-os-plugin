# 369.26 Engine rules for the Mindrian Workspace mod

Measured against Claude Code 2.1.290 with `claude plugin validate`, `claude plugin test` and `tsc -p`, on 2026-10-06 (plans 01, 03, 04, then proved together in plan 01A). Every plan from 05 on follows this file. The kept proofs are in `tests/test-369.26-engine-rules.cjs` (it plants each mistake in a scratch copy and checks the engine still refuses it).

## The five rules

1. **`$` does not cross an import.** The scan follows `$` only into a function declared in the SAME file as the hook. Allowed: a helper declared in the hook's own file that takes `$`; an imported function used AS the hook itself (`on('ui.render', {...}, importedHook)`), with `$` as its own parameter; a registrar that receives `on` and registers the hook inside its own file (`registerBand(on, options)`). Refused: `await helper($)` where `helper` is imported ("$ is followed only into a function declared in this same file, never across an import"). `$` is always spelled `$.noun.event(...)` at the call site and `on` is always `on('<event>', hook)`.
2. **State needs a source the scan can read.** `read($, x)`, `update($, x, fn)`, `$.state.get(x)` and `atom(x, initial)` accept only (a) a literal reference `{ plugin: 'mindrian-workspace', key: 'tab' } as const` written at the call site, (b) a const of the same file that holds such a literal, or (c) an `atom(...)` declared in the same file. An atom or a reference imported from `src/state/atoms.ts` is refused ("a reference whose plugin and key are string literals ... written there or in a const of this file"), and so is `atom(importedRef, ...)`. The scan checks every module reachable by import, so one bad use in a file nobody calls still fails validate for the whole plugin. Plain data crosses an import fine, so `INITIAL.tab` imported from atoms.ts is fine as the second argument of `atom`.
3. **The state contract is named by the manifest and is self-contained.** Once any hook reads or writes state, `.claude-plugin/plugin.json` must carry `"types": "./types/state.d.ts"` (the value starts with `./`), and that d.ts must hold NO `import` ("`import` reaches outside the file"). The tab ids are written inline there as `'room' | 'think' | 'sources' | 'review'`; `tests/contract.test.ts` fails the type-check if the inline union drifts from `TAB_IDS` in `src/runtime/ids.ts`. A new state key is declared in `types/state.d.ts` and its starting value and reference added to `src/state/atoms.ts`.
4. **A render hook cannot write state.** The engine skips it ("drawing is pure"). Writes belong to command, press, key and select handlers, never to a `ui.render` hook.
5. **The engine's own test `$` lacks the env, fs, state, store and plugin nouns.** A test cannot call a `$`-taking function with `mock.env` or `mock.store`; those mocks answer a plugin's own `$` inside a mounted hook. Test pure functions directly; test a hook by mounting (`$.ui.mount`) or by driving its event (`$.command.run`), and answer what sits beneath the plugin yourself (`on('ui.open', ($, e) => ({ value: { isPlaced: true } }))`).

## Plan 01 facts

- **Extensionless imports.** `import { x } from './ids'` loads; so do a directory index and a spelled `.js`. `tsc` accepts extensionless and `.js`, and rejects `.ts` (TS5097). Use the extensionless form everywhere. A missing module fails loudly.
- **hooks.json.** `{ "modules": ["../src/register.tsx"] }`: an ARRAY holding exactly one path, resolved relative to `hooks/hooks.json`. A bare string and a second entry are both refused.
- **Test discovery.** `claude plugin test <dir>` runs every `*.test.ts` and `*.test.tsx` under the folder, each file in its own child. A test imports `claude-code/testing` and may import plugin source by relative path. Tests live in `tests/`.
- **Types laying.** The engine lays `.claude-plugin/types/` when a session loads the mod from a folder; `validate` and `test` do not. `scripts/lay-types.cjs` is the fallback and `scripts/typecheck.cjs` runs it first. The folder is gitignored and never committed (never `git add` the whole mod directory).

## Recipe: how to write a hook file

1. Put the hook in a registrar: `export const registerX: Register = (on, options) => { on('<event>', {matcher}, async ($, e, next) => { ... }) }`, and call it from `src/register.tsx`. A hook receives `($, e, next)`.
2. Everything that touches `$` (reads, writes, env, fs, ui) is written in that file: inline, or in a helper declared in that file. Pure logic (mappers, decisions, copy, theme) lives in other files and receives plain values, never `$`.
3. Declare each atom you read in the hook file with a literal reference; import only plain data (`INITIAL`).
4. Read in render hooks, write in handlers. Spell env names as string literals so validate lists them.
5. Run `claude plugin validate ui/mindrian-workspace-mod`, `claude plugin test ui/mindrian-workspace-mod` and `node ui/mindrian-workspace-mod/scripts/typecheck.cjs`.

Minimal valid example (a render hook that reads two state keys; validated, listed as `state reads: mindrian-workspace.plain, mindrian-workspace.tab`):

```tsx
import { atom, read } from 'claude-code'
import type { Register } from 'claude-code'

import { INITIAL } from '../state/atoms'

const tabAtom = atom({ plugin: 'mindrian-workspace', key: 'tab' } as const, INITIAL.tab)

export const registerBand: Register = (on) => {
  on('ui.render', { component: 'AbovePrompt' }, async ($, e, next) => {
    const tab = await read($, tabAtom)
    const plain = await read($, { plugin: 'mindrian-workspace', key: 'plain' } as const)
    // pure functions take tab and plain as values, never $
    return next(e)
  })
}
```

A handler that writes (a command or key hook), with the reference spelled inline:

```ts
await update($, { plugin: 'mindrian-workspace', key: 'tab' } as const, () => 'think')
await $.ui.open({ id: PANE_ID, title: text('P00'), focus: true, closeOnEscape: true })
```

`src/runtime/open-workspace.ts` is the worked example: `registerOpenWorkspace(on)` declares the `workspace` command hook and its `openOn($, tab)` helper in one file. Other files that need to open the pane write the two lines above inline.
