## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] The engine-laid `.claude-plugin/types/` folder was committed by `git add -f`**
- **Found during:** Task 1 commit
- **Issue:** the engine's `claude --plugin-dir` load (used to measure fact 4) laid the types folder, which carries its own `.gitignore` containing `*`. `git add -f ui/mindrian-workspace-mod` overrode it and staged about 20k lines of declaration files, contradicting the plan ("never committed").
- **Fix:** soft-reset my own unpushed commit (it was HEAD, nothing after it), unstaged the types folder, re-added only the intended paths with `git add -f <paths>` and recommitted with `--only`. Net result: the types folder is not tracked. Later commits add paths explicitly, never the whole package directory.
- **Commit:** `6dbeab6d5`

**2. [Rule 3 - Blocking] hooks.json `modules` must be an array**
- **Found during:** Task 1
- **Issue:** the plan said "one path"; a bare string is refused by `claude plugin validate`.
- **Fix:** `{ "modules": ["../src/register.tsx"] }`, recorded as engine fact 2.

**3. [Rule 2 - Missing] plugin.json author**
- `claude plugin validate` warned about no author; added `{ "name": "MindrianOS" }`.

**4. Smoke test shape**
- The plan said the smoke test asserts the engine's drawing is untouched. A test has nothing beneath the plugin (mounting with no `ui.render` below throws "no implementation for ui.render"), so the test registers its own marker row with `on('ui.render', ...)` standing for the engine and asserts it comes back unchanged. The tree the test hands back must be a plain `RenderElement`, so the file builds it with a function, not a const.
