# Mindrian Workspace - UI Design Contract

> Visual and interaction contract for the Mindrian Workspace: a compact band above the prompt and a pane workstation, drawn natively in the terminal by a Claude Code mod. Generated by gsd-ui-researcher, to be verified by gsd-ui-checker. This is a PRE-PHASE spec: it edits nothing under ROADMAP, STATE, REQUIREMENTS or phases.

> Precedence: the navigator's concept images are the visual target. Section 17 (Concept reconciliation) lists every place they differ from the first draft of this spec and gives a ruling for each. Where a ruling there differs from a component or table elsewhere in this file, the ruling is already applied in place and carries a marker such as "(C-09)". If a marker and a plain sentence ever disagree, section 17 governs. Nothing in the concept images has been rendered in a real mod yet: section 17.2 lists what the spike-008 rendered check must prove.

---

## How to read this spec (the plain-English rule)

Navigator rule, 2026-10-06 (hard): everything a person SEES is plain English in Larry's voice, warm, direct, conversational. No stack lingo on screen. Larry's voice here means short sentences in the second person, no praise, no grades, no sentence that starts with "I", no "great question".

Every section below carries one tag.

| Tag | Meaning | Jargon allowed? |
|---|---|---|
| [PLAIN] | Describes or lists what a person sees | No. Plain words only |
| [ENGINEERING] | Props, tools, files, sources, risks, compliance | Yes, but never copied onto the screen |

Rule for the component specs: every string a person can see is written as a copy deck ID (for example `B10`), never inline. The Copy deck (section 9) is the only place user-visible words live. A method name (a framework, a command) may appear on screen only inside a details view the person opens on purpose.

Illustrative text in this spec is sample text. It is always marked "(sample)" and never describes a real room.

## 1. Simplicity budget [PLAIN]

A first-time person looking at the default screen can answer four questions without help, and nothing else competes with them.

| Question | Where the answer is | Default view |
|---|---|---|
| Where am I? | the "You're in" block (C-03) | band row 1, pane top |
| What is this for? | the "This folder is for" block (C-04) | band row 2 (or pane) |
| What do I do next? | the "Next" block (the one reason sits in the pane, C-09) | band row 3 (or pane) |
| Is anything waiting on my decision? | the yellow "A decision is waiting" block (C-16) | band row 1 (or the one row when short) |

Everything else is one deliberate click away: the other pane tabs, "Show details", "More things to do here", "Help".

Countable ceilings (spec-declared budgets; the spike measures them on the fixture render; section 13 holds the per-view count):

| Budget | Ceiling |
|---|---|
| Distinct elements in the default band at 3 rows | 8 (logo, place, waiting, context with its bar, purpose, next, key hints, version only once a source is verified, OQ-04) |
| Distinct elements in the default band at 1 row | 4 (logo, place, waiting, help); a context or health block takes the waiting slot only when it needs the person (section 10.5) |
| Distinct elements in the default first tab of the pane | 6 (tab row, where-you-are line, purpose, next step, waiting, key hints) |
| Action buttons visible in the default first tab | 4 (add the step to my prompt box, look at this decision, more things to do here, show details); the first draft said 3 and undercounted the "more things" button, found by the clutter audit (section 13) |
| Words per colored block | one plain sentence or one word group; no block holds two ideas |
| Method or command names visible by default | 0 |
| Numbers visible by default | 2 (context used, decisions waiting); both read as words with the number inside |

A tile or panel that only makes sense to someone who knows the stack is removed or moved behind "Show details". The clutter audit (section 13) lists every element and its verdict.

## Design System [ENGINEERING]

| Property | Value |
|---|---|
| Tool | none (not a web UI; shadcn gate is not applicable: no React/Next/Vite app and no `components.json`) |
| Preset | not applicable |
| Component library | Claude Code mod element tables from `$.ui.resolve(e)`: `Box`, `Text`, `Button`, `Markdown`, `Select` for the first build (`Raster`, `Image` optional, terminal only) |
| Icon library | none. Glyphs only, from `references/visual/symbol-system.md`: `▶` (U+25B6, the suggested choice), `>` as the breadcrumb separator and the plain-mode marker, `·` (U+00B7) for the empty bar cells and the plain joiner. `▷` (U+25B7) is no longer used (the compact card has no other-choice rows, C-19). No emoji (ui-system rule). Color blocks are 2-cell Boxes with a background color |
| Font | the person's terminal font. The mod owns none. Canon v3 fonts cannot be honored (section 16) |
| Grid unit | one character cell wide by one terminal row tall |
| Theme | one semantic theme map (section "Color") read from `palette.json` at run time; no color value inside a component |

The mod is TypeScript (ES module, `.tsx`, `import type` from `claude-code`) in a walled-off package; hooks module only, no `import()`, no Node (reference.md: the module runs with no DOM and no Node, everything outside is through `$`).

## Spacing Scale [ENGINEERING]

Spacing is cells (columns) and rows, not pixels. The grid unit is one cell.

| Token | Value | Usage |
|---|---|---|
| xs | 0 | blocks touch; the black frame cell is the divider |
| sm | 1 column | gap between a mark and its word; padding inside a block (`paddingX={1}`) |
| md | 2 columns | gap between adjacent blocks in a row (`gap`) when width allows; width of a Larry mark (2 cells) |
| lg | 1 blank row | between panels in the pane (`marginBottom={1}` or a Box with `height={1}`) |
| xl | 2 blank rows | never used in the band; between the pane's header and its first panel only if the pane is taller than 24 rows |
| row | 1 row | band tile height (`height={1}`) |
| logo | 3 rows by 10 columns | the tall logo (section 6) |

Declared values are multiples of 1 cell (the terminal cannot subdivide a cell). The "multiples of 4px" rule from the template does not apply; the exception is stated here, not hidden. Touch targets: not applicable on a keyboard-first surface; on desktop and mobile the engine draws its own native button sizes.

Exceptions: the 10-column logo, and a 1-row band at maxRows 1.

## Typography [ENGINEERING]

The terminal has one size (one cell) and the mod cannot change font, size or line height. The template's "3 to 4 sizes, 2 weights" becomes four emphasis roles over exactly two weights (regular and bold) plus dim:

| Role | Size | Weight | Line height | Props |
|---|---|---|---|---|
| Heading | 1 cell | bold | 1 row | `Text bold`; one per panel |
| Label | 1 cell | bold | 1 row | `Text bold` in the block's text color; the word that names a block ("Data room:", "For:", "Next:") |
| Body | 1 cell | regular | 1 row, wrapped (`wrap="wrap"`) | `Text`; reading paragraphs may use `Markdown` (max 10,000 characters per `MarkdownProps.text`) |
| Meta | 1 cell | regular (dim only on a black block, or in plain mode; C-29) | 1 row | key hints, "last updated", consequence lines: normal-weight black on the cream page in color mode, never `dimColor` there |

Weights: exactly two (regular, bold). Hierarchy without color (TUI practice 6): bold for headings and the active item, dim for secondary detail, reverse video (`inverse`) for the selected row. About 80 percent of text is in the default style. No italic, no underline, no strikethrough in the first build. No all-caps shouting (Part 12: calm).

## 7. Components [ENGINEERING]

Every user-visible string is a copy deck ID from section 9. Missing-data states use only M01 to M04 (and B/P strings that embed them). Common view model produced by the adapter and read by every component (the renderer invents nothing):

```ts
type Seen<T> =
  | { state: 'ok'; value: T }
  | { state: 'no_room_file' }        // M01
  | { state: 'no_purpose' }          // M02
  | { state: 'unavailable' }         // M03
  | { state: 'not_recorded' }        // M04
  | { state: 'searching' }           // fixture-only until a source exists (R-09)
```

Render-time rules for all components: a render hook never writes (`$.state.set` while drawing is denied); handlers write via `update($, atom, fn)`; every tree is validated by the engine and an invalid tree is replaced by the engine's own (R-01); `$.ui.invalidate('ui.render')` only for external changes (a refreshed read).

### 7.1 Band components (event `ui.render`, matcher `{ component: 'AbovePrompt' }`)

Shared: root `Box flexDirection="row" width={e.props.bodyColumns}`; yields (`next(e)`) when `e.props.hasSurvey`; reads `maxRows` and `bodyColumns` from props only (never `e.viewport.columns`); no animation (no timers redraw the band for effect); text truncates with `Text wrap="truncate-end"`.

**LogoCell**
- Props: `variant: 'tall' | 'compact' | 'text'`, `theme` (palette-keyed colors or null).
- Source: `palette.json` through `$.fs.read` (R-04).
- Loaded: tall = the 10 by 3 grid of 6.3 as `Box` children with `backgroundColor`; compact = the 9 by 1 strip of 6.3 (tier T1); text = `Text bold` B01 on `frame`.
- Missing or unavailable: text variant. Plain mode: B02.
- Key: none. Elements: `Box`, `Text`.

**PlaceTile (shows the "You're in" block; the component keeps its short name IcmTile in code, the name never appears on screen)**
- Props: `room: Seen<string>`, `folder: Seen<string | null>`, `isBound: boolean`.
- Source: `status_read` segment `room_binding` (`bound`, `source`, `slug`) plus `$.session.cwd()` relative to the room's directory (R-05; the folder rule is source TBD until 369.25 lands the room's identity reader). The name shown for the folder is the folder's own name as stored until a recorded plain name exists (OQ-08). The concept shows only the folder ("You're in: Funding"); the data room's name moves to the pane's first line (P10, C-03).
- States: inside a folder B10 (folder name); at the top of the data room B11 (room name); no room bound B12; a registry-fallback room (not a binding) B13; unavailable B14; no room file found, not recorded, searching: not applicable (identity comes from the binding, not from a recorded field). At tier T1 the block shows B16, the name alone (10.5).
- Style: `where` blue, cream text; the label "You're in:" is `bold`.
- Key: none. Elements: `Box` + `Text`.

**JobTile (shows the For block)**
- Props: `purpose: Seen<string>`.
- Source: the folder's `ROOM.md` front matter field `purpose` (templates `ROOM.md.section.tmpl` and `ROOM.md.identity.tmpl` both carry it), read through `room_artifact` or `$.fs.read` of the path. The "section statement" field (`statement`) is not shown (a routing field, not plain language).

## 8. Keys and focus [ENGINEERING for the tables; the words are copy deck IDs]

### 8.1 Who owns the keys

| Owner | When | Notes |
|---|---|---|
| The prompt box (host-owned) | by default | The person types here. The mod never takes it away and never restyles it (C-21). |
| The band | never takes focus on its own | Its keys are `Button` hotkeys. Whether a hotkey fires while the prompt box has focus is UNVERIFIED (R-03). If it does not, the band keys work only after the person moves focus to the band, and the slash command `workspace` (registered with `$.command.register`) is the guaranteed way to open the pane. |
| The pane | `focus: true` when opened by a person's action | Esc closes it (`closeOnEscape`) and gives the keys back to the prompt box. A card in the Review tab is part of the pane, not a dialog. |

Rule: only one thing takes keys at a time; the thing that has them is visibly different (the focused `Button` is drawn in reverse video, which works in every color mode, TUI practices 6 and 9). ### 8.6 Refusals and errors (the E strings)

Every refusal the runtime returns is shown as a plain sentence that says what happened and what to do, never a code. The mapping (the codes are in `lib/mcp/tools/gate.cjs` and spike 005 and 007; they are never shown):

| Runtime answer | Shown | What the person can do |

## 9. Copy deck [PLAIN]

## 10. States and responsive collapse [PLAIN for what is seen; ENGINEERING for the thresholds]

### 10.1 Tiers

The band reads only what the engine gives it: `bodyColumns` (column width less the engine's 5) and `maxRows` (capped at half the terminal rows, prompt included; whether the prompt's 3 rows count inside `maxRows` is UNVERIFIED, R-02, so the row thresholds below are written against `maxRows` as given and the spike measures them). It never reads the terminal size from anywhere else. The floor is the band's own width and rows, not the terminal's, because a docked pane takes part of the width (C-01, R-20).

| Tier | Needs | Draws |
|---|---|---|
| T3-wide | band `bodyColumns` 84 or more and `maxRows` 6 or more | the concept WIDE band: tall logo (3 rows), place, waiting, context with the ten-cell bar; purpose; next with the keys Open and Help; version only if a verified source exists (OQ-04) |
| T3-compact | `bodyColumns` 72 to 83 and `maxRows` 6 or more | the same three rows with the bar and the version dropped; the number stays: "Context used: 62%" |
| T1 | `bodyColumns` 30 to 71, or `maxRows` 4 or 5 | ONE row: compact logo, place, one or two alert blocks, the Help block (10.5) |
| T0 | `bodyColumns` under 30 and `maxRows` 4 or more | one row: B01 and the Help block only |
| yield | `maxRows` under 4, or `hasSurvey` true | draws nothing (`next(e)`); the slash command `workspace` still works |

Why 84 and 72: T3-wide row 1 needs the logo (10), the place block (20 for "You're in: Funding" plus padding), the waiting block (23 for "A decision is waiting") and the context block with its bar (30); that is about 83 plus a frame cell. Without the bar the context block is 19, which gives 72. These are computed from the copy deck lengths on 2026-10-06, to be re-measured on the render (R-02).

### 10.2 Collapse order (what leaves first as space shrinks)

Inside T3-wide: (1) the version, (2) the bar cells. Then T3-compact. Inside T3-compact the key hints shrink to Help only before the tier drops. Then T1. Never dropped before the tier changes: the place, the waiting count, the purpose and the next step. In T1 the purpose and the next step are not in the band; they are in the pane's Room tab, one key (`o`) away, and the band's Help block names that key.
