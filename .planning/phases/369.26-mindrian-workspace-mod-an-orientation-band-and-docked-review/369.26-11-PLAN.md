- Purpose states under the P20 heading: ok shows the purpose text (a `Text`, or `Markdown` only for multi-line text, capped by the engine at 10,000 characters); no_room_file M01; no_purpose M02; unavailable M03; never a related fact.
- Step states under P30: ok shows the step as data, then P31 with the reason when recorded else P32; not_recorded shows M04 and draws NO button; unavailable M03; searching is fixture-only (P78 is a Think string; here use M04 wording per UI-SPEC 7.3 "Missing: step not recorded shows M04").

It never calls `$.prompt.submit`.
- The waiting panel: none P41; one P42; several P44 with the real count; the jump button P43 (hotkey `v`) is drawn only when at least one decision waits and runs `update($, tabAtom, () => 'review')`.
- Result panels: P55 body is D24 with the label from `lastResultAtom`; P56 body is P41, P42 or P44 from the CURRENT model count (re-read after the answer), so the pane never states a count the runtime did not give.
- `keys(ctx)` returns, in order and only when their button is drawn: `n` H01, `v` H02 (plan 15 inserts `m` H03 between them); the shell appends `s` and `h`. `explainId` is X01.
