Facts measured while planning (re-read before use):
- `room_artifact` takes `{ path (room-relative .md path, for example evidence/interview-03/interview-03.md), max_bytes }`, never writes, cannot leave the room and says when a long document is cut (lib/mcp/tools/artifact-read.cjs). Read its reply shape (`handle`) before parsing it.
- A decision card carries `evidence_node_ids`: opaque LOCAL node ids (lib/mcp/tools/gate.cjs gate_render schema). Whether an evidence node id equals a room-relative artifact path is not stated in any file read while planning; the call itself is the test: an id for which `room_artifact` answers ok as a path is a source, any other id is not drawn.
- UI-SPEC P102 is "From {where}": where is the top-level folder segment of the resolved path as stored (OQ-08 default: the folder's own name as stored).

Decisions this plan fixes (Claude's discretion; UI-SPEC rulings preserved):
- The list is the union of `evidenceNodeIds` across the open cards in `vm.gates` (deduplicated, at most 10 considered), resolved on open: each id is read with `max_bytes` 4096 for its first heading (title); a read that fails or has no heading is not drawn. When there are no open cards or no ids the tab shows P104. A failed list load shows M03.
- The reading view: pressing a row's P103 button loads that path with `max_bytes` 40000, keeps the first 10,000 characters for the `Markdown` element (its hard limit), and shows P107 when the artifact is longer; heading P105; Back button P106 with hotkey `b` clears the reading atom. Rows have NO hotkey (Tab or arrows walk them, Enter presses, UI-SPEC 7.5).
- `keys(ctx)` returns `b` H07 only while a reading view is open; the shell appends `s` and `h`. `explainId` is X03. In sample mode the list and the texts come from `src/pane/sources/fixtures.ts` through the same model seam with no MCP call; every fixture title ends with (sample); the empty sample shows P104 and the unreadable sample M03.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| evidence ids to room_artifact | opaque ids are tried as room-relative paths through a tool that contains paths in the room |
| artifact text to Markdown element | the person's own file rendered by the engine |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-369.26-13-01 | Tampering | path traversal through an evidence id | mitigate | the tool refuses paths that leave the room (its own contract); the mod sends no other tool and never builds a path from user text |
| T-369.26-13-02 | Information disclosure | reading reaching the Brain | mitigate | no BRAIN_SERVER reference (grep gate), tool-names arm; Canon Part 8 |
| T-369.26-13-03 | Denial of service | many or huge reads | mitigate | 10 probes max, 4096 bytes each, 40000 for one reading, 10,000 characters drawn |
| T-369.26-13-04 | Repudiation | an invented title or source | mitigate | only a title read from the artifact's own heading is drawn; unresolved ids are not drawn |
</threat_model>
