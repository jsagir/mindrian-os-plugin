<objective>
Ship the WHAT decision: an F.8 governance basket over pending memory candidates. When >=2
`review_status='proposed'` truth-claim nodes (claim/CausalClaim/assumption/decision/opportunity) are
pending, the navigator sees a toggle basket; a Brain-confidence candidate >=0.70 renders PRE-CHECKED
(display-only, never auto-applied, per the shipped F.8 contract); ONE confirm writes N
REMEMBERED_AS edges (the HOW decision -- which Part-4 verb, which section, which truth-state -- rides
as scalar properties on that same edge); every toggled-OFF candidate writes NOT_REMEMBERED_BECAUSE
(rejection is data).

Purpose: this is the SEED-040 WHAT leg, generalizing the GIX deep-grade motivating case to the whole
write path. It composes the ALREADY-SHIPPED F.8 machinery (Phase 188) exactly the way Phase 195-05
composed it for cross-room linking -- clone the shape, mint zero new selector surface, supply only
the per-item closer that is domain-specific (cross-room-umbilical-closer.cjs is the structural
template this plan clones). It also ships the reusable Plurai baseline gate-check script every
subsequent 189 plan's eval GATE leg calls, per the roadmap's "no phase closes without a passing
Plurai baseline."

Brain_consult reuse (mint no 7th reach, SENS-09 precedent): the roadmap directs "LarryReach REUSES
brain_consult for ranking candidates." This plan does NOT add a fresh Brain round-trip to score
candidates -- it reads the `confidence` column ALREADY present on every `nodes` row (the same column
`findBlockingAssumptions`/`findRelevantOpportunities` already read in lib/core/navigation/insights.cjs),
which is populated upstream by whatever process proposed the candidate (Larry's proposal path, itself
informed by brain_consult per Canon Part 9 role 3/4). This mirrors the Phase 191
composeCommandRecommendationReach precedent exactly: read an EXISTING confidence field the
brain_consult-backed pipeline already computed, never re-derive or re-call Brain for it. Zero new
Brain wire, zero new reach -- the 6-reach bank (dial-reach-orchestrator.cjs REACH_DEFS) stays
byte-untouched.
Output: the candidate query, the basket renderer, the confirming closer, and the gate-check script.
</objective>
