The roadmap's acceptance line reads "a turn/meeting/grade that would write >=2 memories surfaces an
F.8 governance basket" -- implying a live invocation trigger. This codebase has NO existing
turn-close / meeting-close / grade-close WRITE pipeline module today (`lib/core/meeting-ops.cjs` is
read-only intelligence computation; no "GIX deep-grade" module exists as code, only as a motivating
comment in SEED-040/188-06). Phase 195's own precedent (195-05) named three CONCRETE triggers because
concrete trigger modules already existed to hook (session-presence, room-open). Phase 194-06 explicitly
deferred its own live-surface wiring ("wiring a live navigator turn to answer the F.9 reconcile at the
surface... is the remaining glue" -- Next Phase Readiness). Following that same precedent, this plan
ships the FULLY TESTED, standalone governance-gate machinery (raiser + F.8/F.9 resolve + closer) and
treats "invoke this from a specific live turn/meeting/grade-close caller" as the remaining glue for
whichever surface (a future grading pipeline, a future meeting-close command) first needs it -- not
invented here against a caller that does not exist. If the navigator has a specific existing surface
in mind to wire NOW, say so; otherwise this plan proceeds on the standalone-machinery scope.
