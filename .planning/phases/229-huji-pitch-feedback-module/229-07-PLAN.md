<objective>
Build the isolated single-submission runner (seam a scaffold + the two-stage spawn). It scaffolds a fresh scratch room with a grading-legal stage, runs Stage A intake (extract + populate) then Stage B `/mos:pipeline PWS_grading` in one headless session, applies the per-unit guardrails, and writes the `out/<id>/` artifacts plus the `.done` marker only when every gate passes.

Purpose: This is per-submission isolation - the boundary that gives a clean cost line, Part-8 containment, and zero cross-student bleed. The scratch STATE.md MUST literally say `Stage: Validation` or grading resolves to null and the chain dies at step 1 (Pitfall 2); never run compute-state on it. Stage B spawns the plugin's own command so the chain runs INSIDE the session (orchestrator never imports runChain). The batch loop (Plan 08) calls runOne; this plan makes ONE submission provably correct end to end.

Output: `scripts/huji-run-one.cjs` exporting `scaffoldScratchRoom` and `runOne`.
</objective>
