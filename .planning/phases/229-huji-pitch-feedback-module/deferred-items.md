## DI-1 - `--json-schema` is passed a file path; CLI 2.1.211 wants inline JSON

- **Where:** `scripts/huji-run-one.cjs` `buildStageAArgs` (`--json-schema config.evidenceSchemaPath`)
  and `buildStageBArgs` (`--json-schema config.feedbackSchemaPath`); `scripts/huji-eval.cjs`
  `spawnJudge` (`--json-schema JUDGE_SCHEMA_PATH`).
- **Symptom (real run):** `Error: --json-schema is not valid JSON: JSON Parse error: Unrecognized token '/'`
  (the leading `/` of the path). `@file` also rejected: `Unrecognized token '@'`.
- **CLI contract:** `--json-schema <schema>` expects the schema object INLINE
  (`{"type":"object",...}`), per `claude --help` in 2.1.211.
- **Why undetected until now:** all Plan 01-08 tests are model-free; the dry-runs assert the
  arg array CONTAINS `--json-schema` but never spawn the CLI. Plan 09 is the first live spawn.
- **Recommended fix:** read the schema file and inline its JSON into the arg
  (`--json-schema`, `JSON.stringify(require(schemaPath))`), in all three call sites.
- **Blast radius:** blocks Stage A extraction, Stage B grading, and the sonnet judge identically.

## DI-2 - Schema declares draft 2020-12; CLI validator does not accept that meta-schema ref

- **Where:** the on-disk schemas `.planning/phases/229-.../schemas/{evidence,feedback-result}.schema.json`
  and `eval/judge-schema.json`, generated by `lib/core/pitch-feedback-schemas.cjs` via
  `z.toJSONSchema` (emits `"$schema":"https://json-schema.org/draft/2020-12/schema"`).
- **Symptom (inline schema, past DI-1):** `Error: --json-schema is not a valid JSON Schema:
  no schema with key or ref "https://json-schema.org/draft/2020-12/schema"`.
- **Recommended fix:** NOT a blind draft downgrade - draft-07 vs 2020-12 differ on keywords
  (`$defs`/`definitions`, `prefixItems`, etc.) and the schema is grade-provenance surface
  (frozen contract across 200 students). Decide at the zod-generation layer whether to emit an
  accepted draft or strip `$schema`, then re-verify every gate against a real artifact. Jonathan
  decision.

## DI-3 - Stage A `--bare` has no credential when `ANTHROPIC_API_KEY` is unset

- **Where:** `scripts/huji-run-one.cjs` Stage A is `--bare` (buildStageAArgs) + key from
  `process.env.ANTHROPIC_API_KEY || ''` (resolveConfig line 102, runOne lines 454-455).
- **Symptom (past DI-1/DI-2):** `is_error:true, result:"Not logged in - Please run /login",
  terminal_reason:"api_error"`.
- **Root cause:** `--bare` deliberately skips OAuth/keychain, so the API key env var is the ONLY
  credential; it is unset here. The Stage B path (NON-bare, keychain) authenticates cleanly in
  this same environment (plugin loads, Larry active), so this is Stage-A-specific.
- **Options (CONTRACTS.md AUTH_PATH decision):** (a) export `ANTHROPIC_API_KEY` for the designed
  `--bare` Stage A; or (b) drop `--bare` on Stage A and use the keychain like Stage B (trading the
  plugin-discovery-skip speedup for a working credential). This is the exact tension AUTH_PATH
  flagged: "Stage A may have been built expecting --bare + API key."
