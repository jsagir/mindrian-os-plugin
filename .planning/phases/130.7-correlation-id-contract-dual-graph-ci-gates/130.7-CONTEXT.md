# Phase 130.7: Correlation-ID Contract + Dual-Graph CI Gates

## Goal

Ship the small, load-bearing dual-graph primitive that the rest of the v1.14.0 render-spine chain stands on, decoupled from the heavy teaching-graph reformat (now Phase 132):

1. **Correlation contract** - a stable `correlation_id` on every teaching-graph node, a one-time Cypher backfill, `lib/brain/chain-recommender.cjs` returning `{correlation_id, canonical_name, primary_label}` tuples (not raw nodes), navigation.cjs memory_event references carrying correlation_id (not raw name), and `bin/local-chain-recommender.cjs` walking aggregates by correlation_id.
2. **Dual-graph CI gates** - release-candidate validation that local memory_event correlation_ids resolve to canonical Brain nodes, that the chain-recommender returns ONE canonical target per query (no fork across duplicates), and that there are no orphan correlation_ids on either side.

This was the "132A" half of the old Phase 132. It is split out and pulled EARLY (before Phase 131) per the 132-REVIEW-4.8 sequencing flip: 131 writes cascade edges that must point at canonical targets, so the correlation_id contract has to exist before 131 ships, or 131's edges fork across the cross-label duplicates that Phase 132 later cleans up.

## Why this matters (from the 131/132 re-baseline review)

- 132-REVIEW-4.8 section 6: the ~6000-node backfill + dedup was bundled with this primitive in one 7-10 day phase; the primitive + CI gates are "the lowest-effort highest-leverage subset" and should ship early and small.
- Cross-phase coherence change 2: "Flip the sequencing - 132's correlation_id must land before 131, not after."
- 131-REVIEW-4.8 section 6 + decision 3: 131's INFORMS/CONTRADICTS edges should land on canonical correlation_ids.

## Key invariant (resolves a 134 worry)

**`correlation_id` is name-based, NOT vector-based** - a stable hash of `(canonical_name, primary_label)`. It is therefore embedding-INDEPENDENT and safe under any Phase 134 (`@huggingface/transformers` CJS embedding port) or Phase 127.1 (Pinecone -> Neo4j HNSW) vector-substrate change. State this as a contract invariant so the downstream substrate swaps cannot invalidate it.

## Scope

- Add `correlation_id` to every active teaching-graph node (one-time Cypher backfill; deterministic hash, idempotent).
- `chain-recommender.cjs` returns `{correlation_id, canonical_name, primary_label}` tuples; ONE canonical target per query.
- navigation.cjs memory_event references carry correlation_id.
- `bin/local-chain-recommender.cjs` resolves identical canonical to the Brain version when Brain is available.
- The 4-metric release-candidate CI health check (fails the build if: any JTBD cohort < 3 frameworks OR REVIEW_REQUIRED count > 10 OR any framework has > 1 target across labels for the same canonical name OR orphan-rate per label > 5%).
- The three curation surfaces that pair with the gates: `/mos:brain-derive --review-anchors`, `--orphan-census`, `--cross-label-dups`.

## Out of scope (these are Phase 132)

- The hypergraph reified event-node reformat (Authorship/Illustration/Contradiction/Motivation/Evolution).
- The ~50 cross-label dedup-group collapses and the ~278-node Wire-It content cleanup.
- The internal-team-name pseudonymization decision.
(130.7 ships the CONTRACT + GATES; 132 does the heavy reformat the gates then measure.)

- [ ] Every active teaching-graph node has a stable, deterministic `correlation_id`

- [ ] `bin/local-chain-recommender.cjs` references correlation_id, not name
- [ ] navigation.cjs memory_event references carry correlation_id
- [ ] correlation_id documented as embedding-independent (safe under 134 / 127.1 substrate swaps)
