<objective>
Fix finding S8: the MCP server blocks its event loop on child processes during stop_gate_check. Measured on the fixture room (384-RANKING.md row S8): a ping sent 20 ms after the call waits 691.7 ms warm (n 15, p95 910.6), and the call starts 3 child node processes with execFileSync. Owner decision 1 approves S8; owner decision 2 sets the floor of 50 ms per event.

Purpose: a Stop gate check should not freeze every other MCP request of the same server for most of a second. The fix moves the three child waits off the event loop and keeps the order of the steps, because the order is behavioral (the comment above _closeOutGuardianOnStop in the file says so).
Output: an async close-out in lib/mcp/stop-gate-handler.cjs, a test file with a parity group and a mechanism group, a golden file, and a measured before and after with a verdict word.
