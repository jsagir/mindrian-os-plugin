  <behavior>
    - K1 exec-counter.c builds with gcc as a shared library (-shared -fPIC -O2 ... -ldl) into the scratch folder. It interposes execve, execv, execvp, execvpe, execl, execlp, execle, posix_spawn and posix_spawnp. Before it calls the real function it appends one line to the file named by MOS_EXEC_LOG with one write call on a descriptor opened with O_APPEND: `E <pid> <ppid> <monotonic ns> <program base name> <script base name or ->`. The script base name is the base name of argv[1] only when the program is node, bash, sh, dash or env and argv[1] does not start with a dash. If the real call returns (it failed), it appends `F <pid>`. The count of a run is the number of E lines minus the number of F lines. It logs no argument other than those two base names. If the variable MOS_EXEC_BLOCK holds a comma list of program base names, a call whose program base name is in the list is logged as `B <pid> <ppid> <monotonic ns> <program base name>` and fails with errno EACCES without running the program; B lines are not part of the count of a run.
    - K2 Calibration A (bash script): a script that runs the builtins `:` and `true`, then `/bin/true` three times, then `/usr/bin/env /bin/true`, then `node -e 0`, then `sleep 0.3 &`, then `wait`. Expected count: 7 (3 for /bin/true, 2 for env and the true it starts, 1 for node, 1 for sleep; builtins count 0). The test asserts exactly 7.
    - K3 Calibration B (node spawns): `node -e` code that calls child_process.execFileSync('/bin/true') once and child_process.execSync('/bin/true; /bin/true') once, run from a bash script. Expected count: 5 (node 1, the first true 1, the shell 1, two true 2). The test asserts exactly 5.
    - K4 Survivors: process-census.cjs sets MOS_PERF_RUN_ID in every hook environment and polls /proc/<pid>/environ (same user, counts only) every 10 ms. A hook `setsid bash -c 'sleep 0.5' &` gives survivors of 1 or more and tail_ms between 400 and 1500. A hook that starts `setsid node -e` with a 400 ms busy loop gives survivor_cpu_ms of 200 or more (a lower bound; label it so). The runner kills a survivor after its wait limit only when its environ holds the run marker.
    - K5 The `blocks` subcommand runs a bash script with `bash -x`, PS4 holding EPOCHREALTIME, the base name of BASH_SOURCE and LINENO, and BASH_XTRACEFD set to an inherited descriptor. It parses the trace in memory, discards all text, and returns milliseconds per named line range plus the top 10 lines by time as `<script base name>:<line>`. A synthetic script with three blocks (sleep 0.1, 0.2, 0.05) gives shares within 30 percent of 29, 57 and 14 percent.
    - K6 The census file (events, process counts, tails) uses the counts schema mos.perf-384-counts/1: it carries the machine record from machineRecord, and verify-results holds it only to the machine record and the Part 8 scan. Per event key it holds: hooks matched (blocking, async, skipped), exec_total (min, median, max over repeats), exec_by_program (top 12 base names with counts), node_starts, bash_starts, find_count, tail_ms, survivors and survivor_cpu_ms. A timing file (the SubagentStop walls) uses mos.perf-384/1 with n of 7 or more. Test: a census file from the synthetic tree passes verify-results although it holds 3 repeats, and a timing file with n = 3 fails it.
    - K7 Copy mode: `run --room copy --source-file <file>` and `walls-subagent --room copy --source-file <file>` work on a synthetic source folder (the path comes from resolveSource of the harness) and writes a counts file that holds no path. Test: the file named by --source-file holds a temporary folder; the result has its file count and no path.
    - K8 Block list: with MOS_EXEC_BLOCK=touch, a script that runs `touch <marker file>` leaves no marker file, the log holds one B line, and the touch call fails (a non-zero status, EACCES). Plan 384-06 uses the block list so that no real npm ever runs.
