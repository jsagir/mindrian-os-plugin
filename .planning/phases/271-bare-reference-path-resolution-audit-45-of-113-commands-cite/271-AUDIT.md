## 3. Classification: LOAD-BEARING vs DESCRIPTIVE PROSE

The ROADMAP's own scoping instruction warns that "a bare `references/` mention is
not automatically a bug - confirm each is actually a load-bearing citation the model
would try to resolve, not prose mentioning the word"
(`.planning/ROADMAP.md:575`). That warning is honored here, in two layers.

**Layer 1, in the gate itself.** The pinned predicate already excludes pure prose:
a site counts only when the token is backtick-delimited OR immediately preceded by a
citation verb (Read, read, load, loaded, see, See, per, from) or a leading list
number. This is why `agents/framework-runner.md:26` - "it executes the chosen
methodology from local references/methodology/*.md via Read/Bash", inside an HTML
comment - is NOT a site. The gate is deliberately narrower than a blanket grep for
the string, because a gate that flags prose gets silenced.

**Layer 2, this classification.** Of the 139 sites the gate does flag, a
verb-proximity pass splits them:

### Disposition rule adopted by this phase: ANCHOR BOTH CLASSES

Justification, in three parts:

1. **Every cited target was verified to exist under the plugin root** (section 1: 0
   MISSING-TARGET). So anchoring a descriptive mention makes it ACCURATE, not merely
   verbose. `skills/ui-system/SKILL.md:394` saying `references/visual/palette.json`
   is describing a path that only means anything relative to the plugin root; naming
   that root is the correction, not decoration.
2. **A split rule needs per-site judgment the gate cannot enforce.** The
   verb-proximity heuristic above is good enough to REPORT a split and nowhere near
   good enough to GATE one. If the fix anchored only the load-bearing class, the
   gate would have to carry 26 permanent exceptions with no principle behind them,
   and the 46th command authored next month would land in the ambiguous middle.
3. **The classes are not stable over time.** `agents/meeting-perspective-extractor.md:45`
   reads as prose today ("Its own perspective definition, verbatim, from
   `references/meeting/extraction-perspectives.md`") but is describing a file the
   agent genuinely opens. Prose that describes a read is one edit away from becoming
   a read.

The single exception to "anchor both classes" is section 4.

## 5. Adjacent class, MEASURED and REGISTERED, not fixed: bare `scripts/` invocations

`--include-scripts` measures a second, adjacent defect class over the same four
surfaces: `bash scripts/<name>` and `node scripts/<name>` invocations that carry no
anchoring and so resolve against the user's cwd exactly like the `references/`
citations do.

| Surface | Advisory sites | Permission-matcher exclusions |
|---|---|---|
| commands | 30 | 1 |
| skills (hand-authored) | 3 | 0 |
| agents | 1 | 0 |
| pipelines | 0 | 0 |
| **TOTAL** | **34** | **1** |

The single exclusion is `commands/status.md:13`, `- Bash(node scripts/mos-status.cjs:*)`,
an `allowed-tools` frontmatter permission matcher. A matcher DECLARES a pattern and
never resolves a path, so counting it would be a false positive. The exclusion count
is printed in the gate's own output rather than swallowed, so a future reader can
see that a suppression happened and how many.

Three of the 34 sit in `commands/file-meeting.md` (lines 771, 978, 983, all
`node scripts/wikilink-file.cjs`). **Implication:** the RCA's references-only fix did
NOT make that file fully portable. The file whose failure motivated this whole phase
still carries three unanchored invocations. This is not a criticism of the RCA, whose
scope was explicitly `references/` citations; it is the measurement that proves the
adjacent class is real and is not covered by anything shipped so far.

**This phase MEASURES and REGISTERS this class. It does not fix it.** The reason for
the split, stated so it is not mistaken for an oversight: a `Read` citation and a
`Bash` invocation fail differently and need different verification. A citation fails
silently and degrades the model's output; an invocation fails loudly with a shell
error, and some of these invocations are dev-only by design in the same way
`/mos:radar` is. Verifying an anchored `Bash` line means actually running it on all
three surfaces. Mixing 34 invocation changes into a 139-site citation sweep would
make the diff unreviewable and put a genuinely-different risk profile behind a single
green check. Plan 271-05 registers this as a follow-up phase.

The advisory tier NEVER affects the gate's exit code. `--check` reports and exits on
the `references/` verdict only.
