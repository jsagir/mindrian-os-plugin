<objective>
Build the spike harness and pre-register the bar before anything runs.

Purpose: D-05. The spike decides the judge and the recall lanes against the Phase 355 baseline
with the same blind protocol, so the numbers are comparable. Nothing in the harness assumes the
answer; it ends in a record and a navigator ruling (366-20), never an automatic adoption.

Settled here: labels attach to `pair_id` (the 355 `pairId`), so the judge arms share one sitting
per recall arm's candidates file (they all judge the same file) and each judge arm's useful rate
is the gold-useful share among the pairs it passes. Recall arms are deterministic, so their three
repeats are recorded as identical runs; the judge arms (Jev, Claude, Claude-then-Jev) repeat three
times each. Per-room cap 32 keeps each arm at n <= 96, matching the baseline n (at n = 96 an arm
needs 53 useful, 55.2%, to clear). Cost per arm (wall time, CPU-seconds, peak RSS, tokens and
dollars where a vendor reports them) is recorded as counts (design section 9 Q5). The Claude arm
is a Claude Code subagent on the user's plan writing a verdicts file from the committed prompt
(no ANTHROPIC_API_KEY on this machine; research A5); an API arm would route through
`claude-routing` role `pair_judge`.
Output: bar.json, the Claude judge prompt, `scripts/spike-366.cjs`, the vector-lane seam in
eureka-recall, a hermetic test.
</objective>
