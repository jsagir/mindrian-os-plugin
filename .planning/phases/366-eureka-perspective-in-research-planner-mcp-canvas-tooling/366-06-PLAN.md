  "one more lockstep place", and place 8 is Theo's own re-emit, a different artifact.

  Theo read the place-8 gate uses (`mappedBy`), plus the plugin version and the refresh time. The
  release gate is offline: at the start of release N+1, place 8 asserts Theo's mappedBy equals N;
  place 9 asserts the snapshot was refreshed after that re-emit, so `theo_stamp.mapped_by` must
  equal the current version N. No network at release for this gate.

  documented command `node scripts/refresh-framework-names.cjs --live`, not as a new automatic call
  inside Phase 349's release-to-Theo dispatch step: that wiring is outside this phase's files and
  would put a live Theo read into the release path, while the gate already makes a stale snapshot
  unshippable, so the regeneration cannot be skipped silently. Navigator ruling 2026-10-01:
  accepted. D-17 is delivered this phase as the lagging release gate plus the documented
  `refresh-framework-names.cjs --live` command. Automatic regeneration in Phase 349's dispatch step
  is not wired this phase. Plan 366-24 lists "wire the D-17 leading edge into the Phase 349 dispatch
  step" as a follow-on in 366-HANDOFF.md.
