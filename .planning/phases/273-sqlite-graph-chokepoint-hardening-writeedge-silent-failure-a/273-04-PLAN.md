<objective>
Close C3: `lib/core/navigation/ingestion.cjs`'s raw `INSERT OR IGNORE` currently writes ANY
Brain-supplied edge `type` string with zero allowlist check, bypassing the closed
`ALLOWED_EDGE_TYPES` vocabulary `writeEdge` already enforces everywhere else. Add an inline
allowlist guard, per D-03/D-03a's settled decision: reuse the existing `ALLOWED_EDGE_TYPES`
export from `edges.cjs`, do NOT route the write through `writeEdge` itself.

**Why not route through writeEdge (do not get this backwards):** `ingestion.cjs` writes with
`INSERT OR IGNORE` (skip-on-conflict); `writeEdge` writes with `ON CONFLICT DO UPDATE`
(overwrite-on-conflict, subject to the confirmed guard). Routing through `writeEdge` would
silently upgrade the Brain from "can never overwrite an existing local edge" to "can overwrite
any non-confirmed edge's properties" -- a Canon Part 9 regression introduced by the very phase
meant to harden Part 9 (273-RESEARCH.md Pitfall 5). The inline guard preserves today's
`INSERT OR IGNORE` semantics exactly; only the type-vocabulary gap closes.

This turns Phase 273's fourth Wave-0 RED test GREEN: `tests/test-273-ingestion-allowlist.cjs`
(273-02). The test file does not change -- the fix must make its already-written assertions
pass.

**MANDATORY standing consult (CLAUDE.md):** `lib/core/navigation/ingestion.cjs` is the same
class of file `edges.cjs` is (a `lib/core/navigation/*.cjs` chokepoint file), so the same
icm-architect standing consult applies here as it does in plan 273-03's Task 1. Task 1 below
requires the consult before this fix commits.

This plan runs in the same wave as 273-03 (parallel-safe: `edges.cjs` vs `ingestion.cjs`, zero
file overlap) but depends only on 273-02 (needs the RED test), not on 273-03's writeEdge change.

Purpose: close the last unclosed edge-write bypass of the closed allowlist -- a
