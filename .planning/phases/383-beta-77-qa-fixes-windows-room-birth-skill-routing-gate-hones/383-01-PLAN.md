The resolver contract (D-03) that these tests pin. Plan 383-03 implements exactly this:

- `resolveRoomRuntime(opts)` in lib/core/platform.cjs. `opts = { platform, env, spawnSync, existsSync, refresh }`, every key optional (defaults: process.platform, process.env, child_process.spawnSync, fs.existsSync, false).
- Return: `{ ok, bash, python, tried, reason, plain }`. `bash = { path, ostype } | null`. `python = { path, cmd, pre, version, version_line } | null`. `tried = [{ kind: 'bash'|'python', cmd, result, detail }]`. `result` is one of `ok`, `not_found`, `rejected_wsl`, `rejected_store_stub`, `probe_failed`, `below_floor`. `reason` is `null`, `no_bash` or `no_python`. `plain` is `''` when ok.
- win32 bash candidates, in order: `env.MINDRIAN_BASH`, `env.CLAUDE_CODE_GIT_BASH_PATH`, `<ProgramFiles>\Git\bin\bash.exe`, `<ProgramFiles>\Git\usr\bin\bash.exe`, `<ProgramFiles(x86)>\Git\bin\bash.exe`, `<LOCALAPPDATA>\Programs\Git\bin\bash.exe`, then each line of `where bash`. ProgramFiles defaults to `C:\Program Files`, ProgramFiles(x86) to `C:\Program Files (x86)`; the LOCALAPPDATA candidate is skipped when the variable is unset.
- A win32 candidate whose path contains `\System32\` or `\WindowsApps\` (case-insensitive, either separator) is `rejected_wsl` with no spawn. A fixed-path candidate that `existsSync` denies is `not_found` with no spawn. A survivor is probed with argv `['-c', 'echo $OSTYPE']`; ENOENT is `not_found`, a non-zero status is `probe_failed`, an ostype that does not start with `msys` or `cygwin` is `rejected_wsl`. The first accepted candidate wins; `bash.path` is the candidate with backslashes turned to forward slashes.
- POSIX bash candidates: `env.MINDRIAN_BASH` when set, then `bash`. The same probe; exit 0 is accepted whatever the ostype.
- Python candidates on every platform: `env.MINDRIAN_PYTHON` when set, `python3`, `python`; on win32 also `py` with `pre = ['-3']`. Probe argv `[...pre, '--version']`. ENOENT is `not_found`; status 9009, or output matching `/Microsoft Store|was not found/i`, is `rejected_store_stub`; another non-zero status is `probe_failed`; no `Python X.Y` in stdout plus stderr is `probe_failed`; X.Y below 3.9 is `below_floor`. On win32 only, an accepted candidate gets a second probe `[...pre, '-c', 'import sys;print(sys.executable)']`; a non-empty first line becomes `python.path` with forward slashes; when that probe fails, `python.path` is the command name, except for `py`, which is then `probe_failed`. On POSIX `python.path` is the command name and no second probe runs.
- `plain` constants, exact text: `PLAIN_NO_BASH_WIN32` = "Room creation cannot start on this computer yet.\n  Why: it needs Git Bash, and no working Git Bash was found.\n  Fix: install Git for Windows from git-scm.com, then ask for the room again." `PLAIN_NO_BASH_POSIX` = "Room creation cannot start on this computer yet.\n  Why: it needs bash, and no working bash was found.\n  Fix: install bash, then ask for the room again." `PLAIN_NO_PYTHON` = "Room creation cannot start on this computer yet.\n  Why: it needs Python 3.9 or newer, and no working Python was found.\n  Fix: install Python 3 from python.org, then ask for the room again." Both bash and python are always probed, so `tried` is complete; `reason` is `no_bash` when no bash was accepted, else `no_python`.
- Memo: only an `ok: true` result of a default call (no injected platform, env, spawnSync or existsSync) is cached; `refresh: true` re-probes; `__resetForTests()` clears the cache.
- `toBashPath(p)` replaces every backslash with a forward slash. `formatTried(tried)` returns one line, for example `bash: C:/Windows/System32/bash.exe rejected_wsl; python: python3 rejected_store_stub, python ok`.
- `spawnRoomRegistry(args, opts)`, `opts = { roomsHome, cwd, timeout, env, runtime, spawnSync, platform, script }`. With `runtime.ok === false` it spawns nothing and returns `{ ok: false, out: null, stderr: 'room runtime not ready: ' + formatTried(tried), status: null, python: <summary>, reason: 'environment_not_ready', plain, tried }`. Otherwise it spawns `runtime.bash.path` with argv `[toBashPath(script)].concat(args)`, where on win32 every arg matching `/^[A-Za-z]:[\\/]/` passes through `toBashPath`; env adds `MINDRIAN_ROOMS_HOME` (forward slashes on win32) and `MINDRIAN_PYTHON = runtime.python.path`; options `{ cwd, env, stdio: 'pipe', encoding: 'utf8', timeout, windowsHide: true }`, never `shell`. Return `{ ok, out, stderr, status, python, reason }` with `reason` one of `null`, `spawn_error`, `timeout`, `exit_nonzero`.
- CLI: `node lib/core/platform.cjs room-runtime [--json]` prints the JSON of `resolveRoomRuntime({ refresh: true })`, exits 0 when ok, else prints `plain` to stderr and exits 1.
