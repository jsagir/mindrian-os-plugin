# Phase 383 - PRD

**Phase:** 383 - Beta.77 QA fixes: Windows room birth, skill routing, gate honesty, voice
**Depends on:** Phase 381
**Written:** 2026-11-05
**Status:** Ready for planning. Nothing here is reproduced yet.

## Why this phase exists

The owner tested beta.77 with a pretend first-time user, a physicist on a Windows laptop, who talked to Larry for 19 turns. The talk itself went well. Things around it broke, and the report lists ten findings. The biggest: a Windows user cannot create a room, so Larry has no memory and no room features, and a real Windows user is stuck on day one. The next: no `/mos` command ran in 19 turns. The other eight are about whether the gates and Larry's voice behave the way the Canon says they do.

The owner read the code and found the risky `bash` calls at the lines the report names. The owner has not reproduced the failure.

This PRD turns the report into ten requirements, each with a "done when" that a test or a human can check.

## How to read the evidence marks

Every finding below carries the mark **reported, not yet reproduced**. That mark means: the owner saw it in the beta.77 QA session, and nobody has re-run it yet on a controlled setup. It does not mean the report is wrong. It means no fix may be called verified until Wave 1 to 3 reproduce the finding first, and Wave 4 re-tests on Windows.

The text of the owner's QA report is not in this repo. The findings are as given in the 2026-11-05 phase request. Before Wave 1 starts, the verbatim report goes into `383-QA-REPORT-verbatim.md` in this directory (the same rule SEED-142 uses for its stderr). Two findings cannot be finished without it: QA383-08 (which number) and QA383-10 (which folder).

## Constraints (binding)

- **SEED-117:** on a room create or switch failure, report the failure line verbatim, file the bug, stop. Never hand-build a room. A failed registry call leaves no half-made room.
- **Canon Part 8:** no room content goes to the Brain. This phase adds no Brain call.
- **Canon Part 7, reuse before build:** `lib/core/platform.cjs` already probes `python3` (it treats the Store stub as absent) and `bash`. Extend it. Search first, and justify any new module against it.
- **Canon Part 12:** every number Larry states is sourced or absent. Hyphens only, never em-dashes.
- **Tri-Polar:** each fix states its CLI, Desktop and Cowork row. A row that is not tested is marked UNVERIFIED, not assumed.
- **Hooks stay `.cjs`.** Any new core file follows the erasable-only rule if it is `.ts`.
- **Release lockstep:** this phase does not bump a version and does not cut a release. `scripts/release.sh` owns that.
- **Git:** commit with `git add -f` and `git commit --only <paths>` (`.planning/` is gitignored). Do not push.
