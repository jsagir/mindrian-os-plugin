`AskUserQuestion` card like its two sibling cold-start branches) and landed the Wave 0

regression test, so a future edit to `scripts/session-start` or `lib/` breaks the build
instead of silently invalidating the audit.

## What Was Built

### Task 1 — SEED-021 card mandate in FIRST_INSTALL (`scripts/session-start`)

Replaced the exact literal `Offer three approaches:\n1. Conversational Q&A` with:

`Offer three approaches - fire the AskUserQuestion card with these three as options; default
to option 3 (Skip) if the user starts talking instead of picking; never render this menu as a
prose list (SEED-021):\n1. Conversational Q&A`

This is a single-line, one-insertion/one-deletion change inside the FIRST_INSTALL bash
double-quoted payload (`git diff --stat scripts/session-start` confirms `1 file changed,
1 insertion(+), 1 deletion(-)`). No `$`, backtick, or double quote was introduced, so the
surrounding bash string stays valid — proved with `bash -n`, not assumed.

**Default-to-Skip reasoning** (for plan 267.1-03 to cite): the sibling `MODE_MENU=` branch
defaults to "Just Talk" (lowest-friction path) when the navigator talks instead of picking.
Here the lowest-friction path is Skip, not option 1 (Conversational Q&A) — Skip requires zero
further input, matching `docs/reward-before-investment-rule.md` line 21, which forbids
demanding input before a first reward. Defaulting to option 1 would silently start an
interactive Q&A the user never asked for.

Nothing else in the block changed: the reward line ("Based on your work in [domain]..."), the
USER.md line, `COLD_START_MENU=`, and the absence of `/mos:ignite` in the menu are all
byte-identical to before (confirmed via `grep -c 'COLD_START_MENU="---' ` = 1 and
`grep -c 'mos:ignite'` = 0). Those are GAP R-1 and GAP I-1, explicitly out of scope for this
phase and registered as Phase 267.2 in plan 267.1-05.

**Deviation from the plan's read_first assumption (GAP I-1 grep count):** the plan's
`<read_first>` and `<action>` describe `grep -rn 'mindrian-user\.md' lib/ scripts/ hooks/`
returning exactly 1 line (`lib/core/user-archetype.cjs`). Running it for real returns 2 lines
— `scripts/session-start`'s own FIRST_INSTALL prose block mentions the literal
`~/.mindrian-user.md` as instructional text for the model (the same string pinned separately
in assertion 5), and grep's substring match legitimately catches it inside that one giant
line. Rather than write an assertion that would immediately and permanently fail (a false

audit's actual claim (no writer in *source code*), the plan's grep command just didn't account
for its own prose collision. Recorded here per Rule 1 (auto-fix bug) so plan 267.1-03 doesn't
re-open this as a fresh discrepancy.

### Task 3 — `tests/run-all-267.1.sh`

Mirrors `tests/run-all-266.sh`: `set -uo pipefail` header, `run()`/`run_may_skip()` helpers,
`shopt -s nullglob` discovery over `tests/test-267-1-*.cjs` and `.sh` with the self-skip
guard, the `found -eq 0` guard (proved non-zero-exit with
`TEST_267_1_PREFIX=tests/test-267-1-nonexistent- bash tests/run-all-267.1.sh`), and the
`PASS=/FAIL=/SKIP=` footer ending in `[ "$FAIL" -eq 0 ]`.

`PREFIX="${TEST_267_1_PREFIX:-tests/test-267-1-}"` uses the dash form in the glob (matching
every other phase's `tests/test-<int>-<slug>.cjs` naming), while the aggregator's own filename
keeps the dot (`run-all-267.1.sh`) to match `run-all-266.sh`'s phase-named form.

Explicit gate line for `tests/test-209-session-start-exemplar.cjs` — task 1 edited the exact
SEED-021 contract region that test guards, and 209 carries no `test-267-1-` prefix for the
glob to discover.

- `EMDASH_TARGETS` (repo-relative): the new test file, the aggregator itself,

  `.planning/research/2026-08-27-hooked-first-install-audit.md`. A MISSING file fails the
  fence unless `TEST_267_1_ALLOW_MISSING=1`.
- `EMDASH_ABS_TARGETS` (absolute path): the rethinking-mindrianos room mirror. A MISSING file
  here increments SKIP and prints an explicit line — never a failure — because that room is
  machine-local.

**Expected-red state, recorded per the plan's success criteria:** `bash
tests/run-all-267.1.sh` WITHOUT `TEST_267_1_ALLOW_MISSING` exits 1 right now and names
`.planning/research/2026-08-27-hooked-first-install-audit.md` as `MISSING (not yet created)`

file under `tests/test-267-1-*`, runs the 209 explicit gate, and reports

**Deviation from the plan's literal acceptance criterion (`node --test` grep):** the plan asks
the header comment to state, mirroring run-all-266.sh, that the runner "runs `node "$t"` bare,
never `node --test "$t"`" — but that exact phrase, if written verbatim, makes

requires (run-all-266.sh itself greps to 1 for the identical reason — its own header comment
contains the phrase it is warning against). Reworded the comment to "never invokes node's
built-in test runner (`--test`)", preserving the exact same meaning without the literal
substring, so both the intent and the literal grep check are satisfied.
