## 3. The F.7 recalibration dial (187.1-04)

### The EXACT function to call (no new function)

There is NO new renderer to build. The tripwire, on fire, calls:

```
require('lib/hmi/selector-dispatcher.cjs').pickShape({
  requestedShape: 'F.7-recalibration',
  roomDir,
  operator: 'CONVERSATION',
  tier: getTier(),
  payload: {
    voice_from: prior.voice,
    voice_to:   current.voice,
    investment_level,           // current dial scalar
    posture,                    // current posture enum
    modality_hint: 'voice_switch'
  }
})
```

`pickShape` routes this via the existing F.7-dial branch
(`lib/hmi/selector-dispatcher.cjs:755-771`) to
`lib/hmi/dial-selector.cjs::renderDialShape` (the Phase-177 dial, reused), which wraps
`renderDialHud` into `zones.header` (`dial-selector.cjs:216-225`). The contract is then
stamped by `appendAskUserQuestionTrailer` (`selector-dispatcher.cjs:528-548`, appended
at line 933) which adds the `[AskUserQuestion contract: shape=F.X verbs=N]` marker. The
returned object is `{ shape, rendered: { zones, contract, askuserquestion_marker } }`.

Note: the related render-only passive surface is `lib/hmi/dial-presenter.cjs`
(`_buildDecisionGateHeader` lines 184-210 already renders the tri-context
LOCAL/BRAIN/SIGNAL header on the F.7 engine arm) and `lib/hmi/shape-f1-renderer.cjs`
(`renderShapeF1`, the FROZEN reusable renderer the dial calls internally). The toggle
layer (section 3b) reuses these same two.

### WHO + 4-arrow + checkbox + free-text slate, mapped to the existing selector contract

The dial object is `zones = { header, body, footer }`:

- HEADER = the 4-arrow HUD, unchanged, from `dial-selector.cjs::renderDialHud`
  (lines 141-158): `[register] up/down investment_level X.XX (Ask<->Tell)  left/right posture HOLD`.
- WHO layer = an AskUserQuestion multi-select ABOVE the arrows, options
  `['Back to Larry', 'Stay with Claude', 'Other / explain']`. The archetype routing
  (`selector-dispatcher.cjs::resolveArchetype` line 168) maps `recalibration_who` ->
  `multiSelect` (or `confirm`).
- CHECKBOX extras (optional: 'shorter', 'show your reasoning') ride the SAME
  AskUserQuestion contract as the WHO pick.
- FREE-TEXT 'Other / explain' is ALWAYS LAST per the Part 3 F.1 human-in-the-loop
  guarantee, enforced by `selector-dispatcher.cjs::ensureFreeTextLast` (line 247).

The 4 arrows are AXES on a register, NOT ranked options, so they do NOT count toward
MAX_K=3. WHO has 3 options (within MAX_K). The keystroke reducer
`dial-selector.cjs::reduceKeystroke` (lines 106-127) is the pure function that computes
the next register from a keystroke (up/down move investment_level by
INVESTMENT_STEP=0.1 line 45; left/right rotate posture clamped within POSTURE_IDS);
`applyControlKeypress` (lines 174-183) writes `register_override` to scratch.

### The SELECTED_REACH / PIVOTED state write

On dial commit (Enter), the selection-handler calls
`lib/core/navigation.cjs::writeEdge(source, target, relationType, properties)`:

- `source` = current decision/turn node id.
- `target` = chosen WHO option (or chosen modality posture).
- `relationType` = `SELECTED_REACH` when the choice MATCHES current state
  (resting-detent, in-sync) else `PIVOTED` (the override). BOTH are already frozen in
  the Part 4 / Part 9 edge set (`docs/MINDRIAN-CANON.md:210`, "dial-decision edges
  PIVOTED, SELECTED_REACH"). NO new edge type is minted (Part 11 R2 born-wired).
- `properties` = ENUM/scalar only: `{ investment_level, posture, voice_from, voice_to,
  timestamp }`. NEVER the navigator's prose or move content (Part 8 / Part 9).

Also log a `memory_event` (system-bookkeeping carve-out, Part 9 line 351):
`event_type='modality_recalibrated'`, `created_by=system`, `review_status=confirmed`.
A second `memory_event` `event_type='voice_switch_detected'` fires when the tripwire
itself fires. Both feed the Part 12 calibration notebook (deferred).

## 3b. The F.7 toggle TUI render (the 2-axis De Stijl Modality Remote)

This is the visual realization of the Part 12 Modality Remote: the up/down/left/right
cross. The mapping (Part 12, `docs/MINDRIAN-CANON.md` Part 12 Modality Remote):

```
            UP = tell me / give me the call   (more TELL)
                          |
  LEFT = challenge -------+------- RIGHT = converge / advance
   (pull back)            |        (push forward)
                          |
          DOWN = draw it out of me, slow down (more ASK)
```

Up/down is the Part 3 ASK/TELL dial; left/right is its second axis
(challenge / converge). These axes are FROZEN (no new axes, Part 12).

### Render form: the SEED-020 no-bespoke-widget constraint

CRITICAL finding: the 2-axis cross render pipeline does NOT YET exist as code. Part 12
DOCUMENTS the remote; no module draws a cross or captures directional input. The build
MUST NOT mint a bespoke widget. It routes through the single SEED-020 construction door:
the toggle calls `lib/hmi/shape-f1-renderer.cjs::renderShapeF1()` (the frozen reusable
renderer the F.7 dial already calls) and passes the 4 directions as custom verbs, then
flows through `selector-dispatcher.cjs` unchanged (the dispatcher owns AskUserQuestion
construction; the toggle owns only the option spec). Reference pattern:
`lib/core/abstraction-gate.cjs::buildAbstractionSelector` (lines 23-26 document
"builds the option SPEC, does NOT construct a bespoke selector payload").

Three candidate render forms (DESIGN DECISION, gates downstream code):
- (A) ASCII cross in the card body using the approved-12 glyph vocabulary; the 4
  directions become 4 AskUserQuestion rows.
- (B) Hybrid: a De Stijl-colored cross drawn in the header framing
  (`dial-selector.cjs::renderDialHud` / `dial-presenter.cjs::_buildDecisionGateHeader`
  lines 184-210) PLUS 4 directional body rows.
- (C) 4 rows only, no visible cross (simplest SEED-020 compliance; loses the Part 12
  "visible by color" legibility).

For 187.1, the dial ALREADY renders the 4-arrow HUD via
`dial-selector.cjs::renderDialHud` (lines 141-158) as the header, so form (B) is the
minimal-build path: the existing HUD IS the cross framing; the WHO + directional rows
are the body. A net-new free-standing cross renderer
(`lib/hmi/f7-toggle-cross-renderer.cjs`) is OPTIONAL and only needed if a richer ASCII
cross is wanted; defer it unless the navigator asks.

### The De Stijl 5-primary palette

Direction markers, if glyphed, MUST route through `lib/hmi/voice-color-mark.cjs`
(`glyphForColor()` / `MARK_COLORS` frozen 5-member Set) and anchor to the 5 Mondrian
primaries in `references/visual/palette.json` (mondrian_red / _blue / _yellow / _black
/ _white). NO sixth color (Part 12 frozen; `voice-color-mark.cjs` validation). The
pedagogical-move color map (Part 12): blue=building/ASK, red=challenging, yellow=
contradiction, black=gate, white=invisibility/handover.

### Cross-surface degradation

- CLI: renders the HUD/cross in the header + the WHO/direction rows in the body.
- Desktop: renders the cross as conversational text framing ("you can guide the
  direction: up = tell me, down = ask me, left = challenge, right = converge") then the
  4 options as host-native inline choices. The body rows NEVER change form (always
  `renderShapeF1` output); only the cross FRAMING changes per surface.
- Cowork: per-actor view; each actor's modality state computes their cross; the shared
  edge lands once; all actors converge.

The cross framing is the only surface-variant part; document it in a
`docs/F.7-TOGGLE-CROSS-SURFACE-CONTRACT.md` only if the toggle is built out beyond the
existing HUD.

### The transition detector

New pure module `lib/core/voice-transition-detector.cjs`, export
`detectedVoiceTransition(currentTurn, priorCheckpointData)` returning
`{ transition_type: 'larry-to-claude' | 'claude-to-larry' | null,
is_first_switch_this_session, should_alert }`. Logic: (a)
`detectVoiceMark(currentTurn)`; (b) read prior checkpoint; (c) compare prior_who vs
current_who; (d) apply debounce; (e) emit only on genuine SWITCH (not every Larry
turn). Reuse the test-harness idiom from `tests/test-larry-voice-mark-182.cjs`; new
suite `tests/test-voice-transition-detection-187.cjs` (9 tests incl. orphan state,
missing file, malformed JSON, rapid A->B->A only emits two alerts).

### The debounce rule

Fire on FIRST instance of a switch in a session; remember "a switch happened" and do
NOT repeat until the REVERSE switch occurs. Persist a LOCAL
`~/.mindrian/tripwire-debounce.json` `{ last_fire_turn, cooldown_turns }`; suggest
cooldown N=3 turns so one quick re-correction does not nag
(STATUSLINE-CONTRACT.md v2 line 195 requires debounce). The detector runs at
conversation TURN compose-start (BEFORE prose generation), NOT on the statusline (the
statusline is passive and cannot host the F.7 dial).

If the detector records a `trigger_mode`, it MUST draw from TRIGGER_TIERS
{signal | context | keyword} (`lib/core/sensors/sensor-types.cjs:73-77`, Part 11 R3):
a glyph change = `signal`; context-block opening = `context`; keyword guess = `keyword`.
