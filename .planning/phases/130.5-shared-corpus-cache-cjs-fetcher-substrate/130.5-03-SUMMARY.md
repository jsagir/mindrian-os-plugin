# Phase 130.5 Plan 03: rs-discovery-engine Corpus Migration Summary

rs-discovery-engine's academic corpus fetch is repointed off its private `fetcherAcademic.fetchAcademic` path onto the unified `fetchCorpus` (Plan 01) wrapped by the shared `research-cache` (Plan 02), closing the duplicate-fetcher / duplicate-API-quota drift, with a network-free fixture regression proving the migration is byte-identical and the shared cache eliminates the duplicate fetch on a repeat.

## What shipped

- **`scripts/rs-discovery-engine.cjs` (migrated)** -- added `fetchCorpus` (from `lib/core/research-corpus.cjs`) and the `research-cache` module to the `m` production-module indirection object so the shared substrate is mockable like every other dependency. Introduced `fetchAcademicViaCorpus(m, flatQueries, roomDir, opts)`: per query it does `m.researchCache.getCached(roomDir, 'openalex', query)` (hit -> reuse), else `await m.fetchCorpus({ source:'openalex', query, limit })` then `m.researchCache.putCached(...)`. Results are concatenated and deduped with the SAME academic dedupe (`m.fetcherAcademic._test.dedupe`) the old path used, then wrapped back into the same `{ tier, source, results, papers, telemetry }` envelope `aggregateDocuments` + `fetcherExperts.mapExperts` consume. The old `m.fetcherAcademic.fetchAcademic(flat_queries, ...)` call site is replaced. roomDir-less callers degrade to a direct `fetchCorpus` (no cache, no throw) so cache-less behavior is unchanged.
- **`tests/fixtures/phase-130.5/sample-room/seed.json`** -- a deterministic frozen corpus payload keyed by query (with a FIXED `fetched_at` stamp so byte-compares are stable) plus a planted forbidden query matrix for the Canon Part 8 assertion.
- **`tests/test-130.5-corpus-migration.cjs`** -- the 3-assertion regression (node:assert/strict, zero network).
- **`tests/run-all-130.5.sh`** -- the Phase 130.5 scoped aggregator mirroring `run-all-130.sh` (`SHELL_SUITES` empty, `CJS_SUITES = test-130.5-corpus-migration.cjs`), executable.
- **`lib/memory/run-feynman-tests.cjs`** -- additive Phase 130.5 block registering the migration suite; every prior block byte-unchanged.

## The three regression assertions

- **A (byte-identical):** runs the pipeline over the fixture once on the OLD-equivalent path (direct `fetchCorpus`, no cache: `room_dir` absent) and once on the migrated cache-wrapped path (`room_dir` present, real `research-cache`), and asserts the FULL downstream bundle slices stringify-equal -- `fetched_results.academic.papers` AND `preprocessed` + `scored` + `classified` + `breakthroughs` + `theses`, not just the paper list.
- **B (cache hit on repeat):** both runs point at a tmp `roomDir`; a stub `fetchCorpus` carries a call counter; the SECOND run over the same query set issues `count_run2 = 0 < count_run1` external calls (the shared cache served every repeat).
- **C (Canon Part 8 preserved):** a planted forbidden flat_query (`$5.2M`, FORBIDDEN_PATTERNS pattern 1) makes the run reject pre-egress with `ExternalEgressViolation` against the REAL `fetchCorpus` audit (not a stub), and ZERO cache entries are written (no results were ever produced).

## Canon compliance

- **Part 8 (graph boundary):** zero direct `fetch(` in `rs-discovery-engine.cjs` (T6 preserved -- the network lives inside `fetchCorpus` / `rs-fetcher-academic`). The engine's gate-level `auditQueryObject(opts)` stays first; `fetchCorpus` runs `auditQueryString(query, 'research-corpus')` per query pre-egress (Assertion C proves a forbidden flat_query rejects with zero egress and zero cache write). Brain is still reached ONLY via `chain-feeder.lookupUpstream` -- this migration adds no Brain path. **brain_impact: NONE** -- no live Brain write.
- **Part 7 (reuse before build):** the migration is a repoint, not a rebuild -- it consumes the Plan 01 `fetchCorpus` + the Plan 02 `research-cache` verbatim and reuses the existing academic `dedupe` so `papers[]` stays byte-identical. The private academic-fetcher path is deleted, shrinking surface rather than adding it.
- **Tampering (T-130.5-03-03):** cache reads/writes go through Plan 02 `getCached`/`putCached` (atomic rename; a corrupt entry returns null -> re-fetch, never a partial).
- **Repudiation / drift (T-130.5-03-04):** Assertion A byte-compares the full downstream bundle old-vs-new; any silent drift fails the suite.
