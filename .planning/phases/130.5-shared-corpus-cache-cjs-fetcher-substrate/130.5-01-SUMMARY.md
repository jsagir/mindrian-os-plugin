# Phase 130.5 Plan 01: Shared CJS Corpus Fetcher Substrate Summary

One CJS-native `fetchCorpus({source, query, limit})` over OpenAlex / arXiv / PubMed / Tavily / Brain-Cypher plus a registered-but-disabled Sci-Bot, with a single fail-closed Canon Part 8 pre-egress audit, native fetch only, zero Python, zero new npm deps.

## What shipped

- **`data/research-sources.json`** -- the machine-readable source enum + per-source gating contract. Default-eligible sources are openalex/arxiv/pubmed/tavily; brain-cypher is enabled but availability-gated; sci-bot is `enabled:false` behind three gates with a `provenance_note` (Sci-Hub provenance, legal-review-required) and `tier_on_enable:practitioner`.
- **`lib/core/research-corpus.cjs`** -- `fetchCorpus` (the single entry point + THE Part 8 audit chokepoint), the frozen `SOURCES` enum loaded from the registry, and the per-source adapter registry. openalex/arxiv/pubmed delegate to `rs-fetcher-academic.cjs` (`fetchOpenAlex`/`fetchArxiv`/`fetchPubMed`) -- reuse, not re-port (Canon Part 7). The net-new surface is the unified interface + Tavily adapter + Brain-Cypher adapter + disabled Sci-Bot stub + the single fetchCorpus-level audit.
- **`lib/core/research-corpus.test.cjs`** -- 5-behavior suite (node:assert/strict + global.fetch stub with a call counter), incl. the planted-violation fail-closed assertion.

## Canon compliance

- **Part 7 (reuse before build):** openalex/arxiv/pubmed HTTP is NOT re-implemented; fetchCorpus delegates to the existing `rs-fetcher-academic.cjs` dispatchers. This module REPLACES the silent-failing `lib/core/rs_corpus.py` corpus path (Phase 134 deletes the .py).
- **Part 8 (graph boundary):** `fetchCorpus` calls `auditQueryString(query, 'research-corpus')` BEFORE any dispatch, so a forbidden user-content query throws `ExternalEgressViolation` pre-egress for EVERY source uniformly -- the planted `$5.2M` query attempts ZERO fetch and ZERO Brain call (Test 2 + Test 4c). The brain-cypher adapter routes only a sanitized generic handle through a `$seed`-bound read-only Cypher via `brain-client.query`; it never embeds user content in a Cypher payload (T-130.5-01-02 mitigated).
- **brain_impact: NONE** -- no live Brain write performed. The brain-cypher path is a read-only methodology query; when the Brain is unavailable it degrades to an empty array (no throw).
- **Sci-Bot stays enabled:false** per the CONTEXT decision -- registered in the enum, three gates encoded, enabled branch is an explicit throw (no headless browser, no HTTP path).
