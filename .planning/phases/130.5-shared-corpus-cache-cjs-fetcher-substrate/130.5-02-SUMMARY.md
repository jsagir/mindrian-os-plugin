# Phase 130.5 Plan 02: Shared Corpus Cache Summary

One CJS-native, source-keyed, TTL-bounded, atomically-written, Python-free on-disk cache (`lib/core/research-cache.cjs`) that both `/mos:research` and `rs-discovery-engine` resolve to the SAME path for the same logical (source, query), closing the duplicate-API-quota drift the 2026-05-15 audit flagged.

## What shipped

- **`lib/core/research-cache.cjs`** -- the ONE shared cache. Exports `{ cacheKey, cachePath, getCached, putCached, isFresh }`.
  - `cacheKey(source, query)` ports `rs_corpus.topic_slug` normalization (lowercase, collapse non-[a-z0-9] runs to a single hyphen, strip edges), prefixes the source id, and appends a 12-char sha256 hash of the normalized `(source, query)` plus a bounded 80-char query stem. Two callers with the same logical (source, query) get the identical key -- this is what makes the cache shared. Different sources for the same query do NOT collide (source-namespaced).
  - `cachePath(roomDir, source, query)` resolves to `<roomDir>/.mindrian/research-cache/<cacheKey>.json` (ONE shared directory) and ensures it via `fs.mkdirSync({recursive:true})`.
  - `putCached(...)` writes `{ source, query_key, fetched_at: <ISO now>, results }` ATOMICALLY: same-dir temp file (`pid + crypto.randomBytes` suffix) then `fs.renameSync(2)`; on rename failure it unlinks the temp so no partial sibling survives. Returns the final path.
  - `getCached(...)` returns the stored results within TTL; returns `null` for absent, corrupt/unparseable, or past-TTL entries (caller re-fetches). Tolerates corruption -- never throws.
  - `isFresh(fetchedAtIso, opts)` ports `rs_cache.is_fresh` (true iff age <= ttl); 30-day default mirrors `TTL_DAYS=30`; clock-skew tolerant.
- **`lib/core/research-cache.test.cjs`** -- 5-behavior suite (node:assert/strict, tmp room via `fs.mkdtempSync`): hit-within-TTL, miss-unseen, miss-past-TTL (via `opts.now` + tiny `opts.ttlMs`), shared-key stability + shared-path proof (a messy-cased write read back via the normalized form), atomic-write (no leftover temp, final file parses as valid JSON).

## Canon compliance

- **Part 8 (LOCAL stays local):** the cache stores ONLY SIGNAL data (public paper metadata returned by `fetchCorpus` -- ids, titles, public abstracts, DOIs). An in-source comment block states no user/room content is cached, and the `(source, query)` key shape carries no room/user bytes (a query string is a generic search handle). Nothing in the module reads from or writes to the Brain MCP. **brain_impact: NONE** -- no live Brain write.
- **Part 9 (memory locality):** the cache is fetch-result storage, NOT room.db graph data, so it correctly does NOT route through `navigation.cjs` (per the plan scope note). It touches no room.db, so it stays outside the Phase 128 substrate allow-list with zero bypass -- confirmed by `scripts/check-substrate.cjs --baseline` (research-cache.cjs is not among the flagged paths).
- **Part 7 (reuse before build):** ports the TTL + source-keying semantics of the legacy `rs_cache.py` (NOT its Pinecone calls) and mirrors `rs_corpus.topic_slug`; reuses the atomic temp+rename idiom proven in `mva-state.cjs` / `jtbd-state.cjs` rather than inventing a new one. Phase 134 will delete `rs_cache.py` and reuse this module.
- **Part 3 (path-traversal mitigation, T-130.5-02-03):** `slugify` collapses to `[a-z0-9-]` only, so no path separator or parent-dir traversal survives normalization (asserted in Test 4: no `[\\/]`, no `..`).
