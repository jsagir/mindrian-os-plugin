**The relationship you're describing is:**

> **Section's job -> current question -> relevant command -> resulting artifact -> update to that section's understanding.**

For example, `file-meeting` starts in **Meetings**, but a discussion about customer pain may produce a proposal for **Problem Definition**, while a funding commitment may produce one for **Funding**. The source remains the meeting; the findings link into the sections they inform.

The section sets the purpose. The current question and problem type determine which command is useful there, not a permanent rule that every section always runs the same tools.
