## What the module does (decisions fixed)

- Seven keys in the key/value identity table, `room.` prefix: room.room_id, room.slug, room.canonical_path, room.parent, room.depth, room.created_at, room.birth_version. The Room node id is `room:<slug>` (created_by system, epistemic_type observation, source_path system:room-identity).
- room_id is an opaque `crypto.randomUUID()`; repair may mint only that one key, and names it `minted_by_repair`.
- A value with no source is the literal `unknown` (source `none`); a top-level room's parent is the literal `none`.
- readRoomIdentity has two doors: `copy` (default, mkdtemp copy of room.db plus -wal and -shm, opened through openRoomDbReadOnlyForCaller) and `in_place` (read-only open of the room's own file, for hot adapter paths). A1 shows the tree hash identical across a copy-door read; A15 shows the in_place door returns the same seven values.
- not_ready results that got as far as reading rows (identity_incomplete, identity_path_mismatch, registry_missing_room) carry `stored`, the room.* values read (A6 checks `stored['room.slug']`).
- Check order in the reader: room.db present, identity table readable, rows (0 -> identity_missing, 1 to 6 -> identity_incomplete), canonical_path versus the normalized realpath, then the registry entry for the stored slug. A copied room therefore reads identity_path_mismatch before the registry is consulted (A5).
- normalizeRoomPath (win32): leading `/c/` becomes `C:\`, `/` becomes `\`, drive letter upper-cased, duplicate separators collapsed, trailing separator stripped (root kept). Comparison lower-cases on win32 only, inside samePath, so the stored value keeps the spelling it was given.
- repairRoomIdentity refuses with `no_approval` before anything is read or written; refuses `room_db_missing` unless createDb, and `room_db_unreadable` unless moveAsideUnreadable (A10 and A11 each assert the refused call changed nothing); moveAside renames room.db (and -wal, -shm) to `room.db.unreadable-<ISO with : and . replaced by ->`, never deletes (A11 compares the 64 bytes). A different existing room_id returns `identity_conflict` and leaves the row unchanged (A9).
- The registry entry for repair is matched by path first; a key match is accepted only for an entry with no path, so a copied room never adopts the original's registry facts.
- writeRoomIdentity validates before writing (identity_invalid:<field>), never catches its own errors, and throws identity_conflict on a different existing room_id. A14 proves a bad slug throws inside BEGIN and a caller failure after a good write both leave 0 room.* keys after ROLLBACK.

## Deviations from Plan

None that change behavior. Judgment calls inside the plan's discretion:

1. Fixtures that need a "ready" room write through `withRoomTx` (BEGIN IMMEDIATE, stamps room_tx_context) instead of a bare BEGIN. The Room node insert fires the change-log trigger, which reads the transaction id from room_tx_context; a bare BEGIN would leave it null. A14 still proves the throw happens inside the transaction and the rollback leaves nothing.
2. A3 and A11 also remove room.db-wal and room.db-shm from the fixture before writing the 64 zero bytes, so the broken file is deterministic and not paired with a stale WAL.
3. For a legacy root room depth and parent come out `unknown`: the registry entry of a birthRoom room carries no depth or parent field, and the plan names registry.depth as the only depth source. ROOM.md icm_self does record depth 0 and parent null for a root, but I did not add it as a source because the plan did not list it. A7 therefore does not assert depth or parent; it asserts slug, canonical_path, birth_version, room_id and created_at. If a later plan wants icm_self.depth as a fallback source, it is a one-line addition in repairRoomIdentity.
4. repair also compares sentinel, ROOM.md and registry room_id values against each other and against an existing row, returning identity_conflict on any disagreement (the plan names only the existing-row case).
