## Deviations from Plan

**1. [Rule 2 - correctness] `handles_on_wire` frontmatter scalar added** (comma-joined, `none` when asked with none, null when not asked). The plan's key list had no way for a reader of the frontmatter to tell the fingerprinted handles (`handles_section_kind`, `handles_job_id`) from the ones Theo actually received. Plan 17 should add it to the face's frontmatter list.

**2. [Rule 1 - honesty] Provenance sentence and F1 differ from the plan text.** The plan wrote "with these handles: lens, section, job, frameworks"; per the carry-over the face names only what was sent.

**3. [Choice inside discretion] Each command name is printed once in the Command sources section, with every source that lists it.** The plan 06 disagreement lists overlap (a name in the contract and the ledger but not the table is in both `agreement` and `contract_only`), and printing it twice contradicted "agreement names listed once with all their source tags". So `contract_only` and `table_only` blocks keep only names no other source lists. As a result a contract-only name that the ledger also lists carries `(source: contract; ledger, see CONTEXT.md section 2)` rather than `(source: contract)`. Arm F4b covers all eleven core sections: no name twice, and the printed set equals agreement plus contract_only plus table_only.

**4. [Choice] Operations are all labelled assisted.** No command on this install maps to a Theo phase label or tool type, so the label is a fixed line, not a `capabilityFor` result.

**5. [Choice] Scalars that are comma-joined list values percent-encode a comma inside a name as `%2C`.** Three canonical framework names contain a comma (measured: 3 of 415 in data/framework-names.json). Plan 18, reading `suggested_frameworks` and `handles_frameworks`, must decode.

**6. [Choice] The Commands list shows at most 10 distinct commands** ("showing 10 of N"), the same 10 that `suggested_commands` carries. Theo rows are per (command, jtbd, framework), so they are deduped by command with the frameworks joined.

**7. [Gap, not fixed here] "matched of total chapters" is not available from the ask result.** theo-ask.cjs keeps `results.chapters` but drops the find_frameworks row's `matched` and `total`. The face reads them from `ask.results.coverage` ({matched, total}) when present and otherwise prints "Theo listed N chapters for this lens; the total chapter count was not returned to this face." Arm F6 covers both branches. To get the real "M of T" line, theo-ask.cjs (plan 05 file, not in this plan's files) needs to carry `coverage: { matched, total }` into `results`; plan 17 or a small quick should add it.

## Notes for plans 17 and 18

- Result keys: `{ frontmatter, body, recommendations }`. `recommendations` items: `{ kind, name, capability (label), capability_cli, capability_mcp, source, rank }`, kinds framework, operation, command.

Empty-string values exist (`suggested_commands` and `suggested_frameworks` when nothing is suggested), written as `key:` with nothing after the colon; brain-md-schema's parser reads that as ''.
