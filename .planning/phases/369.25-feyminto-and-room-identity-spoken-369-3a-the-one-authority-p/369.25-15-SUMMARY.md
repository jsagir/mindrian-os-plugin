## Deviations from Plan

**1. [Rule 1 - Bug] A seeded FEYNMAN.md with the new blocks stopped being scaffold (lib/core/scaffold-predicate.cjs, outside the plan's file list).** Found at the first GREEN run: F1's second write reported `Sources added: FEYNMAN.md` and `The governing thought changed`. Root cause: the Phase 363.1 predicate treats a FEYNMAN.md as scaffold only while it holds frontmatter, an H1, the seed sentence and the two timeline and dial-memory auto blocks; my blocks made it content, so `collectSectionArtifacts` counted FEYNMAN.md as the navigator's artifact (the placeholder governing thought carries the artifact count, so it changed too). The same defect would have hit Eureka and compute-state on every born room. Fix: `lib/core/feyminto/feynman-blocks.cjs` exports `bodyOutsideSentinels` and `HEADER` (the contract the predicate consumes from each auto-block owner) and the predicate lists it as a third owner. F5 proves a seeded face stays scaffold and one human line makes it content. Commit adf7562cd. No later 369.25 plan edits the predicate (plan 17 only reads it).

**2. [Rule 1 - Bug] Entity extraction would have read the seeded blocks as authored text (lib/core/semantic-index/scaffold-template-index.cjs, and tests/test-363.1-feynman-seed.cjs pin).** `isTemplateIdentical` and `stripTemplate` for kind FEYNMAN did not know the blocks, so a freshly born FEYNMAN would have yielded the block lines as an "authored remainder" for entity extraction (scripts/entity-extract.cjs). Fix: for kind FEYNMAN the generated blocks are cut out before matching (lazy, try/caught). The 363.1 seed test pinned the whole seeded file byte for byte; it now pins the frontmatter, the unchanged `# slug` plus seed text, and the blocks, and asserts the face is still template-identical with an empty `stripTemplate` remainder (a MOVING comment records the before). Commit 309960a50.

**3. [Rule 2 - Missing critical functionality] The regeneration pass stamps `room_id` on FEYNMAN.md (generator, in the plan's file list).** The plan stamps FEYNMAN at birth in plan 17, but the generator already holds the identity read and `stampFaceRoomId` exists, so a face the birth step does not reach (a legacy room, a nest created later) would stay "not yet keyed" until a later heal. It stamps only when the identity is ready, never writes `unknown` onto a face. Same value, same read as plan 17, idempotent. F6 proves it. Plan 17's birth stamp is unaffected.

**4. [Rule 3 - Blocking] Three frozen tier-0 baselines re-captured (test-fixtures/feynman/expected-tier0-baseline/*.md).** The integration test pins the generator output byte for byte; the intended frontmatter and block changes moved it. Re-captured with the test's own environment (`MINTO_FROZEN_DATE=2026-04-14`, `MINTO_FROZEN_TIMESTAMP=2026-04-14T00:00:00Z`); the diff is exactly the planned lines plus the AAAK token counts (fixture-small: 734 -> 828 source tokens, ratio 4x -> 4.5x). Fixtures have no room.db, so they read `room: unknown`, `room_identity: room_db_missing`. A first failed run of that test left an untracked `MINTO.md` in the tracked fixture directory (its own cleanup runs after the asserts); I removed that one file.

**5. [Interpretation] writeFeynmanBlocks takes the FEYNMAN.md path** (a section directory is also accepted). The plan names the first argument `sectionPath`; the tests and the callers pass the file.

**6. [Scope] The bare-shell batch path (`generateAllSectionMintos`) writes the new MINTO fields and blocks through `renderSectionMinto` but does not update FEYNMAN.md.** The plan hooks "after each successful `--write`"; the batch path has no `--write` call. Both `--write` paths (tier-0 `runTier0` and tier-1 `writeSectionFromNarrative`) do.

**7. [Design note] Counterevidence reads plain CONTRADICTS edges only.** `navigation.findContradictions` deliberately skips the reified ContradictionEvent shape (its D-04 guard), so a contradiction recorded through `writeContradictionEvent` does not appear; M4 uses `writeEdge`. And `DEPENDS_ON` and `ASSUMES` are not members of `ALLOWED_EDGE_TYPES`, so `navigation.writeEdge` refuses them: `findBlockingAssumptions` can only find assumptions whose edges were inserted by another path. M4 inserts that edge with a direct SQL INSERT in the test fixture. Whether production writers ever mint those edge types is not established here; the Assumptions block will be empty for rooms that do not have them. Reported for the owner of the edge vocabulary.
