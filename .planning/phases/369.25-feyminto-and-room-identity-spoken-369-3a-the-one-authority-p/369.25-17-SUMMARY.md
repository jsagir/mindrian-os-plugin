## Deviations from Plan

**1. [Rule 1 - Bug] A face that holds no Brain content is `staleness: unavailable`, not `fresh` (plan said fresh).** Root cause: `resolveTierMode` lifts any parseable, non-`unavailable` BRAIN.md to `mode_a` when the brain is reachable, and `ensureSectionDerived` short-circuits on a fresh brain-authored file, so a born room's not-asked face would have read as Brain-weighted and would have stopped the first real derivation. `unavailable` is a value the engine, the schema and `navigation-engine-shared` already handle as no weight and tier_0. T6 asserts `resolveTierMode(readQuadruple(...), true)` is `tier_0` for all 11 birth faces. A derivation that asked Theo or got legacy rows is still `fresh`. The face's `brain_graph_version: 0` keeps the existing staleness scan honest: with a fake client returning schema version 21432, `computeBrainStaleness` on a birth face returned `stale, brain_graph_version_mismatch, enqueue_regen` (measured), so the first online session still enqueues the real derivation. Offline the scan reads `fresh, none`, as it does for any young file. The Phase 142 local path (`ensureSectionDerived`, `brainAvailable: true`) keeps `fresh` because test-acpt-05 pins the tier rise it exists for.

**2. [Rule 3 - Blocking] lib/core/folder-memory-shared.cjs gained the six headings.** Its own comment says "Any future heading addition MUST land in both files in the same commit", and folder-memory-quadruple's parity test (9 !== 15) failed without it. It is not in the plan's file list. The headings have no `BRAIN_SECTION_KEY_BY_HEADING` entry, so the quadruple parser ignores them.

**3. [Rule 1 - Bug] lib/core/navigation-engine.cjs `consumedSections` ignores "not asked", the shape line and `(no signal)`.** Without it, the two builder-null legacy sections and every refused read would be reported as consumed sections in the decision trace (measured on the old engine). Two regex sites replaced by one named pattern. T9 (child process, the engine's natural load order) pins it. Not in the plan's file list.

**4. [Rule 1 - Bug] Face frontmatter strings are quote-encoded, not quote-stripped.** `assembleBrainMd` strips `"`, `'` and a backtick from every string; ten canonical framework names hold an apostrophe, so `handles_frameworks` would have lost it and stopped being canonical. Face strings now go through `encodeFaceScalar` (`%22`, `%27`, `%60`) and `decodeFaceList` reverses them with `%2C`. The legacy frontmatter path is unchanged.

**5. [Re-pins, the ruled change "369.25 TFACE-03 / Pitfall 8"].** lib/memory/brain-derivation.test.cjs Test 08 (a nest with no MINTO.md now succeeds and writes the face; no legacy query fires); lib/memory/brain-derivation-graceful-degradation.test.cjs Scenario 06 (a malformed answer now reads "the answer came in a shape this section does not read", never the empty-answer sentinel); tests/test-36925-feyminto-faces.cjs F6 (plan 15's arm expected "one not-yet-keyed warning on a born room, plan 17 stamps at birth"; it now asserts a born room is keyed and removes the stamp to keep proving the regeneration stamps a face birth did not reach), commit 1aafe3f8e; tests/test-vi3-icm-walk.cjs I5, I6, I7, I8b, I8c, M3 (above).

**6. [Choice] Two legacy reader lines are not in theo-ask's closed set.** "not asked: this section was not requested in this run" (an `only_sections` skip) and "the answer came in a shape this section does not read". The face's own `not_asked_reason` still uses only the closed six.

**7. [Choice] `deriveSection` skips the Brain availability gate when `options.offline` or `options.atBirth` is set** (nothing is asked, so no Brain is needed); the byte-locked `brain_unavailable` result for a normal run is unchanged. `cost_tokens` adds 60 per Theo query when the face asked. `brain_query_count` keeps its meaning (legacy sections that returned rows).
