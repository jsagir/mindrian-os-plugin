## Decisions and interpretations (stated so a reviewer does not have to find them)

- **renderBrief returns the whole file text** (a string: frontmatter then the ten blocks). Plan 19 can write it as is. Frontmatter carries `generated: true`, `generated_at`, `section`, `room_id`, `record_basis_fingerprint`, `record_basis_full_fingerprint`, `edit_surface`, `editable_fields: [your_decision]`, `edit_recorded_in`.
- **Two fingerprints.** `record_basis_fingerprint` hashes the five input files only (MINTO, FEYNMAN, BRAIN, CONTEXT, ROOM; an absent file is a line too, so creating one moves it). That is what plan 20 recomputes with `recordBasis(sectionPath)` alone, with or without an identity (BR6 proves equal). `record_basis_full_fingerprint` also folds in the claim-record and run-record digests, which a session-start reader cannot recompute cheaply; plan 19's skip-when-unchanged test should compare the full one, so a new claim or run re-renders the brief.
- **YOUR DECISION** is wrapped in `<!-- feyminto:your-decision:start/end -->` sentinels. `renderBrief({ yourDecision })` keeps a person's text between them verbatim; plan 19 may wire that or leave the default. The frontmatter names the decision card and the MINTO decision_log as where an answer is recorded; a hand edit elsewhere is regenerated away, as the header sentence says.
- **Claim state resolver order** is the plan's: human-confirmed node (`review_status` confirmed and `confirmed_by` not an agent identity, using transitions.cjs AGENT_IDENTITIES with a literal fallback), then a `compare` record that supports against an artifact or source (quote_matched), then a supporting record from an experiment, observation, person, a `test`/`observe` method, or a source other than the claim's own (independently_checked), then a source reference or a source edge (source_reports), else derived. These record-shape mappings are my reading of verification.cjs's closed vocabularies; the annex gives names only. `states` lists every state the records support; the brief shows the first and counts the rest with no label word. A disputed checking status is appended to the record text. The definitions come from `data/claim-state-vocabulary.json` unmodified, and BR3b proves every label occurrence is immediately followed by `: ` and its definition.
- **MINTO key claims** (artifact-derived `### Claim N` blocks) render as source_reports with the artifact as the record. Room.db claim nodes filed with `section` set are read first, through a navigation read-only handle and `readClaimVerification` (no direct db open); `gatherClaimRecords` is exported so a caller can pass claims in.
- **The Theo block renders only what the face recorded** (carry-over 2): asked, time, origin, query count, handles on the wire, the four row counts, suggested commands with their recorded capability, suggested frameworks decoded with `decodeFaceList` (carry-over 1; BR9 proves a comma and an apostrophe survive and no `%2C` reaches the reader), refusals, and the first two Limitations lines. A not-asked face prints `Theo: not asked: <the closed-set line> (reason: <code>)`, says it has no Theo guidance, and, when staleness is `unavailable`, that the engine reads the nest at tier_0. A legacy BRAIN.md with no face keys prints "not recorded"; no BRAIN.md prints "not asked ... face_missing". Never blank, never the empty sentinel. A zero query count on an asked face prints "an investigation lead, not a verdict".
- **Composition sources** (next-move.cjs header has the table): Theo face commands, the filtered ledger candidates, the contract names, the navigator table, the nest's job (registry `serves_jtbd`), and the open MINTO records (open counterevidence lifts commands serving `surface-contradiction`, open assumptions lift commands serving `validate-idea`; these two only add a source to a command another source already names). Order: score, ledger index, contract index, Theo index (last), then name. The three faces enter as: Theo through its commands, MINTO through the open-records lift, and FEYNMAN through the brief's QUESTION and BUT blocks rather than through rank (no shipped data maps a FEYNMAN gap to a command, and I did not invent one).
- **outcomes_differ** is the plan's definition: true when an alternative rests on a different set of sources than the primary. It is a statement about sources, not a prediction of results, and the brief words it that way ("they rest on different sources").
- **Attempted never drops a command by itself**: a research run does not name a command, so run-derived attempted records carry `command: null`. composeNextMove drops a command only for an attempted record that names it, is terminal and is verified. Unresolved attempts are counted in `provenance.unresolved_attempts`.
- **The Verified line** reports checking records on this nest's claims and says none is a result of the move above, because nothing in the repo links a run or a command to a verification record. A finished run is explicitly "not a verified result".
- **An earlier unresolved run stays listed** (`Unresolved: run <id> ...`, up to two) after a later run finishes, until reconciled, per design v2 ("stays visibly unresolved until reconciled"). There is no reconcile mechanism yet; that is a gap, not a decision.
