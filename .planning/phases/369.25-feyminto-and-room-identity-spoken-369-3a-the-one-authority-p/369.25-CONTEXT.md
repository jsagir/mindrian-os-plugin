## Phase Boundary

This phase is the brief's "prove one authority, then generalize" (`.planning/briefs/2026-10-05-prove-one-authority/`) executed on two slices that share one owner:

1. **Room Identity** (brief section 4, the first worked example): the room's identity lives in `room.db` for every room, top-level and nested (ruling 2026-10-05, README). `lib/core/navigation/room-birth.cjs` commits, in one transaction, the `Room` node `room:<slug>` and the `identity` rows (`room_id`, `slug`, `canonical_path`, `parent`, `depth`, `created_at`, `birth_version`) and reads them back before `ok: true`. `ROOM.md` (ICM Layer 0) and the registry entry become projections regenerated from that committed identity, never the other way round. A room whose `room.db` lacks its identity rows is `not_ready` with a typed reason; a repair path writes the rows from the existing `ROOM.md` plus the registry without inventing values. Session binding reads the room id from `room.db`, not from the path. The working sequence create -> register -> bind -> inspect -> governed write -> read back -> restart/reconnect -> inspect again passes on the CLI and on the Windows path shape, with the brief's eight failure tests plus Lawrence's ninth failing first for the real reason, then passing through the actual remediation (a test that merely detects a refusal is not a recovery test).

2. **FeyMinto** (SEED-122, FEYMINTO-DESIGN-v2 binding, FEYMINTO-ICM-AUDIT, FEYMINTO-CROSS): the per-folder reasoning layer, named FeyMinto on every surface a navigator reads, is the identity's first consumer. Its three faces (`MINTO.md`, `FEYNMAN.md`, `BRAIN.md`; file names stay for the referrers) are keyed to the `room.db` identity (the identity invariant is the readback; its id is NOT FEYNMINTO-07, which Phase 81 already used for `--regenerate-all` (81-PLAN-CHECK.md:39); the module labels only FEYNMINTO-01 today, so the planner measures the first id unused by the module and the 81/88 plans and names it; the spoken name stays "the identity invariant"); the Theo face asks Theo per nest which frameworks, operations and `/mos:` commands to consider, with Canon Part 8 handles only, provenance on the face, and "not asked" with a reason never rendered as "(no signal)"; each recommendation is marked runnable here / instruction-only / assisted; the ten-block reader-facing brief is a generated projection (`BRIEF.md`) per nest; the navigation engine reads its next move from that one path.
