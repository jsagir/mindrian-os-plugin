## What was built

- **`formatBriefHead({section, briefText, briefRelPath, stale, staleDetail})`** extracts the three blocks by their H2 headings, cuts each to its cap (bytes / 4: 400, 1200, 800 bytes) with `(more in BRIEF.md)`, adds an optional `stale: inputs changed since this brief was written (<files> changed)` line and the `More: <section>/BRIEF.md (proposed next move, evidence, Theo's contribution, your decision)` line. The 600 covers the printed head: if heading, stale and More lines push it over, the thought and then the question are cut further. A missing block is shown as "(this block is missing from BRIEF.md)", never invented.
- **`assembleBriefHead({roomDir, sessionId, db, section})`**, the one assembler both surfaces call (RESEARCH Pitfall 18). Active nest: explicit `section`, else the session focus section (`resolveFocusSection` on a read handle, through the navigation door), else the nest whose BRIEF.md or MINTO.md changed last. States: `no_briefs` (head null, today's per-section rendering stays byte for byte), `fresh`, `stale` (recordBasis(sectionPath).fingerprint against the file's `record_basis_fingerprint`; a brief with no fingerprint or an unreadable basis is also marked stale with the reason), `no_brief` ("has no brief yet (BRIEF.md has not been written for this nest)"), `unreadable` ("brief could not be read (none of its opening blocks were found)"). Never throws, never writes.
- **`formatTripleContext`** gained `briefHead` and `nestLinks`: the head replaces the per-section blocks (header `## ACTIVE ROOM MEMORY (active nest brief)`), the `Other nests: a/BRIEF.md, b/BRIEF.md, ...` line follows (nests without a brief read `x (no brief yet)`; capped at 1200 bytes with a "+N more nests" tail), and the pending-tier1 and stale footers stay. Absent `briefHead` the output is unchanged (13/13).
- **`fmtBrainLine`**: a brain object carrying `face: feyminto-theo` renders `FeyMinto Theo face: asked <age> (<n> queries)` or `FeyMinto Theo face: not asked (<reason>)`, the reason read from the one table `NOT_ASKED_LINES` in `lib/core/feyminto/theo-ask.cjs`; a stale face appends ` - stale (...)`. A legacy BRAIN.md object renders exactly the old `Brain derivation:` lines (pinned by J7 and the 4/5 staleness suite). `readFaceFields(brainMdText)` reads the four face keys; the hook attaches them to the brain object.
- **`scripts/session-start`**: inside the TRIPLE_CONTEXT block, the face fields are attached, the head is assembled (session id from `CLAUDE_CODE_SESSION_ID` or `MINDRIAN_ACTIVE_SESSION_ID` when present, opening the room read-only; else the newest nest) and passed to the formatter. The plan 13 readiness line now comes from `readinessLine()` in the formatter (identical text; one builder for both assemblers).
- **`context_assemble`**: the answer starts with `feyminto_readiness` (when the room is not ready), `feyminto_brief` (the same text the hook prints, null under `estimate_only`) and `feyminto_brief_meta` ({section, source, state, tokens, budget_tokens}), then the existing four legs unchanged.

## Decisions made

- **Budget split 100 / 300 / 200 of 600** as the plan states; the 600 is enforced on the whole printed head, not only the three block bodies.
- **Reason `no_room_db` kept** for a room with no usable record (existing contract), with added typed fields, rather than a new reason.
- **Plain folders unchanged:** the readiness line and card are offered only for a folder with `.room-root` (the line the heal net draws, plan 13).
- **Without a session id the hook falls to the newest nest.** The hook does not read stdin, so it knows the session only if the id is in the environment; otherwise "the nest whose BRIEF.md or MINTO.md changed last" (the plan's own fallback) applies. The MCP path always has the session id and so uses the focus.
- **Test fixture honesty:** J4 checks "no other nest's governing thought" inside the memory block only (see Observations).
