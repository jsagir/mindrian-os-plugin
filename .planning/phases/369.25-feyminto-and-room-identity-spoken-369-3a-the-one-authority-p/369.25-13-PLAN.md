<objective>
The 2026-10-06 ruling's second half ("calls the net at session start and before the first governed write, behind its existing approval") and the brief's failure test 1 ("Database missing, corrupt, or not writable: no ready-to-write result. A typed reason names the failed requirement"), with recovery rather than refusal as the positive requirement (brief section 4: "A test that merely detects a refusal is not a recovery test").

Decision this plan fixes (brief section 4: "required checks should correspond to the operation being authorized"; CROSS row 3: "not_ready for the operations that need it"): readiness is per operation. A legacy room (every room born before this phase has 0 identity keys, measured) keeps working for governed writes and research, with its missing identity shown on every result and a recovery card offered once per session, because refusing every write in every existing room until a recovery would break every installed user's room at upgrade; a room whose room.db is missing, unreadable or not writable cannot record a governed write at all, so those are refused. This module is also the readiness definition the real-room negative leg (FCLOSE-07, plan 23) asserts, so quick, deep, Eureka and analogies refuse the same rooms for the same reasons.

Tri-Polar: the recovery card is a gate on the MCP surface (gate_render and gate_answer exist on CLI, Desktop and Cowork), so Desktop users recover without the CLI; the session-start line is the CLI hook's (Desktop and Cowork have no SessionStart hook; plan 20 adds the same line to context_assemble).
