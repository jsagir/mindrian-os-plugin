<objective>
Land the two Wave-0 pins that guard this phase's two constitutional edges: the Phase 8 cross-room
fence, and the one memory capability that must work when no room exists at all.

**Why the cross-room fence needs a test and not just care.** `lib/core/navigation/edges.cjs:45`
records "Cross-room aggregation forbidden (Phase 8 cross-room fence)", and
`lib/core/graph-derivation.cjs:44-46` states the rollup "READS, never writes a cross-room row into
the parent." That is the ONLY sanctioned cross-store operation in the system, and plan 270-10 adds
a second consumer of it. The same file records at `:452-457` that a string-spliced ATTACH path was
a real past bug: a directory name carrying an apostrophe silently broke the statement, and a crafted
name was an injection vector on the parent connection. Pitfall P6 exists because this has already
gone wrong once.

**Why the identity write needs a pre-room test.** Every current memory tool refuses with
`{ok:false, reason:'no_room_db', room_dir: roomDir}` when no room exists (`graph.cjs:202`, `:236`,
`:271`). The cross-room identity write is the one capability that must NOT do that: RESEARCH.md 4.3
proved `writeUserMdAtomic(userMdPath, data)` (`lib/core/user-md-ops.cjs:442`) takes an absolute path
and has zero room coupling, and that `lib/core/user-archetype.cjs:64` already READS
`~/.mindrian-user.md`. The gap is a caller, not a mechanism. This test defines what "reachable
pre-room" means before anyone writes that caller.

**Both tests are RED when this plan finishes.** That is the Wave-0 contract. Plan 270-10 greens the
first; plan 270-11 greens the second.

Purpose: put a gate on the two places where getting it wrong is a constitutional breach rather than
a bug.
Output: two RED test files, discovered automatically by `tests/run-all-270.sh`.
</objective>
