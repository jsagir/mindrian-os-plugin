# Phase 95.2 Plan 01: Install-Cache Atomic Recovery -- SessionStart Preflight Summary

Detection layer for the install-cache failure family: a new parallel CJS SessionStart hook (`scripts/preflight-doctor.cjs`) spawns `node scripts/doctor.cjs --json` with a 1.5s budget, parses the report, and surfaces a one-line ANSI-yellow warning above Larry's banner whenever the install dir is missing or drifted -- emitting both `hookSpecificOutput.systemMessage` (user-visible) and `hookSpecificOutput.additionalContext` (Claude-facing). Healthy installs see zero noise. The plan ships purely LOCAL (Canon Part 8 satisfied) and is wired as the 8th SessionStart entry via Node JSON re-serialization rather than fragile string surgery.

The edit was applied via Node JSON.stringify re-serialization (B4 fix; H2 fix), NOT Edit-tool string surgery. The script:

1. Reads hooks.json with `JSON.parse(fs.readFileSync(..., "utf-8"))`.
2. Idempotency check: `some(e => e.hooks?.[0]?.command?.includes("preflight-doctor.cjs"))`. If already wired, exits cleanly.
3. Pushes the new entry with the same shape as entries 2-7 (matcher "startup|clear|compact", node command pointing at `${CLAUDE_PLUGIN_ROOT}/scripts/preflight-doctor.cjs`, timeout 2000ms).
4. Re-serializes the entire file with `JSON.stringify(hooks, null, 2) + "\n"`. The resulting file is canonical 2-space indentation throughout (Node's stringifier output, equivalent to running through a JSON formatter). Trailing newline preserved.

This is the standard project pattern for programmatic JSON edits and is idempotent + safe to re-run.

## Three-Surface Asymmetry (documented)

SessionStart hooks fire only in Claude Code CLI sessions. The asymmetry breaks down as follows:

| Surface       | SessionStart fires? | How user discovers install drift                                |
| ------------- | ------------------- | --------------------------------------------------------------- |
| Claude Code CLI | YES (every session start, clear, compact) | Yellow warning line above banner via preflight-doctor.cjs       |
| Claude Desktop  | NO                  | Manual `/mos:doctor` run reports drift; no proactive surface     |
| Cowork          | NO                  | Manual `/mos:doctor` run reports drift; no proactive surface     |

Per the tri-polar design rule in CLAUDE.md, this is the unavoidable asymmetry: hooks are a CLI-only primitive. Desktop and Cowork users still get the recovery path (via `/mos:doctor --fix` after Plan 95.2-00 lands the missing-install class A eligibility), they just get it on-demand rather than proactively. This is documented in the script header at scripts/preflight-doctor.cjs and called out in 95.2-02-PLAN.md's autopsy.
