<objective>
WAVE 2 CORE: lib/core/chain-executor.cjs -- the runChain spine, the missing RUNTIME. ONE shared
function in lib/core (called by both the CLI entry and the MCP server, thin command wrappers,
Tri-Polar parity per D-166-04) that takes a sequence of reaches/commands and runs it as
autopilot-with-gates. It implements EXEC-01 (loop runner), EXEC-02 (output-passing carrying the
quality signal), EXEC-03 (posture x evidence-quality gate + forced-material irreversible steps),
EXEC-04 (kill switch + single trace), and EXEC-06 (token budget: maxSteps hard cap + quality
early-stop + distilled output-passing). Extracted from the donor loop in scripts/act-command.cjs
(the planChainRun + walk at act-command.cjs:131-147 and the stop/gate render at
act-command.cjs:172-224) -- no new dispatch path. Re-calls decide() per loop (lib/core/
navigation-engine.cjs:596) to re-derive the next reach from the navigated graph neighborhood, and
NEVER mutates decide()'s return shape (B2).

NEXT-STEP AUTHORITY (EXEC-01 + B2 + SPEC Out-of-scope): the loop's next-step selection is driven by
decide() (navigation-engine.cjs:596 returns ONE typed decision from the navigated graph
neighborhood), NOT by recipe-maps.rankedNextReach. rankedNextReach (Wave 1) is the projection's
contract-only reader; live nav-engine consumption of the projection cache for ranked next-reach is
DEFERRED with Phase 157 (166-SPEC.md Out of scope: "the executor reads decide() locally until then").
This is also why B2 is load-bearing: decide() IS the live authority, so the loop re-calls it per step
and records its return UNCHANGED. The loop NEVER substitutes the projection's ranked list for decide().

Purpose: the SPEC's core finding is that the suggester exists but the executor does not -- three
divergent loop copies (act/pipeline/ignite) with no shared runtime, no single posture authority at
runtime, no single trace, and decide() never consumed in a loop. This wave is the cook: deliberately
obedient, it does not pick the menu (the chef = decide()) and does not own truth (the human at the
gate). That separation is what keeps Canon Part 9 intact.

Reuse before build (Canon Part 7): the loop body, the stop-condition, and the kill-switch already
ship in scripts/act-command.cjs (the DONOR) -- this wave EXTRACTS that body into the shared
chain-executor.cjs and generalizes it behind the six-callback contract; act becomes the thinnest
caller in Wave 4. The posture authority is recipe-maps.postureForCommand (Wave 1, delegating to
command-resolver validateChainAutonomy). The per-step brick is agents/framework-runner.md unchanged
(it already accepts previous_output at framework-runner.md:40 and returns chain_output + quality at
framework-runner.md:126,133,164). The trace is decide()'s decision_trace
(navigation-engine.cjs:606) plus each chain_output. A rewrite is rejected because ~80-85 percent of
the machine already exists and is scattered; the net-new is only the contract, the gate predicate,
and the trace join. Explicitly NOT a new orchestration framework (no LangChain/CrewAI/AutoGen per
CLAUDE.md tech-stack rules).

Output: the runChain spine + its callback contract, two test suites, and the Wave-2 entries in
run-all-166.sh. NO em-dashes anywhere (CLAUDE.md HARD RULE).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| step output -> next step input | a low-quality chain_output must not silently propagate down the chain |
| autonomous_safe tag -> auto-run | an irreversible action must never auto-run on a tag alone |
| decide() return -> trace | the engine contract is read-only; the executor must never reshape it (B2); decide() is the live next-step authority, rankedNextReach stays contract-only |
| onStep dispatch -> Brain | the per-step brick is the framework-runner; runChain itself opens no Brain wire (Part 8) |

| T-166-05 | Tampering | garbage chain_output propagation | mitigate | the gate halts on priorOutput.quality === 'low' even for an autonomous_safe step (EXEC-02 quality carry) |

| T-166-07 | Tampering | decide() return-shape mutation | mitigate | the trace records the decision_trace handle unchanged; the loop test asserts reference/deep equality with decideFn's return (B2); the loop uses decide() not rankedNextReach as next-step authority |
