## 2. Decisions of this plan

* D1. A body is `sentences >= 3`, and nothing else. Word count, newline count and a quoted span no longer make a body. Reason: the ruling says a body of text is 3 sentences or more and less than that can go.
* D2. 1 or 2 sentences that are more than a sprout become an edge. Reason: the edge is the existing class for text between a keyword query and a body. Its rules (prose patterns, `PRIVATE_POSSESSIVE`, `PRIVATE_CONFIDENTIAL`, first-person statement, the unknown proper name rule) already decide edges today. The rules of every shape (credentials and the ALWAYS patterns, the room lexicon, structured identifiers) run before the shape branch, so they still block. A new class would need hook and split-route changes; the edge needs none.
* D3. A "long edge": an edge with 40 or more words, 2 or more newlines, or a quoted span (the size that was a body before the ruling). The guard applies the private-claim marker rule (`_hasPrivateMarker`, reason `private_marker`) to a long edge too. Reason: before the ruling such text was blocked whole; without D3 a 2-sentence text of 50 words with "proprietary" or "our onboarding" would pass (PROVEN: an edge today does not check those words). D3 changes nothing for text that was an edge before. The constants are renamed `LONG_EDGE_MIN_WORDS` (40) and `LONG_EDGE_MIN_NEWLINES` (2); `BODY_MIN_WORDS` and `BODY_MIN_NEWLINES` leave the exports (no reader in `lib`, `scripts`, `bin`, `tests`: PROVEN by `grep -rn`).
* D4. A quoted span is never a sprout (`!quoted` is added to the sprout test). Reason: before, a quoted span was a body, so a sprout never held one. Without this, a short quoted phrase would skip the prose and name rules.
* D5. No hard character limit is added to the shaped path. Reason: the canon states none, and no test needs one (85 of the 86 tests keep their state without one, section 1.4). The old-path limit `THEO_STRING_CEILING = 4000` stays unchanged. See assumption A3.
* D6. The sentence count changes as in section 3. Reason: the old count split on every full stop, so "e.g.", "vs.", "U.S." or an initial made 1 question into 3 or 4 sentences (PROVEN: "How does a team use e.g. the five whys vs. a fishbone? * D7. The guard keeps its order of checks. Only 3 lines are added after the edge rules. The hook, the split route and the old path do not change.

## 3. The sentence-count rule

1. Split the text at each line break (`\r\n`, `\r`, `\n`). A line break always ends a sentence. An empty line counts 0.
2. In a line, a sentence ends at a token that ends with `.`, `!` or `?` (closing quotes or brackets may follow), when white space follows and the next token starts with a letter (an opening quote or bracket may come first).
3. A full stop does not end a sentence after: a dotted abbreviation (`e.g.`, `i.e.`, `U.S.`, `a.m.`), a single-letter initial (`J.`), or a word of the short grammar list `etc. vs. cf. approx. incl. al. fig. no. dr. mr. mrs. ms. st. prof. jr. sr.`. `?` and `!` always end a sentence.
4. A sentence counts only when it holds a letter. So a list marker (`1.`, `-`, `*`) is not a sentence of its own, and a number such as `2.0` does not end one (no white space follows the full stop).
5. The last sentence of a line counts when it holds a letter, with or without an end mark.

function countSentences(text) {
  if (!text) return 0;
  const lines = text.split(LINE_BREAK);
  let n = 0;
  for (let l = 0; l < lines.length; l += 1) {
    const parts = lines[l].split(SENTENCE_BREAK);
    let open = false;
    for (let i = 0; i < parts.length; i += 1) {

## 11. Known limits

* L1. Hard-wrapped prose counts 1 sentence per line. 1 sentence wrapped on 3 lines is a body. This matches the old newline rule (2 newlines were a body).
* L2. An abbreviation that is not on the list (for example "Inc." or "Corp.") ends a sentence when a word follows it. An over-count can make a 2-sentence question a body. An abbreviation on the list at a true sentence end undercounts by 1.
* L3. A title-case framework phrase that is not a canonical phrase can fire the name rule on an edge (PROVEN: "the Jobs to be Done framework" in a 2-sentence question gave `edge_rule`; lower case passes). This is the edge behavior of `74fda0093`, not a change of this plan.
* L4. A short edge (under 40 words) does not check the private words `secret`, `proprietary`, `undisclosed` or `my`/`our` with any word (only `PRIVATE_POSSESSIVE` and `PRIVATE_CONFIDENTIAL`). This is the behavior of `74fda0093`; D3 does not change it.
* L5. The comment of the guard at line 1298 ("Shape (size, sentences, lines, quoted text) separates a sprout from a body") is not updated. It stays true for sprout against edge.
* L6. The shaped path has no character limit (D5). A 2-sentence text of several thousand characters with no rule hit is allowed.
* L7. The released plugin changes only after a release and an update (memory: a `main` commit is not live until released).
