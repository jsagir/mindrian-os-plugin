## Design

### Item 1: a new key `goal_job` in the `suggest_next` reply

The key is at the top level of the reply, beside `next_move`. It is sent when the session has a room. It is left out when there is no room or the read fails.

```text
goal_job: {
  state:  "set" or "not_set",
  id:     the goal job id, or null,
  offers: job ids of the job vocabulary, `explore` left out, at most 24 (19 ids today),
  how_to: fixed sentences
}
```

* `state` comes from `resolveSelectionJob(roomDir, null)` (`lib/hmi/jtbd-state.cjs:291`), the 1 read order that the selector and the brief use. `set` means that the result has the origin `goal`. So the key agrees with the selector, also after plan 395-04 (a goal `explore` gives `not_set`) and for a stored goal in free text (`not_set`; this closes mi3 for the new key).
* The first sentence for `not_set` is "No goal job ranks the next move." It is true in each of those cases.
* `how_to` for `not_set`, as sent:

```text
No goal job ranks the next move. The job of a nest ranks the move in that nest, when the nest has one. To set a goal job: ask the person what they want to get done, show goal_job.offers, and let the person pick one job id. Do not pick for the person. Call gate_render with kind "strategy_goal", a header that names the job, approving ["rewrite-jtbd"], and options [{"id":"rewrite-jtbd","label":"Set this job","preview":"{\"jtbd\":\"<job id>\"}"},{"id":"defer","label":"Not now"}]. To set the problem type too, add "rung" to the preview JSON: UnDefined, IllDefined, WellDefined or Wicked. After the person answers the card, call gate_answer with the gate_id, chosen ["rewrite-jtbd"] and verdict "approve", or chosen ["defer"] and verdict "defer". When the gate_render reply has answer and next, the person answered in a dialog: do what next says. When the person closes a dialog with no answer, gate_answer replies card_pending and no job is set: show the card again. The job is set only when the gate_answer reply has strategy_ratification.goal_written true.
```

* `how_to` for `set` starts with "The goal job of this room ranks the next move in every nest: <id>. To change it: let the person pick another job id from goal_job.offers." The steps after it are the same.
* The sentences are constants. They hold no room content and no user words. The job id is from the closed vocabulary.

### Item 2: a strategy card answered in a dialog reaches `gate_answer`

Decision: plan the fix. It is small (19 added lines, 1 removed line, all in `gate_render`) and it is safe for these reasons.

* It adds no second ratification path. The goal is written by `gate_answer`, by the code that writes it for the other rungs.
* The human answer is kept. `gate_answer` accepts the relay only when the chosen ids are exactly the ids the person accepted in the dialog (`gate.cjs:1577-1591`). The same guarantee holds today for a chain halt card and for the room creation card.
* The ledger rules are kept. The entry is released after the commit (`gate.cjs:1763`). A second answer is a replay. The 30 minute limit and the limit of 200 open gates hold.
* The verdict is coherent. The sentence `next` tells the model which verdict to use. When the card declares `approving`, `gate_answer` refuses an approve of `defer` (PROVEN, finding 11).
* No other kind changes. The condition is `goalGate.isStrategyCard(result.card)`. A mirror card is never a dialog (`gate.cjs:1430`), and the condition also names `!mirrorExtra`.

What changes for a host on the dialog rung: before, the dialog answer of a strategy card was lost. After, `gate_render` returns the answer and the key `next`, and the gate stays open for the 1 `gate_answer` call.

The three Claude surfaces (CLI, Desktop, Cowork) do not use the dialog rung (`gate-render.cjs:200`), so nothing changes there.

### Item 3: the goal of the folder that holds the nest

Rule: the goal that ranks a nest, and that is in its brief fingerprint, is the goal of the parent folder of the nest. `recordBasis` and the session-start reader already use that folder. `renderBrief` now uses it too, for the selector call and for the basis, also when the caller gives another folder as `roomDir`.

* For a direct child of the room the parent folder is the room. Nothing changes (PROVEN, "No-change proofs").
* For a nest in a sub-room the folder is the sub-room. A goal of the sub-room ranks its nests. A goal of the root room does not.
* This is how a session bound to the sub-room already works: `decide()`, `suggest_next` and `gate_answer` use the sub-room folder.
* `renderBrief` gives the selector a copy of the nest record with `roomDir` set to that folder. `nextMoveForSection` reads `nest.roomDir` in 1 place, the goal read (`next-move.cjs:486`). No other value of the nest record changes.

### Item 6: the time guard

`sectionForSelector(roomDir, sectionPath, elapsedMs)` returns `undefined` when `shouldSkipReachPenalties(elapsedMs)` is true, else the slug as before. A missing or non-finite time never skips.

 * (jtbd-state resolveSelectionJob), so it agrees with the selector and with the brief. Local read only, never writes,
 * never throws. Returns undefined when there is no room or the read fails, so the reply omits the field.
 *
 * @returns {{ state: 'set'|'not_set', id: string|null, offers: string[], how_to: string }|undefined}
 */
function goalJobFor(roomDir) {
  if (typeof roomDir !== 'string' || !roomDir) return undefined;
  try {
    const sel = require('../../hmi/jtbd-state.cjs').resolveSelectionJob(roomDir, null);
    const vocabulary = require('../../core/section-registry.cjs').JOB_VOCABULARY;
    const offers = vocabulary.filter((id) => id !== 'explore').slice(0, GOAL_JOB_OFFERS_MAX);
    if (sel && sel.origin === 'goal' && typeof sel.id === 'string' && sel.id.length > 0) {
      return { state: 'set', id: sel.id, offers: offers, how_to: GOAL_JOB_SET_HEAD + sel.id + GOAL_JOB_SET_TAIL + GOAL_JOB_STEPS };
    }
    return { state: 'not_set', id: null, offers: offers, how_to: GOAL_JOB_NOT_SET + GOAL_JOB_STEPS };
  } catch (_e) {
    return undefined;
  }
}

// The text of one "## heading" block of a brief (heading line left out).
function block(text, heading) {
  const lines = String(text).split(/\r?\n/);
  const at = lines.findIndex((l) => l.trim() === heading);
  if (at === -1) return '';
  const out = [];
  for (let k = at + 1; k < lines.length; k++) {
    if (/^## /.test(lines[k])) break;
    out.push(lines[k]);
  }
  return out.join('\n').trim();
}
