<objective>
Close TRUST-02. `scripts/check-flagship-floor.cjs::evaluateFloor()` currently stamps any row
without a clean numeric result as `MISS`, so a rate-limited probe, a timed-out probe, and a
framework that genuinely misses the floor are byte-identical to the operator and to any
automation reading the exit code. Give the gate a third verdict, `VOID`, triggered by any of
the three D-05 failure modes, with its own count, its own exit code 3, and output that names
every failed row and its trigger type (D-06).

The failure kind cannot be reconstructed downstream: `brainCall`'s catch block keeps only
`e.message`, which collapses an `AbortSignal.timeout` abort ("The operation was aborted due to
timeout") and a connection failure ("fetch failed") into the same `bodyText` prefix. So the
classification is added at the one place the error object is still in hand.

Purpose: FLOOR-01 says the floor script "exits 0 on a window-fresh run (no probe failures, per
TRUST-02)", and FLOOR-03 says "verify, never predict". A probe that did not cleanly succeed
carries no trustworthy `matches` or `score`, so scoring it at all is the prediction FLOOR-03
forbids.

Output: an additive `errorKind` field on `brainCall`, a `failures[]` array on `probeFramework`,
a `VOID` verdict with `voidCount` and exit code 3 on `evaluateFloor`, two pure exported
renderers, and two new hermetic test suites.
</objective>

## Decisions recorded in this plan

**OQ-1: `brainCall` does NOT get 429 retry logic in this phase.** D-08 governs the RUN, not
the individual HTTP request. Adding retry logic to a second HTTP client doubles this phase's
surface for zero requirement coverage, and TRUST-02's requirement text is satisfied by VOID
alone. Instead, the VOID output prints the `Retry-After` seconds it observed (Task 3) so the
human re-run D-08 mandates lands AFTER the window rather than inside it. If the floor run
VOIDs repeatedly in practice, that is a follow-on seed, not a scope expansion here.

**OQ-2: a framework with NO probe entry at all stays MISS, not VOID.** `tests/test-249-floor-gate.cjs`
pins this ("a framework with no probe result at all (never probed) is a MISS, not silently
dropped"), D-05 names three trigger types and "never probed" is not one of them, and the live
`main()` writes an entry for every enumerated framework so the branch cannot fire in
production anyway. Keeping it preserves a pinned test at zero real-world cost. The reasoning
goes in the code comment.

**OQ-3: a JSON-RPC error object inside an HTTP 200 classifies as `hard_error` and VOIDs the
row.** Under D-05 anything that did not cleanly succeed VOIDs regardless of bucket, so the
label only affects the D-06 detail line. **Carried risk (RESEARCH.md assumption A1):** if
`orchestration_readiness` returns a JSON-RPC error for an unknown framework name rather than a
readiness object, every genuinely-absent framework becomes VOID instead of MISS and the floor
can never turn green during the enrichment phases. A1 was NOT discharged at research time. It
is discharged by the live floor-run checkpoint in Plan 259-04, whose instructions call it out
explicitly. Do not silently assume it holds.

**Tri-Polar Design Rule: CLI-only, as a deliberate call.** `scripts/check-flagship-floor.cjs`
is a maintainer ratification script run by Claude on the CLI. It has no Claude Desktop or
Cowork surface and needs none: it is not a user-facing capability, it is a gate an operator
runs before declaring the floor green. Recording this as a stated skip rather than an
oversight, per the repo's strong default. `scripts/build-brain-census.cjs` is the same class.
Canon Part 11 (CIRS): neither file is an invocable surface, so no born-wired registration and
no `hitl_shape` declaration is due for this plan.
