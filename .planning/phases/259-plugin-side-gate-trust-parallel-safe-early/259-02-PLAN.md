## Decisions recorded in this plan

**OQ-5 / F-09: Option B is taken.** RESEARCH.md flagged this as the one scope call in Phase
259 that edits a contract three prior phases deliberately froze, and asked the planner to make
the call explicitly rather than diverge silently. The call, and why:

1. **The coercion trap is not hypothetical, it is a live landmine.** `REFUSAL_KINDS.indexOf(kind) !== -1 ? kind : 'unreachable'`
   appears three times (:246, :316, :334). Option A ships a sentinel that, the first time any
   caller routes it through the refusal rail, renders as `BRAIN_UNREACHABLE`. That is
   TRUST-01's own bug, one layer up, with no test guarding against it.
2. **D-03's stated rationale names the message.** "Distinguishing temporarily overloaded from
   actually down changes both the honest-refusal message shown and the operator's response."
   Option A satisfies D-03's letter and abandons its reason.
3. **The open RCA prescribes it.** `.planning/debug/brain-client-429-maps-to-unreachable-zero-retry.md`
   `next_action` reads: "a distinct `rate_limited` sentinel so refusal-messaging can say the
   true reason."
4. **Cost is measured and small.** Verified this session: no production caller maps a sentinel
   `.error` into `refusalResponse` today (the shim's pattern is
   `r == null ? refusalResponse('unreachable') : asContent(r)`, so sentinels pass through raw
   exactly as `tier_denied` does), and `grep` finds ZERO consumers of the `next_moves` option
   handles anywhere in `lib/`, `bin/`, `scripts/`, `skills/`, `commands/`, or `tests/`. The
   blast radius is two pinned assertions, both amended deliberately in Task 2.

**This plan makes no wiring change.** It does not alter the shim's `r == null` pattern and does
not route the sentinel through `refusalResponse`. It closes the trap and completes the rail so
that a future consumer, or the operator reading `doctor`, gets the honest status. Recorded as
a deliberate scope boundary, not an oversight.
