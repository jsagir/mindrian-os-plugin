<objective>
Build the CTXL-03 benchmark gate as the THIRD instance of an idiom this repo already
ships twice, not as a new eval architecture: deterministic code checks that gate
every commit at zero API spend, plus an opt-in model leg that skips cleanly. The
manipulated variable is the presence of room context; the measured quantity is
answer accuracy against a fixed local task set; the recorded output is a delta,
whatever its sign.

Purpose: `240.1-RESEARCH.md` Finding 3 established that `scripts/huji-eval.cjs`
(Phase 229) and `scripts/skillopt-eval.cjs` (Phase 230) already implement the
two-layer discipline, the graded anchors, the cost ledger, the clean-skip gate, and
even a before-versus-after comparison assertion. Canon Part 7 says port that shape.
The single most important divergence from the analog is Pitfall 6 and ROADMAP SC3:
huji-eval's calibration gate FAILS CLOSED on a bad correlation; this one must NOT.
If no accuracy delta is measurable at MindrianOS's scale, that is itself the finding
to record, not a reason to skip the gate and not a reason to fail it.

Output: one new harness script, one new gate test.
</objective>

<planner_resolutions>
RESOLUTION 1 (locked, the whole point of the plan). `checkDeltaRecord` asserts that
a measurement RAN and a well-formed result was WRITTEN. It never asserts the SIGN of
the delta. Any assertion of the form `withContext > withoutContext` is forbidden in
this harness and in its gate test. A null or negative delta is a recorded PASS
carrying a `finding` string. This is the direct, literal reading of ROADMAP SC3 and
of Pitfall 6, and it is the one place this harness must diverge from
`scripts/huji-eval.cjs:1055`, which exits 1 on a failed calibration.

RESOLUTION 2 (locked). New env var `CTXL_EVAL_LIVE`. Do NOT reuse `HUJI_JUDGE_LIVE`
(`240.1-RESEARCH.md` Runtime State Inventory says so explicitly). The deterministic
suite never reads it; only the model leg does.

RESOLUTION 3 (locked). `scripts/ctxl-eval.cjs` is a plain `scripts/*.cjs` utility,
the same class as `scripts/huji-eval.cjs` and `scripts/skillopt-eval.cjs`. It is NOT
a command, agent, pipeline, or skill, so Canon Part 11 CIRS's born-wired and
HITL-shape declaration mandates do not apply to it, exactly as they do not apply to
its two predecessors. Do not add a `commands/` entry, do not add a skill, and do not
register it in the connector registry. State this disposition in the summary so the
Tri-Polar and CIRS skips are a stated call rather than an oversight.

RESOLUTION 4 (locked). The A/B condition is assembled from the fixture room's own
artifact bodies by `buildBundle(room, task, { withContext })`. WITH context includes
the artifact text; WITHOUT context includes only the question and a fixed neutral
preamble. The harness never assembles a bundle from any path outside the fixture
root.
</planner_resolutions>
