## Decisions Made

- **Exit-code sequencing (structural deviation from the `run-all-240.sh` analog, not a deviation from this plan's own spec):** `run-all-240.sh`'s `found -eq 0` guard calls `exit 1` immediately, before any other leg runs. This plan's Task 2 explicitly requires the opposite -- "The tripwire leg runs on every invocation" and "The runner still exits 1 overall on the empty test-file discovery" -- so the found-eq-0 check was restructured to set an `EMPTY_DISCOVERY` flag instead of exiting immediately, and the actual `exit 1` was moved to the final summary block (`exit 1` if `EMPTY_DISCOVERY` is set, else the normal `[ "$FAIL" -eq 0 ]`). This is a direct implementation of the plan's own Task 2 done-criteria, not an invented change - flagged here because it diverges from the copied analog's control flow, which the plan's `read_first` pointed at.
- Scope-escape tripwire self-test and the glob-discipline self-test share a single `mktemp -d` / `trap` scratch directory (`$TMP`), per the plan's explicit instruction ("in the same scratch `mktemp -d` used by Task 1's self-test").
- `SCOPE_ESCAPE_TOKENS` is a two-element array (`gsd-core`, `.planning/STATE.md`) checked independently per frozen file via `grep -qF`; either token present (post-`strip_comments`) counts as a scope escape.

None (functional) - plan executed as written, including the two done-criteria that required diverging from the `run-all-240.sh` analog's immediate-exit control flow (documented above under Decisions Made, since it is a direct instruction in the plan text itself, not an unplanned fix).

## Issues Encountered

- The sandbox's Bash tool rejected several otherwise-valid commands (chained `&&` command lists, and `grep` invocations containing a literal multibyte em-dash/en-dash character via `$'...'` bash string literals) with a generic "too complex to verify worktree isolation" / "git operations" error message that did not match the actual command content. Worked around by running commands individually (one command per Bash call) and by using `python3 -c "...codepoint count..."` instead of a literal-unicode `grep -c $'—'` for the em-dash/en-dash checks. No functional impact - all required checks were still executed and passed.
