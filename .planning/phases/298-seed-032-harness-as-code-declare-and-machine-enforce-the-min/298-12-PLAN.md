## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| policy files and Larry surfaces -> the committed manifest | Arbitrary repo file content becomes digest input |
| manifest -> consumers | The pre-commit guard, `recipe-maps.cjs` and `build-new-surface.cjs` all read it |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-298-01 | Tampering | `data/harness-manifest.json` | mitigate | The manifest is generated data only. No consumer executes anything from it: the runner spawns paths declared in policy files, which are separately validated against `runner_path_rule`. sha256 gives tamper EVIDENCE, not tamper PROOF, since the manifest is committed alongside what it digests; that is the correct posture for a repo artifact and is stated rather than overclaimed |
| T-298-02 | Information disclosure | the three new keys | mitigate | `NODE_FIELD_ALLOWLIST` widens by exactly three generic machinery names, and the part8 boundary test asserts every string under them is a repo-relative path, a hex digest or a number. `methodology_tier` stays mindrian-operation. No room content, no user bytes, zero network |
| T-298-05 | Denial of service | `loadPolicies` in the generator | mitigate | Per-file try/catch: one malformed policy is reported by name and skipped from digesting while `--check` still fails, the shipped T-233-01 and T-217-01 pattern |
| T-298-03 | Elevation of privilege | `validatePolicyFile` | mitigate | The `runner_path_rule` is enforced at generation time as well as at run time, so a traversal path cannot reach a committed manifest in the first place. Fail closed per the schema's `default_on_miss` |
| T-298-26 | Tampering | the T-side sync payload | mitigate | `git diff --stat HEAD -- data/command-registry.json` is an acceptance criterion and must report zero changed files; `dist/` is asserted unchanged as well |
| T-298-SC | Tampering | npm/pip/cargo installs | accept | Zero package installs in this phase; hand-rolled validation deliberately avoids ajv and zod |
</threat_model>
