## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| process <-> process via room/.mindrian/write.lock | CLI hooks, scripts and the MCP server contend for one room's writes |
| lock file contents | Any local process can write the lock file; its contents are claims, verified by liveness |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-354-05 | Tampering | acquireLock staleness | mitigate | Age never displaces a live owner; only ESRCH (dead pid) or a corrupt file triggers recovery; case A and B regressions |
| T-354-06 | Tampering | releaseLock | mitigate | Compare token then unlink; a non-owner or stale handle release is a no-op returning not_owner; case E regression |
| T-354-07 | Denial of service | dead-owner recovery race | mitigate | .recover mutex created with 'wx' plus re-read-and-compare before unlink; exactly one winner (case D) |
| T-354-08 | Denial of service | leaked lock held by a live process | accept | A live owner is never displaced automatically (SYS-02 requirement); breakLock is the explicit compare-and-unlink recovery; all current callers release in finally (verified at plan time) |
| T-354-08b | Spoofing | forged lock file claiming a live foreign pid | accept | A forged lock can only block writes (fail-closed) until breakLock; it can never cause two writers |
</threat_model>
