<objective>
Give the room.db opens of the memory hook and of the feynman opener a busy timeout that costs one wait per run, not one wait per write, and measure how long a run then holds the write lock (proposal 400.3-06 items V8 and feynman-timeline-refresh-command.cjs:116; review B-b, M3, M4; D-10, D-11).

Purpose: both scripts open room.db with no busy timeout, so a contended write fails at once. A busy timeout on the handle alone multiplies: lib/core/memory/reconcile-memory-runner.cjs:544-620 runs each write in its own try and swallows the error, so 13 memory files under a held lock would wait 13 x 750 ms, the host would kill the hook, and the typed reason would never print. One BEGIN IMMEDIATE around the whole run waits once and makes the run atomic, but then the run holds the write lock for its whole length, which this plan measures and bounds.

Output: DEFAULT_BUSY_MS in hook-busy-cap.cjs; resolveRoomDb with a busy timeout as the one script opener; reconcileRoom in the memory hook; withRoomTx around the 4 session-start blocks and the 2 refresh commands; the lock-hold measurement; tests/test-400-3-room-db-scripts.cjs; BASE and baseline records.
</objective>
