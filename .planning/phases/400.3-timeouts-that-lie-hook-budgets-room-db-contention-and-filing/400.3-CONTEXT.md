# Phase 400.3 Context: filing that never reaches the graph (plans 01 and 02 only)

## Phase Boundary

This planning round covers two plans only. Plans 03-16 in `400.3-PROPOSAL.md` stay unplanned.

- **400.3-01 Index on MCP filing.** The `artifact_file` MCP tool (`lib/mcp/tools/views.cjs:509-548`, `fileArtifact` at `:221-440`) indexes the filed artifact in the room graph (`lib/core/graph-ops.cjs::indexArtifact`) and reports the index result honestly.
- **400.3-02 Room-root detection.** Replace the `/room/`-or-`/rooms/` path rule (`lib/core/intelligence-cascade.cjs:181-194`, guard `:650-654`) with separator-normalized room-root detection that works for `~/MindrianRooms/<slug>/...` and Windows paths, and fix the bash walk-up in `scripts/post-write:262-273` for backslash paths.

Bug being fixed: on a new room (reported on Windows, PwS Academy), artifacts did not reach the local graph until the user asked for an index or rebuild. Root causes (PROVEN, section 2 of the proposal): MCP filing never indexes; the cascade path rule skips every default-home room on every platform; nothing indexes later (no index call in on-stop, session-start, coordinator, derive drain or sweep).

## Implementation Decisions

- **D-01 (owner ruling 2026-11-26, "Index only now"): widening the room rule turns on graph-index ONLY for rooms the old rule skipped.** The full cascade (classify-insight, HSI, hsi-to-graph, presentation, compute-state, build-graph, analyze-room, git commit, opportunity banking) keeps its current reach until plan 400.3-08 moves it off the foreground. Reason: the full cascade measured about 3,553 ms wall and 5,015 ms CPU per Write (`.planning/debug/384-s2-cascade-path-rule.md` E5) inside a 5 s hook budget (`hooks/hooks.json` post-write). Rooms whose path already matched `/room/` or `/rooms/` keep the full cascade exactly as today (no behaviour change for them).
- **D-02: the old rule was option-b territory, not a revert to undo.** 384-20 reverted option-c (a speed skip, NO-GAIN, commits ab09ac612/94ab074c0 reverted by a312ac9f7/bb2470900). Do not reintroduce option-c.
- **D-03: room-root detection.** Normalize separators first (backslash to forward slash, drive letter kept), then a room root is the nearest ancestor holding the room identity marker the repo already uses (check `ROOM.md` + `.mindrian/` or `STATE.md`; reuse an existing resolver such as `scripts/resolve-room` logic or a `lib/core` room-root helper before writing a new one, Canon Part 7). `findRoomDir` must terminate at a POSIX root and at a Windows drive root (`C:/`, `C:\`). The registry may be consulted only through an existing read helper.
- **D-04: honest result on MCP filing.** `artifact_file` returns `graph_index: { ok, reason }`. When the file landed but the index failed, the response says so (`partial: true`, top-level `ok` stays true only if the file itself landed; never claim indexed when not). Index failure never deletes or rolls back the filed file.
- **D-05: write.lock.** `indexArtifact` goes through `graph-ops.enqueueWrite`, which throws at once on a held `write.lock` (`lib/core/write-lock.cjs:240-256`). Plan 01 must not hang the MCP tool: a held lock gives `graph_index: { ok:false, reason:'write_lock_held' }`. The bounded retry is plan 04, not this round; a minimal bounded retry is allowed only if it reuses the existing backoff in `scripts/minto-debouncer.cjs:188-195`.
- **D-06: hook budget.** The index-only path in post-write must stay well inside the 5 s budget. Run it in the existing foreground cascade call (pass a mode flag through `mindrian-tools.cjs cascade`) or a single node call; no new bash children. Measure on Linux with `scripts/measure-hook-cold-start.cjs` (or the 384 harness) and record the number; native Windows timing is UNMEASURED and must be stated as such.
- **D-07: status honesty in post-write for the index-only path.** The advisory line must say "indexed" or "index failed", never "cascade complete", for an index-only run. (The general `partial` status for the full cascade is plan 03, out of scope.)
- **D-08: Canon.** Part 8: no new egress; the index is local. Part 9: writes go through the existing graph-ops / navigation chokepoints, never a new `DatabaseSync` open. Part 11: no new invocable surface; `artifact_file` keeps its declared shape.
- **D-09: Tri-polar.** Plan 01 is the Desktop/Cowork path (MCP); plan 02 is the CLI path (hooks). Both must pass on Linux; Windows path handling is covered by unit tests on path strings, not by a Windows run.

### Owner rulings after the EGM goldfish review (2026-11-26, recorded from the gate card)

- **D-03 amended (owner ruling): the room marker for indexing is `.room-root` AND an existing `<room>/.mindrian/room.db`.** The old text "ROOM.md + .mindrian/ or STATE.md" is superseded: GSD `.planning/` folders hold STATE.md and `.planning/.mindrian/`, so that text would index planning folders. No second marker (STATE.md + ROOM.md + room.db is NOT accepted). Unmarked older rooms stay healed under approval as today (`lib/core/graph-backfill.cjs`).
- **D-10 (owner ruling): no hook and no index call creates or recreates room.db.** When `.mindrian/room.db` is missing, index-only skips with reason `room_db_missing`. Same rule in node and bash.
- **D-11 (owner ruling): busy wait.** The index-only call waits at most about 750 ms for the SQLite lock, through an option on the existing opener (`lazygraph-ops.cjs::openGraph`, a small slice of plan 06; no new `DatabaseSync`). Before the node call, post-write writes a `pending` side-channel record, so a host kill never leaves a stale "indexed" record.
- **D-12 (owner ruling): MCP reach.** Only `artifact_file` (plan 01) is the Desktop/Cowork index door this round. The `fireCascade` callers in `lib/mcp/tool-router.cjs` pass no `filePath` field, so they never reach the cascade; plan 02 must not claim they index. Logged as a follow-up.
- **D-05 tightened (design fix, inside the existing ruling): bounded lock retry is now required, not optional,** reusing the existing backoff (`scripts/minto-debouncer.cjs:183-197`), total cap about 750 ms, because post-write's own background helpers take `write.lock` about 100 ms before an index-only call.

### Owner rulings after the build (2026-11-26, option A, relayed by the owner's session)

- **C10 (SQLite busy on the index path): RULED.** The arm is "busy is reported within 750 ms". lazygraph indexArtifact reads inside a deferred BEGIN before its first INSERT. In WAL mode, SQLite returns SQLITE_BUSY on that read-to-write upgrade at once (measured 1-3 ms), so the busy timeout of the opener is not used on this path. BEGIN IMMEDIATE on the index path is plan 400.3-06.
- **H5 (hook wall time under a held write.lock): KNOWN-OPEN, fixed by plan 400.3-08.** post-write runs the minto-debouncer enqueue in the foreground with its retry loop (about 11-14 s under a held write.lock, the same at BASE). The arm asserts that the advisory and the side-channel record agree. It measures the wall time and prints it as known-open, not as a pass. Arm H5b (a 30 s holder) reaches "index failed (index only)" for real.
- **Status words.** An index-only run gives cascade_status "indexed" or "index_failed". room_db_missing gives the third word, cascade_status "skipped", with the advisory "post-write: cascade skipped for <file>" and graph_index.reason "room_db_missing".
- **Pending record (stated behaviour change).** post-write writes the pending record before the foreground debouncer when the room is known (STATE.md or an existing room.db), and before the node call when the cascade room differs. This also applies on the legacy full-cascade path: a legacy /room(s)/ room now gets a pending record first, and the final record replaces it.
- **D-10 against D-01 on the legacy path: RULED, D-01 wins this round.** Legacy /room/ and /rooms/ rooms keep their behaviour. The legacy Step 2 indexArtifact call stays without mustExist, so it can still create room.db on a legacy room without one. Plan 400.3-08 fixes the conflict when the cascade moves off the foreground.
