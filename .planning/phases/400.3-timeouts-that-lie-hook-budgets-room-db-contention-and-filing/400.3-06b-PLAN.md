<objective>
Make the room.db write door hook-safe on a ready room, and keep the typed busy contract for the callers that write (proposal 400.3-06 item "skip the migration chain when user_version matches", left after Phase 400.4 plan 10, OR-3; D-10, D-11).

Purpose: every openRoomDb call takes the SQLite write lock, because installChangeLog runs BEGIN IMMEDIATE on every open (PROVEN: under a held write it is the only chain step that waits; the 7 others finish in 0 ms). So a read-only use of the write door waits busyMs and then fails with RoomDbBusyError whenever another process writes: up to 750 ms in a hook (the 400.4 cap) and up to 5000 ms for each MCP tool.

Output: the stamp skip and the writeProbe option in room-db.cjs, the fast path in installChangeLog, writeProbe at the 2 write users that read the typed class at the open, 4 fixture amendments, tests/test-400-3-room-db-opener.cjs, BASE and baseline records.
</objective>
