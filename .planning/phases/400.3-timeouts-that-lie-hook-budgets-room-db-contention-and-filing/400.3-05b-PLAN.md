<objective>
Read the Part 8 room lexicon from a cached file while the room is unchanged, so that the guard hook does not read node rows or rebuild entries on every Brain or Theo call (OR-5, OA-1, proposal 400.3-05).

Purpose: each guard call is a new process, so the in-process memo of loadRoomLexicon (`_cache`, part8-room-lexicon.cjs:55) never helps the hook. Every call loads node:sqlite, opens room.db read-only, reads up to 5000 node rows and rebuilds every entry, inside a 5 s budget on a host whose timing is UNMEASURED (native Windows). With this plan an unchanged room costs one read-only open and 3 small reads; a changed room costs the BASE read once, then the cache is fresh again (OA-1).

Output: the persisted cache in lib/core/part8-room-lexicon.cjs, tests/test-400-3-lexicon-cache.cjs, BASE and baseline records, the Linux timing with a fresh and a changed room.
</objective>

Why the key reads room.db (planning finding, PROVEN by reading): any room.db write can add a room term, and room.db changes on most turns (post-write indexes each Write; several UserPromptSubmit hooks write room.db). A file stat of room.db or of its WAL is not a sound change signal (review major). The change feed of Phase 369 is: every node or edge insert, update and delete writes a room_change_log row through a trigger, and the sequence never goes backwards (AUTOINCREMENT keeps its high-water mark in sqlite_sequence). So the key reads the epoch, the latest sequence and the trigger names through the read-only door, and the node rows only when the key changed. A stale cache is never used.
