Design choice (Claude's discretion, recorded here): the deadline is a child process, not a timer and not a worker thread.
- A timer cannot fire while the main thread is inside a synchronous call (V3).
- A worker thread that times out cannot end the process with exit code 2 (process.exit inside a worker ends only the worker), and a main thread cannot stop a worker that is blocked in a native call. Measured: a worker thread start costs 68 ms; a bare node start costs 10-20 ms; the part8 hook with an unbound session costs 40-50 ms (Linux WSL2, PROVEN in the planning session).
- spawnSync with timeout and killSignal SIGKILL ends a blocked child on Linux and on Windows (TerminateProcess), and the parent then writes the deny and exits 2.
