## 2. The PwS Academy Windows graph-filing bug

Symptom: on a new room on Windows, the local graph did not file artifacts until the user asked.

Both structural causes the audit named are confirmed, and together they explain the symptom with no timeout needed:

1. **Filing through the room tools never indexes.** `artifact_file` (`lib/mcp/tools/views.cjs:509-548`) calls `fileArtifact` only. A grep of `views.cjs` for `indexArtifact`, `runCascade`, `fireCascade` and `graph-ops` returns no records. MCP writes do not fire the PostToolUse `Write|Edit|MultiEdit` hooks. `fireCascade` in `lib/mcp/tool-router.cjs:937-945` is not on this path, and swallows its result where it is used.
2. **The cascade requires `/room/` or `/rooms/` in the path.** `intelligence-cascade.cjs:182-184` (`isRoomFile`) and the guard at `:650-654`. The match is case-sensitive, so `~/MindrianRooms/<slug>/...` (contains `Rooms/`, not `/rooms/`) is skipped on every platform. On Windows a native path such as `C:\Users\...\MindrianRooms\...` has no forward slash at all, so it would be skipped even under a renamed home. Already recorded as `NEVER-RUNS-ON-DEFAULT-ROOMS-HOME` in `.planning/debug/384-s2-cascade-path-rule.md`.
3. **Nothing indexes it later.** `scripts/on-stop`, `scripts/session-start`, `sessionstart-coordinator.cjs` and the two derive drain/sweep scripts contain no `indexArtifact`, `graph-index`, `build-graph` or `graph-rebuild` call (grep, no records). So the graph fills only when the user runs an index or rebuild, which is the reported "until asked".

Windows-specific aggravators (inference, need a native check): `post-write:262-273` walks up with bash `dirname`; on a backslash path `dirname` returns `.` and `room_dir` stays empty, so the cascade is never called (audit I2). If `jq` is missing from Git Bash PATH, post-write exits 0 at `:182-184` with no work (audit I5).

## 3. The phase: plans in priority order

### P0. Make filing reach the graph (fixes the Academy bug)

- **400.3-01 Index on MCP filing.** After `fileArtifact` succeeds, `artifact_file` calls `graphOps.indexArtifact(roomDir, filePath)` and puts the result in the response as `graph_index: {ok, reason}`. Top-level `ok` becomes false, or a new `partial: true` is set, when the file landed but the node or index did not. Files: `lib/mcp/tools/views.cjs:221-440, 509-548`, `lib/core/graph-ops.cjs:22-82`.
- **400.3-02 Replace the path rule with room-root detection.** Swap `isRoomFile` for a check that normalizes separators (`path.resolve` + `/` normalization), then finds the room root by `ROOM.md`/`STATE.md` walk-up or the registry, and supports Windows drive roots (fix `findRoomDir` loop end at `C:\`, audit I6). Same change in `scripts/post-write:262-273` (normalize with `cygpath -u` when present, else replace `\` with `/`). Files: `lib/core/intelligence-cascade.cjs:181-194, 650-654`; `scripts/post-write`. Correction (checked against `ab09ac612` and `.planning/debug/384-s2-cascade-path-rule.md`): 384-20 reverted option-c, a speed skip, for NO-GAIN. It was never a fix. The real fix is that RCA's option-b, which it marks as needing an owner ruling: widening the rule turns on the full cascade (HSI, compute-state, build-graph, analyze-room, git commit) at about 3,553 ms wall and 5,015 ms CPU per Write inside a 5 s hook. So 02 must not widen the rule for the full foreground cascade before 08 moves it off the foreground.
- **400.3-03 Honest status.** `cascade_status_of` reports `partial` when any step entry has `status: 'error'`, and names graph-index explicitly. `lib/mcp/tools/views.cjs` returns `room_db_busy` instead of `no_room_db` when the open failed with `RoomDbBusyError` (change `openRoomDbForCaller` to return the reason, `spine-events.cjs:454-461`). Files: `scripts/post-write:92-104`, `spine-events.cjs`, `views.cjs:535-538`.
- **400.3-04 graph-index survives the plugin's own lock.** `enqueueWrite` retries `acquireLock` with the same bounded backoff `minto-debouncer.cjs:188-195` already uses, inside a total wait that fits the caller's budget. Files: `lib/core/graph-ops.cjs:22-33`, `lib/core/write-lock.cjs`.

### P0. Guards that block on a timeout

- **400.3-05 Part 8 egress guard and web guard.** Keep `onFailure: block` (failing closed is the right direction for egress and credentials). Add an internal deadline about 1 s under the host budget that returns an explicit deny with a plain reason ("check did not finish in time, retry") instead of a silent host kill, and move the room-lexicon read to a cached file so the hook does not open room.db. Raise the budget only from a native Windows measurement. Files: `scripts/part8-egress-guard-hook.cjs`, `lib/core/part8-room-lexicon.cjs:25, 443-448`, `scripts/web-credential-guard-hook.cjs`, `hooks/hooks.json:212-235`.

### P1. room.db contention inside hooks

- **400.3-06 A hook-safe opener.** `openRoomDb(roomDir, {busyMs})` takes the busy wait from the caller; hooks pass a value derived from the remaining budget (proposal: 750 ms) plus one retry, then defer the write to a queue a detached worker drains. Skip the migration chain when `PRAGMA user_version` already matches (`room-db.cjs:307-334`). Add the busy timeout to `memory-artifact-graph-hook.cjs:173` and `feynman-timeline-refresh-command.cjs:116`.
- **400.3-07 Order the parallel PostToolUse opens.** Hooks 15, 18, 19, 20, 21 all open room.db on every Write. Fold 20 and 21 into one reconcile call, and let 18 read the cascade record after the worker writes it instead of racing it. Coordinate with Phase 402 "hook process consolidation" so the work is done once.
- **400.3-08 Post-write cascade off the foreground.** The hook stamps, enqueues and spawns a detached cascade worker, then answers "queued". The worker writes `last-cascade.json` and a per-step ledger so a killed run resumes at the failed step instead of leaving a file with a classification but no index or commit. Files: `scripts/post-write:216-290`, `lib/core/intelligence-cascade.cjs:327-585`.

### P1. Stop gate and room creation

- **400.3-09 Stop gate wait fits its budget.** Cap the retry-store wait at about 1.5 s (75 x 20 ms) or raise the Stop budget from a measurement, and correct the 600 s comment. Lands with Phase 402's card-fire stale-gate fix. Files: `scripts/check-card-fire.cjs:958-977, 1120-1298`, `hooks/hooks.json:156-162`.
- **400.3-10 Room auto-create never deletes a registered room.** Move auto-create out of hook 19 into the detached fire child, use the 60 s registry budget `room-birth.cjs` uses, and on any failure re-read the registry: delete the folder only when the registry does not list the slug; otherwise repair the row. Files: `lib/core/room-auto-create.cjs:240-272`, `scripts/auto-explore-fingerprint.cjs:223`, `lib/core/platform.cjs:548-566`.
