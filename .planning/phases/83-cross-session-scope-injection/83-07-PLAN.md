# Plan 83-07: Mid-session intent classifier hook (Tier 2)

## Goal

Replace the scripts/intent-classifier stub from 83-05 with a real UserPromptSubmit hook that scores the user's message against every room in the registry plus every sealed room on the machine, and emits a mismatch warning when the highest-scoring room is NOT the active room. The classifier is intentionally simple: token overlap, no LLM call, no embedding, no network. Speed beats accuracy. False positives are acceptable; false negatives get caught by 83-06 at write time. Closes leak vectors 1, 2, 3, 7 from 83-CONTEXT.md and SCOPE-INJ-09.

## Scope

1. Implement scripts/intent-classifier (replacing the 83-05 stub). Node CJS, no dependencies. Shebang `#!/usr/bin/env node`. Executable.

2. Logic:
   a. Read stdin to completion. Parse as JSON if possible; otherwise treat raw text as the user message. Tolerate both (the Claude Code hook spec is not fully stable for this event name; see 83-05 risks).
   b. Extract the user message text. If empty, exit 0.
   c. Resolve MindrianRooms root (same 3-way chain as 83-02/03/06).
   d. Build the room corpus:
      - All rooms listed in `.rooms/registry.json` (registered rooms)
      - All sealed rooms (walk MindrianRooms root for GUARDRAIL.md, same walker logic as 83-03)
      - Deduplicate by room name
   e. For each room, build a topic fingerprint:
      - Room directory name (split on `-` and `_` for multi-word match)
      - Project name from STATE.md frontmatter (`project:` field)
      - Key entity names from the first 30 lines of STATE.md (match capitalized phrases and proper nouns as a rough heuristic)
      - Deduplicate tokens; lowercase all tokens for comparison
   f. Tokenize the user message the same way: lowercase, split on word boundaries, strip punctuation.
   g. Score each room by token overlap count against the user message. Weight the room name match higher (exact room-name match = 5 points; each entity name match = 1 point).
   h. Find the highest-scoring room. Tie-break by preferring the active room (no warning on tie).
   i. Read active room from `.rooms/registry.json`.
   j. Warning thresholds:
      - If highest score == 0: exit 0 (silent)
      - If highest-scoring room IS the active room: exit 0 (silent)
      - If score is from a single-point match only: exit 0 (too weak)
      - If room-name exact match to a non-active room: emit warning
      - If score >= 2 entity-name matches for a non-active room: emit warning
   k. Warning format (written to stdout or to the Claude Code context-injection channel the hook event expects; the spec for UserPromptSubmit output is not yet locked, see risks):
      ```
      Intent mismatch detected. User message contains <N> tokens matching room <other-room>, only <M> matching active room <active>. Acknowledge the mismatch in your next reply. Confirm with the user whether to switch rooms before drafting any artifact related to <other-room>.
      ```
   l. Sealed rooms: if the highest-scoring room is sealed AND non-active, use the same warning text plus an extra line noting it is a sealed room. Still a warning, not a block (blocks are 83-06's job at write time).
   m. Never block. Never exit non-zero on scope mismatch (only on internal error). The classifier is advisory.

3. Performance budget: the classifier runs on every user message. Hard cap total walk + scoring time at 200ms. If the budget is exceeded, exit 0 silent. Use a simple start-time comparison in the main function.

## Out of Scope

- Embedding or LLM-based classification (deferred indefinitely)
- Persistent classifier state (stateless, re-scans every message)
- Learning from user dismissals (deferred)
- Writing to any persistent log (stderr debug line only)
- Blocking (that is 83-06's domain at write time)

## Task Breakdown

1. Write scripts/intent-classifier as Node CJS. Reuse any helpers from 83-06 (resolveMindrianRoomsRoot, readActiveRoom, isSealed) by inlining or by factoring a small shared module `lib/core/rooms-scope.cjs` if both hooks benefit.
2. Implement tokenizer (lowercase, word-boundary split, punctuation strip, stop-word list: `a, an, the, of, to, in, on, at, and, or, but, is, are, was, were, be, been`).
3. Implement fingerprint builder (room name tokens, project-name tokens, top-30-line capitalized-phrase extraction).
4. Implement scoring (weighted: room-name exact match = 5, each entity match = 1).
5. Implement threshold logic and warning emission.
6. Write test file `test/83-intent-classifier.test.cjs` (or register with runner). Test cases:
   - No mismatch: user message matches active room only. Exit 0, no warning.
   - Clear mismatch: user message contains an exact non-active room name. Warning emitted, active and other room both named.
   - Multi-token mismatch: user message contains 3 entity names from a non-active room, zero from active. Warning emitted.
   - Sealed room mismatch: user message matches a sealed room name. Warning emitted with sealed-room note. Not a block.
   - Empty message: silent exit 0.
   - Empty registry and no sealed rooms: silent exit 0.
   - Budget timeout: fixture with many rooms, confirm the classifier exits under budget (smoke-level, not a hard timing assertion).
7. Run all tests (83-04, 83-06, 83-07 together). Confirm pass.

## Risks

- Risk: UserPromptSubmit event name may not exist in the Claude Code hook spec. Mitigation: 83-05 risks flagged this; if the event is absent, the classifier is still implementable via alternative dispatch, but Tier 2 may need to defer. Escalate to user decision if 83-05 discovers the event is missing.
- Risk: False-positive rate on ambiguous messages ("let me think about innovation") may produce noise. Mitigation: threshold is conservative (exact-name match OR 2+ entity matches); single weak match is silenced.
- Risk: The capitalized-phrase heuristic for entity extraction is crude and may miss lowercase entity names or pick up non-entities. Mitigation: accepted cost of the "simple, fast, no LLM" design rule. Document as known limitation.
- Risk: The classifier runs on every user message, adding Node startup overhead. Mitigation: 200ms budget is a loose ceiling; typical runs should be <50ms; if measured latency is user-visible in v1.10.7 beta, port to bash or add a warm daemon in a follow-up.
- Risk: The stdout warning channel format for UserPromptSubmit is not guaranteed. Mitigation: write to stdout as plain text wrapped in a structured block that Claude can parse conversationally. If the hook spec rejects this, iterate in a point-release.
- Risk: Token overlap favors common words. Mitigation: stop-word list strips the obvious ones; room-name weighting dominates.
- Risk: Sealed-room warning also surfaces sealed room names in the system prompt as a side effect, potentially leaking the sealed room's identity. Mitigation: sealed room names are already surfaced by 83-03 SEALED ROOMS block, so no new leak; the classifier does not expose sealed-room content, only names.
