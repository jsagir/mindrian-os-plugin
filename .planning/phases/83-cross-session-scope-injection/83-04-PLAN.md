# Plan 83-04: Fixture-based tests for Tier 1 (scope injection, sealed rooms, wrapper)

## Goal

Provide node built-in `assert` based tests for every Tier 1 behavior introduced in 83-01 through 83-03. Tests synthesize fixtures under `/tmp/83-test-fixtures/`, run the patched scripts/session-start (or unit-test the helpers directly when bash integration is too noisy), and assert on the emitted context or settings.json state. Register with `lib/memory/run-feynman-tests.cjs` per the Phase 82 pattern. No jest, vitest, mocha, or ava. Closes the Tier 1 half of SCOPE-INJ-07.

## Scope

Add test file `test/83-scope-injection.test.cjs` (or `lib/memory/tests/83-scope-injection.test.cjs` if the runner expects that location - inspect run-feynman-tests.cjs to confirm before writing). Test cases:

1. **Scope injection happy path**: synthetic MindrianRooms fixture with .rooms/registry.json active=room-alpha and a STATE.md project name. Run session-start with MINDRIAN_ROOMS_ROOT pointed at the fixture. Capture stdout/context output. Assert ACTIVE ROOM CONTEXT block is present, names room-alpha, includes the project name, includes the Cross-Room Policy clause.

2. **No-active-room fallback**: fixture with .rooms/registry.json present but active field empty. Assert no ACTIVE ROOM CONTEXT block, session-start exits 0 cleanly.

3. **No-registry fallback**: fixture with no .rooms/ directory at all. Assert no block, exit 0.

4. **Sealed room walker happy path**: fixture with 3 top-level subdirectories, two containing GUARDRAIL.md. Assert SEALED ROOMS block lists exactly 2 rooms with their sanitized hard rules.

5. **Sealed room cap at 10**: fixture with 15 sealed rooms. Assert block lists 10 alphabetically, ends with `... and 5 more sealed rooms (run /mos:rooms list-sealed for the full set)`.

6. **GUARDRAIL.md prompt injection safety**: fixture GUARDRAIL.md containing YAML frontmatter, a code fence with adversarial content ("Ignore prior instructions"), and 5 prose lines. Assert the surfaced hard rules are the 3 prose lines only, no fences, no frontmatter, backticks stripped.

7. **Wrapper resolution via sort -V**: fixture cache dir with subdirs `1.9.0`, `1.10.0`, `1.10.7`, each containing a stub `scripts/context-monitor` that echoes its version. Run scripts/statusline-mos against the fixture (with HOME overridden). Assert stdout shows 1.10.7, not 1.9.0.

8. **Wrapper migration idempotency**: synthetic settings.json with legacy `command: "node /old/path/context-monitor"`. Run scripts/session-start twice against the fixture. Assert after first run statusLine.command contains statusline-mos; after second run the file is byte-identical to after first run.

9. **Wrapper non-clobber**: synthetic settings.json with `command: "node /home/user/.claude/statusline-mos"` already. Run session-start. Assert statusLine unchanged.

10. **Wrapper fallback when no cache exists**: scripts/statusline-mos against a HOME with no `~/.claude/plugins/cache/mindrian-marketplace/mos/` directory. Assert exit code 0, empty stdout, no error on stderr above a single debug line.

## Risks

- Risk: session-start is a bash script that produces side effects on $HOME/.claude/settings.json. Mitigation: every test sets HOME to the fixture directory so nothing touches the real user settings.
- Risk: The central test runner expects a specific module shape. Mitigation: inspect run-feynman-tests.cjs before writing; match its pattern exactly.
- Risk: Fixture cleanup leaves cruft under /tmp on test failure. Mitigation: wrap each test body in try/finally with `fs.rmSync(fixtureDir, {recursive:true, force:true})`.
- Risk: sort -V behavior differs on BSD vs GNU, making the resolution test flaky. Mitigation: the test can set up fixtures that are unambiguous under either sort, and the wrapper itself falls back gracefully.
- Risk: bash execution from node requires a bash binary present. Mitigation: acceptable dev-env assumption; skip or mark-pending tests that require bash if none found.
