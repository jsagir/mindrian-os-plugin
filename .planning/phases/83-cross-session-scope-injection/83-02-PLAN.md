# Plan 83-02: Active room scope injection block in session-start

## Goal

Inject an ACTIVE ROOM CONTEXT block into the session-start context output so every Claude session opens knowing which room is scoped and what the Cross-Room Policy is. Reads `~/MindrianRooms/.rooms/registry.json` `active` field as source of truth, resolves the room path and project name from the room's STATE.md, and emits the locked block format from 83-CONTEXT.md. Graceful no-registry / no-active fallback: block is omitted, no error. Closes SCOPE-INJ-01 and SCOPE-INJ-03.

## Scope

1. Add a new bash function `inject_active_room_context()` (or equivalent inline section) to scripts/session-start. Placement: AFTER the conversation-mode block ending around line 442, BEFORE the auto-configure block at line 446.
2. Resolution chain for MindrianRooms root:
   - `$MINDRIAN_ROOMS_ROOT` env var if set
   - `$HOME/MindrianRooms/` if exists
   - Fall back: scan `$HOME` for any folder literally named `MindrianRooms`, use the first match
3. Read `$MINDRIAN_ROOMS_ROOT/.rooms/registry.json` with python3 (already a dependency of session-start). Extract `active` field.
4. If `active` is non-empty and corresponds to an existing directory under MindrianRooms root, resolve:
   - `<active-room-name>` = the active field value
   - `<active-room-path>` = the resolved room directory
   - `<currentSection>` = read from statusline tracking file (if present) or literal string "no current section"
   - `<project-name>` = parse from `<active-room-path>/STATE.md` frontmatter `project:` field (if present)
5. Append the locked block to the session-start context (same append pattern used by existing blocks like CONV-06 scratchpad):

   ```
   ## ACTIVE ROOM CONTEXT

   You are scoped to the room: <active-room-name>
   Path: <active-room-path>
   Project: <project-name or "unspecified">
   Section focus: <currentSection>

   ## CROSS-ROOM POLICY

   When the user mentions a room name or topic that maps to a different
   room than the active one, you must:
   1. Acknowledge the mismatch out loud and name both rooms
   2. Ask whether to switch the active room or continue in the current scope
   3. Refuse to draft artifacts that belong to a different room without
      explicit user confirmation of intent
   4. Never file content derived from another room into the active room
   ```

6. On any failure (no registry, empty active, unreadable JSON, missing room directory), emit nothing. Continue session-start. Log to stderr at debug level only.

## Risks

- Risk: python3 not available on user machine. Mitigation: session-start already depends on python3 for the existing auto-configure block; no new dependency introduced.
- Risk: Large STATE.md file slows frontmatter parse. Mitigation: head -n 30 bounds the read.
- Risk: Race condition if .rooms/registry.json is being written mid-session-start. Mitigation: read is one-shot, on parse failure the block is omitted.
- Risk: Prompt-injection via STATE.md project field. Mitigation: strip backticks and newlines before inclusion.

## Deviation Notes

- Added `Project:` line to the locked block format. Not in original locked format but the research and witnessed transcript both indicate project-name disambiguation reduces topic-name collision. If gsd-plan-checker flags this as spec drift, remove the line and keep only room/path/section.
