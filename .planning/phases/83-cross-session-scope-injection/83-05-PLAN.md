# Plan 83-05: Hook registration scaffold for write-scope-check and intent-classifier

## Goal

Stage the hook registrations in hooks/hooks.json and the dispatch entries in hooks/run-hook.cmd so that plans 83-06 and 83-07 can drop in their implementation scripts without also having to wire the hook-event plumbing at the same time. This plan is the dependency anchor for the Tier 1.5 and Tier 2 work. No business logic ships here. The new hook scripts are stubs that exit 0. Previously in Revision 1, plan 83-05 was the release; the release now moves to 83-08. Plan 83-05 is the scaffold.

## Scope

1. Edit `hooks/hooks.json` to add two new entries:
   - Under `hooks.PreToolUse`: a new object with `matcher: "Write|Edit|MultiEdit"` and a single command hook calling `"${CLAUDE_PLUGIN_ROOT}/hooks/run-hook.cmd" write-scope-check` with a 2000ms timeout. If PreToolUse key does not yet exist at the top level of the hooks object, add it.
   - Under `hooks.UserPromptSubmit`: a new object with no matcher (matches all user prompts) and a single command hook calling `"${CLAUDE_PLUGIN_ROOT}/hooks/run-hook.cmd" intent-classifier` with a 2000ms timeout. If the UserPromptSubmit event name does not match the Claude Code hook spec current naming, check existing hooks.json patterns and fall back to `PreUserPrompt` or whichever event name the Claude Code plugin runtime accepts for "user just submitted a message". Document the chosen event name in a code comment inside hooks.json (JSON has no comments; put the note in the commit message and in this plan's Deviation Notes instead).

2. Add dispatch paths in `hooks/run-hook.cmd`. The current dispatch uses an exec pattern that just runs `scripts/$SCRIPT_NAME`, so the script-name-to-file mapping is implicit (the hook name is the filename). No change to run-hook.cmd's routing is required, but:
   - Confirm the existing `exec bash "${PLUGIN_ROOT}/scripts/${SCRIPT_NAME}" "$@"` pattern will correctly dispatch `write-scope-check` and `intent-classifier` as sibling scripts.
   - No edit to run-hook.cmd is expected unless a dispatch gate is needed.

3. Create stub scripts as placeholders:
   - `scripts/write-scope-check` (bash or Node CJS depending on which fits the existing pattern - bash is the default, see 83-06 for the final decision). Stub content: shebang, one-line comment "stub, implemented by 83-06", `exit 0`.
   - `scripts/intent-classifier` (bash or Node CJS - see 83-07). Stub content: shebang, one-line comment "stub, implemented by 83-07", `exit 0`.
   - Both executable.

4. Add a tiny dispatch-smoke test to the same test file scaffold as 83-04 (or a new `test/83-hook-dispatch.test.cjs`) that:
   - Runs `hooks/run-hook.cmd write-scope-check` and asserts exit 0.
   - Runs `hooks/run-hook.cmd intent-classifier` and asserts exit 0.
   - Parses `hooks/hooks.json` as valid JSON and asserts the two new entries are present under PreToolUse and UserPromptSubmit (or whichever event name was chosen).

- Any real logic in intent-classifier (that is 83-07)

## Risks

- Risk: The exact UserPromptSubmit event name may not exist in the Claude Code hook spec under that name. Mitigation: inspect existing hooks.json keys (SessionStart, PreCompact, PostCompact, Stop, PostToolUse, FileChanged, CwdChanged, SubagentStop, TaskCompleted - confirmed from the read above) and note that UserPromptSubmit is not in this set. If absent, the classifier hook has no natural event. In that case, 83-07 is still implementable but will dispatch via a different mechanism (e.g., a user-prompt-submit hook name that the Claude Code team has added since, OR a new delivery mechanism like reading the message from a shared tempfile written by a session hook). Flag as high risk for user decision. See 83-07 Risks and Deviation Notes.
- Risk: PreToolUse event may or may not support `matcher` strings with pipe alternation. Mitigation: the existing PostToolUse entry uses a plain `"matcher": "Write"` string, suggesting single-value matchers. If pipes are not supported, register three separate PreToolUse blocks for Write, Edit, MultiEdit.
- Risk: JSON editing by hand introduces trailing-comma bugs. Mitigation: use a Node one-liner to re-serialize the JSON after patching, or run the JSON.parse check as part of the task.

## Deviation Notes

- The UserPromptSubmit hook-event name is the most likely candidate but is NOT currently in hooks.json. If the Claude Code hook spec does not yet ship this event, 83-07 must either (a) poll a shared tempfile written by session-start, (b) wrap the user prompt via an on-stop-and-reinject pattern, or (c) defer Tier 2 to v1.10.8 and narrow v1.10.7 to Tier 1 + Tier 1.5 + Honesty Layer. This is a user-escalation risk flagged in this plan and in 83-07. Do NOT auto-resolve.
- If PreToolUse matcher does not support `"Write|Edit|MultiEdit"`, register three separate hook entries. Functionally identical.
- Plans 83-06 and 83-07 inherit whatever event name 83-05 lands on.
