# Plan 83-03: Sealed room walker and GUARDRAIL.md surfacing

## Goal

Walk `~/MindrianRooms/` at top level for any subdirectory containing a GUARDRAIL.md file, parse the first 3 prose lines (after stripping frontmatter, h1 title, code fences), and append a SEALED ROOMS block to the session-start context. Treat GUARDRAIL.md content as untrusted user data for prompt-injection safety. Cap at 10 rooms with alphabetical ordering. Async walk with 500ms partial-result fallback. Closes SCOPE-INJ-02.

## Scope

1. Add a new bash helper `walk_sealed_rooms()` to scripts/session-start, called immediately after the active-room injection from 83-02.
2. Walk the MindrianRooms root (resolved via the same 3-way fallback chain as 83-02) at top level only (maxdepth 1). For each subdirectory that contains a `GUARDRAIL.md` file at its root, mark as sealed.
3. For each sealed room, parse GUARDRAIL.md:
   - Strip YAML frontmatter (lines between leading `---` and next `---`)
   - Strip leading markdown h1 title (first line starting with `# `)
   - Strip code fences (any line between triple-backtick blocks)
   - Extract the first 3 non-blank prose lines from the first 30 lines of remaining content
   - Join with ` | ` separator
   - Strip backticks, newlines, and leading/trailing whitespace from each extracted line for prompt safety
4. Build the SEALED ROOMS block:

   ```
   ## SEALED ROOMS (DO NOT LEAK CONTENT INTO THIS SESSION)

   The following rooms exist on this machine and are sealed by GUARDRAIL.md.
   You must NOT pull content from them, draft artifacts about them, or
   reference them in this session unless the user explicitly switches to
   one of them via /mos:rooms switch <name>.

   - <room-name> (path: <relative-path>)
     Hard rules: <first 3 lines joined by " | ">
   ```

5. Ordering: alphabetical by room name for deterministic output.
6. Cap: at most 10 rooms. If more than 10, list the first 10 alphabetically, then append `... and N more sealed rooms (run /mos:rooms list-sealed for the full set)`.
7. Time budget: hard cap at 500ms. Implement as a background walk with a wait-loop that times out; if timeout hits, use whatever partial result was gathered (even empty). Do not block session-start more than 500ms.
8. If no sealed rooms found (empty result), omit the block entirely, no error.
9. No emoji, no em-dashes. GUARDRAIL.md content treated as quoted text only; never eval, never interpret, never source.

## Out of Scope

- Enforcement of sealed-room semantics at read or write time (that is 83-06 for writes; reads are deferred to v2.0)
- `/mos:rooms list-sealed` command (mentioned in the block text but not built in this phase)
- Nested sealed rooms (only top-level subdirectories of MindrianRooms root)
- Sealed room detection via any mechanism other than GUARDRAIL.md presence

## Task Breakdown

1. Write `walk_sealed_rooms()` helper using `find` with maxdepth, `-name GUARDRAIL.md`, `-print0`.
2. Write GUARDRAIL parser as a python3 inline (consistent with existing session-start patterns). Input: path. Output: sanitized " | "-joined first-3-prose-lines string.
3. Build the sealed rooms block, apply alphabetical sort and cap-at-10.
4. Implement 500ms time budget: launch walk as background subshell writing to a tempfile, sleep 0.5, read tempfile, kill background pid if still running. Simple and native.
5. Append block to `$context`, call after the 83-02 active-room block.

- No sealed rooms: block omitted, session-start exits 0

## Risks

- Risk: A malicious GUARDRAIL.md attempts prompt injection via adversarial content in the first 3 lines. Mitigation: sanitize (strip backticks, newlines, treat as quoted text), cap at 3 lines, tested in 83-04.
- Risk: Symlink loops cause the walker to hang. Mitigation: maxdepth 1 prevents recursion; `find -L` not used; walker stays at top level only.
- Risk: 500ms budget insufficient on slow filesystems. Mitigation: partial-result fallback always returns something, even empty; correctness over completeness for v1.10.7.
- Risk: A real room's GUARDRAIL.md contains a legitimate pipe character that collides with the " | " join separator. Mitigation: acceptable for v1.10.7; document as known limitation.
- Risk: Untrusted user data is still injected into the system prompt. Mitigation: content is wrapped in a policy block that tells Claude to treat sealed rooms as scoped out; no interpretation.
