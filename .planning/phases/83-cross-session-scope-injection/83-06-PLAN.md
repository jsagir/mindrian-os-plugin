# Plan 83-06: Filesystem write interception (Tier 1.5)

## Goal

Replace the scripts/write-scope-check stub from 83-05 with a real PreToolUse hook that blocks filesystem writes targeting a non-active room under `~/MindrianRooms/`. The hook reads the tool call payload from stdin, parses the target file path, extracts the target room segment if the path is under MindrianRooms, reads the active room from `.rooms/registry.json`, and either allows or blocks. Blocks are informative and tell the user how to authorize via `/mos:rooms switch <room>`. Sealed rooms (GUARDRAIL.md present) block unconditionally, even when they match the active room. Closes leak vectors 4, 5, 6 from 83-CONTEXT.md and SCOPE-INJ-08.

## Scope

1. Implement scripts/write-scope-check (replacing the 83-05 stub). Pick implementation language:
   - Bash if feasible (JSON parse from stdin is possible via python3 or jq, but jq is not a hard repo dependency)
   - Node CJS is preferred because stdin JSON parsing is trivial with built-ins, matches the CJS-only repo rule, and can share helpers with other CJS core code. Final decision: Node CJS.
   - Shebang: `#!/usr/bin/env node`
   - Executable permissions set.

2. Logic (Node CJS, no dependencies):
   a. Read stdin to completion. Parse as JSON. Expected shape (from Claude Code PreToolUse hook spec): `{tool_name, tool_input: {file_path, ...}}`. If stdin is empty or unparseable, exit 0 silently (no-op).
   b. Extract `tool_input.file_path` (or `tool_input.path` or `tool_input.filePath`, try all common field names). If none present, exit 0.
   c. Resolve MindrianRooms root via same 3-way chain as 83-02 and 83-03 (env var, $HOME/MindrianRooms, home scan).
   d. If the target file path is NOT under MindrianRooms root, exit 0 (allow writes to /tmp, dev workspaces, system paths, etc.).
   e. Extract the target room name as the first path segment under MindrianRooms root.
   f. Read `.rooms/registry.json` active field. If unreadable or empty, exit 0 (no active room, no scope to enforce).
   g. Compare target room to active room:
      - If target == active AND target is NOT sealed: exit 0 (allow).
      - If target is sealed (has GUARDRAIL.md at its root): block with sealed-room-specific error, regardless of active match. Sealed rooms require explicit `/mos:rooms switch <name>` to authorize. Exit 2 (non-zero). Write structured error to stderr.
      - If target != active: block with cross-room error. Exit 2. Write structured error to stderr.
   h. Block error format (written to stderr, exit code non-zero):
      ```
      Blocked: write to <target-room> denied. Active room is <active-room>.
      To authorize, run: /mos:rooms switch <target-room>
      (Or save the artifact in the active room if it belongs there.)
      ```
      Sealed variant:
      ```
      Blocked: write to sealed room <target-room> denied. This room is sealed by GUARDRAIL.md and cannot be written from another scope.
      To authorize, run: /mos:rooms switch <target-room>
      ```

3. The exact exit code and stderr format must match what Claude Code expects for PreToolUse hook blocks. As of the hook spec known at time of writing, non-zero exit plus stderr text blocks the tool call and surfaces the stderr to the assistant. Confirm via the Claude Code hook docs before shipping; if the spec uses a different signaling mechanism (structured JSON on stdout, etc.), adapt the implementation.

## Risks

- Risk: The exact PreToolUse stdin payload shape is not guaranteed stable across Claude Code versions. Mitigation: try multiple field names for file_path; on parse failure default to allow (exit 0) rather than block, because a false block is worse than a false allow for a patch release.
- Risk: The hook spec for signaling a block may use stdout JSON instead of non-zero exit + stderr. Mitigation: confirm via docs or example hooks before implementation; the implementation is a single function and can swap signaling mechanisms trivially.
- Risk: A write to a non-MindrianRooms path that coincidentally contains "MindrianRooms" as a substring (e.g., `/home/user/docs/about-MindrianRooms.md`) triggers a false positive. Mitigation: match on path segment boundary, not substring.
- Risk: Symlinks cause the resolved path to point outside MindrianRooms while the user path is inside. Mitigation: `fs.realpathSync` before analysis; acceptable trade-off.
- Risk: False positives block legitimate writes and frustrate users. Mitigation: block messages are actionable (they name the target and the switch command), and the user can always hit Approve in the tool-call UI if Claude Code surfaces the block as a confirm prompt rather than a hard refuse.
- Risk: The hook runs on EVERY Write/Edit/MultiEdit tool call across the whole session and may add measurable latency. Mitigation: the Node startup overhead is ~50-100ms; acceptable for a safety hook. If it becomes a problem, port to pure bash in a follow-up.

## Deviation Notes

- The hook is written in Node CJS, not bash, because stdin JSON parsing is trivially safer in Node. This is within Claude's Discretion per 83-CONTEXT.md.
- Path-segment analysis uses `path.relative` + segment split rather than regex. Safer.
- Inline helpers instead of shared lib/core file because the only consumer today is this hook. 83-07 may factor out if it needs the same helpers.
