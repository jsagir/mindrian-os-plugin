<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| article markdown -> editor inline nodes | Untrusted room content becomes rendered React inline components |
| editor content -> generated PDF/DOCX files | User content serialized into binary document formats client-side |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-232-05-01 | Tampering (XSS) | wikilink pill render | mitigate | Target renders as React text children (auto-escaped); navigation builds hrefs only from /api/pages values or a hyphen-normalized slug, never raw HTML injection |
| T-232-05-02 | Tampering | malicious [[target]] crafting weird URLs | mitigate | Normalization strips to a lowercase hyphen slug under the fixed /wiki/ prefix; no protocol or host can be injected |
| T-232-05-03 | Information Disclosure | exported PDF/DOCX carry room content | accept | Export is the explicit user intent; generation is fully client-side, nothing leaves the machine |
| T-232-05-04 | Denial of Service | huge article kills exporter | accept | Client-side only; failure surfaces the UI-SPEC export-failed copy |
| T-232-SC | Tampering | package installs | accept | No new installs - pdfmake and docx entered the tree at Plan 03's blocking legitimacy checkpoint with the lockfile committed |
</threat_model>
