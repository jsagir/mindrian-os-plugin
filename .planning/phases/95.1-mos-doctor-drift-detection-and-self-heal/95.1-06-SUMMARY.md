## Decisions Made

- **Self-referential safety design (the headline decision):** A self-scanning detector cannot have literal versions of the patterns it detects in its own source. JavaScript regex literals (`/[╭╮...]/`) embed source bytes verbatim, so a regex literal containing forbidden box chars would cause the detector to flag itself. Solution: build the regex via `new RegExp('[╭╮...]')` from a string of Unicode escape sequences. The string source contains only ASCII (backslash-u-digits), the runtime regex matches the actual codepoints. Comments in the detector source reference Unicode codepoint NAMES (e.g. "U+256D BOX DRAWINGS LIGHT ARC DOWN AND RIGHT") never the literal characters. `grep -nE '╭|╮|╰|╯|✗|✘|✕|❌|❓|❕|❗|─|━|┌|┐|└|┘|│' scripts/doctor.cjs` returns 0 matches.
- **Test scenario 1 substring-overlap fix:** The committed RED test at scenario 1 line 121 filtered for `v.file.indexOf('compliant.md') !== -1` to check that compliant.md was NOT flagged. But `'noncompliant.md'.indexOf('compliant.md') === 3` (found, because "compliant.md" is a substring of "noncompliant.md"). The filter caught BOTH files. To pass test 117 (noncompliant flagged) AND test 124 (compliant not flagged) is logically impossible with substring matching. Fixed test to use `path.basename(v.file) === 'compliant.md'` (exact match). Author intent was clear; this was a one-character oversight in test scaffolding from Plan 95.1-02. Per Rule 1 (auto-fix bug). Documented in deviations.
- **Carve-out filename matching:** isCarveOutFile() uses `endsWith('context-monitor')` OR `endsWith('context-monitor.cjs')` so both the extension-less form (matches the actual scripts/context-monitor with no .cjs extension) and the .cjs variant (defensive) are recognized. Keeps the SKILL.md section 3 emoji exception machine-checkable.
- **Best-effort renderer scan (sub-check c):** Only files containing `lines.push(` are checked for Zone 1+4 patterns. False positives are acceptable per CONTEXT D-13 (a rendering helper without `/mos:` footer is a real warn-worthy finding). False negatives are not (a renderer that doesn't use lines.push() pattern would slip through, but the codebase convention is `lines.push(...)` per Plan 95.1-04's renderHumanReport pattern).
- **Detection-only per D-13:** No --fix dispatch for class F. The report carries `fixable: false` and `fixDeferredTo: '95.2 or human review'`. Auto-rewriting renderer code is out of 95.1 scope.
- **Single-task execution:** The plan defined 1 task with 1 verification step. The task spawned 2 commits (1 feat + 1 fix) to keep deviation tracking clean. Both commits are within the same plan boundary.

### Auto-fixed Issues

**1. [Rule 1 - Bug] Fixed substring-overlap in test-doctor-class-f.cjs scenario 1 filter**

- **Found during:** Task 1 verification (after detector implementation passed 3 of 4 scenarios but failed scenario 1's "must NOT flag compliant.md" assertion)
- **Issue:** Scenario 1's compliant-hits filter (test line 121) used `v.file.indexOf('compliant.md') !== -1`. Because `'noncompliant.md'` contains the substring `'compliant.md'` (`indexOf` returns 3), the filter caught BOTH the noncompliant violation AND would have caught a compliant violation if one existed. The two assertions on lines 119 and 124 (noncompliant present count=1, compliant present count=0) are logically unsatisfiable with substring matching when filenames overlap as `noncompliant.md` and `compliant.md` do.
- **Fix:** Replace `v.file.indexOf('compliant.md') !== -1` with `path.basename(v.file) === 'compliant.md'` (exact-filename check). Preserves the test author's intent (noncompliant flagged once, compliant not flagged) without the substring overlap bug.
