## Implementation Decisions

### Generator design (scripts/generate-section-intelligence.cjs)

- **D-01:** Generator scope per invocation = **single-dir + `--recursive` flag**. Default behavior: generate ROOM.md + MINTO.md for ONE directory. With `--recursive`, walks the whole subtree from that anchor. Composable with find/xargs, easy to test on one dir at a time, matches Unix tool conventions.
- **D-02:** Idempotency = **skip if exists; `--force` overrides**. Default never destroys user edits to ROOM.md/MINTO.md after onboarding. Matches the spirit of `/mos:doctor`'s `--fix` being explicit-opt-in.
- **D-03:** Schema source = **hand-rolled minimal frontmatter**. Templates baked directly into the script as string templates. Self-contained, no fixture coupling, matches Phase 87-01a's existing pre-commit assertions.

### Class D verification fixture (live-cascade end-to-end test)

- **D-04:** Fixture location = **`test/fixtures/cascade-surface-e2e/`**. Mirrors the `test/fixtures/cascade-e2e/` pattern from Phase 87-00. Predictable, sibling to the pipeline-only fixture so the contrast is visible: `cascade-e2e` tests pipeline output, `cascade-surface-e2e` tests the envelope-to-render path.
- **D-05:** Registry registration in test = **`MINDRIAN_ROOMS_HOME` env override** (corrected from initial draft per researcher's finding). Test process sets `MINDRIAN_ROOMS_HOME=test/fixtures/cascade-surface-e2e`. `scripts/resolve-room` (the bash script invoked by post-write hook) reads `MINDRIAN_ROOMS_HOME` directly per its line 34 implementation. Hermetic, no real registry edits, no cleanup risk. Note: codebase has a real env-var inconsistency that 95.1 surfaces — `scripts/resolve-room` uses `MINDRIAN_ROOMS_HOME` while `scripts/memory-lifecycle.cjs` and `lib/core/cross-room-aggregator.cjs` use `MINDRIAN_ROOMS_ROOT`. For the class D test path, the bash hook is the binding constraint, so `_HOME` is canonical here. The Node-side `_ROOT` inconsistency is captured as a deferred finding (env-var-naming drift) — class F's UI compliance scanner can be extended in a future phase to also check for env-var-name consistency, but that's out of 95.1 scope.
- **D-06:** PASS criteria = **exists + 8-key shape**. Assert `<roomDir>/.mindrian/last-cascade.json` exists, parses as JSON, contains all 8 expected root keys: `cascade_status`, `classification`, `file_path`, `git_commit`, `graph_index`, `proactive_intelligence`, `section`, `timestamp`. Tight enough to catch shape regressions; loose enough to not break on additive fields.

### UI Ruling System compliance (drift class F + /mos:doctor retrofit)

Locked by user "all" response after late-stage TUI audit surfaced that current `/mos:doctor` is non-compliant with `skills/ui-system/SKILL.md` (mandatory since Phase 80). The new command we extend would inherit the non-compliance unless retrofitted in this same phase.

- **D-10 (Body shape):** `/mos:doctor` is **Shape E (Action Report)** per SKILL.md §2 mapping (sibling of `/mos:setup`, `/mos:file-meeting`, `/mos:update`). Add `body_shape: action-report` to `commands/doctor.md` frontmatter. Renderer produces: action+source header, per-class status rows with `[before → after]` pattern, summary totals at bottom, signals routed to Zone 3 only when room-proactive surfaces external findings (drift findings themselves are Zone 2 body content, not Zone 3).
- **D-11 (Glyph cleanup):** Replace all unauthorized characters in `renderHumanReport`. Remove `╭─` `╮` `╰─` `╯` box chars (alignment via whitespace per SKILL.md "alignment IS the punctuation"). Remove `✗` (not in 12-glyph vocabulary). Approved glyphs from SKILL.md §3: `■ ▼ ▶ ▷ ├─ └─ ✓ • ⚠ ⚡ ⬜ →`. Mapping for /mos:doctor: `■` for class header rows, `✓` for pass, `⚠` for warning, `⬜` for gap (e.g., missing .room-root), `⚡` for urgent, `▶` for primary next-step in footer, `▷` for alternative next-steps, `→` for transition arrows in `[before → after]`.
- **D-12 (4-zone retrofit):** `renderHumanReport` adds Zone 1 header (`-- MindrianOS -- doctor -- {stage} --`; compact single-line dashes when `>30 lines` per density rule), Zone 4 action footer (always 2-3 grounded `/mos:` next steps; e.g., after class B detected: `▶ /mos:doctor --fix --rooms`, `▷ /mos:rooms switch <name>`, `▷ cat <path>/.room-root`). Zone 2 body holds the per-class drift findings. Zone 3 intelligence strip stays empty by default — populated only when room-proactive surfaces high/medium signals during the doctor run.
- **D-13 (Drift class F detector):** New check function `checkUIRulingCompliance()` in `scripts/doctor.cjs`. Three sub-checks: (a) scan `commands/*.md` frontmatter for missing `body_shape` field; (b) scan `scripts/*.cjs` and any renderer for unauthorized box chars (`╭ ╮ ╰ ╯ ┌ ┐ └ ┘ │ ─ ━`) and unauthorized glyphs (`✗ ✘ ✕ ❌ ❓ ❗ ⚠️` and any other emoji); (c) scan command output renderers for missing Zone 1 header pattern and missing Zone 4 action footer pattern. Reports per-file violations with line numbers. `--fix` for class F is detect-only in 95.1 (auto-rewriting renderer code is out of scope; defer to 95.2 or human review).

### UI Ruling System: cross-surface and structural decisions

User's "all" answer also locks the broader cross-surface TUI factors. These are mostly Claude's discretion calls validated by the broad lock-in.

- **D-14 (Color contract — verify-only):** Existing `scripts/doctor.cjs` color usage maps cleanly to SKILL.md §4 (cyan=commands/paths/links ✓, yellow=warnings ✓, green=success ✓, red=errors-only ✓, dim=meta/hints ✓). No color changes needed in 95.1 retrofit. Class F detector should ALSO scan for unauthorized colors (e.g., magenta, blue) used decoratively per "Color is NEVER decoration" rule.
- **D-15 (Three-surface compatibility):** CLI is master template (existing). Desktop degrades per SKILL.md §9: no box chars (already removed by D-11), no progress bars (Shape E doesn't use them), no tree symbols (Shape E doesn't use them), no ANSI color (Larry surfaces doctor output by reading the report and re-rendering as markdown when on Desktop). Cowork matches CLI — no special handling. Decision: implement renderer once for CLI; Larry handles Desktop degradation conversationally; Cowork uses CLI output verbatim.
- **D-16 (Density logic):** SKILL.md §1 says `>30 lines: compact header, max 2 signals; <10 lines: no padding`. /mos:doctor with 6 classes (A-F) and multiple sub-checks per class WILL exceed 30 lines on a drift-heavy report. Renderer must: (a) measure output line count before emitting Zone 1 header, (b) use compact single-line header (`-- doctor: {N} drift classes checked --`) when projected lines > 30, (c) cap Intelligence Strip signals at 2 in dense mode.
- **D-17 (Intelligence Strip ownership):** Drift findings ARE Zone 2 body content. Zone 3 Intelligence Strip is reserved for OTHER proactive signals from `room-proactive` (contradictions, convergence, gaps in unrelated sections). Default behavior: empty Zone 3. Populated only when the doctor run sees an active room and room-proactive has HIGH/MEDIUM signals to surface. If no room is active or no signals exist: omit Zone 3 entirely.
- **D-18 (Shape F selector for --fix):** When `/mos:doctor` runs WITHOUT `--fix` and finds drift, render an F.1 Next Move selector (per SKILL.md §2 Shape F) at the end of the report, BEFORE Zone 4 action footer. F.1 options: (a) "Run /mos:doctor --fix" (locked verb: Run Methodology), (b) "Defer" (locked verb: Defer), (c) "Free-Text" (locked verb: Free-Text — escape hatch). User selection writes to STATE.md Decisions section per Canon Part 3 Layer 3 (state hook). When `--fix` IS passed, no selector — execute and report via Zone 2.
- **D-19 (voice-dna integration):** The `renderHumanReport` stays purely structural — no Larry-voice prose injection. The voice-dna patterns (`references/personality/voice-dna.md`) apply when Larry SURFACES a doctor finding conversationally (e.g., user asks "what does this mean?"). Renderer produces tight terse status; Larry handles narrative interpretation. This separation matches SKILL.md §6 ("CLI Voice Rules") which mandates terse renderers + Larry-handled narrative.
