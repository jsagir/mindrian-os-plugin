<objective>
Wire the already-declared `visibility: admin` command frontmatter field through the command
registry into the D4 recommendation scorer, so a non-admin navigator is never offered
`/mos:admin` or `/mos:dogfood-flush` as a recommendation.

Purpose: this is a live leak, not a theoretical one. Verified on this tree on 2026-09-08:
`rankForSelector({ roomState: {}, k: 3 })` returns `['/mos:act', '/mos:admin', '/mos:agentshield']`
today. `/mos:admin` is the number 2 recommendation for every navigator, admin or not. Phase 191's
own addendum first flagged this gap; SEED-052 names closing it as the seed's first and smallest
experiment.

Output: a `visibility` field on every registry entry, a fail-closed `opts.isAdmin` filter in the
ranker, and `isAdmin` computed from the already-shipped `scripts/check-admin-identity.cjs` at the
three call sites whose ranker output actually reaches the navigator.

Scope boundary (deliberate, from CONTEXT.md): this is NOT the full SEED-052 scope. The
107-command JTBD/audience/F-shape mini-product GSD-ing is explicitly deferred and must not appear
in this phase. `lib/hmi/dial-reach-orchestrator.cjs` (the fourth ranker call site) and
`scripts/admin-command-gate.cjs` (the execution-time gate) are both untouched, and the plan proves
that rather than asserting it.
</objective>
