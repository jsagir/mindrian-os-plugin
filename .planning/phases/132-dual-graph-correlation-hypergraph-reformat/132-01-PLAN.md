The shipped read-only Brain door is lib/core/brain-client.cjs:
  - async query(cypher, params) -> { records } | { error|text } | null  (READ path, plan-gated to read-only by MINDRIAN_BRAIN_KEY)
  - isAvailable() -> sync boolean
  - The curation batches need WRITE access, so they use the neo4j-driver transport (admin-write pattern), NOT brain-client.query, for mutations. Reads (pre-count / post-count) MAY use either; prefer the driver session for atomicity within a batch.

The existing curation-batch Cypher idiom is scripts/brain-normalize-targeted.cypher:
  - MATCH ... MERGE (a)-[:EDGE {props}]->(b) for wiring
  - the duplicate-merge dance: collect outgoing rels, apoc.create.relationship onto keeper, DETACH DELETE duplicate
  - :Archived tagging + REPLACED_BY (the reversible-delete pattern from the audit, NOT DETACH DELETE for dedup)

The 2026-05-17 audit Section 17 rollback pattern (the reversibility contract this harness encodes):
  - rollback archive:  MATCH (n:Archived {archived_by: $by}) REMOVE n:Archived
  - rollback relabel:  MATCH (p:Person {relabeled_by: $by}) REMOVE p:Person SET p:Concept
  - rollback property: MATCH (f {jtbd_anchor_decided_by: $by}) SET f.jtbd_anchor='REVIEW_REQUIRED' REMOVE f.jtbd_anchor_decided_by
  - rollback edges:    MATCH ()-[r {created_by: $by}]-() DELETE r
