<objective>
Collapse the ~50 same-name-different-label duplicate groups into one canonical correlation_id per cluster with label facets, and resolve the 22 still-REVIEW_REQUIRED Frameworks (anchor-or-archive). This is pillar 2 of Phase 132 (cross-label dedup) and satisfies audit acceptance criteria 5 and 6. The duplicate groups are already enumerated in the 2026-05-17 audit (no live Brain probe): Section 13 names the headline clusters -- "HEART Framework" (:Framework + :Product), "Jobs-to-be-Done" (:Framework + :Product + :DictionaryTerm), "Wicked Problem" (:Concept + :ProblemType + :DictionaryTerm), "Four Lenses of Innovation" (12+ variants across 6 labels incl. 5 mislabeled "Rowan Gibson's X" :Person nodes). The 22 REVIEW_REQUIRED list is the Section 3 classification (5 MUST-FIX already done in the dogfooding session; the leadership cluster of 13 + naming/dedup decisions + domain-specific calls remain).

Coverage is MEASURED, not prose-asserted: CROSS_LABEL_GROUPS encodes the full ~50-group set and its length is asserted against an explicit floor (CROSS_LABEL_GROUP_MIN, set to 45 to anchor the ~50 enumeration with headroom for audit transcription variance), so DEDUP-03 cannot pass while leaving most of the ~50 groups uncollapsed.

Open-decision 2 (cross-label facet model) is resolved HERE in favor of labels-as-facets: the canonical node gains the lost labels as actual labels (SET n:Framework:Product), not as a property array. Labels are queryable via MATCH (n:Framework:Product) and are the conventional Neo4j facet idiom; the visual-noise cost is accepted for the cross-tier-lookup gain. This is a conscious recorded choice, not an accident.

Purpose: cascade edges (INFORMS, CONTRADICTS, SUPERSEDES, AUTHORED) fork across these cross-label variants, so chain-recommender returns the wrong canonical. Collapsing to one canonical correlation_id per cluster is what makes the 130.7 "one canonical target per query, no fork" guarantee TRUE in content. The archive contract is reversible-delete (:Archived + REPLACED_BY), never DETACH DELETE -- the audit Section 9 + Canon Part 7 hard rule.

The canonical-pick rule (from CONTEXT + audit): most-edged node wins; ties broken by primary-label preference (:Framework > :Product > :Concept > :DictionaryTerm). The non-canonical variants are archived with a REPLACED_BY edge pointing at the canonical's correlation_id; the canonical gains the lost labels as facets for cross-tier lookup.

Output: scripts/curation-132-03-cross-label-dedup.cjs (the dedup driver, --dry-run default), its test, the run-all-132.sh append.
