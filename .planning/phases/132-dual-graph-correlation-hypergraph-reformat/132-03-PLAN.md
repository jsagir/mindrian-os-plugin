This is pillar 2 of Phase 132 (cross-label dedup) and satisfies audit acceptance criteria 5 and 6. The duplicate groups are already enumerated in the 2026-05-17 audit (no live Brain probe): Section 13 names the headline clusters -- "HEART Framework" (:Framework + :Product), "Jobs-to-be-Done" (:Framework + :Product + :DictionaryTerm), "Wicked Problem" (:Concept + :ProblemType + :DictionaryTerm), "Four Lenses of Innovation" (12+ variants across 6 labels incl. 5 mislabeled "Rowan Gibson's X" :Person nodes). The 22 REVIEW_REQUIRED list is the Section 3 classification (5 MUST-FIX already done in the dogfooding session; the leadership cluster of 13 + naming/dedup decisions + domain-specific calls remain).

Purpose: cascade edges (INFORMS, CONTRADICTS, SUPERSEDES, AUTHORED) fork across these cross-label variants, so chain-recommender returns the wrong canonical. Collapsing to one canonical correlation_id per cluster is what makes the 130.7 "one canonical target per query, no fork" guarantee TRUE in content. The archive contract is reversible-delete (:Archived + REPLACED_BY), never DETACH DELETE -- the audit Section 9 + Canon Part 7 hard rule.

The canonical-pick rule (from CONTEXT + audit): most-edged node wins; ties broken by primary-label preference (:Framework > :Product > :Concept > :DictionaryTerm). The non-canonical variants are archived with a REPLACED_BY edge pointing at the canonical's correlation_id; the canonical gains the lost labels as facets for cross-tier lookup.

Output: scripts/curation-132-03-cross-label-dedup.cjs (the dedup driver, --dry-run default), its test, the run-all-132.sh append.
