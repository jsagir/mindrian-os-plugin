FUNCTIONS (all synchronous, all defensive, none ever throws):

  `governanceForPass(passName)` -> the frozen entry or `null`. Normalizes with
  `String(passName || '').trim().toLowerCase()`. Never throws.

  `findingFromResult(result)` -> a plain object candidate finding, or `null`.
  Extraction order: if `result` is a plain non-array object and `result.chain_output` is a
  plain non-array object, return `result.chain_output`; else if `result` is a plain non-array
  object and it carries a `source_artifact_id` key, return `result`; else return `null`.
  This function EXTRACTS only. It does NOT validate fields; validation is
  `enforceSalientGovernance`'s job, so violations can be specific rather than collapsing
  every defect into one string. Do NOT call
  `require('./bono/hat-governance.cjs').argumentFromResult` here: it returns null for this
  shape (proven in RESEARCH F-14), which is exactly the silent-pass trap.

  `enforceSalientGovernance(passName, finding)` -> `{ ok: boolean, violations: string[] }`.
  Mechanical, structural checks only; it never interprets prose. Violation strings follow the
  donor's `<category>_<reason>` convention and carry ZERO content bytes (Canon Part 8) --
  never echo `body_text`, an artifact id, or any turn text into a violation string.
    Step 1: `const key = normalize(passName)`. If `key` is not in `SALIENT_PASSES`, return
      `{ ok: false, violations: ['rs_pass_unrecognized'] }` (divergence (b) above).
    Step 2: if `finding` is not a plain non-array object, return
      `{ ok: false, violations: ['rs_finding_unrecognized'] }` (divergence (a) above).
    Step 3 -- the SEVEN NEUTRAL checks, applied for BOTH pass names, each pushing at most one
    violation string:
      `rs_no_id`               : `finding.id` is not a non-empty string
      `rs_no_source_artifact`  : `finding.source_artifact_id` is not a non-empty string
      `rs_no_target_artifact`  : `finding.target_artifact_id` is not a non-empty string
      `rs_direction_missing`   : `finding.direction` is not a non-empty string
      `rs_diff_not_numeric`    : `Number.isFinite(finding.signed_diff)` is false OR
                                 `Number.isFinite(finding.abs_diff)` is false
      `rs_body_text_empty`     : `finding.body_text` is not a string, or its trimmed length is 0
      `rs_chain_text_type`     : `finding.brain_chain_text` is present and is not a string
                                 (the empty string is legal; the field is optional)
    Step 4 -- the FOUR ADVERSARIAL-ONLY checks, applied ONLY when `key === 'adversarial'`.
    They read the SAME fields under a stricter rule set; they must not consult any additional
    input (`eureka-critic.cjs`'s sycophancy-channel discipline):
      `rs_self_referential`      : `source_artifact_id === target_artifact_id` (a salient
                                   against itself is not a salient)
      `rs_diff_sign_mismatch`    : both diffs are finite AND
                                   `Math.abs(finding.signed_diff) !== finding.abs_diff`
                                   (the two numbers contradict each other)
      `rs_diff_below_floor`      : `abs_diff` is finite and equal to 0 (a zero gap is not a
                                   bottleneck)
      `rs_direction_unrecognized`: `RS_DIRECTIONS.indexOf(finding.direction) === -1`
    Step 5: return `{ ok: violations.length === 0, violations: violations }`.

  `makeSalientSelfCritiqueFn(opts)` -> a `selfCritiqueFn(step, result)` closure.
    `opts.commandFilter` (optional string): when set, the returned critic GOVERNS only steps
    whose `step.command` equals it, and ABSTAINS on every other step. Absent or empty means
    govern every step (the fail-closed default).
    ABSTAIN branch, and this is the ONE pass-through branch in the module, deliberately narrow:
    when a `commandFilter` is set and `step.command !== commandFilter`, return
    `{ passed: true, quality: <result.quality if it is a non-empty string, else 'high'>,
       violations: ['rs_step_not_governed'] }`.
    Preserving the incoming quality (rather than upgrading it to 'high') is the donor's own
    behaviour at `reviewer-governance.cjs:292-305` and keeps the critic non-interfering on
    steps it does not own. The `rs_step_not_governed` marker makes the abstention OBSERVABLE
    rather than silent; a test asserts it.
    GOVERNED branch:
      1. `const finding = findingFromResult(result);`
      2. `const neutral = enforceSalientGovernance('neutral', finding);`
      3. `const adversarial = enforceSalientGovernance('adversarial', finding);`
      4. D-10 unanimity: the candidate passes only if BOTH `neutral.ok` and `adversarial.ok`
         are true. Compute `const disagreement = (neutral.ok !== adversarial.ok);`
      5. On failure, return
         `{ passed: false, quality: 'low', violations: <deduped union of both pass violation
           arrays, plus 'rs_pass_disagreement' appended when `disagreement` is true> }`.
         `quality: 'low'` matters: `chain-executor.cjs`'s `LOW_QUALITY` constant is the string
         `'low'` and `_critiqueFailed` tests `verdict.quality === LOW_QUALITY || verdict.passed === false`.
      6. On success, return `{ passed: true, quality: 'high', violations: [] }`.
    Wrap nothing in try/catch that would swallow a programming error into a pass; the module
    must never fail open.
