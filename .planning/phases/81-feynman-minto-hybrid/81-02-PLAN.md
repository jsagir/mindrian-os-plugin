# Plan 81-02: Slash command orchestrator and fixture narratives

## Goal

Rewrite `commands/reason.md` as the Revision 2 structured prompt orchestrator. When the user types `/mos:reason`, Claude (the host session) reads the prompt, walks target sections, calls the generator `--plan` subcommand via Bash, reasons through Feynman stages 1/2/4/5 in its own context using the prompt constants from `lib/memory/feynman-prompts.cjs`, writes narrative JSON to a temp file, calls `--write` via Bash, and cleans up. Zero external API calls. Claude IS the LLM. Commit two additional hand-crafted fixture sections and narratives (medium, large) plus an integration test that validates `--write` against all three fixtures end-to-end without needing a live Claude session.

## Scope

Files to create:
- `test-fixtures/feynman/sections/fixture-medium/` (section folder with `ROOM.md` per Decision 15, 7 to 9 mock artifacts in named nested folders per Decision 16, approx 18 to 24 files including body markdown plus `ROOM.md`).
- `test-fixtures/feynman/sections/fixture-large/` (same shape, 12 to 15 mock artifacts).
- `test-fixtures/feynman/narratives/fixture-medium.json` (hand-crafted valid narrative, validates green against `validateNarrative`).
- `test-fixtures/feynman/narratives/fixture-large.json` (same).
- `scripts/vault-section-minto-generator.integration.test.cjs` (approx 180 to 260 lines): integration runner, one pass per fixture section, asserts plan payload shape, asserts write output structural regex matches, asserts determinism across two invocations, asserts total character length under 15000, asserts zero em-dash characters in output, asserts zero `{placeholder}` tokens leaked into output.

Files to modify:
- `commands/reason.md` (currently approx 100 to 200 lines, grows to approx 300 to 450 lines): full rewrite per R-2. New front-matter stays compatible (name, command, description, usage, allowed-tools). Body is a structured prompt with seven labeled steps telling Claude exactly what to do. Includes (inline for robustness across surfaces) the four prompt constants from `lib/memory/feynman-prompts.cjs`. If the include-at-build step is not yet wired, inline copies are acceptable and are kept in sync by a reminder comment plus a small sanity check in the integration test that asserts the inlined strings equal the library exports.
- `lib/memory/run-feynman-tests.cjs` (from 81-01): add `scripts/vault-section-minto-generator.integration.test.cjs` to the test list.

Out of scope:
- Tier-0 fallback wiring (81-03).
- AAAK footer attachment (81-03).
- `--regenerate-all` flag (81-04).
- CHANGELOG or version bumps (81-04).
- Any live Claude invocation during tests (the entire point of the fixture narratives is that Claude-produced narrative is validated at slash-command runtime, not at unit-test time).

## Out of Scope

- Modifying the Feynman engine skill. The library prompts are the automation-tightened derivatives; the skill stays human-facing.
- Adding any network call, API key, or budget gate. Claude is the LLM. There is no second billing relationship.
- Modifying `lib/memory/aaak-compress.cjs`.
- Modifying the existing `renderSectionMinto` and friends inside the generator.

The body explicitly notes that stages 3 and 6 are skipped in automation per the Revision 2 carry-over of D-2. The body also explicitly notes that Claude is the LLM and no external API is called. ## Tests

- `scripts/vault-section-minto-generator.integration.test.cjs`:
  - Structural: JSON.parse of plan output succeeds; required keys present.
  - Regex: 10 regex patterns for the required MINTO block headings per fixture.
  - Bounds: `output.length < 15000`.
  - Determinism: two runs byte-identical under `MINTO_FROZEN_DATE=2026-04-14`.
  - Em-dash scan: iterate code points, `assert.ok(cp !== 8212 && cp !== 8211)`.
  - Placeholder leak check: `assert.ok(!output.includes('{section_name}'))` and `assert.ok(!output.includes('{artifacts}'))`.
  - Drift check: inlined prompt strings in `commands/reason.md` equal library exports from `lib/memory/feynman-prompts.cjs`.

## Dependencies

## Risks

- Risk: inlined prompt strings in `commands/reason.md` drift from the library constants over time. Mitigation: the integration test drift check in task 7 catches drift the next time anyone runs the test suite. If the drift check becomes noisy, a small `scripts/check-prompt-drift.cjs` can replace inline extraction in 81-04 (nice-to-have, not required).
- Risk: hand-crafted fixture narratives bias the test toward one style of Claude output. Mitigation: three fixtures (small, medium, large) with deliberately different section shapes and narrative flavors, acknowledged as not covering all possible real-world Claude outputs; the structural regex checks are shape-only, not content-style.
- Risk: slash command body gets large enough that the Claude session pays a context cost just to read it. Mitigation: prompts are already bounded `[400, 4000]` chars each per 81-01, so even with all four inlined the slash command body stays under approx 20k chars, well within slash command norms.
- Risk: `/tmp` is not writable on all three surfaces (Cowork containerized). Mitigation: the orchestrator says "temp directory per OS convention", and falls back to `<roomDir>/.mos-reason-tmp/` if `/tmp` is not writable. The slash command body encodes both paths and instructs Claude to pick whichever works.

## Deviation Notes

- Prompts are inlined into `commands/reason.md` rather than `@include`d because the slash command runtime does not have a well-documented `@include` directive for prompt bodies. The drift check test in task 7 restores the single-source-of-truth guarantee.
- Temp file pattern uses `/tmp/mos-reason-<section>-<timestamp>.json` as the primary path, with `<roomDir>/.mos-reason-tmp/` as the fallback. Cleanup is explicit `rm` instructed in step 8 of the slash command body.
- Fixture narratives are committed to git (`test-fixtures/feynman/narratives/*.json`). They are the test baseline and must live in version control.
