# Plan 81-04: Generator rewrite and tier fallback

## Goal

Wire the full 4-stage Feynman pipeline into MINTO.md production via a new `lib/memory/feynman-minto-renderer.cjs` renderer, and modify `scripts/vault-section-minto-generator.cjs` ONLY to add tier fallback logic around the new path. Structural parts of every MINTO (frontmatter, MECE tree, cross-refs, sources, navigation) remain deterministic and free, produced by the existing pre-81 helpers which are preserved byte-equivalently when forced via a `--tier-0` flag. Narrative parts (essence, mental model, governing thought, key claims, argument structure) go through the Feynman pipeline when tier-1 is available. On any tier-1 failure (missing API key, API error, budget exceeded, parse error), the generator falls back transparently to the pre-81 deterministic path plus an AAAK footer from `lib/memory/aaak-compress.cjs`. Goal-backward: three integration test scenarios all produce valid MINTO.md files: (a) LLM available and budget OK, (b) ANTHROPIC_API_KEY unset, (c) budget artificially exhausted. Scenario (a) output is < 1500 tokens. Scenarios (b) and (c) produce byte-equivalent output to the pre-81 generator plus an AAAK footer.

## Scope

Files to create:

- `lib/memory/feynman-minto-renderer.cjs` (new, ~280 lines). Imports structural helpers from the pre-81 generator via a named-export seam (see 81-04 task list). Imports `runFullPipeline` from `./feynman-stages.cjs`. Imports the em-dash scrub helper. Exports `renderFeynmanMinto(section, artifacts, room)` which:
  1. Runs the full Feynman pipeline on the section's concatenated artifact text (plus section metadata from the room's `ROOM.md` for context).
  2. Pulls structural parts from the pre-81 helpers (MECE tree, evidence gaps, cross-refs, sources, navigation) - these calls are free and deterministic.
  3. Composes the final MINTO markdown: frontmatter -> essence block -> governing thought + plain language -> mental model block -> argument structure + key claims -> MECE tree -> evidence gaps -> cross-refs -> sources -> navigation.
  4. Returns `{markdown: string, tokenEstimate: number, pipeline_meta: {...}, cost_usd: number}`.
  Throws on any underlying Feynman error (does NOT catch - catching is the generator's job). Markdown body composition uses plain template strings (no template engine). Em-dash scrub is applied once to the final output as a belt-and-suspenders check.
- `lib/memory/feynman-minto-renderer.test.cjs` (new, ~280 lines). Three integration scenarios (see Tests) plus unit tests for the composition logic (given a mock `runFullPipeline` output, produces expected markdown shape). Uses the fetch shim for the tier-1 scenario to replay the 81-03 full-pipeline fixture. Uses `delete process.env.ANTHROPIC_API_KEY` for the tier-0-no-key scenario. Uses a tmp budget file with spend at cap for the tier-0-budget-exhausted scenario.
- `test-fixtures/feynman/integration/ROOM.md` (new, ~20 lines).
- `test-fixtures/feynman/integration/sample-section/ROOM.md` (new, ~20 lines). Per Decision #15.
- `test-fixtures/feynman/integration/sample-section/artifact-01-problem.md` (new, ~40 lines). Synthetic venture content.
- `test-fixtures/feynman/integration/sample-section/artifact-02-evidence.md` (new, ~40 lines).
- `test-fixtures/feynman/integration/sample-section/artifact-03-analysis.md` (new, ~40 lines).
- `test-fixtures/feynman/integration/expected-tier0-baseline.md` (new). A byte-equivalent snapshot of what the pre-81 deterministic generator produces for the sample section. Used by scenarios (b) and (c) to assert the pre-81 path is preserved. Generated once by running the pre-81 code path on the sample section before any 81-04 changes land, then committed as a frozen reference.

Files to modify:

- `scripts/vault-section-minto-generator.cjs` (modify, ~80-120 lines added, ~0 lines deleted from the pre-81 structural helpers). Changes:
  1. Add `module.exports = { deriveMeceTree, deriveGaps, findRelatedSections, renderSectionMinto, renderSectionMintoTier0, ... }` named exports. The pre-81 main function becomes `renderSectionMintoTier0` as a preserved internal name, and a NEW `renderSectionMinto` becomes the tier-dispatching entry point. The old behavior is the fallback.
  2. New `renderSectionMinto(section, artifacts, room, opts)`:
     - If `opts.forceTier0 === true` (from `--tier-0` CLI flag): call `renderSectionMintoTier0` directly, append AAAK footer via `require('../lib/memory/aaak-compress.cjs').attachAaakFooter`, return.
     - Otherwise: try `require('../lib/memory/feynman-minto-renderer.cjs').renderFeynmanMinto(section, artifacts, room)`. On success: return the markdown.
     - Catch `LLMUnavailableError`, `LLMBudgetError`, `LLMError`, `LLMParseError`, and any `NotImplementedError` (defense). For each: log to stderr `[minto] tier-0 fallback: <error class>: <message>`. Fall through.
     - Tier-0 fallback: call `renderSectionMintoTier0`, append AAAK footer, return.
  3. Add a `--tier-0` CLI flag parser at the top of the main invocation block. Accepted via `process.argv`.
  4. NO other changes to pre-81 logic. Structural helpers stay exactly as they were. Only the entry point gets a dispatching wrapper.
  5. When the `--tier-0` flag is set, the output must be byte-equivalent to the pre-81 output PLUS the AAAK footer. A regression test proves this by comparing against `expected-tier0-baseline.md` with the AAAK footer masked out (the AAAK footer contains a compressed summary which is deterministic for fixed input, but its hash depends on the content, so the assertion is "prefix is byte-equivalent to baseline, suffix matches AAAK footer format").

## Risks

- **Risk: `attachAaakFooter` may not exist in `aaak-compress.cjs`.** The phase constraint says AAAK is not modified. If the function does not exist, 81-04 cannot call it without either modifying AAAK (forbidden) or writing a wrapper.
  - **Mitigation:** task 7 has an explicit fallback: if `attachAaakFooter` is missing, create `lib/memory/aaak-footer.cjs` as a thin new file that imports existing AAAK primitives (whatever `compress`, `extractKeyPoints`, etc. functions are exported) and composes the footer block externally. This is a new file, not a modification to AAAK. The 21/21 AAAK test suite stays green. Decision: the plan executor determines this at task 7 time by inspecting `aaak-compress.cjs` exports. User directive: if the wrapper route is taken, add a one-line note to the 81-04 plan execution log. This risk is pre-flagged so the executor is not blocked.
- **Risk: byte-equivalent baseline capture happens before the 81-04 modifications land.** If an executor captures the baseline after changing the generator entry point, the baseline no longer represents pre-81 behavior.
  - **Mitigation:** task 2 is the SECOND task in the breakdown, explicitly before tasks 6 and 7 (the generator modifications). The commit order enforces this. A pre-capture git tag `phase-81-04-baseline-captured` can be used as a sentinel.
- **Risk: tier-1 path accidentally catches a non-recoverable error and masks a bug.** For example a `TypeError` in the renderer gets caught as "tier fallback reason" and silently falls through.
  - **Mitigation:** the catch block catches ONLY the specific error classes (`LLMUnavailableError`, `LLMBudgetError`, `LLMError`, `LLMParseError`, `NotImplementedError`). Any other error propagates. Test: inject a `TypeError` in the renderer, assert the generator re-throws instead of falling through.
- **Risk: the AAAK footer format may contain characters that make byte-equivalent comparison fragile.** For example, timestamps or non-deterministic fields.
  - **Mitigation:** the baseline comparison strips the AAAK footer before comparing. The stripping logic uses a clear delimiter (`<!-- AAAK-FOOTER-BEGIN -->`). If AAAK does not emit such a delimiter, task 7 adds one to the wrapper path (`lib/memory/aaak-footer.cjs` if it is used).
- **Risk: budget-file path redirection in scenario (c) may not work if `budget-ops.cjs` uses a hardcoded `~/.mindrian/budget.json` path.** 81-01 must support a path override.
  - **Mitigation:** 81-01 already specifies that every budget-ops function accepts an explicit `path` param. The test passes the path explicitly. If `llm-call.cjs` does not thread the path through, 81-04 adds a module-level seam `setBudgetPath(path)` that tests can call. If that fails too, tests use `MINDRIAN_BUDGET_PATH` env var which both `budget-ops.cjs` and `llm-call.cjs` read. This is a 5-line code addition to llm-call.cjs if not already present.
- **Risk: modifying `scripts/vault-section-minto-generator.cjs` beyond the fallback wiring**. The phase constraint is explicit.
  - **Mitigation:** the plan explicitly forbids any modification to the pre-81 structural helpers. Task 1 adds exports without touching internals. Tasks 6 and 7 add a new dispatcher wrapping the old function without renaming or rewriting it. A pre-commit diff review on this file is MANDATORY - if the diff shows changes to `deriveMeceTree`, `deriveGaps`, `findRelatedSections`, or any helper body, the plan executor must revert those changes.
- **Risk: renderer markdown composition might produce subtle differences from what `/mos:reason` consumers expect.** For example, tier-1 might use a different section order or heading level than the pre-81 output.
  - **Mitigation:** the composition unit tests pin the exact section headers and order. If downstream consumers break, that is caught at integration test time (full fixture room regenerate in 81-05).
- **Risk: tier-1 output may exceed 1500 tokens for the long fixture.** 81-03 fixtures include a `solution-design-long` case with 15 artifacts.
  - **Mitigation:** the 1500-token assertion is applied to the sample section in 81-04, which is a typical-sized section with 3 artifacts. For pathologically large sections, the fallback to tier-0 is acceptable and documented. If the typical case fails, the prompt `maxTokens` or the renderer's concat logic needs tightening. This is a plan-execution-time problem, not a blocker.
