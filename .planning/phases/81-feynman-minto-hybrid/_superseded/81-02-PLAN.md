# Plan 81-02: Feynman stages 1 and 2 (essence + plain language)

## Goal

Replace the 81-01 stub bodies of `feynmanStage1_essence` and `feynmanStage2_plainLanguage` with real Anthropic API calls routed through `lib/memory/llm-call.cjs`. Record three fixture cases per stage (short, typical, long input), commit them, and prove via fixture-replay tests that the stages return well-shaped objects matching the Feynman-MINTO schema from 81-CONTEXT D-1. Stages 3 and 6 remain skipped - this plan must document that fact in every comment referencing the pipeline. Goal-backward: a developer running `node lib/memory/feynman-stages.test.cjs` with no network access sees green tests for stages 1 and 2, and running with `FEYNMAN_LIVE_LLM=1` against a real API key produces structurally identical output (no regressions in shape).

## Risks

- **Risk:** Anthropic pricing drift between 81-01's hardcoded cost table and current rates. If the recorded fixture costs exceed the $0.15 per-run cap, the budget gate fires unexpectedly.
  - **Mitigation:** the first fixture recording run prints actual `usage` and computed cost, and the plan execution log must capture these. If `computeCost` numbers are stale, update the table in `llm-call.cjs` within 81-02 as an in-plan fix (one-line table update, no architectural change).
- **Risk:** Model drift. `claude-sonnet-4-20250514` may have been superseded.
  - **Mitigation:** if a fixture recording returns an HTTP 400 "unknown model", update `DEFAULT_MODEL` in `feynman-prompts.cjs` and re-record. Document the change in the plan execution log.
- **Risk:** Temperature 0.2 produces non-deterministic output. Fixtures may drift on re-recording.
  - **Mitigation:** assertions are structural, not exact-string. Fixture diff reviews focus on shape changes, not wording changes. Documented in 81-RESEARCH Section 3.
- **Risk:** Stage 2 prompt may not actually include stage 1 output and still pass tests (false green).
  - **Mitigation:** the prompt-inspection test explicitly captures the user string passed to `llmCall` via a shim spy and asserts the stage1 essence substring is present. This cannot pass accidentally.
- **Risk:** Fixture inputs invented synthetically may not represent real rooms, making 81-04 integration harder.
  - **Mitigation:** the three cases (short, typical, long) cover the range. If a real room's content is available at plan execution time, prefer it. Document the source of each fixture in the paired input.md file header.

## Deviation Notes

- **Model A/B (Sonnet vs Haiku)** - 81-RESEARCH flags this as an optional optimization. I am deferring the actual A/B to plan execution time rather than committing to a choice in the plan. The default stays Sonnet; a follow-up task documents what was observed during fixture recording. This is within the "authorized to make" list from the user instruction.
- **Stage 2 stage1-context JSON file** - I added this sibling fixture file to make stage 2 fixtures fully self-contained (stage 2's input is both the raw text AND stage 1's output). 81-RESEARCH did not explicitly propose this. The rationale: without it, stage 2 replay tests would depend on stage 1 fixtures via an implicit coupling that breaks if either fixture changes. Committing the context as a sibling makes the dependency explicit and diffable.
- **`scripts/record-feynman-fixtures.cjs`** - 81-RESEARCH mentions recording via `RECORD_FIXTURES=1 node lib/memory/feynman-stages.test.cjs`. That still works. I added the convenience script because it can enforce validation before writing (refuse to commit a fixture that would fail assertions), which the test-runner path cannot do cleanly.
