# Plan 81-03: Generator rewrite completion and tier-0 fallback

## Goal

Complete the generator rewrite per R-4 by wiring the tier-0 fallback path: when `scripts/vault-section-minto-generator.cjs --write` is invoked without a `--narrative` flag (bare-shell or cron context, no Claude session in the loop), the generator falls through to the pre-81 deterministic `renderSectionMinto` code path and attaches an AAAK footer via the existing `attachAaakFooter` export. When `--narrative` is provided but validation fails, the same fallback triggers with a warning printed to stderr. Capture the current pre-81 output as a frozen byte-equivalent baseline committed under `test-fixtures/feynman/` so any future touch of the tier-0 path shows up as a diff in `git status`.

## Scope

Files to create:
- `test-fixtures/feynman/expected-tier0-baseline.md` (frozen snapshot, committed): produced at the start of this plan by running the current pre-81 generator against the `fixture-small` section under `MINTO_FROZEN_DATE=2026-04-14`. This file is the regression guard for FEYNMINTO-08.

Files to modify:
- `scripts/vault-section-minto-generator.cjs` (grows by approx 80 to 140 lines): add tier-0 fallback logic inside `writeSectionFromNarrative`. Detection rules: (a) `--write` invoked with no `--narrative` flag - tier-0; (b) `--write` invoked with `--narrative` but the JSON file fails to parse or `validateNarrative` returns `valid: false` - tier-0 with warning to stderr including the validator error list. Tier-0 path invokes the preserved `renderSectionMinto` function (untouched), then calls `attachAaakFooter` from `require('../lib/memory/aaak-compress.cjs')` to append the AAAK footer to the output string, then writes via the existing atomic tmp-plus-rename pattern.
- `scripts/vault-section-minto-generator.integration.test.cjs` (from 81-02, grows by approx 80 to 120 lines): add three new integration cases per R-4 (tier-1 happy path already covered in 81-02; new cases: tier-1 validator reject, tier-0 direct, frozen baseline check).

Out of scope:
- Modifying `lib/memory/aaak-compress.cjs` (frozen, called as-is at the existing `attachAaakFooter` export).
- Modifying the pre-81 `renderSectionMinto` function body (byte-equivalent guard via the frozen baseline).
- Slash command changes (81-02 already done, no additional edits here).
- Migration or release work (81-04).

## Out of Scope

- Any network call or LLM invocation.
- Any budget gate or cost meter.
- Any ANTHROPIC_API_KEY reference.
- Any change to `commands/reason.md`.

## Task Breakdown

1. Capture the frozen baseline. Run `MINTO_FROZEN_DATE=2026-04-14 node scripts/vault-section-minto-generator.cjs test-fixtures/feynman/sections/fixture-small --section fixture-small` (the legacy positional-arg invocation path preserved inside the generator) and copy the resulting `test-fixtures/feynman/sections/fixture-small/fixture-small/MINTO.md` output to `test-fixtures/feynman/expected-tier0-baseline.md`. Commit. This file is the regression guard. Acceptance: file exists and is non-empty.
2. Add the tier-0 detection logic to `writeSectionFromNarrative` in `scripts/vault-section-minto-generator.cjs`. The new flow: (a) if `narrativePath` is null, emit log "tier-0 path: no narrative provided" to stderr, run tier-0; (b) if `narrativePath` is set, read and parse; on parse failure, emit "tier-0 path: narrative JSON parse failed: <err>" to stderr, run tier-0; (c) on parse success, call `validateNarrative`; on invalid, emit "tier-0 path: narrative schema invalid: <errors>" to stderr, run tier-0; (d) on valid, proceed with tier-1 (the `renderFeynmanMinto` path introduced in 81-01). Acceptance: `node scripts/vault-section-minto-generator.cjs --write test-fixtures/feynman/sections/fixture-small --section fixture-small 2>&1 | grep -q 'tier-0'` succeeds.
3. Add AAAK footer attachment to the tier-0 write path. Import `attachAaakFooter` from `../lib/memory/aaak-compress.cjs`, call it on the tier-0 rendered content before the atomic write. The existing `renderSectionMinto` output plus AAAK footer becomes the tier-0 file content. Acceptance: running the generator in tier-0 mode produces a file containing both the pre-81 MINTO body and an AAAK-footer marker (the existing `<!-- aaak-start -->` sentinel or equivalent from `lib/memory/aaak-compress.cjs`).
4. Integration test case: tier-1 happy path. Already covered in 81-02 by fixture-small, fixture-medium, fixture-large. No new work here.
5. Integration test case: tier-1 validator reject. Invoke `--write` with `test-fixtures/feynman/narratives/fixture-small-invalid.json` (new fixture, hand-crafted with one required field missing). Assert stderr contains "tier-0 path: narrative schema invalid". Assert the resulting MINTO.md matches the frozen baseline (byte-equivalent under `MINTO_FROZEN_DATE=2026-04-14` modulo the AAAK footer which is deterministic for a given input).
6. Integration test case: tier-0 direct. Invoke `--write` with no `--narrative` flag. Assert stderr contains "tier-0 path: no narrative provided". Assert the body portion of the resulting MINTO.md (stripped of AAAK footer) matches `test-fixtures/feynman/expected-tier0-baseline.md` byte-for-byte.
7. Integration test case: frozen baseline regression. Read the generated tier-0 body, strip everything from the AAAK footer marker onward, compare against `test-fixtures/feynman/expected-tier0-baseline.md` using `assert.strictEqual`. If this fails, someone modified the pre-81 path.
8. Create `test-fixtures/feynman/narratives/fixture-small-invalid.json`: hand-crafted to fail validation (e.g., `key_claims` array length 2). Commit.
9. Confirm all three fallback paths route through the same tier-0 code, not three parallel copies. Acceptance: a single `runTier0(room, section)` helper inside the generator is the single entry point and the three detection branches all call it.

## Tests

Integration test cases added in `scripts/vault-section-minto-generator.integration.test.cjs`:

- `tier-0 direct path` - structural: output file exists, output starts with `---` (frontmatter); byte-equivalent: body portion equals frozen baseline.
- `tier-0 on invalid narrative` - structural: stderr captured includes 'schema invalid'; behavior: fall-through produces valid tier-0 file.
- `tier-0 on unparseable narrative` - structural: stderr captured includes 'parse failed'; behavior: fall-through produces valid tier-0 file.
- `frozen baseline regression` - `assert.strictEqual(currentBody, frozenBaseline)`.
- `aaak footer attached in tier-0` - output contains `<!-- aaak-start -->` or equivalent AAAK footer sentinel from the existing library.
- `aaak footer NOT attached in tier-1` - tier-1 output from fixture-small with fixture-small.json narrative does NOT contain the AAAK footer sentinel (tier-1 is born compressed; tier-0 is the fallback that needs the footer).

## Risks

- Risk: the frozen baseline captured in task 1 contains a date stamp, and future runs with a different date will diff. Mitigation: capture under `MINTO_FROZEN_DATE=2026-04-14` and run the regression test under the same env var; alternately strip date stamps before comparing with a regex replace inside the test, whichever is cleaner at implementation time.
- Risk: AAAK footer contains a timestamp or non-deterministic field. Mitigation: 81-01 prep work already verified `lib/memory/aaak-compress.cjs` has 21/21 tests green and deterministic output; if a stamp is found, freeze via env var in the same pattern.
- Risk: the pre-81 path uses `today()` which reads system time. Mitigation: wrap the `today()` call to check `process.env.MINTO_FROZEN_DATE` first and return it unchanged if set. This is a zero-risk one-line addition that does not affect default behavior.
- Risk: tier-0 detection mis-fires because of argv parsing edge cases (e.g., `--narrative` with empty value). Mitigation: treat empty string narrative path as "no narrative", test this edge case explicitly.

## Deviation Notes

- The single `runTier0()` entry point pattern in task 9 is not explicitly required by the Revision 2 spec but is a cleanliness requirement to prevent three parallel copies of the fallback logic. Justification: maintainability and single-source-of-truth for the tier-0 code path.
- The invalid-narrative fixture `fixture-small-invalid.json` is added here rather than in 81-02 because 81-02 only needed valid narratives for the happy path. Keeping it with the tier-0 tests keeps the fallback test data co-located with the tests that use it.
- Feynman stages 3 and 6 remain out of automation (carried from D-2). Nothing in 81-03 changes that.
