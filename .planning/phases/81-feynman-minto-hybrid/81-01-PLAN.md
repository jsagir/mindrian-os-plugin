# Plan 81-01: Foundation

## Goal

Split `scripts/vault-section-minto-generator.cjs` into two subcommands (`--plan` and `--write`) that together form the deterministic spine of the Revision 2 Feynman-MINTO pipeline. Create the Feynman prompt constants library and the narrative JSON schema validator. The pre-81 deterministic code path is preserved verbatim inside the new subcommand wrapper so tier-0 regression is byte-stable. All new code is CJS, uses node built-in `assert` for tests, introduces zero runtime dependencies, and makes zero network calls.

## Scope

Files to create:
- `lib/memory/feynman-prompts.cjs` (approx 160 to 220 lines): exports `STAGE_1_ESSENCE`, `STAGE_2_PLAIN_LANGUAGE`, `STAGE_4_MENTAL_MODEL`, `STAGE_5_SWEET_SPOT` as string constants. Each prompt contains placeholder tokens `{section_name}` and `{artifacts}` and instructs Claude to return a JSON fragment matching the relevant subset of the R-3 schema. Prompts are automation-tightened rewrites derived from the Feynman engine skill, not copies.
- `lib/memory/feynman-prompts.test.cjs` (approx 80 to 120 lines): four describe-style blocks using node built-in `assert`. Per constant asserts non-empty, contains `{section_name}`, contains `{artifacts}`, length within `[400, 4000]` chars, contains zero em-dash characters (`charCodeAt` scan for 8212 and 8211), mentions the word "JSON".
- `lib/memory/narrative-schema.cjs` (approx 140 to 200 lines): exports `validateNarrative(obj)` returning `{valid: bool, errors: string[]}`. Enforces required fields (`section`, `essence`, `plain_language`, `governing_thought`, `mental_model.analogy`, `mental_model.mapping`, `mental_model.limits`, `sweet_spot`, `key_claims`), bounded string lengths per R-3, em-dash rejection in every string field (recursive walk), and `key_claims` array length in `[3, 5]`. Also exports `SCHEMA_BOUNDS` object for test introspection.
- `lib/memory/narrative-schema.test.cjs` (approx 140 to 200 lines): covers accept valid, reject missing fields (one case per required field), reject em-dash in each string field, reject over-long string (one case per bounded field), reject `key_claims` length 0, 1, 2, 6, 7, accept at 3, 4, 5.
- `scripts/vault-section-minto-generator.test.cjs` (approx 160 to 240 lines): fixture section at `test-fixtures/feynman/sections/fixture-small/` (3 mock artifacts, hand-built, committed); fixture narrative at `test-fixtures/feynman/narratives/fixture-small.json` (also hand-built); tests assert `--plan` emits JSON payload matching the R-1 shape, `--write` given fixture structural and fixture narrative produces a MINTO.md with expected top-level structure (regex matches on frontmatter block, essence block, mental model block, governing thought block, sweet spot block, key claims block, MECE tree block, cross-refs block, sources block, navigation block).
- `lib/memory/run-feynman-tests.cjs` (approx 40 to 70 lines): node-based runner pattern mirroring existing `lib/import/run-all-tests.cjs`. Requires each test file in turn, catches assertion errors, prints per-file pass or fail, exits 0 on all-pass.

Files to modify:
- `scripts/vault-section-minto-generator.cjs` (approx 395 lines today, grows to approx 560 to 680 lines): add `--plan` and `--write` subcommand routing at top of CLI dispatch. `--plan <roomDir> --section <name>` emits the R-1 JSON payload to stdout. `--write <roomDir> --section <name> --narrative <jsonFile>` merges structural with narrative and writes MINTO.md. The existing `generateAllSectionMintos`, `renderSectionMinto`, and all helper functions are NOT deleted, NOT modified in logic. They are preserved verbatim as the tier-0 code path. The new subcommand router simply dispatches: if `--plan` flag seen, call a new `emitSectionPlanPayload(roomDir, sectionName)` function; if `--write` flag with `--narrative` seen, call new `writeSectionFromNarrative(roomDir, sectionName, narrativePath)`; otherwise fall through to legacy `generateAllSectionMintos` (this is the bare-shell path preserved for 81-03 tier-0 wiring).

Out of scope for this plan: tier-0 fallback wiring (81-03), AAAK footer attachment (81-03), slash command rewrite (81-02), fixture narratives for medium and large sections (81-02), regeneration command (81-04), CHANGELOG or version bumps (81-04).

## Task Breakdown

1. Create `lib/memory/feynman-prompts.cjs` exporting four prompt string constants with placeholder tokens. Each prompt instructs Claude to return a JSON object for its slice of the R-3 schema. Acceptance: `node -e "console.log(Object.keys(require('./lib/memory/feynman-prompts.cjs')).length)"` prints 4.
2. Create `lib/memory/feynman-prompts.test.cjs` asserting each constant is well-formed (non-empty, contains placeholders, bounded length, no em-dash characters, mentions JSON). Acceptance: `node lib/memory/feynman-prompts.test.cjs` exits 0.
3. Create `lib/memory/narrative-schema.cjs` exporting `validateNarrative` and `SCHEMA_BOUNDS`. Implement required-field check, bounded-length check, em-dash recursive rejection, `key_claims` length enforcement. Acceptance: `node -e "const {validateNarrative} = require('./lib/memory/narrative-schema.cjs'); console.log(validateNarrative({}).valid)"` prints `false`.
4. Create `lib/memory/narrative-schema.test.cjs` covering accept, missing field, em-dash, over-long string, `key_claims` bounds. Acceptance: `node lib/memory/narrative-schema.test.cjs` exits 0.
5. Create `test-fixtures/feynman/sections/fixture-small/` directory with `ROOM.md` (Decision 15) and three mock artifact markdown files under named subfolders (Decision 16). Each artifact has frontmatter and 2 to 5 paragraphs of plain body text. Commit these files.
6. Create `test-fixtures/feynman/narratives/fixture-small.json` with a hand-crafted valid narrative for the fixture-small section. Run it through `validateNarrative` by hand (via `node -e ...`) before committing. Acceptance: file validates green.
7. Add `--plan` subcommand dispatch to `scripts/vault-section-minto-generator.cjs`. New function `emitSectionPlanPayload(roomDir, sectionName)` reads the section folder, walks artifacts (via existing `collectSectionArtifacts` and room scanner), builds the payload object `{section_path, section_name, artifacts: [{path, title, excerpt}], target_minto_path, structural: {frontmatter, mece_tree, cross_refs, sources, navigation}}`, and writes JSON to stdout. The `structural` sub-object is assembled using the existing deterministic helpers (`deriveGoverningThought` for placeholder, `deriveMeceTree`, `findRelatedSections`, etc.) so there is one source of truth. Acceptance: `node scripts/vault-section-minto-generator.cjs --plan test-fixtures/feynman/sections/fixture-small --section fixture-small | node -e "let s=''; process.stdin.on('data',d=>s+=d); process.stdin.on('end',()=>{const o=JSON.parse(s); if(!o.structural||!o.artifacts) process.exit(1)})"` exits 0.
8. Add `--write` subcommand dispatch to the same file. New function `writeSectionFromNarrative(roomDir, sectionName, narrativePath)` reads and validates the narrative JSON (via `validateNarrative`), rebuilds structural payload (same code path as `--plan`), merges structural plus narrative into final MINTO.md content using a new helper `renderFeynmanMinto(structural, narrative)`. The new renderer lives alongside the preserved `renderSectionMinto` (which stays untouched for tier-0). Acceptance: `node scripts/vault-section-minto-generator.cjs --write test-fixtures/feynman/sections/fixture-small --section fixture-small --narrative test-fixtures/feynman/narratives/fixture-small.json` writes a MINTO.md to the fixture section folder.
9. Create `scripts/vault-section-minto-generator.test.cjs` using node built-in `assert`. Test cases: plan subcommand emits valid JSON with required keys; write subcommand given fixture structural plus fixture narrative produces MINTO.md passing structural regex checks; write subcommand is deterministic (two consecutive runs produce byte-identical output modulo a frozen date stamp handled via env var `MINTO_FROZEN_DATE`). Acceptance: `MINTO_FROZEN_DATE=2026-04-14 node scripts/vault-section-minto-generator.test.cjs` exits 0.
10. Create `lib/memory/run-feynman-tests.cjs` that requires each test file in turn, catches failures, prints summary, exits 0 on all-pass. Acceptance: `MINTO_FROZEN_DATE=2026-04-14 node lib/memory/run-feynman-tests.cjs` exits 0 and prints 4 passing test file names.

## Tests

Test files and the assertion types they use:

- `lib/memory/feynman-prompts.test.cjs`:
  - Structural: `assert.strictEqual(typeof prompts.STAGE_1_ESSENCE, 'string')` and parallel for the other three.
  - Regex: `assert.ok(prompt.includes('{section_name}'))`, `assert.ok(prompt.includes('{artifacts}'))`, `assert.ok(prompt.includes('JSON'))`.
  - Bounds: `assert.ok(prompt.length >= 400 && prompt.length <= 4000)`.
  - Em-dash scan: iterate code points, `assert.ok(codePoint !== 8212 && codePoint !== 8211)`.
- `lib/memory/narrative-schema.test.cjs`:
  - Structural: `assert.deepStrictEqual(validateNarrative(validFixture).valid, true)`.
  - Missing-field cases: one per required field, each expects `valid === false` and the corresponding error string present.
  - Em-dash cases: for each string field, inject an em-dash, expect `valid === false`.
  - Over-long cases: for each bounded string field, inject length + 1 chars, expect `valid === false`.
  - `key_claims` length cases: 0, 1, 2 reject; 3, 4, 5 accept; 6, 7 reject.
- `scripts/vault-section-minto-generator.test.cjs`:
  - Structural: `--plan` output parses as JSON and has keys `section_path`, `section_name`, `artifacts`, `target_minto_path`, `structural`.
  - Regex: written MINTO.md matches patterns for each R-3 derived section heading (essence, governing thought, mental model, sweet spot, key claims, MECE tree, cross-refs, sources, navigation).
  - Determinism: two runs under `MINTO_FROZEN_DATE=2026-04-14` produce byte-identical output (`assert.strictEqual(fs.readFileSync(a), fs.readFileSync(b))`).
  - Bounds: total output character length under 15000 (rough token proxy).

## Risks

- Risk: `scanRoom` and `walkAllSections` helpers assume a real room structure. The `fixture-small` fixture must include a valid `STATE.md` or equivalent so the scanner does not throw. Mitigation: build the fixture room using the minimum shape the existing scanner expects (verify by running `node -e "require('./lib/vault/room-scanner.cjs').scanRoom('test-fixtures/feynman/sections/fixture-small')"` during task 5).
- Risk: determinism test fails because the pre-81 renderer hard-codes `today()` into output. Mitigation: introduce `MINTO_FROZEN_DATE` env var support in the new `renderFeynmanMinto` and (optionally) mirror it in the preserved `today()` helper without changing default behavior; if the preserved helper cannot be touched, freeze the date only in the new renderer and rely on regex-match rather than byte-identity for the preserved code path (81-03 has a separate frozen baseline).
- Risk: em-dash accidentally creeps into prompt text because the Feynman skill uses em-dashes freely. Mitigation: author prompts from scratch using hyphens only, run the em-dash grep from Verification before committing.

- Test runner is named `lib/memory/run-feynman-tests.cjs` following the existing `lib/import/run-all-tests.cjs` pattern per the authorized naming decision.
- Fixture layout uses `test-fixtures/feynman/sections/<name>/` and `test-fixtures/feynman/narratives/<name>.json` per the authorized fixture layout decision. Each fixture section folder has a `ROOM.md` per Decision 15 and each mock artifact sits in its own named nested folder per Decision 16.
- Feynman stages 3 and 6 are explicitly not represented in `feynman-prompts.cjs` because they are human review gates skipped in automation per the Revision 2 D-2 carry-over.
