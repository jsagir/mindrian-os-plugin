# Plan 81-04: Migration and v1.10.2 release

## Goal

Ship Phase 81 as v1.10.2. Add the `--regenerate-all` flag to the `/mos:reason` orchestrator so users can migrate existing pre-81 MINTOs to the post-81 format with a timestamped backup and a per-section report. Add Decision 17 to both `CLAUDE.md` and `.claude/includes/decisions.md` documenting the slash-command-as-orchestrator architecture and why there is no API key or budget machinery. Finalize `.planning/REQUIREMENTS.md` with the Revision 2 FEYNMINTO-01 through FEYNMINTO-10 list, marking FEYNMINTO-05 and FEYNMINTO-06 as RETIRED. Write the CHANGELOG [1.10.2] entry documenting the Revision 1 architectural mistake, the Revision 2 reframe, the skipped v1.10.1, the semver deviation, and the forward pointer to v3.0 MCP Sampling. Execute the 5-gate release per `.claude/includes/release-process.md`. End-to-end integration test: regenerate a fixture room and verify backup, report, and all MINTOs conform.

## Scope

Files to create:
- `.planning/REQUIREMENTS.md` (or append to existing if present) with the FEYNMINTO-01 through FEYNMINTO-10 block (approx 60 to 100 lines).
- `scripts/vault-regenerate-all.cjs` (approx 140 to 220 lines): the helper invoked by the `/mos:reason --regenerate-all` orchestrator path. Walks every `MINTO.md` in the active room, backs up to `.migration-backup/YYYY-MM-DD-HHMMSS/`, delegates regeneration to the `--plan` and `--write` subcommands (tier-0 fallback is the bare-script path), and emits `.migration-backup/YYYY-MM-DD-HHMMSS/report.md` with per-section old-size, new-size, tier used, and any warnings.
- `scripts/vault-regenerate-all.test.cjs` (approx 120 to 180 lines): copies `test-fixtures/feynman/sections/fixture-small` to a scratch directory, seeds a pre-81 MINTO.md, runs the regenerator, asserts backup created, new MINTO conforms to schema, report file written and parses.

Files to modify:
- `commands/reason.md` (grows by approx 40 to 80 lines): add `--regenerate-all` flag handling at the top of the slash command body. When present, the slash command instructs Claude to call `node scripts/vault-regenerate-all.cjs <roomDir>` via Bash (which handles backup and the per-section regeneration loop), then for each section re-runs the same tier-1 orchestration used by the main path. This keeps the code path single and just wraps the loop.
- `CLAUDE.md`: add Decision 17 entry to the numbered Key Decisions list.
- `.claude/includes/decisions.md`: add Decision 17 row to the decisions table.
- `CHANGELOG.md`: prepend a `## [1.10.2] - 2026-04-14` entry documenting all seven items from the user brief (skipped 1.10.1, slash-command orchestrator, no API key, migration path, semver deviation, v3.0 forward pointer, Revision 1 learning note).
- `.claude-plugin/plugin.json`: bump `version` to `1.10.2`.
- `package.json`: bump `version` to `1.10.2`.
- `lib/memory/run-feynman-tests.cjs`: add `scripts/vault-regenerate-all.test.cjs` to the test list.

Cross-repo handoff (NOT automated inside this plan, flagged as a handoff task):
- `~/mindrian-marketplace/.claude-plugin/marketplace.json`: update `source.ref` to `v1.10.2` after the git tag is pushed. This is a separate repository and is the user's explicit manual step per `.claude/includes/release-process.md`.

## Risks

- Risk: the 5-gate release rule can drift if any of CHANGELOG, plugin.json, package.json, git tag, marketplace.json go out of sync. Mitigation: the verification block above runs greps that fail the plan until all in-repo gates are synced. The cross-repo marketplace.json step is flagged explicitly as a handoff so the user knows to execute it.
- Risk: Decision 17 wording drift between `CLAUDE.md` and `.claude/includes/decisions.md`. Mitigation: both edits happen in the same plan run and both are verified with grep commands.
- Risk: `scripts/vault-regenerate-all.cjs` runs tier-0 regeneration unconditionally, overwriting Claude-produced narrative if the user ran `/mos:reason` earlier. Mitigation: the backup folder preserves every pre-run MINTO.md before any overwrites, and the slash command `/mos:reason --regenerate-all` body is structured so the tier-0 pass is just the safety net - the main tier-1 orchestration loop runs afterward and replaces the tier-0 output with Claude-produced narrative. Net effect: backup contains pre-run state, final files contain tier-1 output, no data loss.
- Risk: the cross-repo marketplace handoff is forgotten. Mitigation: explicit "5 of 5 gates" checklist printed by the release step, gate 5 labeled "USER ACTION REQUIRED - update marketplace.json source.ref".
- Risk: beta gating confusion. The release-process include says "release infrastructure ALWAYS ships as a beta first" but Phase 81 is feature work, not release infrastructure. Mitigation: plan explicitly states Phase 81 is feature work and ships straight to stable.

## Deviation Notes

- Shipping as v1.10.2 not v1.11.0 per user directive. Semver says this is a minor bump (new feature). Documented in CHANGELOG per the user brief.
- Not shipping as beta. Release-process include reserves beta gating for release infrastructure, not feature work. Phase 81 is feature work. Documented in the CHANGELOG Notes section.
- Cross-repo marketplace.json update is a user-executed handoff, not automated inside the plan. The release-process include says "Run `scripts/release.sh <version>` (when it exists)" and flags that the script does not yet exist. Until it does, the final gate is a manual user step.
- The tier-0 safety pass in the regenerator runs before the tier-1 Claude loop. This is belt-and-suspenders: the backup folder alone is sufficient for data safety, but the tier-0 write pass guarantees every section has a readable file even if Claude aborts midway through the tier-1 loop.
- Feynman stages 3 and 6 remain out of automation (carried from D-2 through all four plans).
