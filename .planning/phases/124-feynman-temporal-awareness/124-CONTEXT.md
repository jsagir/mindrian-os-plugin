# Phase 124: FEYNMAN.md temporal awareness (STUB)

**STATUS:** STUB. Scaffolded 2026-05-13 for resumability. Next: `/gsd:discuss-phase 124` -> `/gsd:plan-phase 124` -> `/gsd:execute-phase 124`.

## Thesis (locked from the 2026-05-13 discussion)

`FEYNMAN.md` (the "explain it to a smart 12-year-old" layer of the per-folder memory triple, Phase 88) is currently a still photograph -- a flat list of captured insights with no sense of when each was first written, when it was last touched, or whether it has gone quiet. Phase 109 already shipped the temporal substrate (`memory_event` is a first-class node type in `room.db`; `navigation.findRecentChanges(sinceEpochMs)` and `navigation.findStaleDecisions(...)` are two of the seven insight primitives; Canon Part 9 ratified the "events not just latest state" architecture). Phase 124 surfaces that substrate INSIDE `FEYNMAN.md` so the navigator can see WHEN each piece of understanding came in and WHEN it stopped getting touched -- without leaving the file.

The shape was chosen 2026-05-13: **Option B -- auto-generated `## Timeline (auto)` section appended to `FEYNMAN.md`**, regenerated by a post-write hook reading the Phase 109 `memory_event` log. The body of `FEYNMAN.md` stays human-authored, text-pure; the appended section is the machine view, never hand-edited.

## Hard invariant (LOCKED at thesis)

> The `## Timeline (auto)` section is REGENERATED, never hand-edited. The hook reads only `room.db` (`memory_event` rows, the seven insight primitives via `lib/core/navigation.cjs`). The hook writes only the appended section -- the human-authored body above the section is byte-preserved across regeneration.

A clear sentinel (`<!-- TIMELINE_AUTO_START -->` ... `<!-- TIMELINE_AUTO_END -->`) bounds the auto-section. Anything outside the sentinel is the human-authored body and is byte-preserved. Anything inside is owned by the regenerator. Editing inside the sentinel is a sin; the next write blows it away. (Mirror of the post-write cascade idiom already used elsewhere in the plugin -- e.g. the MINTO post-write hook.)

## Why Option B (and not A / C / D) -- captured 2026-05-13

- **Option A (per-insight inline stamps in the body)** -- considered, rejected. Forces the author to maintain `[captured: ...]` markers; drifts; the body becomes machine-edited surface.
- **Option B (auto-generated `## Timeline` section, appended)** -- **PICKED**. Small hook, file stays one place the navigator looks, inherits Canon Part 9 for free.
- **Option C (A + B together)** -- not picked. Carries A's drift cost.
- **Option D (sibling `TIMELINE.md` file, extending the quadruple to a quintuple)** -- considered, deferred. Canon-affordance expansion (a new per-folder file); bigger discussion; revisit if Option B's auto-section proves too noisy.

## Scope (locked at thesis)

### IN scope
- A post-write hook (or `vault-section-minto-generator.cjs`-style cascade) that fires on every `FEYNMAN.md` write and regenerates the bounded `## Timeline (auto)` section from `lib/core/navigation.cjs::findRecentChanges` + `findStaleDecisions` + a "first-captured / last-touched" projection per insight scoped to the folder's section.
- A renderer module (`lib/core/feynman/timeline-renderer.cjs` or similar -- exact path = planner's discretion) that takes the navigation primitives' output and produces the markdown section. Templated explanation strings, Phase 109 idiom -- zero LLM in the loop.
- Sentinels (`<!-- TIMELINE_AUTO_START -->` / `<!-- TIMELINE_AUTO_END -->`) and a byte-preserving body-merge guarantee (the body above the sentinel is identical pre/post regenerate).
- "Stale" thresholds -- a closed set (e.g. recent < 7 days / quiet 7-30 days / stale 30-90 days / dormant 90+ days; exact thresholds = discuss-phase decision).
- Per-folder scoping (a `FEYNMAN.md` for `room/business-model/` reflects only that section's `memory_event` rows, not the whole room).
- Tests: a fixture room with seeded `memory_event` rows + a `FEYNMAN.md` with sentinels, regenerate, assert the auto-section is exact + the body is byte-identical pre/post. Plus a Canon-Part-9-alignment grep sweep (the renderer touches only LOCAL data; never sends content to the Brain).

### OUT of scope (DEFERRED)
- Per-insight inline timestamps in the body (Option A).
- Sibling `TIMELINE.md` file (Option D).
- Back-dating `memory_event` rows from existing `FEYNMAN.md` body parse (no parsing of human prose; the Timeline starts empty for rooms that pre-date Phase 124 and fills as new events accumulate).
- Surfacing the timeline in `BRAIN.md` (Phase 90's BRAIN.md is the Brain-derived layer; the timeline is LOCAL by definition).
- Statusline glyph / dashboard surface for "stale FEYNMAN sections" -- could be a Phase-125-ish follow-on; not this phase.
- A Brain-side "summarize timeline" job (would be a new entry in Phase 110's closed job vocabulary -- separate discussion).
