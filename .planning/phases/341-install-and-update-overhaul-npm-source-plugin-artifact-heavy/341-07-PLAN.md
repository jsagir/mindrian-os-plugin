Collapse to one install location and retire the shell installer that created the second one.

Purpose: the navigator's teardown named this root cause B, "two answers to where the plugin lives",
and its findings F2 (the live install path fourteen versions stale) and F8 (install debris in user
settings) are both consequences. `install.sh:13` sets `INSTALL_DIR="${HOME}/.claude/plugins/
mindrian-os"` and `install.sh:319` writes a SessionStart hook keyed to the marker `mindrian-os`
pointing at it. That directory IS the second location. 341-RESEARCH confirmed it is reproduced on
Windows and ABSENT on this Linux box, so the teardown must treat "already clean" as a normal success
rather than an error.

It also answered discretion item (f) with five pieces of evidence: `docs/install/PACKAGING-PATHS.md`
enumerates four canonical distribution paths and `install.sh` is not one of them; paths 3 (ZIP or
URL via `--plugin-url` / `--plugin-dir`) and 4 (CI or Docker pre-bake via
`CLAUDE_CODE_PLUGIN_CACHE_DIR` / `CLAUDE_CODE_PLUGIN_SEED_DIR`, both confirmed as literal strings in
the 2.1.266 binary) are exactly the "no marketplace loader" cases and both go through the platform;
Desktop and Cowork consume the plugin through `.mcp.json` and the loader, not a shell installer; and
`install.sh` has a documented failure record in this repo.

`scripts/check-first-touch-drift.cjs:57` lists `'install.sh'` in its `DOC_SURFACES` set, so retiring
the file without editing that check turns a green gate red for an unrelated reason; and the
retirement happens AFTER the cold-install proof, never before.
