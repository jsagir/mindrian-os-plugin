<objective>
Collapse `/mos:update` to Check, Confirm, loader, Verify, delete the second implementation of the
loader that grew up beside it, and replace the retired touch-file with a real post-update signal:
the first session after any install or update verifies itself, says so in one statusline segment,
probes Theo without blocking, and hands the navigator one insight.

Purpose: 341-RESEARCH read the loader out of the shipped Claude Code binary and found it already
does, atomically and with a versioned cache directory, everything `/mos:update` Steps 6 and 7 were
hand-rolling: `Tus` fetches and caches, `E$` copies into the versioned directory, `xje` materializes
dependencies. The navigator's teardown called this root cause C, "update has no transaction", and
proposed a five-step transaction (Check, Confirm, Fetch to staging, Swap, Verify). Three of those
five now have a platform owner. What remains for the plugin is Check, Confirm, delegate, Verify.

D-07a (added 2026-09-10, mid-execution) says what Verify must actually mean. The old Verify was a
sentence the command printed at the end of its own run, backed by a touch-file the plugin wrote to
itself. The new Verify is automatic and it happens where the evidence is: on the NEXT session, when
the swapped bytes are actually the running bytes. The trigger is a version change
(`installed_plugins.json` versus a last-seen marker), which the loader cannot forget to set because
the loader is the thing that writes `installed_plugins.json`. The verification is a bounded, offline
subset of doctor acceptance points that already exist. The result is one statusline segment. Theo is
probed after the local set, detached, honestly. And because a first session after an update is the
first-step surface, it carries one variable reward: a single generic-handle nugget from Theo, framed
by Larry as one question.

The deletion is still bigger than `commands/update.md`. `scripts/post-update-activation.cjs` writes
the touch-file and `scripts/doctor.cjs` carries a `--post-update` flag that spawns it; both go. But
two things that the pre-revision plan proposed to delete now SURVIVE, converted rather than removed,
because D-07a gives them a real job:

- `scripts/sessionstart-post-update-preflight.cjs` stays the registered SessionStart host. Deleting
  it and adding a tenth hook would be the same hook with a different name, and it would throw away
  the Part 7 F8 stale-registry restart cue (`detectStaleRegistry`) that is independent of the
  touch-file and still correct. It is converted in place.
- The `post_update` signal in `lib/statusline/cockpit-signals.cjs` keeps its name and its consumer
  and changes its SOURCE: from a touch-file that only ever meant "a swap happened" to a real
  verification result that means "the post-update check found something".

One doctor point also does NOT go: `activation-reached-the-wire` compares the live MCP server
version to `package.json` and never reads the touch-file, so it survives untouched and keeps proving
the thing that actually matters. It moves onto the DETACHED leg, not the inline one, because it
spawns a real network handshake and the inline leg is offline by contract.

Output: the collapsed command, the retired SHA leg, the removed touch-file mechanism, a session-start
verification tier with a policy and a statusline segment, a detached Theo probe with an honest
refusal, one insight, and the tripwires that keep all of it true.
</objective>
