<objective>
Prove the artifact actually installs, on all three operating systems, before anything else in this
phase ships.

Purpose: D-13 makes the migration order load-bearing and puts this proof second for a measured
reason. `~/.claude/plugins/npm-cache/` DOES NOT EXIST on the dev box: no npm-source plugin has ever
installed here, so the first post-341 install is a genuine cold path with no local precedent. Three
things are unverified until a real install runs: whether the loader's first `npm install` has a
timeout at all (341-RESEARCH assumption A1 could not resolve the constant in the minified bundle),
whether the 60,000 ms dependency install completes on a slow link, and whether Windows behaves the
way the computed MAX_PATH budget says it does (341-RESEARCH is MEDIUM confidence there, path budget
computed and not executed).

This plan cannot be automated past the evidence collector. There is no Windows box and no macOS box
in this environment, and 341-RESEARCH names that as the phase's one hard external dependency with
no fallback. So: build the collector, run the human checkpoint, record the evidence in a tracked
file, and gate on it.

Output: one evidence command, one tracked proof document, one gate test. No product code changes.
</objective>

  <action>
Create `scripts/collect-cold-install-evidence.cjs`, CJS, executable shebang, `'use strict'`, house
header comment naming Phase 341 and D-13 step 2, stating WHAT (it emits one JSON envelope proving a
cold install landed and both MCP servers load) and WHY (there is no Windows or macOS box in the dev

touch is inherited from `doctor --brain-smoke`, which is stated, not hidden), and the house rule
line.

Export `collectEvidence(opts)` and expose `--json` on the CLI. The envelope, every field required:

- `schema`: the literal `mos-cold-install-evidence/1`.
- `collected_at`: ISO timestamp.
- `platform`: `process.platform`, `arch`: `process.arch`, `node`: `process.version`.
- `os_release`: `os.release()`.
- `claude_code_version`: read from the installed binary path if resolvable, else `null` with a
  `notes` entry saying so. Never guess.
- `plugin_root`: `process.env.CLAUDE_PLUGIN_ROOT` or `null`.
- `plugin_version`: read via `lib/core/repo-version.cjs` when running from a checkout, and from
  `<plugin_root>/package.json` when running from an install. Never a tree search.
- `marketplace_source`: the `plugins[0].source` object read from the user's marketplace catalog if
  present, so the evidence records WHICH source type produced this install. This is the field that
  proves the install came through the npm path and not a leftover git clone.
- `npm_cache_present`: boolean, `fs.existsSync(~/.claude/plugins/npm-cache)`. On a first cold
  install this flips from false to true, which is itself evidence.
- `cache_dir`: the resolved `~/.claude/plugins/cache/mindrian-marketplace/mos/<version>/` path.
- `node_modules_present`: boolean, `fs.existsSync(<cache_dir>/node_modules)`.
- `completion_record_present`: boolean,
  `fs.existsSync(<cache_dir>/node_modules/.package-lock.json)`. This is the loader's OWN completion
  record per F-3 and is the strongest single signal that `npm ci --ignore-scripts` finished rather
  than timing out.
- `installed_package_count`: count of directories two levels deep under `<cache_dir>/node_modules`,
  so a PARTIAL tree (the documented timeout failure mode: "A timed-out install can leave a partial
  node_modules tree in the cached copy") is visible as a number rather than a boolean.
- `mcp_servers`: an array of two entries, one per `.mcp.json` server, each
  `{ id, entry_path, entry_exists, loads }`. `loads` is determined by spawning
  `node <entry_path> --version` or the narrowest non-destructive probe each entry supports; read
  each `bin/*.cjs` to find one before inventing a flag. If neither supports a probe flag, spawn
  `node -e "require('<entry_path>')"` with a short timeout and treat a clean exit as `loads: true`.
- `doctor_acceptance`: the parsed result of spawning
  `node <plugin_root>/scripts/doctor.cjs --acceptance --json`, reduced to
  `{ ok, failed_point_ids: [] }`.
- `eureka_smoke`: the parsed result of `node <plugin_root>/scripts/doctor.cjs --eureka-smoke --json`,
  reduced to `{ ok, layers: [{id, ok, advisory}] }`. On a fresh install `model_installed` is
  expected to be `ok:false` and advisory; that is the CORRECT slim-install state and the evidence
  must show it rather than hide it.
- `longest_relative_path`: the longest path length under `<cache_dir>`, and the path itself. This is
  the Windows MAX_PATH datum 341-RESEARCH could compute but not execute (F-5 computed 180 and 188
  characters with 72 to 80 characters of headroom for an 8-character username).
- `first_install_seconds`: `null` by default, with a `notes` field explaining that the human records
  the wall-clock duration of the `claude plugin update` command here. 341-RESEARCH Open Question 1
  asks for exactly this measurement on the slowest of the three platforms.
- `notes`: an array of strings for anything the collector could not determine.

Every probe is wrapped so a failure produces a recorded `null` plus a `notes` entry, never a throw.
An evidence collector that crashes on an unhealthy install is useless precisely when it is needed.
Every spawn uses an argv array, `input: ''`, an explicit `timeout`, and stdout capped at 2000
characters.

CLI: `--json` prints the envelope to stdout and exits 0. Default (no flag) prints a human-readable
summary followed by the JSON. Unknown flag prints `usage` and `process.exit(2)`.
`module.exports = { collectEvidence };`.
  </action>
