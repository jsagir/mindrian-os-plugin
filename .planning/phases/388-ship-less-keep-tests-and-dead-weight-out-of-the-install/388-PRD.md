# Phase 388 - Ship less: keep tests and dead weight out of the install (PRD)

**Source:** auditor claim (hypothesis, to verify): about 2.5 MB of tests ship to every user, and thousands of lines of dead or test-only code ship too.
canon_parts: 7, 11
Depends on: Phase 385 (which decides what is dead). Independent of measurements.

## Scope

1. Measure what the npm package and the marketplace install actually contain: `npm pack --dry-run` file list and size by folder, and the install layout the loader builds. Counts and sizes only.
2. Find what the product needs at run time versus what only tests, docs or build tools need. Check every path a hook, command, skill or doctor point reads at run time before excluding anything.
3. Propose the smallest safe exclusion list (package `files` or ignore rules). A test that pins the installed layout (for example the 369 installed-layout test) must still pass.
4. Apply it only with a before and after size and a fresh-install check. Release lockstep and shrinkwrap rules apply.
5. Owner forks (what users lose, for example the ability to run tests from the install) come as gate cards.

## Rules

Measure first, failing test first, no push/tag/release, `git commit --only`.
