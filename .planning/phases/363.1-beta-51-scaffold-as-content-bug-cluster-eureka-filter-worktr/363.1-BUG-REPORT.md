## P0

### 1. Eureka candidate filter admits scaffold and structural nodes

**Observed (sub-room):** 3034 pairs scored after excluding 2080 scaffold, 1287 container and 1102 figure-guard pairs. All 25 ranked rows pair structural nodes:

| Node kind in ranked rows | Count |
|---|---|
| Section `CONTEXT.md` contracts | 13 |
| `entity:entity-extract:1296d` ("Lab", a generic noun) | 22 refs |
| `claim:` nodes (a root question) | 10 |
| `memory_artifact:*:MINTO` (MINTOs regenerated 1 hour earlier by /mos:reason) | 5 |
| **Rows between two real artifacts** | **0** |

The top row is `market-analysis/CONTEXT` x `Lab` with `validated_demand` 0.99. A section contract is scored as having validated demand.

**Observed (parent):** 642 pairs scored, 1225 scaffold excluded, graph 1008 nodes. All 25 rows are `domain:` nodes whose titles are **classifier fallback buckets**: `unknown`, `freeform_unmatched`, `empty_payload`, `move_set`, plus `memory_artifact:*:ROOM` (ROOM.md). Again 0 real-artifact rows.

**Critic:** `25 resolved (0 passing)` in both rooms, tag `domain_swap_invariant`. The critic is working correctly; the ranker is feeding it garbage.

**Expected:** exclude, before scoring: `*/CONTEXT.md`, `MINTO.md`, `ROOM.md`, `FEYNMAN.md` seeds, `memory_artifact:*` nodes, classifier-bucket domain nodes (`unknown|freeform_unmatched|empty_payload|move_set`), and low-IDF generic entities (`Lab`). Also consider excluding artifacts written by the system in the same session (MINTOs) from "validated_demand".

**Evidence:**
- `translational-capital-lab/.mindrian/eureka/portfolio-report.json`
- `israel-frontier-criticality/.mindrian/eureka/portfolio-report.json`

### 2. `/mos:reason` can't dispatch its mandated agent outside a git repo

The `mos-reason` skill requires `subagent_type: framework-runner`. `agents/framework-runner.md` declares `isolation: worktree`. On Claude Code 2.1.284, all 9 dispatches failed immediately:

```
Cannot create agent worktree: not in a git repository and no WorktreeCreate hooks are configured.
```

Rooms are not git repos by default (`git_enabled: false` on all 28), so this breaks `/mos:reason` for every user who hasn't run `/mos:rooms git-setup`. The same declaration exists on `agents/research.md` and `agents/opportunity-scanner.md`, which have the same exposure.

**Workaround used:** re-dispatched the identical contract with `general-purpose`, and all 9 succeeded.

**Fix options:** drop `isolation: worktree` (each subagent already writes only its own section's MINTO, so disjointness is enforced by contract), or detect non-git rooms and fall back, or ship WorktreeCreate hooks.

## P1

### 3. Eureka tail classifier is degenerate

Sub-room: all 14 sections have `attention=0.3811, growth=0.5`. Parent: 27 tail items, **1 distinct value**. `suspect_noise: true` is correctly raised, but the tail read is meaningless. `growth_proxy` is reported as `created_at-recency` in provenance and `cnumber-recency` inside `tail`, and the two labels disagree.

### 4. Opportunity Statement template substitution bug

Rank-1 statement (verbatim excerpt):

> "...creates a market-analysis x problem-definition\agreed-structure-working-brief-2026-09-28.md approach to a market-analysis x problem-definition\agreed-structure-working-brief-2026-09-28.md cross-domain bridge that addresses the a market-analysis x problem-definition\agreed-structure-working-brief-2026-09-28.md cross-domain bridge gap..."

A file path is used as the mechanism/approach noun in 4 slots, and there is an "the a" article collision. The text also carries `unmet need: no strategic home for unclassified problem for market-analysis/CONTEXT` and the score `composite 0.55`, which the render spec (D-29) says must never be rendered.

### 5. compute-state inflates venture stage from scaffold

`translational-capital-lab/STATE.md` (computed 16:12Z) reports `venture_stage: Investment` and marks 12 sections "Well-developed". After `/mos:reason`, 7 of those sections turned out to contain only `CONTEXT.md` (contract) + `FEYNMAN.md` (34-line birth seed) + `ROOM.md`. Scaffold files are counted as entries (e.g. business-model "3/9, Well-developed" with zero content). The "Suggested Next Action: Comprehensive Data Room... investor readiness" is false.

**Expected:** exclude `CONTEXT.md`, `ROOM.md`, `MINTO.md`, and unmodified seeded `FEYNMAN.md` from entry counts and stage computation.

### 6. `scripts/mos-status.cjs` ignores the registry active room

Run from `~` with a valid active room (`translational-capital-lab`):

```
no active room; /mos:rooms to list available rooms
```

`resolveRoomRoot(cwd)` walks up from cwd only. It should fall back to `room-registry get-active` + path. This especially matters for sub-rooms, whose registry path is relative (`israel-frontier-criticality/translational-capital-lab`).

### 7. Template governing thoughts pass health as "check"

Before `/mos:reason`, 10 sections showed `check` with MINTO text like `"Business Model synthesizes 2 artifacts into a coherent argument for this section..."` and median health 0.73. That text is a placeholder, not a claim. A health score should not reward a governing thought that asserts nothing. A cheap detector: the regex `^<Section> synthesizes \d+ artifacts` -> `--`.

### 8. Registry: 18 rooms with `status: active`

`iris-numa`, `iris-tenders-finder`, ... `iris-cleavio` (18 rooms) all have `status: active` and `last_opened: 2026-09-03T22:45:00Z` (identical timestamp, so a bulk import is likely). The registry's `active` field is `translational-capital-lab`. `set-active` parks the *previous active* but never repairs this drift. Only one room should ever hold `status: active`.

## P2

### 9. HSI cascade hardcodes legacy `room`

`/mos:reason` PHASE 2 step 4 runs `compute-hsi.py room`. From a `~/MindrianRooms/<room>` cwd:

```
Error: ...\translational-capital-lab\room is not a directory
```

`compute-hsi.py .` works (40 artifacts, 20 pairs). The cascade should pass the resolved room dir.

### 10. `/mos:rooms close` Python step is broken on Windows Git Bash

The skill builds `open('$ROOMS_HOME/.rooms/registry.json')` with `ROOMS_HOME=/c/Users/...`. A win32 python can't open MSYS paths:

```
FileNotFoundError: '/c/Users/jsagi/MindrianRooms/.rooms/registry.json'
```

The file exists. Use `cygpath -w`, pass the path via argv from a node helper, or add a `room-registry clear-active` subcommand.

### 11. `/mos:find-analogies` Step 1 checks legacy `room/`

The skill says: "Check if a `room/` directory exists in the current workspace... If no `room/` directory -> x No project found". It also has `produces: "room/**/analogies/*"`. Every `~/MindrianRooms` room would hard-fail if the check were followed literally. It should use `scripts/resolve-room` like `/mos:eureka` does (SEED-034 "ONE door").

### 12. Eureka `status` race after `start`

Immediately after `start` printed "scan started (background)", two consecutive `status` calls (5s apart) returned `{"state":"none"}` before `running` appeared. `status.json` should be written synchronously, before `start` returns, or the skill's 3-poll budget gets wasted on a false "no scan has run".

### 13. `/mos:rooms list` counting and path shape

- Parent `israel-frontier-criticality` counts 158 entries, which includes the 55 in its sub-room (recursive `find`). Sub-rooms should be excluded from the parent's count (stop at a nested `.room-root`).
- Registry `path` for the sub-room is relative (`israel-frontier-criticality/translational-capital-lab`) while every other entry is absolute. Consumers that don't join with ROOMS_HOME will break (see #6).

### 14. Registry stage drift

The registry showed `Pre-Opportunity`, but STATE.md showed `Investment`. Nothing syncs them, so I updated the registry by hand. Given #5, the STATE value is itself wrong. The correct stage is closer to Pre-Opportunity. **Action for you:** the registry currently says `Investment` for `translational-capital-lab` (set by me during testing) and should be reverted.

### 15. Navigation engine calls populated rooms "cold / New room"

The UserPromptSubmit hook rendered, for rooms with 50 and ~100 entries:

```
▼ LOCAL translational-capital-lab (cold) / BRAIN (offline) / SIGNAL (none this turn)
New room - nothing to rank yet. Start anywhere.
```

It also logged `canon_part_2_attribution_breach: brain.author is not "brain"; weight demoted to 0.0` and `BRAIN.md absent` (Tier 0 fallback) on every turn.

### 16. Room-binding picker fires mid-task

After the active room had been switched explicitly (`set-active israel-frontier-criticality`), a later UserPromptSubmit hook emitted `session unbound: choose which room(s) this session writes to` with an 8-page room picker. The CLI registry active room and the MCP session binding are two separate notions of "current room", and they diverge.
