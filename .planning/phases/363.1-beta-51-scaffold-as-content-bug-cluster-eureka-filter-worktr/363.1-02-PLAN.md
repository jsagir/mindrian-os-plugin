<objective>
Remove the two defects in this phase that don't depend on the scaffold predicate. (1) The `isolation: worktree` declaration that hard-fails every `/mos:reason` dispatch outside git (D-08, P0). (2) The eureka `start`/`status` race that reports `none` right after a scan starts (D-09).

Purpose: rooms are not git repos by default (`git_enabled: false` on all 28 test rooms), so `framework-runner` with `isolation: worktree` fails with "Cannot create agent worktree: not in a git repository" for every user who has not run `/mos:rooms git-setup`. Disjointness is already enforced by contract, since each dispatch files into its own `target_section`. Separately, `cmdStart` returns before any status.json exists, which wastes the skill's 3-poll budget on a false "no scan has run".
Output: three agent files edited, `scripts/eureka-command.cjs` `cmdStart` fixed, and two regression tests.
</objective>
