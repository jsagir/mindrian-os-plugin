## Gap closure (2026-09-30)

Closes VERIFICATION GAP 1 (shipped reference doc ranks, B51-01 residual). Gaps 2 (advisory) and 3 (doctor render gate) are addressed below and in 363-18-SUMMARY.md.

### Root cause (trace confirmed)

The sub-room's `.mindrian/room.db` holds the row `id = references/SECTION-SCHEMA`, `type = Artifact`, `source_path = system:rs-engine`, props `{title: "Section Schema", section: "references"}`. In `structuralReason` (`lib/core/eureka/candidate-exclusion.cjs`), `scaffoldCandidates` skips the colon-bearing `source_path`, turns the id into `references/SECTION-SCHEMA.md`, and `isScaffoldBasename` asks `SCAFFOLD_BASENAMES`. That set was built from `SCAFFOLD_KIND_LIST` (seven per-section kinds only) at `lib/core/scaffold-predicate.cjs`, so `SECTION-SCHEMA.md` matched no rule and the node ranked as content. `references/ROOM.md` was already caught because ROOM is one of the seven; the two docs `REFERENCE_DOCS` ships (`SECTION-SCHEMA.md`, `SUB-SCHEMAS.md`) were the uncovered residue.

### Fix

`lib/core/scaffold-predicate.cjs` now consumes `room-skeleton-scaffold.cjs`'s frozen `REFERENCE_DOCS` export and adds those basenames to `SCAFFOLD_BASENAMES` (single source of truth, Canon Part 7; no name is copied, and a test asserts the predicate source contains neither name). No new module was needed: the marginal cost of requiring `room-skeleton-scaffold` after the predicate's existing requires is about 0.03 ms (its top-level requires are node built-ins plus gray-matter, already resident; its heavy requires are lazy inside functions), so the ~0.15 s predicate load cost is unchanged. A load failure degrades to "content wins" (no reference doc treated as scaffold), the same posture as the rest of the predicate.
