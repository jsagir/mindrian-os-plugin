<objective>
Pin the keying. Forward reach.reach_id from closeReach's reject branch into recordSelectorDecision as an OPTIONAL, enum-gated field on the f_selector_decision payload, AND pin the two-turn offer->close propagation so the rendered dial's reach_id survives the turn boundary. This is SC-02 / Priority 1 of 158-RESEARCH: today the rejected dial reach object carries reach_id (dial-reach-orchestrator.cjs:229-237) but closeReach drops it, forwarding only reach.command + reach.framework. After this plan, a reject is keyed by reach_id end to end, so the downstream count-in-window (Plan 02/03) can read rejects per reach_id.

Purpose: every counter in this phase (reject count, presentation count, penalty, suppression, parole) keys by reach_id. Without this keying fix the rejection signal cannot be attributed to a reach. This plan PINS the propagation FIRST so the rest of the phase has a reliable signal.

Output: an optional reach_id enum on recordSelectorDecision, the forward in closeReach, the two-turn propagation pin in intent-classifier.cjs, and a deterministic keying test.
