<objective>
Measure the live state RECON-02's two cards must be authored against. This plan writes zero
graph data. It exists because 258-RESEARCH.md's F-12 amendment made a pre-flight mandatory:
the basis for both order-collision cards is a 2026-08-13 measurement, and a same-day 2026-08-20
Gate 0 diagnostic found `Red Teaming`, one of the claimants on node 24219, inside an
id-28000-29000 block of ~95 nodes whose `:Framework` label appears to have been stripped and
`:Archived` applied.

Why this matters more than a normal staleness check: the repo's existing guard convention (id
plus name double bind) defends against Memgraph internal-id reuse after deletion. It was never
designed to detect a LABEL change on a node whose id and name are both still correct. A card
written as a match on `(f:Framework {name:'Red Teaming'})` would return zero rows, and the
runbook idiom reads zero rows as a SAFE no-op. Here zero rows would mean "the card did nothing",
not "the card correctly declined to act". That is a false success, and it is the exact class the
standing WATCH memory tracks.

Two other gaps close here. F-4 records that `Generate Innovation Opportunities` has NO recorded
internal id, and D-08's card pattern requires an id plus name double guard, so its id must be
resolved by probe before card 2 can be authored. And RESEARCH.md assumption A2 guesses that
`payloads/graphragmeta-stamp-2026-08-19.cypher` has not yet been executed; one cheap read-tier
query settles it, and the answer changes the append semantics of plan 258-05's stamp file.

Output: one read-tier probe script and one numbered evidence file inside the payload directory,
authored BEFORE any card exists.
</objective>
