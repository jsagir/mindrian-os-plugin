## Semantic change to an EXISTING exported constant (state this everywhere it is described)

`CONNECT_PATH_BUDGET_MS` keeps its VALUE (15000) and its NAME, but its MEANING changes:

| | Before this plan | After this plan |
|---|---|---|
| Scope | Per heal CALL | Per PROCESS, across every connect-path heal call |
| Worst case before `initialize` | `4 x 15000 = 60000ms` (measured 60296ms) | `15000ms + poll overhead`, regardless of how many call sites exist |
| Enforcement point | A fresh `{ timeoutMs: CONNECT_PATH_BUDGET_MS }` literal at two sites | One deadline armed once, consulted via `connectPathRemainingMs()` |

Every doc comment that currently describes it as a flat per-call 15000ms number is now WRONG and is
in scope for Task 3. The hook path constant `DEFAULT_INSTALL_TIMEOUT_MS` (120000) is unchanged in
both value and meaning.

## The fix shape (reference sketch, not a literal transcription target)

Design against the real code. This sketch fixes the SHAPE and the identifiers so the executor does
not have to invent them:

```js
// lib/core/mcp-dep-heal.cjs, module scope, next to the two budget constants
const CONNECT_PATH_MIN_ATTEMPT_MS = 250;
let connectPathDeadlineAt = null;   // epoch ms; null = not armed yet

function beginConnectPathBudget(opts) {
  opts = opts || {};
  const budgetMs = (typeof opts.budgetMs === 'number' && isFinite(opts.budgetMs) && opts.budgetMs > 0)
    ? opts.budgetMs
    : CONNECT_PATH_BUDGET_MS;
  if (connectPathDeadlineAt === null || opts.force === true) {
    connectPathDeadlineAt = Date.now() + budgetMs;
  }
  return connectPathDeadlineAt;
}

function connectPathRemainingMs() {
  if (connectPathDeadlineAt === null) beginConnectPathBudget();
  return Math.max(0, connectPathDeadlineAt - Date.now());
}
```

Both heal functions then replace their fresh-budget literal with the same three-step pattern:

```js
// inside requireWithHeal's MODULE_NOT_FOUND branch, and inside ensureDepsPresent's missing branch
let installOpts;                      // undefined = hook-path DEFAULT_INSTALL_TIMEOUT_MS, unchanged
if (connectPath) {
  const remainingMs = connectPathRemainingMs();
  if (remainingMs < CONNECT_PATH_MIN_ATTEMPT_MS) {
    log('[mcp-dep-heal] connect-path budget spent (' + CONNECT_PATH_BUDGET_MS + 'ms process-wide, '
      + remainingMs + 'ms left); skipping the install for <what> and failing fast');
    // requireWithHeal:   throw err;                                  (the ORIGINAL MODULE_NOT_FOUND)
    // ensureDepsPresent: return { healed: false, ok: false, budgetExhausted: true };
  }
  installOpts = { timeoutMs: remainingMs };
}
const outcome = runGuardedInstall(dir, installOpts);
```

Why a module-scoped deadline rather than threading `timeoutMs: budgetFor()` from each call site (the
literal shape 266-REVIEW.md CR-01 sketched): the fourth call site in `bin/mindrian-mcp-server.cjs` is
NOT at module scope, it is inside the `createServer()` factory (line 153). A call-site-threaded
closure would have to be plumbed into that factory, and the SAME factory is re-invoked per session by
the flag-ON multi-session HTTP branch, where a stale `budgetFor()` returning 0 would silently fall
back to `DEFAULT_INSTALL_TIMEOUT_MS` (the `> 0` guard in `runGuardedInstall`) and restore a 120-second
block mid-session. A module-scoped deadline reaches the nested call with no plumbing, keeps the
arithmetic in ONE place with ONE test surface, and makes a later per-session `createServer()`
inherit the already-spent deadline, which is the correct behavior: a live process serving sessions
must never block a session on an npm install. `beginConnectPathBudget()` is still called explicitly
at each entry point so the process-start anchor is readable in the file that owns it.
