<objective>
Remove the malformed splice from the `room_state` tool description that ships to every host on
every surface.

`lib/mcp/tool-router.cjs:648` builds the description as `Check room health, state, and get
framework recommendations. ${compact.slice(0, 80)}`, where `compact` is the first 500 characters
of `references/personality/voice-dna.md` (`lib/mcp/larry-context.cjs:29`). That file opens with a
markdown H1, so the description a host actually receives is:

  Check room health, state, and get framework recommendations. # Voice DNA -- Larry's Voice &
  Tone\n\n*A demanding but warm professor who asks on

A raw `#` heading, a literal double newline, an unterminated `*` emphasis, and a sentence severed
mid-phrase at "asks on". This is the only tool doing this: `grep '\${compact' lib/mcp/
tool-router.cjs` returns line 648 and nothing else, so `larryContext.compact` exists to serve one
truncated 80-character slice.

The fix is removal, not a smarter slice. Two reasons. First, an arbitrary byte offset into a
prose file will never reliably land on a sentence boundary, so a "clean slice" version keeps the
same class of defect and only moves the cut. Second, the description without the splice measures
60 characters, below the D-03 120-character instruction floor that
`tests/test-234-tool-description-floor.cjs` already enforces on every tool. So the splice has to
be replaced by real prose, which is what a tool description is supposed to be anyway: per the
langtalks corpus grounding in `265-RESEARCH-mcp-layer-audit.md` section 3.2a, the description IS
the instruction channel, and 80 borrowed characters of persona prose teach a host nothing about
when to reach for this tool.

Purpose: this description is on the wire in every session on CLI, Desktop and Cowork. It is the
single most visible piece of sloppiness the plugin currently ships.
Output: a static instruction-shaped description, a dead code path removed at both ends, and a
wire test that pins the exact defect so it cannot come back.
</objective>
