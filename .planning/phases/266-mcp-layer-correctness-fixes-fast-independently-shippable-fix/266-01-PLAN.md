<objective>
Stop Claude Code from silently truncating this plugin's MCP `instructions` mid-sentence inside
the Canon Part 8 boundary paragraph, on every session, on every surface.

The defect is not truncation logic in this repo, because there is none. Claude Code has capped
MCP server `instructions` at 2048 bytes since 2.1.84. `lib/mcp/runtime-instructions.cjs` serves
2173. The HOST drops the last 125 bytes, cutting inside the word "artifacts", so the model gets
`Deliverables filed to rooms are clean artifa` and never gets `cts with placeholders, never
conversation banter. Heavy pipeline work belongs in Claude Code - say so when asked for it here.`
The only fix available to this repo is to serve less.

`lib/mcp/no-instructions.test.cjs` cannot catch this: it asserts the served string is
byte-identical to the vetted constant, a SERVER-boundary property. The cap is a HOST-boundary
property. The test passes while the truncation happens.

Purpose: the truncated sentence is the highest-stakes prose on the channel, the constitutional
Part 8 statement plus the surface-routing instruction that exists to give Desktop and Cowork the
hookless parity `runtime-instructions.cjs:2-9` was written to provide. Both land nowhere today.
Output: a trimmed constant under budget, a byte-cap assertion that bites, a frozen copy of the
Part 8 paragraph so trimming can never eat it, and the Phase 266 test aggregator.

NOT IN SCOPE for this phase (recorded, not forgotten): the `alwaysLoad` eager-load
reconsideration, missing `annotations` / `outputSchema` / `title`, the deprecated elicitation
`enumNames` shape, `mcp_tool` hook adoption, the doctor tool-count check, the retired-backend
names in the Brain tool descriptions, and counted-facts drift D-1 / D-2 / D-8. Phase 265's
`data/capability-ledger.json` does not exist on disk yet, so there is no ledger to file them
into. Detail per item: `265-RESEARCH-mcp-layer-audit.md`.
</objective>
