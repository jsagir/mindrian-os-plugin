<objective>
Make the MCP description guardrail's reported result honest.

`tests/test-234-tool-description-floor.cjs` prints "35 passed, 0 failed" over a surface that had
three description defects in it. The number is not a lie about its assertions; it is a lie by
omission about its scope. Its 35 assertions decompose as: 1 harness-honesty check, 1 catalog-size
check, 1 universal 120-character floor applied to all tools, and 32 prose-shape checks (starts
with a capital, ends with a period, within the length ceiling, no em-dash) applied to a
hand-maintained list of eight tool names at lines 67-76. 36 tools are registered. The other 28,
including `room_state` with its mid-word cut, were never prose-checked. A reader sees a green
suite and concludes the tool surface is verified.

This plan takes the locked scope's preferred option (a): expand the coverage to every registered
tool. That was a judgment call the audit could not make, so it was measured during planning
instead. A live wire probe on 2026-08-27 applied all four prose checks to all 36 tools and found
exactly four failures:

| Tool | Failure | Resolution |
|---|---|---|
| `room_state` | does not end with sentence punctuation | fixed by plan 266-02, which replaces the voice-dna splice |
| `room_state_bound` | does not end with sentence punctuation | benign: it ends `... multi-command tool.)` The period is there; the regex `/\.$/` is too literal. Relax the terminator, do not edit the prose. |
| `chain_run` | 1113 characters, over the 600 ceiling | the 600 ceiling was derived from an exemplar the test itself names at line 21 as "`chain_run` 552". That exemplar has doubled. Replace the ceiling with the platform's real 2048-BYTE cap. |
| `gate_answer` | 1152 characters, over the 600 ceiling | same resolution |

All 36 start with a capital. None carry an em-dash. All 36 clear the 120-character floor. So
expansion is a mechanical change to two comparisons and one loop, with zero editorial judgment
required about any tool's prose. Nothing in this plan rewrites a tool description.

Purpose: a false-coverage signal is worse than no test, because it actively discourages the next
audit. The durable fix is that the checked set is DERIVED from `tools/list`, so a tool registered
next month is covered without anyone remembering to add a row.
Output: universal coverage, a byte ceiling at the real host cap, a coverage line in the summary,
and the phase gate run clean without its wave-1 escape.
</objective>
