<objective>
Build the two pure local modules that Door 2 stands on: a snapshot store for the previous portfolio run, and a movement detector that diffs two stored runs by the composite rule.

Purpose: D-01 says each on-demand run is compared with the previous stored run. D-02 says the sensor only reads the stored diff. D-03 sets the rule: a band crossing, OR a tail entrant, OR a top-N reshuffle. D-07 leaves the storage format to the planner with one constraint: local only, inside the room, written through the governed path. This plan fixes the format and the rule in code, with tests, before any producer or sensor exists.
Output: portfolio-snapshot.cjs, portfolio-movement.cjs, the thresholds data file, three test files.

This plan does not depend on that runner. It defines the snapshot contract any producer must meet. Plan 314-02 handles the producer.

Constants to export: SCHEMA_VERSION 1, STORE_DIRNAME 'eureka-portfolio', LATEST_FILE 'latest.json', PREVIOUS_FILE 'previous.json', MOVEMENT_FILE 'movement.json', SEEN_FILE 'movement-seen.json', BANDS (the closed list: none, low, moderate, opportunity, high, breakthrough), MAX_PAIRS 20000, MAX_LABELS 200, MAX_LABEL_CHARS 80, SLUG_RE (a lower-case letter or digit first, then up to 63 lower-case letters, digits or hyphens), HANDLE_RE (1 to 128 characters from letters, digits, underscore, dot, colon, hyphen; room node ids such as entity:entity-extract:7d0acf8a must pass).

Snapshot schema (closed; any other key makes validateSnapshot return false): schema_version (1); ran_at (an ISO-8601 string); scope ('room' or 'subset'); encoder_kind ('live' or 'stub'); provenance (a flat object, at most 40 keys, key names matching a lower-case snake pattern, values only string, finite number, boolean or null); pairs (array of objects with exactly a, b, band, score, rank: a and b match HANDLE_RE, band is in BANDS, score is a finite number, rank is a positive integer); tail (object with exactly composition string, insufficient_structure boolean, suspect_noise boolean, items an array of objects with exactly id matching HANDLE_RE, at most 5000 items); labels (object mapping a handle to a string of at most 80 characters, at most 200 entries). Labels are the only place room text can appear. They stay in the local snapshot and are never copied into the movement envelope.

Envelope validation is owned by plan task 2 (portfolio-movement.cjs). To avoid a require cycle, writeMovement takes the validator by lazy require inside the function. If that require fails, writeMovement returns { ok: false } and writes nothing.

Function contracts: scopeDir(roomDir, scope) where scope is 'room' or a section slug; returns the directory path or null for an invalid slug. saveRun(roomDir, scope, snapshot): validate, mkdir recursive, if latest.json exists and parses as a valid snapshot then rename it to previous.json (rename over an existing previous.json is fine), write the new snapshot to a temp file in the same directory, rename it to latest.json. Return { ok, rotated, reason? }. It never throws. readLatest and readPrevious(roomDir, scope) return a validated snapshot or null. writeMovement(roomDir, envelope), readMovement(roomDir), clearMovement(roomDir) work on <roomDir>/.mindrian/eureka-portfolio/movement.json (one movement file for the whole room, not per scope; the envelope carries the scope enum). markSeen(roomDir, movementId) and isSeen(roomDir, movementId) use movement-seen.json holding { schema_version: 1, movement_id }. A movement id must match ^pm_[0-9a-f]{12}$ or markSeen refuses.

Per D-07 the store is JSON files written temp-then-rename, the same governed idiom as the other .mindrian side-channel files (atomicWriteJson in eureka-reach-runner.cjs). The sensor never writes here. Only the run command and the Desktop view write.

Then create data/eureka-portfolio-thresholds.json with exactly these keys: schema_version 1, calibrated false, top_n null, reshuffle_min_moved null, reshuffle_min_displacement null, calibration null. Then create lib/core/eureka/portfolio-movement.cjs.

Reuse, do not copy: require FIRING_BANDS from lib/core/sensors/sensor-eureka.cjs. The band list and the bands themselves (rs-differential-scorer bandFor) are not changed by this phase. Define BAND_ORDER locally as none, low, moderate, opportunity, high, breakthrough for comparison only.

Rule per D-03 (composite; any one is enough to surface):
1. band_cross: for each pair in the current run, find the same unordered pair in the previous run (key is the two handles sorted). Previous band defaults to 'none' when absent. Emit an event when the band differs AND either the new band or the old band is in FIRING_BANDS. Direction is 'up' when BAND_ORDER index rises, else 'down'. Fields: kind, a_handle, b_handle, from_band, to_band, direction. Pairs that vanished are ignored.
2. tail_enter: handles in current.tail.items absent from previous.tail.items. Fields: kind, handle. Skipped when the current tail verdict is insufficient_structure or suspect_noise (the classifier already refuses to dress up noise).
3. top_n_reshuffle: active only when thresholds.calibrated is true and top_n is an integer of 2 or more and both min values are positive integers (D-04: the numbers come from a real run in plan 314-07, never from a guess here). Take pairs with rank at most top_n from each run. entered is the count of current members absent from previous. left is the count of previous members absent from current. max_shift is the largest absolute rank difference among members present in both. Emit one event when entered plus left is at least reshuffle_min_moved OR max_shift is at least reshuffle_min_displacement. Fields: kind, top_n, entered, left, max_shift.

diffRuns(previous, current, thresholds) returns { comparable, reason, reshuffle_active, events, counts: { band_cross, tail_enter, top_n_reshuffle } }. Comparable needs both snapshots valid, equal scope, equal encoder_kind, equal schema_version. Never throw: wrap in try/catch and return comparable false with reason 'diff_error'.

buildMovementEnvelope(diff, current, now) returns null for no events. Else: schema_version 1, kind 'portfolio_movement', movement_id (the string 'pm_' plus the first 12 hex characters of sha256 over current.ran_at, scope and the sorted event keys, joined with a pipe), detected_at (ISO string from now), scope, encoder_kind, counts, events (first 3 after ordering). validateEnvelope is the closed-schema check (exact key sets per kind; handles must match the HANDLE_RE exported by portfolio-snapshot.cjs, so require it from there). Put the entered, left and max_shift arithmetic in one exported function topNMetrics(previous, current, n) and call it from diffRuns. Export loadThresholds(pathOverride), diffRuns, topNMetrics, buildMovementEnvelope, validateEnvelope, BAND_ORDER, MAX_EVENTS 3.
