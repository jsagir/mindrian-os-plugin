Interface contract (build to this; do not rename):

resolveEngine(env) takes an environment object (default process.env). It returns an object with: state (absent, present or broken), source (env, pointer, default or null), root (an absolute path string or null), cause (null or one of the names below), reason (engine_not_configured, engine_checkout_unavailable or null). Rules, in order:
1. env.MINDRIAN_EUREKA_ROOT, when it is a non-empty string, is the root with source env.
2. Else the saved setting file at HOME/.mindrian/eureka-engine.json (JSON: schema 1, root, set_at, source adopted). HOME is env.HOME, else env.USERPROFILE, read from the object passed in. When the object holds neither, skip rules 2 and 3 (this keeps tests with a synthetic environment off the real home). A file that exists but cannot be parsed or has no root string gives state broken, cause pointer_unreadable, reason engine_checkout_unavailable.
3. Else the default folder HOME/.mindrian/eureka-engine when it exists, with source default.
4. Else state absent, cause null, reason engine_not_configured.
With a root found: the folder must exist (else broken, cause checkout_missing) and hold pyproject.toml (else broken, cause pyproject_missing); both give reason engine_checkout_unavailable. Otherwise state present, reason null. This is the same two-step check the 4 existing call sites do today (root set, pyproject.toml exists). Do not add a project name check or a spawn here: the per-call gate stays cheap, and existing tests use a fixture engine named fake.

describeEngineState(input) takes an object with state and cause. It returns { state, cause, sentence, fix }. The sentence is fixed text, one per cause, and must not hold an absolute path or any engine output:
- absent (cause null): "The Eureka engine is not set up on this machine."
- checkout_missing: "The saved Eureka engine folder is missing."
- pyproject_missing: "The Eureka engine folder has no pyproject.toml, so it is not an engine checkout."
- pointer_unreadable: "The saved Eureka engine setting cannot be read."
- project_name_mismatch: "The folder is not the Mindrian Eureka engine. Its project name is not mindrian-eureka."
- uv_missing: "The tool uv is not installed or is not on the PATH, so the engine cannot start."
- python_missing: "No Python that meets the engine requirement was found."
- env_not_synced: "The engine folder has no prepared environment yet."
- engine_start_failed: "The engine did not start."
- present (cause null): "The Eureka engine is set up."
The fix is one line: for absent, checkout_missing, pyproject_missing, pointer_unreadable and project_name_mismatch it is "/mos:eureka enable engine --path <folder>"; for uv_missing it is "Install uv (https://docs.astral.sh/uv/getting-started/installation/), then run /mos:eureka enable engine --check"; for python_missing it is "Install a Python that meets the requirement, then run /mos:eureka enable engine --check"; for env_not_synced it is "/mos:eureka enable engine --sync"; for engine_start_failed it is "/mos:eureka enable engine --check"; for present it is an empty string.

enginePointerPath(env), readPointer(env), writePointer(root, env), clearPointer(env): path of the setting file; read result { ok, root } or { ok: false, error }; atomic write with mode 0600 (write a temp file in the same folder, then rename) returning { ok, path }; remove returning { ok, removed }. The setting file holds a path and a time only, never room text.

lib/core/eureka/eureka-engine-enable.cjs exports run(argv, deps), main(argv), checkEngine(root, deps), runEngineSync(root, opts, deps). deps holds env, spawnSync, now and is used only by tests. run returns { exitCode, stdout, stderr }. main prints them and sets process.exitCode. Flags: --check (the default), --path DIR, --forget, --sync, --encoder, --approved-via cli|gate, --json, --help.
- checkEngine(root, deps) returns { ok, cause, checks: [ { id, ok, detail } ] } with ids checkout, project_name, uv, python, env_prepared. It reads pyproject.toml with plain string matching (no TOML library): the name line and the requires-python line of the [project] section. project_name must equal mindrian-eureka. It spawns only two commands: the uv command with --version, and the uv command with python find --no-project and the requires-python value. The uv command is env.MINDRIAN_EUREKA_UV when set, else uv. It never spawns the engine and never uses the network. env_prepared is true when root/.venv/pyvenv.cfg exists; a false value is a hint, not a failure.
- --path DIR: DIR must be an absolute path, hold no NUL character, resolve to an existing folder, and pass the checkout and project_name checks. If it fails those, write nothing and exit 1 with the 3-line error (x what failed / Why: sentence / Fix: line). If it passes, save the pointer, then run the uv and python checks and print the report. A miss on uv or python still leaves the pointer saved and exits 1 with the sentence for the cause.
- --check: resolve, then run checkEngine on the root when there is one, and print the state, source and each check. Exit 0 for every state (a report is not a failure).
- --forget: remove the setting file; idempotent; exit 0.
- --sync: needs a present engine root. Without --approved-via it prints one JSON object { kind: "engine_sync_grant", hosts: ["pypi.org", "files.pythonhosted.org", "download.pytorch.org"], command: [the argv it would run], size_note, offline_after: true } and exits 2 with nothing run. With --approved-via cli or gate it runs runEngineSync: spawn the uv command with sync, --locked and --extra mcp-server (add --extra modern-encoder with --encoder), shell false, cwd the engine root, a timeout of 20 minutes, stdout and stderr captured and capped at 500 characters. The child environment is an allowlist: HOME, USERPROFILE, PATH, SHELL, TERM, USER, LANG, LC_ALL, TMPDIR, TEMP, TMP, UV_CACHE_DIR, HTTP_PROXY, HTTPS_PROXY, NO_PROXY, http_proxy, https_proxy, no_proxy, SSL_CERT_FILE. No variable that starts with CLAUDE_ or MINDRIAN_ goes to the child. Report ok from a fresh probe of root/.venv/pyvenv.cfg, not from the exit code alone (the same rule as eureka-enable.cjs).

Reuse (Part 7): copy the home resolution chain from lib/core/eureka-deps-resolver.cjs (HOME, USERPROFILE, os.homedir()) and the temp-then-rename write from lib/core/research-planner/planner.cjs atomicWriteJson (a private function there; copy the 6 lines and name the source in a comment). <threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| --path argument to filesystem and later to a spawn cwd | A person-supplied path selects the folder whose code the engine call will run. |
| saved setting file to every engine call | A tampered file would point calls at another folder. |
| uv sync child to the network | The one step that reaches package hosts. |
| child environment | Room and Brain variables must not reach the child. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-387-03-01 | T | --path value | mitigate | Require an absolute path, refuse a NUL character, resolve with path.resolve, require pyproject.toml with project name mindrian-eureka before saving, spawn with an argv array and shell false. Test arms E3 and E4. |
| T-387-03-02 | T | saved setting file | mitigate | Mode 0600, atomic write, parse errors give state broken (never a silent fallback), and the per-call gate re-checks the folder and pyproject.toml on every call. |
| T-387-03-03 | E | code in the adopted folder runs on engine calls | accept | The person chose the folder. The command shows the saved path, the doctor row (Plan 387-07) shows the path and source, and --forget removes it. The plugin creates no engine folder, so the default folder holds only what the person put there. |
| T-387-03-04 | I | environment leak to the sync child | mitigate | Allowlist environment. No CLAUDE_ or MINDRIAN_ variable reaches the child. Test arm E8. |
| T-387-03-05 | I | network egress | mitigate | Check, save and forget spawn only uv --version and uv python find. The sync needs --approved-via and prints a grant card first. Static arm E10 forbids http, https, net, dns and fetch in both modules. |
| T-387-03-06 | T | dependency drift during sync | mitigate | uv sync --locked uses the engine's own uv.lock and fails when the lock is stale. The plugin adds no package. |
| T-387-03-SC | T | uv sync installs Python packages on the person's machine | mitigate | The plugin installs nothing by itself: no package name is added to any manifest here, and no install runs in a test.
