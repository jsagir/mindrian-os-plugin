== lib/core/eureka/eureka-engine-resolver.cjs ==

resolveEngine(env) takes an environment object (default process.env). It returns { state (absent, present or broken), source (env, pointer, default or null), root (an absolute path or null), cause (null or a name below), reason (engine_not_configured, engine_checkout_unavailable or null) }. Rules, in order:
1. env.MINDRIAN_EUREKA_ROOT, when a non-empty string, is the root with source env.
2. Else the saved setting file HOME/.mindrian/eureka-engine.json (JSON: schema 1, root, set_at, source adopted). HOME is env.HOME, else env.USERPROFILE, read from the object passed in only. When the object holds neither, skip rules 2 and 3 (this keeps tests with a synthetic environment off the real home). A file that exists but cannot be parsed or has no root string gives broken, cause pointer_unreadable.
3. Else the default folder HOME/.mindrian/eureka-engine when it exists, source default.
4. Else state absent, cause null, reason engine_not_configured.
With a root found: the folder must exist (else broken, cause checkout_missing) and hold pyproject.toml (else broken, cause pyproject_missing). Otherwise state present, reason null. This is the same two-step check the existing call sites do. Add no project-name check, no spawn and no environment probe here: the per-call gate stays cheap and existing tests use a fixture engine named fake.

ENGINE_CAUSES is a frozen object of these names: checkout_missing, pyproject_missing, pointer_unreadable, project_name_mismatch, uv_missing, python_missing, env_not_synced, lock_stale, extra_missing, model_missing, node_missing, node_too_old, engine_start_failed.

reasonForCause(cause) returns the typed reason: checkout_missing, pyproject_missing, pointer_unreadable, project_name_mismatch give engine_checkout_unavailable; extra_missing gives engine_extra_missing; model_missing gives engine_model_missing; node_missing and node_too_old give engine_node_missing; uv_missing, python_missing, env_not_synced, lock_stale and engine_start_failed give engine_unavailable; null gives engine_not_configured. The 3 new reasons (engine_extra_missing, engine_model_missing, engine_node_missing) are the typed "needs an extra, a model or Node" states. They are route-level answers: the engine itself is present (engine_state present) and this route needs more.

describeEngineState({ state, cause, detail }) returns { state, cause, reason, sentence, fix }. Sentences are fixed ASCII text. They hold no absolute path and no engine output:
- absent: "The Eureka engine is not set up on this machine."
- present: "The Eureka engine is set up."
- checkout_missing: "The saved Eureka engine folder is missing."
- pyproject_missing: "The Eureka engine folder has no pyproject.toml, so it is not an engine checkout."
- pointer_unreadable: "The saved Eureka engine setting cannot be read."
- project_name_mismatch: "The folder is not the Mindrian Eureka engine. Its project name is not mindrian-eureka."
- uv_missing: "The tool uv is not installed or is not on the PATH, so the engine cannot start."
- python_missing: "No Python that meets the engine requirement was found."
- env_not_synced: "The engine folder has no prepared Python environment yet."
- lock_stale: "The engine uv.lock does not match its pyproject.toml, so the offline start was refused."
- extra_missing: "The engine package group NAMES is not installed." (NAMES is detail.extras joined by ", ")
- model_missing: "No local embedding model was found. The engine never downloads one."
- node_missing: "Node.js was not found on the PATH. Some Eureka workers need Node.js 22 or newer."
- node_too_old: "Node.js is older than version 22. Some Eureka workers need Node.js 22 or newer."
- engine_start_failed: "The engine did not start."
Fix lines: for absent, checkout_missing, pyproject_missing, pointer_unreadable and project_name_mismatch: "/mos:eureka enable engine --path <folder>". uv_missing: "Install uv (https://docs.astral.sh/uv/getting-started/installation/), then run /mos:eureka enable engine --check". python_missing: "Install a Python that meets the engine requirement, then run /mos:eureka enable engine --check". env_not_synced: "/mos:eureka enable engine --sync". lock_stale: "Update the engine checkout, then run /mos:eureka enable engine --sync". extra_missing: "/mos:eureka enable engine --sync --extras NAMES" (NAMES joined by a comma). model_missing: "Put a model folder on this machine and set MINDRIAN_EUREKA_RS_MODEL_PATH to it (the engine's docs/offline-install.md explains how), then run /mos:eureka enable engine --check". node_missing and node_too_old: "Install Node.js 22 or newer, then run /mos:eureka enable engine --check". engine_start_failed: "/mos:eureka enable engine --check --deep". present: an empty string.

enginePointerPath(env), readPointer(env), writePointer(root, env), clearPointer(env): the path of the setting file; { ok, root } or { ok: false, error }; an atomic write with mode 0600 returning { ok, path }; remove returning { ok, removed }. The file holds a path and a time only.

== lib/core/eureka/eureka-engine-requirements.cjs ==

EXTRA_MARKERS (frozen): mcp-server maps to ["mcp"]; modern-encoder to ["sentence_transformers"]; reference-encoder to ["torch", "transformers"]; hmm to ["pomegranate"]. These come from the engine's pyproject extras table (metadata). SYNC_EXTRAS_ALLOWED is those 4 names. The hub-gate and neo4j extras are never allowed.

needsForCall(toolName, args, env) returns { extras (array, always starts with mcp-server), model (yes, no or unknown), node (yes, no or unknown), evidence (an object with one label per cell: plugin-code, engine-read or audit-hypothesis) }. Initial table (the executor refines the model and node cells in Task 3 by reading the engine files named below, and relabels each refined cell engine-read):
- graph tools (eureka_graph_analyze, eureka_graph_propose_relationships, the 5 discovery-signal tools, eureka_graph_backtest, eureka_graph_compare_topics, eureka_graph_genesis_plan, eureka_graph_map_neighbourhoods, eureka_graph_package_relationships, eureka_graph_prepare_artifacts, eureka_graph_rank_paths, eureka_graph_score_surprise, eureka_hsi_interpret_whitespace): extras [mcp-server] (plugin-code: callEurekaWorkflow), model no (audit-hypothesis), node unknown (audit-hypothesis; the two audits disagree about Genesis; resolve it from the engine's workflow handler files and the packaged .js and .cjs data folders).
- eureka_graph_opportunity_scout: extras [mcp-server, the encoder extra] (plugin-code: callEurekaOpportunityScout), model yes, node unknown.
- eureka_capability_run and eureka_capability_start, by args.capability_id: decision.compare_sequence_patterns and decision.fit_sequence_patterns give [mcp-server, hmm] (plugin-code: clientOptions), model unknown; opportunity.find_cross_domain_pairs and opportunity.synthesize_discovery_signals give [mcp-server, the encoder extra], model yes; every other id gives [mcp-server], model unknown, node unknown.
- The encoder extra is reference-encoder when env.MINDRIAN_EUREKA_RS_ENCODER is reference-bert, else modern-encoder (plugin-code, same rule as clientOptions).
- Any other tool name: extras [mcp-server], model unknown, node unknown.

uvRunArgs(root, extras, opts) returns the argument array for the engine start. Default (opts.allowNetwork not true): ["run", "--no-sync", "--offline", "--locked", "--no-python-downloads", "--project", root, then "--extra", NAME for each extra in order, "eureka-mcp"]. With opts.allowNetwork true: ["run", "--locked", "--project", root, then the --extra pairs, "eureka-mcp"]. The flags are in the arguments because UV_OFFLINE is not in the child environment allowlist and a plain uv run syncs. opts.entry replaces the last element: its default is ["eureka-mcp"], and the only other allowed value is ["eureka", "doctor", "--json"] (the deep check of Plan 387-09); any other entry throws a TypeError. It throws a TypeError for an extra name outside SYNC_EXTRAS_ALLOWED.

uvSyncArgs(extras) returns ["sync", "--locked", "--no-python-downloads", then "--extra", NAME for each extra]. mcp-server comes first and once. It throws a TypeError for a name outside SYNC_EXTRAS_ALLOWED. This is the one network step (Plan 387-09 runs it only after a grant).

syncHosts(extras) returns { hosts, python_downloads, builds_from_source }: hosts are pypi.org and files.pythonhosted.org, plus download.pytorch.org when an encoder extra is present; python_downloads is the string off (github.com is not contacted); builds_from_source is ["pomegranate"] when hmm is present, else [].

engineWrites(env) returns the list of places that setup and runs write or read: the environment folder (UV_PROJECT_ENVIRONMENT, else root/.venv; written by sync), the data folder (MINDRIAN_EUREKA_DATA_DIR, else HOME/.local/share/mindrian-eureka; the engine writes jobs.sqlite3 there at every start), the cache folder (MINDRIAN_EUREKA_CACHE_DIR, else HOME/.cache/mindrian-eureka; embeddings.sqlite3), and the Hugging Face hub folder (read only). Each entry has kind, path and access.

extrasInstalled(root, env, deps) reads the environment folder (UV_PROJECT_ENVIRONMENT, relative to root when relative, else root/.venv). It finds site-packages (lib/python3.N/site-packages on POSIX, Lib/site-packages on Windows) and lists names. A package group counts as installed when every marker in EXTRA_MARKERS has a folder or a dist-info entry (names compared in lowercase with hyphens read as underscores). It returns { venv_present, located, installed: { NAME: true, false or null } } where null means the layout could not be read. It spawns nothing.

nodeStatus(env, deps) runs node --version (deps.spawnSync) and returns { ok, version, cause }: ok when the major version is 22 or more; cause node_missing when the command fails or prints nothing readable; cause node_too_old below 22.

modelHint(env) is advisory. It returns { found, via }: found true when any of MINDRIAN_EUREKA_RS_MODEL_PATH, MINDRIAN_EUREKA_HSI_MODEL_PATH, MINDRIAN_EUREKA_JASON_MODEL_PATH or MINDRIAN_EUREKA_ANALOGY_MODEL_PATH is an existing folder (via env-path), or the Hugging Face hub folder (HF_HUB_CACHE, else HUGGINGFACE_HUB_CACHE, else HF_HOME/hub, else HOME/.cache/huggingface/hub) holds an entry that starts with models-- (via hf-cache). The engine's own search may differ, so the hint never blocks a call.

checkEngine(root, deps) returns { ok (true, false or null), cause, checks, families }. checks is a list of { id, ok, detail } with ids checkout, project_name, uv, python, node, extras, model, env_prepared. It reads pyproject.toml with plain string matching (the name line and the requires-python line of the [project] section; no TOML library). The only commands it spawns are: the uv command with --version; the uv command with python find --no-project and the requires-python value; node --version. The uv command is env.MINDRIAN_EUREKA_UV when set, else uv. ok is true when checkout, project_name, uv, python, a prepared environment and the mcp-server group all pass (core ready); false with the first failing cause otherwise; null when the environment exists but its layout could not be read (extras not verified). Node, model and the other groups never change ok. families is a list of { family, status, needs, cause } for graph (needs mcp-server), pairs-and-scout (needs the encoder group, a model), decision (needs hmm) and node-workers (needs Node.js 22 or newer). status is ready, needs_extra, needs_model, needs_node, not_ready or unknown. A family with the group missing is needs_extra with cause extra_missing; a family that needs a model with no model hint is ready for the packages but carries model_hint false. It never reads ok from .venv/pyvenv.cfg.

classifyEngineText(text) returns { cause, extras } or null. Patterns (case-insensitive): the engine text Install the optional extra: pip install 'mindrian-eureka[NAME]' gives extra_missing with extras [NAME]; No module named 'mcp', 'sentence_transformers', 'pomegranate', 'torch' or 'transformers' gives extra_missing with the matching group; No local model found, local_model_unavailable and A local sentence-transformer model is required give model_missing; Node.js 22 or newer gives node_too_old (node_missing when the text says not found); No interpreter found and requires-python give python_missing; a lockfile or uv.lock that needs to be updated gives lock_stale; uv ENOENT, uv: command not found and uv was not found give uv_missing; No virtual environment found gives env_not_synced; anything else gives null.

startLine(text, ctx) returns the first non-empty line of text with these changes: ctx.root replaced by <MINDRIAN_EUREKA_ROOT>, ctx.home replaced by ~, control characters removed, non-ASCII characters replaced by ?, length cut to 160 characters. It returns an empty string when there is no text. It is used only for the start-up text of the engine process, before the process has received any request.
