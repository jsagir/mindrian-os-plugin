# Phase 387 - Eureka reachable on a normal install (PRD)

**Source:** `.planning/audits/AUDITOR-FINDINGS-source.md` (Eureka gap, D6 and B) and the owner statement that Eureka is critical (its unique edge: cross-domain opportunities, analogies and whitespace mapping across local and remote graphs). Auditor claims are hypotheses until checked.
canon_parts: 7, 8, 9, 11
Depends on: Phase 386 (Part 8 first). Independent of measurements.

## Problem (to verify, not assume)

- Auditor: on a normal install 1 of 23 Eureka tools works. Nothing in the plugin sets the engine path (`MINDRIAN_EUREKA_ROOT`), the engine needs `uv` and Python, and only advanced docs mention it. Tool count differs between reports (23 and 24): settle it with the runtime `tools/list`.
- The README now says Eureka needs an optional external engine configured. This phase makes that path real for a normal user.

## Scope

1. Reproduce on a fresh install layout (installed-layout test, not the dev tree): which Eureka tools answer, which refuse, and the exact refusal text. Pin the baseline to `MINDRIAN_EUREKA_ROOT` unset and with no Eureka checkout present or discoverable by the fixture. Do not inherit the maintainer's Eureka path or checkout. Record distinct names from runtime `tools/list` and each tool's result under that exact condition. Use a scratch HOME and a synthetic bound-room fixture for room-dependent calls (also record their unbound result), so a missing room does not masquerade as a missing engine. Test configured-engine states separately.
2. Decide the supported install path for the engine: a documented `/mos:eureka enable` flow that finds or installs the engine, sets the path through a supported config (not a hand-edited env var), and checks `uv` and Python with an honest message when missing. Reuse what exists (`commands/eureka.md`, `lib/mcp/tools/eureka-*.cjs`, doctor smoke). Reuse before build (Part 7).
3. Honest states on every surface (CLI, Desktop, Cowork): engine absent, engine present, engine broken. Never fake a result.
4. Part 8: Eureka reads graphs through the local room projection only; no room text goes to the Brain or to any outside service. Verify with the egress suites.
5. Doctor point that reports Eureka readiness.
6. Owner forks come as gate cards: where the engine lives, whether the plugin may download it, and the network and licence terms.

## Rules

RCA/reproduction first, failing test first, fixture rooms only, no push/tag/release, `git commit --only`.
