Interface contract (build to this):

In lib/mcp/eureka-tool-contract.cjs add and export:
- ENGINE_FREE_TOOLS: a frozen Set of tool names that never need the engine and that the gate skips. Start from one name: eureka_graph_project. Compare with the RCA list of tools that answered without an engine. If the RCA lists another registered tool, add it and say so in the SUMMARY.
- JOB_LIFECYCLE_TOOLS: a frozen Set of eureka_capability_job_status, eureka_capability_job_result and eureka_capability_job_cancel. They need an engine-started job, so they count among the 22 engine tools, but the gate skips them: they answer from the in-process session table and add the engine state to their not-found answer (see Task 3).
- ENGINE_REQUIREMENT: the string "Requires the Eureka engine (set up with /mos:eureka enable engine) and uv."
- typedRefusal(cause, detail): the one builder of a typed refusal. It returns { ok: false, reason (reasonForCause of the resolver), engine_state, cause, route_state, needs, message, fix }. engine_state is absent for a null cause, present for extra_missing, model_missing, node_missing and node_too_old (the engine exists; this route needs more), and broken for every other cause. route_state is needs_extra, needs_model or needs_node for those 3 groups and is left out otherwise. needs is detail.extras for extra_missing and is left out otherwise. message is the describeEngineState sentence, then one space, then "The default /mos:eureka run needs no engine." fix is the describeEngineState fix. Plan 387-11 uses this builder for the route-level causes.
- engineRefusal(env): resolve with resolveEngine(env). Return null when state is present. Otherwise return typedRefusal(cause) for the resolver cause (null cause for absent). The reason is engine_not_configured or engine_checkout_unavailable.
- engineRootOrRefusal(env): return { ok: true, root } when present, else the refusal object. This is the one replacement for the 4 inline root checks.
- classifyEngineStartError(error): return { cause: "uv_missing" } when error.code is ENOENT or the message holds ENOENT, else { cause: "engine_start_failed" }. Use the real text that the RCA recorded for scenarios S4 and S5 to decide the match. Plan 387-11 refines this with the start-up stderr line; here only the ENOENT rule is built. A start failure that is not ENOENT answers typedRefusal("engine_start_failed"), whose fix is "/mos:eureka enable engine --check --deep".
- Inside registerEurekaTool: when the tool name is in neither ENGINE_FREE_TOOLS nor JOB_LIFECYCLE_TOOLS, wrap the handler. The wrapper calls engineRefusal(process.env) first and returns response(refusal, true) when it is not null. The handler body never runs in that case, so the room projection never opens. Add engine_state, cause and fix to the textSummary key list and to outputSchema as optional fields (engine_state is an enum of absent, present, broken; cause and fix are strings).

Keep: every existing reason code, every existing field, the order of checks inside each function (root check, then request check), and the text of messages that are not about the engine root.

| saved setting file to the gate | The gate trusts the resolver's answer on every call. |
