<objective>
Verify Part 8 for Eureka, and close the two gaps the engine audits found. Part 8 says room text never goes to the Brain or to any outside service. For Eureka that means: the engine only sees the local room projection, and the engine process cannot reach the network or install anything by default.

The gaps: (1) the plugin starts the engine with a plain uv run on every path. A plain uv run syncs the environment, so a missing package group can make uv install packages and reach a package index at call time, and UV_OFFLINE is not in the child environment allowlist, so setting it in the parent does not pass through. Only callEurekaWorkflow forces the offline variables. (2) The generic capability call, the async job start and the opportunity scout get a normal environment. The docs even say the scout "may install that package extra" on first call. Under the owner decision (option A, network_terms: sync-on-grant-then-offline), the only network step is the grant-gated uv sync, and every run is offline and does not sync.

Purpose: scope item 4 of the PRD, verified with a fake engine so the plugin side is proven without running the real engine. The real engine side (zero connect calls, files changed only in its data and cache folders, a planted marker in no output) is the owner-run test of Plan 387-10.
Output: a fake engine fixture, an egress test written first, the safety flags in the uv arguments of all four paths through the one builder, the runtime allowlist decision, and the updated Phase 341 tripwire.
</objective>
