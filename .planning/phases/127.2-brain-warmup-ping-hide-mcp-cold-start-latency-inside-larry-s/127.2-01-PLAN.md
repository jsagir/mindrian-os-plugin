### Task 2: Build `lib/core/brain-warmup.cjs`

1. Export `WARMUP_SENTINEL = 'warmup'` constant (immutable).
2. Export `isEnabled()` -- reads `process.env.MINDRIAN_WARMUP_PING` (default `true`; honors `false` / `0` / `no` for kill-switch).
3. Export async `fireWarmup()`:
   - Early-return if `!isEnabled()`.
   - Call `require('./brain-client.cjs').brain_ask({ query: WARMUP_SENTINEL })` wrapped in try/catch.
   - On success: emit memory_event with `warmup: true` flag (coordinate exact event_type with Phase 121 -- candidate: `brain_warmup_succeeded`).
   - On failure (network error, timeout, auth fail, anything): swallow the error silently. Optionally emit a `brain_warmup_failed` event for `/mos:doctor --verbose` debugging.
4. Part 8 invariant: the payload assembly NEVER reads room state, USER.md, artifact bytes, or any local-content source. Hardcoded sentinel only.

### Task 3: Per-surface integration (CLI / Desktop / Cowork)

Per Tri-Polar design rule (CLAUDE.md): all three surfaces must show the same warmup-success behavior OR document explicitly which surface a variant does NOT cover.

- **CLI:** integrate via the anchor chosen in Task 1.
- **Desktop:** Desktop spawns the MindrianOS MCP server as a child process via `claude_desktop_config.json`. The MCP server's startup path can call `fireWarmup()` directly (with a small delay to let the Desktop UI render). Document the integration point in `bin/mindrian-mcp-server.cjs`.
- **Cowork:** Cowork sessions have shared-room lifecycle; warmup should fire once per session, not per room access. Document the integration point and any per-room considerations.
