<objective>
Close the live Canon Part 8 breach. Today `query()` makes ZERO guard calls, and two production
paths push user-typed content through it: `hatAwareRecommend()` interpolates Blue Hat
`methodology_notes` into Cypher, and `suggestValidationSteps()` interpolates an opportunity's
`domain` field, reached in production from `lib/core/opportunity-ops.cjs:1359`. Canon Part 8's
own text (docs/MINDRIAN-CANON.md) defines a breach as any code path that "queries the Brain with
a payload containing user-specific strings". That is exactly what these two do.

Purpose: the classifier is healthy and correct; the path to it was never wired. And the OBVIOUS
fix does not work, measured twice in this worktree:

  1. TEMPLATE LAUNDERING. `part8-egress-guard.cjs`'s `METHODOLOGY_VOCAB` includes `framework`,
     and every production Cypher template contains `(f:Framework)`. Measured:
     `classify({cypher:"CANARY7F3A2B"})` returns `ambiguous / freeform_unmatched`, but
     `classify({cypher:'MATCH (f:Framework) WHERE x="CANARY7F3A2B"'})` returns `allow / move_set`.
     The template's own vocabulary satisfies the positive recognizer and the user payload rides
     along.
  2. SANITIZER DISARMS DETECTOR. `sanitizeCypherInput` is a Cypher-injection sanitizer,
     `value.replace(/[^a-zA-Z0-9 ._-]/g, '')`, which strips `@`. Measured: raw
     `jane@startup.com` inside the template classifies `block`; sanitized `janestartup.com`
     classifies `allow`. One security control silently disarms another.

Therefore the guard must run on RAW FIELDS, before sanitization and before interpolation. A
`query()`-level belt is a necessary backstop but is provably insufficient on its own.

Output: raw-field classify-first guards at both doors, a `query()` backstop, and
`tests/test-239-query-egress-canary.cjs` proving all of it against a captured mock transport.
