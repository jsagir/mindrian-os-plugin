## Canon traceability

**Canon Part 7 (Reuse Before Build).** The justification bar for net-new capability is met explicitly. Plan 94.1-01 ships a 10-step orchestrator that wraps 4 already-shipped scripts (`scripts/migrate-lazygraph.cjs` Step 4 / `scripts/vault-section-state-generator.cjs` Step 6 / `scripts/vault-section-minto-generator.cjs` Step 7 / `scripts/compute-state` Step 9) and adds 6 inline file operations (Steps 1, 2, 3, 5, 8, 10). The only net-new surface is the orchestration loop and the heal-log envelope. Zero new methodology; zero new dependencies; zero new scripts beyond the orchestrator itself. The 4 wrapped scripts cover the heavy operations (graph rebuild, section-state generation, MINTO regeneration, root STATE.md compute); heal composes them.

**Canon Part 4 (Every Choice Is Graph Data).** Every step records {status, duration_ms, details}. The aggregated heal-log.json envelope is the local artifact capturing the full cascade: which sections were touched, which sections backfilled vs already-present, which MINTO writes succeeded vs blocked vs errored, queue depth + age, root STATE.md byte count. The user can read the envelope post-heal to understand exactly what changed. The envelope is forward-additive (schema_version: '1.0'); future heal versions may add fields without breaking readers. Decision-trace consumers (e.g. /mos:explain-decision) can ingest the heal-log as a typed local edge in the room's decision history.

**Canon Part 8 (Graph Boundary).** Heal operates LOCAL-only. Reads STATE.md / ROOM.md / MINTO.md / per-section artifacts / .mindrian/brain-derivation-queue.json / .mindrian/invariant-report.json. Runs the local SQLite graph rebuild via scripts/migrate-lazygraph.cjs. Writes the local heal-log to .mindrian/heal-log.json. ZERO Brain queries. ZERO user-content egress. The brain-derivation-queue is read in Step 8 to report depth + age but NEVER drained inside heal; the drain hook is the v1.12 candidate (BUG-2 in deferred-items.md). The user's data stays in the user's room.

Implementation: when at least one section succeeded AND at least one section blocked, the per-step roll-up is `ok_with_blocked` (not just `ok`) so the user can see at the step level that something graceful-degraded. The summary classifier in runHeal counts `ok_with_blocked` as `ok_count` (the step did useful work) but the per-section detail array still records `blocked_feynminto_01` for the affected section. Caught during Task 2 GREEN test design; the T2 fixture initially asserted `status === 'ok'` and broke when one section blocked; the fix was to widen the assertion to `status === 'ok' || status === 'ok_with_blocked'` and to add the roll-up classifier in the orchestrator. Files modified: scripts/heal-command.cjs (step07SectionMinto rollUp logic), lib/memory/heal-command.test.cjs (T2 status assertion). Found during: Task 2 fixture suite run.

2. **[Rule 2 - Missing critical functionality] Step 10 records `details.note` explaining the passive nature.** Plan said Step 10 is on-stop invariant scan, passive. Implementation: when invariant-report.json does not exist yet, Step 10 returns status='skipped' with `details.reason: 'no_report_yet'` AND `details.note: 'Report writes on next /mos:* command via on-stop hook'`. Reason: without the note, users running heal on a brand-new room would see step_10 as 'skipped' and infer something failed. The note makes the passive contract explicit. Found during: end-to-end smoke (Task 5) verification.

3. **[Rule 3 - Scope decision] commands/heal.md Body Shape E table uses ASCII glyph names ([check], [warn], [dot], [x]) not literal Unicode.** The skills/ui-system/SKILL.md Section 3 vocabulary uses named glyphs (checkmark, warning, dot, x). The slash command body documents the mapping in prose but uses bracket-name placeholders for the renderer to fill in. Reason: the 4-zone output is rendered by the slash command interpreter (Claude); the bracket-name markers signal which glyph from the vocabulary to use without committing the markdown source to a specific Unicode codepoint. Future renderers can map the bracket name to the canonical glyph from `skills/ui-system/SKILL.md` Section 3. Found during: Task 3 commands/heal.md authoring.
