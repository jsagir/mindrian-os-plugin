**Why CR-01 is its own plan:** the fix in 231-01 was written by the debug session; CR-01 was found AFTERWARD by an independent `/gsd-code-review 231 --depth=deep` pass (231-REVIEW.md, 1 critical) and applied in a separate direct-edit pass. Keeping it in its own wave preserves the review trail: original fix -> adversarial review -> reviewed fix -> human gate -> commit.

**CR-01 in one breath (D-04):** tier-2a classifies each unique name ONCE globally, but tier-2b escalates PER ARTIFACT over a separate network call each time. An ordinary transient failure on one of two calls for the same name leaves two `entities` entries disagreeing on `evidenceTier`; both write to the SAME node id (minted from name alone) and `node-insert.cjs`'s ON CONFLICT is a full overwrite - so whichever wrote LAST won, silently flipping a trusted entity to excluded (or laundering junk to trusted) based on filesystem read order, without touching `review_status`, so nothing signaled the flip. The fix normalizes every same-name entry to the single highest-trust verdict via a reduce (never last-write-wins), in place (no entry removal, so every DESCRIBES edge survives). A bug in the fix itself was caught during testing: `Map.get()` returns `undefined` both for absent keys and for present-with-undefined values (a trusted entity's tier is legitimately unset), so presence is tracked with `Map.has()` and the stored value is normalized to the literal string `'None'`.

**This remains a verify-not-build plan** (see 231-01 objective for the process note). If a source assertion fails, STOP and report drift; do not silently re-implement.

Purpose: close the last correctness gap the review found, prove the whole set green, honor the RCA's "do NOT commit until human confirms" gate, and land the commit with a proper trail.
