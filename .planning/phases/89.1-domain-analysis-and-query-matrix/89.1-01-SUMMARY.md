## Decisions Made

Locked decision per plan frontmatter: **Option 1 (shape adapter inside pullFromBrain)**.

Rationale (verified by reading code, NOT speculation):
- `mcp-server-brain/test-brain.cjs` line 133 confirms 5-tool MCP surface: `[brain_query, brain_schema, brain_search, brain_stats, brain_write]`. No vector tool.
- `mcp-server-brain/lib/pinecone-tools.cjs` line 47: `const results = await index.searchRecords(searchParams)`. Pinecone integrated-inference `searchRecords` does NOT return embedding vectors. The error message at lines 53-58 explicitly directs to `brain_query` with an external vector for include_values flow -- there is NO MCP path that surfaces 1024-dim vectors today.
- Option 2 (new `brain-client.searchWithVectors` + `brain_search_vectors` MCP tool) would require expanding the MCP server tool surface, deployable outside this repo. Option 1 is the only viable path within Phase 89.1 boundaries.

Adapter consequence: substrate entries on the live wire path carry `score` (Pinecone hit `_score` in [0, 1]) instead of a 1024-dim embedding. Validator Check E relaxed in lockstep. Downstream RS engines use score directly (lossy vs cosine over local vectors but functionally sufficient for ranking). Strict cosine path filed as 89.2/89.5 follow-up.
