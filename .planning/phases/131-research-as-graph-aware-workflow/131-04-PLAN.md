<objective>
Build the Stage 6 F.1 filing selector and the Stage 7 findings-wirer. The selector mirrors
the shipped `lib/hmi/selector-dispatcher.cjs` F.1 sub-shape (it is NOT a bespoke research
selector) with computed candidate target sections (% match) per finding -- the LOCKED
forward contract that makes Phase 136's richer gate widget a strict superset. The wirer
turns each gate decision into typed graph data through navigation.cjs:
- ACCEPT -> writeEvidenceClaim (proposed) + INFORMS edge (+ CONTRADICTS / SUPERSEDES when applicable) + research_filed event
- REJECT -> REJECTED_BECAUSE edge with the captured reason + research_rejected event
- DEFER  -> research_deferred event queued to milestone audit

EDGE-TARGET SCOPING (the design clarification -- read carefully):
Cascade edges come in two flavours by target, and they resolve DIFFERENTLY:
- LOCAL target (a room section or a local claim node): the edge target is the LOCAL room.db
  node id, resolved via navigation.cjs. It is NOT a correlation_id. MOST of 131's
  INFORMS / CONTRADICTS / SUPERSEDES edges are local-to-local (an EvidenceClaim INFORMS a
  room section; a finding CONTRADICTS an existing local claim) and stay local-node-id.
- TEACHING-GRAPH target (a framework / concept in the teaching graph): the edge target
  resolves to a canonical correlation_id, so the edge does not fork across cross-label
  duplicates (the directive-3 / curation-audit concern). This is the ONLY case that touches
  the correlation_id path.

RE-BASELINE HARD CONSTRAINTS:
- The teaching-graph resolver is built CONSUMER-SIDE from Phase 130.7's REAL exports. 130.7
  ships ONLY computeCorrelationId(canonicalName, primaryLabel) (pure 2-arg hash) +
  parseLabelIndex / the correlation_labels index + CORRELATION_VERSION. There is NO
  correlation.resolve and NO tuple-returning resolver in 130.7. This plan builds the
  resolver (lib/lens-engine/correlation-resolver.cjs) by composing those two REAL exports.
- The F.1 selector mirrors selector-dispatcher (gate-as-write-node forward contract for 136).
- EvidenceClaim node schema + the four cascade predicates are the LOCKED Phase 136 contracts.

Output: correlation-resolver.cjs + research-filing-selector.cjs + findings-wirer.cjs + the
suite (already registered in run-all-131.sh by Plan 01; this plan only CREATES the suite file).
