# Phase 150.8 Plan 01: Typed-Claim DIKW Substrate Summary

Mint the net-new `claim`-type truth-claim writer the entire DIKW ladder stands on: `writeClaimNode` with the frozen 6-member `knowledge_type` enum and the `conditions`/`counter_conditions`/`valid_from`/`valid_until` additive JSON temporal properties, plus the GATE-0 segment-authority seam that formalizes extraction (not the file-level cascade) as the per-segment claim minter, all gated by the one-command `tests/run-all-150.8.sh` phase gate.

## Per-Task Changes

### Task 1: writeClaimNode truth-claim writer + closed-surface re-export (DIKW-01, DIKW-03)

- **`lib/core/navigation/typed-claim.cjs`** (NEW, ~150 lines): mirrors `evidence-claim.cjs` / `memory-artifacts.cjs writeDecisionNode` verbatim in shape.
  - `KNOWLEDGE_TYPES = Object.freeze(new Set(['fact','causal','heuristic','anomaly_cue','mental_model','assumption']))` -- the closed 6-member enum.
  - `writeClaimNode(db, params)`: `isPlainObject` guard first (`invalid_params`); validates `knowledge_type` is in the frozen Set (`invalid_knowledge_type` with `String(...).slice(0,40)` detail); validates `text` is a non-empty string (`invalid_text`). Builds `props` as additive JSON keys only (`knowledge_type`, `conditions`/`counter_conditions`/`valid_from`/`valid_until` defaulting to `''`, `source_speaker`/`source_segment`, optional `disambiguation` only when a non-empty string). `JSON.stringify` inside try/catch (`properties_serialize_failed`). Mints node id via `CLAIM_NODE_ID(sessionId, segmentKey)` (the 31-multiplier hash loop; `segmentKey = sourceSegment || text`). INSERT with `type='claim'`, `created_by='system'`, `confidence=1.0`, `review_status='proposed'`, `ON CONFLICT(id) DO UPDATE SET properties = excluded.properties, last_seen_at = excluded.last_seen_at` -- the DO UPDATE EXCLUDES `review_status` (no-downgrade, copied verbatim from `writeDecisionNode`). Write wrapped in try/catch (`claim_write_failed` with `.slice(0,80)`). Returns `{ ok:true, node_id, knowledge_type }`.
  - Caller-owned db handle: NEVER requires `node:sqlite` or `room-db.cjs` (substrate guard clean, exit 0).
- **`lib/core/navigation.cjs`** (MODIFIED): added `const typedClaim = require('./navigation/typed-claim.cjs')` and an additive re-export block (copying the Phase 150-01 comment-block idiom) exposing `writeClaimNode` / `KNOWLEDGE_TYPES` / `CLAIM_NODE_ID` with the truth-claim proposed-mint sentence and the Plan 03 consumer note. No `room.db` open in the re-export.
- **`tests/test-typed-claim-writer.cjs`** (NEW): 9 checks -- proposed mint, all 6 enum members accepted, off-enum `root_cause` rejected, `invalid_params`, `invalid_text`, idempotent re-filing with no review_status downgrade, frozen `KNOWLEDGE_TYPES` Set with exactly 6 members, re-export identity, deterministic `CLAIM_NODE_ID`.
- **`tests/test-temporal-validity.cjs`** (NEW): 5 checks -- 4 temporal fields round-trip via `json_extract`, absent fields default to `''`, `PRAGMA table_info` proves zero DDL columns for the temporal keys, provenance keys round-trip, `disambiguation` set only when a non-empty string is supplied.

### Task 2: GATE-0 segment-aware filing guard + phase-gate aggregator (DIKW-02)

- **`lib/core/intelligence-cascade.cjs`** (MODIFIED): added `SEGMENT_AUTHORITY` frozen contract object + `assertSegmentAuthority(observed)` pure predicate near `detectBinarySection`, and exported both additively.
