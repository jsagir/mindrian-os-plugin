# Phase 150.8 Plan 03: Claimify 4-Pass DIKW Filing + Ambiguous Queue + Trigger Invariant Summary

Rewrote `/mos:file-meeting` Step 3 into the Claimify 4-pass pipeline (selection -> disambiguation -> decomposition -> typing) calling `navigation.writeClaimNode` per atomic claim, wired the ambiguous-queue SessionStart resurface hook with a mandatory Dismiss + 3-strikes throttle, and asserted the any-transcript DIKW trigger invariant (SENS-06 fires on a filed transcript) as a regression fence rather than rebuilding it.

## What Shipped

### Task 1 (DIKW-05): Claimify 4-pass extraction + knowledge-typing.md
- `commands/file-meeting.md` Step 3 is now the 4-pass Claimify pipeline, all LLM prose (no CJS extractor -- extraction is judgment):
  1. **Selection** keeps the 6-type segment taxonomy + priority sort verbatim; filler tagged `no_claim` and discarded.
  2. **Disambiguation** resolves pronouns via speaker identity (Step 2 roster) + prior 2 to 3 turns; unresolvable -> mint the claim with `disambiguation='ambiguous'` (queued, NEVER dropped), extending the existing below-0.5 ask-the-user rule.
  3. **Decomposition** splits compound segments into atomic claims (extends the Multi-Type rules).
  4. **Typing + write** classifies each atomic claim against the new 6-enum, extracts conditions/counter_conditions + valid_from/valid_until, then calls `navigation.writeClaimNode` per atomic claim. REFINES/ROOT_CAUSES/INSTANTIATES edges minted where prose justifies.
- The "Show Classification Reasoning" transparency block now extends each line with the `knowledge_type`.
- `references/meeting/knowledge-typing.md` (242 lines): per-type sections (fact / causal / heuristic / anomaly_cue / mental_model / assumption) with Definition / Signal phrases / Confidence indicators, plus the conditions/counter_conditions CTA contrastive-probe block and the valid_from/valid_until temporal note. Header comment answers the Part 7 reuse question: this EXTENDS file-meeting + segment-classification.md; repointing is insufficient because the 6 knowledge_type semantics are net-new.
- `knowledge-typing.md` loaded in the command Setup section the same way segment-classification.md is; Setup list renumbered.

### Task 2 (DIKW-06): ambiguous queue + SessionStart resurface hook (TDD)
- `scripts/check-pending-ambiguous.cjs` copies the `check-pending-breakthrough.cjs` queue-then-surface template (envelope emission, room resolution, D-16 empty-state silence, uncaughtException guard verbatim). Changes only: the scan (`json_extract(properties,'$.disambiguation')='ambiguous' AND review_status='proposed'` through `openRoomDb`), the payload (COUNTS + node ids only, Part 8 -- never segment prose), a MANDATORY Dismiss verb (F.7 D-10 doctrine), and the 3-strikes `surfacing_count` throttle that flips `ambiguous` -> `dismissed` so the same node never re-surfaces forever (dismissal-canary fix, mirrors pending-tension-store evaluateAndDecay). Desktop/Cowork fallback documented (post-filing F.1 selector reads the same scan).
- Registered on SessionStart in `hooks/hooks.json` alongside check-pending-breakthrough (additive; breakthrough hook untouched; hooks.json stays valid JSON).
- `tests/test-ambiguous-queue.cjs` (writer/queue unit, 6 checks): mints ambiguous + resolved claims via writeClaimNode on an in-memory db, asserts the scan partitions them and never drops the ambiguous one.
- `tests/test-check-pending-ambiguous.cjs` (hermetic-spawn integration, 10 checks): spawns the hook under a hermetic HOME + `MINDRIAN_ACTIVE_ROOM_DIR` fixture room, asserts the stdout envelope parses, carries the Dismiss verb + counts, leaks no segment prose, degrades to `{continue:true}` on empty, and that 3 surfaces flip the claim to dismissed.

### Task 3 (DIKW-11): assert the any-transcript trigger invariant (TDD)
- `tests/test-trigger-invariant.cjs` (4 arms): a fixture filing writes a fresh `last-cascade.json` representing a filed meeting transcript artifact; `dispatchSensors` fed the production turn shape `{userText, sectionPath, sessionId}` returns a candidate reach carrying signal `artifact_filed` (SENS-06). Fires regardless of the finding edge type (INFORMS + CONTRADICT arms). Two honest-negative arms (no side-channel, empty newFindings) prove the assertion has teeth. This ASSERTS shipped behavior (RESEARCH finding 6 / TRIG-01); it does not rebuild the trigger.
