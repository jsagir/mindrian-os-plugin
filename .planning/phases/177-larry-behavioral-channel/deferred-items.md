## DI-177-09-01 - f-selector-ranker import-cycle NaN-ceiling quirk (pre-existing, logged by 177-09)

`lib/workflow/f-selector-ranker.cjs` computes `BEHAVIORAL_CHANNEL_CEILING = RECOMMENDED_CONFIDENCE_FLOOR + 0.15` by requiring `lib/core/navigation-engine.cjs` at module-load time. The two form a load-time cycle. When navigation-engine is required FIRST, f-selector-ranker loads mid-cycle and reads an undefined floor, leaving its module-level CEILING `NaN`; when f-selector-ranker is required first, CEILING resolves correctly to 0.85. Verified present on the true pre-177-09 baseline (HEAD~2) -- NOT introduced by the SEAM 3 work. 177-09 worked around it by (a) lazy-requiring calibration-gate inside `readBehavioralChannelArmed()` so navigation-engine finishes loading before f-selector-ranker is pulled in, and (b) requiring f-selector-ranker before navigation-engine in test-bch-08. Proper fix (lazy/getter-based floor read in the ranker) belongs in f-selector-ranker, which 177-09 does not own. Runtime consequence is confined to the armed-true `bandCueLosesToBrain` band check, which is data-gated + Canon-Custodian-reviewed before any live arming; the dormant modifier returns null unconditionally today, so the quirk is inert.
