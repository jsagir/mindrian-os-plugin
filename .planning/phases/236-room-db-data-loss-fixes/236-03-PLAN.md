<objective>
Close GRAPHDB-02: `openRoomDb` (`lib/core/room-db.cjs:100`) has zero busy or broken open
handling. It either returns a working `DatabaseSync` handle or throws whatever raw error
`node:sqlite` (or one of the seven chained migration functions) happens to produce. The
demonstrated consequence is at `lib/core/graph-derivation.cjs:254-257`:
`try { db = openRoomDb(roomDir); } catch (_e) { db = null; }` collapses a lock, a mid-migration
exception, and a genuinely-absent room into the same indistinguishable `null`, and the caller
cold-starts as if the room had no history.

The fix classifies the failure at the chokepoint so every caller benefits, whether it catches
or lets the exception propagate.

**Open Question 1 is resolved by probe, not by assumption.** 236-RESEARCH.md rates the exact
thrown-error shape LOW confidence and states plainly that Context7's fetched `node:sqlite` API
pages do not enumerate the error object thrown when the busy timeout is exceeded or the file is
corrupt. Task 1 OBSERVES the real shape on this repo's actual runtime and writes it down BEFORE
Task 2 writes any classifier against it.

Purpose: a chokepoint whose callers cannot distinguish "does not exist yet" from "exists but is
unavailable right now" makes silent cold starts inevitable.
Output: two typed error classes, a classified `openRoomDb`, one narrowed call site, two
mutation-provable tests carrying the observed error shapes on disk, and a written call-site census.
</objective>

## Scope decision: the openRoomDb call-site census (236-RESEARCH.md Open Question 2)

**Stated explicitly rather than narrowed silently, as the research document requires.**

236-RESEARCH.md counts 25+ non-test `openRoomDb` call sites across `lib/core/` and confirms only
ONE, `graph-derivation.cjs:256`, as a demonstrated swallow-to-null.

**Decision: this phase changes `lib/core/room-db.cjs` plus the four-line catch at
`lib/core/graph-derivation.cjs:254-257`. It does not audit or modify the other 24+ sites.**

Reasoning:
- Classification belongs at the chokepoint. 236-RESEARCH.md Pitfall 2 and 236-PATTERNS.md's
  "Out of scope, do NOT touch" line both warn against distributing classification across call
  sites, the anti-pattern that leaves 24 sites drifting out of sync.
- Sites that do NOT catch improve for free: they now propagate a named, `meta`-bearing error
  instead of a bare one. No edit needed.
- The one demonstrated collapse site IS edited, because ROADMAP success criterion 3 requires
  that "the old cold-start collapse cannot be reproduced", and leaving the demonstrated
  reproduction in place would fail that criterion on its own wording. The edit is minimal:
  re-throw only the two new typed classes, keep `db = null` for everything else. That is
  strictly narrower than today and cannot regress the genuine cold-start path. This does not
  contradict 236-PATTERNS.md, whose stated intent is to keep classification OUT of call sites;
  no classification logic moves into this call site.

**Flagged follow-up, not silently dropped:** the remaining 24+ sites have not been individually
traced for whether they swallow, log, or propagate. Task 3 produces a written census so the
follow-up is scoped rather than rediscovered.
