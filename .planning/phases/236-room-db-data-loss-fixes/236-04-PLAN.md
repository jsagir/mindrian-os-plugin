<objective>
Close GRAPHDB-03 and give the phase its test aggregator.

`package.json:37-39` currently declares `"node": ">=22.5.0"`. That is the version at which
`node:sqlite` was INTRODUCED behind the `--experimental-sqlite` flag, and this repo passes that
flag nowhere: `bin/*.cjs` shebangs are plain `#!/usr/bin/env node` with no `NODE_OPTIONS`. So the
stated floor is wrong for the code as written. The correction is NOT to v22.13.0, and the reason
is the whole point of this plan.

**Two different version facts, only one of which GRAPHDB-03 is about.**

1. **v22.13.0** is where the `node:sqlite` MODULE stopped requiring `--experimental-sqlite`. Below
   it, `require('node:sqlite')` at `lib/core/room-db.cjs:30` throws outright.
2. **v22.16.0** is where the `timeout` CONSTRUCTOR OPTION was added (backported alongside v24.0.0,
   nodejs/node PR https://github.com/nodejs/node/pull/57752). Context7-verified against Node's own
   `doc/api/sqlite.md` changelog YAML: `added: v22.5.0`, then
   `changes: - version: [v24.0.0, v22.16.0], pr-url: .../57752, description: "Add \`timeout\`
   option."`.

ROADMAP.md success criterion 4 names fact 2, not fact 1: "The `timeout:5000` write-safety option's
real Node version floor is documented and `package.json` engines reflects it." That option is
passed on BOTH construction branches at `lib/core/room-db.cjs:117-118`, and the Phase 218-02 (D-05)
comment block directly above it states what it buys: without a busy timeout `node:sqlite` fails a
contended write in 0ms with SQLITE_BUSY, and `timeout: 5000` turns that into a roughly five second
busy-wait window.

**Therefore the floor is `>=22.16.0`, and a `>=22.13.0` floor would be a false pass.** On Node
22.13.0 through 22.15.x the module loads fine, the constructor accepts the options object without
complaint, and `timeout` is SILENTLY IGNORED. No error, no warning, no throw. The write-safety
guarantee Phase 218-02 shipped simply is not there, and every contended write fails instantly
instead of waiting. A `>=22.13.0` floor certifies that window as supported. That silent-degradation
band is exactly the false-success shape this whole phase exists to close, so the floor tracks the
option, not the module.

ROADMAP.md and REQUIREMENTS.md both mark GRAPHDB-03 log-only: no phase-blocking behavioral gate
is required. This plan still ships a cheap assertion, because 236-RESEARCH.md's validation table
notes it prevents silent regression at near-zero cost.

This plan also owns `tests/run-all-236.sh`, the phase aggregator every other plan's tests are
discovered by. It is glob-discovery, so it needs no coordination with plans 01 through 03 and
creates no file overlap with them.

Purpose: a wrong version floor is a broken install on a machine that satisfies the declared
requirement, and a floor set to the module's unflagged version rather than the option's real
version is broken silently rather than loudly.
Output: a corrected floor with its source cited, a lockstep sweep of every other stated floor
routed through the generated source rather than the generated file, one regression assertion, and
the phase test runner.
</objective>
