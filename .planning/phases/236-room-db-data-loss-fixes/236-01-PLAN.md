<objective>
Close the GRAPHDB-01 data-loss hole at its source: `rebuildGraph`'s unconditional
`DELETE FROM edges; DELETE FROM nodes;` (`lib/core/lazygraph-ops.cjs:545`) wipes every row in
both tables, including the `memory_event` append-only audit journal, human-confirmed
truth-claim nodes, decision nodes, and opportunity nodes carrying D-17 append-only
`stage_history[]`. The reindex that follows restores only the filesystem-derived
`Artifact`/`Section` subset, so every other population is permanently gone once the enclosing
transaction commits.

This plan replaces that statement with an ownership-scoped DELETE driven by two exported
allowlist constants, and proves the fix with a mutation-provable survival test that is written
FIRST and must be observed RED against the current unscoped code before the fix lands.

**This is NOT a missing-transaction fix.** The `BEGIN`/`COMMIT`/`ROLLBACK` wrap at
`lazygraph-ops.cjs:542` / `:614-618` already exists, is already correct, and is preserved
byte-for-byte. See 236-RESEARCH.md Pitfall 1.

Purpose: a destructive reindex is safe exactly to the degree its ownership scope is explicit
and enforced. This one has none, at any layer.
Output: two exported constants, one scoped DELETE, one shared phase fixture helper, one
mutation-provable survival test.
</objective>
