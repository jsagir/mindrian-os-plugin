    **`tests/helpers/wal-reader-probe-236.cjs`** - a forked child modeled on
    `across-session-race-writer.cjs`. Reads a room dir and an output path from `process.argv`.
    Opens its OWN `DatabaseSync` handle read-only against the room's `.mindrian/room.db` and
    polls in a tight loop, appending one JSON line per sample to the output file with the node
    counts by type and a timestamp. Runs until it receives a stop signal from the parent (a
    `process.on('message')` handler, or a sentinel file the parent touches) then flushes and
    exits 0. Distinct nonzero exits for "cannot open db" and "cannot write output" so a probe
    that never actually sampled is distinguishable from one that sampled and saw nothing.

    Important: the probe must NOT open through `openRoomDb`, because that runs the whole
    migration chain and would itself take a write lock. Open a plain `DatabaseSync` on the

    `ALLOWED_DIRECT_IMPORT` list, so a direct `node:sqlite` require from a test helper is

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Second OS process -> the same `room.db` WAL file | The reader probe is an untrusted concurrent observer by design. It must never take a write lock or run migrations, or it would perturb the very behavior it measures. |
