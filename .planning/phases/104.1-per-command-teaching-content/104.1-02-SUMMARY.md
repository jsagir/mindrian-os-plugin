## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Sweep-edit script needed slug-via-`name:` lookup, not slug-via-filename**

- **Found during:** Task 4 first script run
- **Issue:** The initial implementation built the target file path as `commands/<slug>.md`, where `<slug>` was extracted from the `/mos:<slug>` column in the working artifact. This produced "missing command file" for `/mos:validate-proposition` because the file is named `commands/value-proposition.md` (frontmatter `name: validate-proposition`). The build script uses `fm.name` (not the filename) as the canonical slug source per the Plan-122 contract; the apply script must match.
- **Fix:** Added a one-pass index that scans `commands/*.md`, reads each file's frontmatter `name:` field, and builds a `Map<slug, filePath>`. The main loop then resolves each (slug, teaching) pair via the index instead of via path-construction.
- **Files modified:** `scripts/apply-teaching-content.cjs` (1 new block of ~22 lines; the per-pair loop now reads `slugToPath.get(slug)` instead of `path.join(COMMANDS_DIR, slug + '.md')`).
- **Verification:** Re-ran `node scripts/apply-teaching-content.cjs` -> 1 written + 85 unchanged + 0 missing (1 written = the previously-missed /mos:validate-proposition; 85 unchanged = the already-applied first-run survivors). `node scripts/apply-teaching-content.cjs --check` -> `OK (86 commands match artifact)`.
- **Committed in:** `6d12841` (the tooling commit) -- the fix is in the script itself, applied before any per-command commits beyond batch 1 were affected. The 85 successful first-run writes (from batch 1) were correct; only the unaddressed 86th command (`/mos:validate-proposition`) needed the fix to land, which it did on the second run before batch 5.
