    - `route(bucket)`: returns `ROUTING_TABLE[bucket]`, and returns the `larry` outcome for an unknown

    `classify` contract:

    - Guard clause: non-string or empty input returns
      `{ bucket: 'ambiguous', scores: {...all zero}, margin: 0, confidence: 'low', features: {} }`,
      mirroring `dual-path-detector`'s guard.
    - `scores` is a per-bucket accumulator object keyed by the three REAL buckets (`ambiguous` is an
      outcome of the margin rule, not a scored class), initialised to 0.
    - `features` carries scalars and booleans ONLY. Required members: `word_count` (integer),
      `char_count` (integer), and one boolean per named regex constant. No matched substring, no
      slice of the input, ever appears in `features` or in any return value.

    Named signal constants and their weights. Author the regex bodies yourself against the intent each
    name describes; the constant NAMES, the bucket each contributes to, and the sign of each weight
    are fixed here so the scoring is auditable:

    | Constant | Contributes | Weight |
    |----------|-------------|--------|
    | `NEW_INTENT` | new_venture | +3 |
    | `PRIOR_WORK_INTENT` | prior_work | +3 |
    | `JUST_TALK_INTENT` | just_talk | +3 |
    | `ARTIFACT_REFERENCE` | prior_work | +2 |
    | `FIRST_TIME_ORIENTATION` | just_talk | +2 |
    | `HESITATION` | new_venture | -3 (NEGATIVE) |

    `HESITATION` is the mandatory negative-weight feature. `dual-path-detector`'s `STUCK_LANGUAGE`
    (-3) exists as a deliberate safety net so a thoughtful answer cannot be misread; the same job here
    is to pull AWAY from the aggressive outcome, which is firing `/mos:ignite` at someone who is
    thinking out loud. Without it a hesitant sentence containing the word "start" routes a browsing
    user straight into room creation.

    Decision rule, and this is the part that must not be copied from `user-archetype.cjs`:

    - `margin` = highest score minus second-highest score.
    - `confidence` = `high` when margin >= 3, `medium` when margin >= 2, otherwise `low`.
    - `bucket` = the highest-scoring bucket ONLY when its score >= 3 AND `margin` >= 2. Otherwise
      `ambiguous`. A tie returns `ambiguous`. Never return the first-declared key on a tie:
      `user-archetype.cjs`'s `score > maxScore` line is exactly the construct that produces research
      finding C-3's wrong answer, and decision D-G keeps that bug out of new code.

    Bound every regex: use explicit alternations and word boundaries, never a nested unbounded
    quantifier. A catastrophic-backtracking pattern inside a hook budget is a self-inflicted denial of
    service on session start (research Security Domain, V5). Guard the input length before matching:
    truncate to the first 2000 characters for scoring purposes and record the untruncated
    `char_count` in `features`.

    Absolutely forbidden in this file, per D-07 and D-K: any `require` of `lib/core/brain-client.cjs`,
    `bin/mindrian-brain-mcp-client.cjs`, `node:http`, `node:https`, or any use of `fetch`; any
    Brain-specific or Theo-specific query shape; any filesystem read or write; any `process.env` read.
    The classifier decides, and nothing else.

    No em-dashes anywhere.
