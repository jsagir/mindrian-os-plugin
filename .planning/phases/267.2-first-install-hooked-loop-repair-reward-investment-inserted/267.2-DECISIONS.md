## D-D: The reward is the Instant Brief, fired OUT OF BAND, drained on the next turn. `runPipeline` is never called inline from a hook.

**Grant:** RESEARCH.md C-6, Assumption A6, Open Question 3 (confidence LOW, "measure in Wave 0");
PATTERNS.md A11.

RESEARCH.md left the hook-budget fit unmeasured and asked the planner to measure before committing.
Two pieces of evidence available at plan time settle the architecture question in advance of the
measurement:

- `lib/core/mva-dispatcher.cjs`'s header states binding decision B2 (HARD): **45-second global
  wall-clock budget, 35-second per-agent budget.** `runPipeline` dispatches through it.
- The longest timeout on any entry in the `UserPromptSubmit` chain in `hooks/hooks.json` is 3000ms.

A 45s design budget cannot fit a 3000ms hook by any margin, so "hook calls `runPipeline`
synchronously" is ruled out on documented design constants, not on a guess.

**Architecture (D-D):** `scripts/first-install-router.cjs` spawns `scripts/mva-run.cjs` as a
**detached, fire-and-forget child** with stdout redirected to a file, then returns immediately. A
later `UserPromptSubmit` turn drains the captured render and injects it as `additionalContext`. This
is the repo's own established shape, not a new one: `scripts/brain-derivation-drain.cjs` documents
the identical contract in its own header ("parent exits within ~100ms regardless of queue depth. Each
spawned child runs independently and may take seconds (or minutes) to complete ... that is expected
and acceptable"), and `scripts/auto-explore-fingerprint.cjs` and
`scripts/async-artifact-auto-commit.cjs` both use the same `spawn(..., {detached:true}).unref()`
primitive.

**Plan B, documented not assumed away.** Plan 267.2-01 still runs the measurement RESEARCH.md asked
for and records the real number. If the measurement contradicts the above (that is, if a full
`runPipeline` completes well inside a hook budget on the no-key path), the fallback is NOT to change
architecture mid-phase: the detached shape stays, because a fast no-key run says nothing about a slow
Brain-reachable run, and the hook must not have a bimodal latency profile. If instead the detached
spawn proves unreachable on a target platform, the documented fallback is the one RESEARCH.md named:
the hook writes pending state and emits `additionalContext` telling the model to render, which
reintroduces model compliance for the render step only. That is materially better than today and
must be stated as such, never claimed as a full fix.

**Honest residual:** the reward lands one turn after the sentence that triggers it. It is delivered
by machinery rather than by a prose promise, which is the gap GAP R-1 actually names, but it is not
same-turn. Stated here so the phase does not over-claim.

## D-E: W2's trigger calls the shipped `writeUserMdAtomic` primitive read-modify-write. No second writer.

**Grant:** CONTEXT.md D-05 correction ("W2 is a TRIGGER task, not a writer task"); RESEARCH.md C-1;
`.planning/REQUIREMENTS.md` MEMOP-08 ("must not build a second writer"), binding.

The trigger lives hook-side in `scripts/first-install-router.cjs` and calls
`writeUserMdAtomic(path.join(homedir(), '.mindrian-user.md'), data)` from
`lib/core/user-md-ops.cjs`. `identity_write` (`lib/mcp/tools/identity.cjs`) is untouched and remains
the MCP-surface enrichment path for Desktop/Cowork and for model-driven field capture.

**Why this is not a second writer.** MEMOP-08 forbids a second WRITER, meaning a second
implementation of the atomic write. `writeUserMdAtomic` stays the single implementation; this phase
adds a second CALLER of it, which is exactly the distinction `lib/mcp/tools/identity.cjs:25-31` draws
in its own header ("A hook-side writer may be more deterministic. That is Phase 267.2's decision").
Plan 267.2-09 ships a grep guard that pins this: exactly one `renameSync`-based user-md atomic write
implementation repo-wide, and every reference to `~/.mindrian-user.md` in `lib/`/`scripts/`/`hooks/`
must route through it.

**Read-modify-write, and why it is required.** `buildFrontmatter` does
`Object.assign(emptyUser(), data)`. It does NOT merge with the existing file's frontmatter, only the
BODY below the delimiter is preserved. So a bare second write clobbers every field the caller does
not re-supply. The trigger therefore composes two already-exported primitives:
`readUserMd(userMdPath)` then `writeUserMdAtomic(userMdPath, {...existing, ...delta})`. This also
answers CONTEXT.md's `Claude's Discretion` item on merge behaviour when a later room-birth write meets
an earlier home-directory write: the two target DIFFERENT paths (`roomDir/USER.md` vs
`~/.mindrian-user.md`) and never contend; within `~/.mindrian-user.md` the rule is read-modify-write,
last-writer-wins per FIELD rather than per FILE.

**Discovered pre-existing defect, registered not fixed (see D-N).**

**What the trigger writes deterministically.** Only what a local hook can derive without a model:
`journey_stage: 'first_install'` and `last_detected_at`. Field capture beyond that (`canonical_role`,
`role_blend`, `problem_type`) requires reading meaning out of free text, which only the model can do,
and reaches the file through `identity_write`. The repair GAP I-1 actually gets is therefore: the ASK
is emitted by machinery instead of promised in session-start prose, the file provably EXISTS after a
first session, the write path is the shipped one, and the enrichment path is wired rather than
imagined. The residual model-compliance on FIELD VALUES is stated, not hidden.

## D-H: `mentor` maps to `blueprintFamily=exploration`

**Grant:** RESEARCH.md Assumption A4 ("a genuine design judgment, not a derivation", risk MEDIUM);
PATTERNS.md A9; explicitly routed to the planner by the orchestrator.

`commands/ignite.md:111`'s live derivation rule is "researcher / student / domain_expert ->
exploration; founder / operator / investor -> venture". `mentor` has no mapping anywhere, so adding
the option without deciding its family ships a door that produces an undefined blueprint.

**Decision: `mentor -> exploration`.** Reasoning: the venture family is for a navigator who is
building or capitalising a specific venture of their own (founder, operator, investor). A mentor
arrives to guide someone ELSE's work, so the room they need is a knowledge and pattern room, not a
venture-stage room. That is the same argument that already puts `domain_expert` in exploration: deep
knowledge applied across ventures rather than ownership of one. Recorded as a judgment call with its
reasoning so a later Canon review can overturn it on the record rather than rediscover it.

## D-D measured confirmation

**Measured 2026-09-03, plan 267.2-01 Task 2.** RESEARCH.md Assumption A6 / Open Question 3 (confidence
LOW) asked for the real wall-clock cost of `runPipeline` (the Instant Brief pipeline) to be measured,
not inferred, before D-D's architecture call is treated as settled. This section is that measurement.

**Environment the measurement ran under.** A fresh `fs.mkdtempSync` directory, passed as BOTH `HOME`
and `USERPROFILE` to a child process (per research Pitfall 6: `os.homedir()` reads `/etc/passwd` and
ignores `process.env.HOME` on POSIX, so both must be set and the child must be a fresh process, never
the harness's own process env). `ANTHROPIC_API_KEY` and `TAVILY_API_KEY` were explicitly deleted from
the child env, so the measurement is the real fresh-install no-key path. For each of three repeats: a
fresh `mvaState.writePending` call (also run in a child under the same isolated `HOME`) seeded
`sentence_sha256 = sha256("267.2-01 measurement placeholder sentence, never a real user sentence")` -
a fixed literal, never a real user sentence - with `classifier_source: 'heuristic'`,
`classifier_confidence: 'high'`, `locale: 'en'`. Then `node scripts/mva-run.cjs` was timed end to end
via `Date.now()` around a `spawnSync` call (90s safety-net timeout on the harness call itself, not the
measured budget). The isolated `HOME` directory was removed with `fs.rmSync(dir, {recursive:true,
force:true})` in a `finally` block after all three repeats completed.

**Three timings and the max (worst case, not an average, since the question is hook-budget fit):**

| Run | Elapsed (ms) | Exit code | `~/.mindrian/mva/state.json` written | `~/.mindrian/mva/briefs/<sha8>.json` written |
|-----|--------------|-----------|---------------------------------------|-----------------------------------------------|
| 1   | 4921         | 0         | yes                                   | yes                                            |
| 2   | 3122         | 0         | yes                                   | yes                                            |
| 3   | 5337         | 0         | yes                                   | yes                                            |

**Max: 5337ms.**

**Hook ceiling.** The largest `timeout` value present on any entry in the `UserPromptSubmit` chain in
`hooks/hooks.json` is **3000ms** (three entries tie at this value: `scripts/operator-update.cjs`,
`scripts/jtbd-update.cjs userprompt`, `scripts/auto-explore-drain.cjs`; the rest of the chain
[`admin-command-gate.cjs`, `intent-classifier`, `mva-detect.cjs`, `brain-derivation-drain.cjs`] carry
1500-2000ms). This matches the value D-D's original text already cited from the same file.

**Artifacts observed:** all three runs exited 0, wrote `~/.mindrian/mva/state.json` (the manifest) and
`~/.mindrian/mva/briefs/<sha8>.json` (the side file) inside the isolated `HOME`, and produced 735 bytes
of rendered stdout each time. No run hit the 90s harness safety timeout. `stderr` on each run carried
only Node's benign `SQLite is an experimental feature` `ExperimentalWarning`, nothing else.

**Verdict: max measured 5337ms versus hook ceiling 3000ms: D-D's detached-spawn architecture is
CONFIRMED.**

Even under the real fresh-install no-key path (no Anthropic key, no Tavily key), `runPipeline`'s
worst observed run (5337ms) exceeds the largest `UserPromptSubmit` hook timeout (3000ms) by a wide
margin - it does not come close to fitting. This empirically confirms the documented-constants
argument D-D already made from `mva-dispatcher.cjs`'s binding decision B2 (45s global / 35s per-agent
budget) versus the hook chain's 3000ms ceiling: a synchronous inline `runPipeline` call inside a
`UserPromptSubmit` hook was already ruled out on paper, and this measurement shows it would have
failed in practice too, by roughly 2.3x on the worst observed run alone (and the no-key path is
plausibly the FASTEST case - see the residual note below). The detached, fire-and-forget
