## Plain-language reading: which assertion aborts the file, which legs are UNEXECUTED

The file's very first `ok(...)` block, named:

> `'GAP I-1: ~/.mindrian-user.md has no writer under lib/, scripts/, hooks/'`

throws inside its own body, at the `assert.equal(codeLines.length, 1, ...)` check (source line 41),
before the `ok()` wrapper's `console.log('  ok   ' + desc)` line ever runs. So this test produces
ZERO `ok` output lines - not even for the assertion that is failing. Node then throws uncaught and
exits 1, aborting the rest of the file before it reaches any subsequent `ok(...)` call.

The GAP I-1 assertion expected exactly one code reference to `~/.mindrian-user.md` under
`lib/`, `scripts/`, `hooks/` (the pre-Phase-270-11 shape, when `lib/core/user-archetype.cjs` was the
only reader and there was no writer anywhere). It now finds **4**: the original
`lib/core/user-archetype.cjs:64` reader, plus three NEW references inside `lib/mcp/tools/identity.cjs`
(lines 3, 10, 72) shipped by Phase 270-11's `identity_write` tool, plus the pre-existing
`scripts/session-start:684` prose-instruction line (which the test's own `codeLines` filter is
designed to exclude, and does exclude - it is present in `grep2`'s raw match list but is not what
trips the count, since `codeLines` filters out any line starting with `scripts/session-start:`
before counting). The count that actually fails is `codeLines.length === 4`: the one
`user-archetype.cjs` reference plus the three `identity.cjs` references, all counted as code
references because none of them start with `scripts/session-start:`.

**Root cause, per research finding C-2:** the test's GAP I-1 negative pin was invalidated by Phase
270-11 shipping `identity_write` (a legitimate, in-scope writer for `~/.mindrian-user.md`, not a
267.2 regression), not by anything this phase has done. Phase 270-11 landed after the original 267.1
audit's evidence base was gathered.

**Assertion legs named in this file that are therefore UNEXECUTED today** (no `ok` line ever prints
for any of them, because the file aborts before reaching them):

1. The remainder of the GAP I-1 `ok(...)` block itself, past the `codeLines.length` check: the
   `codeLines[0].indexOf('lib/core/user-archetype.cjs:') === 0` assertion, the
   `codeLines[0].indexOf('safeReadFile') !== -1` assertion, and the second-grep writer-pattern loop
   (`writeFileSync|writeUserMdAtomic|appendFileSync|createWriteStream` scan over
   `lib/`, `scripts/`, `hooks/`, `skills/`, `commands/`) that would have flagged `identity_write`'s
   own `writeUserMdAtomic` call as "a writer for ~/.mindrian-user.md now exists".
2. Every `ok(...)` block after GAP I-1 in the file - this includes, per the plan's own read_first
   pointer to this file, the Action-leg assertion that Task 1 of W0 (a later plan, 267.2-03) is
   scoped to invert. Its current pass/fail state is UNKNOWN because the file never reaches it.

which specific legs the green run actually exercised, since a green run after only touching the
