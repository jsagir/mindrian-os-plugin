<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| detached background worker -> room.db | The spawned `run` child holds a write handle on the room's WAL file |
| batch writes -> room.db transaction | Many node+edge inserts commit atomically or roll back together |
| best-effort re-embed -> encoder | The post-commit indexNodes step may hit a slow/absent local model |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-218-08 | Denial of Service | long-lived / concurrent DB writer | mitigate | Open-work-close per invocation (eureka-command detached-spawn shape); NOT a persistent daemon. D-05 {timeout:5000} covers the writer-vs-live-write window. |
| T-218-09 | Tampering / data integrity | partial batch write | mitigate | One explicit BEGIN/COMMIT/ROLLBACK around the whole node+edge batch; a mid-batch error rolls back all of it (test-218-write-safety rollback leg proves the mechanism). |
| T-218-10 | Availability | slow/absent embedding model blocking the run | mitigate | Route-a re-embed runs AFTER commit in its own try/catch, degrades to lexical-only, never throws or rolls back entity writes (matches eureka's degrade-never-throw contract). |
| T-218-11 | Tampering | raw SQL bypassing the chokepoint | mitigate | Aggregator grep gate: `! grep INSERT INTO (nodes|edges)` over entity-extract.cjs + extractor; all writes route through navigation.writeEntityNode/writeEdge. |
| T-218-12 | Information Disclosure (Canon Part 8) | dispatcher egress | mitigate | Grep gate asserts no fetch/http import in the dispatcher; embedding uses the already-vendored local model path (zero network after first-model-download), never a live API. |
| T-218-SC | Tampering | npm/pip/cargo installs | accept | Zero packages installed this plan; slopcheck N/A per RESEARCH Package Legitimacy Audit. |
</threat_model>
