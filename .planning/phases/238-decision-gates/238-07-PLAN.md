<objective>
Build the committed fixture corpus that pins the card-fire tuning so it cannot silently regress in either direction, and the test that drives it. Land both BEFORE the classifier change, so the must-not-fire half is observed RED against the current code and the fix has something real to turn green.

Purpose (GATE-04, SC3): ROADMAP.md's SC3 asks for a corpus that produces zero false fires while a genuine unrendered-card fixture still fires red. `238-RESEARCH.md` measured that a corpus built ONLY from the logged instances would be vacuously satisfiable today, before any fix, because all 38 records in the live intercept log carry the PRIMARY-arm reason and running the shipped backstop predicate over every one of them returns false 38 times out of 38. The repo's own knowledge base reached the same conclusion independently. So the corpus has to be built from two sources, and the plan has to say honestly which fixtures came from where.

The genuine defect the corpus must pin: the shipped backstop pattern fires on inline academic citations, footnote reference lists, markdown reference-link definitions, code enum indexing, and array indexing in prose. Five of six authored false-positive fixtures fire today; four of four true positives also fire. Those are live measurements from `238-RESEARCH.md`, not hypotheses. In a dev repo, two bracketed indices in ordinary technical prose is not exotic.

Output: one committed JSON corpus and one table-driven test, with the must-not-fire half RED and the must-still-fire half GREEN at the end of this plan.
</objective>
