## Decisions Made

- **Class H -> Class K renaming.** Plan called for class H (stale-first-touch-copy) but class H was already taken (install-incomplete: missing statusLine block + halted .install-receipt.json). Renamed to class K (next available after I, J). The behavior contract from the plan is preserved byte-identical; only the class letter changed. Documented in source (scripts/doctor.cjs comment block + lib/core/stale-copy-scanner.cjs header comment).
- **Banner stamp via Node require(), bash-shell fallback.** scripts/banner is bash but executes `node -e "..."` to compute the canonical stamp string from the stamper. On any error (e.g. node not on PATH, module missing) the banner falls back to a hardcoded `MindrianOS v${VERSION}` so the banner NEVER breaks. The stamper is authoritative when reachable; the bash fallback is the safety net.
- **Doc-example version literals allowlisted, not refactored.** banner header has `(v1.4.0 -> v1.5.1)` doc-example; onboard parsing-logic has `## [1.5.1]` CHANGELOG heading example. Both added to `allowed_hardcoded_versions[]` with `allowlist_reason` fields. Canon Part 7 reuse: preserve comments that explain how the code works rather than rewriting them just to please the scanner.
- **Test 9 strips C-style comments before scanning.** The Canon Part 8 source-grep audit looks for `fetch(`, `require('https')`, `brain.mindrian.ai`, `telemetry` in the scanner source. Without comment-stripping, the docstring "no fetch, no Brain, no telemetry" would self-trip the audit. The test pre-processor strips `/* ... */` and `// ...` so executable source is what gets scanned; docstrings remain free to NAME the constraint they enforce.

**2. [Rule 1 - Bug] Test 9 Canon Part 8 audit false-positived on docstring "no fetch"**
- **Found during:** Task 2 (initial test run after stale-copy-scanner.test.cjs creation)
- **Issue:** The Canon Part 8 audit looked for `/\bfetch\b/` in the scanner source. The header comment "Canon Part 8: local-only; no fetch, no Brain, no telemetry egress." matched. The audit was correctly enforced but its mechanism falsely flagged its own documentation.
- **Fix:** Pre-process the scanner source by stripping C-style block comments (`/* ... */`) and line comments (`// ...`) before applying the forbidden-pattern regexes. Only executable source is scanned. Updated forbidden pattern from `/\bfetch\b/` to `/\bfetch\s*\(/` for tighter matching on function-call syntax (a stricter test).
- **Files modified:** lib/memory/stale-copy-scanner.test.cjs (Test 9 implementation).
- **Verification:** All 12 tests GREEN after fix; the audit still correctly catches a synthetic `fetch(` introduced in a manual probe (verified before committing).
- **Committed in:** b6814fb1 (Task 2 commit)

**3. [Rule 2 - Missing Critical] Added allowed_hardcoded_versions for doc-example version literals**
- **Found during:** Task 2 (running scanner against live repo before commit)
- **Issue:** Scanner correctly flagged 3 stale-version-hardcode violations on the live repo: scripts/banner line 10 (`v1.4.0 -> v1.5.1` in usage header), commands/onboard.md line 328 (`## [1.5.1]` parsing-logic example).
