- **`lib/core/terminal-capability.cjs`** (NEW, 81 lines). Exports `probeCapability(opts)`, `supportsColor()`, `supportsTruecolor()`. Six-way dispatch covered:

  | env / state                                          | returns       |
  |------------------------------------------------------|---------------|
  | `CLAUDE_DESKTOP=1` (or `MINDRIAN_DESKTOP=1`)         | `'ascii'`     |
  | `isTTY=false`                                        | `'ascii'`     |

  | `isTTY=true` AND `TERM` includes `256color`          | `'256color'`  |

## Deviations from Plan

### [Race condition - Parallel execution] Per-task commits attached to sibling executor's commit subjects

- **Found during:** task commit time (both Task 1 and Task 2).
- **Issue:** This phase ran with TWO parallel Wave 2 executors sharing the same git worktree (this executor for Plan 121.5-07; sibling for Plan 121.5-00). The sibling completed `git commit` operations between our `git add` and `git commit` invocations, and on commit the index already contained both sibling-staged and self-staged files. Result: our Task 1 work landed inside the sibling's commit `cb3ca332` (subject: `test(121.5-00): add RED tests + GREEN impl for SessionStart Coordinator core (Task 1)`); our Task 2 work landed inside the sibling's commit `5b075ad3` (subject: `test(121.5-00): register coordinator suite in 121.5 aggregator + Feynman runner (Task 3)`).
- **Impact:** All Plan 121.5-07 code IS in `main` and verifies correctly. Only the commit subjects are mis-labelled. `git log --stat cb3ca332` shows the +1 line addition for each of 88 commands plus `lib/core/terminal-capability.cjs` and `lib/memory/terminal-capability.test.cjs`. `git log --stat 5b075ad3` shows the 8 net-new files for Task 2 plus the `commands/help.md` body rewrite.
- **Fix:** None applied at the commit-history level (`git rebase -i` is destructive and parallel-unsafe; the work is shipped and traceable via `git log --stat`). Documented here so the orchestrator + verifier can locate the work by file path rather than by commit subject.
- **Files affected:** All Plan 121.5-07 output files (listed in `key_files.created` + `key_files.modified` above).
- **Commits with our work (mis-labelled):** `cb3ca332` (Task 1 contents), `5b075ad3` (Task 2 contents).

This is a `[Race condition]` deviation, not a Rule 1-3 auto-fix or a Rule 4 architectural decision. It is a known cost of parallel executor sharing of a single working tree without commit-level isolation. The orchestrator may choose to relabel via a documentation commit if commit-subject accuracy is load-bearing.
