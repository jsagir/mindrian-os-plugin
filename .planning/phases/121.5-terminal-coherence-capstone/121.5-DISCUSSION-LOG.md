## Area 1 -- Statusline Co-Design

### Q1: How should statusline shape relate to active JTBD?

| Option | Description | Selected |
|---|---|---|
| JTBD-adaptive (per-JTBD layouts) | Shape morphs per JTBD. 13 per-JTBD subsections. Highest information density. | |
| Hybrid -- constants + variable zone | Two-zone: constant + variable adapting per JTBD. 1 constant spec + 13 variable specs. | |
| JTBD-invariant single shape | One shape regardless of JTBD. Simpler, less dense. | ✓ |

**User's choice:** JTBD-invariant single shape (Decision D-01)
**Rationale captured:** Simpler design + read; JTBD becomes one segment among many. Eliminates the 13-layout complexity.

**User's choice:** Two rows, identity/situation split (Decision D-02)

## Area 2 -- Bulletproof ASCII /mos:help

### Q1: How should renderer decide color vs ASCII output?

| Option | Description | Selected |
|---|---|---|
| TTY + truecolor probe -- color only when both true | Auto-detect; ASCII fallback. Most bulletproof. | (initial) |
| Pure ASCII always -- color is opt-in via flag | Simplest, biggest visual hit. | |
| Color always -- best-effort fallback | ANSI default; --plain escape hatch. | (clarified away) |
| Two output styles -- color + plain, user picks at install | Configurable preference. | |

**User's initial choice:** Color always -- best-effort fallback
**Reflected back:** Picked option contradicted earlier "BULLITE PROOF ASCII" directive. Three clarifying re-options offered.
**User's clarified choice:** TTY + truecolor probe (Decision D-05)
**Notes:** lib/core/terminal-capability.cjs (NEW) probes process.stdout.isTTY AND $COLORTERM. Reusable across /mos:status, /mos:doctor, /mos:splash.

### Q2: Single source of truth for help groups + JTBD lines?

| Option | Description | Selected |
|---|---|---|
| Hybrid -- groups in data/help-groups.json, JTBD lines in command frontmatter | Distributed JTBD ownership + centralized grouping. | ✓ |
| Centralized -- everything in data/help-groups.json | One file; risk of drift from command-registry.json. | |
| Decentralized -- everything in each command's frontmatter | Most rename-resilient; slowest render. | |
| Generated -- extend command-registry.json via Phase 122 substrate | Maximum Phase 122 reuse. | |

**User's choice:** Hybrid (Decision D-06)

### Q3: "Ship + Share" group composition?

| Option | Description | Selected |
|---|---|---|

| Top-level commands only (7 entries) | Cleaner; subcommands stay buried. | |

### Q4: CI guard severity for help coverage?

| Option | Description | Selected |

## Area 4 -- SessionStart Precedence Ladder + Token Budget

| Option | Description | Selected |
|---|---|---|

| Memory-resume FIRST -- continuity above all | "You were working on X" first. | |
| Tension hook FIRST -- persistent thinking beats anything | Strongest Hooked Fix 1 surfacing. | |

**User's choice:** Proposed default (Decision D-13)
**Rationale captured:** Blocking warnings first (install / sealed-room), continuity before novelty, ambient state last. Aligns with Canon Part 10.

### Q2: Combined token budget?

| Option | Description | Selected |
|---|---|---|
| ~2,000 chars (proposed default) | ~500 tokens; balances visibility against context cost. | ✓ |
| ~1,200 chars -- lean | Aggressive cap; more compression. | |

**User's choice:** ~2,000 chars (Decision D-14)
**Notes:** Per-surface uniform -- one budget, one mental model.

### Q3: Overflow policy?

| Option | Description | Selected |
|---|---|---|
| Iterative compression -- compress lowest-priority until fits | Top 2-3 always full; bottom degrades gracefully. | ✓ |
| Hard drop -- contributors below threshold dropped entirely | Cleanest turn-1 but lossy. | |

| Stop-at-budget -- top-down until cap, drop rest | Simplest; verbose top can crowd out tension hook. | |

**User's choice:** Iterative compression (Decision D-15)

### Q4: Contributor failure isolation?

| Option | Description | Selected |
|---|---|---|

**User's choice:** Isolate failed contributors (Decision D-16)
**Notes:** try/catch per contributor; log to ~/.mindrian/telemetry/sessionstart-errors.jsonl; emit memory_event; drop failed; continue rest.
