## Decisions Made

- **Hard Rule 9 SEARCH-vs-queryNodes branching honored substantively:** The plan's `<interfaces>` block sample showed BOTH useSearch=true AND useSearch=false branches using db.index.vector.queryNodes() -- the plan flagged this as a copy-paste artifact to address. The shipped brain-vector-search.cjs has substantively different Cypher on each branch: the SEARCH branch uses the 2026.04+ inner-CALL form `CALL () { CALL db.index.vector.queryNodes(...) YIELD node, score [WITH node, score WHERE node.namespace = $namespace] RETURN node, score } RETURN node.id, node.metadata, score ORDER BY score DESC LIMIT $topK` so the planner can push the namespace filter inside the inner CALL and prune candidates BEFORE top-K sorting; the queryNodes branch uses the older post-procedure WHERE `CALL db.index.vector.queryNodes(...) YIELD node, score WHERE node.namespace = $namespace RETURN node.id, node.metadata, score ORDER BY score DESC LIMIT $topK` because pre-2026.04 planners cannot push the filter into the index scan. The response shape is identical so the cutover (Plan 127.1-03) is a single-line swap regardless of Neo4j version.
- **Synthetic-pre-live-load fixture pattern:** Because (a) NEO4J_URI/USER/PASSWORD are operator-gated env vars not present in the parallel-executor environment, AND (b) Plan 127.1-01's NDJSON dump is not yet on disk (Plan 127.1-01 commit 95e25d93 documents a Pinecone count drift -- 8543 vs expected 1427 -- that blocked Plan 127.1-01's live load), the Task 2 Step 1 "execute the live load" step cannot run end-to-end from inside this parallel executor. The deliverable that DOES flip Surface 2 GREEN is the index-config fixture matching the DDL-determined shape. Solution: ship a synthetic fixture whose shape mirrors what live Aura WILL return (the DDL is the load-bearing artifact, NOT the live capture), mark it synthetic_pre_live_load:true so any future maintainer knows the live overwrite is pending, and rely on captureIndexConfig() to overwrite it when the operator runs the loader. This is a Rule 3 deviation (auto-fix blocking issue) -- the alternative (waiting for Plan 127.1-01's live count reconciliation) would have blocked Wave 1 entirely.
- **Lock 1 round-trip rewrite step preserved in code, deferred in execution:** scripts/load-embeddings-into-neo4j.cjs's roundTripVerify() function reads back every loaded vector via `MATCH (n:MethodologyChunk) RETURN n.id, n.embedding`, hashes via the same Float64Array buffer protocol, and rewrites the manifest's neo4j_sha256 column from the live values. This function is committed and tested by node --check. Its execution awaits the operator running the loader once Plan 127.1-01's NDJSON drift is reconciled and the live Aura connection is sourced.
- **MCP tool registration shipped but not wired:** registerVectorSearchTool(server) lives in mcp-server-brain/lib/brain-vector-search.cjs but is NOT yet require'd or called from mcp-server-brain/server.cjs. The cutover (swap from lib/pinecone-tools.cjs registerPineconeTools to lib/brain-vector-search.cjs registerVectorSearchTool) is the Plan 127.1-03 act; Plan 127.1-02's job is to deliver the library at production quality. The clean separation lets Plan 127.1-03's cutover be a single git diff with ~5 lines changed in server.cjs.
