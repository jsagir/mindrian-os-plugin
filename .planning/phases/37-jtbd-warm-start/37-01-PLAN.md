  <name>Task 1: Create build-jtbd-nudges script</name>
  <files>scripts/build-jtbd-nudges</files>
  <action>
    read_first: scripts/compute-state, scripts/learn-from-usage, scripts/track-analytics

    Create scripts/build-jtbd-nudges as a bash script that:

    1. Takes ROOM_DIR as $1, PLUGIN_ROOT as $2
    2. Reads room state by parsing the compute-state output already passed via stdin OR by re-reading key room signals directly:
       - venture_stage (from STATE.md YAML frontmatter or by checking which sections have content, same logic as compute-state lines 57-87)
       - total_entries count
       - empty_sections list (sections with 0 .md files excluding ROOM.md)
       - meeting_count (count dirs in room/meetings/)
       - has_cross_refs (any [[section]] refs found)
       - convergence_count (from MEETINGS-INTELLIGENCE.md if exists)
    3. Reads command usage from room/.analytics.json -> commands object. If file missing, treat all commands as unused.
    4. Outputs TWO sections to stdout:

    **Section 1: JTBD Nudges (max 3)**
    Generate 2-3 nudges based on room state. Each nudge MUST follow this exact pattern (per D-01):
    "You have [concrete state]. [Natural language action] [outcome that matters]."

    Nudge selection priority order (pick top 2-3 that apply):
    a) Empty room (0 entries): "You have an empty Data Room. Tell Larry about your venture idea -- he will structure your thinking and file it where it belongs."
    b) Problem only, no market (Pre-Opportunity): "You have [N] entries shaping your problem. Ask Larry to explore your market -- so you know if the problem is worth solving before you go deeper."
    c) Meetings filed but not analyzed: "You have [N] meetings filed but their insights are sitting in transcripts. Ask Larry to pull cross-meeting intelligence into the sections where it belongs."
    d) 3+ sections filled, no grade: "You have [N] sections filled across your Data Room. Ask Larry for an honest grade -- so you see where your case is strong and where it needs work."
    e) Rich room (5+ sections, 10+ entries), no presentation: "Your room has [N] entries across [M] sections. Tell Larry to generate your dashboard -- so investors can browse your evidence without a meeting."
    f) Convergence signals detected: "Your meetings show [N] convergence signals -- multiple sources pointing the same direction. Ask Larry to surface these patterns -- convergence is where your strongest arguments live."
    g) Empty competitive-analysis: "You have no competitive analysis yet. Ask Larry to challenge your assumptions -- knowing your blind spots early saves months of wrong turns."
    h) Has entries but no meetings: "You have [N] entries but no meeting intelligence. File a meeting transcript and Larry will extract insights, track action items, and connect what people said to what your room already knows."

    Per D-03: NEVER describe features. Describe job completion. Frame as what the user GETS, not what the command DOES.

    **Section 2: Dynamic Command Menu (per D-04, D-05, D-06)**
    Read commands object from .analytics.json. Build a menu of 6 commands, prioritized by:
    - Commands relevant to current venture_stage (stage-appropriate commands first)
    - Commands the user has NOT used yet (unused > rarely used > frequently used)
    - Always include /mos:help and /mos:status as anchors

    The 10 candidate commands with stage relevance:
    - /mos:help (all stages) -- "Larry recommends what to do next"
    - /mos:status (all stages) -- "See your Data Room state"
    - /mos:diagnose (Pre-Opportunity, Discovery) -- "Classify your problem type"
    - /mos:file-meeting (all stages) -- "File a meeting transcript"
    - /mos:opportunities (Discovery+) -- "Discover relevant grants and funding"
    - /mos:persona (Validation+) -- "Get 6 perspectives on your work"
    - /mos:query (Discovery+, needs KuzuDB entries) -- "Ask your knowledge graph anything"
    - /mos:grade (Validation+) -- "Honest assessment of your venture"
    - /mos:present (Design+, needs 5+ entries) -- "Generate your Data Room dashboard"
    - /mos:act (Discovery+) -- "Larry runs a framework autonomously"
    - /mos:update (all stages) -- "Check for latest features"

    Output format for the menu (matching existing style):
    ---
    Quick commands (type /mos: to see all):
      /mos:help ........... Larry recommends what to do next
      /mos:status ......... See your Data Room state
      [4 more based on relevance + unused priority]
    ---

    Make the script executable (chmod +x). Use bash + python3 inline (same pattern as learn-from-usage). The python3 section handles JSON parsing and nudge selection logic. The bash wrapper handles room detection and argument parsing.
  </action>
