**Create scripts/prediction-registry.cjs** (per D-05 through D-09):

A CJS script with subcommands for managing the prediction registry.

Usage: `node scripts/prediction-registry.cjs <subcommand> <room_dir> [args...]`

Subcommands:

**add** `<room_dir> <json_file>` -- Add a prediction from a JSON file
- Read prediction data from json_file (Larry generates this during /mos:causal predict)
- Validate required fields: prediction, category (must be one of: business, research, new_business_model, funding, competitive, technical per D-06), deadline, claim_cause, claim_effect
- Generate id: `pred-YYYYMMDD-HHMMSS-NNN` (NNN = sequential within same second)
- Check active count. If >= 10 active predictions (per D-07), print error and exit 1: "Max 10 active predictions. Resolve or expire existing predictions first."
- Append to room/.predictions/REGISTRY.json (create dir + file if not exists)
- Update stats object
- Print: "Added prediction pred-XXXXXXX (category: X, deadline: YYYY-MM-DD)"

**resolve** `<room_dir> <prediction_id> <status> [notes]` -- Resolve a prediction
- status must be "confirmed" or "refuted" (per D-05 lifecycle)
- Update prediction status, resolved_at, resolution_notes
- **Confidence propagation (per D-09):** If claim_id is set, open KuzuDB, query current confidence, compute new confidence:
  - confirmed: `min(1.0, current + 0.1)`
  - refuted: `max(0.0, current - 0.2)`
  - Update CausalClaim node via Cypher: `MATCH (c:CausalClaim) WHERE c.id = $id SET c.confidence = $new_conf`
  - Record confidence_before and confidence_after on the prediction
- Update stats (recalculate hit_rate = confirmed / (confirmed + refuted), overdue_count)
- Trigger archive check: if total resolved > 100, archive to room/.predictions/archive/YYYY.json (per D-07)
- Print: "Resolved pred-XXXXXXX as {status}. Confidence: {before} -> {after}"

**list** `<room_dir>` -- List predictions with summary
- Read REGISTRY.json
- Print table of active (pending) predictions: id, prediction (truncated 60 chars), category, deadline, days until/past deadline
- Print summary stats: total, pending, confirmed, refuted, expired, hit_rate, overdue_count (per PREDICT-05)

**overdue** `<room_dir>` -- Check for overdue predictions (called by session-start)
- Read REGISTRY.json
- Find predictions where status=pending AND deadline < today
- Mark as expired if deadline is > 30 days past (auto-expire stale predictions)
- Output JSON to stdout for session-start to consume:
```json
{
  "overdue": [{"id": "pred-xxx", "prediction": "...", "deadline": "...", "days_overdue": 5}],
  "overdue_count": 2,
  "session_count_check": true
}
```
- The session_count_check field: per D-08, Larry prompts for oldest unresolved every 5th session. The session-start script handles the counter; this script just provides the data.

**archive** `<room_dir>` -- Force archive resolved predictions
- Move all resolved (confirmed/refuted/expired) predictions to room/.predictions/archive/YYYY.json
- Keep only pending predictions in REGISTRY.json
- Update stats

Error handling: wrap all fs operations in try/catch. Create room/.predictions/ directory if it doesn't exist. Handle missing REGISTRY.json gracefully (create empty one).

---

## predict

Generate, track, and resolve falsifiable predictions from causal claims.

### Sub-subcommands

| Action | Usage | Description |
|--------|-------|-------------|
| generate | /mos:causal predict | Generate a new prediction from a causal claim |
| list | /mos:causal predict list | Show all predictions with summary stats |
| resolve | /mos:causal predict resolve <id> | Resolve a prediction as confirmed/refuted |

### generate (default)

1. **Identify source claim.** Ask user which causal claim to base the prediction on. If the room has .causal-candidates.json or KuzuDB claims, list up to 5 recent claims for selection.

2. **Generate prediction.** From the selected claim's cause/mechanism/effect, generate a falsifiable prediction:
   - Format: "If [cause] then [measurable effect] by [specific date]"
   - The prediction MUST be falsifiable -- include a concrete metric or observable outcome
   - The deadline MUST be a specific date (not "soon" or "eventually")

3. **Classify category.** Based on the claim domain and prediction content, assign one of: business, research, new_business_model, funding, competitive, technical

4. **Write prediction.** Create a temp JSON file with the prediction data:
   ```json
   {
     "prediction": "If X then Y by Z",
     "category": "business",
     "deadline": "2026-06-15",
     "claim_cause": "from source claim",
     "claim_effect": "from source claim",
     "claim_id": "KuzuDB ID if available"
   }
   ```
   Then run: `node "${PLUGIN_ROOT}/scripts/prediction-registry.cjs" add "$room_dir" "/tmp/prediction.json"`

5. **Confirm.** Show the user the prediction and ask them to refine if needed.

### list

Run: `node "${PLUGIN_ROOT}/scripts/prediction-registry.cjs" list "$room_dir"`

Show the output in Larry's voice. Add commentary on hit rate if available.

### resolve <id>

1. Ask user: "Was this prediction confirmed or refuted?"
2. Ask for brief resolution notes
3. Run: `node "${PLUGIN_ROOT}/scripts/prediction-registry.cjs" resolve "$room_dir" "<id>" "<status>" "<notes>"`
4. Report confidence change back to user
```
