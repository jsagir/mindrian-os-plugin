<objective>
Ship `lib/core/rs-mind-map.cjs` -- the 5-branch Cytoscape.js generator. Reads from the active tier (Aura when connected, room.db otherwise) and emits Cytoscape JSON + standalone HTML wrapper for browser rendering.

The 5 branches (per kickoff §5):
1. **Direct Intersections** -- pairs where lsa > 0.6 AND bert > 0.6 (high-confidence direct overlap)
2. **Structural Transfer** -- classification = 'structural_transfer' (high lsa, low bert)
3. **Semantic Implementation** -- classification = 'semantic_implementation' (high bert, low lsa)
4. **Discovered RS** -- ReverseSalient nodes (lagging components per Hughes 1983)
5. **Innovation Ecosystem** -- full Author + Institution + Paper + Innovation graph slice (multi-hop)

Each branch is a colored cluster in the Cytoscape graph with its own edge style. The user can filter by branch via query_filter param.

Tier dispatch transparent to the caller. The module accepts opts.tier ('aura' or 'sqlite') OR auto-detects by inspecting opts.driver (Aura) vs opts.roomDir (SQLite). Both read paths produce the same 5-branch JSON shape; Tier 1 (Aura) gets richer multi-hop queries for Innovation Ecosystem; Tier 0 (SQLite) gets the same logical slicing with simpler SQL.

Canon Part 7 reuse: HTML wrapper uses the existing dashboard/index.html Cytoscape CDN pattern (cytoscape@3.33.1 from unpkg). NO new runtime dependency added. NO new Cytoscape build step. Just inline the CDN script tag in the wrapper template.

Canon Part 8: read-only against the user's OWN graph (NO Brain query). BUT `auditQueryObject(rendered_html, 'rs-mind-map-html')` runs on the FINAL HTML output to ensure no forbidden patterns leak into the rendered page (defense-in-depth on the DISPLAY surface). The data source is trusted (user's own room.db / Aura), but the rendered HTML may be shared, exported, or cached, so audit at the display boundary too.

The schema persisted by both writers:
- nodes table rows have type IN ('RSDiscovery', 'ReverseSalient', 'Innovation', 'Paper', 'Author', 'Institution')
- edges table rows have type IN ('DISCOVERED', 'DERIVED_FROM', 'ENABLES', 'AUTHORED_BY', 'AFFILIATED_WITH')
- properties column carries JSON-stringified node/edge metadata (classification, breakthrough_score, lsa, bert, thesis, etc.)

Tier 0 (SQLite) read queries:
```sql
-- Branch 1: Direct Intersections
SELECT id, properties FROM nodes
  WHERE type = 'RSDiscovery'
    AND json_extract(properties, '$.lsa') > 0.6
    AND json_extract(properties, '$.bert') > 0.6;

-- Branch 2: Structural Transfer
SELECT id, properties FROM nodes
  WHERE type = 'RSDiscovery'
    AND json_extract(properties, '$.classification') = 'structural_transfer';

-- Branch 3: Semantic Implementation
SELECT id, properties FROM nodes
  WHERE type = 'RSDiscovery'
    AND json_extract(properties, '$.classification') = 'semantic_implementation';

-- Branch 4: Discovered RS
SELECT id, properties FROM nodes
  WHERE type = 'ReverseSalient';

-- Branch 5: Innovation Ecosystem (multi-table union)
SELECT n.id, n.type, n.properties FROM nodes n
  WHERE n.type IN ('Innovation', 'Paper', 'Author', 'Institution');
SELECT source, target, type, properties FROM edges
  WHERE type IN ('DERIVED_FROM', 'AUTHORED_BY', 'AFFILIATED_WITH');
```

Tier 1 (Aura) read queries (richer multi-hop):
```cypher
-- Branch 1: Direct Intersections
MATCH (d:RSDiscovery)
WHERE d.lsa > 0.6 AND d.bert > 0.6
RETURN d;

-- Branch 5: Innovation Ecosystem (multi-hop)
MATCH (i:Innovation)<-[:ENABLES]-(d:RSDiscovery)
OPTIONAL MATCH (d)-[:DERIVED_FROM]->(p:Paper)-[:AUTHORED_BY]->(a:Author)-[:AFFILIATED_WITH]->(inst:Institution)
RETURN i, d, p, a, inst;
```

<!-- Tier dispatch logic -->

```javascript
async function detectTier(opts) {
  if (opts.tier === 'aura' || opts.tier === 'sqlite') return opts.tier;  // explicit
  if (opts.driver && typeof opts.driver.session === 'function') return 'aura';
  if (opts.roomDir && typeof opts.roomDir === 'string') return 'sqlite';
  throw new TypeError('rs-mind-map: opts.tier OR opts.driver OR opts.roomDir required');
}
```
