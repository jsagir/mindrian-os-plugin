<objective>
Ship `lib/core/rs-neo4j-writer.cjs` -- the Aura Cypher writer for the canonical Reverse Salient framework schema. This is the Tier 1 (Aura-connected) writer in the dual-tier output layer.

Schema (per kickoff §5):
- **Nodes:** RSDiscovery, ReverseSalient, Innovation, Paper, Author, Institution
- **Edges:** DISCOVERED, DERIVED_FROM, ENABLES, AUTHORED_BY, AFFILIATED_WITH

The writer takes a scored+classified+thesis-bearing pair (from Plan 89.2-07's `generateThesis` output) and persists it into the user's own LazyGraph Aura via idempotent MERGE Cypher. Per-write rollback Cypher is captured and returned so the caller can journal it for manual rollback if needed.

Canon Part 7 reuse: this plan ALSO extends `lib/core/lazygraph-ops.cjs::EDGE_TYPES` with the 4 new edge types in place. The constant is the canonical edge-type registry for the project; extension (not fork) is the Canon-compliant path. Plan 89.3-02 (rs-sqlite-mirror) consumes the same extended constant.

**Idempotency in REAL Aura (not just mocks):** The 3 core node ids (discovery_id, rs_id, innovation_id) are deterministically derived via sha256({query_concept, doc_concept, classification}) -- the SAME pair always produces the SAME ids. This makes Cypher MERGE truly idempotent: re-running writeDiscovery with the same input matches the existing nodes by id PRIMARY KEY and yields zero new mutations. This mirrors the same pattern Plan 89.3-02 (rs-sqlite-mirror) uses; both writers share the dedup contract so the dual-tier schema remains consistent across re-runs. The aura_op_id remains random (it's per-op telemetry, not a node ID).

Canon Part 8 defense-in-depth: even though writes go to the user's OWN graph (NOT Brain), `auditQueryObject(cypher_params, 'rs-neo4j-writer')` runs BEFORE every Cypher execution to catch any forbidden patterns that might leak through node properties or edge metadata. Throws `ExternalEgressViolation` on hit. This is conservative; it ensures the writer cannot accidentally smuggle user content into a future caller path that does egress.

Tier dispatch is NOT this plan's responsibility. The writer assumes Aura is reachable. If the backend returns a connection error, the writer throws `AuraUnreachableError` -- a clean signal the caller can use to fall back to rs-sqlite-mirror (Plan 89.3-02). The actual dispatch glue lives in Plan 89.3-05.

Mockable backend: the writer accepts `opts.driver` as an injection point. Tests pass a mock driver; production pulls the live Aura driver via existing lazygraph-ops Aura wiring (when available) or via a clean shim. This mirrors the 89.2 fetcher fetch-mock pattern.

Purpose: Ships SC-01 (rs-neo4j-writer.cjs exports writeDiscovery with idempotent MERGE + rollback Cypher) + partial SC-07 (lazygraph-ops EDGE_TYPES extended without forking) + partial SC-08 (Feynman test suite stays green; this plan adds 1 of 5 new test files for 89.3).
</objective>

<!-- Deterministic id generation (the dedup contract -- shared with Plan 89.3-02) -->

The 3 core node ids MUST be deterministic so MERGE is truly idempotent in REAL Aura (not just mocks). Use the SAME helper Plan 89.3-02 (rs-sqlite-mirror) uses:

```javascript
function buildDeterministicIds(pair) {
  const stableKey = JSON.stringify({
    q: pair.query_concept,
    d: pair.doc_concept,
    c: pair.classification
  });
  const hash = crypto.createHash('sha256').update(stableKey).digest('hex').slice(0, 16);
  return {
    discovery_id: 'rsd-' + hash,
    rs_id: 'rs-' + hash,
    innovation_id: 'inn-' + hash
  };
}
```

This guarantees: re-running writeDiscovery({q, d, c}) yields the SAME 3 core ids -> Cypher MERGE matches existing nodes by id PRIMARY KEY -> zero new node mutations. Both writers (rs-neo4j-writer + rs-sqlite-mirror) share this dedup contract so Tier 0 / Tier 1 round-trip stays consistent.

The aura_op_id (return field) IS still random (`generateOpId` uses crypto.randomUUID + timestamp). It is per-write telemetry for caller-side journaling, not a node identifier.

<!-- The schema this plan ships (the OUTPUT) -->

Cypher MERGE pattern (idempotent via deterministic ids):
```cypher
// Core RS nodes (always created)
MERGE (d:RSDiscovery {id: $discovery_id})
  SET d.classification = $classification,
      d.breakthrough_score = $breakthrough_score,
      d.dominant_dimension = $dominant_dimension,
      d.thesis = $thesis,
      d.bridge_concept = $bridge_concept,
      d.diff = $diff,
      d.lsa = $lsa,
      d.bert = $bert,
      d.created_at = $created_at

MERGE (rs:ReverseSalient {id: $rs_id})
  SET rs.query_concept = $query_concept,
      rs.doc_concept = $doc_concept,
      rs.classification = $classification

MERGE (i:Innovation {id: $innovation_id})
  SET i.thesis = $thesis,
      i.breakthrough_score = $breakthrough_score

MERGE (d)-[:DISCOVERED]->(rs)
MERGE (rs)-[:DERIVED_FROM]->(i)
MERGE (d)-[:ENABLES]->(i)

// Paper nodes (only if opts.context.papers present)
UNWIND $papers AS p
  MERGE (paper:Paper {id: p.id})
    SET paper.title = p.title, paper.doi = p.doi, paper.source = p.source
  MERGE (d)-[:DERIVED_FROM]->(paper)

// Author + Institution (only if opts.context.experts present)
UNWIND $experts AS e
  MERGE (a:Author {name_orcid_key: e.name + '|' + (e.orcid OR '__no_orcid__')})
    SET a.name = e.name, a.orcid = e.orcid, a.h_index_estimate = e.h_index_estimate
  WITH a, e
  WHERE e.institution IS NOT NULL
    MERGE (inst:Institution {name: e.institution})
    MERGE (a)-[:AFFILIATED_WITH]->(inst)

// AUTHORED_BY edges (only if opts.context.papers carries authors arrays)
// The writer constructs paper_author_pairs from opts.context.papers.flatMap(p => p.authors.map(a => ({paper_id: p.id, author_key: a.name + '|' + (a.orcid || '__no_orcid__')})))
UNWIND $paper_author_pairs AS pa
  MATCH (paper:Paper {id: pa.paper_id})
  MATCH (author:Author {name_orcid_key: pa.author_key})
  MERGE (paper)-[:AUTHORED_BY]->(author)
```

Rollback Cypher captured in return:
```cypher
// Inverse DELETE for the just-MERGEd entities (caller may journal)
DETACH DELETE (d:RSDiscovery {id: $discovery_id})
DETACH DELETE (rs:ReverseSalient {id: $rs_id})
DETACH DELETE (i:Innovation {id: $innovation_id})
// Note: shared Paper/Author/Institution nodes are NOT deleted by rollback
// because they may be referenced by other RSDiscoveries; only the RS-specific
// nodes are torn down. The DETACH ensures all incident edges are removed.
```

Return shape:
```javascript
{
  wrote_node_count: 3,           // count of NEW nodes (MERGE without prior match)
  wrote_edge_count: 3,           // count of NEW edges
  rollback_cypher: '...',        // the inverse-DELETE Cypher string
  aura_op_id: 'op-2026-04-27-...', // generated unique id for this write op (random; per-op telemetry)
  schema_version: '1.0'          // for forward compatibility
}
```
