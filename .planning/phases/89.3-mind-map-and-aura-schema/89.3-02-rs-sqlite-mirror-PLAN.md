<objective>
Ship `lib/core/rs-sqlite-mirror.cjs` -- the Tier 0 (no-Aura) writer for the canonical Reverse Salient framework schema. Mirrors the rs-neo4j-writer.cjs (Plan 89.3-01) public API surface so callers swap backends transparently.

Schema parity (per kickoff §5):
- Same 6 node types: RSDiscovery, ReverseSalient, Innovation, Paper, Author, Institution
- Same 5 edge types: DISCOVERED, DERIVED_FROM, ENABLES, AUTHORED_BY, AFFILIATED_WITH
- Stored in room.db nodes + edges tables (the existing lazygraph-ops schema; node.type and edge.type discriminate the kind)
- Same writeDiscovery(pair, opts) signature; same return shape with rollback_cypher field carrying SQL DELETEs

INSERT OR REPLACE pattern provides MERGE-equivalent idempotency: re-running writeDiscovery with the same input pair yields zero NEW rows. The `id` PRIMARY KEY on nodes table is the deduplication key; deterministic id generation (sha256 of stable identity payload) ensures the same pair always produces the same ids.

Canon Part 7 reuse: the writer uses `lazygraph.openGraph()` to obtain a SQLite connection (existing primitive from Phase 88-13). Does NOT introduce a new SQLite wrapper. Consumes the EXTENDED EDGE_TYPES constant from Plan 89.3-01 for edge type validation. Same audit primitives as Plan 89.3-01.

Canon Part 8 defense-in-depth: even though writes go to the user's OWN room.db (NOT Brain), `auditQueryObject(sql_params, 'rs-sqlite-mirror')` runs BEFORE every SQLite write to catch any forbidden patterns. Throws `ExternalEgressViolation` on hit. Conservative because the data lineage flows downstream into rs-mind-map (rendered HTML) and rs-expert-mapper (Aura when available).

Tier dispatch is NOT this plan's responsibility. The writer assumes Aura is unavailable (the dispatch surface in Plan 89.3-05 picks this writer when isAuraConnected returns false). If room.db is missing or unwritable, the writer throws `SQLiteUnreachableError` -- a clean signal for the dispatch layer.

Purpose: Ships SC-02 (rs-sqlite-mirror.cjs exports same writeDiscovery API surface against room.db; Tier 0 fallback proven) + partial SC-08 (Feynman test suite advances; 1 of 5 new test files for 89.3).

<!-- Deterministic id generation (the dedup contract) -->

Same pair MUST produce the same ids across runs (idempotency requirement). Use a deterministic id-from-payload helper:

```javascript
function buildDeterministicIds(pair) {
  const stableKey = JSON.stringify({
    q: pair.query_concept,
    d: pair.doc_concept,
    c: pair.classification
  });
  const hash = crypto.createHash('sha256').update(stableKey).digest('hex').slice(0, 16);
  return {
    discovery_id: 'rsd-' + hash,
    rs_id: 'rs-' + hash,
    innovation_id: 'inn-' + hash
  };
}
```

This guarantees re-running writeDiscovery({q, d, c}) yields the SAME 3 core ids -> INSERT OR REPLACE matches the existing rows -> zero NEW rows. Test 2 verifies this.

NOTE: rs-neo4j-writer uses crypto.randomUUID() for ids (Test 2 there relies on the mock driver tracking by composite key, not id). For the SQLite mirror, deterministic ids are required because the PRIMARY KEY constraint is the dedup mechanism. This is a tier-specific implementation detail; the public API surface is the same.

<!-- Rollback SQL shape -->

rollback_cypher field carries SQL (despite the name; the name is intentional for cross-tier API consistency). Example:
```sql
DELETE FROM edges WHERE source = 'rsd-abc123def456' OR target = 'rsd-abc123def456';
DELETE FROM edges WHERE source = 'rs-abc123def456' OR target = 'rs-abc123def456';
DELETE FROM edges WHERE source = 'inn-abc123def456' OR target = 'inn-abc123def456';
DELETE FROM nodes WHERE id = 'rsd-abc123def456';
DELETE FROM nodes WHERE id = 'rs-abc123def456';
DELETE FROM nodes WHERE id = 'inn-abc123def456';
```

Edges deleted FIRST (foreign-key safety), then the 3 core nodes. Shared Paper/Author/Institution NOT deleted (may be referenced by other RSDiscoveries).
