# AI-SPEC - Phase 355: Hidden in Plain Sight - Jev-through-Theo Cross-Connection Engines

> Navigator ruling (2026-09-23, recorded during framework selection): **Jev is the preferred algorithmic choice for any and all intelligence layers.** Wherever MindrianOS needs a judgment (classify, verify, rank, reconcile), the default is a typed Jev question, not a regex, a threshold literal, or prose. The ruling lives inside two fixed constraints: Canon Part 8 (no room text leaves the machine; only Framework handles, enums and buckets cross) and the 2026-09-17 ruling (Jev never runs on a user machine or in a hook; dev-time ledgers shipped as data, or per-user via plugin -> Theo -> Jev with Theo holding the key). Where a payload would be room text, Jev judges at dev time and its labels are distilled into shipped data or code until a Part-8-clean payload shape and the Theo seam exist. The seam, not the preference, is the gate.

## 1. System Classification

**System Type:** Hybrid - a typed-judgment verification layer over a local graph engine (structured classification / verification). Not RAG, not multi-agent, no text generation.

**Description:**
The room-local engines (RS, HSI, whitespace, Eureka, find-connections) find candidate cross-domain pairings over the user's own room graph and hold every number. This layer adds three typed judgments on top: (1) a direction name for each pairing, defined once from the origin deck (same meaning in different words vs same words with different meaning); (2) a verification stamp computed in code from Theo's `find_connections` shortest-path hop count (strong / indirect / unverified, backend named), with one Jev citation-check Choice (`supports / contradicts / says_nothing`) when the Theo seam exposes a judgment enum and `judge: none` disclosed when it does not; (3) a dev-time Jev Choice measured against the HSI thinking-mode regexes. Users are innovation teams, founders and researchers working an ill-defined problem or extending an opportunity under review; the PWS author placed the tool there. "Good" is: the user reads a short list of explained, stamped pairings instead of a thousand raw ones, no score is ever shown, an accepted pairing files as a proposed opportunity with provenance and a human gate promotes it, and the phase records the first measured hit rate.

**Critical Failure Modes:**
1. A stamp that lies: a fabricated path, a tier not recomputed from Theo's returned hop count, a `strong` that only means "both link to the same hub framework", or a finding silently dropped or snapped to a nearby framework name when its endpoints do not resolve.
2. A direction label that means different things in different producers (the pre-existing rs-math / hsi-lsa / Python conflict), so a pattern or verification judgment is made on a lie.
3. Room text or a raw magnitude crossing the wire: a user sentence, a content id, or a float sent to Theo or Jev; a `TYPESAFE_API_KEY` or `api.typesafe.ai` reference under `lib/` or `hooks/`.
4. Degradation that hides itself: Theo unreachable yet a stamp other than `unverified` + `backend: unavailable`; no Jev seam yet a stamp implying a judge ran.
5. A bare 0.00-1.00 decimal rendered anywhere a user reads (CLI output, Larry's Desktop / Cowork prose, the reach card), or a claim promoted to confirmed without `gate_answer`.

### Known Failure Modes in This Domain

1. **Hub inflation: "strong" that only means "both touch a famous framework".** In problem-finding, a short canon path through a high-degree node (a problem type, a stage, a general category like design thinking) certifies that two frameworks share a textbook, not that the pairing transfers. The briefing's Brain Audit shows why this graph is prone to it: the node types built to carry cross-domain bridges are orphaned (`CrossDomainInnovation` 15 nodes / 0 edges, `DomainBridge` 5 nodes / 0 edges) and the computational-science layer is "ABSENT", so paths will route through pedagogy hubs; Section 2 Finding 5 adds that 306 of 419 frameworks are unplaced. SciMuse (briefing Deep Sweep #20) found high-connectivity concepts were *negatively* correlated with expert interest, so hub-routed `strong` stamps may land exactly where experts find the least value. Outside: "hubby" high-degree nodes inflate knowledge-graph inference metrics (J. Biomedical Semantics 2024, doi:10.1186/s13326-024-00308-z).
2. **Vocabulary mismatch hides real bridges.** The briefing calls it "the single biggest source of missed connections" (a defense user's "critical vulnerability" and a healthcare user's "single point of failure" are one structure; "reverse salient" and "bottleneck" likewise). Here it shows up as `unverified` on real bridges: an endpoint that resolves to no canon Framework handle (Theo resolves via `ALIAS_OF`, never fuzzy match) or a bridge the canon does not yet hold. `unverified` therefore means "not checked or not in canon", not "wrong", and the hit rate among unverified findings must be measured, not assumed low. Terminology Translation (briefing Top Incorporations #1, BioSage arXiv:2511.18298) is out of scope this phase.
3. **The false friend passed off as a bridge.** The deck's own failure note: "apparently automobile means something else in biology". With three producers disagreeing on which sign means which (355-SPEC Background), a same-words-different-meaning pair can be labeled as a same-meaning bridge, and a `strong` stamp on it sends a team to transfer a mechanism that was only a shared word.
4. **Verified but already known.** A 1-2 hop canon path shows the connection is real, and also that methodology already knows it. The deck's Sleep domain returned "mostly improved diagnostics" and one pairing someone "tried last year". Verification and novelty pull in opposite directions; the briefing does not state how to weigh them (not stated in the briefing). The per-tier hit rate is the first data on whether useful pairings sit in `strong` or in `indirect`.
5. **Unusual but useless.** The 2025 devil's advocate: "Signal-to-noise could be low." A long list of odd pairs, each individually defensible, that no domain reader would act on. Guard: the useful / not judgment in Req 7, not any score.
6. **A judge with no rubric produces noise, and must not decide salience.** An LLM judge asked "is this a good connection?" without written criteria produces noise (ai-evals reference, Rubric Design); the stated-vs-withheld rule spike measured 64/64 vs 40/64 (Section 3). The 2025 objection "who decides what is reverse or salient?" sets the boundary: the judge only answers whether the path supports the claim; the room's graph and the human decide salience.
7. **The regex fallback that makes every room look descriptive.** `classifySentenceMode` returns `descriptive` when nothing matches and its pattern matches "issue" and "island" (Finding 4); a practitioner shown "your room is mostly descriptive thinking" is given a false picture of the team's thinking. It can never say none.
8. **AI-only loops converge.** Shiiku et al. 2025 (briefing Deep Sweep #25): AI-only groups' idea diversity collapsed while hybrid human-AI groups became more diverse. If the gate becomes a rubber stamp over a ranked list, the engine loses the diversity it exists to create. `gate_answer` must remain a real human decision.

## 2. Framework Decision

**Selected Framework:** None. Direct calls to TypeSafe's System One HTTP API (`POST https://api.typesafe.ai/v1/systemone`) with Node 22 native fetch, reusing the client already shipped in `scripts/build-section-command-ledger.cjs` (`jev`, `pool`, `loadKey`, `assertEgressCeiling`; already reused by `scripts/eval-icm-writers.cjs`), inside the existing Claude Code plugin + `@modelcontextprotocol/sdk` ^1.29.0 / `zod` ^3.25.76 runtime. Theo's `find_connections` is reached only through `lib/core/brain-client.cjs` `callTool` (Part 8 guard already lists `find_connections {from, to, maxHops?}` as a known safe shape, `part8-egress-guard.cjs:430`).

**Version:** Jev `jev-1.13.0` (the client sends `jev-latest`; the resolved model version is recorded per run - see Findings). Node >= 22.16.0. No package added.

**Rationale:**
This phase makes three kinds of call: typed Choice judgments (`supports / contradicts / says_nothing`; five thinking modes + `none`), a graph-path lookup whose hop tier is computed in code, and dev-time-only scripts whose results ship as data. The 30-line client in the repo already covers retry with backoff, pooling at concurrency 4, and an executable Part 8 ceiling. The no-new-deps, CJS-only, Node >= 22.16.0, no-TypeScript, no-Python-added constraints remove every framework in the decision matrix before scoring starts; each of them targets text generation, RAG or agent orchestration, and this system needs none of those. Jev is the navigator's preferred algorithmic choice for every intelligence layer (ruling above); the framework question is therefore only "how is Jev called", and the answer is the client that already exists.

**Alternatives Considered:**

| Framework | Ruled Out Because |
|-----------|------------------|
| `@typesafe-ai/sdk` as a scripts-only devDependency | Breaks no-new-deps; adds nothing the in-repo client lacks; never measured in a spike. Reconsider only if TypeSafe changes the wire contract (e.g. the 400-vs-422 behavior) faster than the local client can follow. |
| Claude Agent SDK | Claude-only and a new dependency; a second agent runtime inside a plugin that already runs in Claude Code; the judgments here are typed classification, not generation. |
| Claude-as-judge (Larry decides `supports / contradicts` in prose) | No calibrated probabilities, not reproducible, and the stamp must be computed in code. |
| LangChain, LangGraph, CrewAI, LlamaIndex, Haystack, OpenAI Agents SDK, Google ADK, AutoGen/AG2 | No Python or TypeScript build; no-new-deps excludes them. |
| Theo-proxied Jev via a `computeGraphMetric` judgment enum | Not an alternative: it is the future per-user home. Theo-side code, out of scope this phase; the seam is consumed as it is and its absence is disclosed (`judge: none`). |

**Vendor Lock-In Accepted:** Partial, consciously. TypeSafe Jev is the judgment model by ruling; the wire contract is one HTTP endpoint with a typed body, so a swap is a client change, not a framework change. Anthropic Claude is the host composer and gate runner, not a framework choice. Theo (Neo4j Aura) is the path source, not a model.

**Findings the planner must carry (from framework selection, 2026-09-23):**
1. The existing client's `assertEgressCeiling` accepts only the section-ledger payload shape (state keys `{section, problem_type, stage, candidates}`, candidate keys `{name, jtbd, glossary, description}`, 140-char cap; `build-section-command-ledger.cjs:83-128`). The HSI payload `{sentence}` and the citation-check payload `{claim, path}` both throw. Give each question type its own ceiling passed into the client, with the ledger's ceiling as the default; do not widen the shared allow-list.
2. The client is not pinned (`MODEL = 'jev-latest'`, line 62). Record the resolved model version per run in the phase record or the regex-vs-Jev numbers are not reproducible.
3. "Adopt" for the HSI classifier means distilling Jev's labels into a revised mode word-list or rule table under `data/`, re-measured offline against the same fixture. Runtime classification of user sentences via Theo -> Jev is blocked by Part 8 (a sentence is room text) until a Part-8-clean payload shape exists; that shape is an explicit open item, not an assumption.
4. The regex classifier never answers `none` and falls back to `descriptive` (whose pattern matches is/are/has), so almost any sentence scores descriptive (`hsi-spectral.cjs:112-125`). Report accuracy on the full set with `none` counted, on the 5-mode subset, and per mode.
5. Hub inflation: `allShortestPaths` over 3 hops across a canon where 306/419 frameworks are unplaced and 417/552 are name-only may connect many pairs through a few hubs. Measure the share of `strong` stamps whose path passes through a top-decile-degree framework, and the hit rate per tier. The tier rule stays; the measurement says whether the stamp carries information.
6. Endpoint-to-Framework handle resolution is the silent failure point. Unresolved endpoints stamp `unverified` with a reason; never dropped, never snapped to a close-enough name.

```js
// Theo returns aligned arrays: path[i], edges[i] joins path[i] -> path[i+1], edges.length === path.length - 1
// (~/Theo/src/mcp/content/find-connections.ts:249-252, :266-275). Turn them into named hops so Jev

    hops.push({ from: theoPath.path[i], relation: theoPath.edges[i].toLowerCase().replace(/_/g, ' '), to: theoPath.path[i + 1] });

  if (!payload || typeof payload !== 'object') throw new Error(label + ': payload must be an object');
  if (!isDeepStrictEqual(Object.keys(payload).sort(), ['model', 'questions', 'state'])) throw new Error(label + ': top-level keys must be model/state/questions');
  if (payload.model !== PINNED_MODEL) throw new Error(label + ': model must be ' + PINNED_MODEL);

// Ceiling for {claim, path}: closes over the exact Theo answer, so only Framework names Theo itself
// returned, one enum phrase, and Theo's edge types can cross. Anything else throws before fetch().
function makeCitationCeiling({ from, to, direction, theoPath }) {
  const claim = renderClaim(from, to, direction);
  const hops = hopsFromTheoPath(theoPath);
  return function citationCeiling(payload) {
    checkTop(payload, 'citationCeiling');
    const s = payload.state || {};
    if (!isDeepStrictEqual(Object.keys(s).sort(), ['claim', 'path'])) throw new Error('citationCeiling: state keys must be exactly claim/path');
    if (s.claim !== claim) throw new Error('citationCeiling: claim is not the templated name + direction string');
    if (!isDeepStrictEqual(s.path, hops)) throw new Error('citationCeiling: path is not the hop list Theo returned');
    if (!isDeepStrictEqual(payload.questions, CITATION_QUESTIONS_STATED) && !isDeepStrictEqual(payload.questions, CITATION_QUESTIONS_WITHHELD)) {
      throw new Error('citationCeiling: questions are not a frozen citation-check set');
    }
    return true;
  };
}

    if (!isDeepStrictEqual(payload.questions, THINKING_MODE_QUESTIONS)) throw new Error('sentenceCeiling: questions are not the frozen thinking-mode question');
    return true;
  };
}
```

### Common Pitfalls

1. **Literal reading (`jaggedness` #1).** Jev "answers the question you wrote, not the one you meant"; scoping words and negations are read at face value. For thinking mode this is exactly where the regexes fail ("This is a risk" contains `is` but is evaluative), so each option carries a `not_for` and a boundary example. When a wrong answer makes you explain what you meant, that explanation is the missing criterion. Never copy gold-fixture sentences into `examples` (it inflates Jev's score against the bar in Finding 8).
2. **Indirection (`jaggedness` #4).** A 3-hop path is multi-hop reasoning. Give hops as named `{from, relation, to}` objects, render edge types as plain words (`PRODUCES_INPUT_FOR` -> `produces input for`; `jaggedness` "Numeric representations" says semantic forms beat codes), and keep the tier in code. Jev judges only whether the hops support the claim.
3. **Context rot (`jaggedness` #5).** "Accuracy falls as the state grows with content unrelated to the decision." Filter in code: one sentence per state (do not pack all 100+ sentences into one state with 100 questions; every question would read 99 distractors), and no Theo descriptions in `{claim, path}` (also forbidden by the 2026-09-17 IP ruling, SKILL.md requirements).
4. **Adversarial state (`jaggedness` #6).** "State is data, and jev-1.13 does not treat it as hostile by default." Text that argues for its own label moves the answer. This is one more reason user sentences never reach Jev (Part 8), and why the Claude-written fixture must exclude sentences that name their own mode ("This is an analytical point").
5. **400 vs 422.** `api.md` "Errors" lists `422 Unprocessable Entity` for a malformed body; the 2026-09-17 spike measured **400** (`jev-typed-decisions-api.md` "What to Avoid"); the SDK ships both `BadRequestError` and `UnprocessableEntityError` classes (`llms.txt` SDK index). Treat every 4xx except 429 as non-retryable and never branch on 422 alone.
6. **`jev-latest` drift.** "An alias moves when a new release ships, so the answers behind it can change without a change on your side" (`models.md` "Aliases"). The shared client sends `jev-latest` (`build-section-command-ledger.cjs:62`) and keeps only the last response's `model` (`:562`). Phase 355 scripts send `jev-1.13.0` and fail the run if any response reports a different `model` (`consistency_choice_cookbook.md`: "Report every returned version so alias changes within a run remain visible").
7. **Regex fallback bias (Finding 4).** `classifySentenceMode` returns `descriptive` on zero matches (`hsi-spectral.cjs:139`) and the descriptive pattern `\b(is|are|was|were|has|have|...)\w*\b` (`:115`) also matches `issue`, `island`, `hash`. The regex can never answer `none`. Report accuracy on the full set with `none` counted, on the 5-mode subset, and per mode. Adopting a 6th label also changes HSI's Markov state space (`THINKING_MODES_v1` at `:97-103` feeds `buildTransitionMatrix`), so an adoption decision must say where `none` sentences go in the chain.
8. **The shared ceiling and the Theo shape both reject the obvious payload.** `jev()` hard-calls the ledger ceiling (`build-section-command-ledger.cjs:137`), which throws on `{sentence}` and `{claim, path}` (Finding 1). On the Theo side, send exactly `{from, to}`: the plugin guard admits only `from`/`to` plus optional `maxHops` (`part8-egress-guard.cjs:430-437`), while Theo seals inputs with `z.strictObject` (`~/Theo/src/mcp/register-content-tool.ts:144`) over `from`/`to`/`limit` with no `maxHops` (`find-connections.ts:64-70, :382-413`). `maxHops` fails Theo; `limit` fails the guard.
9. **Silent drops.** The ledger loop `continue`s past any non-200 (`build-section-command-ledger.cjs:561`) and the client has no request timeout (`fetch` without `signal`, `:143`). Copying that into the HSI measurement would shrink the denominator without saying so. Count every non-200 and schema failure per run, and pass `AbortSignal.timeout()`.
10. **Numbers and comparisons.** "Jev is not a calculator" (`jaggedness` #2): never send lsa/semantic floats, hop counts or thresholds; the direction label is computed in code and only its enum phrase crosses. "A Noul and a Choice are not comparable" (`jaggedness` #8, 0.22 vs 0.01 measured): this phase is Choice-only; never carry a threshold tuned on one to the other.
11. **Run-to-run variation is not zero.** TypeSafe repeated its plurality label 90.8% of the time and flipped on 2 of 8 questions over 15 repeats (`consistency_choice_cookbook.md`); two of eight Nouls carried sampling noise (`parallel_questions.md`). A single-run accuracy delta near the 10-point bar is inside that noise; the eval plan (Section 5) should repeat the run.

## 4. Implementation Guidance

**Model Configuration:**
- **Jev `jev-1.13.0`, pinned in the request body**, dev-time scripts only. The request body has exactly three fields, `state`, `model`, `questions` (`api.md` "Request body"). There is no temperature, seed or max-tokens parameter: not in docs. Output is typed and output tokens are free (`models.md` "Price").
- **Record the resolved model per response and require it to be uniform across a run** (Finding 2). The response `model` field "reports the versioned ID that answered" (`models.md` "Aliases"). A replayed fixture is valid only for the model id stored with it.
- **Decision policy (application code, not model parameters):**
  - Citation check (dev-time calibration only this phase): verdict stands at `confidence >= 0.8`, otherwise it goes to human review (`citation_check.md` `AUTO_ACCEPT = 0.8`, "start high"). Below 0.5 means do not act (`confidence.md` "Thresholds scale with risk").
  - Thinking mode: the primary metric is the argmax `choice` against the gold label, with no abstention. This compares like for like with the regex, which never abstains, so the Finding 8 bar is measured fairly.
  - Also recorded, as secondary analysis only (never used for the bar): `confidence`, `probabilities`, and a "report a coarser label below 0.9" cut. At 0.9, the confident half was right 90% of the time and the rest 40% (`classification_using_confidence.md`, measured on `jev-1.12`).
- **Claude** is the host composer and never judges here (Section 2). **Theo** is the path source, not a model.

**Core Pattern:**

Three pieces. Code finds and computes, Jev judges one typed question, and nothing Jev returns reaches a user this phase.

(1) The one edit to the shared client (Finding 1 + pitfall 9). It stays backward compatible, because both existing callers pass two arguments (`build-section-command-ledger.cjs:560`, `eval-icm-writers.cjs` `resolveJevItems`) and keep the ledger ceiling:

```js
// scripts/build-section-command-ledger.cjs -- replaces jev() at :136-159
async function jev(key, body, opts) {
  const o = opts || {};
  (o.ceiling || assertEgressCeiling)(body);        // per-question ceiling; the ledger ceiling stays the default
  const timeoutMs = o.timeoutMs || 15000;
  let attempt = 0;
  for (;;) {
    const t0 = Date.now();
    let r;
    try {
      r = await fetch(ENDPOINT, {
        method: 'POST',
        headers: { Authorization: 'Bearer ' + key, 'Content-Type': 'application/json' },
        body: JSON.stringify(body),
        signal: AbortSignal.timeout(timeoutMs),      // a hung socket can no longer hang the script
      });
    } catch (e) {
      if (attempt++ < 3) { await sleep(500 * 2 ** attempt); continue; }
      return { status: 0, ms: Date.now() - t0, json: null };
    }
    const ms = Date.now() - t0;
    const text = await r.text();
    let json = null;
    try { json = JSON.parse(text); } catch (_e) { /* leave json null */ }
    if ((r.status === 429 || r.status === 529) && attempt++ < 4) {
      const ra = Number(r.headers.get('retry-after'));  // models.md: SDKs honor retry-after when present
      await sleep(Number.isFinite(ra) && ra > 0 ? ra * 1000 : 400 * 2 ** attempt);
      continue;
    }
    return { status: r.status, ms: ms, json: json, text: text.slice(0, 200) }; // 400/401/422: returned, never retried
  }
}
```

(2) The runtime stamp. This is `lib/core`: no Jev, no key, Theo only through `callTool`. Tier is computed from the edges Theo returned and cross-checked against Theo's own `hops`. The `Stamp` schema is in Section 4b. The logic was verified against a mocked `callTool` for eight outcomes: strong, unavailable, endpoint refused, empty paths, local handle unresolved, thrown transport error, `egress_blocked` sentinel, and hop mismatch.

```js
// lib/core/verification-stamp.cjs (runtime)
const { z } = require('zod');
// `Stamp` (the zod schema in Section 4b) is defined at the top of this same file.

const TheoReturnedPath = z.object({ path: z.array(z.string()), edges: z.array(z.string()), hops: z.number().int() }).passthrough();

function tierFromHops(hops) {                     // the whole tier rule, in code (355-SPEC.md Req 4)
  if (hops === 1 || hops === 2) return 'strong';
  if (hops === 3) return 'indirect';
  return 'unverified';
}

async function stampFinding({ fromHandle, toHandle, direction }, deps = {}) {
  const callTool = deps.callTool || require('./brain-client.cjs').callTool;
  const unverified = (backend, reason) => Stamp.parse({ verification: 'unverified', backend, direction, judge: 'none', reason });
  if (!fromHandle || !toHandle) return unverified('not_called', 'handle_unresolved');   // Finding 6: never dropped, never snapped
  let res = null;
  try { res = await callTool('find_connections', { from: fromHandle, to: toHandle }); } // exactly {from, to} (pitfall 8)
  catch (_e) { res = null; }
  if (res === null || res === undefined) return unverified('unavailable', 'backend_unavailable'); // null = transport failure (brain-client.cjs:627-630)
  if (res.error === 'egress_blocked') return unverified('unavailable', 'egress_refused');         // a defect in the adapter, surfaced, not hidden
  if (!Object.prototype.hasOwnProperty.call(res, 'paths')) return unverified('theo', 'endpoint_unresolved'); // Theo omits `paths` on refusal (find-connections.ts:111-119)
  const parsed = z.array(TheoReturnedPath).safeParse(res.paths);
  if (!parsed.success) return unverified('theo', 'malformed_response');
  if (parsed.data.length === 0) return unverified('theo', 'no_path_within_3_hops');              // `paths: []` is a real answer
  const best = parsed.data.reduce((a, b) => (b.edges.length < a.edges.length ? b : a));
  const hops = best.edges.length;
  if (hops !== best.hops || best.path.length !== hops + 1) return unverified('theo', 'malformed_response');
  const verification = tierFromHops(hops);
  if (verification === 'unverified') return unverified('theo', 'malformed_response');
  return Stamp.parse({ verification, backend: 'theo', path: { nodes: best.path, edges: best.edges }, direction, judge: 'none' });
}
module.exports = { stampFinding, tierFromHops };
```

## 4b. AI Systems Best Practices

> Written by `gsd-ai-researcher`. Cross-cutting patterns every developer building AI systems needs, independent of framework choice.

### Structured Outputs with zod (Pydantic does not apply: CJS, no Python added)

Jev is typed by construction: answers "conform to the structured software types and JSON schema your code expects, so it never has to recover a value from generated prose" (`how-to-build-with-system-one.md` "Structured"). So validation here is not about parsing prose. It catches three things:
- a vendor contract change;
- a `choice` outside our criteria;
- model drift.

A second schema makes a lying stamp unrepresentable (critical failure 1). Both schemas were verified under zod 3.25.76 against mock inputs.

```js
// scripts/jev-response-schema.cjs (dev-time) -- mirrors docs.typesafe.ai/api.md "Answer types"
const { isDeepStrictEqual } = require('node:util');
const { z } = require('zod');
const { PINNED_MODEL } = require('./jev-question-ceilings.cjs');

const ChoiceAnswer = z.object({
  type: z.literal('choice'),
  choice: z.string(),
  probabilities: z.record(z.number().min(0).max(1)),   // "floats that sum to 1"
  confidence: z.number().min(0).max(1),                 // Choice and Score only
});
const NoulAnswer = z.object({ type: z.literal('noul'), noul: z.number().min(0).max(1) }); // no confidence field
const JevResponse = z.object({
  model: z.string().regex(/^jev-\d+\.\d+\.\d+$/),       // the versioned id that answered (models.md)
  answers: z.record(z.discriminatedUnion('type', [ChoiceAnswer, NoulAnswer])),
  usage: z.object({ input_tokens: z.number().int().nonnegative(), output_tokens: z.number().int().nonnegative() }),
});

// expected: { questionId: [option, ...] } taken from the frozen question's criteria keys
function parseJevResponse(res, expected) {
  if (!res || res.status !== 200) return { ok: false, reason: 'http_' + (res ? res.status : 'none') };
  const parsed = JevResponse.safeParse(res.json);
  if (!parsed.success) return { ok: false, reason: 'schema: ' + parsed.error.issues.map((i) => i.path.join('.') + ' ' + i.message).join('; ') };
  const out = parsed.data;
  for (const qid of Object.keys(expected)) {
    const a = out.answers[qid];
    const options = expected[qid];
    if (!a || a.type !== 'choice') return { ok: false, reason: 'missing choice answer ' + qid };
    if (!options.includes(a.choice)) return { ok: false, reason: qid + ': choice outside criteria' };
    if (!isDeepStrictEqual(Object.keys(a.probabilities).sort(), [...options].sort())) return { ok: false, reason: qid + ': probability keys differ from criteria' };
    const sum = Object.values(a.probabilities).reduce((x, y) => x + y, 0);
    if (Math.abs(sum - 1) > 0.02) return { ok: false, reason: qid + ': probabilities sum to ' + sum.toFixed(3) };
  }
  if (out.model !== PINNED_MODEL) return { ok: false, reason: 'model drift: answered by ' + out.model };  // Finding 2
  return { ok: true, model: out.model, answers: out.answers, usage: out.usage };
}
module.exports = { JevResponse, parseJevResponse };
```

```js
// lib/core/verification-stamp.cjs (runtime) -- the stamp object {verification, backend, path?, direction, judge}
const { z } = require('zod');
const DIRECTIONS = ['meaning_bridge', 'term_collision'];   // import from the Req 1 direction module
const REASONS = ['handle_unresolved', 'endpoint_unresolved', 'no_path_within_3_hops', 'backend_unavailable', 'egress_refused', 'malformed_response'];

const Stamp = z.object({
  verification: z.enum(['strong', 'indirect', 'unverified']),
  backend: z.enum(['theo', 'unavailable', 'not_called']),   // names which graph answered, or that none did
  path: z.object({
    nodes: z.array(z.string().min(1).max(128)).min(2).max(4),
    edges: z.array(z.string().min(1)).min(1).max(3),
  }).strict().optional(),
  direction: z.enum(DIRECTIONS),
  judge: z.literal('none'),        // every runtime stamp this phase (Finding 7); widen to a union only when the Theo seam exists
  reason: z.enum(REASONS).optional(),
}).strict()                        // .strict(): a `score` or `confidence` key is a parse failure, so no raw 0.xx can ride along
  .superRefine((s, ctx) => {
    const fail = (message) => ctx.addIssue({ code: z.ZodIssueCode.custom, message });
    const hops = s.path ? s.path.edges.length : 0;
    if (s.path && s.path.edges.length !== s.path.nodes.length - 1) fail('path: edges.length must equal nodes.length - 1');
    if (s.verification === 'strong' && !(hops >= 1 && hops <= 2)) fail('strong requires a 1-2 hop path');
    if (s.verification === 'indirect' && hops !== 3) fail('indirect requires a 3-hop path');
    if (s.verification !== 'unverified' && (s.backend !== 'theo' || s.reason)) fail('a verified stamp comes from theo and carries no reason');
    if (s.verification === 'unverified' && (s.path || !s.reason)) fail('unverified carries a reason and never a path');   // no fabricated path
    if (s.backend === 'unavailable' && !['backend_unavailable', 'egress_refused'].includes(s.reason)) fail('unavailable needs backend_unavailable or egress_refused');
    if (s.backend === 'not_called' && s.reason !== 'handle_unresolved') fail('not_called only when a local endpoint did not resolve');
```

**Retry and failure policy:**

| Outcome | Action | Source |
|---------|--------|--------|
| 429 / 529 | Exponential backoff `400 * 2 ** attempt`, up to 4 retries. Honor `retry-after` when present. After that, the item fails with `http_429` / `http_529` | `api.md` "Handling rate limits"; `models.md` "Rate limits"; client `:156` |
| Network error / timeout | `500 * 2 ** attempt`, up to 3 retries, then `status: 0` | client `:148-150` |
| 401 | Never retry. Abort the whole run with a loud message that never prints the key | `api.md` Errors; spike "401 on a bad key is correct and loud" |
| 400 or 422 | Never retry. The frozen question or state is malformed, so this is a defect in our code. Abort the run and log status + `text` (already truncated to 200 chars, `:157`) | `api.md` lists 422; spike measured 400 (pitfall 5) |
| 200 but `parseJevResponse` fails (schema, choice outside criteria, probability keys, model drift) | Retry the call once. If it still fails, the item fails with the reason string | ours |
| Any failed item | The run fails (non-zero exit), because an accuracy with a silently smaller denominator is a lie (critical failure 4 analogue). Rerun; a full run costs under a cent | ours |

**Never log:** the key. There is no room content to log; the ceilings make sure of that.
**Surface:** a one-line summary per run (calls, failures, tokens, cost, model) plus `355-JEV-MEASUREMENT.md`.

### Async-First Design

- **How async works here.** Plain Node 22 CJS with native `fetch`. CJS has no top-level `await`, so every dev-time script uses `main().catch(...)` under `require.main === module`, the shipped pattern at `build-section-command-ledger.cjs:699-708`. Concurrency comes from `pool(items, n, fn)` (`:161-172`): n workers share one index counter, which is safe because Node runs one thread.
- **The one common mistake: `Promise.all(fixture.map(callJev))`.** It fires 100+ requests in one burst.
  - The docs rate limits are 1,200 requests per minute and 250,000 tokens per second, and they are "adjusting dynamically" (`models.md` "Rate limits" warning).
  - `pool(…, 4)` at the measured ~300 ms p50 is about 13 requests per second, or ~800 per minute. That is under the limit.
  - Do not raise concurrency above 4 without a limiter. The spike's clean 20-wide burst (`jev-typed-decisions-api.md` Constraints) is one observation, not a guarantee.
- **Batching.** The docs push many questions per call over one state (`primitives.md` "Ask multiple questions together"; `parallel_questions.md`). That saving comes from sending a big state once. Here every item has its own tiny state, so there is nothing to amortize. Packing 100 sentences into one state would trade a negligible saving for context rot (pitfall 3). One state per call is correct here. Batch only when several questions genuinely share one state; for example, a later phase that asks a pattern Choice and an existence Noul about the same finding.
- **Stream vs await.** Streaming is not in the docs: the API returns one JSON body (`api.md` "Response body"). Always `await` the whole response, then validate with `parseJevResponse`.
- **The runtime stamp.** `stampFinding` is async because `callTool` is. For a list of findings, dedupe `(from, to)` pairs, run them through `pool(…, 4)`, and `await` all of them before rendering. A finding is never rendered without its stamp.
- **Hooks.** None of this runs in a hook. Jev never runs on a user machine (2026-09-17 ruling). The spike's `Promise.race` budget wrapper (`jev-typed-decisions-api.md` "Wrapper shape") is only needed if a future per-turn path appears.

### Prompt Engineering Discipline

- **State vs questions replaces system vs user.** Jev has no system prompt. The discipline is "Separate content from questions" (`concepts/state.md`):
  - `state` carries only data (`claim`, `path`, `sentence`);
  - `instructions` + `criteria` carry only policy;
  - data is referenced from the question by backticked name, never pasted into it (`primitives.md` "Reference specific fields").
- **State the policy.** The decision rule goes in `instructions.rule`. The spike measured 64/64 agreement with the rule stated and 40/64 without; every miss was a priority-order miss (`policy-execution-parity.md`). The citation calibration re-measures stated vs withheld on this question (Finding 7) rather than assuming the result transfers.
- **Align criteria with instructions.** "When the instructions and the criteria ask for different things, jev-1.13 might get confused" (`jaggedness` #7). Keep one snap judgment per question (`primitives.md` "Ask for one snap judgment per question").
- **Few-shot: inline and static, never dynamically retrieved.**
  - Examples live inside each option as `{what, not_for, examples}` (`primitives/choice.md` "Structured instructions and criteria"; `primitives/advanced.md` "JSON rubric for boundary clarification").
  - Dynamic per-item example retrieval would make every request's question different. That breaks the frozen-question ceiling and makes item results incomparable.
  - Examples are authored separately from the gold set. Iterate criteria wording on a small separate tuning set, then run the >= 100-sentence gold set once, with the question frozen. Tuning on the gold set would bias the Finding 8 bar.
- **Version the question.** The ceilings enforce the frozen question with a deep-equality check. Record `sha256(JSON.stringify(questions))` in the measurement record. Any criteria edit is a new measurement, not a patch.
- **Always include an escape option:** `says_nothing`, `none` (`primitives/choice.md`; spike case E put 0.95 on the no-match option at confidence 0.93).
- **Token bound.** There is no `max_tokens` or output-length parameter in the docs. Outputs are typed, and output tokens are free (`models.md`). The production bound goes on input instead:
  - ceiling string caps (sentence 300 chars; Framework names 128 chars max per Theo's own schema, `find-connections.ts:384-386`);
  - the per-call 8,000-input-token tripwire (Section 4).

### Context Window Management

This is a Hybrid classification layer, not RAG, conversation or an autonomous agent. There is no chunking, no summarisation and no compaction. The strategy is to filter in code before sending (`jaggedness` #5; `how-to-build-with-system-one.md` "Decompose the input state"):
- `{claim, path}` is built from two names, one enum phrase and at most three hops. Theo fixes the hop bound at 3 and caps paths at 10 (`find-connections.ts:168-173`).
- **Send the one path that set the tier.** `allShortestPaths` can return several equal-length paths (default 5). Send only the path whose hop count set the tier, one path per request, and record which one. Several paths in one state would make each question read the others as distractors and blur which path produced the verdict.
- `{sentence}` is one sentence of at most 300 chars.
- Headroom against the 32k state + longest-question budget is more than 40x. If `usage.input_tokens` ever approaches the 8,000 tripwire, something unintended entered the state; stop and inspect, do not raise the limit.

## 5. Evaluation Strategy

**How the generic dimensions map here.** Safety = D6 + D9 + D10. Task completion = D4 + D10. Hallucination and faithfulness = D5 + D6 + D15. No RAG metric applies, because nothing is retrieved and nothing is generated.

**Tension (a): "Show your work" vs no score.** The briefing's Action Plan Phase 3 says every finding shows "the graph path, the scores, and the source evidence". Its Implementation Detail asks for a "Combined score with all three components visible" and "Not a black-box number. A traceable chain of reasoning that the user can inspect, question, and override" (briefing mirror `08-plan.md`, `09-impl.md:113`).

- **Resolution adopted here:** show the evidence, never the scalar. The user sees the path hop by hop, the tier word, the direction phrase, the backend and the judge outcome. No number is ever shown.
- **Why this is a conscious deviation from the briefing:** it follows Canon Part 12 and the 2025 review's trust answer (`355-INTENT.md` section 3). The chain stays inspectable, questionable and overridable, which meets the briefing's intent without its numbers.
- **Who is told:** the PWS author, explicitly, at rubric calibration.
- **Left open for discuss-phase:** whether a bucketed why-line (for example "strong: 2 hops, through Lateral Thinking") is exposed beyond the stamp line. D8 holds either way: a bucket word is allowed, a number is not.

**Composition expectations, fixed before judging** (briefing Brain Audit, mirror `06-brain.md`):
- **What the canon looks like:** in Theo's canon, `CrossDomainInnovation` (15 nodes) and `DomainBridge` (5 nodes) carry **0 edges**, and exactly one Framework node represents an actual algorithm ("Algorithmic Generation of Reverse Salient Solutions").
- **What to expect on cross-domain pairs:** a **high unverified rate** and **heavy hub routing**.
- **How they are recorded:** both as explicit metrics with no target.
- **How a high unverified rate is reported:** as a canon-coverage finding, sent upstream to Theo's content backfill (SEED-096, `355-BRIEF.md:293`), with the Framework-pair list attached. It is **not a phase failure**.

**Labeling:**
- **Blindness is provable, not asserted.** Each gold fixture carries `labeled_by` (a role, never a name), `labeled_at` and a `_labeling_note` (the 353 `evals/icm/cases/turns.json` precedent). It is committed before the first `tests/fixtures/355-jev-*-responses.json` exists, and a test checks that git order.
- **Hit-rate order, so a stamp cannot anchor its own judgment:**
  1. The navigator judges the unstamped baseline first.
  2. The navigator judges the stamped output in a later sitting, with pairings shuffled.
  3. The per-tier rate is computed in code by joining the **blind (unstamped) judgments** to the stamps.
  4. The stamped-pass rate is recorded beside it as the as-shown rate. The gap between the two is recorded as the stamp's influence on the reader, not as usefulness.
  5. Pairings that appear only in the stamped output are judged once and flagged.
- **Disagreements:**
  - If a second blind labeler is available (Section 1b, recommended), they label >= 30 thinking-mode sentences, >= 15 citation pairs and >= 10 pairings per room.
  - Exact agreement and Cohen's kappa are computed in code.
  - The navigator's label stays gold. The second label is stored beside it, and every disagreement is listed in the record.
  - Disputes the PWS author settles carry `adjudicated_by: pws-author` and a one-line reason.
  - Without a second labeler, the record says "one labeler".
- **Timeline:**
  - Sets (i)-(iii) are authored and labeled in the first wave, before the direction module, the stamp adapter or the Jev scripts land.
  - The fixture rooms are built during implementation.
  - Judging happens only after the stamp renders on all five producers and the Theo `tools/list` precondition is recorded.
- **Reference points, not targets:**
  - The briefing's MVP bar, "50%+ of top-10 findings judged 'interesting'" (Implementation Detail timeline), may be quoted next to the measured rate as the briefing's own reference point. It is **not** this phase's target.
  - The briefing's three-signal convergence rule is not a baseline either, because it has never been run. The only baseline is today's raw eureka / find-connections output.

## 6. Guardrails

Four online guardrails, all already in the design and all cheap. None of them calls a model; the runtime makes zero Jev calls this phase.

### Online (Real-Time)

| Guardrail | Trigger | Intervention |
|-----------|---------|--------------|
| **Part 8 egress guard.** Existing: `lib/core/part8-egress-guard.cjs` behind the brain-client, plus the PreToolUse hook `scripts/part8-egress-guard-hook.cjs` (`hooks/hooks.json`). Covers critical failure 3; D9. | Any Brain-bound call whose arguments are not a known safe shape. In this phase, anything other than `find_connections {from, to}` with canon handles. | **Block.** The call is refused with `egress_blocked`. The stamp becomes `unverified / unavailable / egress_refused`, and the finding is still shown. A count of `egress_refused` above 0 is an adapter defect, surfaced and never hidden. |
| **Refusal-inside-success stamp.** `stampFinding` plus `Stamp.strict().superRefine` (Sections 4 and 4b). Covers critical failures 1 and 4; D5, D6. | Theo returns null, throws, refuses, answers `paths: []`, sends a malformed answer or a hop mismatch; or a local endpoint does not resolve; or a stamp object fails to parse. | **Flag.** The stamp says `unverified` with the backend and reason, and the line reads "may be novel or hallucinated - verify with a domain expert". It never carries a path and is never dropped. A stamp that fails to parse is replaced by `unverified / malformed_response`; it is never rendered as it was. |
| **No-decimal render check.** Covers critical failure 5; D8. | A code-rendered stamp line or reach card (CLI) is about to carry a bare 0.00-1.00 value. | **Block.** By construction, the stamp is composed from enums and path names only, so a number has no field to ride in. The CLI renderer's final assertion refuses the offending token and renders the stamp without it. A local `memory_event` names the producer (no content). **Limit, stated plainly:** Larry's Desktop / Cowork prose is generated by the host and cannot be filtered by plugin code at runtime. It is covered offline instead, by the D8 prose fixtures and the flywheel sampling below. |
| **Proposed-only write.** Canon Part 9; critical failure 5; D10. | An accepted finding is filed through the harvest path. | **Block.** The node lands as `review_status: proposed` through `navigation.cjs`. Only `gate_answer` promotes it; any other path to `confirmed` is refused at the chokepoint. |

**Dev-time guardrails** apply to every Jev call, and only in `scripts/`. They run online within a measurement run, and they are why a dev-time number can be trusted.

| Guardrail | Trigger | Intervention |
|-----------|---------|--------------|
| **Per-question egress ceiling** (Finding 1) | The payload is not exactly the frozen shape: a non-fixture sentence, an untemplated claim, a path Theo did not return, an extra key, an edited question. | **Block.** The ceiling throws before `fetch()`. |
| **Model pin** (Finding 2) | A response reports a `model` other than `jev-1.13.0`. | **Block.** The run aborts. |
| **Input-token tripwire** (Section 4) | `usage.input_tokens` exceeds 8,000 on any call. | **Block.** Stop and inspect the state. Do not raise the limit. |
| **Denominator guard** (pitfall 9) | Any non-200 or schema failure after one retry. | **Block.** The run exits non-zero. An accuracy is never reported on fewer items than the fixture holds. |
| **Key hygiene** | A 401. | **Block.** Abort the run and never print the key. |

Expected to be high (the Brain Audit: the cross-domain node types have 0 edges). | The action depends on which reason dominates. **`no_path_within_3_hops` or `endpoint_unresolved`:** this is a **canon-coverage finding, not a phase failure.** Report it upstream to Theo's content backfill (SEED-096) with the Framework-pair list. **`handle_unresolved`:** vocabulary mismatch; note it for the later Terminology Translation phase. **Any `egress_refused` or `malformed_response`:** an adapter defect; fix it before judging continues. |

## 7. Production Monitoring

**Tracing Tool:** **Override: the Arize Phoenix default is not used.** There are three reasons.
- **No new dependencies, CJS only, no Python.** Phoenix is a Python package plus a local server.
- **Nothing to trace at runtime.** The runtime makes zero model calls this phase (`judge: none`).
- **No central store is allowed.** Canon Part 8 means no user data leaves the machine, so no central trace store may receive it.

Tracing is done instead with the repo's own instruments:
1. **The phase record.**
   - `355-VERIFICATION.md` holds the hit rates, Theo `find_connections` latency p50/p95 (not measured in any spike yet; this is its first measurement), the tier and reason mix, the hub share and the unverified rate.
   - `355-JEV-MEASUREMENT.md` holds the model id per run, the question sha256, the fixture sha256, calls, tokens, cost, the accuracy cuts and the recorded decision.
2. **The resolved Jev model version, per run and per response.** The run aborts on drift (Finding 2), and a replay is valid only for the model stored with it.
3. **Local `memory_event` through `navigation.cjs`**, pinned by a test in the `tests/test-reverse-salient-telemetry.cjs` idiom. The test checks four things: an exact key set; zero user-content strings in any payload; emission on the all-unverified path too; and the `MINDRIAN_DISABLE_MEMORY_EVENT` resilience contract. Proposed events (names final in discuss-phase):
   - `cross_connection_stamped` with `{producer, finding_count, tier_counts, reason_counts, backend, judge, theo_ms_bucket}`;
   - `cross_connection_gate_outcome` with `{finding_id, tier, direction, response}`.

   Both stay local and never egress.
4. **The `cross-connection-honesty` point in `doctor.cjs --acceptance`** (Section 5), on every pre-tag and full run.

**Key Metrics to Track:**
1. **Stamp coverage** (must be 100%) and **finding-count equality** between what the engine produced and what was rendered, per producer.
2. **Tier distribution and unverified reason mix** per producer. The unverified rate and the hub-inflation share are explicit, with no target.
3. **Theo `find_connections` latency p50 / p95**, first measured on the fixture rooms.
4. **Hit rate per tier vs the unstamped baseline**, always with n.
5. **The provenance of every recorded number:** the Jev model id, the question and fixture sha256, and the Theo canon version or date.

**Alert Thresholds:**
- **Hard.** Each of these fails the run or blocks the release, with no judgment call:
  - stamp coverage below 100%;
  - any engine finding missing from the render;
  - any bare 0.00-1.00 in a covered surface;
  - any `path` on an unverified stamp;
  - any Jev payload reaching `fetch()` without passing its ceiling;
  - model drift;
  - any non-200 left in a measurement run;
  - a replay that differs from its record;
  - any `TYPESAFE_API_KEY` or `api.typesafe.ai` under `lib/` or `hooks/`;
  - SENS-13 firing anything other than exactly once;
  - any `confirmed` without `gate_answer`;
  - a doctor acceptance failure outside the documented baseline.
- **Investigate.** These go to the flywheel and never block:
  - any `egress_refused` or `malformed_response` stamp;
  - `backend_unavailable` on 100% of a run while Theo's `tools/list` includes `find_connections`;
  - Theo p95 above 2x the first recorded p95. That threshold is set from the first measurement, not guessed now;
  - the unverified rate or hub share moving between two runs on unchanged plugin code. That means Theo's canon moved: record it and report it to Theo, never absorb it;
  - a gate acceptance rate near 100%.
- **Never an alert:** a high unverified rate on its own. That is the expected canon-coverage signal, reported upstream (Section 6).

**Smart Sampling Strategy:**
- **100% human review, flagged by signal:**
  - stamps with `egress_refused` or `malformed_response`;
  - `strong` stamps whose path crosses a top-decile hub;
  - findings whose direction came from a near-tie (inside the direction module's tie band);
  - citation-check items below confidence 0.8 (routed to a human by rule);
  - thinking-mode items where Jev and the regex disagree, and items where Jev's confidence is below 0.9;
  - every false-friend mark.
- **Every Larry prose fixture that renders a stamp:** they are few; each is code-checked, and a human reads it once.
- **A random 10% of the remaining stamped findings per fixture run**, for the PWS author's periodic read.
- **Not sampled: live user rooms.** Part 8 and the SPEC keep this phase on dev-repo fixture rooms. Extending measurement to real ventures needs its own decision, and would be the next calibration point after this one.
