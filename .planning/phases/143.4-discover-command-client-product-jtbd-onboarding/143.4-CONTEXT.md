# Phase 143.4: /mos:discover - Client + Product + JTBD Onboarding - Context

## The one-paragraph why

A web/UX firm never starts with pixels; it starts by understanding three souls - the brand, the product, and the users' jobs - through a guided, multi-turn conversation, then turns that into a brief that makes every later decision strategic. MindrianOS has every atom for this (`/mos:new-project`, `/mos:analyze-needs`, `/mos:user-needs`, `/mos:beautiful-question`, `/mos:persona`, `/mos:jtbd`, conversation-mode "Build a Room") but no single Larry-led discovery flow that sequences them and lands a navigator from "I have a client/product" to a scaffolded Data Room + a Discovery Brief. This phase ships `/mos:discover` as that flow - and, per the 143.3 Connector Contract, it JOINS the spine by declaring connector frontmatter rather than hardcoding a route. It is the FIRST product command authored to ride the self-extending connector spine.

## Locked decisions (navigator, 2026-06-07)

1. **Own phase = 143.4** (not folded into 143.3). 143.3 ships the contract + orchestrator; 143.4 is the first real command declaring against it.
2. **Orchestration, not a new atom (Canon Part 7).** `/mos:discover` SEQUENCES existing methodology commands; it does not duplicate them. Every step names which existing command it reuses; net-new surface limited to the flow + the brief/scaffold synthesis.
3. **No 6th reach (143.2 freeze respected).** Discovery maps onto existing sensors/reaches; it adds NO reach_id and NO new selector format. It renders through the 143.1 Shape F.1 dial.
4. **Output is a room, not just a doc.** The flow produces a Discovery Brief AND scaffolds a Data Room (ICM Layer 0 ROOM.md per folder); personas+JTBD land as artifacts; the Hooked habit-loop lands as a filed section.
5. **Part 8 hard.** All discovery content (brand soul, product, personas, JTBD, client specifics) is LOCAL room data. Brain queries carry generic handles only (framework names, phase ids). Zero client-content egress.

## Requirements

### The command
- **DISC-01:** `commands/discover.md` - Larry-led `/mos:discover`. Reuses the conversation engine + AskUserQuestion Shape F.1 selector (no bespoke dialog). Carries the connector frontmatter (DISC-05).
- **DISC-02:** the six-movement investigation, MindrianOS-native and ONE question at a time: (1) real why / stakes, (2) brand soul (archetype + voice + "never says"), (3) product essence (one core job, business case, constraints), (4) users + JTBD (functional/emotional/social + what they fire + trigger), (5) competition / whitespace, (6) the product as a Hooked loop. Adapts order to navigator input; spends turns where energy + ambiguity are.
- **DISC-03 (Part 7 reuse map):** each movement routes to an existing atom - warm-up/why -> beautiful-question; brand soul -> persona/six-hats; product essence -> new-project + lean-canvas; users+JTBD -> analyze-needs/user-needs + jtbd; competition -> compare-ventures/whitespace. The plan MUST justify, per movement, "which existing command this reuses and why a thin orchestration beats a new atom."

### The outputs
- **DISC-04:** synthesis - write the Discovery Brief (brand soul, product essence, persona+JTBD cards, positioning, habit loop, design implications, open-questions/assumptions) AND scaffold the Data Room sections with ROOM.md identity; file personas + the habit-loop section as artifacts; mark every guess as an assumption (Canon Part 5 evidence tiering + Part 9 proposed-not-confirmed).
- **DISC-07:** Hooked, two ways - (a) the brief's habit-loop section (Trigger -> Action[B=MAP] -> Variable Reward[tribe/hunt/self] -> Investment) with the Facilitator-quadrant ethics check; (b) the command's OWN engagement loop (visible brief-taking-shape as the investment hook). The four Hooked stages are INLINED from the ported `question-bank.md` Hooked worksheet (reconciliation 2026-06-07: there is no in-repo `hooked-model` skill to read; do not point a `read_first` at one - embed the stages, optionally noting the globally-available `hooked-model` skill as a runtime reference only).
- **DISC-10 (Feynman simplification - the brief-to-message bridge):** discovery uncovers the complex truth; this step translates it into plain, compelling language - the load-bearing handoff from discovery to any website/deck build. After synthesis, run the Feynman 6-stage pipeline (reduce to essence -> plain language -> expose confusion -> build the mental model -> simplify until it breaks -> teach it back) over the product essence + brand soul to produce: (a) the plain-language messaging the website hero + value-prop consumes (the "explain it to a smart twelve-year-old" line from the question bank, sharpened), and (b) optionally a YC-grade deck. The Discovery Brief gains a **Plain-language message** section (one-liner + the value-prop ladder), and `FEYNMAN.md` for the scaffolded room's sections is seeded from it (Canon Part 9). **Part 7 reuse:** the in-repo `MOSDeckEngine` skill is the canonical Feynman surface (no standalone `feynman-engine` skill dir or `slides` command exists in this repo) + `/mos:mos-reason` (Feynman-MINTO reasoning, Part 4) for the reasoning pyramid; plain-language message by DEFAULT, deck on request.
