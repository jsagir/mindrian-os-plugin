# Phase 89.2 Plan 05: fetcher-experts Summary

**Experts post-processor that extracts deduped author records from the academic fetcher's papers[] output, sorts deterministically by paper count and name, and gates the output through a defense-in-depth auditQueryObject scan even though the module introduces no new network egress surface.**

## Objective

Ship lib/core/rs-fetcher-experts.cjs with mapExperts(papers, opts) as the Wave-2 experts post-processor for Phase 89.2. Despite the rs-fetcher-experts.cjs naming convention (chosen for Wave-2 grouping), the module is NOT a fetcher and makes no outbound calls. It walks papers[] from the academic fetcher (Plan 89.2-02) and emits experts[] as a normalized 6-field record per deduped author, ready for downstream 89.5 rs-expert-mapper.cjs to MATCH against the user's own Aura via Cypher.

## What Shipped

### lib/core/rs-fetcher-experts.cjs

- mapExperts(papers, opts) public entry point.
- scrubScalar(s) helper: returns null on FORBIDDEN_PATTERNS hit, empty string, or non-string input; passes other strings through unchanged.
- isPublicEmail(paper, author) helper: 3-layer check (PUBLIC_EMAIL_SOURCES allow-list + strict PUBLIC_EMAIL_REGEX + FORBIDDEN_PATTERNS scan).
- computeHIndexEstimate(citations) helper: standard h-index over a citation list. Empty list returns 0.
- extractAuthorRecord(paper, author) helper: per-occurrence intermediate record builder.
- dedupExperts(papers) helper: composite-key authorMap aggregator over all (paper, author) pairs.
- ExternalEgressViolation re-exported for instanceof callers (single-source-of-truth via require of 89.2-01 shared module; never re-defined).

## Key Decisions

- **Post-processor, not fetcher.** The module name follows the rs-fetcher-* Wave-2 naming convention but it does NOT fetch. The module reads papers[] from the academic fetcher's output (already validated + audited at the network boundary by Plan 89.2-02) and walks it locally. No new external egress surface is introduced.
- **Defense-in-depth audit anyway.** auditQueryObject(experts, 'experts') runs pre-return as the third tripwire even though there is no outbound call. This is conservative because downstream Plan 89.5 rs-expert-mapper.cjs writes to the user's own Aura (still NOT the Brain), and the experts[] output is the lineage. Auditing at this seam ensures any forbidden bytes that slip past the upstream academic fetcher cannot smuggle into the Aura write.
- **PUBLIC_EMAIL_SOURCES = Object.freeze(new Set(['openalex'])).** Locked per kickoff section 15 open-question-4. OpenAlex emails are public via the OpenAlex authorships.author.email field. All other sources (Scopus, IEEE, Nature, arXiv, PubMed) route to public_email_or_null = null whether or not they happen to carry an email payload.
- **Three-layer isPublicEmail check.** (1) source allow-list, (2) strict PUBLIC_EMAIL_REGEX, (3) FORBIDDEN_PATTERNS scan. Each layer is independently sufficient to drop a malicious or malformed email; all three required to promote one into output.
- **Composite-key dedup (name|orcid).** Authors without ORCID disambiguate by name alone via "__no_orcid__" sentinel suffix. Authors with the same name but different ORCIDs are treated as different people. First-non-null wins for institution + email when an author appears across multiple papers.
- **Helper field stripped from output.** dedupExperts internally tracks citations_per_paper for h-index computation, but the final experts[] output drops this field. Only the contracted 6-field shape leaks. Test 1 explicitly fences this invariant.
- **Standard h-index computation.** computeHIndexEstimate sorts citations descending, walks h from sorted.length down to 1, returns the first h such that sorted[h-1] >= h. Determinism guaranteed.
- **opts parameter reserved for forward compatibility.** Currently unused; preserved in the signature so future plans can add knobs (e.g. min_paper_count filter) without changing the API.
