# Phase 89.2 Plan 04: Fetcher Industry Summary

Tavily-orchestrated industry-signal fetcher with TWO-LAYER Canon Part 8 chokepoint and graceful degradation when Tavily is unavailable.

## Objective Met

Ships `lib/core/rs-fetcher-industry.cjs::fetchIndustry(queries, opts)` -- the industry-signal egress surface for Wave 2 of Phase 89.2. Single source: Tavily orchestration only. The Tavily MCP is already in the plugin stack (CLAUDE.md tech stack); we do NOT re-implement Crunchbase direct. Each user query expands to 3 frozen-order refined sub-queries that target startup-database content (Crunchbase / Pitchbook), corporate R&D announcements, and early-stage funding rounds.

The TWO-LAYER audit pattern is the load-bearing innovation of this plan:
- **Layer 1** -- `auditQueryString(userQuery, 'industry')` runs on the raw user query before any refinement.
- **Layer 2** -- `auditQueryString(refinedSubquery, 'industry')` runs on EACH refined sub-query AFTER template substitution but BEFORE the URL/body is constructed.

Layer 2 is necessary because a clean user query can still be combined with an `opts.refinement_template_override` that smuggles a forbidden pattern into the refined sub-query. Test 10 (meeting-via-override) and Test 11 (phone-via-override) exercise the second layer explicitly.

## Patterns Adopted from Wave 2 Siblings

**From 89.2-02 (academic):**
- Frozen `SOURCES` array; iteration order = dedup tie-breaking order
- Frozen `SOURCE_ENV_VARS` for env-key-gated sources
- `fetchWithTimeout` as the ONE native-fetch call site (chokepoint exclusivity)
- `parseRateLimit` probing common header names
- Per-source dispatcher pattern (parity with academic + patents shape)

**From 89.2-03 (patents) -- Pattern 6 + Pattern 7:**
- **Pattern 6** -- Pre-flight Canon Part 8 audit. fetchIndustry walks ALL queries through `buildIndustryQuery` (which itself runs auditQueryString at both layers) BEFORE the source/sub-query loop runs. This ensures adversarial input throws BEFORE any fetch() call, so tests can assert ZERO captured URLs / bodies on adversarial scenarios.
- **Pattern 7** -- INDUSTRY_SOURCES gate in validator. Per-source / per-entry checks scope to `'tavily'` only via `INDUSTRY_SOURCES` Set. Mirrors `PATENTS_SOURCES` in external-patents-invariants.cjs. Prevents duplicate warnings across academic + patents + industry validators on the shared global ledger (`~/.mindrian/telemetry/external-papers.json`).

## Industry-Specific Innovations

1. **TWO-LAYER audit chokepoint.** The 89.2-04 PLAN added Test 11 to ensure the second layer catches forbidden patterns ACROSS THE FULL FAMILY of FORBIDDEN_PATTERNS (not just meeting-fragment). Test 11 specifically targets the phone-like regex `/\b\+?1?[\s.\-]?\(?\d{3}\)?[\s.\-]?\d{3}[\s.\-]?\d{4}\b/` via an opts override. The second-layer audit catches it before the URL is built.

2. **POST + body capture.** Unlike academic/patents which use GET, Tavily uses POST with a JSON body. The test harness captures `opts.body` so the A1 sweep scans BOTH outbound URLs and request bodies for forbidden patterns.

3. **Refined sub-query fan-out.** Each user query expands to 3 sub-queries (controlled, frozen-order). The test harness mocks one Tavily handler and asserts exactly 6 fetch calls for 2 user queries (Test 1). Determinism is the dedup invariant.

4. **Deterministic company extraction.** `extractCompany(url, title)` derives a Title-Cased company name from the URL's second-level domain, falling back to the first capitalized title token, then to `'Unknown'`. NO LLM, NO global state.
