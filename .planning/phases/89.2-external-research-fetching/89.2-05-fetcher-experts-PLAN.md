<objective>
Ship `lib/core/rs-fetcher-experts.cjs` with `mapExperts(papers, opts)` -- the experts post-processor for Wave 2 of Phase 89.2.

**Critical:** Despite the file naming convention (`rs-fetcher-experts.cjs` for Wave-2 grouping), this module is NOT a fetcher. It is a POST-PROCESSOR over academic-fetcher output. NO network egress. NO fetch() calls. NO Canon Part 8 chokepoint required for outbound queries (because there are none).

What it does: extracts authors + institutions + ORCID from academic fetcher results (papers[]) and emits a deduped `experts[]` array with one record per author. Output feeds 89.5 (`rs-expert-mapper.cjs`) which writes to user's Aura via Cypher.

Privacy stance per kickoff §15 open-question-4: **public author emails from OpenAlex are ALLOWED** (Canon Part 8 compliant since the data is already public via the OpenAlex API's authorships.author.email field). Anything behind a login wall (Scopus per-author profile, IEEE author profile when not in API response) is SKIPPED (public_email_or_null = null).

Determinism: same papers[] input -> same experts[] output. Sort order: paper_count descending then name ascending (deterministic tie-break).

Defense in depth: even though no network egress, mapExperts runs `auditQueryObject(experts, 'experts')` pre-return. Mirrors 89.1 Plan 02 `auditOutput` pattern. Throws ExternalEgressViolation on FORBIDDEN_PATTERNS hit. This is conservative because downstream 89.5 expert-mapper writes to Aura (user-owned graph -- still NOT Brain) and the experts[] output is the lineage; we audit at the boundary.

NO new validator (no telemetry surface). NO Feynman registration (Plan 89.2-08 sweep).

Purpose: Ships SC-04 (rs-fetcher-experts.cjs exports mapExperts producing 6-field author records) + partial SC-10 (Canon Part 8 enforcement on experts post-processor output via auditQueryObject defense-in-depth). 4 adversarial Canon Part 8 scenarios cover the four input vectors that could carry forbidden patterns into expert lineage: name, email, institution, and paper-source-or-id.
</objective>
