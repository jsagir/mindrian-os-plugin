# Phase 89.2: External Research Fetching (EXPANDED) + Preprocessing + Scoring + Thesis + Experts -- Context

## Phase Boundary

**Delivers (Phase 1.5 + Phase 2 + Phase 3 + Phase 4 of canonical Reverse Salient framework, per kickoff §5):**

### Phase 1.5 -- 4 External Fetchers (NEW egress surfaces)
- `lib/core/rs-fetcher-academic.cjs` -- consumes 60-query matrix from `rs-query-matrix.cjs::generateQueryMatrix`. Existing v1.10.16 baseline (OpenAlex + arXiv + Tavily) lives in `lib/core/rs_corpus.py` -- this CJS module wraps + extends it with NEW sources: Scopus + PubMed + IEEE + Nature/Science via native `fetch`. Output: deduped paper objects with `{id, title, abstract, authors[], institution, doi, source, fetched_at}`.
- `lib/core/rs-fetcher-patents.cjs` -- NEW: Google Patents + USPTO via native `fetch`. Output: deduped patent objects with `{patent_id, title, abstract, inventors[], assignee, filing_date, source, fetched_at}`.
- `lib/core/rs-fetcher-industry.cjs` -- NEW: Crunchbase + corporate R&D + startup tracker queries orchestrated through Tavily (existing `mcp__tavily-mcp__tavily-search` MCP, already in stack per CLAUDE.md tech stack). Output: structured `{company, signal, source, url, fetched_at}` records.
- `lib/core/rs-fetcher-experts.cjs` -- NEW: extracts authors + institutions + ORCID from academic fetcher results (post-processor; does NOT directly fetch). Output: `{name, orcid, institution, paper_count, h_index_estimate, public_email_or_null}` records. Per kickoff §15 open-question-4: public author emails from OpenAlex are allowed (anything behind login: skip).

### Phase 2 -- Preprocessing
- `lib/core/rs-preprocessor.cjs` -- NEW: Phase 2 of canonical framework. Per-document deterministic processor producing `{technical_terms[], concepts[], methods[], relevance_score, boundary_flag}` from raw fetcher output. NO runtime LLM round-trip from CLI surface (89.1 precedent: deterministic decomposition seeded by substrate metadata).

### Phase 3 -- Detection + Classification + Scoring
- `lib/core/rs-differential-scorer.cjs` -- NEW: dual-floor filters per kickoff §5: pair passes IFF `diff > 0.3 AND LSA > 0.2 AND BERT > 0.2`. Consumes existing `rs_math.py` (Kwan 2023 LSA) + `rs_cache.py` (Pinecone multilingual-e5-large BERT). Output per pair: `{diff, lsa, bert, passes}`.
- `lib/core/rs-innovation-classifier.cjs` -- NEW: deterministic rule-based classifier on differential-scorer output. Produces one of `structural_transfer | semantic_implementation | hybrid` per pair (per kickoff §5 Phase 3 enumeration).
- `lib/core/rs-breakthrough-scorer.cjs` -- NEW: 0-10 rubric across 5 dimensions per kickoff §5 (`feasibility + market + magnitude + advantage + impact`). Deterministic weighted sum from substrate metadata + classifier output. Output: `{score: 0-10, breakdown: {feasibility, market, magnitude, advantage, impact}}`.

### Phase 4 -- Synthesis
- `lib/core/rs-thesis-generator.cjs` -- NEW: emits `"By applying [X] to [Y], achieve [Z] because [mechanism]"` template fill from classifier + breakthrough scorer outputs (kickoff §5 Phase 4). Pure template fill. NO runtime LLM. Output: thesis string per scored pair.

### Cross-cutting Canon Part 8 enforcement
- Each fetcher (4 modules) introduces a NEW external-egress surface. Each MUST inherit the 89.1a 5-tripwire pattern (kickoff §8):
  - **T1** schema doc: cache + fetcher I/O schemas explicit in source comments

### Per-source rate-limit + graceful degradation
- Mirror Phase 88.6-03 telemetry pattern: per-source budget tracked in `external-papers.json queries[]` (existing JSON, append-only). Each query record carries `{source, query_text_hash, status, rate_limit_remaining, http_status, fetched_at}`. Hash the query text -- never persist the literal (Canon Part 8 compliance even in telemetry).
- Per-source budget = per-source-default with override via `opts.budget`. Default values: OpenAlex 100/day, arXiv 100/day, Scopus 50/day (if API key absent: budget=0, skip), PubMed 100/day, IEEE 50/day (if API key absent: budget=0, skip), Nature 25/day, Google Patents 50/day, USPTO 50/day, Tavily orchestrated 30/day.
- 429 / 503 responses: degrade gracefully -- log telemetry record with `status="rate_limited"`, return empty for that source, continue with remaining sources. NEVER throw on rate-limit (only on Canon Part 8 violation).

### Strict 1024-dim Cosine over Local Substrate (deferred-from-89.1 resolution)

Per RESUME §Deferred Items: 89.1's substrate cache carries `score` field (not 1024-dim `embedding` array) on live wire path because Pinecone `searchRecords` MCP tool has no `include_values=true` flag (per 89.1 lock-in evidence: `mcp-server-brain/lib/pinecone-tools.cjs:47`).

**Decision (planner formalizes during planning):**
- Option (a): 89.2's `rs-differential-scorer.cjs` invokes `rs_cache.py` Pinecone-direct (NOT through brain-client MCP) with `include_values=true` to fetch real 1024-dim vectors for the dual-similarity computation. Pinecone Python SDK supports include_values natively. CJS->Python bridge already exists (used by 89.1a substrate fixture path).
- Option (b): defer dual-similarity to 89.3. 89.2 ships preprocessor + classifier + breakthrough scorer + thesis on score-only substrate (cheaper, faster). Differential scorer becomes a stub returning `{passes: true}` for all pairs in 89.2; real dual-floor filter wired in 89.3.

**Recommended (planner judgment):** Option (a). Rationale: (1) real differential scorer is Phase 3's core value; (2) `rs_cache.py` already exists and supports the call; (3) no new external dependency; (4) 89.3's scope (mind map + Aura schema) is independent and shouldn't carry algorithmic debt from 89.2. Counter-argument: if Pinecone-direct call adds significant latency or rate-limit pressure, defer is acceptable. Planner verifies per-call latency in research/planning phase.
