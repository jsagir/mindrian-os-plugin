<objective>
Ship Phase 2 (preprocessing) + Phase 3 detection-floor of the canonical Reverse Salient framework. Three new CJS modules:

1. **lib/core/rs-pinecone-bridge.cjs** -- thin CJS shim that spawns python3 with `rs_cache.py` imports + JSON-over-stdio. Returns `{hits: [{id, score, values: 1024-dim, metadata}]}`. The bridge is the load-bearing piece that resolves the strict-1024-dim-cosine deferred item from 89.1: `rs_cache.py::fetch_all_from_namespace` ALREADY returns `values` (1024-dim embeddings) per its existing v1.10.16 contract -- no Wave-0 prerequisite needed.

2. **lib/core/rs-preprocessor.cjs** -- Phase 2 of the canonical framework. Per-document deterministic processor producing the 5-field output `{technical_terms[], concepts[], methods[], relevance_score, boundary_flag}` from raw fetcher output (papers/patents/signals all flow through the same preprocessor with source-aware extraction).

3. **lib/core/rs-differential-scorer.cjs** -- Phase 3 detection. Dual-floor filter per kickoff §5: pair passes IFF `diff > 0.3 AND LSA > 0.2 AND BERT > 0.2`. The pair-wise LSA cosine is computed via an embedded sklearn TfidfVectorizer + TruncatedSVD subset (DELIBERATE Canon Part 7 carve-out -- documented in must_haves and in source comments). BERT cosine consumed via the new pinecone-bridge that wraps existing rs_cache.py (Canon Part 7 reuse, no carve-out). Graceful degradation: if bridge fails (no PINECONE_API_KEY, network error, namespace empty), falls back to LSA-only with bert=null + warning='bert_unavailable'.

**Canon Part 7 carve-out: pair-wise LSA cosine.** `rs_math.py::build_tfidf_svd` is the authoritative Kwan 2023 LSA implementation -- but its API expects `Sequence[str] >= 3 documents` and fits a corpus-wide IDF + SVD basis. A pair-wise comparison (1 query_concept vs 1 doc_concept = 2-document mini-corpus) cannot consume that API without forcing degenerate corpus statistics: a 2-document IDF is meaningless, and a 1-component SVD does NOT correspond to Kwan's algorithm. The pair-wise question requires fresh per-pair TF-IDF + SVD fit, which is what `lsaBridgeScript` does. `rs_math.py` continues to be consumed in its corpus-mode use case (e.g., `scripts/rs-engine.py` for corpus reverse-salient computation per Phase 89). To avoid a future drift toward "all LSA goes through one path," this carve-out is documented in (a) the plan's must_haves block, (b) source comments at the top of `rs-differential-scorer.cjs`, and (c) `# BSL 1.1` + carve-out justification comment block at the top of `lsaBridgeScript`.

**Strict 1024-dim cosine decision (Option a from CONTEXT.md):** verified `rs_cache.py::fetch_all_from_namespace` already returns 1024-dim `values` per its existing v1.10.16 contract (lib/core/rs_cache.py lines 397-455). No new Pinecone API surface needed; bridge is a thin JSON-over-stdio shim. **NO Wave-0 prerequisite plan needed.**

Combined into one plan because preprocessor and differential scorer are tightly coupled: differential scorer takes a query_concept + doc_concept (both produced by preprocessor's concepts[] field). Splitting into two plans would create a Wave 3 -> Wave 4 chain where Wave 4 has only one test surface; combining keeps the dependency graph flat (Wave 2 fetchers -> Wave 3 preprocessor+scorer -> Wave 4 classifier+breakthrough+thesis).

**Note on depends_on:** Plan 06 depends only on Plans 02 + 03 + 04 (the 3 egress fetchers), NOT on Plan 05 (experts post-processor). Experts is a parallel post-processor over academic output that emits a different output path (experts[]); preprocessor consumes documents[] from the 3 egress fetchers. Wave 3 starts only after Wave 2 completes (so Plan 05 is on disk by then), eliminating any race condition.

Purpose: Ships SC-05 (rs-preprocessor.cjs exports preprocess deterministic 5-field output) + SC-06 (rs-differential-scorer.cjs exports score returning {diff, lsa, bert, passes}).
</objective>
