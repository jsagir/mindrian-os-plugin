Replace it: the new class I + class J code MUST resolve via `resolveActivePluginRoot()` from `lib/core/active-plugin-root.cjs` (Plan-2 extended it with the `topology` field). Treat the legacy path as ONE branch of the topology enum, not the only path. Existing class A (`checkInstallVersion`) keeps its current semantics, but its "missing" finding on a marketplace-only box is reinterpreted by class I (per Bug 7 -- per D-11): topology=='marketplace-cache' is VALID, not drift; only `not-found`, or a declared-vs-actual mismatch, is drift.

   - **Record present + internally consistent.** `~/.mindrian/install-state.json` exists, parses, has all 9 D-04 keys (`active_version, active_root, topology, resolved_at, surfaces, installed_plugins_version, statusline_renders_version, last_version_file_value, path_bin_version`).    - **Topology classification (D-11, Bug 7 fix).** Read `topology` from the record (or the live resolver if the record is absent). Each of `marketplace-cache | dev-clone | legacy | not-found` is VALID. ONLY `not-found` is drift. A `legacy` topology on a box that also has a valid marketplace-cache install is "legacy-clone migration candidate" (flag with `recoverable: true`, `--fix` performs the backup-verify-remove migration per D-13). The "no legacy clone dir on a marketplace box" finding that class A produces today must be reinterpreted (or muted) by class I.
   - **6-way version-of-record equality.** Compare `installed_plugins.json` `plugins["mos@mindrian-marketplace"][0].version` (call it IP) <-> record.`active_version` (AV) <-> record.`statusline_renders_version` (SR) <-> the SessionStart-banner version (recorded by `session-start` as part of the record OR inferred from the most recent session log) (SB; if not available, skip this leg of the comparison rather than fail) <-> `~/.mindrian-last-version` file content (LV) <-> the `$PATH` plugin-bin entry's `.../mos/<v>/bin` segment (PB). **String equality, NOT `semver.valid`** -- the active install on the dev box is `1.12.5.1` (a 4-component non-semver string); the equality check must tolerate it. Any divergence is a drift finding; the remediation depends on which legs disagree (e.g. AV != LV -> `--fix` rewrites LV; AV != SR -> "likely active-plugin-root.cjs bug, file it"; AV != IP -> "record stale, re-run session-start").
   - **--fix scope (D-13):** auto-recover missing record (run `session-start`'s record-write path -- spawn `bash $PLUGIN_ROOT/scripts/session-start --record-only` if such a flag exists, else `bash $PLUGIN_ROOT/scripts/session-start` and verify the record landed); rewrite `~/.mindrian-last-version` to match `installed_plugins.json`; conservative `installed_plugins.json` repair (only when demonstrably stale -- points at a version dir that no longer exists, OR is missing the `mos` entry while a valid marketplace-cache dir is present; prefer "repoint the entry at the newest valid marketplace-cache dir" over a wholesale rewrite; back up first via the existing class-A `safeRename` pattern; emit a `note: "Claude Code must be restarted to re-read installed_plugins.json"` finding; ONE backup file per repair).
   - **Legacy-clone migration (D-13):** ONLY when topology classification confirms the path is `legacy` (specifically `~/.claude/plugins/mindrian-os/`) AND a separate `dev-clone` test (via `git -C <root> remote get-url origin` containing `mindrian-os-plugin` case-insensitive, OR `MINDRIAN_OS_ROOT` pointing at it) confirms it is NOT a dev clone. NEVER delete the active root.
