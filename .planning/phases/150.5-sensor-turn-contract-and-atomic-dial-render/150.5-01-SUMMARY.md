# Phase 150.5 Plan 01: Sensor Turn-Contract Repair Summary

One-seam dispatchSensors entry normalization (text alias + two side-channel
signal fuels, additive merge, never mutating the caller turn) revives the 5
structurally-dead sensors against the exact production turn shape, proven
RED-first by a 21-arm firability suite with a turn-builder drift fence.

## What was done

### Task 1: RED -- tests/test-150-5-sensor-firability.cjs (commit b8a26534)

Created the 21-arm regression suite driving the REAL `dispatchSensors` with the
EXACT production turn shape `{ userText, sectionPath, sessionId }` (fixtured
from scripts/intent-classifier.cjs:1351, never hand-shaped):

- 8 fire arms (one per registered sensor) + a 9th additive-merge arm proving
  caller-supplied signals and derived signals coexist in one dispatch
- 8 honest-negative arms (neutral text; absent/empty side-channels; STALE
  side-channels backdated via `fs.utimesSync` beyond `SIGNAL_FRESHNESS_MS`;
  no decision signal; non-commit-near stage; same-slug jtbd re-set; no cortex
  scalars) plus an extra absent/empty file-fuel arm
- Turn-builder DRIFT FENCE: source-greps the classifier's builder block for
  `/userText:\s*conversationSeed/`, `/sectionPath:\s*sectionPath/`,
  `/sessionId:\s*sessionId/` and asserts NO bare `text:`/`signals:` keys --
  if the hook ever enriches the turn, the suite flags itself for re-derivation
- NO-MUTATION FENCE: `Object.keys` + `JSON.stringify` of the caller turn are
  byte-identical across dispatch (the D-03a structural guarantee)
- SEAM-EXPORT arm with a guarded require (a missing export reports FAILED,
  never a crash)

RED proof on pre-seam main (verified before the GREEN commit): exit 1 with
6 FAILED arms naming `lagging_component`, `external_fact`, `first_material`,
`artifact_filed`, the additive-merge lane, and the absent seam exports. The
passthrough methodology arm, both already-live state sensors (gate_approach,
jtbd_changed, memory_cortex), and all honest negatives were green on main.

### Task 2: GREEN -- the one-seam normalization (commit ae7f0870)

In lib/core/insight-sensors.cjs, added and exported three symbols and wired
the chokepoint:

1. `SIGNAL_FRESHNESS_MS = 30 * 60 * 1000` -- the side-channel freshness window
2. `deriveTurnSignals(ctx)` -- pure-LOCAL, sync, soft-fail-to-[]: derives
   `'artifact_filed'` from a FRESH `<roomDir>/.mindrian/last-cascade.json`
   with non-empty `proactive_intelligence.newFindings` (the same gate
   sensorArtifactFiled re-checks) and `'first_material'` from any FRESH
   `<roomDir>/.mindrian/auto-explore-*.json` fire marker. stat-before-parse
   (mtime gate runs before any JSON read); returns closed-enum kind strings
   only, never file content (threat T1)
3. `normalizeTurn(turn, ctx)` -- a shallow enriched COPY
   (`Object.assign({}, turn)`): `text = turn.text || turn.utterance ||
   turn.userText || ''` (existing text/utterance always win); `signals` = the
   deduplicated union of caller signals (preserved verbatim, objects included)
   and the derived kinds. NEVER mutates the input
4. `dispatchSensors` normalizes ONCE at entry, wrapped so a normalization
   fault degrades to the raw turn; every sensor in the registry loop receives
   the normalized copy. No sensor file edited (one seam, not eight patches)

The Phase 144 fence is untouched: no `routing_source` assignment, no
`decide()` call, `REACH_IDS`/`POSTURE_IDS` byte-intact. Module header extended
with the seam + two-fuel documentation lines.
