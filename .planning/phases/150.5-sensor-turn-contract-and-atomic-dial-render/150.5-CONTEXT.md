## Finding A -- the sensor turn-contract break (root cause of "never triggered")

The hook builds the production turn at scripts/intent-classifier.cjs:1351:

    turn = { userText, sectionPath, sessionId }

Against that shape, in lib/core/insight-sensors.cjs:

| Sensor | Reads | Why it can never fire |
|---|---|---|
| sensor-lagging-component | `turn.text \|\| turn.utterance` | key mismatch vs `userText` |
| sensor-external-fact | `turn.text \|\| turn.utterance` | key mismatch vs `userText` |
| sensorFirstMaterial | `turn.signals` | hook never populates `signals` |
| sensorArtifactFiled | `turn.signals` | hook never populates `signals` |
| sensorMethodologyDecision | `turn.signals` | hook never populates `signals` |

Only 3 sensors (gate-approach, jtbd-reweight, memory-cortex) are live-firable,
and each needs room state most rooms lack (venture_stage set; a real JTBD
transition; a non-empty cortex projection). Net effect on a typical machine:
fire_skill stays null, routing_source stays legacy, the dial never renders.
Live evidence: motj-ecosystem decision traces 2026-06-09, every turn
routing_source=legacy, 'Tier 0 fallback: BRAIN.md absent', room.db 163KB with
navigated_neighborhood=null and edges_consulted=0.

Fix shape (SENS-FIX-01): normalize at ONE seam -- either the hook enriches the
turn (userText + text alias + signals fed from shipped side-channels:
.mindrian/last-cascade.json proactive_intelligence, auto-explore fire markers)
or dispatchSensors normalizes its input. One seam, not eight sensor patches.
SENS-FIX-02: the regression suite must drive dispatchSensors with the EXACT
turn object the hook builds (require the builder or fixture it from the real
code path), one fire arm + one honest-negative arm per sensor.
