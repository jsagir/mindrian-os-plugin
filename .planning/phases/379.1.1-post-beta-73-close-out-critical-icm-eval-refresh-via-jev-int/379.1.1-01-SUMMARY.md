## How the gate works now

- `loadIgnoreRules(root)` reads only `<root>/.gitignore`. `isIgnored(rules, relPath)` follows the plan: comments and blanks skipped, `!` negation, trailing `/` directory-only, a `/` inside the rule anchors it at the root, `**`, `*`, `?` converted to regex, last matching rule decides.
- The `fail` closure takes the absolute path. A covered target goes to `ignored_generated` as `{file, target, pattern}`. Any other target goes to `failures`.
- Exit stays 1 only when `failures` is not empty. Plain output adds `, N skipped as gitignored generated` to the summary line and one `  skipped: FILE -> TARGET (PATTERN)` line per skip. With no skip the OK line is byte for byte the old line.
- SKIP_DIRS, SCAN_DIRS, resolves, mask and argSpan are untouched.

## Risk of the wider exemption

A require into `node_modules/` that points at a package missing from `package.json` would no longer fail this gate on a clone, because the target is missing in the clone and `node_modules/` is gitignored. The gate does not check dependencies. Missing dependencies stay covered by other checks (npm-shrinkwrap tests such as `tests/test-341-shrinkwrap-no-dev.cjs`, and the loader's `npm ci`). The risk is limited by the printed skip line: the reviewer sees every `node_modules` skip in the gate output. A broader `.gitignore` line (for example `*.cjs`) would also hide real breaks. The gate trusts the repo's own tracked root `.gitignore`.

Other limits: only the root `.gitignore` is read. A require without a file extension (`require('./__nav-stub')`) tests the path as written, so a rule that names `__nav-stub.cjs` would not cover it. That case fails loudly, not silently.
