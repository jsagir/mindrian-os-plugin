## Working definition (ASSUMED)

No file in the repo defines "Layered Context Access". The working definition is ASSUMED. It reads the term as the three-layer read of room context by the navigation engine:

- mode_a: the Brain is reachable, and a usable BRAIN.md is present.
- mode_b: the Brain is offline, and a BRAIN.md marked `brain_offline` is present.
- tier_0: no usable BRAIN.md, or no quadruple.

The navigator must confirm or correct the term before promotion.

The probe reads two fixture rooms and calls three pure functions. It makes no network call and no Brain call. It writes nothing. Two runs gave equal bytes (PROVEN: cmp). `git status --porcelain tests/fixtures` printed nothing after the run (PROVEN).

Two facts follow from the table:

1. The first four shapes give tier_0 whatever the Brain state. A missing or broken BRAIN.md decides the tier. The Brain flag does not.
2. With the Brain unreachable, a fresh BRAIN.md still gives tier_0. Only a BRAIN.md marked `brain_offline` gives mode_b.

## Why does a session sit at tier_0

Short answer: the Brain flag is nearly always true, so it is not the cause. The cause is the BRAIN.md of the one section the session reads, or the absence of that section.

1. `brainAvailable` is true in nearly every session. `isAvailable()` in lib/core/brain-client.cjs (line 244) returns true when a URL string is set. The default URL is set on line 41. The session path in scripts/intent-classifier.cjs (lines 2296 to 2305) copies that value. PROVEN (code read, and the probe prints `is_available: true`). It does not test that the Brain answers.
2. The session reads one section only. `resolveActiveSectionPathForRoom` (scripts/intent-classifier.cjs line 1002) returns the section in `.mindrian/active-section.json`. If that is absent, it returns the newest section that holds a MINTO.md. If it finds none, the quadruple is null and the result is tier_0 (truth table row 1). PROVEN (code read).
3. A section without BRAIN.md gives `brain` null, and the result is tier_0 under either Brain state (truth table row 2). PROVEN (probe on both fixture rooms: 5 of 5 sections).
4. Newly born rooms hold a BRAIN.md face. lib/core/navigation/room-birth.cjs writes it at birth (line 867 for the root stub, lines 1625 to 1629 for each core section face). PROVEN (code read). So a room born on a current version should not sit at tier_0 for this reason. A legacy room, or a section added later, can.
5. The only refresh path for an existing room is the derive queue and the manual command. Details are in the writer trace below. The auto-fire entry point `ensureSectionDerived`, written to lift the tier for an un-derived section, has no caller outside its own file and the tests. PROVEN (grep of lib, scripts, hooks, bin, mcp and docs; excluded: tests, node_modules, .planning, .claude).
6. Whether the navigator's own live session is at tier_0, and for which of the causes above, is UNVERIFIED. The probe did not measure it.
