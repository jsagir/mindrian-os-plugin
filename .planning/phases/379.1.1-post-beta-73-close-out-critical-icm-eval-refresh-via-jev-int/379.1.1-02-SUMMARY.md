# Phase 379.1.1 Plan 02: Named Step 2.3 ledger rebuild Summary

release.sh now has a named Step 2.3 that rebuilds the section-command ledger with the Jev-scored builder only when the offline check says it is stale, a standalone `--ledger-only` mode, a dry-run line, and the unchanged Step 2.4 staleness gate after it.

All code lives in the release tree `/home/jsagi/dev/MindrianOS-Plugin-release` (branch main). Nothing was pushed. No real cut ran. The live Jev rebuild did not run.

## Root cause (PROVEN)

The Jev-scored rebuild had no step in `release.sh`. A comment above Step 2.4 said the rebuild was "never a release.sh step". So the beta.73 cut met it as a manual surprise, and the dry-run could not list it. The ledger is stale today: `node scripts/build-section-command-ledger.cjs --check` prints `plugin_version drift: ledger=2.0.0-beta.72 repo=2.0.0-beta.74` (exit 1).

Order fact: the rebuild is a commit, so it moves HEAD, and Step 2.6 needs a real-room receipt for the exact HEAD. So Step 2.3 sits after the Step 2 verify block and before Step 2.4, 2.5 and 2.6. A cut with a stale ledger runs the step in place and Step 2.6 then refuses until a receipt exists for the new HEAD. The operator avoids that with `--ledger-only` before the real-room read.

## Deviations from Plan

**1. [Rule 1 - Bug] The standalone mode died under set -e**
- **Found during:** Task 2, test leg W7. The library took the check status with a bare `$?` after a command substitution. `release.sh` runs under `set -euo pipefail`, so a failing check ended the whole script before the verdict. Tests had run the function without `set -e`, which hid it.
- **Fix:** the library takes the status with `|| check_rc=$?` and guards the version pipe with `|| true`; the standalone call uses `|| LEDGER_ONLY_RC=$?`. Added test S9, which runs the function under `set -euo pipefail` (stale dry run and full rebuild).
- **Commit:** 1307192bb.

**2. [Rule 1 - Bug] Usage text broke two pinned tests**
- **Found during:** the baseline re-run. `test-release-cut-listener-wiring` pins `[--no-cut-listener] [--dry-run]` as adjacent. `test-release-keyholder-notice` pins 16 bracket entries.
- **Fix:** `[--ledger-only]` moved out of the pair; the usage text now ends with `| bash scripts/release.sh --ledger-only (alone, no bump flag; add --dry-run to preview)`, which adds no bracket entry.
- **Commit:** e5c2d0827.

**3. [Rule 3 - Blocking] Pinned exit count in another test**
- **Found during:** the same re-run. `test-release-keyholder-notice` pins the count of non-comment `exit 1` lines in release.sh at 70. The plan adds 3 aborts (missing-library guard, bump flag with `--ledger-only`, Step 2.3 ABORT). The pin moved from 70 to 73 with a comment. This follows the earlier re-pin convention (quick 261007-c6j). `tests/test-353-release-wiring.cjs` was not edited.
- **Commit:** e5c2d0827.

**4. [Plan detail] Dry-run verdict for a current ledger**
- Under `--dry-run` a current ledger also prints `[DRY RUN]`, so the verdict line exists whether the ledger is stale or current. Without this, test W7 and W8 would depend on the ledger being stale and fail after plan 10 rebuilds it.
