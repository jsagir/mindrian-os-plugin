# Phase 127.3 Plan 01: jtbd-update.cjs Chokepoint Refactor Summary

## One-liner

Replace `scripts/jtbd-update.cjs`'s two independent broken registry walks with single-source-of-truth calls into the Plan 00 chokepoint (`lib/core/resolve-active-room.cjs`); end the ~7-month JTBD-memory-layer silent-failure regression that shipped in every release since v1.11.x.

## Context

The RCA (`.planning/debug/jtbd-auto-anchor-silent-failure/jtbd-auto-anchor-silent-failure.md`) identified `scripts/jtbd-update.cjs:65-79` `resolveActiveRoom()` as the silent-failure root cause: the function read against an obsolete registry shape (expected legacy `reg.active_room` + Array `reg.rooms`; actual writes current `reg.active` + Object `reg.rooms`), returned `null` on every call, `main()` short-circuited at line 132, the classifier never fired, `jtbd-state.json` never got written, and `/mos:memory` reported `0/0/0` forever for every Larry session since 2026-04-26.

PATTERNS.md flagged the DUAL REGISTRY WALK landmine: the same file ALSO carried a hand-rolled registry walk at lines 196-214 inside the Phase 103-05 across-session promotion block, which tolerated the legacy Array shape but missed the current Object shape's slug derivation (fell back to `path.basename(roomDir)`).

Plan 00 (commits 62ce006f, 728fc33c, bc2c76bf) shipped `lib/core/resolve-active-room.cjs` as the canonical resolver with the 3-function public API. This Plan 01 makes `scripts/jtbd-update.cjs` the FIRST consumer of that chokepoint.
