**2. [Rule 1 - Semantic-mismatch bug fix on check-onboard-statusline detectSealedRoom]**

- **Found during:** Task 5
- **Issue:** Plan Task 5 instructed to reroute `detectSealedRoom()` through the chokepoint. But `detectSealedRoom()` semantically wants the INVERSE of the chokepoint -- it wants to detect WHEN the nominal active room IS sealed; the chokepoint FILTERS sealed rooms out. Rerouting would always return null (defeats the function's purpose). Cannot extend the chokepoint with a non-filtering accessor without violating Plan 00's byte-stable export contract (landmine #3).
- **Fix:** Rewrote `detectSealedRoom()` with shape-tolerant local read (current `reg.active` + Object `rooms`; legacy `reg.active_room` + Array `rooms`); added detection for `room.status === 'sealed'` alongside legacy `room.sealed === true`. Injected `slug` field on Object-shape entries so downstream `room.slug` references continue to work. File added to tripwire ALLOW (10th entry) with TODO Phase 129 noting the semantic-inverse mismatch.
- **Files modified:** `scripts/check-onboard-statusline.cjs`, `tests/test-127.3-sibling-sweep.sh`
- **Commit:** `8c77a296`
