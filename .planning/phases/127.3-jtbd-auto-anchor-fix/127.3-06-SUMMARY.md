## What Was Built

Three additive surfaces lock the Phase 127.3 fix into the codebase as a regression fence:

### 1. tests/test-jtbd-auto-anchor-empirical.sh (NEW, 230 lines, executable)

Two-half empirical reproduction of the RCA's "Reproduction Steps" protocol:

**Half 1 (Plan 01 + Plan 00 hook end-to-end):**
- Fresh test room via `scripts/room-registry create` (Plan 04 also seeds USER.md / STATE.md / ROOM.md / .mindrian/).
- Seeds `.mindrian/conversation-operator.json` with `current: BUILD_ROOM` so the classifier threshold stays at 0.6 (default JUST_TALK would raise it to 0.8 AND boost the 'explore' fallback because JUST_TALK is in explore's operator_affinity).
- Fires `scripts/jtbd-update.cjs userprompt` with a 4-cue decide-pursue message: `"should we pursue this idea, pivot or double down or kill it or keep it"`. Saturates the tokens stratum (normalize(>=3) = 1.0 -> 0.5) plus +0.3 BUILD_ROOM operator boost -> confidence 0.8.
- Asserts `<roomDir>/.mindrian/jtbd-state.json` was created with `current.jtbd === 'decide-pursue'`.

**Half 2 (Plan 00 slug resolution + Phase 103-05 across-session promotion):**
- Calls `lib/core/resolve-active-room.cjs::resolveActiveRoom()` directly; asserts the chokepoint returns `{ slug: 'test-jtbd-127.3-empirical', abs_path: ... }` (proves canonical-slug return, not `path.basename` fallback).
- Constructs a synthetic 3-row within-session history for `decide-pursue` and calls `lib/hmi/across-session-memory.cjs::promoteIfEligible` with `manual=false` so the `>= 3 turn_count` gate triggers.
- Asserts `in_flight` for the test slug contains `decide-pursue` AND that `~/MindrianRooms/.memory/jtbd-history.json` was lazily bootstrapped by the across-session pipeline (third symptom from the RCA's actual: section).

**Deviation rationale (Rule 1 fix; plan's `<action>` note explicitly authorizes this):** the verbatim "fire 3 times with same message" from the RCA's Reproduction Steps does not reach `turn_count >= 3` on current code because the `isTransition` gate in `jtbd-update.cjs:115-122` short-circuits subsequent same-confidence calls. Only ONE history row lands; `promoteIfEligible` never fires its `>=3` gate. Splitting into two halves on their canonical surfaces faithfully reproduces the RCA's INTENT (every layer alive, not silently dead) without fighting the throttle.

## Deviations from Plan

### Rule 1 -- Bug Fix: Two-half empirical protocol (Task 1)

- **Found during:** Task 1 (empirical test first-run iteration; the verbatim PATTERNS.md draft failed because the classifier+isTransition combination cannot produce 3 transitions from 3 same-cue messages).
- **Issue:** PATTERNS.md draft used a single-cue message ("should we pursue this idea") + no operator seed. With default JUST_TALK, threshold raises to 0.8 AND `explore` gets +0.3 affinity boost, beating `decide-pursue`'s 0.17 -- classifier returns null/below_threshold, state file never written, false-negative test that masks drift instead of catching it. Even with a 4-cue message + BUILD_ROOM operator seed (confidence 0.8), the `isTransition` gate (delta > 0.15) short-circuits subsequent same-confidence calls; only ONE history row lands, `turn_count = 1`, `promoteIfEligible` never reaches its `>= 3` gate.
- **Fix:** Two-half protocol per the plan's `<action>` note authorization ("use whichever cue / protocol triggers the same decide-pursue outcome"). Half 1 tests hook end-to-end via the user-prompt event surface; Half 2 tests across-session promotion via `promoteIfEligible` with a synthetic 3-turn history. Together they cover the canonical surfaces of both layers in the RCA's three-defect cluster.
- **Files modified:** `tests/test-jtbd-auto-anchor-empirical.sh` (Task 1).
- **Commit:** `c6479651`.
