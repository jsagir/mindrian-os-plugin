## Deviations from plan

### [Rule 3 -- Blocking issue auto-fixed] Parallel-session git index race on Task 2 commit

- **Found during:** Task 2 commit step (after empirical verification + acceptance gates all passed)
- **Issue:** Plan 04 ran in parallel with Plan 03 on the same working directory + same `.git/index`. After staging only `scripts/room-registry` (and verifying via `git diff --cached --stat` that nothing else was staged), the `git commit` call fired -- but in the same window, Plan 03's parallel session was also committing. Plan 03's `git add scripts/operator-command.cjs` + `git commit` ran first, and because the git index is global to the working tree, that commit FOLDED my staged `scripts/room-registry` changes into Plan 03's commit (commit SHA `99958b6e`, message `feat(127.3-03): Task 4 -- operator-command.cjs rerouted through chokepoint`). My subsequent `git commit` call found an empty index and was a no-op.
- **Functional outcome:** Both Plan 03 Task 4 (operator-command.cjs) AND Plan 04 Task 2 (scripts/room-registry bootstrap-missing) changes ARE on main HEAD. All acceptance criteria pass. The functional release is complete and correct.
- **Attribution outcome:** Commit `99958b6e` carries both Plan 03's and Plan 04's content but its message describes only Plan 03's work. A reviewer reading `git log --oneline` will see Plan 04 Task 2 only via Plan 03 Task 4's commit body file-stat list, not as its own line.
- **Recovery options considered:**
  - Option A: `git reset --soft HEAD~1` + re-commit Plan 03's operator-command.cjs as its own commit, then re-commit my Task 2 as its own commit. **REJECTED** -- destructive git operation per execution rules; would require Plan 03's executor cooperation; non-zero risk of losing one or the other's work in the rebase.
  - Option B: Add a clarifying commit on top: `docs(127.3-04): note that Task 2 content landed in 99958b6e via parallel-session index race`. **DEFERRED** -- adds historical commit noise without functional value; the SUMMARY.md (this file) is the canonical record.
  - Option C: Document the race in this SUMMARY and move forward. **CHOSEN** -- pure documentation, zero git rewrite, future maintainers see the rationale in the canonical phase record.
- **Prevention guidance for future parallel executions:** when two executors run in the same working directory, the `.git/index` is a shared resource. Atomic-per-task commits require either (a) serial commit ordering coordinated by the orchestrator, (b) per-executor git worktrees (`git worktree add`) so each executor has its own index, or (c) a commit-level mutex (file lock around `git add` + `git commit`). For one-time hotfix scenarios with parallel plans like 127.3, option (c) is the cheapest mitigation; option (b) is the structural fix.
- **Files modified:** scripts/room-registry (final content of the file IS my Task 2 work; attribution is the only issue)
