# Phase 127.3: JTBD Auto-Anchor Silent-Failure Fix (with chokepoint extraction)

## Source RCA

Full diagnostic with 3-layer root cause, evidence chain, refuted/confirmed hypotheses, proposed fixes with diffs, reproduction steps, and verification protocol lives at:

`.planning/debug/jtbd-auto-anchor-silent-failure/jtbd-auto-anchor-silent-failure.md`

This CONTEXT.md is the GSD scaffolding around that RCA. Do not relitigate the diagnostic; read the RCA first.

## JTBD

When a user opens Larry in a fresh room and starts a multi-hour exploration session, the JTBD classifier is supposed to detect their job-to-be-done from natural conversation cues ("should we pivot", "what's the real problem", "decide-pursue") and accumulate in-flight JTBD evidence that surfaces via `/mos:memory`. The user expects: by turn N of a serious session, `/mos:memory` reports an in-flight JTBD with confidence rising as the same cue type repeats.

**Actual today:** 24+ artifacts filed in a multi-hour session, `/mos:memory` reports `in_flight: 0, parked: 0, completed: 0` forever. The JTBD memory layer is silently dead in every release shipped since v1.11.x.

The job: make turn 1 onward of every fresh-room Larry session start accumulating JTBD evidence, so the auto-anchor mechanism actually anchors.

## Goal

Land a three-defect fix in `v1.13.0-beta.34`:

1. **PRIMARY:** Patch `scripts/jtbd-update.cjs:65-79` `resolveActiveRoom()` to tolerate both registry shapes (legacy `active_room` + Array `rooms` AND current `active` + Object `rooms`). Returns the correct room dir on first call. Classifier runs. State file gets written. Hysteresis works. `/mos:memory` populates.
2. **SECONDARY:** Extract `lib/core/resolve-active-room.cjs` as the Canon-Part-7 shared chokepoint that THREE sibling scripts (intent-classifier.cjs, jtbd-update.cjs, across-session-memory.cjs) consolidate against. Phase 129's spine-repair work absorbs the OTHER 6 spine scripts onto the same helper. The 2026-05-24 RCA explicitly names this as the structural fix that retires the contract-drift class.
3. **TERTIARY:** Bootstrap fix in `scripts/room-registry create` -- seed `<roomDir>/USER.md`, `<roomDir>/STATE.md`, `<roomDir>/ROOM.md` (Canon decision 15), `<roomDir>/.mindrian/` (directory only; do NOT seed jtbd-state.json -- absence is correctly handled and writing an empty file would mask the legitimate first-write event). Closes the `intent_persona = all-null` symptom that has shown up in every decision trace since fresh-room sessions started running through intent-classifier.
4. **TERTIARY+:** Add first-touch JTBD nudge to `scripts/memory-resume-nudge.cjs` (or sibling) for empty-state rooms: fires when active room exists AND jtbd-state.json absent AND room age < 7 days. Closes H5 (the resumption-only nudge gap).

Zero perceived behavior change for working code paths. Every test that depended on the broken silent-exit behavior was already broken-as-shipped and will continue to be broken-as-shipped if any exists (none do per the RCA evidence).

## Design decisions (locked from 2026-05-24 RCA)

### D-01: Ship the chokepoint (Fix 2) in this hotfix, not in Phase 129
Phase 129 (spine-repair-memory-event) is the canonical long-term venue for "scripts that bypass navigation.cjs". But Phase 129 ships v1.13.1-beta.3 (multiple weeks out per EXECUTION-PLAN Wave 4 Stream F). Phase 127.3 needs to ship in v1.13.0-beta.34 right now. The right architectural call is: ship the chokepoint helper (`lib/core/resolve-active-room.cjs`) in 127.3, refactor jtbd-update.cjs to use it, and leave the OTHER 6 spine scripts (mos-status, suggest-next, act, pipeline, jtbd, operator, memory) for Phase 129 to absorb onto the same helper. This delivers the Canon Part 7 win NOW for the load-bearing script + sets up Phase 129 to be a pure repointing operation later.

### D-02: Do NOT seed jtbd-state.json on room creation
Fix 4 in the RCA explicitly notes: seed `.mindrian/` (directory only); do NOT seed `jtbd-state.json` itself. Absent-file is correctly handled by every reader; writing an empty file would mask the legitimate first-write event in audit logs. Same applies to `operator-state.json`. The directory makes the path navigable; the file appears on first real classifier hit.

### D-03: First-touch nudge gates on room age < 7 days
The H5 fix (first-touch nudge) MUST gate on room age to avoid pestering users who intentionally left a room blank. 7 days is the agreed window. After 7 days, an absent JTBD is a deliberate choice and the nudge stops. Implementation: stat the room's ROOM.md mtime; compare to now; gate the nudge accordingly.

### D-04: Sibling sweep is mandatory
The RCA Fix 1 calls for `grep -nE 'reg\.active_room|Array\.isArray\(reg\.rooms\)|room\.abs_path|room\.sealed === true' scripts/ lib/`. Any other script copying the broken pattern needs the same fix in the same plan. Without the sweep, the bug regenerates as soon as another script that quietly copied the pattern fires.

### D-05: Test coverage is the verification protocol from the RCA
RCA section "Reproduction Steps" provides 6-step before-and-after fixtures. The plan's test suite is the protocol from the RCA, not a re-derivation:
- Before fixture: `rm -rf ~/MindrianRooms/test-jtbd-bug && bash scripts/room-registry create test-jtbd-bug test-jtbd-bug` then probe -> no state file
- After fixture: same room, run hook 3x with same cue -> state file exists, promoteIfEligible fires, `.memory/` exists
- Sibling sweep test: grep assertion that no script in `scripts/` or `lib/` matches the broken pattern

### D-06: Doctor probe is OPTIONAL in this hotfix
RCA Fix 3 proposes `scripts/doctor.cjs --check-jtbd` as a sibling to `--check-rs-engine`. NICE-TO-HAVE for this hotfix; SHOULD-HAVE for Phase 129. Lands in plan as an optional sub-task; can defer to 129 if scope pressure surfaces during planning.
