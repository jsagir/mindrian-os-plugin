# Phase 127.3 Plan 00 -- Wave-0 Single-Resolver Chokepoint Extraction

## One-liner

Canon-Part-7 single-resolver chokepoint (`lib/core/resolve-active-room.cjs`) lands as the consolidation point for the FOUR-place registry-shape guesser drift that has kept the JTBD memory layer silently dead since v1.11.x. Public API trio + CLI entry + 12 hermetic scenarios all green; Wave 1 (Plans 01 + 02 + 03) is unblocked.

## What shipped

### `lib/core/resolve-active-room.cjs` (NEW -- 199 lines)

The Canon-Part-7 single-resolver. Mirrors the structural shape of `lib/core/resolve-brain-key.cjs` (the Phase 123 Plan-07 precedent):

**Public API** (`module.exports`):

| Function | Returns | Used by |
|----------|---------|---------|
| `resolveActiveRoom(opts)` | `{ slug, abs_path }` or `null` | Full-shape consumers (Plan 02 intent-classifier reroute) |
| `resolveActiveRoomSlug()` | `string` or `null` | Slug-only consumers (statusline, mos:status) |
| `resolveActiveRoomDir()` | `string` or `null` | Dir-only consumers (Plan 01 jtbd-update.cjs reroute) |

**Precedence chain** (first hit wins):

1. `CLAUDE_ACTIVE_ROOM` env override (test/operator seam)
2. `MINDRIAN_ROOMS_HOME/.rooms/registry.json` `active` field + Object `rooms` (current shape; the live production registry layout)
3. Same registry file, `active_room` field + Array `rooms` (legacy shape; the v1.11.x and earlier layout still carried by `jtbd-update.cjs:65-79`)
4. `null` (not-found, never throws)

**Sealed/archived disposition:** `entry.sealed === true` OR `entry.status` in `{sealed, archived}` returns `null`. The registry's job is to mark; the resolver's job is to honor the mark.

**abs_path resolution:** `entry.abs_path` wins; else `entry.path` (resolved relative to home if not absolute); else compose `<home>/<slug>`. Final gate: `fs.existsSync(abs_path)` -- a registry pointing at a deleted directory is treated as stale and returns `null`.

**HOME default:** `process.env.HOME || process.env.USERPROFILE || os.homedir()` -- NOT bare `os.homedir()`. This is the FLAG-3 landmine from `resolve-brain-key.cjs:21-26`: on Linux/POSIX, `os.homedir()` reads `/etc/passwd` and ignores `process.env.HOME`, breaking hermetic mkdtempSync-based tests. Source-asserted by `rar.9` analog in resolve-brain-key tests; structurally present here (verified via `grep -c "process.env.HOME.*USERPROFILE" lib/core/resolve-active-room.cjs` returning 2).

**Graceful degradation:** top-level `try/catch` returns `null` on any unexpected error. NEVER throws. Mirrors the `jtbd-update.cjs:248-255` envelope -- Larry must never block on a resolver failure.

**CLI entry:**

```bash
$ node lib/core/resolve-active-room.cjs
{"slug":"mof-procurement-workshop","abs_path":"/home/jsagi/MindrianRooms/mof-procurement-workshop"}
$ echo $?
0
```

Exit-code distinction (0 on hit, 1 on miss) lets bash wrappers shell out and dispatch without a JSON parser. This is a deliberate departure from `resolve-brain-key.cjs` (which always exits 0 because its result has nuanced reason+source fields); the active-room shape is null-or-object and maps cleanly to exit-code semantics.
