Author role: elephant (EGM). Status: draft for goldfish review. Evidence for each code claim is in 400.2-RESEARCH.md (section numbers are cited as R-n). Labels: PROVEN, UNVERIFIED, ASSUMED (a guess), DEFAULT CHOSEN (owner may overrule). Owner rulings in 400.2-CONTEXT.md are locked and are not re-opened here.

## 1. Problem

`/mos:persona` promises six hat lenses built from the room and six independent readings. Today:
- No step writes a reasoned persona file; the parallel run requires files that only a template preview writes (R-2 check 3).
- The six hats reason over the room only; `web_scope` is null.
- The research leg that exists for `/mos:bono` has no door, no approval check and no string check, and the hat does not change what is searched (R-1, R-2).
- A hat that fails disappears from the result; nothing says "not run" (R-8 pitfall 5).

## 2. Goals and non-goals

Goals (S1 to S7 plus cycle v2):
- G1. Six personas produced from the room by six fresh `persona-analyst` runs.
- G2. White researches first and shares its package. Black, Yellow and Green research their own side. Red and Blue never search.
- G3. One approval card for each researching hat with its exact strings (4 cards).
- G4. Six independent readings; a hat cites only the White package and its own sources.
- G5. A merge that records dissent first, uses only the tension map, keeps attribution, and adds nothing.
- G6. Two named modes: deep and quick. Triage chooses.
- G7. Personas live until the room changes.
- G8. A recorded comparison of deep and quick on one question.
- G9. The capability carries nine jobs as equals.

Non-goals: a new agent; a loop until agreement; any agent-side confirmation; a change of `/mos:bono` behaviour; an MCP tool for the research leg; a fix of `HAT_LENS_BIAS`; a change of the `produces` path; a benchmark suite.

## 4. Design

### 4.1 The ten-step cycle

| Step | Who | What | Gate |
|---|---|---|---|
| 1 Triage | Larry | recommend deep or quick; the navigator picks | F.1 |
| 2 Brief | Larry | target, governing question, reading list (room paths) | F.6 |
| 3 Produce | 6 fresh agents | one persona for each hat, only when personas are missing or stale | F.8 (accept or rebuild each) |
| 4 Shared facts | door | White strings, card, fetch, White package | F.0 (card 1) |
| 5 Private research | door | Black, Yellow, Green strings, one card each, fetch | F.0 (cards 2 to 4) |
| 6 Readings | 6 fresh agents | each hat reads the target alone | none |
| 7 Check | door | citation boundary, per-hat rules, not-run list | none |
| 8 Merge | door, then Larry | deterministic artifact; Larry narrates it | none |
| 9 Rulings | navigator | one ruling for each tension | F.5 |
| 10 Measure | door | optional comparison record of deep and quick | none |

Quick mode is steps 1, 2 (short brief), then one pass of six hats in the main context (`analyzeAllPerspectives`), then step 9 as an option. It makes no agent run and no fetch.

Triage rule (Larry recommends, the navigator decides): quick when the target is one artifact and the question needs no outside fact; deep when the question needs outside evidence, or the decision is costly to reverse. An unattended caller (`/mos:act`, `chain_run`) always gets quick (precedent `commands/dominant-designs.md:89`).

### 4.2 Mode identity

- Deep keeps the entry `/mos:persona --parallel` and adds the alias `deep`. Reason: `tests/test-265-persona-route.cjs` and the MCP route name `persona --parallel` (R-6).
- Quick keeps the entry `analyze` and adds the alias `quick`.
- Each output starts with one fixed line. Deep: "Deep review: six isolated hats, own research, own reading." plus, when true, "Research not run for: <hats>." Quick: "Fast look: six hats in one pass, one context, no research. This is not an independent review." The quick line is a constant `QUICK_NOTICE` in `persona-ops.cjs`, in the style of `PREVIEW_NOTICE` (`:103`).
- If a deep step runs in the main context for any reason, the output says "same-context run" for that hat (EGM rule).

### 4.3 The door (one new script)

`scripts/persona-hats.cjs`, the one CLI door for every deterministic step. Justification under Part 7: the Bono leg has no door at all (R-1 item 2), and prose-only wiring is what failed. Precedents: `scripts/dominant-design-research.cjs`, `scripts/close-loop.cjs`. Input always from a JSON file path, never argv text. The Bono modules are required lazily inside the door only.

Subcommands:
- `status --room`: persona freshness (4.7).
- `write-persona --room --spec <file>`: validate one persona spec and write `personas/<hat>-<domain>.md`.
- `plan-research --room --hat --persona <file>`: compose strings, audit, list providers. No network. Writes `<scratch>/<hat>.plan.json` with `q_hash` of each string.
- `run-research --room --hat --plan <file> --approved <file>`: fetch and wire. Writes `<scratch>/<hat>.evidence.json`.
- `check-reading --hat --reading <file> --evidence <own> --shared <white>`: step 7.
- `merge --room --run <dir>`: step 8. Writes the review artifact and the run record.
- `compare --room --deep <run.json> --quick <run.json>`: step 10.

How `run-research` reuses the Bono leg:
- One `runCellFanout` call for each hat: `hats: [Hat]`, `subdomains: approvedStrings` (2 or fewer), `selfCritique: keep-all`.
- `dispatchCell` is a wrapper around `personaDispatchCell`. It adds `ctx = {db, roomDir, sessionId: 'persona-<run>-<hat>'}`, sets `subdomain: 'personas'` (the INFORMS target, R-3 Q4), injects an `extractContextFn` that removes the `brain` lens, passes no `brainFn`, and stores the full reading (with `wired_sources`) in a side map.
- Each approved string must equal `genericDomainHandle(string)`. This proves that the string on the card is the string sent.
- Result state for each string: `ran_with_results`, `ran_empty`, `failed:<reason>` (the stub with `error`), `refused:<reason>`.

### 4.4 Search strings

- The persona builder proposes 2 or fewer generic domain handles (4 words or fewer each).
- The door composes the string: handle plus a fixed 2-word hat qualifier. Table `HAT_RESEARCH_QUALIFIER` (provisional wording): White `data statistics`; Black `failure cases`; Yellow `success cases`; Green `analogous solutions` (Green imports from other fields). This is where the hat scope becomes real; today it is prose only (R-2 check 4). It also gives each hat its own cache entry.
- The navigator may edit a string on the card. An edit goes back through the same audit (precedent `lane-queries.cjs:172-192`).

### 4.5 What each hat sees

| Input | Produce step | Reading step |
|---|---|---|
| Hat discipline (fixed: `HAT_DEFINITIONS` + `HAT_GOVERNANCE` text) | yes | yes (in its persona file) |
| The brief | yes | yes |
| Room sections | yes, except `personas/` | reading list only |
| Own persona file | n/a | yes |
| White shared package | n/a | yes (all six hats) |
| Own evidence pack | n/a | yes (Black, Yellow, Green) |
| Another hat's persona, evidence (not White) or reading | no | no |
| The conversation, Larry's view | no | no |
| Run ledger (counts and states only, no content) | no | Blue only |

Enforcement, stated plainly:
- Fresh context: each hat is a separate Agent call (mechanical on CLI).
- Reads: a prompt contract only. The agent `Read` tool is unscoped and the tools list is pinned by a test.
- Web: the dispatch prompt forbids WebSearch and WebFetch in these roles. The mechanical check is after the fact: any citation outside the allowed id set fails step 7.
- Citations: `validateCitations` with `wired_sources = own ids + White ids`. A violation marks the reading `rejected:citation_outside_sources`; it is reported as not run. It is never repaired by the merge.

The agent file is not edited (test S7, R-7). The two role contracts (persona builder, isolated hat reader) and their JSON return shapes live in the dispatch prompt text of `commands/persona.md`. Cost of this choice: `agents/persona-analyst.md:58,64` keep two sentences that are wrong for this command. Owner item O-3.

### 4.6 Per-hat rules (step 7)

| Hat | Check in `check-reading` | Reuse |
|---|---|---|
| White | `enforceGovernance('white')`; `missing_data` is a list (may be empty only with a stated "nothing missing"); evidence from own package | existing rule + 1 new field check |
| Red | zero evidence items; `enforceGovernance('red')` (no justification) | existing rule + 1 new check |
| Black | `enforceGovernance('black')` (disconfirming first); the hat sets `disposition` for each item | existing rule |
| Yellow | 1 or more success-case items, or `none_found: true`. The map violation `yellow_value_not_evidence_backed` with `none_found: true` is the named state "no success case found", not a failure. | existing rule + mapping |
| Green | 1 or more `provocations`; stance is fixed to `refines`; no verdict field | existing rule + 1 new check |
| Blue | zero evidence items; fields `skipped`, `thin`, `ask_next` only; the Blue rule of the map is skipped and the output says so | new, small |

Rule results are lines on the reading. They do not drop a reading, except the citation boundary and a Red or Blue reading that cites evidence.
"Black is never averaged": no step computes a combined score or a combined stance. The merge has no numeric field across hats. A test asserts this.

### 4.7 Persona lifetime and staleness

- New `roomFingerprint(roomDir)` in `persona-ops.cjs`: SHA-256 over the sorted list of `relative path + content hash` for each `.md` file under each discovered section, recursive, except `personas/`, dot directories and STATE.md. STATE.md is excluded because it is recomputed often.
- `write-persona` stores `room_fingerprint`, `built_by: persona-analyst`, `persona_status: proposed` (then `accepted` after the F.8 gate), `research_handles`, and no `PREVIEW_NOTICE`.
- `personaFreshness(roomDir)` returns `fresh`, `stale`, `missing` or `preview_only`. Deep mode rebuilds on any state other than `fresh`, after it tells the navigator why.
- The run's own outputs do not change the fingerprint (they are in `personas/` and room.db).
- A settled tension: `merge` reads `.mindrian/hats/tension-rulings.json` (key: target path + hat pair). A match is shown as "settled on <date>: <ruling>" and is not asked again. Only the navigator can re-open it.

### 4.8 Merge (step 8)

- `merge` builds the artifact from reading fields only, in this fixed order: (1) dissent register: one attributed position line for each hat that ran; (2) tensions from `synthesizeTensionMap` through `lens-engine.rotate` (parallel mode, one node for each hat that ran, same topic); (3) not run: each hat with its reason; (4) rule lines; (5) sources by hat.
- The artifact holds no sentence that is not a reading field or a fixed label. This is the checkable form of "the merge adds no new fact".
- Larry narrates the artifact on screen. Limit, stated plainly: Larry's spoken text cannot be checked by code. The filed artifact can. Open item O-5 (Larry or a fresh agent) keeps the default: Larry.
- The tension map knows 3 hat pairs. Agreement between hats is listed as "same position, both attributed"; nothing is merged or removed.

### 4.9 Measure (step 10)

`compare` reads two run records with the same brief hash and writes `compare.md`: for each mode the hats that ran, tensions found, tensions found in one mode only, source count, agent runs, cards, wall time. One empty field "navigator note". No score and no winner.

## 5. Part 8 analysis

Strings that can leave the machine in deep mode: the approved search strings only, to the providers named on the card (openalex always; tavily and patents only with a key). Nothing leaves in quick mode. Nothing goes to the Brain: the `brain` lens is removed and no `brainFn` is passed.

What stops room text, in order:
1. Shape: the string must equal `genericDomainHandle(string)`: lower case, letters, digits, 6 words or fewer.
2. Content fence: `auditQueryString(string, 'persona-hats')`.
3. Room identity screen (new, small): refuse a string that contains the venture name, the `primaryDomain` slug words as a phrase, or the room directory name.
4. The card: the navigator sees each exact string and each provider before a fetch.
5. Plan binding: `run-research` refuses a string whose `q_hash` is not in the plan, and a count above 2.
6. `auditWebCredential` inside the corpus (existing).

Residual risk, stated plainly: checks 1 to 3 cannot detect a product name or a person name that is not the venture name. The card is the final control. On CLI the code cannot prove that a human answered the card; the approved file is written by the command after the card, as in `/mos:dominant-designs`. A hat agent holds WebSearch and WebFetch and can misuse them; the citation check detects the use of the result, not the call.
