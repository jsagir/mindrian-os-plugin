# Phase 400.2 Plan 19: arXiv, host web search, AskNature and Kaggle Summary

The four researching hats now search arXiv, a web lens falls back to the host web search when no Tavily key is set, Green can search AskNature and White can search Kaggle datasets, and the spike preparation prints all of it offline.

## What was built

- **arXiv (task 1).** `LENS_TO_SOURCE.preprint = 'arxiv'` (the existing keyless source of `research-corpus.cjs`, tier Academic). `HAT_RESEARCH_LENSES` now: white `scholarly, preprint, industry, datasets`; black `scholarly, preprint, industry`; yellow `industry, scholarly, preprint`; green `scholarly, preprint, patent, nature`. The status stays `provisional`.
- **Paper key.** `tests/lib-4002-hat-overlap.cjs` `paperKey(item)`: DOI (field or doi.org URL), an arXiv DOI (`10.48550/arxiv.<id>`) maps to the arXiv id, else arXiv id from an arxiv.org abs or pdf URL (version removed), else the normalised URL. `normaliseUrl` stays (third fallback). To make this work on real packs, a finding of the driver and a pack item carry an optional `doi` (only when the provider gave one).
- **Domain lenses.** In the driver, `DOMAIN_LENSES` (`nature`: asknature.org; `datasets`: kaggle.com with path prefix `/datasets`) and `domainLensAccepts(lens, url)`. With a Tavily key the lens calls Tavily with `include_domains`, no cache layer, no recovery envelope (a retry would drop the filter), keeps only on-site URLs, and labels the findings `asknature` (Practitioner) or `kaggle` (Operational).
- **Host-web (task 2).** `lensPlanOf` returns `host_lenses`: a web lens (industry, nature, datasets) whose Tavily gate is unmet is not refused, it gets the provider `host-web`. Each planned hat holds `host_lenses` and `host_searches` `[{lens, label, q_hash, text}]` (labels: `web search by the assistant`, `AskNature (through web search)`, `Kaggle datasets (through web search)`). `planEdit` recomputes them after an edit. `run-research` takes `--host-results`; `validateHostResults` binds each entry to the approved q_hashes, the plan host searches and the exact host string. Items are stripped with `stripInjectionSpans`, wired through the same wrapper as door findings (section:personas, proposed) and shown in the pack with provider `host-web`. The output of each string has a `host` list `{lens, state, reason, items, refused}`.
- **Honest states.** No entry means `not_executed` with `provider_unavailable:host_web`: the string is partial, and a hat whose providers are all empty is `failed`, not `ran_empty`. An entry with an empty result list is `executed_empty`.
- **Command.** `commands/persona.md` Step 5: the cards show the host searches with label and exact text plus the sentence "Code cannot prove that the assistant searched exactly that string."; a new point 4 runs the host web search and writes the results file into a `mktemp -d` directory; point 5 passes `--host-results`; three new refusal reasons mapped; the research lines print a host-web not-run line. Skill mirror rebuilt.
- **Review artifact.** A fixed line (`host_web_limit`) states the limit once, only when a host-web item is in a pack.
- **Spike preparation.** `tests/lib-4002-spike-prepare.cjs` prints the providers per string, the host searches with exact text, the host results file (starts with no entries) and passes it in the printed run-research line.
