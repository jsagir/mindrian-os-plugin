## State rules for owner sign-off

1. WR-01 rebuild/accept. Before: write-persona left persona.json in place, so a rebuild whose builder wrote nothing re-proposed the old persona, and accept-persona accepted any proposed file with the right room fingerprint. After: the door deletes persona.json once it reads it, records the file name and SHA-256 of the file it wrote, and accept-persona refuses a hat that is not `proposed` (`not_proposed:<hat>`) or whose file bytes differ (`persona_file_changed:<hat>`). Residual: a hand edit of a proposed persona file can no longer be accepted; the navigator must ask for a rebuild.
2. WR-04 quick tension key. Before: the tension key was hash(target, sub-question, hat pair) in both modes, so a ruling on a quick look settled the same tension in every later deep run. After: a quick run adds the part `quick` to the key; a quick ruling settles only later quick runs and a deep ruling settles only later deep runs. Residual: a ruling stored by a quick run before this fix has the 3-part key and still settles a deep run (the store entry has no mode field, ASSUMED from the record-ruling code); the branch is not released, so only test rooms can hold one.
3. WR-05 off-site results. Before: a host web search whose every result was off the site was `executed_empty`, so the hat could be `ran_empty`. After: zero kept results with at least one refused result is `not_executed` with `provider_failed:host_off_site`, and the hat is `failed` when no other provider ran. Residual: when another lens of the same string ran empty, the string is `ran_empty` with `partial`; a host answer with no results at all is still an honest empty.
4. WR-09 store lock. Before: the rulings store and the handles store were read, changed and written with no lock, so two Cowork writers could lose a ruling. After: each write takes `<store>.lock` (create-exclusive), re-reads the store under the lock, merges by key and renames; a lock held past 2 s gives `rulings_store_busy` or `write_failed:handles_store_busy`, and a lock older than 30 s is removed. Residual: two writers of the same key give last-writer-wins; the stale-lock removal is not atomic; create-exclusive on a network share is not proven.
5. PS-09 nature handle. Before: the AskNature lens searched the normal Green string (handle plus the qualifier `analogous solutions`) with `site:asknature.org`. After: the Green handle agent proposes one separate `nature_handle` (1 to 6 words, no qualifier) that passes the room identity screen, the generic-shape check and the egress audit; only that handle goes to the nature lens, the normal Green strings go only to openalex, arxiv and patents, and a missing or refused nature handle gives `not_planned:<reason>`, never `ran_empty`. Residual: "nature terms" is a prompt rule (code checks shape and room words only); Green can now send 3 strings; the AskNature on-site yield is not proven by a live run.
6. WR-03 seal location. Before: the pack seal was in run.json inside the room, which the sealed hat agents can write. After: the seal is in the private run map `~/.mindrian/persona-hats/runs/<run id>.json` (mode 0600, scripts/persona-hats.cjs:397), check and merge compare only that copy, and run.json keeps a record copy that is never compared. Residual: the run map belongs to the same OS user; a hat agent that guesses the default path can still reach it; only the agent contract forbids reads outside its own directory.
