## What was built

- Quick merge: `merge --room --run --quick-result <file> [--counts <file>]`. The quick result is `{schema "mos.persona-quick/1", run_id, hats}`; each hat holds `positions` (and `provocations` for green; `skipped`, `thin`, `ask_next` for blue only). Refused by name, with nothing written: `forbidden_key:` for evidence, self_search_strings, self_found_sources, justification, verdict, none_found, missing_data (and positions on blue); `unknown_key:`; `schema_invalid:*`; `citation_outside_sources` for any URL or evidence claim id in a string. The merge runs the same tension call (lens engine, no db), the same same-position rule and the settled mark as deep, writes the artifact (first line QUICK_NOTICE, second line the fixed quick label, then the usual sections) and the run record (mode quick, `steps.check` skipped, `research` never_searches for red and blue and not_applicable for the other four, `quick_result_sha256`), copies the file to `quick-result.json` in the review folder, and deletes the scratch tree. Output has the same shape as deep merge with `session_log: {}`.
- compare: `compare --room --deep <id> --quick <id>`. Refusals in order: room_not_found, run_not_found, `modes_not_deep_and_quick`, `not_merged:<id>`, `brief_hash_differs`. It writes only `compare.md` in the deep run folder (temporary file and rename) and changes no record. File layout: title, both run ids, the governing question, one table for each sub-question (hat, deep value, deep line, quick value, quick line; six rows), one counts block for each mode (hats that ran, door evidence items, self-found sources, agent runs, stops, cards each marked "(reported by the command)", wall time from merged_at minus started_at), then the empty "Navigator note:" field. Output: `{ok, deep_run_id, quick_run_id, file}`.
- Rulings section: after a stored ruling, record-ruling sets the `state:` line above each `tension id:` line from the run record, drops the stale `settled on` and `stored` lines of a tension that is open again, and writes a last section "## Rulings" (tension id, ruling, side hat, ruled on; fixed labels, the reason text is not written). A missing artifact never undoes a ruling: the output field `artifact` is `{state: "updated"}` or `{state: "not_updated", reason}`.
- Command: the Quick mode section now writes the quick result file into the inbox, calls merge with it, prints `notice_lines` first, offers record-ruling, and says no agent run, no fetch and no web search; a new "Compare" section (and the sentence that a surface with no shell has no run record and no compare); Step 9 names the Rulings section and the `artifact` field.
- The recorded comparison: see 400.2-COMPARE-RECORD.md. Its first lines say the inputs are fixture readings written in one context. The two run records and compare.md are real door outputs; the readings and the quick result are fixture files; the evidence is a synthetic envelope through the seam. Leg K7 rebuilds both runs and compares the file byte for byte with `compare-golden.md` (fixed clock and fixed hex seam).
