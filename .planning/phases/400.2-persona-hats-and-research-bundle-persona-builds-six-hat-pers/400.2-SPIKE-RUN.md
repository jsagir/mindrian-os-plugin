# Phase 400.2 spike run sheet: do the four hats get the same search results?

Owner-gated. No agent runs steps 4 and 5. Run every command from the repository root /home/jsagi/dev/MindrianOS-Plugin-399.

## Purpose

- The persona command gives each of the four researching hats (white, black, yellow, green) its own search: one generic handle, plus a fixed 2-word qualifier and a fixed lens order for each hat.
- If two hats get mostly the same result URLs, "own research for each hat" is not true in practice (risk K-11).
- The spike measures it once. Decision rule: when 2 hats share more than half of their URLs, the qualifier or the lens set of one of them is changed before the research slice closes.

## What leaves the machine

- 4 generic strings, one for each hat, built from the handle "battery recycling" and the fixed hat qualifier. Nothing of any room: the room of the spike is a made-up fixture.
- Each string goes only to the providers that the preparation tool prints next to it. By default this is openalex (no key needed); tavily and patents join only when their key is set in your shell.
- The providers also see the normal data of a web request (your IP address and, where one is set, your API key). That is not room data.
- Nothing goes to the Brain.
- You may give another generic handle: add `--handle "<1 to 4 lower case words>"` to the command of step 1.

## Steps

1. Prepare the run. It is offline: it sends nothing.
   `node tests/lib-4002-spike-prepare.cjs --dir <a new empty directory>`
   Set TAVILY_API_KEY and PATENTSVIEW_API_KEY in your shell BEFORE this step if you want the full provider set. Use the same shell for step 4: the door refuses a changed provider set (`provider_set_changed`).
2. Read the 4 printed strings and their providers. This is exactly what step 4 sends. If you do not accept a string, leave that hat on "defer" in step 3.
3. Open the printed approved file. Change `"decision": "defer"` to `"decision": "approve"` for each hat you accept. Change nothing else in the file.
4. Run the printed run-research line (it starts with `MINDRIAN_HOME=`). This sends the approved strings to the named providers. It prints one JSON object. You expect `"ok": true` and a state for each hat.
5. Run the 4 printed `cp` lines, then the printed overlap line:
   `node tests/lib-4002-hat-overlap.cjs --packs <the packs directory> --out tests/fixtures/4002/spike-overlap-record.json`
   It writes the record: counts and shares only, no URL and no title. It prints the decision: pass, change_needed or inconclusive.
6. Answer the checkpoint: type "spike-done" when the record file exists, or "defer" to leave the tables provisional and the slice open.
7. Delete the directory of step 1. It holds the full result URLs and titles. Do not copy them into the repository.

## Limits to know

- A hat has 5 URLs or fewer for one string (the lens run returns 5 findings or fewer for each call). The shares are over small sets, so one shared URL moves a share a lot.
- A missing Tavily or patents key reduces the provider set. The record shows the providers that ran for each hat. With no key set, all four hats search openalex only, with four different strings: the measure is then weaker, and a pass is weaker evidence.
- A hat that gets zero results makes 3 of the 6 pairs `no_result`. The decision is then `inconclusive`, and you run again with another handle or a provider key.

## What happens next

- Record decision `pass`: the tables become `spike_checked` and the research slice closes.
- Record decision `change_needed`: you choose a new qualifier or lens set for one of the two hats; a second run confirms it.
- Record decision `inconclusive`, or "defer": the tables stay `provisional`, the spike test keeps printing the pending line, and the phase cannot be signed off.
