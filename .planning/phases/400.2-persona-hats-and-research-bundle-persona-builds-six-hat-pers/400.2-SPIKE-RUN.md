# Phase 400.2 spike run sheet: do the four hats get the same search results?

Owner-gated. Run every command from the repository root /home/jsagi/dev/MindrianOS-Plugin-399.
Who makes the live call: the owner, or the main session (never a sub-agent) after the owner approved the exact strings and providers on a card in the same session (owner answers, "Fourth card"). This sheet was updated after plan 19 (arXiv, host web search, AskNature, Kaggle). The run of 2026-11-25 used it; its result is in 400.2-SPIKE-RECORD.md. Use the sheet again only to confirm a changed qualifier or lens set.

## Purpose

- The persona command gives each of the four researching hats (white, black, yellow, green) its own search: one generic handle, plus a fixed 2-word qualifier and a fixed lens order for each hat.
- If two hats get mostly the same results, "own research for each hat" is not true in practice (risk K-11).
- The spike measures it once. Decision rule: when 2 hats share more than half of their results, the qualifier or the lens set of one of them is changed before the research slice closes.
- The unit of "same result" is a paper key: the DOI, else the arXiv id, else the normalised URL. One paper that OpenAlex and arXiv both return counts as one paper.

## What leaves the machine

- 4 generic strings, one for each hat, built from the handle "battery recycling" and the fixed hat qualifier. Nothing of any room: the room of the spike is a made-up fixture.
- Door providers, called by the door script: openalex and arxiv (no key needed) for all four hats. With a key in your shell the set grows: tavily (TAVILY_API_KEY: the industry lens, and with a site filter the AskNature lens of green and the Kaggle datasets lens of white) and patents (PATENTSVIEW_API_KEY: green).
- Host web searches: a web lens with no Tavily key is not dropped. It becomes the provider `host-web`. The assistant of the host (WebSearch in Claude Code) runs it with the exact string that the preparation tool prints, then writes the results into the host results file. Two lenses add a fixed prefix: `site:kaggle.com/datasets <string>` (white) and `site:asknature.org <string>` (green). Code cannot prove that the host searched exactly that string.
- The providers also see the normal data of a request (your IP address and, where one is set, your API key). That is not room data.
- Nothing goes to the Brain.
- You may give another generic handle: add `--handle "<1 to 4 lower case words>"` to the command of step 1.

## Steps

1. Prepare the run. It is offline: it sends nothing.
   `node tests/lib-4002-spike-prepare.cjs --dir <a new empty directory>`
   Set TAVILY_API_KEY, PATENTSVIEW_API_KEY or OPENALEX_API_KEY in your shell BEFORE this step if you want a larger provider set. Use the same shell for step 4: the door refuses a changed provider set (`provider_set_changed`).
2. Read the printed strings, the providers of each string and the printed host web searches. This is exactly what steps 3 and 4 send. If you do not accept a string, leave that hat on "defer" in step 3.
3. Approve.
   - Open the printed approved file. Change `"decision": "defer"` to `"decision": "approve"` for each hat you accept. Change nothing else in the file.
   - If the preparation printed host web searches: run each of them with the host web search tool, with the exact printed text, unchanged. Write the results into the printed host results file (schema `mos.persona-host-results/1`, one entry for each search that ran: the lens, the q_hash, the string, and for each result a url, a title and a snippet). Write an entry only for a search that ran. A search with no entry is reported as `not_executed` (`provider_unavailable:host_web`), never as empty. A search that ran and found nothing gets an entry with an empty list. For a site-limited search, results off the site are dropped by the door and counted as refused; do not pass them in.
4. Run the printed run-research line (it starts with `MINDRIAN_HOME=` and ends with `--host-results <file>`). This sends the approved strings to the named door providers. It prints one JSON object. You expect `"ok": true` and a state for each hat.
5. Run the 4 printed `cp` lines, then the printed overlap line:
   `node tests/lib-4002-hat-overlap.cjs --packs <the packs directory> --out tests/fixtures/4002/spike-overlap-record.json`
   It writes the record: counts and shares only, no URL and no title. It prints the decision: pass, change_needed or inconclusive.
6. Answer the checkpoint: type "spike-done" when the record file exists, or "defer" to leave the tables provisional and the slice open.
7. Delete the directory of step 1. It holds the full result URLs and titles. Do not copy them into the repository.

## Limits to know

- A door lens run returns 5 findings or fewer for each call, so a hat has few results for one string (a pack holds 10 items at most). The shares are over small sets, so one shared paper moves a share a lot.
- A missing key reduces the provider set. The record shows the providers that ran for each hat. A web lens with no Tavily key runs only as a host web search, and only if the host results file has an entry for it.
- A site-limited host search (Kaggle datasets, AskNature) can return only off-site links through a general web search. Those are dropped, so the lens is measured as ran with zero items. The measure is then silent about that source.
- A hat that gets zero results makes 3 of the 6 pairs `no_result`. The decision is then `inconclusive`, and you run again with another handle or a provider key.

## What happens next

- Record decision `pass`: the tables are `spike_checked` and the research slice closes.
- Record decision `change_needed`: you choose a new qualifier or lens set for one of the two hats; a second run confirms it.
- Record decision `inconclusive`, or "defer": the tables stay `provisional`, the spike test keeps printing the pending line, and the phase cannot be signed off.
