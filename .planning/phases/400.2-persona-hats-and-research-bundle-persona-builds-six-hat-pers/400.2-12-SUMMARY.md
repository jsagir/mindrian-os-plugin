# Phase 400.2 Plan 12: run-research Summary

run-research fetches only the strings that the navigator approved on the cards, from exactly the providers the cards showed, through the unchanged Bono research leg. It records a per-string and per-hat state that cannot read a failed provider as "found nothing", writes the evidence packs and the five White copies, seals the pack hashes and then marks the step done.

## What was built

- **Approval binding.** Order of checks for the whole call (nothing is fetched on a refusal): `step_out_of_order:plan_research`, `mode_not_deep`, `step_already_done:run_research`, `run_map_missing`, `plan_missing`, `plan_changed` (sha256 of `<scratch root>/plan.json` against `ledger.plan_sha256`), `approved_file_missing`, then `validateApproved`: `schema_invalid:*`, `unknown_key:*`, `plan_seq_stale`, `hat_never_searches` (red, blue), `too_many_strings` (before the plan check), `string_not_in_plan`, `provider_list_mismatch` (approve entries only; the list must equal the plan list in the same order).
- **Per-hat results with no fetch.** refuse gives `declined`; defer gives `declined` with reason `deferred`; a planned hat the file does not name gives `declined` with reason `no_answer`; `preflightLenses` computed again with another lens or provider set gives `failed` with reason `provider_set_changed`. A hat that was not planned keeps its `not_planned:<reason>` state.
- **Fetch.** White first, then black, yellow, green; one `runCellFanout` call for each approved hat (`subdomains` = the approved strings, `hats` = [hat], keep-all critique, no `roomDir`). The wrapper `dispatchCell` calls `personaDispatchCell` with a ctx of exactly `{db, roomDir, sessionId, extractContextFn, runSourceLensFn, wireAcceptFn}` (no `brainFn`, no `classifyFn`). `sessionId` is `persona-<hat>-<12 hex of the string hash>`. `extractContextFn` runs the real extractor for the local preflight and sets `lens_set` to the frozen set of the plan. `runSourceLensFn` adds `_substituteFn: async () => null` and stores the result per string. `wireAcceptFn` stores each finding with its wire result. A string whose `cell.handle` differs from the approved text is `failed:handle_changed` and is not fetched.
- **States.** String: `ran_with_results` (partial with the failed provider named), `fetched_not_wired:<wire_failed|filtered|no_db>`, `ran_empty`, `failed:<thrown|empty_lens_set|provider_failed:<class>|provider_unavailable|invalid_opts|handle_changed>`. Hat: `ran_with_results`, `fetched_not_wired`, `ran_empty`, `failed`, `declined`, `not_planned:<reason>`.
- **Packs.** `evidence.json` for white, black, yellow, green (not-planned hats get a zero-item pack with their state); `shared-white.json` (byte-equal copy of White's pack) in white, red, black, yellow, green; none in blue; no `evidence.json` in red. Items: id (the wired node id), title, url, tier, provider, summary (600), retrieved_at, q_hash; 10 at most; only wired findings.
- **Ledger.** `hats.<hat>.research` = the state; `hats.<hat>.research_reason` when there is a reason; `research.strings_approved` = the number of hashes the navigator approved; `research.strings_refused` = the plan-time count plus every planned string that was not approved; packs sealed through `sealPacks` before `run_research` is marked done.
- **Output** of `run-research` (one JSON object): `{ok, run_id, plan_seq, hats (six states; red and blue `never_searches`), reasons, strings {hat: [{q_hash, state, partial, research_mode, findings, wired, substitute_calls, recovery_action}]}, evidence_items, counts}`.
- **Router.** `SUBCOMMANDS` now has `run-research`; the router needs `--room`, `--run`, `--approved` and prints one JSON object (the router already awaits a promise).
