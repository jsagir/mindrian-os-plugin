# Phase 400.2 Plan 11: plan-research planning branch, handles store, edit path, pack hashes Summary

plan-research now turns the handles of each researching hat into at most 2 checked search strings, binds the providers that can run, writes one plan for the four cards, stores passed handles by brief and persona hash, and accepts a navigator edit that must keep the hat qualifier. The ledger also seals the pack hashes, so a hat cannot widen its own citation set by rewriting its evidence pack or its copy of the White package.

## What was built

- **Planning branch.** Order for each of white, black, yellow, green: persona not usable (`not_planned:persona_not_accepted`), identity screen did not run (`not_planned:identity_screen_unavailable`, no handle file is read), handles from the store (same brief hash and persona file hash) else `handles.json` (S-3a, 1 or 2 items, closed keys), each handle through `checkHandle` then `composeString`, at most 2 strings, then `preflightLenses(HAT_RESEARCH_LENSES[hat])`. No string: `not_planned:no_valid_handle`. No available lens: `not_planned:no_available_provider`. Lens weight is 1.0, 0.8 by table position. Providers come from `LENS_TO_SOURCE` of the available lenses, in table order. `unavailable_line` is the driver sentence.
- **Output.** `plan` (S-3, no `round` key), `plan_seq`, `hats` (state strings, `never_searches` for red and blue, as before), `planned`, `refused_shown` (stdout only). `plan.json` is written to the scratch root (mode 0600) only when 1 or more hats are planned; its SHA-256 is in `ledger.plan_sha256`.
- **No hat planned:** the closing branch of plan 07 runs (packs with zero items, `run_research` skipped), now followed by the seal of the packs.
- **Handles store.** `<room>/.mindrian/hats/handles/<first 16 hex of brief hash>.json`, schema `mos.persona-handles-store/1`; each hat holds `persona_sha256`, `brief_hash` and only the handles that passed. Stored handles are checked again on every use. Writing the store does not change the room fingerprint (test E22).
- **handles_needed.** `start` (deep, only when nothing is to build or accept) and `accept-persona` (only when the step closes) list the researching hats with a usable persona and no store entry for this brief and persona file. Never red or blue.
- **Edit path.** `plan-research --edited <file>` (S-3b). Order of checks: schema of the file; hat must be a researching hat (`hat_never_searches`); the hash must be in the plan (`string_not_in_plan`); the full text through `auditEditedQuery` (`empty_query`, `bad_query`, `too_long`, `egress_violation`); the text must end with the qualifier (`qualifier_removed`); the text without the qualifier through `checkHandle` (shape, digit, room identity); the full text through `composeString`. An accepted edit replaces the string in place and sets `edited: true`. A file with 1 or more accepted edits raises `plan_seq` by 1 and adds `{hat, q_hash, plan_seq}` to `ledger.audit.edited_strings`. A refused edit keeps the old string, is in `refused_shown`, and raises no `plan_seq`.
- **Pack hashes (all five items of the plan 10 handoff are done).** `sealPacks(ledger, map)` records `ledger.packs = {schema, shared_white, evidence: {white, black, yellow, green}}`; the five copies of `shared-white.json` must be equal. `judgeReading` (shared by check and merge) calls `packTamper` after the schema step and before the citation step. The merge artifact shows a pack only when it matches its seal.
- **Real ledger.research counts.** `strings_approved` is the number of planned strings, `strings_refused` the number of refused handles plus refused edits. See the handoff for plan 12.

## Planner and executor decisions

- Persona state is judged before the identity screen: a refused persona is `persona_not_accepted` even in a room with no venture name.
- A hat whose handles.json fails its schema is `no_valid_handle`, with `refused [{reason: "schema_invalid:handles"}]` and `refused_shown` text `null`. It does not count in `strings_refused`.
- Two handles that compose the same string are deduplicated without a refusal.
- Extra edit refusals not named in the plan: `string_unchanged` (same text as the string it replaces) and `duplicate_string` (equals another string of the hat).
- A test seam `deps.preflightLenses` (function option, not a CLI flag) lets a test remove all providers (leg E27c).
- `plan-research` called twice without `--edited` is refused with `step_already_done:plan_research`; `--edited` before any plan is `step_out_of_order:plan_research`.
