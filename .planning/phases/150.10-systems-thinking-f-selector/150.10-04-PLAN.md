# Plan 150.10-04 - Piece D: Leverage Point Local-Graph Excavation

## Intent

Make leverage-point analysis OPERATIONAL, not just taxonomic (navigator directive 2026-06-14): the Brain directs HOW to scan a local room graph and excavate where the leverage points actually are in the user's specific system. Brain holds the generic mapping; the local graph executes the scan. This is the Part 9 contract made concrete (Brain = external cortex supplying method; SQL/local = the navigator) and gives the systems-thinking selector's M4 move real teeth.

## The design - Meadows level -> local-graph signature (the scan_pattern)

Each of Meadows' 12 leverage levels maps to a STRUCTURAL signature any room.db graph can be scanned for. Descending leverage (12 = weakest, 1 = strongest); the scanner scores higher-leverage (lower-number) hits higher. Room.db node types: claim, assumption, decision, opportunity, CausalClaim. Edge types: INFORMS, CONTRADICTS, CONVERGES, INVALIDATES, ENABLES, REFINES, ROOT_CAUSES, FEEDS_INTO, DEFERRED.

| Meadows level | Local-graph signature (what the scanner queries room.db for) |
|---|---|
| 12 Parameters/constants | leaf claim nodes with scalar/numeric evidence, no outgoing edges |
| 11 Buffers | high evidence-count accumulation nodes |
| 10 Stock-and-flow structure | nodes with high (in+out) degree (structural hubs) |
| 9 Delays | DEFERRED edges + claims with valid_from/valid_until lag |
| 8 Balancing loops | cycles dominated by CONTRADICTS / INVALIDATES polarity |
| 7 Reinforcing loops | cycles dominated by CONVERGES / ENABLES polarity |
| 6 Information flows | high-betweenness / bridge nodes (cross-section connectors) |
| 5 Rules | assumption-typed nodes (the assumption registry) |
| 4 Self-organization | ROOT_CAUSES fan-out sub-graphs (generative nodes) |
| 3 Goals | the governing-thought / STATE objective node |
| 2 Paradigm | the root problem-formulation node (ICM Layer 0) |
| 1 Transcending | the systems-thinking meta-lens itself (M4) |

## Threat model

- **Part 8 Brain egress (HIGH):** the scanner must NEVER send room candidates to Brain. Mitigation: the scanner has zero network surface (grep-proven); only the generic mapping crosses Brain->local, never local->Brain. The Brain node holds the generic mapping only.
- **Part 9 read-path bypass (MED):** a scanner that opens room.db directly (sqlite) bypasses the navigation.cjs chokepoint. Mitigation: acceptance asserts navigation.cjs is the sole read path.
- **Orphan (MED):** the new Brain node must be wired on creation. Mitigation: Task 1 re-runs the orphan-scan gate.
