# Phase 143.2 Plan 05: conversation-mode Lane Picker + Ackoff DIKW Summary

conversation-mode is now the EXPLICIT Shape F.1 lane-picker (a Decision Gate, not a silent classifier) with the 3 lanes mapped to Ackoff DIKW bidirectional position and a build-crossing Brain chain offer carrying generic framework handles only.

## What Was Built

Additive doctrine edit to `skills/conversation-mode/SKILL.md` -- markdown only, zero code, zero dependencies. Two sections inserted directly after the Plan-03 "Conversational Reaches (Part 2/3)" note and before "## Mode 1: Just Talk", so the lane-picker sits near the top where the no-room session begins.

### CONV-01 -- "## Lane Picker (Shape F.1 -- the explicit traffic cop)"

At the start of a no-room session (and whenever the lane is ambiguous), Larry no longer silently classifies the user's persona into a mode. He surfaces an EXPLICIT Shape F.1 selector (the SEED-020 host-native AskUserQuestion card-selector, reusing renderShapeF1 / the host primitive -- no bespoke widget) with three lane cards, each carrying a one-line description:

- Just chatting -> Mode 1 Just Talk
- Brainstorming -> Mode 2 Explore+Capture
- Building something -> Mode 3 Build a Room

The navigator picks the lane; the pick is a Decision Gate (Canon Part 3, GUIDED default), never an inferred classification. Persona Detection still runs WITHIN the chosen lane to shape Larry's questions (HOW he asks), not to pick the lane (WHICH lane). The Mode 1 upgrade-offer line and the Mode 2 "I am ready to build" transition are framed as the SAME lane-picker re-surfaced (a re-pick), with two re-surface rules: one re-surface per turn-cluster, and never auto-switch lanes.

### CONV-02 -- "## Lanes as Ackoff DIKW position (bidirectional)"

The three lanes ARE positions on the Ackoff DIKW pyramid:

- chat = Data / Information (low structure, raw thinking)
- brainstorm = Knowledge (divergent synthesis, patterns banked)
- build = Wisdom / Understanding (convergent artifact, the room)

This is the UP-ascent (Data -> Information -> Knowledge -> Wisdom). The DOWN-descent is the honesty loop: a built artifact returns to validate its assumptions and data; building does not skip validation. When a built artifact fails validation (None-tier evidence, a contradiction), Larry surfaces the descent -- drop back a DIKW level to re-test the data before re-ascending.

The section states explicitly that this REUSES the larry-personality bidirectional Ackoff ascent doctrine: push_forward IS the ascent earning evidence up the levels; pull_back IS the descent decomposing back to re-test near a commit. The DIKW mapping is the same traversal named at the conversation surface -- additive, not a contradiction.

The lane-picker reads and advances the DIKW position. When the navigator picks "Building something" (the lane crosses into build = Wisdom), Larry OFFERS the Brain chain as a Decision Gate: Ackoff Pyramid FEEDS_INTO Systems Thinking and Ackoff Pyramid FEEDS_INTO MAP THE HIERARCHY. The offer is never auto-routed -- the Brain query fires only after the navigator approves the gate. Part 8 floor stated inline: the offer carries generic framework handles only (framework names + problem-type enum), never the user's conversation content, artifacts, or banked opportunities; if the Brain is unreachable, Larry omits the chain line and continues from local context.
