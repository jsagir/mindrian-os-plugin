## Gap 13: NOW says Theo is not answering while the THEO row says on

Classification: NEW FAILURE (a defect in ui/mos-face). Not an ENV GAP: it reproduces with no network.

Chain (PROVEN, code read and run):
1. hooks/probe.ts line 76 to 77: probeReach reads brain-prewarm.json. When no Theo host is recorded it notes "No Theo host is recorded, so Theo was not checked" and returns Reach { host: 'unknown', status: null, ms: null } without any check.
2. hooks/lines.ts line 124: nowLine reads the condition snap.theo.status === null (or 500 and over, or the local health file saying error) as "Theo is not answering its health check". A status null from a check that never ran is taken for a check that failed.
3. hooks/status.ts theoWord: the THEO row reads the local health file first (brain ok gives on). So the same screen says on in the THEO row and "not answering" in NOW and in the pinned line.
4. The fixture home of plan 10 has no brain-prewarm.json: screens/index.json sessionHome lists next-move, bridge/brain-health, room-health, stance-state, voice-mark, update-check, install-state and three room files, and no brain-prewarm.json. The capture driver (380-19-evidence/capture-driver/drive.cjs) writes none. PROVEN.

Reproduction (evidence 380-19-evidence/g13-run.txt, scratch copy, claude plugin test run alone):

| Case | Files | Health answer | NOW | THEO row | Pinned line |
|------|-------|---------------|-----|----------|-------------|
| A | no brain-prewarm.json; bridge/brain-health.json ok | not asked | "Theo is not answering its health check" | on | "/m:os  Theo is not answering  /mos:doctor" |
| B | prewarm with a host; brain-health ok | 503 | "Theo is not answering its health check" | on | same |
| C | prewarm with a host; brain-health ok | 200 | "All quiet. Ready when the question is" | on | none |
| E | prewarm with a host; brain-health ok | no answer | "Theo is not answering its health check" | on | same |

Root cause: nowLine takes a null status of a Theo host that was never recorded (so nothing was checked) as a failed check; the unchecked marker is the host text 'unknown' in probe.ts, which no reader tests. The cause is PROVEN and sits inside ui/mos-face. Task 2 fixes it: an exported constant NO_HOST in status.ts, used in probe.ts where the unchecked Reach is made, and tested in nowLine; a check that ran and failed (host recorded, status null or 500 and over) and a local health file that says error stay failures. Case B and E keep their words. Note: in B and E the THEO row says on because the local health file says ok; that is the existing rule of theoWord and is not changed here (the local file is the status line's own source).
