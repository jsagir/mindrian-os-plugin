Stripping rule decided here (D-03 asked planning to decide it):
- S1, known names: remove, case-insensitively and as whole words, the bound room slug, each part of the slug (split on hyphen, underscore, dot and space, parts of 3 or more letters), the workspace folder name and the base name of the session folder. The panel already knows these locally.
- S2, proper names: replace each capitalized word that is not the first word of a sentence, and each all-caps word of 2 or more letters, with one placeholder "(a name)", unless it is in the allow-list (the words of the framework names and problem types, Theo, PWS, MindrianOS, the pronoun I and its contractions, weekday and month names, and the acronyms PWS JTBD SWOT PEST API AI UX MVP ROI KPI). A run of replaced words collapses to one placeholder.
- S3, sentence-initial words (navigator review W3): also replace the first word of each sentence (the start of the text, and the word after a full stop, a question mark, an exclamation mark or a line break) with the same placeholder, unless the word is in COMMON_STARTS, a closed list of function words kept in advice.ts (articles, pronouns, conjunctions, auxiliary verbs, question words and common adverbs such as the, a, we, our, it, this, there, they, you, what, why, how, when, if, but, and, so, because, can, could, should, would, do, is, are, was, have, not, now, then, also, maybe, just, some, each, all), or the word matches a cue word of any RULES entry (so Customers, Symptom or Blocked at the start of a sentence survive, because the classifier needs them), or it belongs to the framework-name allow-list. Acme is losing money loses Acme; We lost three deals keeps We. A plain noun at the start of a sentence that is neither common nor a cue (for example Money) is over-stripped; that costs a little fit and never leaks.
- Residual risk, stated: a venture name typed in lowercase in the middle of a sentence is not caught unless it equals a part of the room slug, the workspace name or the session folder name (S1). The panel shows the excerpt in full, /mos-words turns it off, and the plugin's egress guard hook is a second line on the shim path (its effect on a plugin-originated call is UNVERIFIED and is recorded, not assumed).

Two items go beyond D-03 as written. They are PROPOSALS, not rulings, and both default to on: P1 shimOnlyExcerpt (the excerpt travels only through the guarded shim; the raw-server fallback sends handles only; reason: CLAUDE.md THEO-04, the raw theo server never passes the egress guard) and P2 envSwitch (MOS_FACE_WORDS=off at session start turns the excerpt off for good; reason: the opt-out is proven non-persistent). A veto flips one flag, rebuilds the dist and re-runs the tests; it needs no re-plan, because the tests in this plan run both values of each flag (E10) and the vetoed behavior is the ruling as written (with P1 off the raw fallback may carry the excerpt, as the ruling says "brain_ask"; with P2 off the variable is ignored and no text names it).
