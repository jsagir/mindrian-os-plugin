## Root cause

The dev package ui/mos-face was named mos (commit bfc7cd798), the name of the installed plugin, so claude --plugin-dir on it silently replaced the installed plugin: the session then held only the mod, with no /mos:* commands and no shim tool for brain_ask. PROVEN (R1b and the quoted rule).

Link to G1. With the shim tool missing, the panel's ask loop tried the raw Theo server, which the host's auto mode refused. That produced the pair "Theo was not asked" and "Theo was sent" of real-8.png. Plan 380-16 fixed the pair (one honest sentence). That the raw call was tried because the shim tool was missing is PROVEN by plan 16 (the throw "no tool named" of a missing tool) and consistent with R1b (the tool is absent). That this was the exact launch of the navigator's session is UNVERIFIED (the launch line is not in the shots).

The denied call. "denied by auto mode - Classifier unavailable" is the host's permission mode refusing a tool (the raw server has no allow rule). It is not decided by the mod. UNVERIFIED which state the classifier was in.

## Classification

- Unknown /mos:* commands: WORKING AS DESIGNED, by the documented host rule (a --plugin-dir plugin replaces a same-named installed one). The collision itself was introduced by commit bfc7cd798 and removed by the follow-up 01ed3f929 (the source is named mos-face again; the build rewrites the owner to mos only in the dist). So it is not a failure of the mod today.
- Denied brain_ask: ENV, the host's auto mode and its classifier, outside the mod. The raw server has no allow rule and the guarded shim was not in the session.
- Neither is a NEW FAILURE of the mod. No fresh /gsd:debug session is needed.

## Resolution
<!-- overwrite -->

Decision rule applied: the name must stay mos in the plugin the person installs, because plan 09 measured that the engine lets only the plugin named like the owner write the atoms. The source keeps mos-face and the build rewrites to mos in the dist (owner decision of the card 2026-10-24, done before this plan). So no code change is needed in this plan: documentation only. ui/mos-face/README.md now tells how to try the panel from a checkout (the launch line with the whole plugin, the warning, how to see the override, and the off switch).
