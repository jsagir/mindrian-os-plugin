<interfaces>
Extract adapter result contract (Plan 02's ingestUrl consumes this; any change lands in BOTH plans):

```json
{
  "ok": true,
  "provider": { "id": "tavily-extract", "status": "ok | provider_unavailable | rate_limited | timeout | size_exceeded | error", "reason": "missing_key | http_429 | http_<code> | timeout | oversize | <short string>", "counts": { "urls_requested": 1, "urls_succeeded": 1 } },
  "results": [ { "url": "<echoed url>", "markdown": "<full page markdown>", "title": "<when surfaced>" } ]
}
```

- `ok:false` carries `provider` with the typed status and an EMPTY `results` array - never a throw for key/network/HTTP conditions (the adapterTavily degrade posture, upgraded from bare [] to a typed envelope per D-01/D-19).
- The ONLY throw path is upstream: fetchCorpus's auditQueryString (fail-closed, pre-egress) and its existing TypeErrors for bad args/unknown source.
- Invocation: ALWAYS via fetchCorpus({ source: 'tavily-extract', query: url, opts }) - the adapter is never called directly by product code (chokepoint rule; __testables export is for tests only, matching the existing adapterTavily convention).
- extract_depth defaults to 'advanced' (JS-rendered SPAs; 2 credits / 5 URLs - VERIFIED docs.tavily.com 2026-07-13); opts.extractDepth may pass 'basic'. format 'markdown' always. One URL per call in v1 (the ingest pipeline is single-URL; the API caps at 20/request - do not batch in this phase).
- Size bound (D-02): a raw response body above MAX_EXTRACT_BYTES (module const, 5_000_000, documented in a header comment) returns status 'size_exceeded' without materializing the oversize content downstream.
</interfaces>
