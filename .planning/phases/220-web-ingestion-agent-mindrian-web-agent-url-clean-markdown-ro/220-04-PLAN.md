<interfaces>
Registry contract <roomDir>/.mindrian/watched-sources.json (filesystem-as-truth, Decision 15; the schema_version + generated_note header convention from data/research-sources.json):

```json
{
  "schema_version": 1,
  "generated_note": "Phase 220 watched-sources registry. Room-level. No em-dashes.",
  "max_ingests_per_run": 2,
  "sources": [
    {
      "id": "<stable slug>",
      "url": "https://...",
      "kind": "rss | repo | paper-feed | page",
      "cadence": "daily | weekly | monthly",
      "enabled": true,
      "etag": null,
      "last_modified": null,
      "last_content_sha": null,
      "last_run": null,
      "note": "<why watched>"
    }
  ]
}
```

- Cadence defaults (Claude's discretion, documented in the module header): 'weekly' when omitted; a source is DUE when enabled && (last_run is null || now - last_run >= cadence window).
- Change detection: fetch through ingestUrl (which hashes); a 'no_op' outcome means unchanged (update last_run only); 'filed'/'superseded' means changed (update last_content_sha + last_run). etag/last_modified fields are reserved-and-honored-when-present: v1 populates them only if the extract path ever surfaces them (research open question 1 - content-hash is the dependable primary).
- Missing/malformed registry file -> { sources: [] }, never a throw (the crawl step reports '0 sources due').
- v1 treats every source kind as a page-fetch of its URL (rss/repo/paper-feed enrichment is future registry-side work; the kind enum exists so registrations are forward-stable).
