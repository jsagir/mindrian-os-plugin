The stage envelope (annex section 2 - the REQ-1 contract every stage result carries; verbatim consumed by Plans 02/03/04):

```json
{
  "run_id": "...",
  "stage": "retrieval|discovery|normalization|segmentation|extraction|dedup|ranking|synthesis|gate|filing|readback|orchestration|presentation",
  "engine": "engine-or-provider-id",
  "status": "ok|empty_valid|degraded|failed|blocked",
  "failure_class": null,
  "retryable": false,
  "attempt": 1,
  "input_fingerprint": "sha256(...)",
  "output_fingerprint": "sha256(...) or null",
  "started_at": "ISO-8601",
  "completed_at": "ISO-8601",
  "provenance": [],
  "warnings": [],
  "payload": {},
  "error": null
}
```

FAILURE_CLASSES (frozen enum, Claude's-discretion values locked by this plan): missing_credential, network_timeout, http_error, parse_error, engine_unavailable, query_error, policy_blocked, contract_violation, schema_invalid, readback_mismatch, size_exceeded, unknown_error, spend_limit_exceeded. Rules the validator enforces: status failed or blocked REQUIRES a non-null failure_class from the enum; status ok or empty_valid REQUIRES failure_class null and error null; blocked covers policy / credential / human-gate / authoritative-source / spend-limit (annex 2).

spend_limit_exceeded is ARCHITECTURALLY DISTINCT from every other class and is called out here because it is self-validated: this exact phase's own planning session hit it (four parallel background agents killed simultaneously by an account-level Claude API spend cap, mid-execution, 2026-07-13 - the incident is the fixture). Unlike network_timeout/http_error/engine_unavailable, a spend-limit failure means the RECOVERY MECHANISM ITSELF (the LLM) is what is out of budget - retrying wastes more of an already-exhausted cap (Tier-1 must never fire), and offering Tier-3 LLM recovery is a bootstrapping paradox (you cannot spend more LLM to recover from being out of LLM - Tier-3 must never fire, joining the empty_valid/policy_blocked/cadence-origin never-list Plan 02 defines). status is ALWAYS 'blocked' (never 'failed' - this is not retryable-in-principle, unlike a transient error); retryable is ALWAYS false structurally, not situationally. Routes directly to Tier-4 human_required with a message naming the exact actionable step ("raise your limit at claude.ai/settings/usage, or wait for the monthly reset") - Plan 02 owns the routing rule, this plan owns the class definition and the structural retryable:false invariant.

Injection env-var scheme (mirrors the vector-store.cjs forced-seam idiom exactly - opts._force seam PLUS a non-empty env var, latched once, SILENT): MINDRIAN_FORCE_<STAGE>_<CLASS-SHORTNAME>. Canonical names (used by the Plan 04 matrix): MINDRIAN_FORCE_RETRIEVAL_TIMEOUT (retrieval/network_timeout), MINDRIAN_FORCE_PARSE_CORRUPT (normalization/parse_error), MINDRIAN_FORCE_READBACK_MISMATCH (readback/readback_mismatch), MINDRIAN_FORCE_EGRESS_BLOCK (gate/policy_blocked), plus MINDRIAN_FORCE_RETRIEVAL_HTTP, MINDRIAN_FORCE_ENGINE_ABSENT (reuse the 219-05 name where the stage matches, never a second name for the same seam).
