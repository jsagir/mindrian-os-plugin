<objective>
Implement REQ-3: the bounded LLM recovery controller - the intelligence tier, fenced. Built LAST among the engine waves (D-01) so it receives observable typed failures from Plans 01-02, never undefined behavior. The controller is an ADAPTER over shipped capabilities (SPEC boundary; the Manus rule): pipeline-state journal/resume for checkpoints, the mva-state atomic-write idiom for the case file, file-evidence-readback.cjs as the ONLY filing-truth authority. Deterministic code owns every machine-checkable invariant (schemas, hashes, path guards, transitions, readback equality); LLM judgment supplements through supplied hooks, never replaces.

Implements D-05 (one module home lib/core/recovery/ - layout resolved: case-file.cjs for persistence, controller.cjs for the state machine; case file under the run's .mindrian workspace; profiles diagnostic | high_effort | forensic with forensic prohibiting mutation and emitting a human review packet), D-06 (hard fences are TESTS: egress un-weakenable, unknown-never-zero, writer-bypass impossible via grep + behavioral, readback-truth, injection-as-data; capability-based model selection recorded in the attempt ledger), and D-07 (the material-surface Tier-3 offer reuses 219's D-20 gate semantics - the offer-verb pattern - one doctrine, zero duplication).

The LLM-adapter shape (how a CJS module "does" LLM recovery): the controller exposes hook seams (ctx.diagnoseFn, ctx.executeFn, ctx.reconcileFn) that the invoking surface supplies - at run time that surface IS the model (the same D-20 llm-manual pattern 219 shipped); in tests they are stubs. Every hook result passes the deterministic validators before acceptance; ctx.modelInfo {model, version} (capability-resolved at runtime by the surface, never name-pinned - SPEC out-of-scope rule) is recorded in the attempt ledger on every hook call. Governance never branches on the model identity (D-06: a model change never alters governance).

Purpose: when deterministic recovery is not enough, intelligence recovers the run - inside fences it cannot cross.
Output: case-file persistence module, controller state machine, state-machine tests, the hard-fence suite.
</objective>
