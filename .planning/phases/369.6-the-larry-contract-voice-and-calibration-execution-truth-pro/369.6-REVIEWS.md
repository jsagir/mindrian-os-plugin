## Concerns

### C1. HIGH: Room isolation is retrospective and contradicts the no-read rule

**369.6-02 Task 2; 369.6-05 Task 2; 369.6-04 Task 2**  
Paths: `scripts/eval-larry-voice.cjs`, `scripts/session-start`, `tests/test-3696-one-next-move.cjs`

`snapshotGuardedPaths()` explicitly reads metadata under `~/MindrianRooms`, contradicting the owner’s prohibition on reading those rooms. Its two-level mtime/size snapshot also cannot establish that no nested file changed, and detecting damage afterward does not prevent it.

Setting only `MINDRIAN_HOME` and `MINDRIAN_ROOMS_HOME` is insufficient. The existing `scripts/session-start` directly uses `$HOME` for writes, including `.mindrian-last-version` and `.mindrian`, and reads installed-plugin state there. `buildRoom()` also mutates `process.env.MINDRIAN_ROOMS_HOME`.

Foreign-plugin and room-path refusals occur after the live session has run. They cannot support the claim that the session “cannot” access a real room.

### C2. HIGH: The recorded tool log cannot prove the room fence, OP2 or approval order

**369.6-05 Task 2**  
Paths: `scripts/eval-larry-voice.cjs`, `tests/fixtures/3696-operation-stream.jsonl`

`parseStream()` retains input **key names**, discarding values, and retains results only for `suggest_next` and `chain_resolve`. That loses:

- The actual `room_bind` target and other path arguments.
- Whether an attempted operation succeeded or refused.
- Whether an approval authorized the particular material action.
- Whether approval preceded that action.

OP2 cannot distinguish an attempted call from executed work. The room fence cannot inspect paths that the parser discarded. OP5’s command-name match also falls short of R-23’s “same engine call, same words.”

### C3. HIGH: The Jev boundary validates shape, not provenance

**369.6-02 Task 2**  
Path: `scripts/eval-larry-voice.cjs`

`assertJudgeEgress()` permits a known probe id, bounded reply length and text without home paths. Those conditions do not prove that text is invented fixture material. An imported or edited reply containing private content can satisfy all of them.

The missing `tool_log` field is also not proof that a reply contains no Theo-derived material. This matters because rungs capture real hook output before generating replies.

The vendor boundary needs trusted run provenance and isolation, not just prohibited-string checks.

### C4. HIGH: The evaluation composition and comparison contract are incomplete

**369.6-02 Tasks 1-3; 369.6-05 Task 2; persona-edit measurement tasks**  
Paths: `evals/larry-voice/rubric.json`, `scripts/eval-larry-voice.cjs`

Several problems undermine R-01 and A-03:

- Rung 1 is called the P method but adds all frontmatter skills. The research explicitly describes agent text only.
- The operational builder loads the plugin but does not explicitly select `larry-extended` or otherwise prove that its agent body is loaded. Plugin loading alone does not establish which persona was tested.
- The operational rung specification does not explicitly reproduce the same agent, skill, style and hook composition as the voice ladder.
- “Not comparable” does not have a defined failing or incomplete exit status.
- Judge abstentions, different judges and partial runs have no fixed comparison rules.
- More samples are proposed after a drop, but no sample aggregation or retry decision rule is specified.

The authorized optional-live policy may remain. Missing evidence must produce an incomplete result, not a successful comparison.

### C5. HIGH: Known-failure matching can hide new failures

**369.6-01 Task 3; 369.6-13 Task 1**  
Path: `tests/run-all-3696.sh`

The referenced `tests/run-all-3692.sh` implementation classifies a failing test as KNOWN whenever its output contains the recorded signature. If the old failure and a new failure both appear, it still reports KNOWN.

That violates D-19’s “no new failing leg.” Recording exact baseline failure sets is necessary; matching one familiar substring is insufficient.

### C6. HIGH: The KNOWN-pass rule creates a guaranteed intermediate failure

**369.6-03 Task 1; 369.6-07 Tasks 1-2**  
Paths: `tests/test-3696-identity-parity.cjs`, `references/personality/voice-dna.md`, `lib/mcp/larry-context.cjs`

C9 checks whether `loadLarryContext(...).full` contains the shared identity sentence. Plan 07 Task 1 changes `voice-dna.md`, so C9 becomes true immediately: the loader directly concatenates that file.

Other threshold-based KNOWN legs can also become true earlier than their nominated closing plan. Their transition policy must accommodate that without weakening the assertions.

### C7. HIGH: The drift test cannot detect the advertised unknown names

**369.6-03 Task 2**  
Path: `tests/test-3696-persona-drift.cjs`

Tool-token prefixes are derived from existing registered tools. The required synthetic `not_a_tool` example need not share any registered prefix, so extraction can miss it entirely.

The same issue applies to unknown section slugs if extraction recognizes only canonical names. A resolver that rejects unknown references is ineffective when extraction silently ignores them.

D-42 needs explicit reference syntax or another extraction grammar independent of the current valid-name set.

### C8. MEDIUM: The closing gate expects deferred panel wiring

**369.6-04 Task 2; 369.6-09 Task 2; 369.6-13 Task 2**

### C9. MEDIUM: Parallel plans share mutable verification state

### C11. LOW: House-rule and fixture exceptions are ambiguous
