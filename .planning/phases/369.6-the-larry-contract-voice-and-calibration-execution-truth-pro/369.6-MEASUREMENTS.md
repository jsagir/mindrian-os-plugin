### (n) The isolation statement (D-31)

What holds the rule that no run changes the owner's rooms, without reading those rooms: the child gets a scratch HOME and explicit roots set before it starts (`isolatedEnv`, built from a table, never copied from the parent); the built-in file, shell and web tools are off (`--tools ""` and a deny list in the scratch settings file); only the dev plugin's own MCP tools are allowed; a PreToolUse fence (`evals/larry-voice/fence-hook.cjs`) denies, before execution, a path with a parent-directory component (checked before any normalisation) and any path outside the scratch root by canonical containment, symlink escapes included, with no stat outside the scratch root; the post-run parser repeats the same check as a second line; the run exits 1 on any fence entry, a wrong-room bind, a foreign plugin or server in the init event, or a repository change (a content fingerprint, so a second write to an already modified file is seen).

The limits, stated plainly: a write that bypasses every tool call, every hook and every configured root is not observable without reading the real rooms, which the domain rule forbids; a link created inside the scratch root between the fence check and the call is caught only by the parser after the call; the flag set (`--tools ""`, `--settings`, `--permission-mode dontAsk`, the hook decision shape) comes from `claude --help` of 2.1.312 and the repo's own hooks, not from a live run, so the first live run confirms it. `scripts/sessionstart-npm-reconcile.cjs` counts as containable only when the run-time proof of its switch `MINDRIAN_NPM_RECONCILE_SKIP` passes.
