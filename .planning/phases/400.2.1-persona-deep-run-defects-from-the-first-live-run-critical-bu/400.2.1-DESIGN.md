The text words lose the same function words. ## S5: reader search screen hook
- Owner ruling 2026-11-26, in the owner's words: "A: screen with a hook". It overrides owner answer second-1 of 400.2 (400.2-OWNER-REVIEW.md:170, "No run sentinel and no change of scripts/web-credential-guard-hook.cjs") for the run sentinel only. The credential guard does not change.
- Change: a new PreToolUse hook, scripts/persona-reader-search-guard-hook.cjs, on `^(?:WebSearch|WebFetch)$`, timeout 5. Round 3, owner ruling "Fail closed, plus an off switch": hooks.json gives it `onFailure: block` (test-391 H5, test-261029 A5 and test-389 now name three guard hooks), and it also fails closed inside (exit 2 when the screen cannot run while a marker file exists). The off switch is the maintenance subcommand `persona-hats.cjs disarm-reader-screen [--run <id>]` (not in SUBCOMMANDS, so the run budget does not change); every block message names the run id and that command.
- Require graph (round 3): the hook loads lib/core/persona-reader-screen.cjs only (node built-ins, plus rs-egress-prompts.cjs for the content fence), not the door. The module holds roomVentureNameOf, roomIdentityScreen, screenSearchText, readLedger and liveReaderMarkers; the door and persona-ops import them. Cold p95 on the worst-case room (12 reading-list files of 256 KiB, 200 team files, 2,000 artifacts): 373 to 615 ms (three runs); budget 1,000 ms, five times below the 5 s timeout (test-261029 A5c; H9 measures it on every run). With no marker the hook returns in about 40 ms without loading the module. run-research writes a marker `<MINDRIAN_HOME>/persona-hats/reader-search/<run_id>.json` (schema, run id, room path, created_at, expires_at; no token); plan-research writes it when it skips run-research. merge removes it. A marker older than 2 hours, past expires_at, or not valid is ignored and removed. Round 3 (M1): a marker is removed only when its run is not found or its run is merged; any other ledger failure (for example ledger_invalid) is a block with `reader_search_screen_unavailable` and the marker stays. Round 3 (M2): the screen is armed only when the room identity screen runs; a room that states no name gets `not_armed:no_room_name` and no marker.
- Screen: `screenSearchText` of the door, the same function as the after-the-fact count of check: the content fence (auditQueryString), then the room identity screen of the room of the run (venture name tokens, room directory, team files, proper nouns of the reading list). It screens the WebSearch query (raw and decoded) and, for WebFetch, the path and the query of the url, raw and decoded (round 3, M3: plus to a space, then decodeURIComponent inside a try). Round 3 (M5): the host is not screened, and a closed list of well-known organisation, vendor and path words (wikipedia, google, github, arxiv, openalex, statista, python, blog, news and similar) is skipped in a url. Wrong-block measure on the riemann-claim-hats run: 0 of 10 self-found urls blocked wrongly (1 blocked, holding the room name and a person name); see RESEARCH.
- Egress effect, exact: while a deep run is open, a WebSearch query or a WebFetch url of this machine that holds a screened room word or fails the fence is blocked before it is sent. Nothing else changes: the hook sends nothing, and a query or url with no screened word leaves as before. The screen cannot catch a figure or a detail with no screened word, and the WebFetch prompt is not screened. ASSUMED: the hook input has no reliable field that names the subagent, so the marker screens every WebSearch and WebFetch call of the machine while the run is open, the orchestrator included.
- The ledger keeps `reader_search_screen` (armed, not_armed:<reason>, or lapsed). The review artifact says "A hat's own searches passed the reader search screen of the door ..." when the marker was live at the merge; "The reader search screen of this run expired or was removed before the merge. No code screened ..." when it lapsed (round 3, M2); and the prompt-rule line ("No code checked them ...") when it was never armed. The reader contract and the search card sentence name the hook.
- Tests: tests/test-40021-reader-search-hook.cjs (H1 to H9: fail closed, ledger_invalid, run_not_found, expires_at in the past, encoded url, no room name, off switch, require graph, latency); test-389, test-261029 (A5, A5c), test-391 H5 and data/arbitration-rule-catalogue.json record the hook; tests/test-369-hook-require-graph.cjs runs in run-all-40021.
