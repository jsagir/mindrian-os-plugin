## S4: relevance floor on door findings
- Change: `wireAndRecord` checks each finding before the wire call. The handle words are the words of the approved string minus the hat qualifier, in order, each with a final s removed. A finding passes when its title and summary hold two handle words next to each other in the handle order, or every handle word (a one-word handle needs that word). A finding that fails is not wired: the string record counts it (`dropped_below_floor`) and lists up to 10 of them (title and url). The run output gets `dropped_below_floor.<hat>` and, on each string, `dropped_below_floor` and `dropped`. A string whose findings were all dropped gets `fetched_not_wired:below_relevance_floor`. The evidence pack keeps its closed key list (S7 of test-4002-research-states pins it), so the count is in the run output only. commands/persona.md Step 5.6 prints the count. Nothing is dropped silently.
- Evidence for the rule: a floor of 1 or 2 shared words keeps "Hairy Black Holes in a Box" (black, box) and "Natural Law Theory ..." (law, theory). The adjacent-pair rule drops all 3 observed titles (test R1). PROVEN on titles only; the summaries of the live run were not kept, so the effect on them is ASSUMED.
- Cost (measured): the synthetic compare fixture of plan 400.2-16 has 10 paraphrased on-topic items; the rule dropped 7 of them until each abstract named its handle. A lexical floor cannot keep a paraphrase. A semantic reranker is the full fix and is not in this phase. The constant rule is in one function (`meetsRelevanceFloor`) for tuning.
- Fixtures: synthetic fixture texts ("About the field") now name the handle of their string, so the existing legs keep their intent.
- Test: tests/test-40021-relevance-floor.cjs (R1 to R3).
- Part 8: none (local filter after the fetch, no new egress). Part 9: fewer proposed evidence nodes; the filter runs before the one wire chokepoint, which is unchanged. Part 11: none.
