### S5: the screen covers web calls outside the persona run

**What starts the screen.** One marker file: `<MINDRIAN_HOME or ~/.mindrian>/persona-hats/reader-search/<run_id>.json`. The door writes it at the end of a successful `run-research` step of a deep run, or at the end of `plan-research` when no hat is planned. It writes it only when the room states a name (a STATE.md `venture:` line, a real first heading, or the ROOM.md `icm_self.room` key). Else the state is `not_armed:no_room_name` and nothing is screened. Quick mode never arms the screen.

**What ends the screen.** The first of these:
1. The `merge` step of that run removes the marker.
2. The off switch removes it.
3. The marker is older than 2 hours (or past `expires_at`): the next hook call removes it. This covers a run that was left before the merge.
4. At a hook call the run folder is not found, or the run is already merged: the hook removes the marker.
5. The marker file is not valid: the hook removes it.

**What is screened while it is live.** Each WebSearch query and each WebFetch url path and query, in every Claude Code session of this user that loads the plugin hooks, in any project. The hook does not know which agent calls. Screened words: the venture name words, the room directory words, the team file names, and each capital-letter word of the reading-list files that does not start a line or a sentence; 4 letters or more; a stop list of 33 common words is skipped. Not screened: the url host, the WebFetch prompt, `allowed_domains`, MCP search tools, shell commands.

**How the off switch works.** `node scripts/persona-hats.cjs disarm-reader-screen --run <run_id>` removes the marker of one run. With no `--run` it removes every marker. It prints `{"ok": true, "removed": [...]}`. It writes no ledger. The merge of that run then records `lapsed`, and the review says: "The reader search screen of this run expired or was removed before the merge. No code screened the own searches of the hats after that point." Each block line of the hook names the run id and this command. commands/persona.md tells the assistant to run it only when the navigator asks.

**What a person sees when a web call that is not part of the persona run is refused.** The web call does not run. The hook exits with code 2 and gives this one line to the assistant (PROVEN text):

> Canon Part 8 (hat reader search, run `<run_id>`): the search text holds a room detail or could not be screened (reason room_identity_word). The request was blocked and nothing was sent. Search with general words of the field, with no venture name, person name, figure or other room detail. To stop this screen, run: node "`<plugin>`/scripts/persona-hats.cjs" disarm-reader-screen --run `<run_id>`

How the host shows this line on the screen is UNVERIFIED (ASSUMED: a hook notice in the transcript, and the assistant says in its own words that the search was blocked). The line does not say which word hit (by design). It says "hat reader search" also when the call comes from another window, and it does not say in plain words that a deep persona run is open on this machine.
