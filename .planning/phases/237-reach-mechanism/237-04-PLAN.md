<objective>
Stop a candidate reach in one session from being driven by another session's marker file.

Purpose: `deriveTurnSignals(ctx)` derives `artifact_filed` and `first_material` from `<roomDir>/.mindrian/last-cascade.json` and `<roomDir>/.mindrian/auto-explore-*.json` using nothing but a 30-minute mtime window. Freshness is being used as a proxy for ownership and it is not one. Three links are missing at once: neither marker's PATH carries a session id, neither marker's CONTENT carries one, and `ctx` does not carry a `sessionId` to compare against even if it did. Session A files an artifact, and within 30 minutes session B's `suggest_next` reports A's action as B's own turn signal. This is a Cowork-critical defect, not a CLI curiosity, because Cowork is explicitly multi-user concurrent.

This plan fixes the READER half and defines the marker contract. Plan 06 makes the writers stamp it.

The direction that matters most: this check is a FILTER, not a GATE. A gate fails closed; a filter fails OPEN. Suppress ONLY on a positive mismatch, meaning both the marker's session id and the caller's session id are present AND different. Every other state fires. Over-suppressing would trade a visible bug for an invisible one, and `resolveEffectiveSessionId` genuinely returns null on stdio in real installs, so a fail-closed design would silently kill the reach layer on a common surface.

The fix goes in `lib/core/insight-sensors.cjs`, the shared module both the MCP path and the CLI navigation-engine path call. A fix landing in `lib/mcp/tools/sensors.cjs` alone is a Tri-Polar violation and leaves CLI and Cowork bleeding.

Output: a widened `deriveTurnSignals(ctx, sessionId)`, a new exported `isMarkerOwnedByCaller` helper both readers share, and a two-process fence plus four degrade legs.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| concurrent session A -> shared room filesystem | Session A writes `<roomDir>/.mindrian/*.json` markers that session B reads; this is the untrusted-across-sessions edge |
| marker file content -> signal derivation | `session_id` read out of a JSON payload written by another process |
| caller turn -> `deriveTurnSignals` | The caller-asserted session id, threaded from upstream, never re-derived here |
