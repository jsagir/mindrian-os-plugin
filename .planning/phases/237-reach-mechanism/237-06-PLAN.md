<objective>
Make the two marker writers stamp the session that produced them, so the reader Plan 04 built has something real to compare against.

Purpose: Plan 04 closed the read side and made every unstamped marker fire for everyone (the correct backward-compatible degrade). That fix is complete and safe on its own, but until the writers stamp, no marker is ever suppressed and the bleed persists on newly written markers. This plan closes the loop.

The enabling fact, confirmed against the official Claude Code hooks documentation during research: `session_id` is a documented COMMON input field on every hook event, including `PostToolUse`. Both writers sit behind hooks that already parse hook stdin JSON and simply discard the field. `grep -n "session" scripts/post-write` returns zero hits today, and `grep -n "session" scripts/auto-explore-fire.cjs` returns one comment and zero code.

Research assumption A2 asked whether a session id can reach `scripts/auto-explore-fire.cjs`, which is spawned detached and therefore not a hook itself. It can, and the path is verified: `scripts/auto-explore-fingerprint.cjs` IS a registered hook (`hooks/hooks.json` line 292), it already reads stdin JSON to extract `file_path`, and it spawns `auto-explore-fire.cjs` with a three-element argv at line 319. Threading the session id is one more argv element. A2 is resolved, not assumed.

Output: `session_id` on both marker payloads, the atomic write discipline preserved byte-for-byte, and an end-to-end test that drives the real bash hook and the real detached script rather than a reimplementation of them.
</objective>
