## How GSD actually parallelizes (mechanics, read from ~/.claude/gsd-core/workflows/execute-phase.md)

- `/gsd-execute-phase` parallelizes WAVES OF PLANS WITHIN one phase, via
  `Agent(subagent_type="gsd-executor", isolation="worktree", run_in_background=true)`.
- Those `Agent()` calls are dispatched ONE AT A TIME, one per message. The one-at-a-time discipline is not
  politeness: simultaneous `Agent()` calls race on `.git/config.lock` during `git worktree add`.
- Once the worktrees exist, the agents DO run concurrently. The serialization is only at dispatch.
- What it does NOT do: parallelize ACROSS phases. There is no cross-phase orchestrator.
- Achieving cross-phase parallelism requires either:
  - (i) separate concurrent top-level sessions or terminals, one per phase, or
  - (ii) one `Agent()` per phase within a single session, each with `isolation="worktree"`, each
    independently running that phase's `/gsd-plan-phase` or `/gsd-execute-phase`, under the same
    one-at-a-time dispatch discipline.
