# Quick 261029-s9x: cache the telemetry room walk (perf change D)

<objective>
Stop the PostToolUse telemetry hook from walking the whole room on every Read, Grep and Glob call.

scripts/query-efficiency-telemetry.cjs runs after every Read, Grep and Glob. It calls estimateRoomTokens(roomRoot) (lib/core/token-estimator.cjs line 152). That function walks every directory of the room with readdirSync and calls statSync on every .md file. The cache in that function is a Map in memory, so it dies with the hook process: every hook call walks again. On the real room on /mnt/c this costs about 613 ms per call (audit finding 4: stat 362 ms, readdir 212 ms).

After this plan:
1. A tool result with no countable text (tokens_used 0) exits before the hook resolves the room and before the estimate (DD-1). The output does not change.
2. The estimate is cached in <room>/.mindrian/token-estimate.json for 10 minutes (DD-2). A hit is one small file read.
3. A miss walks the room with fs/promises and a bounded fan-out of 32 (DD-7). The token count is the same number as the old sync walk (DD-8).
4. A new test pins the cache, the parity, the failure paths and the hook end to end.
5. The real-room numbers before and after are in the SUMMARY and in one CHANGELOG bullet.

Output: tests/test-261029-s9x-token-estimate-cache.cjs (new), lib/core/token-estimator.cjs, scripts/query-efficiency-telemetry.cjs, CHANGELOG.md (one bullet).
</objective>

## Interfaces (to build; the test of Task 1 pins them)

lib/core/token-estimator.cjs adds, next to the existing API:

- `TOKEN_ESTIMATE_CACHE_FILE = 'token-estimate.json'` (the file lives in `<roomRoot>/.mindrian/`).
- `TOKEN_ESTIMATE_MAX_AGE_MS = 600000` (10 minutes).
- `WALK_FANOUT = 32`.
- `walkRoomTokensAsync(roomRoot) -> Promise<{ tokens: integer, fileCount: integer } | null>`. Never rejects. null for a non-string or empty input, a missing path, a path that is not a directory, or an unexpected error.
- `estimateRoomTokensCached(roomRoot, opts) -> Promise<integer | null>`. opts is optional: `{ now?: number }`, milliseconds since the epoch, a test seam for the clock. Never rejects. null in the same cases as walkRoomTokensAsync.
- Cache record (exactly these 4 keys, all integers): `{ "version": 1, "computed_at_ms": <ms since epoch>, "tokens": <integer >= 0>, "file_count": <integer >= 0> }`, then a newline.
- Unchanged: estimateTokens, estimateRoomTokens (sync, in-memory Map), clearCache, validateEventShape, classifyRatio, aggregateEvents, EVENT_REQUIRED_FIELDS, BELOW_THRESHOLD_RATIO, MAX_ROOM_DEPTH = 12 (internal).

## Design decisions made in planning (DD-1..DD-9)

- DD-1, zero-token exit first. In main(), compute tokensUsed directly after the tool gate and extractSlashCommand, and run `if (tokensUsed <= 0) return exitSilent();` before resolveRoomRoot() and before the estimate. The estimator require moves up with it, because estimateTokens is in that module. Every exit before the JSONL append is silent today, so the output does not change on any path. Reason: a real Read result gives tokens_used 0 (facts above), and the hook paid the room walk, plus a bash resolve-room spawn when cwd has no .room-root, for an event it never writes. This goes beyond the audit design. It is the code that says otherwise (C-1).
- DD-2, the validity rule is the age alone: a cache entry is valid when 0 <= now - computed_at_ms < 600000. There is no top-level mtime check and no root mtime check. Reasons: (a) the top-level check costs 20.0 ms async and 81.2 ms sync per call on the real room, about 3 times the cache read (7.0 ms); (b) plugin writes change the root mtime (each STATE.md rewrite) and every section mtime (FEYNMAN.md rewrites), so an mtime rule would discard the cache after the plugin's own writes; (c) a directory mtime does not change when a file in it is edited, so the check is partial in any case; (d) one 10 KB artifact moves a 200,099-token estimate by about 1.3 percent, far from the 10x line of classifyRatio. A hit is one file read and no stat. Task 1 records the probe numbers again on the day of execution. If they differ, keep DD-2 and report the numbers in the SUMMARY.
- DD-3, no mkdir. The estimator writes the cache only when `<roomRoot>/.mindrian` already exists as a directory. It never creates .mindrian/, because a new .mindrian/ switches on the Phase 88 block of on-stop (on-stop-state DD-2). When .mindrian/ is absent, every call walks (async), and that is still faster than today.
- DD-4, keep estimateRoomTokens and clearCache unchanged, byte for byte. The cache is a new async function. Reason: test 5 of lib/memory/query-efficiency-telemetry.test.cjs needs clearCache() to make the next sync call count a new file; a disk read inside the sync function would return the old value. The old sync function also stays the parity reference.
- DD-5, keep the default libuv thread pool. Do not set UV_THREADPOOL_SIZE. The planning probe shows no gain from a pool of 32 (114 and 145 ms against 119 and 121 ms).
- DD-6, the cache record is the 4 integer keys of the Interfaces section. It has no path, no file name and no content. It has no mtimes (DD-2). computed_at_ms comes from the same clock as the validity check (opts.now or Date.now()).
- DD-7, the bounded fan-out. A small inline limiter with a slot count of WALK_FANOUT wraps only the leaf fs calls: fs.promises.readdir and fs.promises.stat. Warning: do not wrap the recursive walk function in the limiter. A parent that holds a slot while it waits for children that need slots can deadlock the walk. The walk of a directory starts its children and file stats, then awaits Promise.all of them.
- DD-8, the same rules as the old walk. Skip every name that starts with '.'. Recurse into Dirent.isDirectory() entries with depth + 1, and return when depth > 12 (root depth 0). Count only Dirent.isFile() entries whose name matches /\.md$/i, by the size from fs.promises.stat. Skip symlinks (Dirent is neither a file nor a directory). A readdir error skips that directory; a stat error skips that file. node_modules is NOT skipped, because the old walk does not skip it. tokens = Math.ceil(totalBytes / 4). fileCount is the number of .md files whose stat succeeded.
- DD-9, the extractor is not changed. A real Read result has its text under tool_response.file.content, which the hook does not read. A fix would start a JSONL line for every Read, which changes what the telemetry records. That is a decision for the main session (RISKS R-1, NEXT).
