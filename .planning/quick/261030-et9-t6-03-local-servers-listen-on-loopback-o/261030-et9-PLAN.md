## Deviations from the orchestrator design (planner)

- DV-1, Host port: `hostHeaderAllowed(hostHeader)` checks the host name only. A port in the header must be 1 to 5 digits, but it is not compared with the server port. Reason: the host name alone blocks DNS rebinding (a rebinding page always sends its own name). A port compare adds no protection and breaks an SSH or editor port forward to a different local port. lib/core/mcp-install-responder.cjs isLoopbackHostHeader uses the same rule.
- DV-2, CORS port: `corsHeaders(reqOrigin, port)` takes the server port. The servers pass `req.socket.localPort`.
- DV-3, one 403 writer: the helper also exports `refuseForeignHost(req, res)` and `expressHostGuard(req, res, next)`, so the 403 response is written in one place.
- DV-4, probes: the port probes of serve-wiki and serve-presentation also move to 127.0.0.1, for consistency with the servers they start. They are probes, not servers. The static arm checks all of scripts/.
- DV-5, commit order: the test commit comes first and alone (pure RED). The helper commit comes second.
- DV-6, out of scope: no Host guard for lib/wiki/wiki-server.cjs and no Host guard for the Python dashboard in this quick. Both stay residual T6-08 exposure (RISKS, NEXT).
