# Quick Task 260602-0pb: Fix Windows shell bug in installer cli.js spawnSync

## Problem

`npx @mindrian_os/install` aborts on Windows with "Claude Code is not installed
(no `claude` command on your PATH)" even when `claude --version` works in the
user's shell. Confirmed live by tester "rea" on Windows 10.0.26200, Claude Code
2.1.159.

Root cause: `bin/cli.js` spawns `claude` via `spawnSync('claude', ...)` with no
`shell` option. On Windows the npm-global `claude` binary is a `claude.cmd`
shim; Node's `spawnSync` without `shell:true` does not consult `PATHEXT`, so it
looks for a bare file named `claude`, fails with ENOENT, and the installer
falsely reports "not installed". The interactive shell consults `PATHEXT` and
resolves `claude.cmd`, hence the contradiction.

## Scope refinement (deviation from initial brief)

The initial brief said "add `shell` to the `run()` helper". That is WRONG and
would regress Windows: `run()` is also called as `run(process.execPath, ...)`
in the `doctor` subcommand, and on Windows `process.execPath` is
`C:\Program Files\nodejs\node.exe` (contains a space). With `shell:true`, Node
passes the command unquoted to cmd.exe, which parses `C:\Program` as the
command and breaks. `git` (real `.exe`) and `process.execPath` resolve
correctly WITHOUT shell; only the `claude` `.cmd` shim needs the shell route.

Therefore the fix is SCOPED to `claude` spawns only, via a dedicated
`runClaude()` wrapper, leaving the generic `run()` helper untouched.
