<objective>
Fix the release.sh Step 9.7 registry-propagation poll, which does not poll.

Proven cause (do NOT re-derive it): release.sh runs under `set -euo pipefail` at
line 86. The poll body at line 1211 is
`PROP_SEEN="$(npm view "@mindrian_os/cli@$NEW_VERSION" version 2>/dev/null | tr -d '[:space:]')"`.
With pipefail the pipeline's status is npm's exit 1 (E404 while the registry is
still processing an asynchronous publish), the assignment inherits it, and
errexit kills the whole ceremony BEFORE the loop prints its first
`waiting for npm registry` line. Both the v2.0.0-beta.43 (09:58:03 UTC) and
v2.0.0-beta.45 (14:09:24 UTC) logs of 2026-09-17 end one line after
`-> sandbox: ...` with zero waiting lines, and the NPX_PROP_RETRIES /
NPX_PROP_BACKOFF_S overrides set for beta.45 were inert because the loop never
iterated. Every asynchronous npm publish therefore drops the ceremony into the
RULE 7 split-brain state.

Purpose: an asynchronous npm publish (about 10 min on beta.43, about 8 min on
beta.45) must be waited out, not fatal. Release infra, so RULE 6 beta-first:
this ships in v2.0.0-beta.46.

Output: three atomic commits. A new errexit-safe release-lib function plus its
unit suite, the Step 9.7 rewiring with a 12-minute default budget, and the
corrected/resolved RCA with its docs and CHANGELOG lockstep.
