# Phase quick-260819-c55 Plan 01: One Resume Owner for material_step Gates Summary

Split chain.cjs's resume logic into a consume-half and an execute-half, minted the
execute-half onto the gate-ledger entry as a callable `resumeFn`, and made `gate_answer`
delegate to that function reference so an approve verdict through the documented resume
verb actually runs the halted material step and returns its real result, instead of
dying at `unknown_or_expired_gate` on the second (dead) leg of the old two-step flow.

## What Was Built

**Task 1 -- `lib/mcp/tools/chain.cjs` (commit `9fe51871`).** Extracted
`_executeResumedEntry(entry, gateAnswer)` out of `_resumeFromGateAnswer` as the ONE
execution authority for a halted material step: chosen validation against the entry's
card, the non-approve early return, the `onStepFn` call wrapped in try/catch, the
completed-chain return, and the recursive `chainRun` tail continuation, all moved
verbatim (same reason slugs, same response shapes). `_resumeFromGateAnswer` now owns
only the consume half (missing-gate-id check, `_consumeResumeLedger`, the
`unknown_or_expired_gate` / `session_mismatch` branches) and delegates to
`_executeResumedEntry`. `chainRun`'s halt-and-mint block hoists the ledger-entry object
literal into a named `resumeEntry` const and attaches `resumeEntry.resumeFn = function
(gateAnswerPayload) { return _executeResumedEntry(resumeEntry, gateAnswerPayload); }`
before minting -- a doctrine comment above it explains why this is safe (the stored
ledger copy and the closed-over `resumeEntry` are interchangeable for every field
`_executeResumedEntry` reads; the function reference is the ONE way another
`lib/mcp/tools/*.cjs` module reaches this execution path without requiring chain.cjs;
minting the reference adds no new execution authority because the entry stays
unreachable until someone wins the single consume). `_executeResumedEntry` is exported
on `module.exports._internal`. `chain_run`'s tool description and its `gate_answer`
parameter's `.describe()`, plus the module header, now state the one true flow instead
of the dead ratify-then-thread-back sequence.

**Task 2 -- `lib/mcp/tools/gate.cjs` (commit `10063962`).** After the existing
`chosen`-validation block and before any room-db access, added a fail-closed guard: a
`material_step` entry with no callable `resumeFn` returns `{ok:false,
reason:'resume_owner_missing', gate_id}` before anything is written. After the existing
`logMemoryEvent` write, added the delegation: for a `material_step` entry, `await
live.resumeFn({gate_id, chosen: validChosen, verdict})` (the RESOLVED option ids, not
the raw submitted `chosen`), wrapped in try/catch mapping a thrown error to
`{ok:false, reason:'resume_fault', detail}`. The response nests the result under
`chain_result` with `resumed:true` (never spread, to avoid clobbering the ratification
fields), and the top-level `ok` / `isError` flip false when `chain_result.ok === false`
-- an execution fault never reads as a green ratification. `gate_answer`'s tool
description now states the same one-flow contract `chain_run`'s description states.

**Task 3 -- test convergence (commit `e544e0c6`).** Created
`tests/test-c55-one-resume-owner.cjs` (295 lines, 17 assertions): four interleavings
(gate_answer-then-chain_run, chain_run-then-gate_answer, gate_answer-twice,
chain_run-twice), each on its own freshly halted chain with its own execution-witness
counter, asserting the first caller succeeds, the second is refused with
`unknown_or_expired_gate`, and the counter equals exactly 1; a reject case (counter
equals 0, gate still burned); and an anti-vacuity control (a never-minted id refused by
both verbs). Updated `tests/test-238-one-ledger.cjs` to add the execution assertions its
Case 1/3 region never had (`stepCounter.n === 1`, `answer.resumed === true`,
`answer.chain_result.executed === true`) -- the id-identity check alone was vacuous
about whether the step actually ran. Updated `tests/test-237-approve-executes.cjs`
header only (no assertion changed): names `chainRun(null,{gateAnswer})` as the direct
path and `gate_answer` as the MCP-surface sibling verb over the same single-use entry,
cross-references the new interleaving file, and relabels Leg 6 as the
double-execution guard rather than an isolated single-use quirk.
