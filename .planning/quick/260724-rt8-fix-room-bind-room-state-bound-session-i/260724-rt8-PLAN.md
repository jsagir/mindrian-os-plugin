<objective>
Fix the room_bind/room_state_bound false-success bug: on the stdio transport (local Claude Code CLI), the MCP SDK never populates `extra.sessionId`. `room_bind` already carries a proven 3-tier fallback (explicit param > `extra.sessionId` > `process.env.CLAUDE_CODE_SESSION_ID` > null; tool-router.cjs:1478-1481) that was never propagated to its 20 sibling call sites across 9 files, which still do the bare, broken `(extra && extra.sessionId) || undefined`. Those sibling tools (including room_state_bound) silently fail to resolve a session id on stdio and fall through to the wrong, machine-wide resolution path -- reproducing the exact false-success bug already live-verified in a prior session (room_bind reports `bound:true` while room_state_bound reads an unrelated stale room).

Purpose: widen session-id resolution to the already-proven fallback everywhere it is missing, so every MCP tool call in a single stdio session resolves the SAME session id and therefore reads/writes the SAME per-session binding file.

Output: one new shared helper (`resolveEffectiveSessionId`) in lib/core/session-binding.cjs, room_bind refactored to call it instead of its own inline copy, and all 20 sibling call sites updated to call the same helper. Purely additive -- widens resolution, never removes a working path.
</objective>

| Boundary | Description |
|----------|-------------|
| MCP client request -> tool handler session-id resolution | Client-supplied explicit session id params (room_bind's `sessionId`, stop_gate_check's `input.session_id`) cross into a function whose return value is later used to derive a filesystem path (`sessionsDir(home)/<sessionId>.json`) |
| Host process env -> tool handler session-id resolution | `process.env.CLAUDE_CODE_SESSION_ID` is set by the Claude Code CLI host process itself; it is not part of the MCP JSON-RPC request payload and cannot be set by a tool-call argument |

| T-RT8-03 | Information Disclosure | Env-var fallback (`CLAUDE_CODE_SESSION_ID`) resolves a session id sourced from the host process | accept | Identical trust level to the already-shipped room_bind fallback this plan propagates; the env var is host-process state, never attacker-controlled request data |
