<objective>
Fix the two contract mismatches that make `/mos:intel-pipeline` fan out with zero lenses and read as a silent halt, and lock the fix behind a hermetic regression test.

Purpose: `lib/core/intel-pipeline.cjs:118` calls `extractor.extractContext(context.roomDir, { dimension })` positionally, but `lib/core/research-context-extractor.cjs:253` is `function extractContext(opts)` taking ONE object (it reads `opts.roomDir`, `opts.topic`, `opts.db`), so the extractor sees no roomDir. Then `lib/core/intel-pipeline.cjs:121` spreads the extractor's snake_case `lens_set` (returned at `research-context-extractor.cjs:278`) into the driver, but `lib/lens-engine/source-lens-driver.cjs:445` reads camelCase `opts.lensSet`. `rawLensSet` is therefore `[]`, the driver returns `{ ok: false, reason: 'empty_lens_set' }` at `source-lens-driver.cjs:450-452`, findings are empty, quality is `low`, and `intel-pipeline.cjs:440-445` halts the whole fan with the SEED-059 disclosure. The MCP path at `lib/mcp/tool-router.cjs:546-556` already does it correctly; `/mos:intel-pipeline` is the only broken caller (grep 2026-09-10, recorded in the todo). No test caught it because `tests/test-223-intel-pipeline.cjs` injects `researchFn` at every call site and never reaches `defaultResearchFn`.

Output: one failing-then-passing regression test, a three-line contract fix in `defaultResearchFn`, two injectable seams on `runIntelPipeline`, one `_internal` test export, one aggregator leg, and two cross-reference comments naming the single shared contract (Canon Part 7).
