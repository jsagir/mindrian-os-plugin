# Quick 261029-lx3: SessionStart reuses STATE.md and a cached analyze-room result, and runs the doctor at most once a day

## Design decisions made in planning (DD-1..DD-13), with the reason for each

- DD-1 (C-1, deviation from the literal text): the reuse path removes ONLY the `gsd_state_version:` and `status:` lines from the first frontmatter block. It does not strip the whole frontmatter. Reason: F-1 and F-2. The orchestrator text said "strip the YAML frontmatter", but that would delete computed, venture_stage, total_entries and current_room from the [Room State] block, and the same constraint requires an identical format.
- DD-2: Format guard. Reuse only when line 1 is `---`, the first frontmatter block has a line that starts with `computed:`, the first line after the closing `---` is `# Data Room State`, and no line equals `## Live (auto)`. Any other shape runs compute-state. Reason: F-3.
- DD-3: The recompute triggers are the on-stop-state set, in the same order: STATE.md missing or 0 bytes; the registry `${MINDRIAN_ROOMS_HOME:-$HOME/MindrianRooms}/.rooms/registry.json` is newer; STATE.md is older than 24 h (`find -mmin +1440`); the on-stop-state find prints a path. There is NO trigger on the compute-state script mtime. Reason: session-start does not write STATE.md, and on-stop-state has no such trigger, so a script-mtime trigger would force compute-state at every start after each update until the room changes.
- DD-4 (C-2): The analyze cache is a miss when any of these is true: the cache is missing or 0 bytes; `$SCRIPT_DIR/analyze-room` is newer than the cache (update or dev edit; session-start rewrites the cache itself, so this cannot loop); the root STATE.md is newer than the cache (F-4; the find excludes STATE.md by name); the cache is older than 24 h (F-4, day-relative lines); the on-stop-state find, with the cache as the reference, prints a path. The cache lives in .mindrian/, which the find prunes, so the cache never invalidates itself.
- DD-5: A room with no .mindrian/ directory runs analyze-room as today, with no cache. Do not create .mindrian/ (creating it switches on other blocks; the kqv DD-2 reason).
- DD-6 (C-2): On a miss, capture the stdout and the exit code separately. Print the stdout (the same text that today's `|| echo ""` keeps, including a partial stdout after exit 1). Write the cache only when the exit code is 0, the output is not empty, and the output is not exactly NO_ROOM. Write with `printf '%s\n'` to `<cache>.tmp.$$` in .mindrian/, then `mv -f` onto the cache. On a write failure remove the tmp file. A failed run leaves the old cache byte-identical.
- DD-7: Observability. When .mindrian/ exists, append one line per call to <room>/.mindrian/session-start-state.log: `<date -u +%FT%TZ> state mode=<reuse|compute> reason=<reason>` or `<date -u +%FT%TZ> analyze mode=<hit|miss> reason=<reason> rc=<n> cached=<yes|no>`. Remove newlines from the reason (the on-stop-state pattern). Stdout carries only the result. Task 3 uses these lines to prove the mode of each measured run.
- DD-8 (C-3): The throttle wraps BOTH doctor contributors (F-6). check-onboard-statusline.cjs is out of scope, so the throttle lives in scripts/preflight-doctor.cjs (in scope, no line budget) as `throttled(id)`, and the coordinator changes its 'install-drift' and 'onboarding' map entries to it. The coordinator diff is 2 changed lines plus 1 comment line (F-9).
- DD-9 (C-3): `--graph-derive-health` is above 300 ms (F-7, 599-636 ms), so 'install-drift' is throttled like the others. Task 3 re-measures it 3 times for the record.
- DD-10: Stamp path: `~/.mindrian/banner-state/sessionstart-throttle-<id>.json` (F-12; `os.homedir()` at call time). Fields: id, plugin_version, cwd, ran_at_ms, ran_at (ISO), fragment. The key is plugin_version for both ids, plus cwd for 'install-drift' only. Reason for cwd: graph-derive-health reads the room of the session, so another cwd can be another room, and another room's nudge must not show. The window is 24 h. The plugin version is read from `path.resolve(__dirname, '..', '.claude-plugin', 'plugin.json')`, the same file that check-onboard-statusline.cjs reads.
- DD-11: The decision of throttled(id)(), in order:
  1. Version unreadable: call the inner contributor directly (today's behaviour), mode no-version.
  2. 'onboarding' only: when `require('./check-onboard-statusline.cjs').shouldFire()` is false, call contributeOnboarding() directly. It returns an empty fragment without a spawn, as today. Mode gate-off. No stamp write. Reason: a cached gate must not show after the person confirms the statusline.
  3. Stamp file absent: run the inner contributor synchronously, write the stamp, return the result. Mode first-sync (the first-install path of C-3).
  4. Stamp readable, version equal, cwd equal when keyed, age 0 or more and under 24 h, and the cached fragment passes contributor-interface validateFragment: return the cached fragment. Mode fresh.
  5. Every other case (age, version, cwd, parse error, invalid fragment): start the detached refresh, then return the cached fragment when only the age is stale, else an empty fragment. Mode stale-detached, or stale-locked when a live lock exists.
  6. Any unexpected throw inside the throttle: call the inner contributor directly (today's behaviour), mode error-fallback. The throttle never removes a check.
- DD-12: Detached refresh. Lock `<stamp>.lock`, created with `fs.openSync(lock, 'wx')`, content `<pid> <ISO>`. EEXIST with a lock mtime of 120 s or less: no spawn (stale-locked). An older lock: unlink it and try once more. Spawn `child_process.spawn(process.execPath, [__filename, '--refresh', id], { detached: true, stdio: 'ignore', windowsHide: true, env: process.env, cwd: process.cwd() })`, then `child.unref()`. A synchronous spawn throw removes the lock. The child (`node preflight-doctor.cjs --refresh <id>`) runs the inner contributor synchronously, writes the stamp atomically (same-dir tmp `<stamp>.tmp.<pid>` plus renameSync), removes the lock in a finally block, and exits 0. Reason: the 1,500 ms Promise.race of the coordinator cannot stop a spawnSync (the event loop is blocked), so the only way not to wait is to not run it in the hook process.
- DD-13: Telemetry. Each throttled() call and each refresh child appends one JSONL line to `~/.mindrian/telemetry/sessionstart-doctor-throttle.jsonl` (the directory that sessionstart-errors.jsonl already uses): `{ts, id, mode, reason}`; the child writes mode refresh-done with elapsed_ms. Best effort, never throws. Task 3 uses these lines.
