# Phase quick-260713-fx2 Plan 01: Fix eureka freshness gate blind to nested artifact layout

## What

`scripts/eureka-command.cjs`'s `newestArtifactMtimeMs()` (the T-218-VD-5 freshness gate
built earlier this same session) walks exactly ONE directory level deep
(`roomDir/section/*.md`). Every real artifact this codebase files goes through
`navigation.cjs` into the STANDARD nested layout instead - `section/name/name.md`, one
folder per artifact (decisions.md #16) - including every `url-ingest.cjs` write. The
one-level walk never sees those files' mtimes, so the freshness gate always reads "nothing
changed" against a room with real, newer content, and `eureka run` silently never
auto-re-extracts in production.

## Why now

Found live, not in a fixture: ingested a real URL into `aion-eureka-synergy` via
`ingestUrl()` (a live smoke test of the just-shipped Phase 220 pipeline), then ran
`/mos:eureka run` expecting the new content to be auto-extracted first (T-218-VD-5's whole
point). The entity-extract status stayed dated yesterday; the new artifact never got
extracted automatically. Running `entity-extract.cjs` directly against the same room picked
it up fine (38->65 artifacts, 354->605 entities), proving the extractor itself was always
correct - only this mtime probe was shallow.

## Fix

`newestArtifactMtimeMs` now recurses (bounded `MAX_WALK_DEPTH = 8`, generous headroom for a
room directory that is never pathologically deep), skipping dot-directories at every depth,
not just the top one.

## Task

1. Fix `newestArtifactMtimeMs` in `scripts/eureka-command.cjs` to recurse.
2. Add a regression-pinning test leg (3b) to `tests/test-218-eureka-auto-extract.cjs` that
   files a NEW artifact in the standard nested `section/name/name.md` shape and asserts it
   trips the gate - the 4 existing legs all use a FLAT fixture and stayed green straight
   through the bug (a second "fixture-green lied" instance in the same session that coined
   the phrase).
3. Prove the new leg actually catches the regression: temporarily revert the fix, confirm
   leg 3b goes RED with the exact production failure mode, restore the fix, confirm 5/5
   green.
4. Live re-verify: re-run `entity-extract.cjs` directly against `aion-eureka-synergy` to
   confirm the artifact-count jump the gate should have triggered on its own.
