<objective>
Remove the dead `scripts/sync-rooms-brain` egress path: drop its three detached
invocations, delete the writer, retire its documentation, and add a default-deny
regression test so a script-level Brain write cannot come back silently.

**Why (one sentence, the rationale):** Canon Part 8 forbids LOCAL -> BRAIN user
data egress, and this script string-interpolated every room's name, venture name,
stage, status and path into `MERGE (r:Room {name: '...'})` Cypher and POSTed it to
the live Brain on every session start and every room create/archive, which is a
constitutional breach at the source regardless of whether the destination accepted
the writes.

Purpose: close a seven-week-silent Part 8 leak and make its return a test failure.
Output: three call sites removed, one script deleted, two docs retired, one
regression test registered in an existing aggregator.

**Root cause (VERIFIED 2026-09-10, do NOT re-derive):** `scripts/sync-rooms-brain`
(commit `6c97a5f5`, feat 59.2) is spawned detached with output to `/dev/null` from
`scripts/session-start:375`, `scripts/room-registry:337` and
`scripts/room-registry:602`. Its only gate is `brain.isAvailable()` at line 368,
true whenever a Brain key is present. It interpolates room name, venture_name,
venture_stage, status, created and path into Cypher (line 94 and siblings) and
sends it through `brain.write()` -> `lib/core/brain-client.cjs` `callTool('brain_write')`
to the default origin, which since Phase 339 (2026-09-04) is
`https://theo-mcp.onrender.com`. A `{cypher}` payload is neither a proven MOVE-SET
packet nor a free-form question, so the in-process Part 8 belt rates it ambiguous
and proceeds. `brainWrite()` swallows every error and the script exits 0. Loopback
capture on 2026-09-10 observed one run producing 1,498 `brain_write` POSTs carrying
55 distinct Room names with venture/stage/status/path plus the Authorization header
on every request. The destination has refused these writes since roughly 2026-07-23
(`brain_write` is admin-only on the live incumbent), so the leak was silent for
seven weeks. Room state already lives in local SQLite via `scripts/sync-rooms-graph`,
so nothing depends on this writer.

**Evidence trail (Dev-Research Compositing, per CLAUDE.md):**
`~/MindrianRooms/rethinking-mindrianos/research/2026-09-10-sync-rooms-brain-egress-observed.md`
(4.5 KB, filed 2026-09-10). Cite it in the commit body.

**Tri-Polar note:** `session-start` fires only on the Claude Code CLI surface;
Claude Desktop and Cowork never ran this writer, so removal has no surface-specific
effect. `room-registry create` and `archive` are CLI-invoked as well. No Desktop or
Cowork behavior changes.

**Explicitly out of scope:** do NOT touch `lib/core/brain-client.cjs` `write()`
itself (line 1591). Admin paths (`scripts/admin-brain-write.cjs`) still use it. Only
the script-level callers are in scope. `scripts/sync-rooms-graph`, the local SQLite
writer, is untouched at all three sites.
