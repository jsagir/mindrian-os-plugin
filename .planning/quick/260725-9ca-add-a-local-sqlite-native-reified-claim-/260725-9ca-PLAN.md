<interfaces>
`REIFIED_EVENT_TYPES.ContradictionEvent.roles` (the LOCAL role table this module ships, contrast with the Brain-side shape it mirrors):
- `{ role: 'claim', node: 'claim', edge: 'CONCERNS', kind: 'participant' }` -- the event-to-claim "this event is about that claim" link (CONCERNS is net-new per the Edge vocabulary decision).
- `{ role: 'rivalClaim', node: 'claim', edge: 'CONTRADICTS', kind: 'participant' }` -- the event-to-rivalClaim link, reusing the EXISTING `CONTRADICTS` type verbatim (no `CONTRADICTED_BY` minted).
- `{ role: 'evidence', kind: 'scalar' }` -- a short handle/id, never full prose (Canon Part 8).
- `{ role: 'status', kind: 'scalar' }` -- one of `REIFIED_STATUS_VALUES` = `{'open', 'resolved'}`.

`writeContradictionEvent(db, { claim, rivalClaim, evidence, status })` -> `{ ok: true, node_id, event_type: 'ContradictionEvent', edges: [...] }` on success, `{ ok: false, reason, detail? }` on any validation or write failure (never throws). `db` is a caller-owned handle (via `openRoomDb`), exactly like `writeEdge` / `writeEntityNode` / `writeClaimNode` -- this module never opens room.db itself and never requires `node:sqlite`.

`REIFIED_CLAIM_EVENT_ID(eventType, participants)` mirrors `hypergraph-event-schema.cjs`'s `deterministicEventId` construction (sha256 over every present role value, truncated to 16 hex chars) but returns `'event:' + eventType.toLowerCase() + ':' + hash` -- a SQLite `INSERT ... ON CONFLICT(id)` target, not a Cypher `MERGE` target.
</interfaces>
