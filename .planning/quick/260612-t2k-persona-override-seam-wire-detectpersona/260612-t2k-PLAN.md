# Quick Task 260612-t2k: Persona Override (identity-only)

## Problem (QA Report #1: Persona Test Debrief - Context Collapse, beta.20)

A tester role-played a synthetic persona. After three /mos:doctor runs, the persona collapsed:
the system re-injected the REAL user's identity (USER.md) every turn with NO suppression and NO
"I am role-playing" flag. Prior trace found: `detectPersonaUpdate` (user-md-ops.cjs:492) already
has a `user_override` case (line 499-500) but NOTHING ever sets `signal.source === 'user_override'`
- the gate is built, the key was never cut. And readUserMd (line 218) is the single chokepoint that
all ~9 persona readers (intent-classifier per-turn read, navigation engine, shape-f renderers, lens
engine, room-birth, confirm-node, research-preflight, persona-taxonomy) funnel through.

## Decision (navigator-LOCKED): identity-only override via the readUserMd seam

Make `readUserMd` override-aware and back it with a persistent store. The synthetic persona is
returned to every caller from ONE seam; the store lives outside the context window so it survives
/mos:doctor (the exact failure that collapsed the persona). Real room state / memory are NOT
suppressed in this slice (that is the larger feature, see Out of scope).

## Tasks

### Task 1 — New module: lib/core/persona-override.cjs (the store)

**files:** lib/core/persona-override.cjs (new)

**action:** A small dependency-free CJS module that owns the override store. Store location:
`~/.mindrian/persona-override.json` (global, room-agnostic, survives everything). Honor
`MINDRIAN_PERSONA_OVERRIDE_PATH` env override for tests (so tests never touch the real file).

Exports:
- `getOverride()` -> the parsed override object `{ role_blend?, canonical_role?, journey_stage?,
  problem_type?, venture_stage?, set_at }` or `null` if the file is absent / unreadable / malformed
  (graceful: any failure returns null = no override).
- `setOverride(partial)` -> validate fields against lib/core/persona-taxonomy.cjs allowed values
  (drop unknown roles/stages, coerce role_blend to the 7 known keys with numeric weights), stamp
  `set_at` (ISO string), atomically write the JSON (tmp + rename), return the written object.
- `clearOverride()` -> delete the store file (idempotent; no error if absent).
- `isActive()` -> boolean (getOverride() !== null).
- A CLI entry (`require.main === module`): `node lib/core/persona-override.cjs <set <role>|set-blend <json>|clear|status>`
  for the activation surface and tests. `set <role>` sets canonical_role + a 1.0 role_blend on that
  role. `status` prints the active override JSON or "none". Exit 0 on every path (never crash).

NO network, NO Brain, NO require of anything beyond node builtins + persona-taxonomy.cjs.

**verify:** `node lib/core/persona-override.cjs status` prints "none" (clean machine);
`MINDRIAN_PERSONA_OVERRIDE_PATH=/tmp/po.json node lib/core/persona-override.cjs set founder` then
`... status` prints an override with canonical_role founder; `... clear` then `... status` prints "none".
`grep -nE "fetch|https?:|brain|tavily|onrender" lib/core/persona-override.cjs` returns ZERO matches.

**done:** store get/set/clear/status work, validate against taxonomy, atomic write, default-absent, local-only.

### Task 2 — readUserMd seam: return synthetic persona while override active

**files:** lib/core/user-md-ops.cjs

**action:** At the TOP of `readUserMd` (line 218, before the path/stat logic), consult the override store:
```js
try {
  const personaOverride = require('./persona-override.cjs');
  const ov = personaOverride.getOverride();
  if (ov) {
    const out = emptyUser();
    out.parse_failed = false;
    out.override_active = true;            // marker any surface can show
    if (typeof ov.canonical_role === 'string') out.canonical_role = ov.canonical_role;
    if (typeof ov.journey_stage === 'string') out.journey_stage = ov.journey_stage;
    if (typeof ov.problem_type === 'string') out.problem_type = ov.problem_type;
    if (typeof ov.venture_stage === 'string') out.venture_stage = ov.venture_stage;
    if (ov.role_blend && typeof ov.role_blend === 'object') {
      for (const k of Object.keys(out.role_blend)) {
        if (typeof ov.role_blend[k] === 'number') out.role_blend[k] = ov.role_blend[k];
      }
    }
    return out;   // every caller inherits the synthetic persona; real USER.md ignored while active
  }
} catch (_) { /* fall through to the real file read - never break readUserMd */ }
```
- Add `override_active` to the `emptyUser()` shell shape (default false) so the field exists on the
  normal path too and never reads as undefined (check emptyUser definition; mirror the existing
  schema-tolerant style). Keep the change ADDITIVE - the entire existing function body is the
  else-branch and stays byte-identical when no override is active.
- The override taxonomy validation already happened in setOverride; readUserMd just maps fields.

**verify:** with `MINDRIAN_PERSONA_OVERRIDE_PATH` pointing at a set override, `readUserMd(<any real
USER.md path>)` returns the synthetic canonical_role/role_blend (NOT the file's); with the override
cleared, `readUserMd(<real path>)` returns the real file contents byte-identical to before. Confirmed
by Task 3 test.

**done:** override active -> synthetic persona to all callers; override absent -> byte-identical legacy behavior.
