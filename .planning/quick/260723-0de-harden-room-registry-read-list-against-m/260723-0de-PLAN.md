<objective>
Harden `room-registry read` and `room-registry list` so a registry entry missing its `path` field can never again be misread as an orphaned or never-built room.

Purpose: a real navigator QA report (Leah Aronhime, 2026-07-22) proved a session concluded a month-old room (`teaching-fall-2026`) was "orphaned, never built" purely because `read` dumped a stored entry that lacked a `path` key, with zero disk cross-check. The session nearly offered to rebuild the room via /mos:ignite over real work. The same file's `bootstrap-missing` stanza already contains the correct, production-proven 3-tier path-resolution logic; this plan ports that exact logic into what `read` and `list` REPORT, plus a new `path_exists` boolean computed from the filesystem, so the caller receives a direct disk-truth signal instead of inferring existence from key presence.

Output: hardened `read`/`list` stanzas in `scripts/room-registry` (output-only, nothing written back to registry.json) plus a hermetic regression test.
</objective>
