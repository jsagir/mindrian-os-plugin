<objective>
Close room_search's .html blindness. `lib/mcp/tools/room.cjs:119` carries `if (!e.name.endsWith('.md')) continue;` inside the `collectMatches` directory walk, so every non-markdown file in a room is skipped before it is ever opened. Rooms legitimately contain .html briefs, rubrics, and decks (the repo's own canonical room-artifact allowlist, `ARTIFACT_EXT` in `lib/core/graph-backfill.cjs:68`, is `['.md', '.docx', '.html', '.htm']`), and every one of them is invisible to room_search today. The tool reports a clean empty result, so the miss is silent.

Purpose: room_search is the literal-recall door into a bound room. A silent miss is worse than an error, because Larry and the user both read an empty result as "not in this room" rather than "not searched". This is a correctness bug in a read tool that is supposed to be exhaustive within its stated scope.

Output: a widened, evidence-grounded extension allowlist; a dependency-free, line-preserving HTML-to-text pass so hits carry readable text and truthful line numbers instead of tag soup; a regression test that proves a term living only inside an .html file is found; and an RCA note filing the adjacent defect this investigation surfaced.

<prior_investigation>
These findings are already verified live in this working tree. Do NOT re-derive them; they are the grounding for the decisions below.

**1. The bug is real and is at `lib/mcp/tools/room.cjs:119`.** Inside `collectMatches`'s `walk()`, after the directory recursion and before `scanned += 1`, the line `if (!e.name.endsWith('.md')) continue;` drops every non-markdown entry. The file is never opened, so no content matching happens.

**2. The repo already has a canonical room-artifact extension set.** `lib/core/graph-backfill.cjs:68` freezes `ARTIFACT_EXT = ['.md', '.docx', '.html', '.htm']`; `lib/core/graph-self-heal.cjs:74` freezes the same list minus `.htm`. That is the grounded answer to "which extensions are room content", not a guess.

**3. `.txt` is NOT room content in this repo.** Every `.txt` path under `lib/` and `scripts/` is tooling scratch: `data/correlation-labels-index.txt`, the eureka-critic workdir files, `scripts/scout-cadence-guard.cjs`'s last-run marker, `requirements-hsi.txt`. Nothing writes a `.txt` room artifact and `.txt` is absent from both `ARTIFACT_EXT` copies. So `.txt` is a checked-and-rejected candidate, not an oversight.

**4. Reusing `lib/core/doc-text-extractor.cjs` for .html would make room_search WORSE, not better.** Its header comment calls cheerio "the already-listed HTML-parse dep". That claim is false in this repo: `cheerio` is absent from `package.json` dependencies and absent from `node_modules/`. A live probe confirms it:

```
node -e "require('./lib/core/doc-text-extractor.cjs').extractDocText('/tmp/x.html')"
-> THREW: CHEERIO_UNAVAILABLE cheerio unavailable: Cannot find module 'cheerio'
```

`extractDocText` re-throws `CHEERIO_UNAVAILABLE` (it deliberately does not swallow it), so wiring room_search to it would turn a silent miss into a thrown tool error on every .html file. Canon Part 7 (reuse before build) is satisfied by having searched and by recording WHY the existing surface cannot carry this: the dependency it needs was never installed. Do not add cheerio as part of this fix; that is a dependency change with its own vendoring and release-lockstep consequences.

**5. `extractDocText`'s .docx leg IS dependency-free** (node:fs + node:zlib only) and does work. It is still excluded from this fix for a different, stated reason: `extractDocxText` joins every `<w:t>` run into ONE space-separated string, so a .docx has no line structure. Every hit would report `line: 1`, which makes room_search's `{file, line, snippet}` contract silently false. Including .docx needs its own result-shape decision and is out of scope here.

**6. Nothing pins room_search's RESULT object shape.** `tests/test-198-contract-schema.test.cjs` asserts registration and input schemas only. `tests/test-room-search-rank-before-cap.cjs` asserts `file`, `line`, `snippet`, `match_count` are present and correct, never that no other key exists. An additive field is safe.

**7. `tests/test-234-tool-description-floor.cjs` grades room_search's description over the live wire.** Floor 120 chars, ceiling 2048 bytes (the real Claude Code platform cap), capital start, sentence terminator, no em-dash. The current description is 446 chars, so there is ample headroom for a scope correction.
</prior_investigation>
