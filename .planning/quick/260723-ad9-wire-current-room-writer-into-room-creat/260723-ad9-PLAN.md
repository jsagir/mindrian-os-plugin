<objective>
Build the missing WRITE half of the Phase 94-01 statusline active-room contract so the CLI room chip reads real tracked state through the documented canonical source instead of surviving only by accident of a fallback.

Root cause (from .planning/debug/statusline-active-room-leah-gap.md, status: diagnosed): Phase 94-01 shipped a READ contract (STATE.md frontmatter `current_room` -> `getCurrentRoom()` -> `scripts/context-monitor` chip) with 8 green tests, but NOTHING writes `current_room` anywhere. Zero of 22 real rooms carry it. The chip renders a name only via context-monitor's fallback (registry active slug, then `path.basename`). The canonical source is dormant.

This plan wires two coordinated writers so the canonical field is populated AND stays populated:
1. `scripts/room-registry` create + set-active write `current_room: <slug>` into the room's own STATE.md at the create/switch event (the navigator-approved Option B; gives immediate correctness the moment a room is created or switched to, satisfying the Lawrence "reflects within one cycle" contract).
2. `scripts/compute-state` re-derives `current_room` for the active room from the registry when it regenerates STATE.md frontmatter. This is REQUIRED for durability, not scope creep: `scripts/on-agent-complete` runs `compute-state > STATE.md`, and the shell truncates STATE.md BEFORE compute-state runs, so without this the event-driven write is wiped on the next agent-complete and the fix goes dormant again. Re-deriving from the registry (not from the truncated STATE.md) is the only truncation-safe way to keep the field alive "going forward."

Design decision (answers the CONTEXT question about a markdown-prose step): NO edit to commands/rooms.md is needed. The two script-level writers cover BOTH room-creation paths (birthRoom STEP 4 and the legacy /mos:rooms new Step 4) and the switch path (/mos:rooms open Step 3), across all three surfaces, and compute-state's derive protects even the legacy /mos:rooms new Step 5 `compute-state > STATE.md` regeneration. A prose step would be interpretation-prone and surface-specific; the script fix is strictly better.

Purpose: Make the "canonical source of truth" the April fix established actually canonical, without weakening context-monitor's fallback chain and without backfilling the 22 existing rooms.
Output: room-registry + compute-state writers, a write-side regression suite (the currently-missing half of the contract), and the read-side suite confirmed still green.
</objective>

<interfaces>
The write value MUST match exactly what `parseCurrentRoomField` (lib/core/folder-memory.cjs lines ~450-495) reads:
- STATE.md MUST open with `---` on the very FIRST byte, followed immediately by a newline.
- A closing `---` on its own line ends the frontmatter block.
- The parser matches `^current_room\s*:\s*(.+?)\s*$` inside the frontmatter, strips surrounding single/double quotes and whitespace, and REJECTS any value containing a colon, or the literals `null` / `~`, or empty.
- Therefore write the PLAIN, UNQUOTED kebab slug: a line reading exactly `current_room: <slug>` (this matches the read-side test fixture `current_room: core-power`). Room slugs are lowercase alphanumeric + hyphen (validated upstream in commands/rooms.md Step 1 and lib/core/navigation/room-birth.cjs slug guard), so they never contain a colon.

Real room-dir resolution (both writers must target the SAME STATE.md getCurrentRoom reads):
- room-registry `create` receives RPATH that is ABSOLUTE when called by birthRoom STEP 4, and a RELATIVE slug when called by /mos:rooms new Step 4. Resolve: if RPATH begins with `/`, REAL_ROOMDIR=RPATH; else REAL_ROOMDIR="${ROOMS_HOME}/${RPATH}". (Do NOT reuse the existing `${ROOMS_HOME}/${RPATH}` concatenation, which doubles an absolute path.)
- room-registry `set-active` and compute-state resolve the room dir from the registry entry via the 3-tier precedence already used by the `read`/`list`/`bootstrap-missing` stanzas: `entry.abs_path` -> `entry.path` if absolute -> `${ROOMS_HOME}/${entry.path}` -> `${ROOMS_HOME}/${slug}`.

getCurrentRoom resolution reminder (why writing the room's OWN STATE.md is correct): in a live CLI session the user's cwd IS the room, so resolveCanonicalStateMd falls through to Strategy 3 (`<cwd>/STATE.md`). Writing `current_room: <slug>` into the room's own STATE.md is what the chip reads.
</interfaces>
