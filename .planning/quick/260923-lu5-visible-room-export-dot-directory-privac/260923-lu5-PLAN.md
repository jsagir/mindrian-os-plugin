<objective>
Hotfix the live privacy leak in the Visible Room (EXECUTION-PLAYBOOK Tier 0, T0.1; SEED-006 pack Wave 0 items Q0.1 and Q0.2, plus the loopback-bind half of Q0.5).

Plain-terms purpose. The wiki has one scanner, `scanRoom` in `lib/wiki/page-renderer.cjs`. It turns every top-level folder of a room into a wiki section and skips only a short list of names (`:15`, `:61`). Folders whose names start with a dot are the room's private memory (last session notes, snapshots, the local graph database), and the scanner publishes them as ordinary pages. That one scanner feeds the static `--export`, the live wiki server, and the MCP `view_compile('wiki')` tool on Desktop and Cowork, so all three leak. The pack measured the leak in 30 of 38 local rooms. Two more doors sit next to it. First, the export's asset step (`wiki-export.cjs:343-346`) copies the whole room, `room.db` included, as soon as any page references `/room-assets/`, and it crashes when the output folder sits inside the room. Second, the live server (`wiki-server.cjs:685`) listens on every network interface with an unguarded save route. This plan closes all three at the source, behind a regression test that fails today.

Verified against the working tree on 2026-09-23 (the pack's line anchors still hold): `page-renderer.cjs:15` SKIP_DIRS and `:61` skip; `wiki-export.cjs:343-346` whole-room cpSync; `wiki-server.cjs:29` `port = port || 8421`, `:51` `/room-assets` static mount, `:685` `app.listen(port, ...)` with no host; `lib/mcp/tools/views.cjs:332-346` compileWikiView calls `pageRenderer.scanRoom`. Facts measured at planning time: Node 22.23.1 `fs.cpSync` still throws ERR_FS_CP_EINVAL for a destination inside the source even with a `filter` option, so a filtered whole-room copy cannot fix the crash and only a per-file referenced copy can. Express 5.2.1 / send 1.2.1 already ignores dot paths under `/room-assets` by default but serves a `*.db` file that sits outside a dot-dir (for example `research/data.db`). The sibling house scanners `scripts/generate-snapshot.cjs:188` and `lib/mcp/app-views.cjs:128` already skip dot-dirs, so the wiki scanner is the regression. No new ICM rule is invented here. The exclusions mirror section-registry's own hidden-dir rule and the pack's Q0.1 list (the pack consulted icm-architect, and the binding consult applies at Wave 1 walker planning).
