<objective>
Fix the embedding-spine OOM: batch the real-model path of embedTexts() so large-N
rooms embed in bounded memory.

Root cause (verified by orchestrator code-read + real-room failure evidence):
lib/core/eureka/embedding-spine.cjs embedTexts() line 366 passes the ENTIRE texts
array to enc.encoder(list, {pooling:'mean', normalize:true}) in ONE forward pass.
On the real jhtv-oliver-kuntz room (2117 claim nodes) the tokenizer pads to
[2128, 512] input_ids and ONNX runtime attempts a ~26.7GB allocation in a single
Expand node. Documented in the rethinking-mindrianos Data Room entry
~/MindrianRooms/rethinking-mindrianos/research/2026-07-06-jhtv-d15-real-room-test-and-opportunity-formula/2026-07-06-jhtv-d15-real-room-test-and-opportunity-formula.md
section 2 (live-mode bug a). This fix unblocks Phase 212 per that entry's
explicit recommendation.

Purpose: large real rooms (thousands of claim nodes) must embed locally without
exhausting memory; the fix is internal to embedTexts so no consumer changes.
Output: batched embedTexts + MINDRIAN_EMBED_BATCH env tunable + offline test
wired into run-all-211.sh.

Locked decisions (do not redesign): batch INSIDE embedTexts real-model path only;
resolveBatchSize() env resolver with DEFAULT_BATCH = 32; encodeFn seam stays
unbatched passthrough; envelope contract and provenance shape unchanged; pure
helper batchSlices extracted for offline testability.
</objective>
