# Quick 261030-8vd: the on-stop Phase 88 recompile wait waits only on the recompile PIDs

<objective>
Remove a fixed 1 s wait from every Stop hook run.

The Phase 88 block of scripts/on-stop starts one background recompile per section that has ROOM.md. Then it starts a watcher, `( sleep 1 && kill $(jobs -p) ... ) &`, and runs `wait $(jobs -p)`. The `jobs -p` list includes the watcher. So the wait always lasts the full 1 s, also when the recompiles end in about 0.1 s (PROVEN by the orchestrator, F-1). Also, inside the watcher subshell `$(jobs -p)` is empty, so the old watcher never killed anything (PROVEN in planning, P-4).

After this plan:
1. The hook collects the recompile PIDs in an array and waits only on them (C-1).
2. The watcher is a pure timeout: after 1 s it kills the recompile PIDs that are still alive. Its output goes to /dev/null, so its orphaned sleep cannot hold the hook stdout open (DD-3).
3. The 0.4 s per-recompile timeout and the exit 0 contract stay (C-2). The brief block stays untouched (C-3).
4. A new test pins the block shape and the timing.
5. The Stop medians before and after are measured on a room copy and on the real room, and one CHANGELOG bullet records them.

Output: tests/test-261030-8vd-onstop-wait.cjs (new), scripts/on-stop (recompile block only), CHANGELOG.md (one bullet).

## Design decisions made in planning (DD-1..DD-9)

- DD-1: Test method. The test extracts the block from scripts/on-stop between the two EXISTING comment anchors of P-1 (start line inclusive, end line exclusive), and runs it in a temp bash harness under `set -euo pipefail` with ROOM_DIR and SCRIPT_DIR as arguments. Reason 1: both anchors exist in the unchanged file, so the RED run fails on real timing (P-6), not on a missing marker. Reason 2: the whole hook runs about 10 other steps (on-stop-state, memory-lifecycle, the snapshot, BRIEF rendering up to 1.2 s, the guardian up to 3 s), so a 1 s change sits inside multi-second noise, and a hang stub would need a fake node on PATH for every step. Whole-hook coverage stays with the P-9 suites. No new marker comments are added. The anchor lines must stay byte-identical.
- DD-2: Target block shape, replacing lines 380-396 (keep the two anchor lines; keep the name WAIT_KILL_PID):

```bash
  # 2. Recompile ROOM.md references for every top-level section in parallel.
  # Each recompile has its own 0.4 s timeout. Quick 261030-8vd: the hook waits
  # only on the recompile PIDs. The old wait also listed the 1 s watcher job,
  # so every stop waited the full second. mtime-conflict skips are expected
  # (recompiler exits 0 with stderr warning in that case).
  RECOMPILE_PIDS=()
  for SECTION_DIR in "${ROOM_DIR}"/*/; do
    [ -d "$SECTION_DIR" ] || continue
    [ -f "${SECTION_DIR}ROOM.md" ] || continue
    ( timeout 0.4 node "${SCRIPT_DIR}/recompile-room-references.cjs" "${SECTION_DIR%/}" >/dev/null 2>&1 || true ) &
    RECOMPILE_PIDS+=("$!")
  done
  # The watcher kills recompiles still alive after 1 s. Its output goes to
  # /dev/null, so its orphaned sleep cannot hold the hook stdout open. Bash 3.2
  # safe: indexed array, no wait -n; the +set test is safe under set -u.
  if [ -n "${RECOMPILE_PIDS[0]+set}" ]; then
    ( sleep 1; kill "${RECOMPILE_PIDS[@]}" 2>/dev/null || true ) >/dev/null 2>&1 &
    WAIT_KILL_PID=$!
    wait "${RECOMPILE_PIDS[@]}" 2>/dev/null || true
    kill "$WAIT_KILL_PID" 2>/dev/null || true
  fi

```

  The comments do not contain the literal text `jobs -p`. The recompile line is byte-identical to line 387 today.
- DD-3: The watcher subshell gets `>/dev/null 2>&1`. Reason: P-5. After `kill "$WAIT_KILL_PID"`, its `sleep 1` child lives on with the hook stdout. Claude Code reads the hook stdout (ASSUMED: it waits for the pipe to close), so a short hook would wait for the orphaned sleep. The redirect removes that hold.
- DD-4: Bash 3.2 (macOS /bin/bash) statement. `arr=()` and `"${arr[@]}"` with elements work in bash 3.x. `arr+=(x)` exists since bash 3.1. The block uses no `wait -n` (bash 4.3), no `declare -A` (bash 4.0), no mapfile or readarray (bash 4.0). Before bash 4.4, `"${arr[@]}"` of an EMPTY array under set -u fails with "unbound variable", and under set -e that ends the hook. So every expansion of the array sits behind `[ -n "${RECOMPILE_PIDS[0]+set}" ]`. The `${name+word}` form is exempt from nounset in every bash version. The guard is ASSUMED correct for 3.2 from documented behavior; no 3.2 binary is on this host (P-3), so record it as UNVERIFIED.
- DD-5: The track-analytics job of line 147 is no longer waited on (P-8). Reason: C-1 says wait on the recompile PIDs. The job prints nothing to stdout and normally ends in milliseconds, long before line 380. Record it in the SUMMARY as a known change of scope of the wait.
