<objective>
Fix SEED-104. A Eureka plan in the research planner can never fetch today: every approval mints a whitespace-only
standing grant that cannot cover the plan's concept-evidence/v1 queries, so run_quick reasks forever. Fixing the
loop un-blocks sends, so three parts ship together in one change set:
(1) the grant covers the plan's own query families, bounded by FAMILY_IDS, and whitespace-only output stays byte-identical;
(2) egress safety: room prose (markdown claim text) can never become a composed query, an approved term, or a fetched string, and eureka_recall hands the composer abstracted terms;
(3) a loop guard that returns the typed error grant_scope_cannot_cover_plan instead of another card.

Purpose: Phase 366's deliverable (the Eureka perspective in the research planner) cannot fetch until this lands
(SEED-104 trigger: before Phase 366 closes). Canon Part 8: room bytes never egress beyond navigator-approved composed terms.
Canon Part 3: one governed gate path, no unanswerable gates. Canon Part 7: the fix lands in the shared core used by
every door (MCP research_run for Desktop and Cowork, the CLI door scripts/research-planner.cjs, the ambient offer).

Output: the core edits, typed refusals at the doors, one new hermetic regression test plus a golden, registration in
the release-gated aggregator, and a SEED-104 note recording the out-of-scope items.
