## Critical Issues

### CR-01: `theo --help` (and `-h`) runs a live Theo propose instead of printing usage

**File:** `scripts/release-cut-listener.cjs:733-734` (parseArgs) and `:749-755` (main)
**Issue:** `--help` sets `a.sub = a.sub || 'help'`. When a subcommand comes first (`theo --help`, `theo -h`, `all --help`), `a.sub` is already `theo` and the help flag is dropped. `main` then runs the full Theo leg: with Theo present, it spawns `release_sync.py` in propose mode.

Proven offline: `main(['theo','--help'], fakeDeps)` returned 0 and called spawnSync once.

Per the contract, propose compiles payloads and writes evidence into Theo's tree. Section 5 adds: "Running the call again issues a new token and the old line stops working". So someone asking for help mid-cut silently cancels the apply line they were about to run. `website --help` also runs a real scan and writes a report file.
**Fix:**
```js
case '-h':
case '--help': a.help = true; break;
// in main, before the subcommand switch:
if (a.help || a.sub === 'help') { deps.out(USAGE); return LISTENER_EXIT.OK; }
```
Add a unit assert that `main(['theo','--help'])` returns 0 and leaves the spawnSync call count at 0.

## Warnings

### WR-01: Valued flags take the next token even when it is a flag, so `--dry-run` silently disappears

**File:** `scripts/release-cut-listener.cjs:725-728`
**Issue:** `--plugin-root`, `--website-dir` and `--report-dir` take `argv[i+1]` without checking it. `theo --report-dir --dry-run` (or `--plugin-root --dry-run`) uses `--dry-run` as the directory and runs Theo live. Proven offline: `main(['theo','--plugin-root','--dry-run'])` spawned once. `--version` and `--ref` are protected only because their regexes reject the swallowed token.
**Fix:** In parseArgs, `if (i + 1 >= argv.length || argv[i + 1].indexOf('-') === 0) throw new UsageError(t + ' needs a value');`

### WR-02: The Theo JSON line is not checked against what was asked (version, sha, mode)

**File:** `scripts/release-cut-listener.cjs:295-298`
**Issue:** mapTheoResult checks `contract`, `exit_code` and that `status` belongs to the code. It does not check:
- `obj.version` against the `--version` passed
- `obj.plugin_ref_sha` against `--ref`
- `obj.mode` against `propose`

Proven: `{status:0, mode:'verify', status:'verified'...}` for version `1.0.0` and a different sha maps to RAN-OK/CONTINUE. The plan's must-have ("an unparseable or inconsistent JSON line ... stop") and threat T-5v9-02 (Spoofing) are only partly met. Only the lagging Step 0.6 gate still catches a wrong-version answer.
**Fix:** Pass `{version, ref, mode:'propose'}` into mapTheoResult and return `violation(...)` when any of these hold:
- `obj.version !== version`
- `obj.plugin_ref_sha` is non-null and `!== ref`
- `obj.mode !== 'propose'`

Restrict propose-mode code 0 to `already-current`, since `verified`, 21, 22 and 23 are verify-mode answers.

### WR-03: The audit text says "the Step 0.6 stamp gate still guards" even when `--no-theo-check` has turned that gate off

**File:** `scripts/release.sh:239, 252, 259, 264`; `scripts/release-cut-listener.cjs:376, 399`
**Issue:** With `--no-theo-check`, `mos_theo_stamp_gate` skips (theo-stamp-gate.sh:136). Yet every Step 0.55 fail-open line, and the listener's own SKIPPED reasons, still claim the stamp gate guards the cut. On a cut with `--no-theo-check` plus a missing or broken Theo, the operator is told a guard exists when none does. That is a false audit record on exactly the path RULE 5 wants explicit.

The reverse also bites. Operators who pass `--no-theo-check` because Theo is in a no-write window or cannot read its canon (codes 10 and 5) will now be stopped at Step 0.55 anyway. Only the recovery line on that path explains they also need `--no-cut-listener`.
**Fix:** In release.sh, choose the suffix by flag. If `NO_THEO_CHECK=1`, say "the Step 0.6 stamp gate is ALSO opted out (--no-theo-check): nothing guards Theo freshness on this cut". Otherwise say "the Step 0.6 stamp gate still guards". Remove the gate claim from the listener's reason strings, since the listener cannot know the release flags, and mention the interaction in the RULE 5 paragraph.

### WR-04: The live Theo propose runs before the cheap pre-flight refusals, binding Theo to commits the cut may never tag

**File:** `scripts/release.sh:226-267` (placement before Step 1 at :306 and Step 2.5 at :577)
**Issue:** Step 0.55 sits ahead of three checks that refuse cuts cheaply:
- Step 1's bump-mode refusal: "No bump mode passed and current version '$CURRENT' is clean"
- Step 2's verify-release
- Step 2.5's clean-tree gate

So a cut that will abort seconds later still compiles a Theo payload, writes evidence and mints a new apply token, which invalidates any earlier line.

A dirty tree causes a second problem. `CUT_LISTENER_VERSION` comes from the working-tree plugin.json (repo-version.cjs), while Theo reads plugin.json at HEAD through `git show`. A dirty plugin.json therefore surfaces as a Theo code 3 STOP ("check the sha and version") instead of the clear dirty-tree abort.

The contract only requires the call before the stamp gates, which leaves room for cheap guards first.
**Fix:** Right before the listener call in Step 0.55 (non-dry-run), refuse or SKIP when this fails:

`git -C "$PLUGIN_DIR" diff --quiet HEAD -- .claude-plugin/plugin.json data/command-registry.json lib/core/recipe-maps.cjs data/connector-registry.json`

Also move the clean-version bump-mode refusal above Step 0.55. At minimum, have the listener compare `readRepoVersion` against `git show <sha>:.claude-plugin/plugin.json` before spawning.

### WR-05: Every spawn kill is reported as a timeout, which misdirects recovery

**File:** `scripts/release-cut-listener.cjs:272-275`
**Issue:** The branch fires on `ETIMEDOUT` or on any signal with a null status. Two cases get mislabeled:
- `maxBuffer` overflow (`ENOBUFS`, SIGTERM). Proven: the reason reads "did not answer before THEO_SYNC_TIMEOUT_MS (spawn ENOBUFS) ... Raise THEO_SYNC_TIMEOUT_MS".
- An external SIGKILL (for example the OOM killer).

Both tell the navigator to raise a timeout that had nothing to do with it. On a real timeout, only the python process gets SIGTERM. Children Theo spawned can keep running and writing in Theo's tree after the listener has printed STOP, and nothing warns about this.
**Fix:** Branch three ways:
- `err.code === 'ETIMEDOUT'`: timeout text, plus "Theo child processes may still be running; check `ps` before re-running".
- `err.code === 'ENOBUFS'`: "stdout exceeded 16 MiB (contract allows one line)".
- Anything else: "killed by <signal>". Keep the outcome STOP.

Update the test at tests/test-release-cut-listener.cjs:242-244, which currently locks in the SIGKILL-means-timeout wording.

### WR-06: The wiring suite's whole-repo `git status --porcelain` comparison is flaky in this shared tree

**File:** `tests/test-release-cut-listener-wiring.cjs:138-141, 182-184, 202`
**Issue:** The test snapshots `git status --porcelain` for the whole repo before and after a dry-run that takes several seconds. In this tree, two other sessions (Phase 267 and Phase 366) edit and stage files at the same time. Any peer write in that window fails the suite (and run-all-349) even though release.sh wrote nothing. It is a false red that has nothing to do with the code under test.
**Fix:** Limit the snapshot to paths release.sh could touch, for example `git status --porcelain -- .claude-plugin package.json CHANGELOG.md npm-shrinkwrap.json data scripts`. Or hash those specific files before and after instead of reading the global status.

## Info

### IN-01: Report files hold the apply token, use default permissions, and overwrite on a same-second collision

**File:** `scripts/release-cut-listener.cjs:805-809`
**Issue:** On code 20, `theo.apply_command` (the navigator's token) goes into `$HOME/.mindrian/release-cut-listener/*.json`, created with the default mode (0644 under umask 022). Two runs of the same leg and version in the same second overwrite each other, because `writeFileSync` is called without `flag: 'wx'`.
**Fix:** `deps.writeFileSync(file, data, { mode: 0o600, flag: 'wx' })`, and add a `-<pid>` suffix on EEXIST.

### IN-02: Usage and crash exits write no report, though the plan says every non-dry-run invocation does

**File:** `scripts/release-cut-listener.cjs:766-774, 825-833`
**Issue:** At Step 0.55, exit 2 (for example an empty `CUT_LISTENER_VERSION` after repo-version.cjs refuses) and exit 1 both continue the cut. They leave only a terminal line, with no report file.
**Fix:** Write a minimal report `{exit_code, error}` from the catch blocks when not under `--dry-run`.

### IN-03: The dry-run opt-out line prints raw escape codes

**File:** `scripts/release.sh:442`
**Issue:** `echo "              ${YELLOW}...${NC}"` without `-e` prints literal `\033[1;33m`. This copies the pre-existing `--no-website` line's defect.

### IN-04: The `[DRY RUN]` branch of the 10|11 arm can never run

**File:** `scripts/release.sh:255-256`
**Issue:** Under `--dry-run` the listener never spawns, so it can only return 2 or 3. Harmless defensive code, but it suggests a path that does not exist.

### IN-05: The commands-canon version row can cite the wrong line

**File:** `scripts/release-cut-listener.cjs:505-506`
**Issue:** The line number comes from the first `"version"` match anywhere in the file, which may be a nested key, not the top-level field whose value is reported.

### IN-06: The banned scan skips symlinks without saying so

**File:** `scripts/release-cut-listener.cjs:425`
**Issue:** Symlinked files and directories under `src/` are skipped with no row. That runs against the "nothing silent" rule.
**Fix:** Count the skipped symlinks and add them to the reason (for example "2 symlinks not followed").

### IN-07: The recovery hint does not quote the plugin root

**File:** `scripts/release-cut-listener.cjs:605`
**Issue:** `MOS_PLUGIN_DIR=' + pluginRoot` breaks copy-paste when the path contains spaces.
**Fix:** Use `shellQuote(pluginRoot)` and `shellQuote(version)`.

### IN-08: The run-all-310 leg 4 label hard-codes the fixture's baseline

**File:** `tests/run-all-310.sh:174`
**Issue:** The label says `>= 61` while the actual baseline comes from the fixture. The label will drift on the next rebaseline.

### IN-09: The JSON parse takes the last non-empty line instead of enforcing exactly one

**File:** `scripts/release-cut-listener.cjs:288-291`
**Issue:** Contract section 4 says JSON mode prints exactly one line. Extra stdout lines (for example generator chatter leaking to stdout) are accepted without comment.
**Fix:** If more than one non-empty line is present, either STOP as a contract violation or record `stdout_extra_lines: N` in the leg.
