## Planner decisions (discretion, open to the plan checker)

- P1: the block uses `decision:"block"` plus `reason`. Not Stop `additionalContext` (hard rule 5; the host doc gives no version floor for it).
- P2: `reason` is 1 fixed string. It is never built from transcript text or from a verdict slug.
- P3: 1 side-file gate record forces 1 block at most. The hook marks the session's records `forced` on an intercept. At the start of a later Stop, when the stdin has a boolean `stop_hook_active`, the hook drops the forced records. Reason: on a continuation the "preceding user text" is the hook's own feedback line, so a second relevance check is not a real check; on a new turn the record is stale. The declared-fork arm reads the turn's own text and keeps its retries (3 at most).
- P4: a stdin with no `stop_hook_active` key keeps the old lifecycle. This is the direct-field convention of this file; it keeps the replay corpus byte-stable (0 corpus entries carry the key).
- P5: the log record gets 1 new field, `stop_hook_active` (true, false or null), so the next measure can check that the host sends the key.
- P6: the MCP-first Stop path (scripts/on-stop lines 118 to 121, flag off by default) keeps its `continue:false`. It is not in scope. Record it in the SUMMARY as an open item.
