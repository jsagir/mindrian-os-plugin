# Quick Task 260706-13z: D3 model swap + D1 adapter seam + D14 eureka-smoke

## Problem (per the room's ratified diligence, cited directly)

Phase 211-01 shipped `lib/core/eureka/embedding-spine.cjs` with
`DEFAULT_MODEL = 'Xenova/all-MiniLM-L6-v2'` and `EMBED_DIM = 384` as constants
(embedding-spine.cjs:65-67), and 211-02 repeated the hardcode
(tri-modal-index.cjs:52, and the vec0 DDL at :146). The room's commissioned
diligence doc (source of record:
`~/MindrianRooms/rethinking-mindrianos/research/2026-07-05-eureka-critic-brain-mcp-plan/2026-07-05-eureka-technical-diligence.md`)
rules on exactly this, before 211 executed but read after:

- **D3 (doc lines 78-103): the model half is OUTDATED.** all-MiniLM-L6-v2 is a
  2019-2021-era model, among the LOWEST scorers in a 16-model open benchmark
  (56% top-5, 28% top-1). Recommendation: default to **MongoDB/mdbr-leaf-ir**
  (23M params, Apache 2.0, #1 on MTEB BEIR/RTEB <=100M params, native 768-dim,
  MRL-truncatable) "pending a one-day spike confirming ONNX weights load in
  transformers.js v4"; fallback **Xenova/bge-small-en-v1.5** (384-dim, already
  first-class in transformers.js). And structurally: "stop hard-coding 384
  dims. Store embedding_model and embedding_dim per room in the SQLite schema"
  (doc line 103).
- **D1 (doc lines 32-56): keep sqlite-vec, add guardrails.** Pin >= 0.1.9
  (VERIFIED already satisfied: package.json:34 has `"sqlite-vec": "^0.1.9"`),
  "put all vector operations behind a thin adapter module (one file that owns
  insert vector / knn query / delete)" so a swap to sqlite-vector or the
  v0.1.10 ANN path is a one-file change, and name vlasky/sqlite-vec as the
  contingency fork in a comment (single-maintainer risk; the mitigation is the
  seam, not hope).
- **D14 (SEED-049 lines 383-393): the first-use model download is the one real
  distribution gap.** npm install != model weights; the tens-of-MB ONNX fetch
  happens lazily on the FIRST real embedding call and today looks like a
  silent hang. Recommended fix: an `--eureka-smoke` doctor class mirroring the
  shipped `--brain-smoke` 5-layer-probe pattern, plus a ONE-TIME friendly
  notice when a real download is about to happen.

The navigator decision is recorded in SEED-049 D13 (line 376): "file a
follow-up fix... spike the newer model, keep the adapter-seam pattern from D1,
make embedding_dim schema-driven. Queued to run once 211-05 merges." 211-05
has merged (run-all-211.sh has all 6 legs). This is that follow-up.

## Fix strategy

Three seams, all additive, none touching 211-03/04/05 logic:

1. **embedding-spine.cjs** owns model identity + dim resolution + the
   download notice. The offline seams (`encodeFn`, `_forceUnavailable`) stay
   byte-compatible - that is what keeps every 211 test green without network.
2. **vector-store.cjs (new)** owns the vec tables end to end (create at the
   RESOLVED dim, insert, knn, delete, eureka_meta bookkeeping).
   tri-modal-index.cjs becomes a delegating consumer; its exports and
   signatures do not change, so hybrid-retrieve.cjs and eureka-room-report.cjs
   need zero edits (eureka-room-report's own `EMBED_DIM = 384` at :61 is a
   deterministic offline HASH-STUB dimension, not the model dim - explicitly
   out of scope, its report already stamps `dim` from actual vectors at :382).
3. **doctor** gets a class-S probe module (sibling of
   lib/core/doctor/class-m-brain-smoke.cjs) + flag + acceptance point.
