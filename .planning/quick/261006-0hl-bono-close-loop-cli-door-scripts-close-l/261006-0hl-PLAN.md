# Quick 261006-0hl: the BONO close-loop CLI door

## Why

The navigator's "fix" on the egain bono close-out (2026-10-06) named two gaps: "the governed BONO runtime has no CLI entry point, so no writeCloseLoop graph write or SUPERSEDES chain was made", and the run "skipped the offer to file hats as reusable experts because the room has no SyntheticExpert nodes". The spine is shipped (lib/core/close-loop-writer.cjs, Phase 223-02) and the expert modules are shipped (lib/core/expert-library.cjs, lib/core/navigation/synthetic-expert.cjs, Phase 164-02). What is missing is a door a command surface can run from a shell. Reuse before build (Canon Part 7): a grep of scripts/ and bin/ finds no caller of writeCloseLoop, offerExpertsForFiling or writeSyntheticExpertNode; lib/core/intel-pipeline.cjs calls writeCloseLoop in-process inside runIntelPipeline (a library composer, not a CLI). So this is ONE script with `--surface bono|intel-pipeline`, composing shipped modules only. No change to the writer, the navigation chokepoints, or expert-library.

## Contract findings that shape the design (measured while planning; read before Task 2)

1. **The writer never looks up the prior itself.** The supersede runs only when `payload.priorConclusionId` is set (close-loop-writer.cjs:476). The door runs `findPriorConclusion(db, topicHash)` and sets it.
2. **A supersede needs a CONFIRMED prior and a HUMAN byUser.** transitions.cjs TRANSITIONS allows only `confirmed->superseded`, and the Phase 348 SUPER-02 guard (transitions.cjs ~:239-252) refuses a supersede of a truth-claim node attributed to an agent identity. The writer's default supersedeFn passes no byUser, so supersede defaults to 'system' and is refused (WD-348-6: zero SUPERSEDES edges in 47 live rooms; tests/test-223-supersedes-chain.cjs:66-80 drives the seam for this reason). The door therefore passes the writer's shipped `opts.supersedeFn` seam bound to `navigation.resolveByUser(roomDir)`, which reads the room's USER.md and coerces any agent identity to 'navigator' (the lib/core/temporal/supersession-gate.cjs SUPER-03 precedent: identity from USER.md only, never from a caller flag). For an unconfirmed prior the door follows commands/bono.md:115 verbatim: write the new proposed conclusion, pass no priorConclusionId, disclose "no chain written: prior unconfirmed". It never auto-confirms.
3. **Arm C ("0 nodes on an invalid conclusion") is impossible with a bare single call.** The writer writes `claims[]` (:210-236) BEFORE it validates the conclusion (:238-247) and keeps going after a failure. The door resolves this without touching the writer: the ONE writeCloseLoop call runs inside `navigation.withRoomTx` (Phase 369 D-18; every writer on this path composes through the `db.isTransaction` owns idiom: typed-claim.cjs:231, transitions.cjs:257; node-insert, typed-opportunity, typed-open-question and opportunity-ops open no transaction and no second connection), and the door throws a local sentinel to roll back whenever `summary.ok` is false or `failures[]` is non-empty. Measured: node v22.23.1 `DatabaseSync.isTransaction` reads false, true after BEGIN IMMEDIATE, false after ROLLBACK. The bank .md is a file and cannot roll back; D-01 already accepts a bank-visible .md with no node, and the door lists every such path in `bank_md_written`. The smallest additive writer change that would also make this possible, NOT taken here (out of scope): export a pure `validateCloseLoopPayload(payload)` from close-loop-writer.cjs.
4. **The door must not require lib/core/room-db.cjs directly.** The pre-commit `scripts/check-substrate.cjs --diff` rejects that require from scripts/ (BANNED_REQUIRE_PATTERNS), openRoomDb's `auditBypassIfNeeded` would append to `~/.mindrian/telemetry/navigation-bypass.jsonl` (a write outside the room), and openRoomDb CREATES a room.db when none exists. The door opens through `navigation.openRoomDbForCaller` (the same room-db.cjs openRoomDb behind the allow-listed chokepoint, returns null when room.db is absent) and `navigation.openRoomDbReadOnlyForCaller` for version-log (file: URI mode=ro, no migrations). Never node:sqlite directly.
5. **offerExpertsForFiling ranks by ONE SUM, not tier-then-survival.** `contributionRank = EVIDENCE_TIER_RANK[tier] / 4 + survivalRate`, sorted descending (expert-library.cjs:279-293). A Practitioner hat at 0.90 survival outranks an Academic hat at 0.30. Arm E pins the shipped sum with a fixture where the two orders differ; the docs describe the sum. expert-library.cjs is not changed.
6. **run-all-223 is not all green today.** Its DESENSITIZE leg greps `SENS-05` in commands/bono.md, which now carries `sensor_triggers: [SENS-17]` (grep count 0). So arm H is "the signature after equals the signature before", recorded leg by leg.

## The door, specified (Task 2 implements exactly this)

**Shape.** `scripts/close-loop.cjs`, CommonJS, node built-ins plus repo modules only. A switch-case router on `argv[0]` (the gsd-tools pattern, CLAUDE.md); flags parsed by one loop accepting `--flag value` and `--flag=value` (the scripts/doctor.cjs `--room` idiom, lines 309 and 361-367). An unknown flag, a missing required flag, a missing or unknown subcommand: usage text on stderr, exit 2. `--help` or `-h`: usage on stdout, exit 0. Requires: `lib/core/navigation.cjs`, `lib/core/close-loop-writer.cjs`, `lib/core/temporal/supersession.cjs`, `lib/core/expert-library.cjs`, `lib/core/navigation/synthetic-expert.cjs` (for SYNTHETIC_EXPERT_FIELDS only). Exports `{ main, REFUSAL_REASONS, MAX_INPUT_BYTES }`; runs `main(process.argv.slice(2))` only when `require.main === module`.

**Output.** JSON subcommands print `JSON.stringify(obj, null, 2)` on stdout. A refusal prints `{ ok:false, subcommand, reason, detail? , ... }` on stdout plus one stderr line `close-loop <subcommand>: refused (<reason>)`, exit 1. `detail` is a scalar at most 120 characters, never a payload body and never a stack trace. A top-level try/catch in main maps any unexpected throw to reason `internal_error` (message only, sliced to 120), exit 1.

**Room resolution (close, version-log, file-expert).** `path.resolve` the value, `fs.realpathSync` it (failure: `room_not_found`), must be a directory (else `room_not_found`); `<real>/.mindrian/room.db` must exist and be a file (else `room_db_missing`); `fs.realpathSync(dbPath)` must sit inside `<real>` by `path.relative` (no leading `..`, not absolute; else `room_db_outside_room`). No refusal path creates a directory or file. Every later use passes the realpath.

**Input files (payload, hats, spec).** `fs.statSync` size over `MAX_INPUT_BYTES` (1048576) refuses `<kind>_too_large`; a read error refuses `<kind>_unreadable`; strip one leading U+FEFF; a JSON.parse error refuses `<kind>_not_json` (detail = the parser message, sliced).
