# Quick Task 260705-x85: Fix check-card-fire.cjs relevance-gate false positive Summary

**One-liner:** The PRIMARY-path relevance gate now judges a stale reach against the gate's OWN recorded subject text (`gate_subject_text`, sourced from the gate's own rendered header/body/label content) instead of the current turn's assistant reply, which previously almost always looked "relevant" because a reply naturally echoes the user's current topic back regardless of what the stale reach was actually about.

## What Was Built

**Task 1 - `lib/core/card-fire-sidechannel.cjs`:** additive, optional, bounded `subjectText` schema.
- `MAX_SUBJECT_CHARS = 300` + `sanitizeSubjectText(v)` (non-string -> `''`, else trim + slice, never throws).
- `recordReachedGate` now stores `subject: sanitizeSubjectText(o.subjectText)` alongside the existing `{ entry, shape, ts }` scalars. Omitting `subjectText` (every pre-existing call site until Task 2) yields `subject: ''` - fully backward compatible.
- New export `readReachedGateSubjects(sessionId, opts)` mirrors `readReachedGates`'s exact control flow (prune, session-bucket union with `NO_SESSION_KEY`, same `sideFilePath` precedence) but collects deduped, non-empty `rec.subject` values. Completely separate from `readReachedGates`'s bare entry-path-array contract, which is untouched.
- Module header doctrine comment updated with a dated note explaining the deliberate, bounded departure from the prior "zero user text, zero room content" phrasing.

**Task 2 - wire `subjectText` at the three PRIMARY producer call sites:**
- `lib/hmi/selector-dispatcher.cjs` pickShape trailer door: `result.rendered.zones.header` + `.body` (pre-trailer, real gate content), joined with a space.
- `scripts/intent-classifier.cjs` engine arm: `rendered.text` (the dial's own rendered content).
- `scripts/intent-classifier.cjs` emitBindingGate F.8: `zones.header` + `zones.body`.
- All three changes are additive - one new key in an existing object-literal argument; no existing parameter, return value, or call signature changed.

**Task 3 - `scripts/check-card-fire.cjs` consumer wire + regression proof:**
- `deriveTurnSignals` now also calls `sidechannel.readReachedGateSubjects(sessionId)` (only inside the branch where the side-channel itself supplied `ranEntries` - the true PRIMARY path), joins the result into `sideChannelSubjectText`, guarded by its own try/catch (degrades to `''`, never throws).
- New returned field: `gate_subject_text`, with direct-field envelope precedence (`e.gate_subject_text`) over the side-channel-derived value, mirroring the existing `ran_entries` precedence rule exactly. The BACKSTOP (transcript-only) path never populates `sideChannelSubjectText`, so the field stays `''` there and `readTranscriptTurn` was left completely untouched.
- `classifyCardFire`: `gateAlreadyAnswered` and its `gateLabels` (still derived from `outputText`) are unchanged. Immediately before the relevance check, `gateSubjectText = t.gate_subject_text || outputText` is computed, and `gateRelevance.gateTopicallyRelevant(precedingUserText, gateSubjectText)` replaces the old `(precedingUserText, outputText)` call. The `gateLabels.length === 2` binary exemption further down is untouched.
- Comment block updated in Feynman-plain language explaining the root cause and the fix.
- `tests/test-209-primary-sidechannel.cjs` extended with:
  - **Behavior 8**: subject round trip + truncation (`readReachedGateSubjects` returns a normal subject verbatim and truncates an oversized one to `MAX_SUBJECT_CHARS`).
  - **Behavior 9**: the literal 2026-07-05 false-positive regression proof - a stale PRIMARY reach recorded with an unrelated subject text, exercised against a current turn about a completely different topic (drafting a Gmail email about an assignment status). Asserts `turn.gate_subject_text` equals the recorded subject and `classifyCardFire` now returns `{ intercept: false, reason: 'gate-irrelevant-to-turn' }`. Also asserts, as a documented mechanism-of-failure contrast, that the OLD comparison (`gateRelevance.gateTopicallyRelevant(precedingUserText, outputText)`) would have returned `true` for the identical fixture - proving the exact failure mechanism without changing `gate-relevance.cjs` itself.
  - Constitutional-floor check extended with `assert.equal(src.indexOf('gate_subject_text') !== -1, true, ...)`.

## Root Cause (confirmed, now fixed)

`classifyCardFire` compared `precedingUserText` (the current user turn) against `outputText` (the CURRENT TURN's assistant reply). On the PRIMARY path, the model is instructed elsewhere (SEED-021) never to reproduce a stale gate's own subject/labels once it judges the gate irrelevant - so `outputText` was just the model's ordinary reply to the current turn, which naturally shares tokens with `precedingUserText` (an assistant answering a question echoes the question's topic back). `gateTopicallyRelevant` therefore returned `true` (looked relevant) almost every time on the PRIMARY path, regardless of what the stale reach was actually about. The three producer call sites already computed genuinely real, human-readable gate subject text (`zones.header`/`.body`, `rendered.text`) before calling `recordReachedGate` - it simply was not being captured. Capturing it and threading it through as `gate_subject_text` (falling back to `outputText` only on the BACKSTOP path, where `outputText` legitimately IS the gate-shaped text) fixes the false positive at its real source.
