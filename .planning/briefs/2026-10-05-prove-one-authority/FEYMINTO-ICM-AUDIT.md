# FeyMinto design v2 under the ICM audit (2026-10-05)

Audited by the orchestrator with the icm-architect skill's ten invariants and walk test, against a live nest (egain-des-liquid-conductor/problem-definition, HEAD bd035d5bf). Verdict: the design holds eight of the ten invariants as written; two need a structural change, and three measured duplications need one home each.

## Measured on the live nest

- `CONTEXT.md` (ICM layer 2) is GENERATED from `data/section-command-ledger.json` and `lib/core/section-registry.cjs`: `job_id: find-problem`, a methodology sequence (`/mos:beautiful-question`, `/mos:analyze-needs`, `/mos:user-needs`), writing rules, a "Do NOT load" line. So a per-nest, Theo-derived command sequence already exists, in the nest's contract, rebuilt by script.
- `MINTO.md` `sources:` lists the nest's artifacts; `ROOM.md` wikilinks the same artifacts. Two homes for "what belongs here".
- `BRAIN.md` is named by 63 files under lib, scripts and hooks; renaming the file is a reference-integrity job, not a rename.
- The rooms home is a git repository with an auto-commit hook, so revisions of every face already exist as history.

## Walk test

- Where am I, where do I go: the room's `ROOM.md` plus the nest's `CONTEXT.md` plus `BRIEF.md`: three reads. Passes once `BRIEF.md` exists.
- Status by scanning: `STATE.md` + `BRIEF.md`'s RECORD BASIS + the run folder's three outputs. Passes once materialized.
- Routing file carrying payload: `CONTEXT.md` section 2 carries the methodology sequence (payload in a contract); acceptable because it is generated and short; the Theo face must not copy it.
- One fact in two places: the three duplications above.
- Token check: entry + contract + the brief's first three blocks lands inside 8k; the full triple for every nest does not.

## Guardrails

- Not over-structured: regeneration is automated and repeating (the debouncer, heal, on-stop), so the folder rung is earned.
- Where ICM loses: real-time multi-agent work. FeyMinto is sequential with human gates; the research fan-out (HARNESS-07) is the part that is not ICM and needs admission control in code (369.3b).
- Reference integrity: file names stay (`MINTO.md`, `FEYNMAN.md`, `BRAIN.md`); the layer is named FeyMinto; any rename goes through the referrer gate (63 referrers for `BRAIN.md` alone).

## On icm-runtime (the brief's S6)

No icm-runtime skill is installed in this session; the brief's author read the repository. From that reading (brief section 5): it would side with FeyMinto on frozen per-run contracts (our run folder plus `RECORD BASIS`), append-only history (the ledger, the invariant report, git) and enforcement disclosure (the guardian's severity and the "not asked" marker); it would warn against its own two completion definitions (output presence versus `stage_done` events), which is why FeyMinto's completion is derived from the ledger's terminal states and the decision records, never from a file existing; and it would not be installed as a second state-owning runtime beside `room.db`.
