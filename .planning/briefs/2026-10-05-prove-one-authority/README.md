## Ruling 2026-10-05 (navigator, verbatim: "the feyminto room id is not part of icm ? if not needs to be a part of the room.db ! its a must")

Measured on HEAD d535c22f7 before the ruling was recorded: a real room's `room.db` carries no Room node (node types in a live room: memory_event, claim, focus_area, memory_artifact, Artifact, Section, decision, governing_thought, jtbd, birth_gate_anchor, navigator_persona; `room:<slug>` typed `Room` is inserted only in the born-wired sub-room branch, `lib/core/navigation/room-birth.cjs` ~1192-1197); the `identity` table in `room.db` holds 7 migration stamps and no room identity; the ICM Layer 0 identity is `ROOM.md` on the filesystem; the registry index lives in `<rooms home>/.rooms/registry.json`.

The ruling: the room's identity is part of `room.db`, for every room, top-level and nested. The Room Identity exemplar (the brief's section 4) makes `room-birth.cjs` the owner that commits, in one transaction, the `Room` node `room:<slug>` and the `identity` rows (`room_id`, `slug`, `canonical_path`, `parent`, `depth`, `created_at`, `birth_version`), and reads them back before `ok: true`. `ROOM.md` (ICM Layer 0) and the registry entry become projections of that committed identity, regenerated from it, never the other way round; a room whose `room.db` lacks its identity rows is `not_ready` with a typed reason, and a repair path writes them from the existing `ROOM.md` + registry without inventing values. Session binding reads the room id from `room.db`, not from the path.
