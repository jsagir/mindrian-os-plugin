## 4. Architecture (Canon Part 8 Compliant)

### Brain-Local Graph Communication

This is the load-bearing architectural decision per Intent 5.

LOCAL GRAPH (user's Aura OR SQLite room.db mirror):
- User corpus (papers from OpenAlex/arXiv/patents/industry fetched by the engine)
- User Paper/Author/Institution nodes (built from public metadata, scoped to user's corpus)
- User RSDiscovery/ReverseSalient/Innovation instances
- User venture artifacts + sections + cross-refs (from Phase 88 memory triple)
- SELECTIVE cache of Brain methodology embeddings for local similarity compute

BRAIN (remote Neo4j at brain.mindrian.ai + Pinecone methodology index):
- Framework nodes + chain rules (FEEDS_INTO / LEADS_TO / CO_OCCURS)
- Technique nodes (tech-lsa, tech-bert-similarity, tech-differential-analysis, tech-domain-analysis, tech-cross-domain-synthesis, tech-innovation-mapping)
- 1,427 methodology Pinecone embeddings (PUBLIC vectors representing canonical methodology content, NOT user data)
- Canonical exemplars (drone-naval / plant-elderly / auto-battery)
- Problem type taxonomy (UDP / IDP / WDP)
- ProblemType ↔ Framework edges

### The "Talking" (What Crosses the Boundary)

Brain → Local (allowed freely, no rate limit beyond API):
- Methodology embeddings (the 1,427 public vectors)
- Framework chain rules via generic-handle queries
- Canonical exemplars + threshold hints
- Anonymized cross-user success patterns (future)

Local → Brain (TIGHTLY CONSTRAINED — generic handles only):
- "What chains from reverse-salient-framework at problem_type=IDP?"
- "Fetch methodology embeddings for frameworks adjacent to JTBD"
- NEVER: user artifact bytes, author names from user corpus, venture content, meeting transcripts, proprietary numbers
- Every outgoing query audited against Canon Part 8 forbidden-regex set before being sent

One legitimate Brain-write allowed during 89.1:
- USES_TECHNIQUE edge from rss-phase-1 to tech-domain-analysis
- Methodology canon edit, not user data
- Routed through /mos:admin brain-write path per existing admin contract

### The RS Algorithm Runs Locally

Enriched local corpus:
```
CombinedCorpus = UserCorpus ∪ BrainMethodologyEmbeddings ∪ CanonicalFrameworkChains
```

Differential computation local only:
```
LSA(CombinedCorpus)     ← structural similarity, local compute (rs_math.py Kwan 2023)
BERT(CombinedCorpus)    ← semantic similarity, local compute (rs_cache.py Pinecone e5-large)
Differential            ← |LSA - BERT|, local
Classification          ← structural_transfer if LSA>BERT else semantic_implementation, local
BreakthroughScore       ← 0-10 rubric, local
InnovationThesis        ← "By applying [Brain methodology] to [User domain]...", local
ExpertNetwork           ← Cypher on user's Aura, local
```

### Three New Pair Classes Unlocked

Current v1.10.16 produces only:
- Cross-room: UserArtifact_A × UserArtifact_B (same room)
- Cross-corpus: UserArtifact × ExternalPaper (from OpenAlex/arXiv)

Brain-Local talking unlocks THREE NEW:
- **Domain × Methodology:** UserArtifact × Brain methodology embedding (e.g., user's team-execution section × `hsi_semantic_surprise_analysis` framework → semantic_implementation opportunity)
- **Cross-domain Methodology:** Brain methodology A × Brain methodology B filtered by user's venture proximity (e.g., `reverse-salient-framework × JTBD` differentially scored for user's IDP problem)
- **Patent × Academic:** Patent claim × academic method gap (from expanded external fetcher per Intent 6)
- **Industry × Academic:** Startup activity × academic frontier (commercial readiness signal)

The Domain × Methodology pair class is what makes RS algorithmic AT MINDRIANOS SCALE. Your venture section has methodology-shaped gaps (structural) or methodology-shaped missing concepts (semantic) — the Brain's 1,427 embeddings are the canonical candidate space to find them.

## 6. Chain Mechanism Requirement (USER'S LOAD-BEARING INTENT)

Per Intent 7, the engine must understand chain mechanisms to spawn abilities/skills AND chain with more engines according to context. Four concrete requirements:

### 6.1 Upstream Chain Awareness

The engine knows which frameworks produce its input:
- `systems-thinking` (for focal component definition)
- `hsi_semantic_surprise_analysis` (the semantic-surprise twin)
- `Cynefin` (for pre-classification of problem domain)

Before running, engine queries Brain:
```
"What's the chain context for venture at problem_type=IDP and stage=opportunity_identified?"
```
Answer tells engine whether to run standalone or pause for upstream framework completion.

### 6.2 Downstream Chain Emission

Every ReverseSalient output carries chain metadata:
- Which canonical Part 3 verb the user can invoke next (Run Methodology / Reformulate / Spawn Sub-Agent / Navigate Graph / Devil's Advocate / Scenario Plan / Synthesize / Bank Opportunity / Defer / Free-Text)
- Which downstream framework FEEDS_INTO accepts this output (PWS VP / JTBD / Causal Loop / Navigation Engine)
- Which skill gets spawned based on reverse salient type + breakthrough score

### 6.3 Context-Aware Engine Orchestration

The RS Discovery Engine is ONE of multiple engines in MindrianOS that can chain:
- HSI Semantic Surprise Engine (`hsi_semantic_surprise_analysis` — the twin)
- Navigation Engine (Phase 91 — L5 Decision layer reading the quadruple memory)
- Future: Scenario Engine, Opportunity Engine, Team Assembly Engine

These engines talk via structured hand-offs:
- `RSDiscovery` → `HSI` for surprise verification (is this differential genuinely surprising?)
- `HSI` → `Navigation Engine` for problem-type routing (which skill handles this)
- `Navigation Engine` → `RS` for candidate re-exploration (if decision was deferred)

The `rs-chain-feeder.cjs` module codifies this choreography. It consults Brain's FEEDS_INTO topology at each step to determine the next legitimate engine hop.

### 6.4 Skill Spawning

Each reverse salient can spawn a skill invocation if context warrants:
- High breakthrough + structural_transfer → spawn `/mos:find-analogies` (SAPPhIRE/TRIZ deepening)
- High breakthrough + market signal → spawn `/mos:lean-canvas`
- Cross-methodology discovery → spawn `/mos:pipeline` chaining (e.g., RS → JTBD → Persona)
- Expert network dense → spawn `/mos:persona` for team composition
- Low breakthrough + Cynefin complex → spawn `/mos:think-hats` for perspective diversity

Skill spawning is RECOMMENDED not forced. The user always decides per Canon Part 3 Tri-Context Decision Gate.
