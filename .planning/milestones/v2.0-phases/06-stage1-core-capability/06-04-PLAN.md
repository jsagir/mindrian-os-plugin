  <action>
Create `references/meeting/cross-relationship-patterns.md` defining the 5 relationship types that the file-meeting command's Step 6 batch scan uses to discover cross-subsystem impacts.

For each relationship type, document:
- **Definition**: What this relationship means in the wicked problem context
- **Detection heuristics (Tier 0)**: Keyword and structural patterns Larry uses conversationally (no ML required)
- **Examples**: 2-3 concrete examples from venture/startup context
- **Impact level**: How significant this is (HIGH/MEDIUM/LOW) and when to surface vs. skip
- **Wicked problem connection**: Which of the 10 wicked problem characteristics this addresses

**INFORMS** (MEDIUM):
- New artifact provides evidence or context for another section
- Tier 0: Shared keywords between new artifact and existing section content; explicit section references in text; speaker mentions another domain ("this affects our financials")
- Example: A researcher's insight about material costs INFORMS the financial-model section
- Surface when: Direct relevance to a section the user has content in

**CONTRADICTS** (HIGH):
- New artifact conflicts with an existing claim in the Data Room
- Tier 0: Opposite sentiment about same topic; numerical disagreements; "actually" / "contrary to" / "I disagree" signals; assumption with status:validated that new data challenges
- Example: Investor says "TAM is $50M" but market-analysis has "TAM is $190M"
- Surface: ALWAYS — contradictions are the most valuable signal

**CONVERGES** (HIGH):
- Theme from this meeting appears in 3+ sections (cross-cutting concern)
- Tier 0: Key noun phrases from new artifacts appear in 3+ existing sections; proper nouns (competitor names, technologies) mentioned across sections
- Example: "Sustainability" mentioned by mentor in problem-definition, by researcher in solution-design, and now by investor in business-model
- Surface: ALWAYS — convergence signals a theme the venture should pay attention to

**INVALIDATES** (HIGH):
- New artifact makes an existing assumption stale
- Tier 0: Scan existing artifacts' `assumptions:` frontmatter fields. Compare new information against `claim:` values. Look for temporal/numerical/factual conflicts. "That was true in Q1 but..." signals
- Example: New competitive intelligence invalidates the assumption "No competitors in ionic liquids space"
- Surface: ALWAYS — stale assumptions are the #1 underserved outcome

**ENABLES** (MEDIUM):
- New artifact unblocks something in another section
- Tier 0: Action items completed that other sections referenced; decisions that resolve open questions; "now we can..." / "this means we can..." signals
- Example: Decision to go B2B enables financial-model projections that were blocked by undefined market
- Surface when: The previously blocked section exists and has content waiting

Also document:
- **Batch scan protocol**: After all filing is complete, Larry reads filed artifacts + existing room content for each non-empty section. Identifies cross-relationships by comparing themes, assumptions, and explicit references. Presents only significant findings.
- **Tier progression**: Tier 0 (Phase 6) = Larry's reasoning + keyword matching. Tier 1 (Phase 8) = LSA + MiniLM embeddings for semantic similarity. Tier 2 (Phase 9) = Full HSI with Brain graph.
- **Output format**: For each discovered relationship, Larry presents: "{edge_type}: {source_artifact} -> {target_section}. {brief explanation}. Impact: {HIGH/MEDIUM}."

```bash
# Count meetings
meeting_count=0
last_meeting_date=""
if [ -d "$ROOM_DIR/meetings" ]; then
  for meeting_dir in "$ROOM_DIR"/meetings/*/; do
    [ -d "$meeting_dir" ] || continue
    meeting_count=$((meeting_count + 1))
    dir_name=$(basename "$meeting_dir")
    # Extract date from YYYY-MM-DD-{name} format
    meeting_date="${dir_name:0:10}"
    if [[ "$meeting_date" > "$last_meeting_date" ]]; then
      last_meeting_date="$meeting_date"
    fi
  done
fi
```
